Forest Fire Propagation with Wind in GPU.js

This article provides a technical guide on simulating real-time forest fire propagation under dynamic, variable wind vectors using GPU.js. By translating cellular automata algorithms to WebGL compute shaders, developers can leverage browser-based parallel computing to simulate thermal transfer and wind-driven combustion across massive 2D landscape grids. Below, you will explore the underlying cellular automata math, the formulation of wind bias vectors, and the concrete implementation of a high-performance GPU.js kernel.

The Propagation Model and Wind Dynamics

Forest fire spread is typically modeled via a 2D grid cellular automaton using a Moore neighborhood (eight surrounding adjacent cells). Each cell exists in one of three discrete states:

  • 0: Unburnt fuel
  • 1: Burning
  • 2: Burnt out (ash)

When a cell is burning, it emits heat that can ignite adjacent unburnt cells. Under calm conditions, propagation probability is isotropic (equal in all directions). When wind is introduced, propagation becomes anisotropic. The probability of ignition increases downwind and decreases upwind.

To model wind influence, let \(\vec{w} = (w_x, w_y)\) be the normalized wind direction vector scaled by wind magnitude, and let \(\vec{d} = (dx, dy)\) be the normalized directional vector from a burning neighbor to the target unburnt cell. The directional influence is derived from the dot product:

\[\text{influence} = \vec{w} \cdot \vec{d}\]

The effective ignition probability \(P_{\text{ignite}}\) from a burning neighbor is expressed as:

\[P_{\text{ignite}} = \max(0.0, P_{\text{base}} \times (1.0 + c \cdot (\vec{w} \cdot \vec{d})))\]

Where:

  • \(P_{\text{base}}\) is the base ignition probability under zero wind.
  • \(c\) is a wind sensitivity constant.
  • If \(P_{\text{ignite}} > 1.0\), it is clamped to \(1.0\).

Implementing the GPU.js Kernel

GPU.js compiles standard JavaScript functions into WebGL shaders. In a cellular automaton, writing back to the input buffer causes race conditions, so a double-buffering (ping-pong) pattern is required: read from gridA, write to gridB, then swap.

Because true random number generation inside a GPU shader requires a deterministic pseudo-random hash, the kernel incorporates a simple coordinate-and-time-based PRNG to evaluate the ignition probability.

const gpu = new GPU();

const GRID_WIDTH = 512;
const GRID_HEIGHT = 512;

// Pseudo-random number generator for WebGL shaders
function pseudoRandom(x, y, seed) {
  const n = Math.sin(x * 12.9898 + y * 78.233 + seed) * 43758.5453;
  return n - Math.floor(n);
}

const fireKernel = gpu.createKernel(function (grid, windX, windY, windSpeed, seed) {
  const x = this.thread.x;
  const y = this.thread.y;
  const currentState = grid[y][x];

  // If the cell is burning, it turns to ash (burnt out)
  if (currentState === 1) {
    return 2;
  }

  // If already burnt out or empty, state does not change
  if (currentState === 2 || currentState === -1) {
    return currentState;
  }

  // If unburnt (0), inspect all 8 neighbors
  if (currentState === 0) {
    let ignited = 0;
    const baseProb = 0.2;
    const windCoeff = 0.5;

    for (let dy = -1; dy <= 1; dy++) {
      for (let dx = -1; dx <= 1; dx++) {
        // Skip current cell
        if (dx === 0 && dy === 0) continue;

        const nx = x + dx;
        const ny = y + dy;

        // Ensure boundary conditions
        if (nx >= 0 && nx < this.constants.width && ny >= 0 && ny < this.constants.height) {
          if (grid[ny][nx] === 1) {
            // Direction vector from burning neighbor to target cell (x, y)
            const dirX = -dx;
            const dirY = -dy;
            const dist = Math.sqrt(dirX * dirX + dirY * dirY);
            const normDirX = dirX / dist;
            const normDirY = dirY / dist;

            // Dot product between wind vector and direction vector
            const dot = (windX * normDirX) + (windY * normDirY);
            
            // Adjust probability based on wind vector
            let prob = baseProb * (1.0 + (windSpeed * windCoeff * dot));
            if (prob < 0.0) prob = 0.0;
            if (prob > 1.0) prob = 1.0;

            // Generate PRNG value for this interaction
            const rand = pseudoRandom(x + dx * 0.1, y + dy * 0.1, seed);
            if (rand < prob) {
              ignited = 1;
            }
          }
        }
      }
    }

    if (ignited === 1) {
      return 1;
    }
    return 0;
  }

  return currentState;
})
.setFunctions([pseudoRandom])
.setConstants({ width: GRID_WIDTH, height: GRID_HEIGHT })
.setOutput([GRID_WIDTH, GRID_HEIGHT]);

Initializing Grid and Simulation Loop

Construct two grids for ping-pong buffering and trigger an ignition source at the center:

let currentGrid = [];
for (let y = 0; y < GRID_HEIGHT; y++) {
  const row = [];
  for (let x = 0; x < GRID_WIDTH; x++) {
    row.push(0); // 0 = Unburnt fuel
  }
  currentGrid.push(row);
}

// Spark ignition at the center
currentGrid[Math.floor(GRID_HEIGHT / 2)][Math.floor(GRID_WIDTH / 2)] = 1;

// Simulation parameters
let windAngleDegrees = 45; // Wind blowing toward North-East
let windSpeed = 2.5;       // Velocity scale factor
let tick = 0;

function stepSimulation() {
  tick += 1.0;

  // Convert wind angle to vector components
  const radians = (windAngleDegrees * Math.PI) / 180;
  const windX = Math.cos(radians);
  const windY = Math.sin(radians);

  // Compute next grid state using the GPU kernel
  const nextGrid = fireKernel(currentGrid, windX, windY, windSpeed, tick);

  // Swap buffers
  currentGrid = nextGrid;
}

Dynamic Updates and Optimization

Because the windX, windY, and windSpeed parameters are uniforms passed directly to the kernel, you can alter the wind direction and intensity on every frame without recompiling the WebGL shader program.

To maximize performance in production:

  1. Pipeline Output: Set .setPipeline(true) on the GPU.js kernel to avoid reading back memory to the CPU on every step. This retains the state as a WebGL texture directly inside the GPU memory.
  2. Direct Rendering: Use a secondary rendering kernel that maps state numbers (0, 1, 2) directly to RGB values on a WebGL-enabled <canvas> element to maintain a 60 FPS simulation cycle across millions of cells.
