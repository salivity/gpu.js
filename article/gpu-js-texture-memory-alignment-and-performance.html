gpu.js Texture Memory Alignment and Performance

Texture memory alignment directly impacts execution speed and bandwidth efficiency when processing chained computational kernels in gpu.js. In WebGL-based compute workflows, data is serialized into texture memory rather than raw linear buffers, requiring the GPU to sample and write to specific texel boundaries. When intermediate texture outputs adhere to native hardware alignments—typically 4-byte, 16-byte, or power-of-two dimension boundaries—the GPU's memory controllers access data with minimal cache misses and zero padding overhead. Conversely, misaligned textures force the graphics pipeline to perform uncoalesced memory fetches, introduce stride compensation cycles, and trigger internal memory re-allocations between pipeline stages, significantly degrading computational throughput.

How gpu.js Employs Texture Memory

gpu.js operates by compiling JavaScript functions into WebGL fragment shaders. Because WebGL lacks native compute shaders in standard configurations, gpu.js encodes input and output matrices as 2D floating-point textures. When pipeline: true is enabled, the output of one kernel remains in GPU VRAM as a WebGL texture and is passed directly as an input texture to the next kernel, bypassing the CPU-GPU transfer bottleneck.

Inside the GPU, texture units rely on localized spatial caching (texture caches) to read data efficiently. Texture memory is laid out in memory blocks or tiles rather than continuous linear rows. If the dimensions of these textures do not align with hardware block sizes, the hardware must execute extra read cycles to reconstruct adjacent data points.

The Mechanisms of Alignment Penalties

  1. Uncoalesced Memory Access: GPUs read memory in unified bursts (transactions) of 32, 64, or 128 bytes. If a kernel output has non-standard dimensions (such as odd row widths), adjacent compute threads in a warp or wavefront will access addresses that cross memory transaction boundaries. This causes multiple memory transactions for data that should have fit into a single transaction.

  2. Stride and Row Padding Overhead: WebGL implementations require texture row boundaries to align to specific byte limits (usually 4-byte alignment via gl.pixelStorei(gl.UNPACK_ALIGNMENT, 4)). If an array's row byte width is not a multiple of four, the graphics driver must insert padding bytes. In a multi-stage gpu.js pipeline, this requires continuous coordinate recalculation inside fragment shaders to skip padding texels, consuming arithmetic logic unit (ALU) cycles.

  3. RGBA Channel Underutilization: Textures are fundamentally composed of four channels: Red, Green, Blue, and Alpha (RGBA). Standard scalar calculations often only utilize the Red channel or require gpu.js to pack single 32-bit floats across four 8-bit channels. Misalignment in how data elements map across these four-component vectors leads to fragmented writes in the framebuffer attachment, reducing the effective memory bandwidth of the GPU by up to 75%.

  4. Pipeline Framebuffer Reconfiguration: When texture dimensions vary unpredictably between chained kernels, the underlying WebGL context must continuously rebind or reallocate Framebuffer Objects (FBOs). This context switching introduces pipeline stalls, forcing the GPU to flush its draw queues before the subsequent kernel can begin execution.

Performance Effects in Pipelined Workflows

In a benchmarked gpu.js pipeline executing iterative operations (such as matrix multiplication, cellular automata, or neural network layers), texture alignment dictates the ceiling for sustained throughput:

  • Cache Locality: Well-aligned textures maximize the L1/L2 texture cache hit rate. Non-aligned dimensions force neighbor fetches to cross cache line boundaries, stalling the execution pipeline while waiting for high-latency VRAM access.
  • Latency Accumulation: Because pipeline mode chains operations sequentially, small alignment penalties do not happen once; they compound across every stage. A 10% memory stall in an isolated kernel translates to hundreds of milliseconds of wasted latency over several thousand iterations.
  • VRAM Fragmentation: Frequently creating textures with awkward dimensions causes fragmentation within the browser's allocated WebGL heap, occasionally triggering automatic garbage collection and GPU memory defragmentation cycles.

Best Practices for Optimal Alignment

To maintain optimal memory alignment in gpu.js pipelines, align data architectures with standard GPU hardware conventions:

  • Pad Dimensions to Multiples of 4 or 8: Ensure that kernel output matrices have widths and heights that are multiples of 4 or 8, ideally targeting powers of two (e.g., 256, 512, 1024) where feasible, even if it requires padding unused edge values.
  • Maintain Dimension Uniformity: Keep intermediate textures in a pipeline workflow the same size across consecutive kernels to prevent the driver from resizing or reallocating WebGL framebuffers.
  • Vectorize Operations: Restructure data to process 4-element vectors concurrently. Utilizing full RGBA vectors matches the native width of the texture memory bus and eliminates channel alignment waste.
