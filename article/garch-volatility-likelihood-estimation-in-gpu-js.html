GARCH Volatility Likelihood Estimation in GPU.js

This article explains how to implement parallelized GARCH(1,1) log-likelihood calculations across multiple financial assets using GPU.js. By delegating the computationally intensive task of recursive variance tracking and log-likelihood summation to the GPU, quantitative developers can perform rapid parameter evaluations, grid searches, and calibration over large cross-sections of return series directly within a JavaScript environment.

The GARCH(1,1) Likelihood Model

The standard GARCH(1,1) model defines the conditional variance \(\sigma_t^2\) of an asset return series \(r_t\) (with zero mean or mean-adjusted residuals \(\epsilon_t\)) as:

\[\sigma_t^2 = \omega + \alpha \epsilon_{t-1}^2 + \beta \sigma_{t-1}^2\]

Where:

  • \(\omega > 0\) is the baseline variance.
  • \(\alpha \ge 0\) is the ARCH parameter (reaction to recent shocks).
  • \(\beta \ge 0\) is the GARCH parameter (persistence of volatility).
  • \(\alpha + \beta < 1\) ensures stationarity.

Assuming conditional normality, the log-likelihood \(LL\) for a single time series of length \(T\) is computed by summing the Gaussian conditional log-densities:

\[LL = -\frac{1}{2} \sum_{t=1}^{T} \left( \ln(2\pi) + \ln(\sigma_t^2) + \frac{\epsilon_t^2}{\sigma_t^2} \right)\]

In optimization routines (e.g., maximum likelihood estimation), the goal is to minimize the Negative Log-Likelihood (NLL), omitting constant terms such as \(\ln(2\pi)\) during numerical optimization.

Parallelization Strategy in GPU.js

Because the GARCH variance equation is inherently autoregressive—\(\sigma_t^2\) depends explicitly on \(\sigma_{t-1}^2\)—parallelizing calculations across time for a single series introduces serialization overhead.

However, evaluating likelihoods across multiple independent assets (or across an evaluation grid of parameter sets) represents an embarrassingly parallel workload. The optimal design maps each GPU thread to a specific asset or parameter candidate. Each thread iterates sequentially over the time-series dimension for its designated asset and returns the resulting negative log-likelihood.

Setting Up the GPU.js Kernel

GPU.js compiles pure JavaScript functions into WebGL or OpenCL shaders. WebGL kernels require statically defined bounds or constant loop limits. Below is a complete implementation that processes multiple asset return series concurrently.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Configuration
const NUM_ASSETS = 1024; // Number of parallel assets
const TIME_STEPS = 500;  // Length of return series

/**
 * Kernel: Compute Negative Log-Likelihood for GARCH(1,1)
 * Parallelized over: Assets (Thread index corresponds to Asset index)
 */
const computeGARCHLikelihood = gpu.createKernel(function(returns, params, timeSteps) {
    const assetIdx = this.thread.x;

    const omega = params[assetIdx][0];
    const alpha = params[assetIdx][1];
    const beta  = params[assetIdx][2];

    // Compute sample unconditional variance to initialize sigma^2_0
    let sampleVar = 0.0;
    for (let t = 0; t < timeSteps; t++) {
        const ret = returns[assetIdx][t];
        sampleVar += ret * ret;
    }
    sampleVar = sampleVar / timeSteps;

    let currentSigma2 = sampleVar;
    let nll = 0.0;

    // Sequential evaluation over time for the current asset
    for (let t = 0; t < timeSteps; t++) {
        const ret = returns[assetIdx][t];
        const ret2 = ret * ret;

        // GARCH(1,1) recurrence relation
        if (t > 0) {
            const prevRet = returns[assetIdx][t - 1];
            currentSigma2 = omega + alpha * (prevRet * prevRet) + beta * currentSigma2;
        }

        // Numerical clamp to prevent division by zero or negative variance
        if (currentSigma2 < 1e-6) {
            currentSigma2 = 1e-6;
        }

        // Add to Negative Log-Likelihood (excluding constant term)
        nll += Math.log(currentSigma2) + (ret2 / currentSigma2);
    }

    return 0.5 * nll;
})
.setOutput([NUM_ASSETS])
.setDynamicArguments(true);

Data Formatting and Kernel Execution

GPU.js processes inputs via textures. Input matrices must be structured as uniform multidimensional arrays or flattened 1D TypedArrays for optimal transfer speeds.

// 1. Prepare Returns Matrix: [NUM_ASSETS][TIME_STEPS]
const returnsData = [];
for (let i = 0; i < NUM_ASSETS; i++) {
    const assetReturns = new Float32Array(TIME_STEPS);
    for (let t = 0; t < TIME_STEPS; t++) {
        // Example: Simulated zero-mean daily returns
        assetReturns[t] = (Math.random() - 0.5) * 0.04;
    }
    returnsData.push(assetReturns);
}

// 2. Prepare Parameters: [NUM_ASSETS][3] -> [omega, alpha, beta]
const parameterData = [];
for (let i = 0; i < NUM_ASSETS; i++) {
    // Example test parameters: omega = 0.00001, alpha = 0.08, beta = 0.90
    parameterData.push([0.00001, 0.08, 0.90]);
}

// 3. Execute Kernel on GPU
console.time('GPU_GARCH_Execution');
const negativeLogLikelihoods = computeGARCHLikelihood(returnsData, parameterData, TIME_STEPS);
console.timeEnd('GPU_GARCH_Execution');

console.log(`Computed NLL for ${negativeLogLikelihoods.length} assets.`);
console.log(`Asset 0 NLL: ${negativeLogLikelihoods[0]}`);

Technical Considerations for Production

  1. Precision: Standard WebGL 1.0 environments rely on 16-bit or 32-bit floats (Float32Array). Accumulating thousands of variance steps can encounter precision drift compared to 64-bit CPU math. Keeping timeSteps under 2,000 observations per run mitigates rounding errors.
  2. Stationarity Violations: In an optimization pipeline, candidate parameters that violate \(\alpha + \beta \ge 1\) or \(\omega \le 0\) should either be penalized directly inside the kernel with a high synthetic NLL value (e.g., 1e8) or filtered prior to kernel submission.
  3. Memory Transfers: To minimize CPU-GPU memory overhead during recurring iterations, avoid recreating input matrices. Maintain data on the GPU by passing gpu.js textures directly between consecutive estimation steps.
