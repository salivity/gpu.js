Acoustic Wave Simulation in GPU.js

Acoustic wave propagation through non-homogeneous media can be computed using finite-difference methods within gpu.js. By leveraging the library's ability to compile JavaScript functions into WebGL compute shaders, the spatial and temporal updates of the acoustic wave equation can run in parallel across thousands of GPU cores. Spatially varying material parameters, such as sound speed and density, are easily represented as arrays or textures, enabling real-time or near-real-time wave simulations directly in a web browser or Node.js environment.

The Mathematical Framework

In an acoustic medium with spatially varying velocity \(c(\mathbf{x})\) and uniform density, the scalar wave equation governing pressure \(p(\mathbf{x}, t)\) is expressed as:

\[\frac{\partial^2 p}{\partial t^2} = c^2(\mathbf{x}) \nabla^2 p\]

When media density \(\rho(\mathbf{x})\) is also heterogeneous, the general second-order acoustic equation takes the form:

\[\rho(\mathbf{x}) \nabla \cdot \left( \frac{1}{\rho(\mathbf{x})} \nabla p \right) - \frac{1}{c^2(\mathbf{x})} \frac{\partial^2 p}{\partial t^2} = 0\]

Using standard central finite differences, spatial derivatives are approximated using a discrete grid with spacing \(\Delta x\) and \(\Delta y\), while temporal derivatives use a time step \(\Delta t\). For the simplified variable-velocity model, the update rule for pressure at discrete grid point \((i, j)\) and time level \(n+1\) is:

\[p_{i,j}^{n+1} = 2p_{i,j}^n - p_{i,j}^{n-1} + (c_{i,j} \Delta t)^2 \left( \frac{p_{i+1,j}^n - 2p_{i,j}^n + p_{i-1,j}^n}{\Delta x^2} + \frac{p_{i,j+1}^n - 2p_{i,j}^n + p_{i,j-1}^n}{\Delta y^2} \right)\]

Stability requires adherence to the Courant-Friedrichs-Lewy (CFL) condition:

\[\Delta t \le \frac{1}{c_{\max} \sqrt{\frac{1}{\Delta x^2} + \frac{1}{\Delta y^2}}}\]

Implementing the Simulation in gpu.js

Finite-difference stencils require localized grid lookups, which map directly to GPU texture lookups.

1. State Management and Double Buffering

Because calculating \(p^{n+1}\) requires \(p^n\) and \(p^{n-1}\), gpu.js must manage memory across successive time steps. GPU computations in WebGL cannot read and write to the same texture simultaneously. A ping-pong (or circular) buffer strategy using three textures representing \(p^{n+1}\), \(p^n\), and \(p^{n-1}\) is required. After each time-step kernel execution, the texture references are swapped.

2. Representing Non-Homogeneous Media

Non-homogeneous properties, such as a localized sound speed matrix \(c_{i,j}\), are passed into the gpu.js kernel as 2D array inputs. When compiled, gpu.js treats these 2D arrays as sampler textures, allowing the kernel to sample the acoustic velocity at c[this.thread.y][this.thread.x]. Sudden impedance changes (e.g., bone vs. soft tissue or air vs. water) are modeled simply by setting different values at corresponding array indices.

3. Kernel Structure

A basic 2D propagation kernel in gpu.js is defined as follows:

const updateWave = gpu.createKernel(function(pCurrent, pPrevious, cGrid, dx, dy, dt) {
    const i = this.thread.x;
    const j = this.thread.y;

    // Boundary check for borders
    if (i === 0 || i === this.constants.width - 1 || j === 0 || j === this.constants.height - 1) {
        return 0;
    }

    const c = cGrid[j][i];
    const laplacian = (
        (pCurrent[j][i + 1] - 2 * pCurrent[j][i] + pCurrent[j][i - 1]) / (dx * dx) +
        (pCurrent[j + 1][i] - 2 * pCurrent[j][i] + pCurrent[j - 1][i]) / (dy * dy)
    );

    return 2 * pCurrent[j][i] - pPrevious[j][i] + (c * c * dt * dt) * laplacian;
})
.setOutput([width, height])
.setConstants({ width, height })
.setPipeline(true);

Setting .setPipeline(true) is critical because it forces gpu.js to retain the output on the GPU as a texture rather than serializing data back to the CPU via JavaScript arrays, maintaining high throughput.

Handling Boundary Conditions

Simulating infinite domains or non-reflective edges requires absorbing boundary conditions. In gpu.js, this can be implemented through:

  • Damping Layers (Sponge Layers): An artificial attenuation term is multiplied against the pressure values within a border zone of 20 to 50 cells. This approach requires only an additional spatial multiplier array passed into the kernel.
  • Perfect Matched Layers (PML): PML splits wave field components to absorb reflections cleanly at varying angles of incidence, though it increases the number of required state variables per grid cell.

Performance and Precision Considerations

  • Floating-Point Precision: WebGL implementations underlying gpu.js often default to single-precision (32-bit) or half-precision floats depending on the platform. Single precision is sufficient for standard finite differences, but cumulative roundoff errors can occur over tens of thousands of time steps.
  • Grid Dispersion: Non-homogeneous media with low local velocities compress wavelengths. The spatial grid spacing \(\Delta x\) must remain fine enough to ensure at least 8 to 10 nodes per shortest wavelength to avoid numerical dispersion.
  • Memory Limits: The maximum simulation grid size is constrained by the maximum texture dimensions and VRAM supported by the client's GPU.
