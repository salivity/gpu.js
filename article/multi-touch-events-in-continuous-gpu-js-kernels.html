Multi-Touch Events in Continuous GPU.js Kernels

Passing multi-finger touch coordinates into continuous GPU.js kernels is entirely feasible and can achieve smooth 60+ FPS performance when implemented correctly. This article explains the technical pipeline required to bridge standard DOM touch events with WebGL-accelerated GPU compute kernels, covering event capture, fixed data structuring, render loop synchronization, and essential optimizations to eliminate frame stutter.

The Challenge of Real-Time Inputs in GPU.js

GPU.js compiles JavaScript-like functions into WebGL shaders. In a continuous execution loop (such as real-time simulations, particle systems, or generative art), the kernel runs every frame via requestAnimationFrame.

The primary difficulty with multi-touch interaction is data variability. Touch events generate a variable number of coordinates dynamically, whereas WebGL shaders expect uniform data with fixed structures and types. Dynamically changing the shape of your kernel arguments triggers internal shader recompilation, which causes severe frame drops and destroys smoothness.

Architectural Solution: Fixed-Size Uniform Buffers

To maintain smooth execution, you must decouple touch input capture from kernel execution and format touch data into a fixed-size array.

  1. Define a Maximum Touch Threshold: Most mobile screens support up to 5 or 10 simultaneous touches. Pre-allocate a typed array to hold coordinates up to this limit (e.g., a Float32Array of size 10 holding [x0, y0, x1, y1, ...]).
  2. Track Active Touch Count: Pass the number of currently active touches as a separate integer uniform so the kernel knows how many points to process.
  3. Normalize Coordinates: Convert screen-space coordinates (clientX, clientY) relative to the canvas resolution (0 to width and 0 to height or normalized 0.0 to 1.0).

Implementation Blueprint

1. Input Capture and Coordinate Normalization

Set up passive event listeners on the target canvas to track touchstart, touchmove, and touchend/touchcancel.

const MAX_TOUCHES = 5;
const touchCoords = new Float32Array(MAX_TOUCHES * 2);
let activeTouchCount = 0;

function updateTouches(e) {
  const rect = canvas.getBoundingClientRect();
  const touches = e.touches;
  activeTouchCount = Math.min(touches.length, MAX_TOUCHES);

  for (let i = 0; i < activeTouchCount; i++) {
    // Normalize coordinates to canvas space
    touchCoords[i * 2] = touches[i].clientX - rect.left;
    touchCoords[i * 2 + 1] = rect.height - (touches[i].clientY - rect.top); // Flip Y for WebGL
  }
}

canvas.addEventListener('touchstart', updateTouches, { passive: true });
canvas.addEventListener('touchmove', updateTouches, { passive: true });
canvas.addEventListener('touchend', updateTouches, { passive: true });
canvas.addEventListener('touchcancel', updateTouches, { passive: true });

2. Writing the GPU.js Kernel

Write the kernel expecting a fixed-length array and an active count. Use a static loop inside the kernel up to the predefined maximum:

const gpu = new GPU({ canvas });

const renderKernel = gpu.createKernel(function(touches, touchCount) {
    let intensity = 0;
    const px = this.thread.x;
    const py = this.thread.y;

    for (let i = 0; i < 5; i++) {
        if (i < touchCount) {
            const tx = touches[i * 2];
            const ty = touches[i * 2 + 1];
            const dist = Math.sqrt((px - tx) * (px - tx) + (py - ty) * (py - ty));
            intensity += Math.max(0, 1 - dist / 100);
        }
    }

    this.color(intensity, intensity * 0.5, 1.0, 1.0);
})
.setOutput([canvas.width, canvas.height])
.setGraphical(true);

3. Continuous Execution Loop

Synchronize execution using requestAnimationFrame. Pass the pre-allocated buffer directly without reallocating arrays on each frame:

function render() {
  renderKernel(touchCoords, activeTouchCount);
  requestAnimationFrame(render);
}
requestAnimationFrame(render);

Critical Performance Optimizations

  • Avoid Memory Allocation in Event Handlers: Do not use Array.from(), map(), or allocate new arrays inside touchmove. Overwrite the existing Float32Array in place to avoid triggering garbage collection pauses.
  • Prevent Kernel Recompilation: Keep the kernel argument signature consistent. Never pass arrays of changing lengths.
  • Use Graphical Output Mode: Set .setGraphical(true) so the kernel writes directly to an HTML5 WebGL canvas instead of transferring pixel buffers back to the CPU.
  • Scale Coordinates for HiDPI/Retina Displays: Multiply clientX and clientY offsets by window.devicePixelRatio if your canvas buffer is scaled for high-density screens.
