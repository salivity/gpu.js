Runge-Kutta 4th Order Integration in GPU.js

This article explains how to implement the Runge-Kutta 4th Order (RK4) numerical integration method inside a gpu.js kernel to accelerate ordinary differential equation (ODE) computations. You will learn how to adapt the multi-step RK4 algorithm to the WebGL shading language constraints enforced by gpu.js, structure state arrays for parallel execution, and execute an end-to-end integration step across thousands of independent data points simultaneously.

Understanding the RK4 Algorithm for GPU Execution

The Runge-Kutta 4th Order method approximates the solution to an initial value problem \(\frac{dy}{dt} = f(t, y)\) using a weighted average of four trial increments over a time step \(h\):

  1. \(k_1 = f(t_n, y_n)\)
  2. \(k_2 = f(t_n + \frac{h}{2}, y_n + \frac{h}{2} k_1)\)
  3. \(k_3 = f(t_n + \frac{h}{2}, y_n + \frac{h}{2} k_2)\)
  4. \(k_4 = f(t_n + h, y_n + h k_3)\)
  5. \(y_{n+1} = y_n + \frac{h}{6} (k_1 + 2k_2 + 2k_3 + k_4)\)

When executing RK4 inside gpu.js, all mathematical operations compile into WebGL fragment shaders. Because GPU kernels prohibit recursion, object allocation, and dynamic function references, the derivative function \(f(t, y)\) must be statically defined and registered using gpu.addFunction().

Step 1: Registering the Derivative Function

The derivative function must accept scalar values and return a scalar value. For coupled or multi-dimensional systems, multiple helper functions can be registered or the equations can be evaluated component-wise.

Below is an example of an ODE defining a damped harmonic oscillator or decay system:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Register the derivative function f(t, y)
gpu.addFunction(function computeDerivative(t, y) {
  // Example ODE: dy/dt = -0.5 * y + Math.sin(t)
  return -0.5 * y + Math.sin(t);
});

Step 2: Creating the RK4 Kernel

A gpu.js kernel executes across a designated output dimension, where each thread handles a single state variable or particle. The kernel takes the current state array, the current time \(t\), and the step size \(h\) as inputs.

const rk4Kernel = gpu.createKernel(function (currentY, t, h) {
  const i = this.thread.x;
  const y = currentY[i];

  // Step 1: Compute k1
  const k1 = computeDerivative(t, y);

  // Step 2: Compute k2
  const y_k1 = y + 0.5 * h * k1;
  const t_half = t + 0.5 * h;
  const k2 = computeDerivative(t_half, y_k1);

  // Step 3: Compute k3
  const y_k2 = y + 0.5 * h * k2;
  const k3 = computeDerivative(t_half, y_k2);

  // Step 4: Compute k4
  const y_k3 = y + h * k3;
  const t_full = t + h;
  const k4 = computeDerivative(t_full, y_k3);

  // Combine slopes to compute next state
  return y + (h / 6.0) * (k1 + 2.0 * k2 + 2.0 * k3 + k4);
})
.setOutput([100000]); // Number of parallel instances

Step 3: Integrating Over Multiple Steps

To step forward in time, chain kernel evaluations using pipelining. Enable setPipeline(true) so output buffers remain on the GPU memory between integration steps, eliminating CPU-GPU memory transfer overhead.

const steps = 1000;
const h = 0.01;
let t = 0.0;

// Enable GPU texture reuse
rk4Kernel.setPipeline(true);

// Initialize 100,000 states
let states = new Float32Array(100000).map(() => Math.random() * 10);

for (let step = 0; step < steps; step++) {
  states = rk4Kernel(states, t, h);
  t += h;
}

// Read back the final state from GPU to CPU
const finalResults = states.toArray();
console.log(finalResults);

Handling Coupled Multi-Variable Systems

To simulate coupled equations (e.g., position \(x\) and velocity \(v\) in Newtonian mechanics), configure a 2D kernel where each entity has coordinates along the Y-axis and individual components along the X-axis:

// State representation: [x, v] for each particle
const rk4CoupledKernel = gpu.createKernel(function (states, h) {
  const particleIdx = this.thread.y;
  const component = this.thread.x;

  const x = states[particleIdx][0];
  const v = states[particleIdx][1];

  // k1 slopes: dx/dt = v, dv/dt = -k/m * x
  const k1_x = v;
  const k1_v = -2.0 * x;

  // k2 slopes
  const x_k1 = x + 0.5 * h * k1_x;
  const v_k1 = v + 0.5 * h * k1_v;
  const k2_x = v_k1;
  const k2_v = -2.0 * x_k1;

  // k3 slopes
  const x_k2 = x + 0.5 * h * k2_x;
  const v_k2 = v + 0.5 * h * k2_v;
  const k3_x = v_k2;
  const k3_v = -2.0 * x_k2;

  // k4 slopes
  const x_k3 = x + h * k3_x;
  const v_k3 = v + h * k3_v;
  const k4_x = v_k3;
  const k4_v = -2.0 * x_k3;

  if (component === 0) {
    return x + (h / 6.0) * (k1_x + 2.0 * k2_x + 2.0 * k3_x + k4_x);
  } else {
    return v + (h / 6.0) * (k1_v + 2.0 * k2_v + 2.0 * k3_v + k4_v);
  }
})
.setOutput([2, 50000]); // 2 components per particle, 50,000 particles

This configuration ensures high computational throughput while preserving the 4th-order accuracy of the Runge-Kutta integrator inside a WebGL context.
