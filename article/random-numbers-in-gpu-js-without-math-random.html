Random Numbers in GPU.js Without Math.random

This article explains how to generate pseudo-random numbers inside GPU.js kernels where JavaScript's native Math.random() is unavailable. Because GPU.js compiles kernel functions into WebGL shaders, threads run strictly in parallel without access to native CPU-bound JavaScript APIs. You will learn how to implement deterministic mathematical hash functions using thread coordinates and seed values to produce uniform pseudo-random numbers directly on the GPU.

Why Math.random() Fails in GPU.js

When GPU.js compiles a JavaScript function into a GLSL shader, it only supports a subset of standard JavaScript operations. Shaders are stateless and execute concurrently across hundreds or thousands of GPU cores.

Native Math.random() relies on internal state that mutates with every call on a single CPU thread. In a massively parallel GPU architecture, shared mutable state causes race conditions and severe performance penalties. Consequently, GPU.js does not transpile Math.random(), and attempting to use it inside a kernel will result in a compilation error.

The Solution: Hash-Based PRNGs

To generate pseudo-random numbers on the GPU, you must use a stateless Pseudo-Random Number Generator (PRNG). These functions take deterministic inputs—such as the thread's coordinate indices (this.thread.x, this.thread.y) and an external seed—and pass them through a mathematical hash function that produces an apparently random float between 0.0 and 1.0.

The Canonical Sine-Fraction Hash

The most common shader-based pseudo-random function relies on a high-frequency sine wave and fractional extraction:

function pseudoRandom(x, y, seed) {
  const n = Math.sin(x * 12.9898 + y * 78.233 + seed) * 43758.5453123;
  return n - Math.floor(n);
}

This function performs two main tasks:

  1. Calculates a dot product between the thread coordinates and two distinct prime-derived constants, offset by an external seed.
  2. Multiplies the sine of the result by a large scalar (43758.5453123) and extracts the fractional part (n - Math.floor(n)), which yields a uniform distribution in the range [0, 1).

Implementing the PRNG in GPU.js

To use the pseudo-random generator inside a GPU.js kernel, register the function using gpu.addFunction() or write it inline within the kernel.

Full Implementation Example

const { GPU } = require('gpu.js');
const gpu = new GPU();

// 1. Register the PRNG function with GPU.js
gpu.addFunction(function pseudoRandom(x, y, seed) {
  const n = Math.sin(x * 12.9898 + y * 78.233 + seed) * 43758.5453123;
  return n - Math.floor(n);
});

// 2. Create the kernel
const generateRandomMatrix = gpu.createKernel(function(seed) {
  const randVal = pseudoRandom(this.thread.x, this.thread.y, seed);
  return randVal;
}).setOutput([512, 512]);

// 3. Execute the kernel with an external seed
const seed = Math.random() * 1000;
const randomMatrix = generateRandomMatrix(seed);

console.log(randomMatrix);

Best Practices for GPU Randomness

  • Vary the Seed Per Frame: If you run the kernel in an animation loop or successive iterations, pass an updated seed (such as an incremental frame index or performance.now()) on every run. Without changing the seed, the kernel will output identical values across invocations.
  • 3D Kernels: For three-dimensional kernels, incorporate this.thread.z with a third distinct factor: 
    function pseudoRandom3D(x, y, z, seed) {
  const n = Math.sin(x * 12.9898 + y * 78.233 + z * 37.719 + seed) * 43758.5453123;
  return n - Math.floor(n);
}
  • Precision Awareness: The sine-based hash relies on 32-bit floating-point precision. On certain low-end mobile GPUs with low float precision, artifacts or banding patterns may appear. In such cases, keep seed values within reasonable bounds (e.g., modulo the seed between 0 and 10000) to avoid loss of precision in the multiplication step.
