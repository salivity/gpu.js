Reporting Reproducible Bugs in gpu.js

Filing an effective bug report in the gpu.js repository ensures that maintainers can quickly diagnose, reproduce, and resolve issues related to GPU-accelerated JavaScript. Because gpu.js bridges high-level JavaScript code with low-level WebGL and WebGPU pipelines, bug reports require specific hardware details, isolated test cases, and execution logs. This guide outlines the essential practices developers must follow to submit high-quality, actionable bug reports to the gpu.js issue tracker.

1. Search for Existing Issues

Before opening a new ticket, search both open and closed issues as well as discussions in the repository. Many common errors—such as unsupported matrix operations, syntax limitations inside kernels, or known browser-specific WebGL quirks—have already been reported, resolved, or documented with workarounds. If a related issue exists, contribute additional reproduction details to that thread instead of creating a duplicate.

2. Isolate a Minimal, Reproducible Example (MRE)

Provide the smallest amount of code necessary to trigger the bug. Do not submit an entire application codebase or complex external dependencies.

  • Extract only the problematic kernel and its immediate input data.
  • Hardcode simple input arrays (such as [1, 2, 3]) rather than reading from network requests or large assets.
  • Provide the example as a self-contained snippet in markdown code blocks, or host it on an interactive sandbox like JSFiddle, CodePen, or a minimal GitHub repository.

3. Detail Hardware and Environment Specifications

Because gpu.js relies heavily on hardware acceleration, behavior often varies across graphic cards, operating systems, and browser runtimes. Always include the following system details:

  • Operating System: Exact version and architecture (e.g., macOS Sonoma 14.4, Windows 11 64-bit, Ubuntu 22.04).
  • Runtime / Browser: Specific version of Node.js or browser (e.g., Node.js v20.11.0, Chrome 123.0.6312.86).
  • GPU Model and Driver: Specific graphics hardware (e.g., NVIDIA GeForce RTX 3080, Apple M2 Max, Intel Iris Xe) and driver versions.
  • gpu.js Version: The exact npm package or CDN version installed.

4. Test Across Fallback and Execution Modes

gpu.js supports multiple execution modes, including WebGL 2, WebGL 1, and a pure CPU fallback. Testing your kernel across these modes isolates whether the issue is a compiler parser error or a graphics pipeline failure. Specify in your report:

  • Does the code fail under { mode: 'gpu' }?
  • Does it fail under { mode: 'cpu' }?
  • Does the error persist if forced into { mode: 'webgl' } or { mode: 'webgl2' }?

5. Include Complete Logs and Stack Traces

Vague descriptions like "the kernel crashes" make debugging impossible. Provide exact diagnostic output:

  • Full JavaScript console error messages and stack traces.
  • WebGL context warnings or GLSL compile errors logged to the developer console.
  • Expected output values contrasted directly against the actual returned output values.

6. Follow the Repository Issue Template

When opening a ticket, strictly follow the repository's provided markdown issue template. Fill in every requested section completely, format all code with appropriate markdown syntax highlighting, and avoid posting screenshots of text or code blocks.
