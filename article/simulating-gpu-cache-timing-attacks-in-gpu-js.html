Simulating GPU Cache Timing Attacks in GPU.js

This article explores the theoretical modeling and benchmarking of microarchitectural cache timing side-channels using GPU-accelerated JavaScript environments like GPU.js. It details the mechanics of data-dependent memory access on graphics hardware, outlines how timing variations are measured and isolated in research environments, and discusses the defensive countermeasures designed to mitigate browser- and API-level microarchitectural leakage.

Theoretical Foundations of GPU Cache Timing

Microarchitectural side-channel attacks rely on indirect observations of a physical system's state to infer sensitive data, such as cryptographic keys. In cache timing attacks, the primary observable is the difference in execution latency between a cache hit and a cache miss. When applied to cryptographic implementations (such as table-based AES or modular exponentiation algorithms), data-dependent lookups cause specific cache lines to be loaded into fast memory. If an observer can deduce which cache lines were accessed, the secret key or internal state can potentially be reconstructed.

Modern GPUs implement complex memory hierarchies, typically comprising high-speed registers, shared memory (L1-equivalent programmable scratchpad), and hardware-managed L2 caches shared across compute units. While GPUs are designed for massive data-parallel throughput rather than low-latency serial operations, their shared caches remain susceptible to contention and access latency discrepancies.

Modeling Memory Contention with GPU.js

GPU.js compiles JavaScript functions into WebGL shaders or WebGPU compute kernels to execute parallel code on the graphics hardware. To study cache effects, researchers construct synthetic benchmarks that simulate lookup table operations under varying access patterns:

  1. Synthetic Kernel Construction: Kernels are defined to perform repeated array reads. In one baseline model, accesses are uniform or purely sequential, ensuring high cache locality. In the variable model, memory indices are derived from pseudo-secret values or non-contiguous strides designed to force cache line eviction.
  2. Measuring Execution Time: GPU.js provides profiling utilities (mode: 'gpu', with benchmark modes enabled) that interface with underlying graphics APIs. On the host side, execution time is traditionally measured by bounding kernel invocations with high-resolution timestamps.
  3. Synchronizing Host and Device: GPU operations are executed asynchronously. Reliable timing simulation requires explicit synchronization barriers—often achieved by reading back a result buffer to the CPU—to ensure that measured intervals reflect actual hardware execution rather than driver queuing overhead.

Analytical Limitations and Challenges

Simulating or observing side-channels through WebGL abstractions introduces significant noise compared to native execution environments:

  • Timer Granularity and Jitter: Modern web browsers actively mitigate microarchitectural attacks (such as Spectre) by clamping high-resolution timers like performance.now() to reduced precisions (e.g., 5 to 20 microseconds) and introducing synthetic jitter.
  • Driver Optimizations: Graphics drivers and JIT compilers frequently optimize out redundant lookups, reorder memory operations, or map uniform reads across threads via warp-level broadcast mechanisms, flattening expected latency deltas.
  • Coalesced Memory Access: GPU architectures rely on memory coalescing, where adjacent threads reading contiguous addresses merge their requests into single transactions. Simulating single-thread cache effects requires isolating thread behaviors or saturating entire warps/wavefronts to expose contention.

Defensive Strategies and Countermeasures

Mitigating cache side-channels in accelerated computing environments requires interventions at both the cryptographic and platform levels:

  • Constant-Time Implementations: Cryptographic algorithms must be implemented using algorithms that execute in constant time regardless of input. For symmetric ciphers, this means utilizing bitsliced representations or vector-permutation instructions rather than static lookup tables (such as S-boxes).
  • Hardware-Accelerated Primitives: Using platform-native cryptographic primitives (e.g., Web Cryptography API, AES-NI) bypasses software-level lookup table vulnerabilities by executing operations within dedicated, side-channel-resistant hardware circuits.
  • API Restrictions: Browser vendors continue to partition GPU contexts, restrict cross-origin access to WebGL/WebGPU resources, and disable fine-grained hardware performance counters from untrusted script contexts to prevent covert timing telemetry.
