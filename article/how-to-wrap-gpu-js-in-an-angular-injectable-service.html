How to Wrap GPU.js in an Angular Injectable Service

This article demonstrates how to integrate GPU.js into an Angular application by encapsulating its computational pipeline within an Angular injectable service. By abstracting GPU kernel creation and lifecycle management inside a dedicated service, you ensure optimal resource utilization, avoid memory leaks from dangling WebGL contexts, and provide a clean, testable API to your components for high-performance parallel processing.

Prerequisites and Installation

First, install GPU.js in your Angular project:

npm install gpu.js

If you encounter TypeScript declaration issues, you can install the types if available or declare the module in your src/typings.d.ts file:

declare module 'gpu.js';

Step 1: Create the Angular Injectable Service

Generate a new service using the Angular CLI:

ng generate service services/gpu-compute

In this service, initialize the GPU instance once, compile the required computational kernel, and expose a clean method to invoke the pipeline.

import { Injectable, OnDestroy } from '@angular/core';
import { GPU, IKernelRunShortcut } from 'gpu.js';

@Injectable({
  providedIn: 'root',
})
export class GpuComputeService implements OnDestroy {
  private gpu: GPU;
  private matrixMultiplyKernel: IKernelRunShortcut;

  constructor() {
    // Initialize GPU instance
    this.gpu = new GPU();

    // Compile the computational pipeline (kernel)
    this.matrixMultiplyKernel = this.gpu.createKernel(function (
      a: number[][],
      b: number[][]
    ) {
      let sum = 0;
      for (let i = 0; i < 512; i++) {
        sum += a[this.thread.y][i] * b[i][this.thread.x];
      }
      return sum;
    })
    .setOutput([512, 512])
    .setPipeline(true); // Keeps output on the GPU for chained calculations
  }

  /**
   * Executes the matrix multiplication pipeline on the GPU.
   * @param matrixA 512x512 matrix
   * @param matrixB 512x512 matrix
   * @returns Array result or GPU texture
   */
  public multiplyMatrices(matrixA: number[][], matrixB: number[][]): Float32Array | number[][] {
    try {
      const result = this.matrixMultiplyKernel(matrixA, matrixB);
      
      // If pipeline mode is active, cast or extract values to array
      if (typeof (result as any).toArray === 'function') {
        return (result as any).toArray();
      }
      
      return result as number[][];
    } catch (error) {
      console.error('GPU computation failed:', error);
      throw error;
    }
  }

  /**
   * Clean up WebGL contexts and compiled kernels when the service is destroyed.
   */
  ngOnDestroy(): void {
    if (this.matrixMultiplyKernel) {
      this.matrixMultiplyKernel.destroy(true);
    }
    if (this.gpu) {
      this.gpu.destroy();
    }
  }
}

Step 2: Inject and Use the Service in a Component

Inject the computational service into an Angular component to process calculations without coupling UI logic directly to WebGL contexts.

import { Component, OnInit } from '@angular/core';
import { CommonModule } from '@angular/common';
import { GpuComputeService } from './services/gpu-compute.service';

@Component({
  selector: 'app-compute-demo',
  standalone: true,
  imports: [CommonModule],
  template: `
    <div>
      <button (click)="runComputation()">Execute GPU Pipeline</button>
      <p *ngIf="executionTime !== null">Execution Time: {{ executionTime }} ms</p>
    </div>
  `
})
export class ComputeDemoComponent implements OnInit {
  public executionTime: number | null = null;
  private matrixA: number[][] = [];
  private matrixB: number[][] = [];

  constructor(private gpuService: GpuComputeService) {}

  ngOnInit(): void {
    this.matrixA = this.generateMatrix(512, 512);
    this.matrixB = this.generateMatrix(512, 512);
  }

  runComputation(): void {
    const startTime = performance.now();
    
    const result = this.gpuService.multiplyMatrices(this.matrixA, this.matrixB);
    
    this.executionTime = performance.now() - startTime;
    console.log('Result sample:', result[0]);
  }

  private generateMatrix(rows: number, cols: number): number[][] {
    return Array.from({ length: rows }, () =>
      Array.from({ length: cols }, () => Math.random())
    );
  }
}

Key Considerations for Production

  1. Kernel Compilation Cost: Compiling a GPU kernel compiles GLSL shaders under the hood, which is computationally expensive. Always define and compile kernels in the service constructor or an initialization method, rather than re-creating them inside invocation methods.
  2. Memory Leaks & Context Limits: WebGL contexts are limited per browser page (typically 8–16 contexts). Keeping the service as a root-level singleton (providedIn: 'root') avoids creating multiple GPU instances. Implement ngOnDestroy to call kernel.destroy() and gpu.destroy() when tearing down.
  3. Pipeline Mode: If your computational pipeline consists of multiple sequential kernels, chain them by setting .setPipeline(true) on intermediate kernels. This avoids transferring texture data back and forth between GPU VRAM and CPU RAM until the final output step.
