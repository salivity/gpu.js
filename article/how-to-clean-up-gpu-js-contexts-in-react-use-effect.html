How to Clean Up GPU.js Contexts in React useEffect

When integrating GPU.js into React components, failing to manage the underlying WebGL resources leads to rapid memory leaks and "Too many active WebGL contexts" browser crashes. Because browsers impose a strict limit on simultaneous WebGL contexts (typically between 8 and 16), every GPU instance must be cleanly torn down when a component leaves the DOM. Structuring your useEffect hook to explicitly invoke GPU.js cleanup methods on unmount ensures stable performance across component lifecycles.

The WebGL Context Leak Problem

Each time you call new GPU(), the library initializes an invisible HTML canvas and binds a hardware-accelerated WebGL rendering context. React's default garbage collection does not automatically release these WebGL bindings when a component unmounts. If your component mounts, unmounts, or re-renders repeatedly (such as during route transitions or in React 18's StrictMode), unreleased contexts accumulate until the browser forcefully terminates the oldest contexts or fails entirely.

Structuring the useEffect Hook

To prevent memory leaks, you must create your GPU instance and its compiled kernels within the useEffect scope and return a synchronous cleanup function that invokes .destroy().

import React, { useEffect, useRef } from 'react';
import { GPU } from 'gpu.js';

export function MatrixComputation({ data }) {
  const resultRef = useRef(null);

  useEffect(() => {
    // 1. Instantiate the context inside the effect
    const gpu = new GPU();

    // 2. Define your kernel
    const computeKernel = gpu.createKernel(function (inputMatrix) {
      return inputMatrix[this.thread.x] * 2;
    }).setOutput([data.length]);

    // 3. Execute the computation
    const output = computeKernel(data);
    resultRef.current = output;

    // 4. Return the explicit cleanup callback
    return () => {
      // Destroy kernel first if referenced separately, or directly destroy the GPU instance
      computeKernel.destroy(true); // pass true to detach sub-resources if necessary
      gpu.destroy();
    };
  }, [data]);

  return <div>Computation Complete. Open console to view results.</div>;
}

Key Practices for GPU.js Cleanups

  1. Call gpu.destroy() Unconditionally: The .destroy() method disposes of the underlying WebGL context, releases textures, and detaches the canvas element from internal memory. This must be the final operation in your effect's cleanup phase.

  2. Handle Kernel Cleanup Explicitly: If you compile multiple or long-running kernels via gpu.createKernel(), call .destroy() on the individual kernels before calling gpu.destroy(). While gpu.destroy() attempts to wipe associated resources, explicitly freeing kernels prevents dangling texture references during hot reloads.

  3. Manage Persistent Contexts with useRef: If your component re-renders frequently and you do not want to re-instantiate the GPU context on every render, initialize the GPU instance once using a useRef or an empty dependency array []. Ensure that the cleanup function tied to that lifecycle destroys the ref target:

useEffect(() => {
  const gpu = new GPU();
  gpuRef.current = gpu;

  return () => {
    if (gpuRef.current) {
      gpuRef.current.destroy();
      gpuRef.current = null;
    }
  };
}, []);
  1. Prepare for React 18 StrictMode: In development environments, React 18 immediately mounts, unmounts, and remounts components to test resilience. Structuring the cleanup correctly ensures the first initialization is destroyed cleanly without invalidating the second context. Avoid storing kernels in module-level global variables, as this breaks when React mounts parallel instances of the same component.
