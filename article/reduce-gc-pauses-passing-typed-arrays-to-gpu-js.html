Reduce GC Pauses Passing TypedArrays to gpu.js

Constantly allocating and passing new TypedArrays to gpu.js can trigger severe JavaScript engine garbage collection (GC) pauses, degrading performance in real-time simulations, animations, and high-frequency data pipelines. This guide outlines practical memory-management patterns—including buffer pre-allocation, kernel pipelining, flat memory layouts, and view reuse—to stabilize frame rates and eliminate GC bottlenecks when dispatching compute workloads to the GPU.

Pre-allocate and Reuse TypedArray Buffers

The primary trigger for GC pauses in numeric applications is allocating new memory inside an animation or computation loop. Instantiating arrays via new Float32Array(length) every frame constantly allocates blocks on the heap, triggering minor and major garbage collection cycles.

To avoid this, allocate your TypedArrays once outside the execution loop and mutate their contents in place:

// Pre-allocate working memory once
const dataSize = 1024 * 1024;
const persistentInput = new Float32Array(dataSize);

function updateData() {
  // Overwrite existing buffer values instead of instantiating a new array
  for (let i = 0; i < dataSize; i++) {
    persistentInput[i] = Math.random();
  }
}

function renderLoop() {
  updateData();
  kernel(persistentInput);
  requestAnimationFrame(renderLoop);
}

Keep Data on the GPU Using Kernel Pipelining

Transferring large TypedArrays across the CPU-GPU boundary incurs overhead both in memory serialization and object generation. If the output of one kernel serves as the input to another, avoid reading the result back into a CPU-side TypedArray.

Enable the pipeline mode in gpu.js. This forces kernels to output WebGL textures rather than serializing data back to JavaScript memory:

const kernelA = gpu.createKernel(function() {
  return this.thread.x * 2;
}).setOutput([1024]).setPipeline(true);

const kernelB = gpu.createKernel(function(textureInput) {
  return textureInput[this.thread.x] + 1;
}).setOutput([1024]);

// Execution passes texture memory directly on the GPU without CPU heap churn
const intermediateTexture = kernelA();
const finalResult = kernelB(intermediateTexture);

// Explicitly delete textures when they are no longer needed
intermediateTexture.delete();

Avoid Native Multi-Dimensional JavaScript Arrays

Standard nested JavaScript arrays (e.g., [[1, 2], [3, 4]]) create a separate heap object for every row. Passing these into gpu.js forces the library to internally convert the nested arrays, causing a high volume of temporary memory allocations.

Always flatten your input data into a single 1D TypedArray and compute indices mathematically inside the kernel:

// Flatten 2D data: index = x + y * width
const width = 512;
const height = 512;
const flatBuffer = new Float32Array(width * height);

const kernel = gpu.createKernel(function(flatInput, width) {
  const index = this.thread.x + (this.thread.y * width);
  return flatInput[index] * 2.0;
}).setOutput([width, height]);

Use Subarrays Instead of Slicing

When passing segments of an array to a kernel, developers frequently use TypedArray.prototype.slice(), which allocates a fresh memory buffer and copies the data.

Instead, use TypedArray.prototype.subarray(). A subarray creates a lightweight view over the existing ArrayBuffer without allocating new underlying storage or duplicating binary contents:

// Slice creates a new ArrayBuffer (triggers GC):
// const chunk = persistentInput.slice(0, 1000); 

// Subarray creates a fast view referencing the original buffer:
const chunk = persistentInput.subarray(0, 1000);
kernel(chunk);

For maximum performance, pre-create and store subarray references if the bounds of the slices do not change dynamically.

Implement a Double-Buffering Ring Pattern

If input data arrives asynchronously from external sources such as WebSockets or video feeds, an immediate-write approach can introduce race conditions and memory thrashing.

Implement a double-buffering or ring-buffer strategy using a fixed pool of TypedArrays:

  1. Allocate two identical TypedArrays (bufferA and bufferB).
  2. Write incoming streaming data into bufferA.
  3. Dispatch bufferB to the gpu.js kernel.
  4. Swap the references on the next tick.

This pattern isolates read and write operations, preserves contiguous memory blocks, and keeps heap allocation flat throughout the application lifecycle.
