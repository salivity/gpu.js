Computing DTW Distance Matrices with GPU.js

Dynamic Time Warping (DTW) distance matrices across pairs of time series can be computed using GPU.js by exploiting inter-pair parallelism. While the dynamic programming algorithm for a single DTW alignment has sequential dependencies that make it difficult to parallelize internally, computing the distances between hundreds or thousands of distinct time series pairs is embarrassingly parallel. GPU.js compiles JavaScript functions into WebGL or WebGPU compute shaders, allowing developers to assign individual pair-wise DTW computations to separate GPU threads and significantly accelerate distance matrix generation directly in the browser or Node.js.

The Parallelization Strategy: Inter-Pair vs. Intra-Pair

A standard DTW calculation between two sequences of length \(L\) requires filling an \(L \times L\) cumulative cost matrix using the recurrence relation:

\[D(i, j) = \text{cost}(i, j) + \min(D(i-1, j), D(i, j-1), D(i-1, j-1))\]

Because cell \((i, j)\) depends strictly on the results of adjacent cells, parallelizing a single pair's alignment (intra-pair) requires complex wavefront algorithms and cross-thread synchronization, which GPU.js does not natively support.

However, when generating an all-pairs distance matrix for a dataset of \(N\) time series, you must calculate \(N \times N\) independent DTW distances. In GPU.js, each output thread can map directly to coordinates \((x, y)\) of the distance matrix, computing the complete DTW distance between series \(x\) and series \(y\) independently.

Implementing DTW in a GPU.js Kernel

To calculate pairwise DTW using GPU.js, you must structure the data and the kernel logic to comply with WebGL shader constraints:

  1. Memory Optimization via Rolling Arrays: A full \(L \times L\) grid inside a GPU thread will quickly exceed register and local memory limits. Instead, maintain only two rows (the previous row and the current row) to calculate the cumulative distance, reducing thread space complexity from \(O(L^2)\) to \(O(L)\).
  2. Fixed Loop Bounds: WebGL shaders require deterministic loop bounds. All time series must be padded or interpolated to a uniform length \(L\), and loop counters must run against static constants rather than dynamic variables.
  3. Data Formatting: Pass the collection of time series as a 2D array, where each row represents a sequence and each column represents a time step.
const { GPU } = require('gpu.js');
const gpu = new GPU();

const SEQUENCE_LENGTH = 100;

// Kernel to compute the pairwise DTW distance matrix
const calculateDTWMatrix = gpu.createKernel(function(dataset) {
    const i = this.thread.y;
    const j = this.thread.x;

    // Use two alternating rows to store cost
    let prevRow = [0];
    let currRow = [0];

    // Initialize the first row
    let diff0 = dataset[i][0] - dataset[j][0];
    prevRow[0] = diff0 * diff0;

    for (let col = 1; col < this.constants.length; col++) {
        let diff = dataset[i][0] - dataset[j][col];
        prevRow[col] = prevRow[col - 1] + (diff * diff);
    }

    // Dynamic programming loop
    for (let row = 1; row < this.constants.length; row++) {
        let diffFirst = dataset[i][row] - dataset[j][0];
        currRow[0] = prevRow[0] + (diffFirst * diffFirst);

        for (let col = 1; col < this.constants.length; col++) {
            let cost = dataset[i][row] - dataset[j][col];
            let dist = cost * cost;

            let minPrev = prevRow[col];
            if (currRow[col - 1] < minPrev) {
                minPrev = currRow[col - 1];
            }
            if (prevRow[col - 1] < minPrev) {
                minPrev = prevRow[col - 1];
            }

            currRow[col] = dist + minPrev;
        }

        // Copy current row to previous row
        for (let col = 0; col < this.constants.length; col++) {
            prevRow[col] = currRow[col];
        }
    }

    return Math.sqrt(currRow[this.constants.length - 1]);
})

Constraints and Considerations

While GPU.js provides substantial speedups over pure JavaScript loops for medium-sized matrices, several technical limitations must be managed:

  • Sequence Length Limitations: Because shaders allocate local memory per thread, sequence lengths greater than a few hundred points can exhaust local GPU memory or lead to register spilling, reducing performance.
  • Driver Timeouts: Large matrices (e.g., \(N > 2000\)) with long sequences may exceed the OS watchdog timer (TDR) for browser-based WebGL contexts, crashing the shader. Processing large datasets in tiled batches avoids this issue.
  • Precision Differences: WebGL typically operates on 32-bit floating-point numbers. Accumulating squared distances across long paths can lead to precision loss compared to 64-bit CPU implementations.

GPU.js is an effective tool for computing pairwise dynamic time warping matrices, provided the parallel workload is partitioned at the sequence-pair level rather than within individual path alignments.
