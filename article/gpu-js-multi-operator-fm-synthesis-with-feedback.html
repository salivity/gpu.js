GPU.js Multi-Operator FM Synthesis with Feedback

Implementing multi-operator frequency modulation (FM) synthesis with recursive feedback loops in gpu.js requires bridging parallel GPU compute structures with inherently sequential digital signal processing. While standard FM algorithms map cleanly to parallel threads, feedback loops introduce time-dependent state variables that conflict with standard SIMD processing. By structuring gpu.js kernels to process independent audio blocks sequentially per thread, or by pipelining feedback buffers across successive kernel dispatches, high-throughput multi-operator audio generation can be achieved entirely in the browser.

The Feedback Bottleneck in Parallel Synthesis

Standard FM synthesis without feedback allows each audio sample \(n\) to be calculated in parallel, making it a natural fit for GPU acceleration where each thread computes a single sample:

\[y[n] = \sin(\omega_c n + I \cdot \sin(\omega_m n))\]

However, self-modulating operators rely on feedback where the current sample depends directly on the previous sample output:

\[y[n] = \sin(\omega n + \beta \cdot y[n-1])\]

In GPU compute environments like gpu.js, threads execute concurrently without cross-thread temporal synchronization. You cannot directly read the output of thread \(n-1\) from thread \(n\) during the same execution cycle.

To overcome this, two architectural patterns exist in gpu.js:

  1. Intra-Thread Block Generation: Each GPU thread computes an entire contiguous block (or voice) of samples sequentially using an internal loop, keeping feedback memory in fast thread-local registers.
  2. Ping-Pong Buffer Iteration: Each kernel pass computes a single sample across all active voices, ping-ponging the feedback state between two framebuffers.

For real-time Web Audio rendering, the intra-thread block approach offers optimal throughput by avoiding frame-dispatch overhead.

Operator Routing and Modulation Matrix

A classic multi-operator architecture (such as Yamaha 4-Op or 6-Op) relies on an algorithm matrix where the outputs of modulators modulate the phases of carriers.

For a 4-operator setup:

  • Each operator \(i \in \{0, 1, 2, 3\}\) has a frequency multiplier, envelope level, and output phase.
  • A modulation matrix \(M[i][j]\) defines how much operator \(j\) modulates operator \(i\).
  • Feedback is represented as self-modulation where \(M[i][i] > 0\).

Implementing the Kernel in gpu.js

Below is a complete implementation demonstrating a 4-operator algorithm where Operator 3 has a feedback loop, modulating Operator 2, which modulates Operator 1, which in turn modulates Carrier 0. Each thread calculates a slice of audio or an independent voice over a buffer window.

const { GPU } = require('gpu.js'); // or window.GPU in browser
const gpu = new GPU();

const BUFFER_SIZE = 1024;
const NUM_VOICES = 64; // Parallel voices
const SAMPLE_RATE = 44100;

// Kernel configuration: 1 thread per polyphonic voice
const renderFMVoices = gpu.createKernel(function(
  frequencies,
  modIndexMatrix,
  ratios,
  feedbackAmount
) {
  const voiceIdx = this.thread.x;
  const baseFreq = frequencies[voiceIdx];

  // Operator states: feedback history (1 sample delay)
  let op3_prev = 0.0;
  let op3_phase = 0.0;
  let op2_phase = 0.0;
  let op1_phase = 0.0;
  let op0_phase = 0.0;

  const twoPi = 6.28318530718;

  // Compute phase increments per sample
  const inc0 = (baseFreq * ratios[0] * twoPi) / 44100.0;
  const inc1 = (baseFreq * ratios[1] * twoPi) / 44100.0;
  const inc2 = (baseFreq * ratios[2] * twoPi) / 44100.0;
  const inc3 = (baseFreq * ratios[3] * twoPi) / 44100.0;

  // Process sequential samples within this thread
  for (let i = 0; i < 1024; i++) {
    // Op 3: Feedback operator
    const op3_mod = op3_prev * feedbackAmount;
    const op3_out = Math.sin(op3_phase + op3_mod);
    op3_prev = op3_out;
    op3_phase += inc3;

    // Op 2: Modulated by Op 3
    const op2_mod = op3_out * modIndexMatrix[2];
    const op2_out = Math.sin(op2_phase + op2_mod);
    op2_phase += inc2;

    // Op 1: Modulated by Op 2
    const op1_mod = op2_out * modIndexMatrix[1];
    const op1_out = Math.sin(op1_phase + op1_mod);
    op1_phase += inc1;

    // Op 0: Carrier modulated by Op 1
    const op0_mod = op1_out * modIndexMatrix[0];
    const op0_out = Math.sin(op0_phase + op0_mod);
    op0_phase += inc0;

    // Direct write or voice output accumulation
    // Note: If writing to a flattened buffer, compute linear index:
    // output[voiceIdx * 1024 + i] = op0_out;
  }

  // Returning the final carrier output of the block for illustration
  return op0_phase;
})
.setOutput([NUM_VOICES]);

Addressing Cross-Block Feedback Continuity

When streaming audio via the Web Audio API's AudioWorkletNode, synthesis occurs over continuous windows (typically 128 samples). To prevent audible clicks, the feedback state \(y[n-1]\) and the accumulator phases must persist across worklet render calls.

To achieve continuous feedback:

  1. State Persistence Buffers: Maintain a state array on the CPU or an input texture containing the terminal phases and the last output sample of the feedback operator from block \(k-1\).
  2. State Injection: Pass these terminal values into the gpu.js kernel as uniform arrays at the beginning of block \(k\).
  3. State Extraction: Output the final phases and feedback sample alongside the computed audio samples so they can be re-supplied into the next cycle.

Audio Pipeline Integration

To output the computed GPU buffers through the Web Audio API:

  1. Create an AudioWorkletProcessor.
  2. Instantiate gpu.js inside the main thread or directly inside an AudioWorklet (if WebGL/WebGPU context access is available via OffscreenCanvas).
  3. If using the main thread, dispatch the kernel, copy the raw Float32Array output to an intermediate shared buffer (SharedArrayBuffer), and let the AudioWorklet consume the rendered frames using a ring buffer to maintain an uninterrupted playback stream.
