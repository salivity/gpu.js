Implementing Conway's Game of Life with gpu.js

This article explains how to build Conway's Game of Life as a 2D cellular automaton using gpu.js to achieve massive parallel acceleration. By offloading state evaluations from the CPU to WebGL compute shaders, the grid updates all cells simultaneously rather than iterating sequentially through nested loops. You will learn the mechanics of the compute kernel, neighbor counting on the GPU, handling boundary conditions, and managing generational state updates.

Understanding the GPU Architecture for Cellular Automata

Conway's Game of Life operates on a uniform 2D grid where every cell's next state depends entirely on its own current state and the states of its eight immediate neighbors. On a CPU, evaluating a large grid requires \(O(W \times H)\) sequential iterations, which rapidly bottlenecks JavaScript performance.

The library gpu.js bridges JavaScript and WebGL by transpiling written JavaScript functions into GLSL (OpenGL Shading Language) compute shaders. When compiling a 2D kernel, the GPU assigns individual hardware execution threads to each coordinate (x, y) across the grid. Every cell computes its transition rules independently and concurrently in parallel.

Setting Up the 2D Kernel

To build the simulation, initialize an instance of GPU and compile a kernel configured with a two-dimensional output dimension matching the grid's width and height.

Inside the kernel function, gpu.js exposes the thread's execution coordinates via this.thread.x and this.thread.y. These variables represent the column and row of the target cell being evaluated.

const gpu = new GPU();

const updateLife = gpu.createKernel(function(grid, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;
    
    // Count alive neighbors using toroidal wrapping
    let neighbors = 0;
    
    for (let dy = -1; dy <= 1; dy++) {
        for (let dx = -1; dx <= 1; dx++) {
            if (dx === 0 && dy === 0) continue;
            
            const nx = (x + dx + width) % width;
            const ny = (y + dy + height) % height;
            
            neighbors += grid[ny][nx];
        }
    }
    
    const currentState = grid[y][x];
    
    // Conway's Rules: B3/S23
    if (currentState === 1) {
        if (neighbors === 2 || neighbors === 3) {
            return 1; // Survives
        }
        return 0; // Underpopulation or Overpopulation
    } else {
        if (neighbors === 3) {
            return 1; // Reproduction
        }
        return 0; // Remains dead
    }
})
.setOutput([width, height])
.setPipeline(true);

Neighbor Counting and Boundary Handling

The standard Conway's rules use the 8-cell Moore neighborhood. Within the kernel, two nested loops from -1 to 1 query surrounding states, skipping dx === 0 && dy === 0.

Boundary conditions can be handled in two ways:

  1. Toroidal Wrapping: As shown in the snippet above, using modulo arithmetic (coordinate + offset + dimension) % dimension creates a continuous wrap-around universe.
  2. Fixed Boundaries: Discarding coordinates outside [0, width - 1] or [0, height - 1] treats edges as perpetually dead cells.

Because shader execution is uniform across threads, keep arithmetic branchless or light to avoid shader warp divergence.

Optimizing with Pipeline Mode

Passing arrays between JavaScript and the GPU introduces memory transfer overhead. To sustain high frame rates:

  1. Enable pipeline mode via .setPipeline(true). This instructs gpu.js to output WebGL textures directly into GPU memory rather than serializing the result back to a JavaScript array.
  2. Employ a double-buffering (ping-pong) loop: pass the output texture of generation \(N\) directly as the input grid parameter for generation \(N + 1\).
  3. When visual rendering is needed, compile a separate rendering kernel that outputs directly to a <canvas> element via .setOutput([width, height]).setGraphical(true).

By maintaining the cellular state completely in GPU texture memory, this 2D cellular automaton can simulate millions of cells at native 60 FPS.
