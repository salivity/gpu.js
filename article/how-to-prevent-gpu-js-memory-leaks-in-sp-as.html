How to Prevent gpu.js Memory Leaks in SPAs

Dynamic single-page applications (SPAs) that mount and unmount component tabs using gpu.js often suffer from severe memory degradation, browser tab crashes, and WebGL context loss. Because the JavaScript garbage collector does not automatically release underlying GPU memory and WebGL contexts when DOM nodes are removed, developers must enforce strict manual lifecycle cleanup patterns. This article explains the underlying causes of gpu.js memory leaks during dynamic tab switching and provides practical implementation strategies to properly dispose of kernels, canvases, and WebGL contexts.

Understand the Cause of WebGL Leaks

Browsers impose a strict limit on the number of active WebGL contexts allowed simultaneously (typically between 8 and 16). When a component initializing a new GPU() instance is unmounted, JavaScript may free the local variable references, but the browser retains the allocated WebGL rendering context, textures, and compiled shaders in VRAM. If a user switches between tabs repeatedly, new contexts are created until the browser hits its limit, causing existing contexts to crash and uncollected memory to balloon.

Explicitly Destroy Kernels and the GPU Instance

The most crucial step in preventing leaks is calling the native cleanup methods provided by gpu.js. Never let a kernel or instance fall out of scope without explicit disposal.

  1. Destroy Kernels: Call .destroy() on every compiled kernel function to release its associated WebGL textures and framebuffers.
  2. Destroy the GPU Instance: Call gpu.destroy() to tear down the underlying canvas, WebGL context, and all associated resources.
// Example: Complete teardown sequence
function cleanupGpuResources(gpuInstance, kernels = []) {
  // 1. Destroy individual kernels
  kernels.forEach(kernel => {
    if (kernel && typeof kernel.destroy === 'function') {
      kernel.destroy(true); // pass true to detach sub-dependencies if applicable
    }
  });

  // 2. Destroy the main GPU instance
  if (gpuInstance && typeof gpuInstance.destroy === 'function') {
    gpuInstance.destroy();
  }
}

Force Context Loss on Unmount

In environments where gpu.destroy() does not immediately release hardware context handles, manually trigger context loss via the WEBGL_lose_context extension. This immediately signals to the browser driver that hardware resources should be freed.

function forceContextLoss(canvas) {
  if (!canvas) return;
  
  const gl = canvas.getContext('webgl2') || canvas.getContext('webgl');
  if (gl) {
    const loseContextExt = gl.getExtension('WEBGL_lose_context');
    if (loseContextExt) {
      loseContextExt.loseContext();
    }
  }
}

Implement Framework Lifecycle Hooks

Ensure destruction routines are bound strictly to component unmounting hooks in your SPA framework.

React Pattern

Use the return cleanup function inside useEffect:

import React, { useEffect, useRef } from 'react';
import { GPU } from 'gpu.js';

export function GpuComputeTab() {
  const gpuRef = useRef(null);
  const kernelRef = useRef(null);

  useEffect(() => {
    const gpu = new GPU();
    gpuRef.current = gpu;

    const kernel = gpu.createKernel(function() {
      return this.thread.x * 2;
    }).setOutput([1024]);
    
    kernelRef.current = kernel;

    return () => {
      if (kernelRef.current) kernelRef.current.destroy();
      if (gpuRef.current) gpuRef.current.destroy();
      gpuRef.current = null;
      kernelRef.current = null;
    };
  }, []);

  return <div>GPU Tab Active</div>;
}

Vue Pattern

Use onBeforeUnmount in the Composition API:

import { onMounted, onBeforeUnmount } from 'vue';
import { GPU } from 'gpu.js';

export default {
  setup() {
    let gpu = null;
    let kernel = null;

    onMounted(() => {
      gpu = new GPU();
      kernel = gpu.createKernel(function () {
        return this.thread.x + 1;
      }).setOutput([512]);
    });

    onBeforeUnmount(() => {
      if (kernel) kernel.destroy();
      if (gpu) gpu.destroy();
      gpu = null;
      kernel = null;
    });
  }
};

Share a Persistent GPU Instance (Singleton Pattern)

Instead of creating and destroying a new GPU() instance every time a user switches tabs, use a shared service or singleton module.

  • Initialize a single GPU context at the application root or store level.
  • Keep the context alive across the entire user session.
  • Only compile or reassign kernels when switching into the compute tab, and destroy only the kernels—not the base context—upon leaving the tab.

This architectural shift bypasses WebGL context limits entirely, avoids initialization overhead, and ensures stable memory consumption regardless of how frequently users toggle between views.
