Can GPU.js Process Labelled Break Statements?

The gpu.js Abstract Syntax Tree (AST) compiler cannot successfully process labelled break statements. While gpu.js translates standard JavaScript into WebGL-compatible GLSL (OpenGL Shading Language), its compiler lacks the translation logic for labelled jump targets, primarily because the underlying GLSL specification does not support labelled loops, multi-level breaks, or goto instructions.

The Limitation in the AST Compiler

gpu.js operates by parsing written JavaScript functions into an AST using a JavaScript parser. During this process, it walks through each AST node and converts JavaScript syntax into corresponding GLSL code.

When encountering a standard BreakStatement without an identifier (a simple break;), the compiler translates it directly into the native C-style break; statement supported by GLSL. However, when a label identifier is attached to the break statement (such as break outerLoop;), the compiler fails. The AST traversal mechanism in gpu.js does not contain an implementation to map labelled AST jump nodes to GLSL-compliant control flow structures. Depending on the version of gpu.js, this will either trigger an unsupported syntax compilation error during AST validation or generate invalid GLSL code that fails to compile on the GPU.

The Underlying GLSL Constraint

Even if the AST compiler were modified to parse the label AST node, GLSL itself imposes strict architectural constraints on control flow:

  • GLSL only permits break statements to exit the immediately enclosing for, while, do-while, or switch construct.
  • GLSL has no syntax for labels or arbitrary jumping mechanisms.
  • Emulating a labelled break in shader languages requires synthetically flattening control structures or inserting conditional state variables.

Because gpu.js relies on a mostly direct syntax-to-syntax conversion strategy, it does not rewrite deeply nested loop ASTs into complex flag-checking structures.

Recommended Workarounds

To achieve the behavior of a labelled break within a gpu.js kernel, code must be restructured using patterns native to GLSL:

  1. State Flags: Use a boolean variable outside the inner loop. Set the boolean to true when the exit condition is met, trigger a standard break; in the inner loop, and check that boolean in the outer loop to break immediately.
  2. Loop Invariants: Modify the loop condition of the outer loop to evaluate a shared termination condition, allowing both loops to terminate sequentially.
  3. Early Returns: If the break is meant to terminate the entire computation for a given thread or invocation, replace the labelled break with a return statement, which GLSL natively supports.
