GPU.js Post-Processing: Distortion, Vignette & Aberration

GPU.js is fully capable of performing chromatic aberration, vignette, and lens distortion post-processing effects. By compiling JavaScript functions into WebGL fragment shaders, GPU.js executes high-performance pixel manipulations directly on the graphics card. Because these visual effects rely on mathematical transformations of pixel coordinates and color channels, they can be implemented using standard GPU.js kernels that operate on 2D image data or HTML canvas elements.

How GPU.js Handles Post-Processing

GPU.js works by transpiling written JavaScript code into GLSL (OpenGL Shading Language). In a post-processing context, an image or render canvas is passed into a GPU.js kernel as an input texture. The kernel runs simultaneously across every pixel, using the built-in this.thread.x and this.thread.y coordinates to determine the color of each output pixel.

Implementing Chromatic Aberration

Chromatic aberration simulates the failure of a lens to focus all colors to the same convergence point. It is achieved by splitting the color channels of an image and sampling them at slightly different coordinates.

In GPU.js, this is done by:

  1. Normalizing the thread coordinates to locate the pixel.
  2. Defining an offset vector that scales outward from the center of the image.
  3. Sampling the red channel from a coordinate shifted slightly outward, the green channel from the base coordinate, and the blue channel from a coordinate shifted inward.
  4. Combining the separated channels into a single output pixel color.

Implementing Vignette

A vignette effect darkens the edges of an image relative to the center, drawing focus to the middle. This is a purely mathematical operation based on radial distance.

In GPU.js, the vignette calculation involves:

  1. Converting this.thread.x and this.thread.y into normalized coordinates where the center of the image is (0, 0).
  2. Calculating the distance of the current thread from the center using the Pythagorean theorem or a distance formula.
  3. Using a smooth falloff function (such as a cosine or smoothstep function) to compute a darkening multiplier based on that distance.
  4. Multiplying the RGB values of the source pixel by this factor, leaving the center intact while darkening the borders.

Implementing Lens Distortion

Lens distortion—such as barrel or pincushion distortion—deforms an image by warping the coordinates non-linearly based on their distance from the optical axis.

In GPU.js, this requires reverse coordinate mapping:

  1. Normalizing the coordinates so the center is the origin (0, 0).
  2. Calculating the radius \(r\) from the center.
  3. Applying a polynomial distortion formula, typically altering the coordinate vector by a factor of \(1 + k_1 r^2 + k_2 r^4\), where \(k_1\) and \(k_2\) represent distortion coefficients. Negative values produce barrel distortion (bulging outward), while positive values create pincushion distortion (pinching inward).
  4. Sampling the original image at these newly calculated coordinates.

Performance and Considerations

Because GPU.js compiles directly to WebGL, these effects run at interactive frame rates suitable for real-time video or canvas animations. For maximum efficiency, all three effects should be combined into a single GPU.js kernel. Combining them avoids the performance overhead of passing intermediate textures back and forth between multiple shader passes, allowing distortion, chromatic shift, and vignette to be applied in a single computation per pixel.
