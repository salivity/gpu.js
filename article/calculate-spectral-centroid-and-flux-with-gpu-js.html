Calculate Spectral Centroid and Flux with gpu.js

This article explains how to compute two essential audio features—spectral centroid and spectral flux—in parallel across short-time Fourier transform (STFT) magnitude frames using gpu.js. By utilizing WebGL kernels, you offload the bin-level summations and frame-to-frame difference calculations to the GPU, making real-time or batch audio analysis significantly faster than standard CPU loops.

Input Data Representation

Both features rely on the magnitude spectrum of consecutive audio frames obtained via an STFT. The input should be formatted as a 2D array or texture of shape [numFrames][binCount], where:

  • numFrames is the total number of temporal windows analyzed.
  • binCount is the number of frequency bins per frame (typically \(\text{FFT size} / 2\)).

1. Spectral Centroid Kernel

The spectral centroid measures the "brightness" of a sound by calculating the center of mass of its spectrum. For a single frame, it is defined as:

\[\text{Centroid} = \frac{\sum_{k=0}^{N-1} f(k) \cdot M(k)}{\sum_{k=0}^{N-1} M(k)}\]

where \(M(k)\) is the magnitude of frequency bin \(k\), and \(f(k)\) is the corresponding frequency in Hertz (\(f(k) = \frac{k \cdot \text{SampleRate}}{2 \cdot N}\)).

To compute this across all frames in parallel, configure the kernel to output an array of size [numFrames]. Each GPU thread processes a single frame index (this.thread.x).

import { GPU } from 'gpu.js';

const gpu = new GPU();

function createSpectralCentroidKernel(numFrames, binCount) {
  return gpu.createKernel(function(magnitudes, binCount, sampleRate) {
    const frameIndex = this.thread.x;
    let weightedSum = 0;
    let totalSum = 0;
    const nyquist = sampleRate / 2;

    for (let k = 0; k < binCount; k++) {
      const mag = magnitudes[frameIndex][k];
      const freq = (k / binCount) * nyquist;
      weightedSum += freq * mag;
      totalSum += mag;
    }

    if (totalSum === 0) {
      return 0;
    }
    return weightedSum / totalSum;
  })
  .setOutput([numFrames]);
}

2. Spectral Flux Kernel

Spectral flux measures the rate of local spectral change between successive frames, commonly used in onset detection. It evaluates the difference between bin magnitudes of the current frame \(t\) and the previous frame \(t-1\).

Half-wave rectified flux (retaining only increases in energy) is standard:

\[\text{Flux}_t = \sum_{k=0}^{N-1} \max(0, M_t(k) - M_{t-1}(k))\]

The kernel assigns each thread to compute the flux for a single frame this.thread.x. The first frame (frameIndex === 0) evaluates to zero as there is no preceding frame.

function createSpectralFluxKernel(numFrames, binCount) {
  return gpu.createKernel(function(magnitudes, binCount) {
    const frameIndex = this.thread.x;
    
    // Boundary condition for the initial frame
    if (frameIndex === 0) {
      return 0;
    }

    let flux = 0;
    for (let k = 0; k < binCount; k++) {
      const diff = magnitudes[frameIndex][k] - magnitudes[frameIndex - 1][k];
      if (diff > 0) {
        flux += diff;
      }
    }

    return flux;
  })
  .setOutput([numFrames]);
}

Complete Execution Example

const sampleRate = 44100;
const binCount = 1024;
const numFrames = 500;

// Mock magnitude spectrum data: 500 frames by 1024 bins
const magnitudes = Array.from({ length: numFrames }, () =>
  Array.from({ length: binCount }, () => Math.random())
);

// Instantiate kernels
const centroidKernel = createSpectralCentroidKernel(numFrames, binCount);
const fluxKernel = createSpectralFluxKernel(numFrames, binCount);

// Compute features on GPU
const centroids = centroidKernel(magnitudes, binCount, sampleRate);
const fluxes = fluxKernel(magnitudes, binCount);

// Clean up GPU allocations when finished
centroidKernel.destroy();
fluxKernel.destroy();

Performance Considerations

  1. Memory Transfer Overhead: Passing deeply nested JavaScript arrays causes significant CPU-to-GPU data marshalling overhead. Use 1D Float32Array instances paired with flattened 2D index logic (magnitudes[frameIndex * binCount + k]) for larger audio buffers to avoid allocation bottlenecks.
  2. Dynamic Loop Bounds: GPU drivers require fixed unrolling hints or explicit dynamic loops. Passing binCount as an argument or inlining it via constants ensures cross-device compatibility.
