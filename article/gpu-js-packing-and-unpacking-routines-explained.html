gpu.js Packing and Unpacking Routines Explained

This article explores why gpu.js relies on internal packing and unpacking routines during GPU-accelerated computations. In gpu.js, packing and unpacking serve as essential encoding and decoding mechanisms that map standard JavaScript numerical data—specifically 32-bit floating-point numbers—to and from WebGL-compatible texture formats. These routines ensure that mathematical calculations retain full numerical precision and remain broadly compatible across different browsers, mobile devices, and graphics hardware.

The Underlying WebGL Limitation

gpu.js accelerates JavaScript by compiling code into GLSL (OpenGL Shading Language) and executing it on the graphics card via WebGL. Because WebGL was originally designed for rendering graphics rather than general-purpose computing (GPGPU), it processes outputs as color textures rather than arbitrary memory buffers.

In standard WebGL (especially WebGL 1.0), the default framebuffers and textures operate using four 8-bit color channels: Red, Green, Blue, and Alpha (RGBA). This structure provides a total of 32 bits per pixel, but divided into four separate bytes ranging from 0 to 255. Standard JavaScript numbers, however, are typically 64-bit floats or 32-bit single-precision floats. Without a way to reconcile this discrepancy, outputting complex mathematical results directly from a shader would lead to severe truncation or loss of precision.

The Purpose of Packing

Packing is the process of converting a single high-precision number into a 4-byte RGBA vector directly inside the GPU fragment shader.

  • 32-Bit Float Encoding: When a kernel outputs a standard 32-bit IEEE 754 floating-point number, the packing routine splits the sign, exponent, and mantissa across the four 8-bit channels (vec4(r, g, b, a)).
  • Hardware Portability: While modern WebGL extensions support native floating-point textures (like OES_texture_float or WebGL 2.0 targets), many mobile devices or older GPUs do not support rendering or reading directly from floating-point framebuffers. Packing ensures the output remains a standard 8-bit RGBA image that any WebGL implementation can render.

The Purpose of Unpacking

Unpacking is the complementary process that restores the original numerical value from the encoded RGBA structure. It happens in two primary scenarios:

  1. CPU Readback: Once the GPU finishes processing, gpu.js retrieves the pixel buffer using the standard WebGL method gl.readPixels(). Because gl.readPixels() reliably extracts only unsigned byte data in many environments, gpu.js unpacks these 4-byte pixels back into JavaScript 32-bit floating-point numbers using typed array buffers or CPU-side decoding logic.
  2. Multi-Pass Shaders: If a kernel requires the output of a previous computation as its input, the shader unpacks the encoded RGBA values from the input texture back into native GLSL floats before executing subsequent arithmetic operations.

Key Benefits of These Routines

  • Cross-Platform Consistency: Applications built with gpu.js can execute reliably on low-end hardware, mobile browsers, and modern desktops without throwing capability errors related to unsupported float textures.
  • Precision Preservation: Packing guarantees that 32-bit single-precision calculations are preserved bit-for-bit without being clamped to low-precision 8-bit color values.
  • Reliable Data Transfer: It provides a predictable pipeline for moving numerical arrays between the JavaScript main thread and GPU memory buffers.
