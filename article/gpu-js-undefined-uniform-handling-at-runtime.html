GPU.js Undefined Uniform Handling at Runtime

This article provides an overview of how GPU.js processes undefined uniform parameters when a compiled kernel is invoked at runtime. Because GPU.js translates JavaScript functions into strongly typed WebGL GLSL shaders, passing undefined values disrupts the data-binding layer between the CPU and GPU. Below, we examine the underlying mechanics of uniform passing in GPU.js, how the WebGL context responds to missing or undefined inputs, the differences between GPU and CPU execution modes, and strategies to prevent runtime execution failures.

The Role of Uniforms in GPU.js

In GPU.js, uniforms are read-only variables accessible across all parallel execution threads (work units) within a kernel. While JavaScript is dynamically typed, the underlying GPU target (GLSL via WebGL) requires strict type definitions, such as float, int, vec2, or sampler arrays.

When a kernel is defined and compiled, GPU.js analyzes the inputs or uses declared uniform types to construct the corresponding GLSL shader code. At runtime, whenever the kernel function is invoked with arguments intended for these uniforms, GPU.js uses the WebGL API (such as gl.uniform1f or gl.uniform1i) to bind the JavaScript values to the active GPU program.

Runtime Behavior When Passing undefined

When an argument mapped to a uniform resolves to undefined during a kernel invocation, the following behaviors occur:

1. WebGL Type Coercion and API Errors

WebGL uniform assignment methods expect specific primitive types (numbers, typed arrays, or WebGL textures). When GPU.js attempts to pass an undefined value to native WebGL functions:

  • Float and Integer Uniforms: WebGL method signatures (e.g., gl.uniform1f(location, value)) attempt to convert undefined into a number. In JavaScript, Number(undefined) results in NaN. Browsers running WebGL may either upload NaN directly to the GPU or generate a WebGL warning (such as TypeError: Failed to execute 'uniform1f' on 'WebGLRenderingContext': parameter 2 is not of type 'float'), failing the draw call.
  • Array and Texture Uniforms: If a uniform expects a texture or an array and receives undefined, GPU.js attempts to read properties like .length or bind the texture target. This directly throws an unhandled JavaScript runtime error: Cannot read properties of undefined.

2. Visual Artifacts or Zero-Value Fallbacks

If the WebGL driver converts NaN to a float without halting execution, arithmetic operations involving that uniform within the GLSL kernel will propagate NaN. Depending on how the output is mapped to pixels or array elements, the kernel typically returns all zeros, empty canvas buffers, or blank outputs.

3. CPU Mode Fallback Discrepancies

GPU.js includes a CPU fallback mode for environments lacking WebGL support or when explicitly configured. In CPU mode, the kernel function runs as native JavaScript in a series of loops. An undefined uniform will behave purely according to standard JavaScript rules:

  • Mathematical operations involving the uniform yield NaN.
  • Logical checks against undefined evaluate to false.
  • Array index accesses against an undefined uniform throw immediate TypeError exceptions.

This creates behavioral inconsistency: code that triggers an explicit WebGL uniform-binding error in GPU mode might silently produce an array filled with NaN in CPU mode.

Preventing Undefined Uniform Errors

Because GPU.js does not automatically sanitize runtime arguments or assign default fallback values to missing uniforms, values must be properly validated before triggering execution:

  1. Default Argument Values: Use standard JavaScript default parameters in wrapper functions or kernel calls: 
    const myKernel = gpu.createKernel(function(multiplier) {
    return this.thread.x * multiplier;
}).setOutput([100]);

// Ensure a valid fallback exists
function runKernel(multiplier = 1.0) {
    return myKernel(multiplier);
}
  2. Explicit Type Declarations: Utilize the constants or explicit uniforms configuration options provided by GPU.js to lock in variable types, and verify variables are fully defined before dispatching computations to the GPU pipeline.
