Soft Body Deformation with GPU.js

Simulating soft body deformation in the browser requires calculating physics interactions—such as elastic restoring forces, damping, and collision responses—across hundreds or thousands of vertices simultaneously. This article demonstrates how to implement a high-performance, real-time mass-spring soft body simulation under external forces using gpu.js. By offloading vertex integration and force calculations to WebGL shaders through gpu.js, you can achieve interactive frame rates that CPU-bound JavaScript loops cannot sustain.

The Physics Model: Mass-Spring System

A standard approach for simulating soft bodies is a mass-spring-damper network. The object is discretized into a set of particles (mass points) connected by structural, shear, and bending springs.

The net force acting on each particle \(i\) is the sum of internal spring forces and external forces:

\[\mathbf{F}_{total, i} = \mathbf{F}_{ext} + \sum_{j \in N(i)} (\mathbf{F}_{spring, ij} + \mathbf{F}_{damping, ij})\]

  • Hooke's Law (Spring Force): \(\mathbf{F}_{spring, ij} = -k_s (\|\mathbf{x}_i - \mathbf{x}_j\| - L_{0, ij}) \frac{\mathbf{x}_i - \mathbf{x}_j}{\|\mathbf{x}_i - \mathbf{x}_j\|}\)
  • Damping Force: \(\mathbf{F}_{damping, ij} = -k_d (\mathbf{v}_i - \mathbf{v}_j)\)
  • External Forces (\(\mathbf{F}_{ext}\)): Gravity (\(m \cdot \mathbf{g}\)), user interactions (such as cursor drag forces), and contact impulses.

Data Representation for GPU.js

Because GPU kernels execute in parallel across independent threads, data must be structured in flat arrays or textures rather than nested object-oriented graphs.

For a 2D soft body mesh of dimensions \(W \times H\):

  1. Positions (pos): A \(2 \times N\) array storing \((x, y)\) coordinates.
  2. Velocities (vel): A \(2 \times N\) array storing \((v_x, v_y)\) components.
  3. Rest Lengths: Pre-calculated distances between neighboring nodes.

Step 1: Initialize GPU.js

Install and import gpu.js, then create a GPU instance:

import { GPU } from 'gpu.js';

const gpu = new GPU();

Step 2: Compute Internal and External Forces Kernel

The first kernel calculates the combined forces acting on each vertex. To optimize GPU memory access, particles only sample their immediate neighbors (left, right, up, down).

const computeForces = gpu.createKernel(function(positions, velocities, restLength, stiffness, damping, gravityY, extForceX, extForceY, extIndex, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;
    const index = y * width + x;

    const px = positions[0][index];
    const py = positions[1][index];
    const vx = velocities[0][index];
    const vy = velocities[1][index];

    let fx = 0.0;
    let fy = gravityY; // Apply constant external gravity

    // Apply external localized interaction force (e.g., mouse pull)
    if (index === extIndex) {
        fx += extForceX;
        fy += extForceY;
    }

    // Evaluate 4-way adjacent spring connections
    // Neighbor offsets: [dx, dy]
    const neighbors = [
        [-1, 0], [1, 0], [0, -1], [0, 1]
    ];

    for (let i = 0; i < 4; i++) {
        const nx = x + neighbors[i][0];
        const ny = y + neighbors[i][1];

        if (nx >= 0 && nx < width && ny >= 0 && ny < height) {
            const nIndex = ny * width + nx;
            const dx = positions[0][nIndex] - px;
            const dy = positions[1][nIndex] - py;
            const dist = Math.sqrt(dx * dx + dy * dy);

            if (dist > 0.0001) {
                // Spring force
                const springMag = stiffness * (dist - restLength);
                fx += (dx / dist) * springMag;
                fy += (dy / dist) * springMag;

                // Damping force relative to neighbor
                fx += damping * (velocities[0][nIndex] - vx);
                fy += damping * (velocities[1][nIndex] - vy);
            }
        }
    }

    return [fx, fy];
})
.setOutput([width, height])
.setPipeline(true);

Step 3: Numerical Integration Kernel

Using the forces computed in the previous step, update velocities and positions via Semi-Implicit Euler integration:

const integrate = gpu.createKernel(function(positions, velocities, forces, dt, mass, groundY, width) {
    const coord = this.thread.x; // 0 for X, 1 for Y
    const index = this.thread.y;

    const f = forces[coord][index];
    let v = velocities[coord][index] + (f / mass) * dt;
    let p = positions[coord][index] + v * dt;

    // Floor collision handling (External reaction force)
    if (coord === 1 && p < groundY) {
        p = groundY;
        v = -v * 0.3; // Restitution / bounce loss
    }

    return [p, v];
})
.setOutput([2, totalParticles]);

Step 4: The Simulation Loop

Chain the kernels together inside an animation frame loop:

function stepSimulation() {
    // 1. Calculate internal elastic forces + external inputs
    const forces = computeForces(
        currentPositions, 
        currentVelocities, 
        restDistance, 
        stiffnessCoefficient, 
        dampingCoefficient, 
        -9.81,           // External gravity
        userForceX,      // External user impulse
        userForceY, 
        targetIndex, 
        gridWidth, 
        gridHeight
    );

    // 2. Integrate acceleration into velocity and position
    const nextState = integrate(
        currentPositions, 
        currentVelocities, 
        forces, 
        deltaTime, 
        particleMass, 
        0.0,             // Ground level
        gridWidth
    );

    // 3. Extract updated positions and velocities
    currentPositions = nextState.map(p => p[0]);
    currentVelocities = nextState.map(p => p[1]);

    requestAnimationFrame(stepSimulation);
}

Performance Considerations

  1. Pipeline Mode: Use .setPipeline(true) on your kernels. This keeps the data in WebGL texture memory between computation passes, preventing expensive GPU-to-CPU data readbacks on every frame.
  2. Topology Storage: For complex 3D meshes where regular grid indexing cannot be used, pass an adjacency lookup texture that defines connected vertex indices for each node.
  3. Time Step Stability: Explicit integration can become unstable under high stiffness (\(k_s\)). Use sub-stepping (running multiple smaller integration steps of \(dt / N\) per visual render frame) to maintain soft body stability without introducing structural collapse.
