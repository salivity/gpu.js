Run GPU.js in Headless Node.js Environments

Running GPU.js on a headless Node.js server allows you to offload computationally heavy tasks to the GPU without requiring a graphical display or web browser. Because Node.js lacks native WebGL support, configuring GPU.js in a server environment requires installing native system graphics libraries, using the gl (headless-gl) package as an underlying WebGL context, and properly configuring the GPU instance in your code. This guide walks you through the system requirements, package installation, and code configuration needed to achieve hardware-accelerated computation on a headless server.

1. Install System Dependencies

Before installing Node.js packages, you must install the native development libraries required by headless-gl to compile and interface with your GPU.

On Ubuntu or Debian-based systems, run:

sudo apt-get update
sudo apt-get install -y build-essential libxi-dev libglu1-mesa-dev libglew-dev pkg-config

If you are using a dedicated NVIDIA GPU, ensure that the proprietary NVIDIA drivers and the CUDA toolkit are installed on the host system.

2. Install Node.js Packages

In your project directory, install gpu.js along with the gl package:

npm install gpu.js gl

The gl package provides the headless WebGL implementation that GPU.js uses to execute kernels when no browser window or display server (like X11 or Wayland) is present.

3. Initialize GPU.js in Node.js

Import GPU from gpu.js and instantiate it. GPU.js will automatically detect the presence of the gl package in a Node.js environment and attempt to leverage the server's GPU.

const { GPU } = require('gpu.js');

// Initialize with GPU mode explicitly requested
const gpu = new GPU({
  mode: 'gpu'
});

// Define a sample computation kernel
const matrixMultiply = gpu.createKernel(function(a, b) {
  let sum = 0;
  for (let i = 0; i < 512; i++) {
    sum += a[this.thread.y][i] * b[i][this.thread.x];
  }
  return sum;
}).setOutput([512, 512]);

// Verify runtime mode
console.log(`GPU.js is running in mode: ${gpu.mode}`);

4. Handling Fallbacks and Verification

If the headless server lacks a compatible GPU or driver configuration, GPU.js will throw an error if forced into mode: 'gpu'. To allow graceful degradation to multi-threaded CPU execution, configure the initialization or handle errors dynamically:

const { GPU } = require('gpu.js');

let gpu;

try {
  gpu = new GPU({ mode: 'gpu' });
  console.log('Hardware acceleration enabled via headless-gl.');
} catch (error) {
  console.warn('GPU unavailable. Falling back to CPU mode:', error.message);
  gpu = new GPU({ mode: 'cpu' });
}

5. Running inside Docker (Optional)

When deploying to a headless containerized environment, base your image on an OS that includes the required Mesa or NVIDIA container runtimes:

FROM node:18-bullseye

# Install graphics dependencies
RUN apt-get update && apt-get install -y \
    build-essential \
    libxi-dev \
    libglu1-mesa-dev \
    libglew-dev \
    pkg-config \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /usr/src/app

COPY package*.json ./
RUN npm install

COPY . .

CMD ["node", "index.js"]

If passing through an NVIDIA GPU to Docker, ensure your host uses the NVIDIA Container Toolkit and run the container with the --gpus all flag:

docker run --gpus all my-gpu-app
