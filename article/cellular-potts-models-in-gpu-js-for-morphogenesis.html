Cellular Potts Models in gpu.js for Morphogenesis

This article provides a practical guide to implementing the Cellular Potts Model (CPM) for simulating biological tissue morphogenesis using gpu.js. It covers the mathematical formulation of the Hamiltonian, strategies to circumvent the sequential nature of traditional Monte Carlo methods on parallel architectures, and the step-by-step creation of GPU kernels for energy evaluation, state updates, and visualization in the browser.

The Cellular Potts Model Framework

The Cellular Potts Model (also known as the Glazier-Graner-Hogeweg model) represents cells as collections of contiguous pixels (or voxels) on a discrete lattice. Each lattice site \(\vec{x}\) is assigned a spin value \(\sigma(\vec{x})\) identifying the cell occupying that site, alongside a cell type \(\tau(\sigma(\vec{x}))\).

Morphogenesis is driven by minimizing a system Hamiltonian \(H\), typically defined as:

\[H = \sum_{(\vec{x}, \vec{x}')} J(\tau(\sigma(\vec{x})), \tau(\sigma(\vec{x}'))) (1 - \delta(\sigma(\vec{x}), \sigma(\vec{x}'))) + \sum_{\sigma} \lambda_{V} (V(\sigma) - V_0(\sigma))^2\]

  • Adhesion Energy (\(J\)): Quantifies contact energy between neighboring lattice sites belonging to different cells.
  • Volume Constraint (\(\lambda_V\)): Penalizes deviations of the cell's current volume \(V(\sigma)\) from its target volume \(V_0(\sigma)\).

Dynamic evolution is typically executed using a modified Metropolis algorithm: a source site attempts to copy its spin into an adjacent target site, with acceptance dictated by the change in energy:

\[P(\Delta H) = \begin{cases} 1 & \text{if } \Delta H \le 0 \\ e^{-\Delta H / T} & \text{if } \Delta H > 0 \end{cases}\]

where \(T\) corresponds to biological cell membrane fluctuation amplitude.

Overcoming GPU Parallelization Bottlenecks

Standard CPM runs sequentially using Metropolis-Hastings updates. Writing simultaneously to neighboring sites on a GPU creates race conditions and violates detailed balance.

To parallelize CPM execution in gpu.js:

  1. Sub-Lattice (Checkerboard) Decomposition: Divide the lattice into non-interacting sets (e.g., 2-color checkerboard for von Neumann neighborhoods, or 4-phase/9-phase blocks for Moore neighborhoods). In each phase, only sites in the active set evaluate spin copies from their immediate neighbors, ensuring no neighboring sites update at the exact same time.
  2. Volume Reduction Decoupling: Global volume calculation requires an aggregation pass. In gpu.js, compute volume arrays via an accumulation kernel or run an auxiliary reduction pass between sub-lattice update cycles.

Implementation in gpu.js

1. Setup and Lattice Representation

Install gpu.js and initialize the context. Store the spatial domain as a 2D array where each element contains the cell ID \(\sigma(\vec{x})\).

const { GPU } = require('gpu.js');
const gpu = new GPU();

const WIDTH = 256;
const HEIGHT = 256;
const NUM_CELLS = 50;

// Initialize lattice with background (0) and assigned cell IDs (1..NUM_CELLS)
let lattice = new Int32Array(WIDTH * HEIGHT);
// Seed cells at random positions...

2. Calculating Adhesion and Target Candidates

Due to limitations of GLSL transpilation in gpu.js (e.g., constrained dynamic memory allocation), store contact energies in a flat 1D texture or matrix of size NUM_TYPES x NUM_TYPES.

Define the checkerboard update kernel. The following example processes a red-black pass (phase = 0 or 1):

const cpmKernel = gpu.createKernel(function(grid, phase, seed, T, J_MATRIX) {
    const x = this.thread.x;
    const y = this.thread.y;
    const width = this.constants.width;
    const height = this.constants.height;

    // Check if the current pixel belongs to the active checkerboard phase
    if ((x + y) % 2 !== phase) {
        return grid[y][x];
    }

    // Pseudo-random neighbor selection (Von Neumann)
    const rand = Math.sin(x * 12.9898 + y * 78.233 + seed) * 43758.5453;
    const dir = Math.floor(Math.abs(rand) % 4);

    let nx = x;
    let ny = y;
    if (dir === 0) nx = (x + 1) % width;
    else if (dir === 1) nx = (x - 1 + width) % width;
    else if (dir === 2) ny = (y + 1) % height;
    else if (dir === 3) ny = (y - 1 + height) % height;

    const sourceSpin = grid[ny][nx];
    const targetSpin = grid[y][x];

    if (sourceSpin === targetSpin) {
        return targetSpin;
    }

    // Compute local adhesion energy before proposed copy
    // (Exemplified with 4-neighborhood sum)
    let H_before = 0.0;
    let H_after = 0.0;

    // Evaluate bonds with immediate neighbors
    const neighborsX = [x + 1, x - 1, x, x];
    const neighborsY = [y, y, y + 1, y - 1];

    for (let i = 0; i < 4; i++) {
        const checkX = (neighborsX[i] + width) % width;
        const checkY = (neighborsY[i] + height) % height;
        const neighborSpin = grid[checkY][checkX];

        // Contact energy before copy
        if (targetSpin !== neighborSpin) {
            H_before += 2.0; // Retrieve from J_MATRIX via cell type lookup
        }
        // Contact energy after copy
        if (sourceSpin !== neighborSpin) {
            H_after += 2.0;
        }
    }

    const deltaH = H_after - H_before;

    // Metropolis Acceptance Rule
    if (deltaH <= 0.0) {
        return sourceSpin;
    } else {
        const acceptProb = Math.exp(-deltaH / T);
        const roll = Math.abs(Math.cos(rand * 1.5)) % 1.0;
        if (roll < acceptProb) {
            return sourceSpin;
        }
    }

    return targetSpin;
}, {
    constants: { width: WIDTH, height: HEIGHT },
    output: [WIDTH, HEIGHT],
    pipeline: true // Keeps output in texture memory for sequential passes
});

3. Integrating Area/Volume Conservation

Strict volume constraints require updating cell sizes dynamically:

  1. Volume Count Kernel: Compute the area of each cell by running an aggregation pass where each cell ID increments a corresponding index in an area array.
  2. Global Integration: Include the volume penalty \(\Delta H_{vol} = \lambda_V \left[ (V_{new} - V_0)^2 - (V_{old} - V_0)^2 \right]\) within the cpmKernel. Pass the volume table as an auxiliary input texture.

4. The Simulation Loop

To perform continuous morphogenesis, alternate the phases, swap GPU textures, and render to a canvas:

let currentGrid = lattice;
let seed = 0;

function stepSimulation() {
    seed += 0.01;
    
    // Pass 1: Even phase update
    let textureEven = cpmKernel(currentGrid, 0, seed, 10.0, jMatrix);
    
    // Pass 2: Odd phase update
    let textureOdd = cpmKernel(textureEven, 1, seed + 1.0, 10.0, jMatrix);

    currentGrid = textureOdd;
}

5. Real-Time Visualization

gpu.js supports rendering directly to an HTML5 canvas without reading data back to the CPU using graphical kernels:

const renderKernel = gpu.createKernel(function(grid) {
    const spin = grid[this.thread.y][this.thread.x];
    if (spin === 0) {
        this.color(0.1, 0.1, 0.1, 1.0); // Background
    } else {
        // Color mapping derived from spin ID
        const r = (spin * 37 % 255) / 255;
        const g = (spin * 59 % 255) / 255;
        const b = (spin * 83 % 255) / 255;
        this.color(r, g, b, 1.0);
    }
})
.setOutput([WIDTH, HEIGHT])
.setGraphical(true);

function renderLoop() {
    stepSimulation();
    renderKernel(currentGrid);
    requestAnimationFrame(renderLoop);
}

Optimization Notes

  • Pipeline Mode: Set pipeline: true on iterative simulation kernels to maintain textures entirely within VRAM, preventing CPU-GPU bus bottlenecks.
  • Neighborhood Size: Using higher-order neighborhoods (e.g., 2nd- or 3rd-order Euclidean neighbors) reduces lattice anisotropy (grid bias) in cell shapes, but requires expanding the checkerboard decomposition to an \(N \times N\) block-stride pattern to avoid race conditions.
