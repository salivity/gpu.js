Recursive Functions in GPU.js Kernels

This article examines how gpu.js handles recursive function calls within custom kernel functions, detailing the technical constraints imposed by WebGL and GLSL that prevent recursion, the resulting errors developers encounter, and the standard iterative workarounds used to achieve equivalent logic on the GPU.

The Short Answer: Recursion Is Not Supported

GPU.js does not support recursive function calls inside custom kernel functions. If you attempt to define and call a function recursively within a kernel, the kernel will fail to compile or throw a runtime transpile error.

Why GPU.js Cannot Handle Recursion

GPU.js works by transpiling JavaScript functions into WebGL shader code (specifically GLSL—OpenGL Shading Language) so they can execute on the GPU. The limitation with recursion originates directly from the architecture of graphics processing units and the GLSL specification:

  1. GLSL Specification Limits: The GLSL ES specification that WebGL relies on explicitly disallows recursive function calls. The shader compiler must be able to statically determine function call paths and inline them or allocate resources ahead of execution.
  2. Lack of a Dynamic Call Stack: Unlike a CPU, which maintains a deep dynamic call stack to track return addresses and local execution states during recursive steps, GPU execution pipelines are designed for massive parallelism across thousands of lightweight threads. Traditional GPUs do not maintain a call stack for each individual thread due to memory overhead and hardware complexity.

When the GPU.js compiler parses your JavaScript code into an Abstract Syntax Tree (AST) to generate GLSL, it cannot resolve recursive dependency trees, resulting in shader compilation errors.

Workarounds for Recursive Logic in GPU.js

Because recursion is fundamentally unsupported on the underlying graphics pipeline, algorithms typically designed recursively must be rewritten iteratively.

1. Converting Recursion to Loops

Most standard recursive patterns (such as factorials, tree traversals, or binary searches) can be translated into standard for or while loops.

For example, a recursive countdown or calculation should be rewritten as:

const kernel = gpu.createKernel(function(values) {
    let result = 0;
    for (let i = 0; i < 100; i++) {
        // Iterative operations replacing recursive steps
        result += values[this.thread.x] * i;
    }
    return result;
}).setOutput([512]);

Ensure that loop termination conditions are deterministic whenever possible, as unbounded dynamic loops can degrade GPU performance or exceed timeout limits imposed by the browser.

2. Manual Stack Simulation

For non-tail-recursive algorithms (such as depth-first search or certain fractal generation tasks), you can simulate a call stack using fixed-size arrays.

Because dynamic array allocations are also constrained in GLSL, you must define an array with a fixed maximum size to serve as the stack, tracking the current stack pointer manually:

const kernel = gpu.createKernel(function() {
    let stack[32]; // Fixed-size stack
    let stackPointer = 0;

    // Push to stack
    stack[stackPointer] = 10;
    stackPointer++;

    let total = 0;

    // Process stack iteratively
    while (stackPointer > 0) {
        stackPointer--;
        let current = stack[stackPointer];
        total += current;

        // Conditional push
        if (current > 1 && stackPointer < 31) {
            stack[stackPointer] = current - 1;
            stackPointer++;
        }
    }

    return total;
}).setOutput([1]);

Summary

GPU.js cannot execute recursive functions because its underlying target language, GLSL, lacks call-stack capabilities and forbids recursion by specification. When writing kernels in gpu.js, algorithms must always be flattened into loops or managed with static, manually allocated array stacks.
