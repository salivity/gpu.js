Pass Texture Output Between Kernels in GPU.js

In GPU.js, transferring intermediate calculation results back to the CPU creates an expensive memory transfer bottleneck that drastically slows down computational pipelines. You can eliminate this latency by enabling pipelining, which keeps computation on the GPU by outputting WebGL textures from one kernel and passing them directly into another without reading pixels back into JavaScript memory.

Enabling Pipeline Mode

By default, a GPU.js kernel compiles its result into a standard JavaScript array or typed array, which forces the GPU to transfer data back to the CPU. To override this behavior, chain .setPipeline(true) to your kernel declaration. This configuration directs the kernel to return an internal Texture object containing the raw WebGL texture reference.

Step-by-Step Implementation

To chain kernels, set the first kernel to output a pipeline texture, pass that returned texture as a parameter to the second kernel, and then extract the final computation back into a readable array.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// 1. Define the first kernel with pipeline mode enabled
const firstKernel = gpu.createKernel(function (inputMatrix) {
    return inputMatrix[this.thread.y][this.thread.x] * 2.0;
})
.setOutput([512, 512])
.setPipeline(true);

// 2. Define the second kernel to accept and process the texture
const secondKernel = gpu.createKernel(function (textureInput) {
    const value = textureInput[this.thread.y][this.thread.x];
    return value + 10.0;
})
.setOutput([512, 512]);

// 3. Execute the pipeline
const initialData = [/* 512x512 array */];

// Generates a GPU Texture object instead of an Array
const intermediateTexture = firstKernel(initialData);

// Passes the GPU Texture directly into the next kernel
const finalResult = secondKernel(intermediateTexture);

Chaining Multiple Pipelined Kernels

If you have three or more steps, enable .setPipeline(true) on every intermediate kernel. When you are ready to consume the final result on the CPU, you can either:

  1. Leave .setPipeline(false) on the final kernel in the sequence (the default state).
  2. Call the .toArray() method directly on the final returned Texture instance if all kernels use pipeline mode.
const step1 = kernelA.setPipeline(true)(data);
const step2 = kernelB.setPipeline(true)(step1);
const finalTexture = kernelC.setPipeline(true)(step2);

// Extract the final result to CPU memory
const result = finalTexture.toArray();

Managing Texture Memory

When working with continuous frame updates or iterative loops (such as physics simulations or cellular automata), uncollected GPU textures can lead to VRAM exhaustion. Clean up intermediate textures manually using .delete() if they are created dynamically inside a render loop and are no longer referenced by subsequent operations:

let currentTexture = initialTexture;

for (let i = 0; i < iterations; i++) {
    const nextTexture = iterateKernel(currentTexture);
    
    // Delete the previous texture if it is no longer the initial input
    if (currentTexture !== initialTexture) {
        currentTexture.delete();
    }
    
    currentTexture = nextTexture;
}

const finalOutput = currentTexture.toArray();
currentTexture.delete();
