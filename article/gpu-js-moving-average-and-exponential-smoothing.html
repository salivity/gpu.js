GPU.js Moving Average and Exponential Smoothing

This guide demonstrates how to accelerate time-series data analysis by calculating Simple Moving Averages (SMA) and Exponential Moving Averages (EMA) using GPU.js. By compiling JavaScript functions into WebGL or OpenCL shaders, GPU.js allows you to process large numerical arrays in parallel directly on the GPU, significantly reducing calculation times for windowed calculations and exponential smoothing models.

Setting Up GPU.js

Install GPU.js via npm or include it via a CDN in your project. Initialize a new GPU instance to compile and run your computational kernels.

npm install gpu.js
const { GPU } = require('gpu.js');
const gpu = new GPU();

Calculating Simple Moving Averages (SMA)

The Simple Moving Average computes the unweighted mean of the previous \(n\) data points for each position in the series. Because each output index can be calculated independently, it is an ideal candidate for parallel execution on the GPU.

SMA Kernel Implementation

The kernel loops through the specified window size behind each index, sums the values, and calculates the average.

function createSMAKernel(dataLength, windowSize) {
  return gpu.createKernel(function (data, windowSize) {
    const index = this.thread.x;

    // Return current value or 0 if index is smaller than the window
    if (index < windowSize - 1) {
      return data[index];
    }

    let sum = 0;
    for (let i = 0; i < windowSize; i++) {
      sum += data[index - i];
    }

    return sum / windowSize;
  }).setOutput([dataLength]);
}

// Example usage:
const data = [10, 12, 14, 15, 16, 18, 20, 22, 24, 25];
const windowSize = 3;

const smaKernel = createSMAKernel(data.length, windowSize);
const smaResult = smaKernel(data, windowSize);

console.log(Array.from(smaResult));

Calculating Exponential Smoothing (EMA)

Exponential smoothing applies exponentially decreasing weights over time. The standard recursive formula is:

\[S_t = \alpha \cdot Y_t + (1 - \alpha) \cdot S_{t-1}\]

Because GPUs execute threads in parallel, recursive dependencies between adjacent threads cannot be directly maintained without synchronizing steps. To compute exponential smoothing efficiently on the GPU, the formula is expanded into an explicit weighted sum:

\[S_t = \sum_{k=0}^{M} \alpha (1 - \alpha)^k Y_{t-k}\]

Where \(M\) is a cutoff window (such as \(M = 3.45 / \alpha\)) beyond which older weights become negligible, or simply bounded to the start of the array.

EMA Kernel Implementation

This kernel computes the weighted average using a finite lookback window based on the smoothing factor \(\alpha\) (alpha).

function createEMAKernel(dataLength, maxLookback) {
  return gpu.createKernel(function (data, alpha, maxLookback) {
    const index = this.thread.x;
    
    let weightedSum = 0;
    let totalWeight = 0;
    
    // Determine how far back to compute
    const steps = index < maxLookback ? index + 1 : maxLookback;

    for (let k = 0; k < steps; k++) {
      // Weight decreases exponentially with distance
      const weight = Math.pow(1 - alpha, k);
      weightedSum += data[index - k] * weight;
      totalWeight += weight;
    }

    // Normalize weights so the output matches the data scale
    return weightedSum / totalWeight;
  }).setOutput([dataLength]);
}

// Example usage:
const timeSeriesData = [10, 15, 12, 20, 25, 30, 28, 35, 40, 45];
const alpha = 0.3;          // Smoothing factor between 0 and 1
const lookbackWindow = 20;  // Number of historical points to consider

const emaKernel = createEMAKernel(timeSeriesData.length, lookbackWindow);
const emaResult = emaKernel(timeSeriesData, alpha, lookbackWindow);

console.log(Array.from(emaResult));

Performance Considerations

  • Memory Transfers: Copying large datasets between the CPU and GPU memory involves overhead. Process large arrays or chain multiple calculations within the GPU pipeline to minimize transfer costs.
  • Fixed Bounds: GPU.js kernels require explicit loops with statically determined upper bounds. Always pass integer limits like windowSize and maxLookback as kernel arguments rather than computing dynamic loop conditions on the fly.
