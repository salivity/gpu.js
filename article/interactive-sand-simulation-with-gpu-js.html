Interactive Sand Simulation with GPU.js

This article explains how to build a high-performance, real-time interactive sand and granular material simulation in the browser using GPU.js. By translating cellular automata physics onto graphics hardware, you can simulate hundreds of thousands of particles simultaneously at 60 frames per second. The following sections walk through the underlying simulation model, the implementation of GPU compute kernels, handling user interaction, and rendering directly to an HTML5 canvas.

Understanding the Granular Material Model

Granular simulations like sand typically rely on cellular automata rather than complex fluid dynamics. The simulation space is divided into a 2D grid where each cell represents empty space, a stationary obstacle, or a granular particle like sand.

In a basic falling-sand model, the state of a particle updates every frame based on simple neighborhood rules:

  1. Vertical Fall: If the cell directly below a sand grain is empty, the sand moves down.
  2. Diagonal Slide: If the cell below is blocked, but the cell down-left or down-right is empty, the sand slides diagonally.
  3. Rest: If down, down-left, and down-right are all occupied, the grain remains stationary.

Because these rules are local to each cell, every cell can theoretically be evaluated independently, making it an ideal candidate for massive GPU parallelization.

Solving the GPU Concurrency Problem

Because GPU threads run simultaneously, two neighboring sand grains might attempt to move into the same empty cell at the same time, causing race conditions. In CPU simulations, this is solved by iterating in a specific order (e.g., bottom-to-top).

On the GPU, this is resolved using a sub-stepping phase approach or a margin-based checkerboard update:

  • Divide the update step into distinct phases (e.g., Even Rows / Odd Rows, or Left-Falling / Right-Falling).
  • Use a ping-pong buffer (double buffering) where one texture stores the current state and a second texture stores the computed next state, alternating roles on each frame.

Setting Up GPU.js

First, include GPU.js in your project via npm or a CDN:

<script src="https://cdnjs.cloudflare.com/ajax/libs/gpu.js/2.16.0/gpu-browser.min.js"></script>

Initialize GPU.js and prepare the canvas context:

const canvas = document.getElementById('simCanvas');
const width = 512;
const height = 512;

const gpu = new GPU({
  canvas: canvas,
  mode: 'gpu'
});

Implementing the Simulation Kernel

The physics logic is written as a GPU.js kernel. To prevent write collisions, write the logic from the perspective of the target cell: determining whether a particle moves into this position or vacates it.

const updateSand = gpu.createKernel(function(grid) {
  const x = this.thread.x;
  const y = this.thread.y;
  const current = grid[y][x];

  // Boundaries
  if (y === 0) return current;

  // 1. If currently sand, check if it falls down
  if (current === 1) {
    const below = grid[y - 1][x];
    const belowLeft = x > 0 ? grid[y - 1][x - 1] : 2;
    const belowRight = x < this.constants.width - 1 ? grid[y - 1][x + 1] : 2;

    if (below === 0 || belowLeft === 0 || belowRight === 0) {
      return 0; // Moves away
    }
    return 1; // Stays
  }

  // 2. If currently empty, check if sand falls into here from above
  if (current === 0) {
    const above = y < this.constants.height - 1 ? grid[y + 1][x] : 0;
    if (above === 1) return 1;

    const aboveRight = (y < this.constants.height - 1 && x < this.constants.width - 1) ? grid[y + 1][x + 1] : 0;
    const aboveRightBelow = x < this.constants.width - 1 ? grid[y][x + 1] : 2;
    if (aboveRight === 1 && aboveRightBelow !== 0) return 1;

    const aboveLeft = (y < this.constants.height - 1 && x > 0) ? grid[y + 1][x - 1] : 0;
    const aboveLeftBelow = x > 0 ? grid[y][x - 1] : 2;
    if (aboveLeft === 1 && aboveLeftBelow !== 0) return 1;
  }

  return current;
})
.setConstants({ width, height })
.setOutput([width, height])
.setPipeline(true);

Setting .setPipeline(true) ensures output stays in GPU memory as a texture rather than transferring back to the CPU, maximizing throughput.

Rendering the Simulation Directly

Avoid reading pixel data back into JavaScript. Use a graphical kernel in GPU.js to draw directly to the canvas:

const render = gpu.createKernel(function(grid) {
  const cell = grid[this.thread.y][this.thread.x];
  
  if (cell === 1) {
    // Sand color: yellowish
    this.color(0.92, 0.79, 0.45, 1.0);
  } else if (cell === 2) {
    // Wall color: gray
    this.color(0.4, 0.4, 0.4, 1.0);
  } else {
    // Background: dark
    this.color(0.08, 0.08, 0.1, 1.0);
  }
})
.setOutput([width, height])
.setGraphical(true);

Adding Interactivity

Interactivity requires updating the simulation grid dynamically when the user clicks or drags. This can be handled by an "interaction" kernel that injects particles at mouse coordinates.

const addParticles = gpu.createKernel(function(grid, mouseX, mouseY, radius, type) {
  const x = this.thread.x;
  const y = this.thread.y;
  
  const distSq = (x - mouseX) * (x - mouseX) + (y - mouseY) * (y - mouseY);
  if (distSq < radius * radius) {
    return type;
  }
  return grid[y][x];
})
.setOutput([width, height])
.setPipeline(true);

Track mouse state on the canvas:

let isMouseDown = false;
let mouseX = 0;
let mouseY = 0;

canvas.addEventListener('mousedown', () => isMouseDown = true);
window.addEventListener('mouseup', () => isMouseDown = false);
canvas.addEventListener('mousemove', (e) => {
  const rect = canvas.getBoundingClientRect();
  mouseX = Math.floor((e.clientX - rect.left) * (width / rect.width));
  mouseY = Math.floor((rect.bottom - e.clientY) * (height / rect.height));
});

Running the Animation Loop

Combine the physics, interaction, and rendering within requestAnimationFrame:

let currentGrid = new Array(height).fill(0).map(() => new Array(width).fill(0));

function loop() {
  if (isMouseDown) {
    currentGrid = addParticles(currentGrid, mouseX, mouseY, 8, 1);
  }

  currentGrid = updateSand(currentGrid);
  render(currentGrid);

  requestAnimationFrame(loop);
}

requestAnimationFrame(loop);

Optimization Considerations

  1. Avoid CPU-GPU Transfers: Ensure all intermediate state passes via .setPipeline(true). Transferring arrays to and from CPU memory destroys real-time performance.
  2. Directional Bias Mitigation: Alternate the evaluation of left and right diagonal checks across consecutive frames to prevent sand from disproportionately sliding in one direction.
  3. Material Diversity: Expand the cell value scale to simulate other materials—such as water (which spreads horizontally further) or solid stone barriers (which ignore gravity completely).
