Setup Xvfb for Headless GPU.js on Ubuntu Server

Running GPU-accelerated JavaScript through gpu.js on a headless Ubuntu server requires an active display environment to initialize WebGL or OpenGL contexts. Cloud servers lack physical monitors and desktop display managers, which causes Node.js GPU bindings to fail immediately. This guide provides a straightforward method for installing and configuring Xvfb (X Virtual Framebuffer) to emulate a display server, enabling gpu.js to execute parallel computing tasks seamlessly on headless cloud infrastructure.

1. Update the System and Install Dependencies

Cloud instances need Xvfb, the Mesa OpenGL utility libraries, and standard build tools required for native Node.js addons:

sudo apt update
sudo apt install -y xvfb libgl1-mesa-dri libgl1-mesa-glx libxi-dev libxext-dev build-essential

If you are using an instance with a dedicated physical GPU (such as NVIDIA on AWS, GCP, or Azure), ensure your proprietary GPU drivers and CUDA/OpenGL libraries are properly installed. If no physical GPU is present, Mesa will handle the rendering via software emulation.

2. Initialize the Node.js Project

Create a directory for your application, initialize the project, and install gpu.js:

mkdir headless-gpu-runner
cd headless-gpu-runner
npm init -y
npm install gpu.js

3. Create a Test Script

Create a basic file named index.js to verify that gpu.js initializes and executes on the virtual framebuffer:

const { GPU } = require('gpu.js');

const gpu = new GPU();

// Define a simple matrix multiplication kernel
const multiplyMatrix = gpu.createKernel(function(a, b) {
    let sum = 0;
    for (let i = 0; i < 512; i++) {
        sum += a[this.thread.y][i] * b[i][this.thread.x];
    }
    return sum;
}).setOutput([512, 512]);

// Generate dummy data
const matrixA = Array(512).fill(0).map(() => Array(512).fill(1));
const matrixB = Array(512).fill(0).map(() => Array(512).fill(2));

console.log("Running calculation...");
const result = multiplyMatrix(matrixA, matrixB);
console.log("Calculation complete. Sample output:", result[0][0]);

gpu.destroy();

4. Run the Script Using xvfb-run

The cleanest way to execute a Node.js process inside a temporary virtual framebuffer is using the xvfb-run utility wrapper. It automatically handles launching the X server on an unused display port, running your command, and shutting the server down when finished.

Run your application with the following command:

xvfb-run --auto-servernum --server-args="-screen 0 1024x768x24 -ac +extension GLX +render -noreset" node index.js
  • --auto-servernum: Prevents collisions by picking an available display number automatically.
  • -screen 0 1024x768x24: Configures screen dimensions and a 24-bit color depth required for modern OpenGL buffers.
  • +extension GLX: Explicitly enables the GLX extension required for OpenGL rendering.

5. Running a Persistent Xvfb Display (Alternative Method)

If you have continuous background jobs, WebSockets, or a long-running web service utilizing gpu.js, you can run Xvfb as a background daemon instead of invoking xvfb-run repeatedly.

Start the virtual display manually on port :99:

Xvfb :99 -screen 0 1024x768x24 -ac +extension GLX +render -noreset &

Export the DISPLAY environment variable so all subsequent commands target this display:

export DISPLAY=:99

Run your application normally:

node index.js

To persist this configuration across sessions, append export DISPLAY=:99 to your ~/.bashrc file or configure your systemd service file to include the Environment="DISPLAY=:99" parameter.
