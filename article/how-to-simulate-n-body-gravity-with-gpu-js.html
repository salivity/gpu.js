How to Simulate N-Body Gravity with GPU.js

This article explains how to simulate large-scale, gravity-interacting N-body systems using GPU.js, a JavaScript library that compiles functions into WebGL shader code. You will learn how to bypass the central processing unit's computational limitations, structure position and velocity data for parallel execution, implement Newton’s law of universal gravitation inside compute kernels, and optimize rendering pipelines to maintain high frame rates across large particle counts.

The N-Body Problem and GPU Parallelism

Simulating \(N\) bodies under mutual gravitational attraction requires calculating the forces between every unique pair of particles. Using direct brute-force computation, the algorithmic complexity is \(O(N^2)\). At one million particles, a single time-step requires \(10^{12}\) interactions—a workload that instantly stalls standard single-threaded CPU loops.

GPU.js accelerates this process by mapping calculations across thousands of GPU cores simultaneously. Because each particle's net acceleration depends on all other particles independently of adjacent force evaluations, the workload is an ideal candidate for massively parallel execution.

Setting Up Data Structures

GPUs operate most efficiently on contiguous numeric arrays. To maximize throughput and avoid WebGL texture packaging overhead, store particle properties (positions, velocities, and masses) in flat, single-dimensional typed arrays (Float32Array).

For a 3D simulation with \(N\) particles:

  • Positions: Stored as [x0, y0, z0, x1, y1, z1, ...] of length \(3N\).
  • Velocities: Stored as [vx0, vy0, vz0, vx1, vy1, vz1, ...] of length \(3N\).
  • Masses: Stored as [m0, m1, ...] of length \(N\).

Initializing the GPU Context

Install and import GPU.js into your application:

import { GPU } from 'gpu.js';
const gpu = new GPU();

When handling massive datasets, always configure GPU.js to run in webgl2 mode to unlock 32-bit floating-point textures and larger uniform buffer limits.

Writing the Gravitational Compute Kernel

The gravitational force equation between two bodies \(i\) and \(j\) is:

\[F = G \frac{m_i m_j}{(r^2 + \epsilon^2)^{3/2}} \cdot \mathbf{r}\]

A softening parameter, \(\epsilon\) (epsilon), prevents infinite acceleration and numerical instability when two particles approach each other at near-zero distances.

Define the kernel function that evaluates new velocities by iterating over every particle in the system:

const updateVelocities = gpu.createKernel(function(positions, velocities, masses, count, dt, G, softeningSq) {
    const i = this.thread.x;
    const idx = i * 3;

    let px = positions[idx];
    let py = positions[idx + 1];
    let pz = positions[idx + 2];

    let ax = 0.0;
    let ay = 0.0;
    let az = 0.0;

    for (let j = 0; j < count; j++) {
        const jdx = j * 3;
        const dx = positions[jdx] - px;
        const dy = positions[jdx + 1] - py;
        const dz = positions[jdx + 2] - pz;

        const distSq = dx * dx + dy * dy + dz * dz + softeningSq;
        const invDist = 1.0 / Math.sqrt(distSq);
        const invDist3 = invDist * invDist * invDist;

        const forceFactor = G * masses[j] * invDist3;

        ax += dx * forceFactor;
        ay += dy * forceFactor;
        az += dz * forceFactor;
    }

    return [
        velocities[idx] + ax * dt,
        velocities[idx + 1] + ay * dt,
        velocities[idx + 2] + az * dt
    ];
})
.setOutput([numParticles])
.setPipeline(true);

Updating Particle Positions

Once the velocities are updated, a second, lightweight kernel updates the positions based on numerical integration (such as Euler or Leapfrog integration):

const updatePositions = gpu.createKernel(function(positions, velocities, dt) {
    const i = this.thread.x;
    const idx = i * 3;

    return [
        positions[idx] + velocities[idx] * dt,
        positions[idx + 1] + velocities[idx + 1] * dt,
        positions[idx + 2] + velocities[idx + 2] * dt
    ];
})
.setOutput([numParticles])
.setPipeline(true);

Optimization Techniques for High Particle Counts

Simulating hundreds of thousands to millions of bodies interactively requires specific memory and hardware optimizations:

  1. Keep Data on the GPU (setPipeline(true)): Transferring large arrays back and forth across the CPU-GPU bus creates a severe performance bottleneck. Enabling setPipeline(true) forces the kernel to output WebGL textures rather than serializing data back to JavaScript arrays. The output of updateVelocities feeds directly into updatePositions entirely within VRAM.

  2. Loop Unrolling: Instruct the GLSL compiler to process loop increments in chunks (for example, 4 or 8 bodies per step). This reduces branching overhead inside the fragment shaders.

  3. Sub-Sampling and Tree Approximations: Pure \(O(N^2)\) direct summation reaches modern consumer GPU compute limits around \(10^5\) to \(2 \times 10^5\) bodies at 60 FPS. To reach multiple millions of particles, implement a hierarchical tree algorithm (such as Barnes-Hut) or a Particle-Mesh (PM) method. In this approach, particles are interpolated onto a 3D grid texture, and forces are computed via Fast Fourier Transforms (FFT) on the GPU, lowering algorithmic complexity to \(O(N \log N)\).

Executing the Simulation Loop

Run the calculations inside an animation loop:

function stepSimulation() {
    // Both kernels output textures residing strictly in GPU memory
    currentVelocities = updateVelocities(
        currentPositions, 
        currentVelocities, 
        masses, 
        numParticles, 
        0.016, 
        6.674e-11, 
        0.001
    );

    currentPositions = updatePositions(
        currentPositions, 
        currentVelocities, 
        0.016
    );

    requestAnimationFrame(stepSimulation);
}

stepSimulation();

By retaining all state variables in VRAM and offloading gravitational force integration to parallel fragment shaders, GPU.js transforms computationally prohibitive N-body workloads into high-performance web applications.
