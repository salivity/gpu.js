Handling WebGL Context Loss in GPU.js Kernels

Running compute and graphical operations with GPU.js can occasionally cause the browser's WebGL context to crash or reset due to heavy workloads, driver updates, or power-saving states. Handling this gracefully requires intercepting browser context loss events, preventing default browser termination behaviors, halting active render loops, and re-initializing your GPU.js instance and kernels once the context is restored. This guide covers how to detect context loss, prevent application crashes, and restore graphical GPU.js pipelines seamlessly.

Why WebGL Context Loss Happens

WebGL context loss (webglcontextlost) typically occurs when the GPU is overloaded, the operating system resets the graphics driver (TDR - Timeout Detection and Recovery), or the device switches power modes (such as entering sleep mode or switching between integrated and discrete GPUs). Because GPU.js relies directly on WebGL to execute graphical kernels, an unhandled context loss immediately throws runtime errors and halts execution.

Step 1: Intercept Context Loss Events

GPU.js graphical kernels render to an HTML5 canvas. You must attach event listeners directly to the underlying canvas used by your GPU instance.

To allow WebGL to attempt a recovery, call event.preventDefault() inside the webglcontextlost event listener. Without this call, the browser marks the context as permanently lost.

const canvas = document.getElementById('my-canvas');
const gpu = new GPU({ canvas });

canvas.addEventListener('webglcontextlost', (event) => {
  event.preventDefault(); // Informs the browser that the application will handle recovery
  handleContextLoss();
}, false);

canvas.addEventListener('webglcontextrestored', () => {
  handleContextRestored();
}, false);

Step 2: Pause Execution and Clean Up State

When the context is lost, all WebGL-allocated resources—including textures, buffers, and compiled shader programs—are discarded by the hardware. Any ongoing requestAnimationFrame loop or kernel execution will fail immediately.

Implement a flag to pause your animation and render loops:

let isContextLost = false;
let animationFrameId = null;

function handleContextLoss() {
  isContextLost = true;
  if (animationFrameId) {
    cancelAnimationFrame(animationFrameId);
  }
  console.warn('WebGL context lost. Execution paused.');
}

Step 3: Re-initialize the GPU Instance and Kernels

When the webglcontextrestored event fires, the underlying canvas is ready for a fresh WebGL context. However, GPU.js retains references to the destroyed context internally. You must destroy the old GPU instance, create a new one attached to the same canvas, and recompile your graphical kernels.

let renderKernel;

function createKernels(gpuInstance) {
  return gpuInstance.createKernel(function() {
    this.color(this.thread.x / 500, this.thread.y / 500, 0.5, 1);
  })
  .setOutput([500, 500])
  .setGraphical(true);
}

function handleContextRestored() {
  console.log('WebGL context restored. Rebuilding GPU pipeline...');

  // 1. Clean up old GPU instance
  try {
    gpu.destroy();
  } catch (e) {
    // Ignore cleanup errors on lost context
  }

  // 2. Instantiate a fresh GPU instance with the original canvas
  gpu = new GPU({ canvas });

  // 3. Recompile the kernels
  renderKernel = createKernels(gpu);

  // 4. Reset state and resume execution
  isContextLost = false;
  startRenderLoop();
}

function startRenderLoop() {
  function render() {
    if (isContextLost) return;

    renderKernel();
    animationFrameId = requestAnimationFrame(render);
  }
  render();
}

Step 4: Fallback to CPU Mode

In severe cases where the browser cannot restore the WebGL context, provide a fallback. You can detect whether WebGL is permanently unavailable and fall back to CPU computation or notify the user to refresh the page:

canvas.addEventListener('webglcontextlost', (event) => {
  event.preventDefault();
  handleContextLoss();

  // Set a recovery timeout
  setTimeout(() => {
    if (isContextLost) {
      console.error('WebGL context could not be restored. Falling back to CPU mode.');
      fallbackToCPU();
    }
  }, 3000);
});

function fallbackToCPU() {
  gpu = new GPU({ mode: 'cpu' });
  // Recompile logic using standard CPU computation or fallback rendering
}

Summary of Best Practices

  • Always call event.preventDefault(): This prevents the browser from permanently destroying the context.
  • Halt loops immediately: Stop all render calls via cancelAnimationFrame before missing texture errors occur.
  • Recompile all kernels: Treat context restoration as a complete application restart for GPU-resident assets.
  • Keep kernel setup modular: Encapsulate kernel creation inside factory functions so they can be re-run whenever a new GPU instance is initialized.
