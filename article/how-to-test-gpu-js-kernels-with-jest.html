How to Test GPU.js Kernels with Jest

Testing GPU.js kernels in Jest presents a challenge because Node.js test runners lack native hardware-accelerated WebGL contexts by default. This article explains how to configure Jest to execute GPU.js unit tests effectively, detailing how to force CPU fallback mode for fast and deterministic logic testing, how to integrate headless WebGL drivers for GPU pipeline validation, and how to write clean, leak-free test suites.

The Underlying Issue

GPU.js relies on WebGL to compile and run JavaScript functions on the graphics card. Because Jest executes tests in a Node.js process—even when using jest-environment-jsdom—the required browser-level WebGL context does not exist natively. Without explicit configuration, GPU.js will either crash attempting to access an undefined context or trigger memory leaks during teardown.

Method 1: Testing with CPU Fallback (Recommended)

For unit tests, your primary goal is validating mathematical correctness and kernel output logic rather than benchmarking hardware throughput. GPU.js provides a built-in CPU mode that interprets the kernel code using pure JavaScript.

1. Set Up the Test Environment

Ensure your Jest configuration uses the standard Node environment. In your jest.config.js:

module.exports = {
  testEnvironment: 'node',
  transform: {},
};

2. Configure the GPU Instance in the Test

Instantiate GPU with the mode option explicitly set to 'cpu'. This bypasses all WebGL requirements.

const { GPU } = require('gpu.js');

describe('Matrix Multiplication Kernel', () => {
  let gpu;

  beforeEach(() => {
    gpu = new GPU({ mode: 'cpu' });
  });

  afterEach(() => {
    gpu.destroy();
  });

  test('correctly multiplies two 2x2 matrices', () => {
    const multiplyMatrix = gpu.createKernel(function (a, b) {
      let sum = 0;
      for (let i = 0; i < 2; i++) {
        sum += a[this.thread.y][i] * b[i][this.thread.x];
      }
      return sum;
    }).setOutput([2, 2]);

    const a = [
      [1, 2],
      [3, 4],
    ];
    const b = [
      [5, 6],
      [7, 8],
    ];

    const result = multiplyMatrix(a, b);

    expect(Array.from(result[0])).toEqual([19, 22]);
    expect(Array.from(result[1])).toEqual([43, 50]);
  });
});

Method 2: Testing with Headless WebGL (gl)

If you must verify that your kernels compile properly down to GLSL shaders without syntax errors or WebGL type constraints, you can provide a simulated WebGL context using the gl (headless-gl) package.

1. Install Dependencies

Install the headless WebGL implementation:

npm install --save-dev gl

2. Configure Jest Setup

Create a setup file to expose the context globally or configure GPU.js to accept it. In jest.config.js:

module.exports = {
  testEnvironment: 'node',
  setupFilesAfterEnv: ['./jest.setup.js'],
};

In jest.setup.js:

const gl = require('gl');

// Polyfill the WebGL rendering context for Node.js
global.WebGLRenderingContext = gl(1, 1).constructor;

3. Run Kernels in Headless Mode

Instantiate GPU.js using the headless context:

const { GPU } = require('gpu.js');
const headlessGL = require('gl');

describe('GPU Hardware Shader Test', () => {
  let gpu;

  beforeEach(() => {
    const context = headlessGL(512, 512);
    gpu = new GPU({
      context: context,
      mode: 'headlessgl',
    });
  });

  afterEach(() => {
    gpu.destroy();
  });

  test('executes kernel through headless WebGL context', () => {
    const addKernel = gpu.createKernel(function (a, b) {
      return a[this.thread.x] + b[this.thread.x];
    }).setOutput([4]);

    const result = addKernel([1, 2, 3, 4], [10, 20, 30, 40]);

    expect(Array.from(result)).toEqual([11, 22, 33, 44]);
  });
});

Best Practices for GPU.js Jest Suites

  1. Always Call gpu.destroy(): Failing to invoke .destroy() on the GPU instance in an afterEach or afterAll hook will leak contexts and native memory allocations, causing Jest to hang or crash with worker process exited unexpectedly.
  2. Normalize Kernel Outputs: WebGL kernels return typed arrays (like Float32Array) or internal vector objects. Convert outputs using Array.from() or nested maps before using Jest's toEqual assertion.
  3. Separate Logic and Shader Compilation: Run standard unit tests in mode: 'cpu' for optimal execution speed during development and pull request validation. Limit headless WebGL testing to integration pipelines.
