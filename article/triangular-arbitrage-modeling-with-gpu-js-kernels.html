Triangular Arbitrage Modeling with GPU.js Kernels

This article provides a technical guide on detecting multi-currency triangular arbitrage opportunities using parallel matrix operations in GPU.js. By structuring currency exchange rates into an adjacency matrix and mapping rate multiplication to logarithmic addition, high-frequency currency combinations can be evaluated simultaneously. You will learn the underlying mathematical framework, how to construct a parallelized GPU.js kernel, and how to extract executable, profitable 3-currency cycles at scale.

Mathematical Framework for Triangular Arbitrage

A triangular arbitrage cycle occurs when an initial capital amount traded through three distinct currencies yields more than the starting balance after returning to the base asset.

For three currencies \(i\), \(j\), and \(k\), a profitable cycle exists if:

\[R[i][j] \times R[j][k] \times R[k][i] > 1.0 + \text{fees}\]

Where \(R[a][b]\) represents the exchange rate for converting currency \(a\) to currency \(b\).

Because graphics hardware excels at linear algebra and floating-point addition rather than sequential multiplicative chains, the rates are transformed using negative natural logarithms:

\[W[a][b] = -\ln(R[a][b] \times (1 - f_{ab}))\]

Where \(f_{ab}\) is the transaction fee for that pair. With this transformation, the condition becomes finding cycles where the sum of weights is negative:

\[W[i][j] + W[j][k] + W[k][i] < 0\]

Mapping the Problem to Parallel Matrix Kernels

In a market with \(N\) currencies, evaluating all potential triangular cycles requires assessing \(N \times (N - 1) \times (N - 2)\) combinations, an \(O(N^3)\) computational workload. On a CPU, evaluating hundreds of pairs sequentially introduces latency that renders arbitrage signals stale.

Using GPU.js, this workload is distributed over a 3-dimensional output grid of size \((N \times N \times N)\). Each thread on the GPU evaluates a single triplet \((i, j, k)\) concurrently in \(O(1)\) parallel time complexity.

GPU.js Kernel Implementation

To run this model, prepare the cost matrix as a flattened 1D array or a 2D array of transformed weights, pass it to a custom GPU.js kernel, and read back candidate cycles.

const { GPU } = require('gpu.js');
const gpu = new GPU();

const N = 4; // Number of currencies (e.g., USD, EUR, GBP, JPY)

// Transformed negative-log rate matrix: W[i][j] = -ln(Rate * (1 - Fee))
// Zero on diagonal (converting asset to itself yields no gain)
const weightMatrix = [
  [ 0.0000, -0.0870,  0.2705, -0.0034],
  [ 0.0910,  0.0000,  0.3610,  0.0850],
  [-0.2650, -0.3540,  0.0000, -0.2690],
  [ 0.0040, -0.0820,  0.2740,  0.0000]
];

// Define the parallel kernel
const findTriangularArbitrage = gpu.createKernel(function(matrix, size) {
  const i = this.thread.x;
  const j = this.thread.y;
  const k = this.thread.z;

  // Avoid self-referencing cycles
  if (i === j || j === k || i === k) {
    return 0.0;
  }

  // Calculate the cycle weight: i -> j -> k -> i
  const cycleWeight = matrix[i][j] + matrix[j][k] + matrix[k][i];

  // Return negative values indicating profitable arbitrage paths
  if (cycleWeight < 0.0) {
    return cycleWeight;
  }

  return 0.0;
})
.setOutput([N, N, N]); // 3D parallel dispatch

// Execute kernel
const cycleResults = findTriangularArbitrage(weightMatrix, N);

Parsing and Filtering Profitable Cycles

The output matrix is a 3D array where indices [k][j][i] map directly to the currency index nodes. A negative value indicates an arbitrage opportunity, with the magnitude corresponding to the profit potential:

function extractOpportunities(results, currencies) {
  const opportunities = [];
  const size = currencies.length;

  for (let k = 0; k < size; k++) {
    for (let j = 0; j < size; j++) {
      for (let i = 0; i < size; i++) {
        const weight = results[k][j][i];
        if (weight < 0) {
          // Convert negative-log weight back to profit ratio
          const profitMultiplier = Math.exp(-weight);
          const profitPercentage = (profitMultiplier - 1) * 100;

          opportunities.push({
            path: [currencies[i], currencies[j], currencies[k], currencies[i]],
            profitPercentage: profitPercentage.toFixed(4) + '%'
          });
        }
      }
    }
  }
  return opportunities;
}

const currencies = ['USD', 'EUR', 'GBP', 'JPY'];
const profitablePaths = extractOpportunities(cycleResults, currencies);
console.log(profitablePaths);

Optimizations for Production Execution

  1. Memory Allocation: Keep the rate matrix in memory as a contiguous typed array (Float32Array) to prevent garbage collection overhead and enable fast memory transfer to WebGL textures.
  2. Dynamic Order Books: Use depth-adjusted effective prices rather than top-of-book spot rates. Populate \(R[i][j]\) with the marginal rate valid for a specific trade size to prevent false signals caused by low liquidity.
  3. Pipelining: Keep the GPU kernel compiled and reuse it across market ticks using findTriangularArbitrage.run(matrix) to eliminate shader recompilation delays.
