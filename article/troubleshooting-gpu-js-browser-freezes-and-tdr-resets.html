Troubleshooting gpu.js Browser Freezes and TDR Resets

When executing compute-heavy tasks with gpu.js, browsers can freeze or crash due to operating system Timeout Detection and Recovery (TDR) mechanisms. This guide explains why these GPU resets occur and provides actionable techniques to diagnose, optimize, and structure your gpu.js workloads to maintain smooth browser performance and prevent hardware driver timeouts.

Understanding the Cause of TDR Resets

Operating systems like Windows include a watchdog feature known as Timeout Detection and Recovery (TDR). If the GPU spends more than a set amount of time (typically 2 seconds) processing a single execution command without yielding control back to the operating system or desktop window manager, the OS assumes the GPU is hung. It forcibly resets the graphics driver, causing the browser to lose its WebGL context, crash the GPU process, or freeze the entire window.

1. Chunk and Paginate Heavy Computations

The most frequent cause of TDR resets in gpu.js is passing massive output dimensions (e.g., millions of elements) in a single synchronous dispatch.

  • Break up the output array: Split large 2D or 3D datasets into slices or batches.
  • Yield to the event loop: Process each batch sequentially using requestAnimationFrame() or setTimeout(..., 0). This allows the browser to render UI updates and resets the OS watchdog timer between kernel calls.
async function runBatchedKernel(totalRows, cols, batchSize) {
  for (let offset = 0; offset < totalRows; offset += batchSize) {
    const currentBatch = Math.min(batchSize, totalRows - offset);
    kernel.setOutput([cols, currentBatch]);
    const result = kernel(offset);
    // Yield execution to the browser thread
    await new Promise((resolve) => setTimeout(resolve, 0));
  }
}

2. Flatten and Eliminate Nested Loops

Deeply nested loops inside a gpu.js kernel compound the execution time exponentially on every thread.

  • Move iterations to the grid: Instead of writing an internal for loop inside your kernel function, map the iteration counter directly to the kernel's output dimensions (this.thread.x, this.thread.y, this.thread.z). Let the GPU's native parallelism handle iteration rather than running loops sequentially on individual shader cores.
  • Minimize divergence: Avoid heavy if/else branching within internal loops. Branch divergence forces threads within the same warp/wavefront to execute both branches serially, multiplying execution duration.

3. Manage Memory and Dynamic Kernel Re-compilation

Recompiling kernels or creating new GPU contexts inside an active loop consumes significant CPU and GPU memory, leading to browser thread locks.

  • Reuse kernel instances: Create your kernel once with gpu.createKernel() and call it multiple times. Do not recreate kernels within request frames or iterative functions.
  • Clean up textures: If passing raw textures back and forth using pipeline mode (pipeline: true), ensure you call .delete() on intermediate textures to prevent memory leaks that can degrade driver response times.

4. Handle WebGL Context Loss Gracefully

When a TDR reset occurs, WebGL dispatches a webglcontextlost event. If unhandled, gpu.js will fail silently or throw unhandled exceptions on subsequent calls.

Attach an event listener to the canvas element utilized by gpu.js:

const canvas = gpu.canvas;
canvas.addEventListener('webglcontextlost', (event) => {
  event.preventDefault(); // Informs the browser you intend to handle recovery
  console.warn('GPU context lost due to TDR or driver crash.');
});

canvas.addEventListener('webglcontextrestored', () => {
  console.info('GPU context restored. Re-initializing kernels...');
  // Re-instantiate gpu.js kernels here
});

5. Benchmark with CPU Mode Fallback

To determine whether the freeze originates from GPU hardware constraints, WebGL driver bugs, or fundamental algorithmic complexity, toggle the kernel to CPU mode:

const gpu = new GPU({ mode: 'cpu' });

If the CPU execution completes reliably (albeit slower) without a browser crash, the issue is directly tied to the WebGL shader execution exceeding the OS TDR budget. Continue reducing batch sizes and optimizing shader logic until the GPU mode runs reliably under the 2-second threshold.
