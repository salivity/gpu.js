Tainted Canvas as a Texture in gpu.js Explained

Passing an un-sanitized, tainted canvas as an input texture into gpu.js results in an immediate execution failure due to browser security restrictions. Because the canvas contains cross-origin data loaded without proper Cross-Origin Resource Sharing (CORS) approval, the browser flags its origin-clean state as false. Consequently, when gpu.js attempts to ingest the canvas to create a WebGL texture or read its pixels, the browser halts the operation and throws a SecurityError DOMException, preventing the kernel from running.

The Origin-Clean Restriction

A canvas becomes "tainted" the moment it draws an image, video, or external SVG from a different origin that does not supply a valid Access-Control-Allow-Origin header. Once tainted, the browser marks the internal origin-clean flag of the canvas element as false. This flag serves as a fundamental security boundary designed to prevent malicious scripts from extracting sensitive cross-origin pixel data.

What Happens in the WebGL Pipeline

Under normal conditions, gpu.js accelerates computations by translating JavaScript functions into WebGL shaders and uploading input arguments—including images and canvases—to the GPU as 2D textures.

When a canvas element is passed to a gpu.js kernel:

  1. Texture Creation: gpu.js allocates a WebGL texture via gl.createTexture().
  2. Data Upload via texImage2D: gpu.js invokes gl.texImage2D(), passing the tainted canvas element directly as the image source to populate the GPU memory.
  3. Browser Interception: The browser inspects the source canvas before uploading its pixels to the GPU context. Because the origin-clean flag is false, the browser blocks the call to prevent cross-origin data leakage through shader execution or subsequent read operations.
  4. Exception Thrown: The browser raises a DOMException with the name SecurityError (specifically: "The operation is insecure").

Because this error is thrown at the WebGL API level, the texture allocation fails entirely, execution stops, and the kernel returns an uncaught exception rather than a computed output.

Impact on CPU Fallback Mode

gpu.js includes a CPU fallback mode for environments lacking WebGL support or when explicitly configured to run on the CPU. In this mode, inputs are processed using standard 2D canvas contexts.

If an un-sanitized tainted canvas enters the CPU pipeline:

  1. gpu.js attempts to extract the pixel array using CanvasRenderingContext2D.getImageData().
  2. The browser immediately intercepts this call because reading raw pixel buffers from a tainted canvas is strictly forbidden.
  3. A SecurityError DOMException is thrown identically to the WebGL pathway, terminating execution before processing can begin.

Summary of Consequences

  • Execution Failure: The gpu.js kernel will crash synchronously upon receiving the tainted input.
  • No Leaked Data: The GPU shader never receives the pixel buffer, ensuring cross-origin protections remain intact.
  • Console Warnings: The browser developer console will log a SecurityError, identifying the canvas as non-origin-clean.
