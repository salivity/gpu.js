GPU.js Custom Functions: Arrays and Textures

GPU.js allows developers to run JavaScript code on the GPU using WebGL, but passing complex data types into custom helper functions requires careful architectural consideration. While the primary kernel functions in GPU.js natively accept both arrays and textures as inputs, custom sub-functions added via gpu.addFunction() cannot accept dynamic arrays or textures as parameters. This article explains how GPU.js handles these data types, why this limitation exists within custom functions, and the standard workarounds used to process array and texture data effectively.

Kernel Functions vs. Custom Helper Functions

To understand argument handling in GPU.js, it is essential to distinguish between the main kernel function and custom helper functions:

  1. Kernel Functions: Created via gpu.createKernel(), these are the entry points compiled into GPU shaders. Kernel functions accept arrays (1D, 2D, 3D), numbers, and texture objects generated from previous GPU.js runs.
  2. Custom Helper Functions: Registered using gpu.addFunction(), these functions are compiled into native GLSL (OpenGL Shading Language) sub-routines to keep kernel code modular and reusable.

Can Custom Functions Accept Arrays or Textures?

Custom functions in GPU.js cannot accept arbitrary dynamic arrays or texture references as arguments.

When GPU.js translates JavaScript functions into GLSL, dynamic textures and arrays represent specific WebGL constructs (sampler2D samplers or global memory buffers). WebGL GLSL functions have strict static typing constraints, meaning custom functions cannot dynamically accept variable-length arrays or texture samplers without predetermined type definitions and uniform bindings.

Custom functions are primarily limited to scalar values, such as:

  • Floats (Number)
  • Integers
  • Fixed-size vectors (e.g., small arrays of 2, 3, or 4 elements that map directly to GLSL types like vec2, vec3, or vec4, provided their argument types are strictly defined)

Recommended Workarounds

Because custom functions cannot receive dynamic arrays or textures directly, standard GPU programming patterns should be used instead:

1. Sample Data in the Kernel

Extract specific values from the array or texture within the main kernel function first, then pass those individual scalar values or vectors into the custom function.

gpu.addFunction(function computeAdjustment(valA, valB) {
  return (valA * 0.5) + (valB * 0.5);
});

const kernel = gpu.createKernel(function(myArray1, myArray2) {
  const a = myArray1[this.thread.y][this.thread.x];
  const b = myArray2[this.thread.y][this.thread.x];
  return computeAdjustment(a, b);
}).setOutput([512, 512]);

2. Inline Complex Logic

If an algorithm requires indexing across multiple locations of a single array or texture conditionally, write the operations directly inside the main kernel function body. The kernel has direct uniform access to any input textures or arrays provided at execution time.

3. Use Texture Pipelining

When dealing with intermediate multi-pass calculations, keep data stored on the GPU as textures using the pipeline: true kernel setting. Pass the resulting texture output directly into subsequent kernel functions rather than attempting to pass them through custom internal functions.
