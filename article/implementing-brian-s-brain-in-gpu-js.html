Implementing Brian's Brain in gpu.js

This article explains how to build high-performance multi-state cellular automata, specifically Brian's Brain, using the WebGL-accelerated library gpu.js. You will learn the state transition rules for Brian's Brain, how to map multi-state logic into a GPU kernel function, and how to utilize GPU memory pipelining to avoid expensive data transfers between the CPU and GPU during simulation loops.

Understanding the Brian's Brain Rules

Brian's Brain is a three-state cellular automaton developed by Brian Silverman. Unlike standard two-state automata like Conway's Game of Life, cells in Brian's Brain exist in one of three conditions:

  • State 0 (Off/Ready): A dead or quiescent cell.
  • State 1 (Alive/On): An active, firing cell.
  • State 2 (Dying): A refractory cell that cannot fire.

The transition rules are deterministic:

  1. If a cell is Alive (1), it transitions to Dying (2) in the next generation.
  2. If a cell is Dying (2), it transitions to Off (0) in the next generation.
  3. If a cell is Off (0), it becomes Alive (1) if and only if exactly two of its eight Moore neighbors are currently Alive (1). Otherwise, it remains Off (0).

Setting Up the GPU Instance and Pipeline

To achieve optimal framerates, the simulation must keep grid data in GPU memory across iterations instead of transferring multi-dimensional arrays back to the CPU. In gpu.js, this is achieved using the pipeline: true configuration, which keeps return values as WebGL textures.

const gpu = new GPU();
const WIDTH = 512;
const HEIGHT = 512;

The Simulation Kernel

The kernel computes the next state of each cell in parallel using its 2D coordinates (this.thread.x and this.thread.y). Boundary conditions are handled by wrapping edges cyclically (a toroidal grid).

const stepKernel = gpu.createKernel(function(grid, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;
    const currentState = grid[y][x];

    // State 1: Alive -> Transitions directly to Dying
    if (currentState === 1) {
        return 2;
    }

    // State 2: Dying -> Transitions directly to Off
    if (currentState === 2) {
        return 0;
    }

    // State 0: Off -> Count neighbors in State 1
    let aliveNeighbors = 0;

    for (let dy = -1; dy <= 1; dy++) {
        for (let dx = -1; dx <= 1; dx++) {
            if (dx === 0 && dy === 0) {
                continue;
            }

            // Toroidal boundary wrapping
            const nx = (x + dx + width) % width;
            const ny = (y + dy + height) % height;

            if (grid[ny][nx] === 1) {
                aliveNeighbors++;
            }
        }
    }

    // Rule: An off cell with exactly 2 alive neighbors turns on
    if (aliveNeighbors === 2) {
        return 1;
    }

    return 0;
})
.setOutput([WIDTH, HEIGHT])
.setPipeline(true)
.setImmutable(true);

Rendering Kernel

Because stepKernel operates in pipeline mode, it outputs an internal texture. To display this data on an HTML5 canvas, create a dedicated rendering kernel configured with .setGraphical(true).

const renderKernel = gpu.createKernel(function(grid) {
    const state = grid[this.thread.y][this.thread.x];

    if (state === 1) {
        // Alive: White
        this.color(1.0, 1.0, 1.0, 1.0);
    } else if (state === 2) {
        // Dying: Blue
        this.color(0.2, 0.4, 0.9, 1.0);
    } else {
        // Off: Black
        this.color(0.0, 0.0, 0.0, 1.0);
    }
})
.setOutput([WIDTH, HEIGHT])
.setGraphical(true);

document.body.appendChild(renderKernel.canvas);

Initializing and Running the Simulation Loop

Populate an initial 2D array on the CPU with random values to seed the board, then run the animation loop.

// Generate initial board
function createInitialGrid(width, height) {
    const grid = [];
    for (let y = 0; y < height; y++) {
        const row = [];
        for (let x = 0; x < width; x++) {
            // Seed roughly 20% of cells as alive
            row.push(Math.random() < 0.2 ? 1 : 0);
        }
        grid.push(row);
    }
    return grid;
}

let currentGrid = createInitialGrid(WIDTH, HEIGHT);

function loop() {
    // Compute next generation on GPU
    const nextGrid = stepKernel(currentGrid, WIDTH, HEIGHT);
    
    // Render state to canvas
    renderKernel(nextGrid);

    // Free previous GPU texture to prevent memory leaks if immutable
    if (currentGrid.delete) {
        currentGrid.delete();
    }

    // Advance generation
    currentGrid = nextGrid;
    requestAnimationFrame(loop);
}

requestAnimationFrame(loop);

Extending to Other Multi-State Automata

This pattern applies to any multi-state cellular automaton:

  • Generations Automata: Cellular automata extending Life rules where alive cells decay through \(N\) states before dying. Modify the currentState === 1 branch to increment the state up to \(N - 1\), after which it resets to 0.
  • Wireworld: A four-state automaton (0: Empty, 1: Electron Head, 2: Electron Tail, 3: Conductor). Change the condition to: State 1 becomes State 2; State 2 becomes State 3; State 3 becomes State 1 if exactly 1 or 2 neighbors are State 1; State 0 stays State 0.
  • Star Wars: Another Generations family rule with multiple decay states and custom survival/birth thresholds, which only requires adjusting the neighborhood condition checks inside the nested loop.
