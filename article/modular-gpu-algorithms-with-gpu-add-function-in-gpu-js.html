Modular GPU Algorithms with gpu.addFunction in GPU.js

Building scalable, maintainable GPU-accelerated web applications requires structured code reuse rather than monolithic kernel definitions. This guide explains how to use the gpu.addFunction() method in GPU.js to define, register, and organize modular mathematical and algorithmic functions into reusable libraries. By treating GPU functions as modular components, developers can break complex compute tasks into testable, composable building blocks across multiple compute kernels.

The Role of gpu.addFunction in GPU.js

GPU.js compiles JavaScript functions into WebGL or WebGPU shader code at runtime. Because GPU kernels execute in parallel on graphics hardware, they cannot directly invoke standard JavaScript functions or access closures from the CPU memory space.

The gpu.addFunction() method bridges this gap. It transpiles custom, standalone JavaScript functions into GLSL-compatible functions and injects them into the execution context of every kernel created by that GPU instance.

Basic Syntax and Registration

To register a reusable function, call gpu.addFunction(fn, options). You must declare the return type and argument types if the compilation target requires explicit typing.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Define a pure utility function
function calculateDistance(x1, y1, x2, y2) {
  const dx = x2 - x1;
  const dy = y2 - y1;
  return Math.sqrt(dx * dx + dy * dy);
}

// Register it with the GPU instance
gpu.addFunction(calculateDistance, {
  argumentTypes: { x1: 'Number', y1: 'Number', x2: 'Number', y2: 'Number' },
  returnType: 'Number'
});

Once registered, calculateDistance can be invoked directly inside any kernel attached to that gpu instance.

Creating an Algorithm Library Module

To structure algorithms into an exportable, reusable library, separate your mathematical implementations from the kernel execution logic.

1. Define the Algorithm Library

Create a module that contains related algorithms. Structure functions so that each takes only primitive values or fixed-size structures supported by GPU.js.

// mathLib.js
function normalize(val, min, max) {
  if (max === min) return 0;
  return (val - min) / (max - min);
}

function lerp(start, end, t) {
  return start + (end - start) * t;
}

function clamp(value, min, max) {
  return Math.max(min, Math.min(max, value));
}

export const MathAlgorithms = [
  {
    fn: normalize,
    options: {
      argumentTypes: { val: 'Number', min: 'Number', max: 'Number' },
      returnType: 'Number'
    }
  },
  {
    fn: lerp,
    options: {
      argumentTypes: { start: 'Number', end: 'Number', t: 'Number' },
      returnType: 'Number'
    }
  },
  {
    fn: clamp,
    options: {
      argumentTypes: { value: 'Number', min: 'Number', max: 'Number' },
      returnType: 'Number'
    }
  }
];

2. Register the Library

Create a setup utility to batch-register the algorithm definitions into your GPU instance before generating kernels.

// registerLibrary.js
export function registerAlgorithmLibrary(gpuInstance, library) {
  library.forEach(({ fn, options }) => {
    gpuInstance.addFunction(fn, options);
  });
}

3. Consume the Library in Kernels

Import both the registrar and your modular library into the consumer application:

// main.js
import { GPU } from 'gpu.js';
import { MathAlgorithms } from './mathLib.js';
import { registerAlgorithmLibrary } from './registerLibrary.js';

const gpu = new GPU();

// Inject modular algorithms into the GPU instance
registerAlgorithmLibrary(gpu, MathAlgorithms);

// Create a kernel using the modular functions
const processDataset = gpu.createKernel(function (data, minVal, maxVal) {
  const rawValue = data[this.thread.x];
  const normalized = normalize(rawValue, minVal, maxVal);
  return clamp(normalized, 0.0, 1.0);
}).setOutput([1000]);

const inputData = [5, 12, 45, 100, -5, 20];
const result = processDataset(inputData, 0, 50);
console.log(result);

Best Practices for Modular GPU Functions

  • Enforce Pure Functions: Registered functions must not rely on external lexical scope, global variables, or non-deterministic APIs (e.g., Date.now(), Math.random()). All values must be passed via arguments.
  • Strict Typing: Always specify argumentTypes and returnType within options. While GPU.js can occasionally infer simple numeric types, explicit typing prevents compilation failures when targeting different WebGL platforms.
  • Support Native GPU Types: You can use specialized types like Array(2), Array(3), or Array(4) for vector calculations to maximize the parallel computing capabilities of the underlying shader pipeline.
  • Maintain Instance Scope: Functions added via gpu.addFunction() are bound only to that specific GPU instance. If multiple GPU instances are created in an application, the library must be registered across each instance separately.
