GPU.js Texture Filtering in Pipeline Chaining

This article provides an overview of how gpu.js handles texture minification and magnification filters when executing chained kernel pipelines. In pipeline mode, intermediate calculation results are retained on the graphics hardware as WebGL textures rather than being read back to CPU memory. To preserve numerical precision and prevent interpolation artifacts across successive computations, gpu.js strictly configures both minification and magnification filters to nearest-neighbor sampling, ensuring exact discrete data transfer between chained kernels.

The Role of Textures in Pipeline Chaining

When running kernels in gpu.js with the { pipeline: true } option enabled, the output of a kernel is not serialized back into a standard JavaScript array via gl.readPixels. Instead, the output remains inside a WebGL framebuffer object bound to an off-screen 2D texture. When a subsequent kernel accepts this output as an argument, it binds that intermediate texture as a sampler input for its fragment shader.

Texture Filter Configuration

WebGL requires explicit filtering behavior for cases where a texture is rendered at dimensions smaller (minification) or larger (magnification) than its native resolution. In compute workflows, any mathematical interpolation between texels alters the underlying numeric values.

To prevent data corruption, gpu.js configures the WebGL texture parameters using nearest-neighbor filtering:

  • Magnification (gl.TEXTURE_MAG_FILTER): Set to gl.NEAREST.
  • Minification (gl.TEXTURE_MIN_FILTER): Set to gl.NEAREST.

By binding gl.NEAREST to both parameters via gl.texParameteri(), gpu.js instructs the GPU to return the color or float value of the single nearest texel coordinate rather than calculating a weighted average of surrounding texels. This guarantees that matrix values, floating-point vectors, or packed integer data passed from one kernel to the next remain identical to their output state.

Mipmapping and Texture Dimensions

gpu.js explicitly avoids generating or using mipmaps for intermediate pipeline textures. Typical WebGL texture minification options such as gl.NEAREST_MIPMAP_NEAREST or gl.LINEAR_MIPMAP_LINEAR require downsampled levels of detail, which are unnecessary and counterproductive for general-purpose computing on GPUs (GPGPU).

Because mipmaps are disabled and the minification filter is strictly gl.NEAREST, gpu.js also satisfies WebGL specifications for handling Non-Power-of-Two (NPOT) texture dimensions. Coupled with texture wrapping set to gl.CLAMP_TO_EDGE, this filtering configuration allows chained pipelines to process arbitrarily sized arrays and matrices without requiring dimensions to be padded to powers of two.

Internal Abstraction

These filtering properties are managed automatically within the underlying WebGL kernel classes (such as WebGLKernel or WebGL2Kernel). Developers do not need to configure sampler states or texture parameters manually. When a kernel returns a Texture object, gpu.js ensures the internal metadata and WebGL handles retain their discrete filtering rules, preserving data integrity until the pipeline ends with an explicit .toArray() call.
