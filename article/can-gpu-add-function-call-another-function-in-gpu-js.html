Can gpu.addFunction Call Another Function in GPU.js?

Yes, a function registered with gpu.addFunction in GPU.js can call another registered custom function. When compiling JavaScript kernels into GPU-compatible shaders, GPU.js translates your registered helper functions into native WebGL shader code, allowing modular code reuse within the GPU execution environment. This article explains how function chaining works in GPU.js, how to implement it, and the technical limitations to keep in mind.

How GPU.js Handles Interdependent Functions

When you add a function using gpu.addFunction(), GPU.js parses the JavaScript Abstract Syntax Tree (AST) and converts the logic into GLSL (OpenGL Shading Language). Each registered function is declared globally within the generated fragment shader.

Because these functions exist in the same global shader scope, any function processed by gpu.addFunction() can reference and call another registered function, as long as both functions are registered to the same GPU instance before the kernel executes.

Implementation Example

To call one custom function from another, declare both standard JavaScript functions, ensure the caller invokes the dependency, and register both using gpu.addFunction:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Base helper function
function square(n) {
  return n * n;
}

// Higher-level function calling the helper
function sumOfSquares(a, b) {
  return square(a) + square(b);
}

// Register both functions to the GPU instance
gpu.addFunction(square);
gpu.addFunction(sumOfSquares);

// Define kernel that calls the higher-level function
const kernel = gpu.createKernel(function (valA, valB) {
  return sumOfSquares(valA[this.thread.x], valB[this.thread.x]);
}).setOutput([5]);

const result = kernel([1, 2, 3, 4, 5], [2, 3, 4, 5, 6]);
console.log(result); // [5, 13, 25, 41, 61]

Key Considerations and Limitations

  • No Recursion: Standard GPU architecture and GLSL do not support recursion. Function A can call function B, but function A cannot call itself, nor can function B call function A. Circular dependencies will cause compilation errors.
  • Type Strictness: GLSL is strongly typed. Ensure return types and input arguments match properly across functions. If you define explicit argument and return types in the gpu.addFunction options, the passed values between functions must strictly match those signatures.
  • Execution Order: While GPU.js analyzes dependencies to structure the shader appropriately, registering lower-level utilities before the higher-level functions that consume them avoids runtime parsing issues.
  • Pure Logic Only: Any function called within the GPU pipeline must only use JavaScript operations supported by GPU.js (such as standard arithmetic and supported Math methods). Calling DOM APIs, closures, or unsupported external libraries within these sub-functions is not allowed.
