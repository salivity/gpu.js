Passing Textures Between GPU.js Instances

When using GPU.js to accelerate JavaScript operations via WebGL, passing a GPU-bound texture generated by one GPU instance into a kernel belonging to another instance will cause an execution failure. Because each GPU instance manages an independent WebGL rendering context, textures cannot be natively shared across them. Attempting this transfer breaks WebGL's boundary rules, triggering context errors, undefined behaviors, or corrupt calculations.

Underlying WebGL Context Isolation

Each time you initialize a new GPU.js instance using new GPU(), the library provisions a dedicated, self-contained WebGL context on the canvas or headless environment. In standard WebGL architectures, GPU memory resources—such as textures, framebuffers, and vertex arrays—are strictly tied to the specific context that allocated them.

A Texture object produced by GPU.js wraps an underlying WebGLTexture. When this texture is passed to a different GPU instance, the receiving instance attempts to bind that native texture ID using its own WebGL context methods (such as gl.bindTexture). Because the texture identifier is foreign and unmapped within the second context, the WebGL runtime raises a WebGL INVALID_OPERATION or INVALID_VALUE error.

What Actually Happens at Runtime

Depending on your browser, operating system, and GPU.js mode, passing a texture across instances results in several failure modes:

  • WebGL Errors in Console: The receiving kernel triggers gl.bindTexture: texture does not belong to this context or a generic INVALID_OPERATION during draw calls.
  • Corrupted or Blank Data: If the error does not halt JavaScript execution completely, the receiving kernel reads empty, black, or all-zero data matrices because the sampler cannot resolve the foreign texture memory.
  • Pipeline Breakdown: GPU.js pipelines rely on chaining textures to keep calculations inside VRAM. Passing foreign textures breaks this chain, defeating the purpose of memory-optimized GPU pipelines.

The Proper Way to Share Data Between Instances

If you must distribute data from one GPU instance to another, the texture data must cross the CPU boundary first:

  1. Convert Texture to CPU Array: Call .toArray() on the output texture of the first instance. This downloads the pixel data from the GPU into standard JavaScript arrays or TypedArrays.
  2. Pass Arrays to the Second Instance: Supply the resulting CPU-side array directly as an argument to the kernel belonging to the second GPU instance, which will then generate a new texture within its own context.

The Recommended Architecture: Reuse a Single Instance

Rather than attempting cross-instance sharing, create only one GPU instance throughout the application lifecycle. A single GPU instance can compile multiple kernels that safely read and write the same shared textures when configured with { pipeline: true }. This approach avoids expensive CPU roundtrips via .toArray() while fully adhering to WebGL context constraints.
