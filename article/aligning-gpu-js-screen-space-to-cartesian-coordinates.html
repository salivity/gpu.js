Aligning gpu.js Screen Space to Cartesian Coordinates

Aligning gpu.js screen space with a Cartesian coordinate system requires a linear mapping from discrete, non-negative thread indices to a continuous, centered coordinate plane. This article explains the dimensional differences between gpu.js thread indexing and standard Cartesian coordinates, provides the mathematical formula for translation and scaling, and details how to account for aspect ratio and axis orientation inside a GPU kernel.

Understanding the Coordinate Discrepancy

In gpu.js, kernels execute across a discrete grid defined by setOutput([width, height]). Within the kernel execution context, each thread references its position via this.thread.x and this.thread.y.

  • gpu.js Thread Space: The origin \((0, 0)\) resides at the bottom-left corner of the execution grid. Values are discrete integers where \(x \in [0, \text{width} - 1]\) and \(y \in [0, \text{height} - 1]\).
  • Cartesian Coordinate Space: The origin \((0, 0)\) typically sits at the center of the viewport, with coordinates spanning negative and positive ranges (for example, \(x \in [-1, 1]\) and \(y \in [-1, 1]\)), moving continuously in both directions.

The Linear Transformation Formula

To map the discrete thread range \([0, W]\) and \([0, H]\) to an arbitrary Cartesian domain \([x_{\min}, x_{\max}]\) and \([y_{\min}, y_{\max}]\), apply a standard affine linear transformation:

\[x_{\text{cartesian}} = x_{\min} + \left( \frac{\text{this.thread.x}}{\text{width}} \right) \cdot (x_{\max} - x_{\min})\]

\[y_{\text{cartesian}} = y_{\min} + \left( \frac{\text{this.thread.y}}{\text{height}} \right) \cdot (y_{\max} - y_{\min})\]

Mapping to a Centered Plane with Equal Scaling

When mapping the viewport so that \((0, 0)\) is directly in the center and ranges from \(-1.0\) to \(1.0\) along the shortest axis, you must account for the aspect ratio to avoid geometric distortion.

  1. Normalize Thread Coordinates: Scale indices to a \([0, 1]\) range: \[u = \frac{\text{this.thread.x}}{\text{width}}\] \[v = \frac{\text{this.thread.y}}{\text{height}}\]

  2. Shift the Origin to the Center: Shift the range to \([-0.5, 0.5]\) and scale by 2 to reach \([-1.0, 1.0]\): \[x = (u - 0.5) \cdot 2.0\] \[y = (v - 0.5) \cdot 2.0\]

  3. Correct for Aspect Ratio: Multiply the wider dimension by the aspect ratio (\(A = \frac{\text{width}}{\text{height}}\)): \[x_{\text{cartesian}} = x \cdot \left(\frac{\text{width}}{\text{height}}\right)\] \[y_{\text{cartesian}} = y\]

Handling Canvas and Texture Y-Inversion

While standard WebGL and gpu.js place this.thread.y = 0 at the bottom, standard HTML5 Canvas 2D contexts and DOM mouse events treat the top-left corner as \((0, 0)\).

If your input data comes from an inverted screen coordinate system (such as screen-space mouse coordinates), you must invert the vertical component before transforming:

\[y_{\text{inverted}} = (\text{height} - 1) - \text{this.thread.y}\]

Implementation in a gpu.js Kernel

Inside a gpu.js kernel function, compute the coordinates at the start of execution:

const kernel = gpu.createKernel(function(width, height) {
    // 1. Shift origin to center and map to [-1, 1]
    const x = (this.thread.x / width) * 2.0 - 1.0;
    const y = (this.thread.y / height) * 2.0 - 1.0;

    // 2. Adjust for aspect ratio
    const aspectRatio = width / height;
    const cartesianX = x * aspectRatio;
    const cartesianY = y;

    // Use cartesianX and cartesianY for plotting functions, fractals, or simulations
    return Math.sin(cartesianX) * Math.cos(cartesianY);
}).setOutput([800, 600]);

This normalization and scaling sequence aligns the discrete execution grid of gpu.js directly with mathematical Cartesian space.
