Texture Filtering in GPU.js: Nearest vs Linear

GPU.js accelerates JavaScript operations by compiling code into WebGL shaders, using textures internally to store and pass numerical arrays and matrices across the GPU. Because GPU.js is designed primarily for high-performance computing rather than visual 3D rendering, it handles texture filtering by enforcing nearest-neighbor sampling by default, deliberately avoiding linear interpolation to preserve numerical precision.

The Role of Textures in GPU.js

In WebGL, data inputs—such as 1D, 2D, or 3D numerical arrays—are mapped onto 2D textures where each texel stores floating-point or integer values. When a kernel function reads an array element using bracket notation (such as matrix[y][x]), the compiled GLSL shader performs a texture lookup to fetch the corresponding value.

Why GPU.js Defaults to Nearest-Neighbor

GPU.js configures WebGL textures using nearest-neighbor filtering (gl.NEAREST for both magnification and minification). When executing computational algorithms, exact data retrieval is essential. Linear filtering (gl.LINEAR) calculates a weighted average of surrounding texels, which is ideal for smoothing graphics but detrimental to mathematical computations. If linear filtering were applied to matrix multiplications or numerical simulations, intermediate data points would become blurred, producing mathematically invalid outputs.

By using nearest-neighbor filtering alongside exact texel coordinate calculation, GPU.js guarantees:

  • Precision: Every read operation retrieves the exact value stored at a specific memory location.
  • Compatibility: Many mobile and older desktop GPUs lack the hardware extensions required to perform linear filtering on high-precision floating-point textures (such as OES_texture_float_linear). Using nearest-neighbor maximizes hardware support.

Pipeline Mode and Texture Handling

When chained computation is enabled via .setPipeline(true), kernels output directly to WebGL textures instead of serializing data back into CPU memory. These intermediate textures maintain the same gl.NEAREST configuration. The subsequent kernel treats the output texture as an exact lookup table, ensuring data passes through multi-stage computational pipelines without rounding or interpolation artifacts.

Manual Implementation of Linear Filtering

GPU.js does not expose a high-level configuration API (such as a kernel setting) to switch textures to gl.LINEAR. If an application requires bilinear interpolation—such as for image scaling, smoothing, or visual texture synthesis—the developer must implement the interpolation logic directly inside the kernel function.

To achieve bilinear sampling manually:

  1. Pass the base texture or image into the kernel.
  2. Calculate the four neighboring coordinates (x0, y0, x1, y0, x0, y1, and x1, y1) corresponding to the fractional sample position.
  3. Retrieve all four discrete values using standard index lookups.
  4. Compute the weighted average based on the fractional offset using arithmetic operations within the kernel.

Through this architecture, GPU.js prioritizes deterministic computational accuracy by relying on nearest-neighbor sampling under the hood, while leaving specialized spatial interpolation to user-defined shader logic.
