Tensor Contraction for 4D Arrays in GPU.js

This article explains how to design and execute tensor contraction algorithms across four-dimensional (4D) numerical arrays using the GPU.js library. It covers the mathematical formulation of index contraction, the structural limitations of WebGL-based pipelines regarding multidimensional arrays, index mapping techniques to bypass 3D kernel constraints, and a complete code implementation for executing parallel contractions on the GPU.

Mathematical Formulation

Tensor contraction generalizes matrix multiplication to higher dimensions. For two 4D tensors, \(A \in \mathbb{R}^{I \times J \times K \times L}\) and \(B \in \mathbb{R}^{K \times L \times M \times N}\), contracting across the shared indices \(k\) and \(l\) yields a new 4D tensor \(C \in \mathbb{R}^{I \times J \times M \times N}\):

\[C_{i,j,m,n} = \sum_{k=0}^{K-1} \sum_{l=0}^{L-1} A_{i,j,k,l} \cdot B_{k,l,m,n}\]

Index Mapping and Dimensional Constraints in GPU.js

GPU.js supports output dimensions up to three levels (output: [x, y, z]). Because a direct 4D output topology is unsupported, the 4D result space must be mapped onto a 2D or 3D kernel space.

A reliable method maps the output pairs \((i, j)\) and \((m, n)\) onto a 2D computational grid:

  • The horizontal thread coordinate (this.thread.x) represents the composite index of \((m, n)\), with size \(M \times N\).
  • The vertical thread coordinate (this.thread.y) represents the composite index of \((i, j)\), with size \(I \times J\).

Within the kernel, the composite thread coordinates are decomposed back into individual indices:

  • \(m = \lfloor \text{thread.x} / N \rfloor\)
  • \(n = \text{thread.x} \pmod N\)
  • \(i = \lfloor \text{thread.y} / J \rfloor\)
  • \(j = \text{thread.y} \pmod J\)

Input tensors can be passed as nested 4D arrays directly if supported by the environment, or flattened into 1D/2D arrays to minimize WebGL texture transfer overhead. Passing structured nested arrays remains the most readable approach.

Implementation

The following code configures a GPU.js kernel to contract two 4D arrays across two shared dimensions:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Dimensions: A is [I][J][K][L], B is [K][L][M][N]
const I = 4, J = 4, K = 8, L = 8, M = 4, N = 4;

const contract4DTensors = gpu.createKernel(function(A, B, K_dim, L_dim, J_dim, N_dim) {
    // Decode 2D thread coordinates to 4D target indices
    const n = this.thread.x % N_dim;
    const m = Math.floor(this.thread.x / N_dim);
    
    const j = this.thread.y % J_dim;
    const i = Math.floor(this.thread.y / J_dim);

    let sum = 0;

    // Perform contraction over shared dimensions K and L
    for (let k = 0; k < K_dim; k++) {
        for (let l = 0; l < L_dim; l++) {
            sum += A[i][j][k][l] * B[k][l][m][n];
        }
    }

    return sum;
})
.setOutput([M * N, I * J]);

// Tensor Initialization Helpers
function create4DTensor(d1, d2, d3, d4) {
    return Array.from({ length: d1 }, () =>
        Array.from({ length: d2 }, () =>
            Array.from({ length: d3 }, () =>
                Array.from({ length: d4 }, () => Math.random())
            )
        )
    );
}

const tensorA = create4DTensor(I, J, K, L);
const tensorB = create4DTensor(K, L, M, N);

// Execute kernel
const flatResult = contract4DTensors(tensorA, tensorB, K, L, J, N);

// Optional: Reshape 2D output back into a 4D array [I][J][M][N]
function reshapeTo4D(flatArray, dimI, dimJ, dimM, dimN) {
    const result = [];
    for (let i = 0; i < dimI; i++) {
        result[i] = [];
        for (let j = 0; j < dimJ; j++) {
            result[i][j] = [];
            const y = i * dimJ + j;
            for (let m = 0; m < dimM; m++) {
                result[i][j][m] = [];
                for (let n = 0; n < dimN; n++) {
                    const x = m * dimN + n;
                    result[i][j][m][n] = flatArray[y][x];
                }
            }
        }
    }
    return result;
}

const tensorC = reshapeTo4D(flatResult, I, J, M, N);

Performance Considerations

  1. Memory Transfer: WebGL encodes nested input arrays into 2D floating-point textures. For very large dimensions, passing pre-flattened typed arrays (Float32Array) reduces JavaScript garbage collection overhead and texture conversion latency.
  2. Loop Bounds: GPU.js requires dynamic loop upper bounds to be passed directly as numeric arguments rather than reading them from tensor properties.
  3. Precision: GPU.js uses single-precision 32-bit floating-point numbers by default. Accumulating contractions across large dimensions can introduce precision drift compared to 64-bit CPU implementations.
