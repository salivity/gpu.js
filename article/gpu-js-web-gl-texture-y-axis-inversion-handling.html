GPU.js WebGL Texture Y-Axis Inversion Handling

This article explores how GPU.js resolves the fundamental mismatch between WebGL's bottom-left texture coordinate system and JavaScript’s top-left row-major array indexing. By automating coordinate transformations during shader compilation and read-back phases, GPU.js ensures that mathematical matrix representations match standard 2D array conventions without requiring manual index manipulation from the developer.

In standard WebGL, the texture coordinate system (UV space) places the origin (0, 0) at the bottom-left corner, with the Y-axis increasing upward. Conversely, standard JavaScript 2D arrays, HTML5 Canvas contexts, and image processing conventions place the origin at the top-left corner, with the vertical axis increasing downward (row-major order). Without compensation, directly mapping arrays into WebGL textures and rendering them results in vertically flipped data.

GPU.js addresses this coordinate discrepancy at the GLSL code generation level. When a kernel is defined, GPU.js abstracts the parallel execution grid into threads accessible via this.thread.x, this.thread.y, and this.thread.z. Under the hood, the compiler maps these thread coordinates to the physical WebGL viewport and texture dimensions. When calculating internal fragment positions, GPU.js accounts for the inversion by directly offsetting or inverting the vertical dimension inside the generated vertex and fragment shaders.

For input data, GPU.js processes JavaScript arrays and packs them into floating-point or integer textures. Depending on whether the input is raw array data or an existing HTML element, GPU.js either structures the texture memory to align with expected index lookups or configures WebGL pixel storage flags, such as UNPACK_FLIP_Y_WEBGL, ensuring that index [0][0] accurately corresponds to thread coordinate (0, 0).

When managing kernel outputs, GPU.js maintains texture pipeline consistency. If a kernel returns a texture for composition or subsequent kernel passes, the inverted coordinate space is preserved internally between shaders to avoid redundant flipping operations. However, when output data is retrieved back to the CPU via gl.readPixels, GPU.js reverses the row order of the pixel buffer. This ensures that the returned multidimensional JavaScript array restores the standard top-down index ordering, keeping the hardware-level inversion completely invisible to the programmer.
