GPU.js Graphical Mode Alpha Blending Explained

In gpu.js, graphical mode enables kernels to render directly to an HTML5 canvas using WebGL fragment shaders instead of returning computed numeric arrays. Transparency and alpha blending in this mode are managed through normalized color channels passed to the built-in this.color(r, g, b, a) function, where WebGL handles transparency at the canvas layer against the webpage DOM, while any internal pixel-over-pixel blending within a single render pass must be manually computed in shader logic.

The this.color() Method and Normalized Alpha

To enable graphical rendering, the kernel must be initialized with the { graphical: true } option. Inside a graphical kernel, the output of each thread (which corresponds to an individual pixel) is defined using:

this.color(r, g, b, a);

All four parameters require floating-point values normalized between 0.0 and 1.0:

  • 0.0 represents complete transparency for the alpha channel.
  • 1.0 represents complete opacity.
  • Values between 0.0 and 1.0 represent semi-transparency.

Canvas and DOM Compositing

When gpu.js outputs pixel data with an alpha value lower than 1.0, the underlying WebGL context composites the rendered canvas over HTML elements behind it.

By default, WebGL uses premultiplied alpha compositing when writing to the browser's display buffer. If an area of the canvas has this.color(1, 0, 0, 0.5), it renders a semi-transparent red pixel. The browser will blend this red pixel with whatever background color or image lies beneath the <canvas> tag in the DOM structure.

Internal Blending Limitations

A common misconception is that gpu.js supports automatic hardware-level blending between overlapping shapes drawn inside the same kernel execution. WebGL fragment shaders execute across all pixels in parallel, meaning a thread writing to a specific coordinate cannot directly read the previously written color at that exact screen location in standard execution.

Because of this architectural constraint:

  1. Single-Pass Layering: If you are rendering multiple visual elements (such as two overlapping circles) in a single kernel run, you must calculate the alpha blending manually in the kernel code using the standard "Over" blending formula:

\[C_{result} = C_{foreground} \times \alpha_{foreground} + C_{background} \times (1.0 - \alpha_{foreground})\]

\[\alpha_{result} = \alpha_{foreground} + \alpha_{background} \times (1.0 - \alpha_{foreground})\]

  1. Multi-Pass Rendering: If you need to accumulate layers iteratively across multiple frames or passes, you must feed the canvas or output texture from the previous render pass back into the kernel as an input texture, sampling the background color with kernel.canvas or input arrays and calculating the composite manually before calling this.color().

Code Implementation Example

The following pattern demonstrates manual alpha blending of a semi-transparent foreground object over a background color within a graphical kernel:

const gpu = new GPU();

const render = gpu.createKernel(function() {
    // Coordinates normalized to [0, 1]
    const x = this.thread.x / this.output.x;
    const y = this.thread.y / this.output.y;

    // Background color: Blue (opaque)
    const bgR = 0.0;
    const bgG = 0.0;
    const bgB = 1.0;
    const bgA = 1.0;

    // Foreground color: Red with 50% transparency
    const fgR = 1.0;
    const fgG = 0.0;
    const fgB = 0.0;
    const fgA = 0.5;

    // Determine if pixel is inside a centered circle
    const dx = x - 0.5;
    const dy = y - 0.5;
    const isInsideCircle = (dx * dx + dy * dy) < 0.04;

    if (isInsideCircle) {
        // Alpha blending: Target = Foreground * Alpha + Background * (1 - Alpha)
        const finalR = (fgR * fgA) + (bgR * (1.0 - fgA));
        const finalG = (fgG * fgA) + (bgG * (1.0 - fgA));
        const finalB = (fgB * fgA) + (bgB * (1.0 - fgA));
        const finalA = fgA + (bgA * (1.0 - fgA));

        this.color(finalR, finalG, finalB, finalA);
    } else {
        this.color(bgR, bgG, bgB, bgA);
    }
})
.setOutput([512, 512])
.setGraphical(true);

render();
document.body.appendChild(render.canvas);

Using this approach allows full control over how overlapping transparencies behave, bypassing the single-pass limitations of WebGL shaders while leveraging GPU acceleration.
