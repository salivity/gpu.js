Catastrophic Cancellation in gpu.js Float Math

Catastrophic cancellation is a severe numerical instability that occurs when subtracting two nearly equal floating-point values, and in gpu.js, this problem is heavily magnified due to the framework's reliance on WebGL-based single-precision arithmetic. This article examines the mechanics of catastrophic cancellation within gpu.js kernels, explains why WebGL precision constraints exacerbate accuracy loss compared to standard JavaScript execution, and details practical mathematical and architectural strategies to maintain precision in GPU-accelerated computing.

What is Catastrophic Cancellation?

Catastrophic cancellation occurs when two nearly identical floating-point numbers are subtracted. In floating-point arithmetic, numbers are represented by a sign, an exponent, and a mantissa (significand). When two numbers share their most significant digits, subtracting them cancels out those leading digits, leaving only the least significant bits.

Because the least significant bits often contain accumulated rounding errors from prior operations, shifting these remaining bits into the most significant position during normalization magnifies the noise. The result can lose most or all of its significant digits, yielding answers that are mathematically incorrect by orders of magnitude.

The gpu.js Precision Bottleneck

JavaScript executed on the CPU natively uses the IEEE 754 double-precision (64-bit) floating-point format, which provides 53 bits of significand precision—roughly 15 to 17 decimal digits.

When code is offloaded to the GPU using gpu.js, the library compiles the JavaScript kernel functions into WebGL fragment shaders (GLSL). Most WebGL environments and mobile GPUs natively execute floating-point operations using IEEE 754 single-precision (32-bit), designated by the highp precision qualifier. Single-precision floats allocate only 24 bits to the significand, providing roughly 7 decimal digits of precision.

Because gpu.js runs operations in 32-bit precision by default, the margin for error before catastrophic cancellation occurs shrinks dramatically:

  • In native JavaScript (64-bit): Subtracting 1.000000000001 from 1.000000000002 retains sufficient precision to resolve the difference.
  • In gpu.js (32-bit): Numbers like 1.000001 and 1.000002 already sit at the boundary of 7 decimal digits. Subtracting them causes the identical high-order bits to cancel, leaving behind low-order rounding noise or rounding to zero entirely.

Common Scenarios in gpu.js Kernels

Catastrophic cancellation frequently affects specific algorithms run via gpu.js:

  1. Numerical Differentiation: Approximating derivatives using finite differences requires calculating expressions like (f(x + h) - f(x)) / h. As the step size h becomes small, f(x + h) and f(x) become nearly identical, leading to massive cancellation in 32-bit execution.
  2. Geometric Distances and Collision Detection: Calculating distances between points that are far from the origin but very close to each other (such as large-scale coordinates in geospatial or physics simulations) requires subtracting large coordinates, which destroys the resolution of the small offset.
  3. Statistical Variance: Using the naive formula Var(X) = E[X^2] - (E[X])^2 causes catastrophic cancellation if the variance is small relative to the mean squared.

Mitigating Cancellation in gpu.js

To avoid precision loss within gpu.js kernels, consider the following approaches:

1. Algebraic Reformulation

Restructure mathematical formulas to eliminate direct subtraction of nearly identical values. For example:

  • Instead of computing sqrt(x + 1) - sqrt(x), multiply by the conjugate to compute 1.0 / (sqrt(x + 1) + sqrt(x)).
  • For small angles, replace 1.0 - cos(x) with 2.0 * sin(x / 2.0) * sin(x / 2.0).

2. Relative Coordinates (Local Reference Frames)

When dealing with spatial data, do not pass absolute global coordinates directly to the gpu.js kernel. Center the data on the CPU before passing it to the GPU:

  • Subtract a local base origin on the CPU using 64-bit precision.
  • Pass the smaller relative offsets into the 32-bit gpu.js kernel for difference, distance, or matrix transformations.

3. Two-Pass Variance Algorithms

Instead of computing variance via E[X^2] - (E[X])^2, use a two-pass approach. First, calculate the mean across the dataset. Second, pass the precalculated mean to the gpu.js kernel to compute the sum of squared deviations (x - mean)^2, ensuring the difference operation does not subtract two massive squared sums.
