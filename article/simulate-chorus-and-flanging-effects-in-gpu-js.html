Simulate Chorus and Flanging Effects in GPU.js

Simulating delay-line modulation effects such as chorus and flanging across multi-channel audio buffers requires parallelizing fractional delay lookups and low-frequency oscillator (LFO) evaluations. By utilizing gpu.js, you can offload this computation to the GPU by mapping audio channels and sample frames to a two-dimensional grid. This article details the mathematical model of time-varying delay lines, addresses linear interpolation for fractional indices, and provides an implementation pattern for multi-channel processing in WebGL via gpu.js.

Delay-Line Mechanics: Flanging vs. Chorus

Both effects rely on reading from a delay buffer using a modulated read pointer:

  • Flanging: Employs a short delay range (typically 0.1 ms to 10 ms) with high depth and optional feedback, creating closely spaced comb-filter notches across the spectrum.
  • Chorus: Uses a longer delay range (typically 10 ms to 30 ms) with multiple non-synchronized delay paths, lower feedback, and subtle pitch-shifting deviations to emulate multiple instruments playing simultaneously.

The time-varying delay \(d(t)\) at sample index \(n\) is defined by:

\[d(n) = \text{baseDelay} + \text{depth} \times \sin(2\pi \cdot f_{\text{LFO}} \cdot \frac{n}{f_s} + \phi_{\text{channel}})\]

Where:

  • \(f_s\) is the sampling rate (e.g., 44100 Hz).
  • \(f_{\text{LFO}}\) is the modulation rate (typically 0.1 Hz to 5 Hz).
  • \(\phi_{\text{channel}}\) is a phase offset per channel to widen the stereo or surround field.

Data Layout for GPU.js

Because WebGL shaders execute concurrently across pixels, processing is best structured block-by-block or as static sample buffers. To handle multiple channels, configure the GPU kernel to use a 2D output space where:

  • X-axis (this.thread.x): Sample index within the current audio block.
  • Y-axis (this.thread.y): Audio channel (e.g., 0 for Left, 1 for Right).

Input audio must be passed as an array of arrays (one array per channel) or flattened with uniform dimension accessors.

Handling Fractional Samples via Linear Interpolation

A modulated read position rarely lands on an exact sample boundary. Reading nearest neighbors produces harsh quantization noise; therefore, the kernel must perform linear interpolation between the two nearest surrounding discrete samples:

\[\text{sample}(n - d) \approx (1 - f) \cdot x[\lfloor n - d \rfloor] + f \cdot x[\lfloor n - d \rfloor + 1]\]

Where \(f = (n - d) - \lfloor n - d \rfloor\).

Implementation in GPU.js

Below is the complete kernel configuration for rendering a multi-channel chorus/flange block.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Define constants
const sampleRate = 44100;
const bufferLength = 2048;
const channelCount = 2;

// Set parameter ranges:
// For flanger: baseDelay = 0.003 (3ms), depth = 0.002 (2ms)
// For chorus:  baseDelay = 0.020 (20ms), depth = 0.005 (5ms)
const baseDelaySec = 0.015;
const depthSec = 0.005;
const lfoFreq = 1.2;
const dryWetMix = 0.5; // 0.0 = full dry, 1.0 = full wet

const processModulation = gpu.createKernel(function(audioBuffer, sampleRate, baseDelaySec, depthSec, lfoFreq, dryWet) {
    const sampleIdx = this.thread.x;
    const channelIdx = this.thread.y;

    // Phase offset per channel (e.g., 90 degrees out of phase for stereo widening)
    const channelPhase = channelIdx * 1.57079632679; 
    const currentTime = sampleIdx / sampleRate;

    // Calculate LFO value
    const lfo = Math.sin((6.28318530718 * lfoFreq * currentTime) + channelPhase);

    // Calculate current delay in samples
    const delaySamples = (baseDelaySec + (depthSec * lfo)) * sampleRate;
    const readPos = sampleIdx - delaySamples;

    // Dry sample
    const drySample = audioBuffer[channelIdx][sampleIdx];

    // Boundary check for buffer underrun
    if (readPos < 0) {
        return drySample;
    }

    // Fractional delay components
    const indexLow = Math.floor(readPos);
    const indexHigh = indexLow + 1;
    const fraction = readPos - indexLow;

    // Fetch bounding samples
    const sampleLow = audioBuffer[channelIdx][indexLow];
    const sampleHigh = (indexHigh < this.output.x) ? audioBuffer[channelIdx][indexHigh] : sampleLow;

    // Linear Interpolation
    const wetSample = (1.0 - fraction) * sampleLow + fraction * sampleHigh;

    // Wet/Dry mix output
    return (drySample * (1.0 - dryWet)) + (wetSample * dryWet);
})
.setOutput([bufferLength, channelCount]);

Boundary Handling and Block-Based Processing

When executing delay processing in continuous real-time audio streams:

  1. History Buffers: A thread at the start of a buffer (sampleIdx = 0) reading backward will attempt to access indices below zero. To resolve this in streaming architectures, concatenate the tail of the preceding audio frame (at least equal in length to maxDelay = baseDelay + depth) to the beginning of the input matrix.
  2. Feedback Limitations: Pure feedforward chorus and flanging parallelize fully because each output sample depends only on input memory. If recursive feedback is required (common in intense flanging), samples become causally dependent on preceding outputs, which breaks total parallelization. For feedback architectures, execute the GPU kernel over shorter block intervals or calculate the state sequentially inside loop constructs per thread.
