Computing Audio STFT with GPU.js

This article explains how to compute sliding-window Short-Time Fourier Transforms (STFT) on raw audio buffers using GPU.js. By translating the Discrete Fourier Transform (DFT) formulation into WebGL shaders, you can process audio frames in parallel across the GPU rather than iterating serially on the CPU. The following sections cover window slicing parameters, kernel configuration, trigonometric accumulation, and practical performance considerations.

Understanding the Pipeline

An STFT divides a continuous audio signal into overlapping segments (frames) and computes the Fourier transform for each frame. This produces a 2D time-frequency representation (spectrogram).

The key parameters are:

  • Audio Buffer (\(x\)): A 1D array of PCM audio samples (typically Float32Array).
  • Window Size (\(N\)): The length of each segment in samples (e.g., 1024 or 2048).
  • Hop Size (\(H\)): The number of samples advanced between consecutive frames (e.g., 256 or 512).
  • Window Function (\(w\)): An attenuation function (such as Hann or Hamming) applied to each frame to minimize spectral leakage.

The total number of frames is calculated as:

\[\text{numFrames} = \left\lfloor \frac{\text{audioLength} - N}{H} \right\rfloor + 1\]

Because real-valued signals yield symmetric frequency representations, we only compute \(K = \frac{N}{2} + 1\) bins per frame.

Setting Up the GPU.js Kernel

GPU.js allows developers to write standard JavaScript functions that are automatically compiled into GLSL fragment shaders.

While the Fast Fourier Transform (FFT) algorithm minimizes operations to \(O(N \log N)\) on single-threaded CPUs, a standard Discrete Fourier Transform (DFT) can be computed in \(O(N)\) operations directly per thread. Because the GPU can process thousands of bin-frame combinations simultaneously, a direct DFT kernel across time and frequency is straightforward to implement and highly performant.

The output grid is mapped as a 2D matrix:

  • X-dimension: Frequency bins (\(k \in [0, N / 2]\))
  • Y-dimension: Time frames (\(m \in [0, \text{numFrames} - 1]\))

Kernel Implementation

import { GPU } from 'gpu.js';

function computeSTFT(audioBuffer, windowSize, hopSize) {
  const gpu = new GPU();
  const audioLength = audioBuffer.length;
  const numBins = Math.floor(windowSize / 2) + 1;
  const numFrames = Math.floor((audioLength - windowSize) / hopSize) + 1;

  // Precompute Hann window values on the CPU
  const windowFunction = new Float32Array(windowSize);
  for (let n = 0; n < windowSize; n++) {
    windowFunction[n] = 0.5 * (1 - Math.cos((2 * Math.PI * n) / (windowSize - 1)));
  }

  // Define the GPU kernel
  const stftKernel = gpu.createKernel(function(audio, win, winSize, hop) {
    const k = this.thread.x; // Frequency bin index
    const m = this.thread.y; // Frame index

    let real = 0.0;
    let imag = 0.0;

    const frameOffset = m * hop;
    const pi2 = 6.283185307179586;

    for (let n = 0; n < winSize; n++) {
      const sample = audio[frameOffset + n] * win[n];
      const angle = (pi2 * k * n) / winSize;
      
      real += sample * Math.cos(angle);
      imag -= sample * Math.sin(angle);
    }

    // Return the spectral magnitude
    return Math.sqrt(real * real + imag * imag);
  })
  .setOutput([numBins, numFrames])
  .setPrecision('unsigned');

  // Execute kernel
  const spectrogram = stftKernel(audioBuffer, windowFunction, windowSize, hopSize);

  return {
    spectrogram,
    numFrames,
    numBins
  };
}

Explanation of Execution

  1. Window Alignment: Each thread uses m * hop to find the start index of the current frame in the flattened audio buffer.
  2. Windowing & Transformation: The inner loop iterates \(N\) times. Each sample is multiplied by the corresponding coefficient from win before evaluating the trigonometric components.
  3. Magnitude Calculation: The kernel sums the real and imaginary components over all \(N\) points, computes the Euclidean norm \(\sqrt{\text{real}^2 + \text{imag}^2}\), and writes the value to that specific pixel/coordinate in the output texture.

Performance and Implementation Considerations

  • Memory Transfers: Uploading massive audio buffers to GPU texture memory introduces overhead. For large audio files (e.g., several minutes), split the input into contiguous chunks (e.g., 5- to 10-second segments) to balance GPU memory consumption and execution efficiency.
  • Complex Number Outputs: If phase information is required alongside magnitude, change the kernel to return a vector [real, imag] using GPU.js graphical output modes, or run two separate kernels for real and imaginary matrices.
  • Window Size Constraints: Because the loop runs \(N\) times per thread, large window sizes (such as \(N \ge 4096\)) will increase shader execution time. For very large window sizes, implementing a multi-pass radix-2 Cooley-Tukey FFT structure across multiple shader passes is preferable over a single-pass DFT.
