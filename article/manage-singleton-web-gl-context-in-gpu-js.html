Manage Singleton WebGL Context in gpu.js

Web browsers enforce strict limits on the number of concurrent WebGL contexts allowed per page, which typically ranges between 8 and 16. Instantiating multiple GPU objects with gpu.js rapidly exhausts these available slots, causing older contexts to silently fail or throw context-loss errors. Implementing a singleton pattern for your GPU instance centralizes resource allocation, preserves GPU memory, and ensures all kernel operations share a single, long-lived WebGL context. This guide covers the mechanics of context limits, provides an implementation of a singleton wrapper for gpu.js, and outlines strategies for kernel reuse.

The Cause of WebGL Context Exhaustion

Every time you call new GPU(), the library creates a hidden HTML <canvas> element and initializes a new WebGL rendering context (WebGLRenderingContext or WebGL2RenderingContext).

Browsers limit the maximum number of active hardware contexts to conserve system VRAM. When an application exceeds this limit, the browser automatically destroys the oldest context using the webglcontextlost event to make room for the newest one. Any gpu.js kernels bound to the evicted context will immediately stop functioning and throw unrecoverable execution errors.

Implementing a Singleton GPU Manager

To prevent exhaustion, instantiate GPU exactly once and share that reference across your entire codebase. In modern JavaScript environments (such as Node.js bundling with Vite, Webpack, or ES modules), a module-level singleton pattern ensures that only one instance exists.

import { GPU } from 'gpu.js';

class GPUManager {
  constructor() {
    if (!GPUManager.instance) {
      this.gpu = new GPU({
        mode: 'gpu' // Falls back to CPU if WebGL is unavailable
      });
      this.kernels = new Map();
      GPUManager.instance = this;
    }
    return GPUManager.instance;
  }

  getInstance() {
    return this.gpu;
  }

  /**
   * Caches and retrieves compiled kernels to avoid recompilation overhead.
   */
  getOrCreateKernel(name, createKernelFn) {
    if (!this.kernels.has(name)) {
      const kernel = createKernelFn(this.gpu);
      this.kernels.set(name, kernel);
    }
    return this.kernels.get(name);
  }

  /**
   * Destroys existing kernels and cleanly releases context resources if necessary.
   */
  destroy() {
    this.kernels.forEach((kernel) => kernel.destroy(true));
    this.kernels.clear();
    if (this.gpu) {
      this.gpu.destroy();
      GPUManager.instance = null;
    }
  }
}

const instance = new GPUManager();
Object.freeze(instance);

export default instance;

Reusing Kernels and Managing Memory

Context management goes beyond avoiding repeated new GPU() calls; creating too many individual kernels on the same context also wastes memory. Compiling a kernel creates WebGL programs, shaders, and framebuffers.

Follow these best practices to maintain efficiency:

  1. Cache Kernels: Use the kernel caching pattern shown in the manager class above. Instead of generating an anonymous kernel inside an event listener or render loop, generate it once and invoke it with new input parameters.
  2. Keep Outputs Predictable: Changing the output dimensions (setOutput([width, height])) of an existing kernel forces WebGL framebuffer reallocations. If dimensions vary frequently, compile separate dedicated kernels or use the maximum needed boundary and slice the output.
  3. Clean Up Textures: If you enable pipeline mode (pipeline: true) to feed output from one kernel directly into another without downloading data back to the CPU, manually call .delete() on intermediate textures when they are no longer required to prevent VRAM bloat.

Passing an Existing WebGL Context

If your application already uses a WebGL context for rendering (such as with Three.js, Babylon.js, or custom canvas logic), avoid creating a secondary context entirely. You can instruct gpu.js to hook directly into the existing canvas or context via its constructor options:

import { GPU } from 'gpu.js';

const canvas = document.getElementById('application-canvas');
const existingContext = canvas.getContext('webgl2');

const gpu = new GPU({
  canvas: canvas,
  context: existingContext
});

Sharing a single WebGL context between a 3D renderer and compute kernels requires managing WebGL state bindings carefully, but it guarantees that the application never encounters context exhaustion.
