WebGL2 vs WebGL1 in gpu.js Texture Limits and Precision

Running gpu.js in WebGL2 mode delivers substantial performance and architectural improvements over the legacy WebGL1 backend, specifically regarding memory capacity and computational accuracy. By taking advantage of the modern WebGL2 standard, gpu.js increases maximum texture sizes, doubles accessible texture units, natively handles 3D memory layouts, and guarantees native 32-bit floating-point and integer arithmetic. These upgrades eliminate the memory workarounds, precision degradation, and performance overhead common in WebGL1 mathematical operations.

Expanded Texture Size and Allocation Limits

In gpu.js, arrays and matrices are mapped to GPU textures to perform general-purpose computing (GPGPU). WebGL2 significantly broadens the scale of data that can be bound and processed simultaneously:

  • Larger Maximum Texture Dimensions: WebGL1 mandates a minimum hardware texture size support of only 2048×2048 pixels, whereas WebGL2 raises baseline hardware requirements, often enabling allocations of 8192×8192, 16384×16384, or higher on modern hardware. This allows gpu.js to process substantially larger single-kernel matrices without splitting data across multiple passes.
  • Increased Texture Units: WebGL1 requires implementations to support only 8 texture image units in the fragment stage. WebGL2 increases the mandatory minimum to 16. This doubling of texture units allows gpu.js kernels to accept more concurrent array arguments and large input matrices at once without running out of hardware sampler slots.
  • Native 3D Textures: When handling three-dimensional datasets, WebGL1 requires flattening the 3D space into a 2D mosaic texture, adding index calculation overhead in the generated shader code. WebGL2 introduces native 3D textures (TEXTURE_3D), enabling direct 3D array addressing and more efficient volumetric calculations inside gpu.js kernels.

Enhanced Floating-Point Precision and Type Support

Precision limitations in WebGL1 frequently introduce floating-point drift and rounding errors. WebGL2 standardizes modern data representations:

  • Guaranteed 32-Bit Float Support: In WebGL1, 32-bit floating-point textures were dependent on optional vendor extensions (OES_texture_float and WEBGL_color_buffer_float). When these extensions were missing or read-only, gpu.js had to encode floating-point numbers across four 8-bit RGBA channels (byte-packing). WebGL2 makes high-precision floating-point formats like R32F and RGBA32F core capabilities, allowing direct reading and writing of standard IEEE 754 single-precision floats without conversion overhead.
  • Native Integer and Bitwise Operations: WebGL1 shaders rely on GLSL ES 1.00, which lacks genuine integer data types and native bitwise operators, forcing integer math to be approximated using floating-point operations. WebGL2 uses GLSL ES 3.00, introducing signed and unsigned integers (int, uint) along with native bitwise operators (<<, >>, &, |, ^, ~). This ensures exact bit-level operations and eliminates precision degradation during integer-based computations in gpu.js.
  • Uniform High Precision: WebGL2 tightens precision qualifiers across implementations. Shaders can reliably utilize highp precision across both fragment and vertex stages, producing consistent, deterministic mathematical output across varied consumer hardware.
