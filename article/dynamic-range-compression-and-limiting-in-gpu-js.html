Dynamic Range Compression and Limiting in GPU.js

This article explains how to implement real-time dynamic range compression and brickwall audio limiting in web applications using GPU.js. You will learn the mechanics of audio dynamic control, how to adapt sequential envelope detection for parallel GPU execution, write specialized GPU kernels for gain reduction, and pipe audio data between the Web Audio API and the GPU with minimal latency.

Understanding Dynamic Range Compression and Limiting

Dynamic range compression reduces the volume of loud sounds and amplifies quiet sounds by narrowing an audio signal's dynamic range. A limiter is an aggressive compressor with a high ratio (often \(\infty:1\)) and an immediate attack time designed to prevent the signal from exceeding a maximum peak threshold (typically 0 dBFS to avoid digital clipping).

Key parameters include:

  • Threshold: The level above which gain reduction begins.
  • Ratio: The amount of gain reduction applied to signals exceeding the threshold.
  • Attack Time: How quickly gain reduction engages when the threshold is crossed.
  • Release Time: How quickly the signal returns to uncompressed levels once the signal falls below the threshold.
  • Knee: Smoothness of the transition around the threshold.

The Architecture for GPU-Accelerated Audio

Standard dynamic range compression relies on recursive Infinite Impulse Response (IIR) filters for envelope tracking (\(y[n] = \alpha y[n-1] + (1 - \alpha) x[n]\)), which are inherently sequential and difficult to run on massively parallel architectures.

To execute compression efficiently on the GPU via GPU.js, use a feed-forward lookahead window approach:

  1. Audio samples are chunked into uniform buffers via the Web Audio API.
  2. The GPU calculates the local absolute peak within a lookahead window for each sample in parallel.
  3. The GPU maps each peak against the compression curve to compute the required gain reduction factor.
  4. The calculated gain factor is applied directly to the original audio buffer on the GPU, applying hard limiting if any output sample still exceeds the hard ceiling.
  5. The processed buffer is transferred back to the audio context for output.

Implementing the Processor with GPU.js

1. Initialize GPU.js

Load GPU.js and construct a compute instance optimized for WebGL/WebGPU pipeline execution.

import { GPU } from 'gpu.js';

const gpu = new GPU();
const BUFFER_SIZE = 2048;
const LOOKAHEAD_SAMPLES = 64; // Approx 1.4ms at 44.1kHz

2. Write the Compression and Limiting Kernel

The kernel computes the local windowed envelope, determines gain reduction via a soft-knee compressor curve, applies a brickwall limiter, and returns the modulated audio signal.

const processAudioKernel = gpu.createKernel(function(
  samples, 
  threshold, 
  ratio, 
  knee, 
  ceiling, 
  lookahead
) {
  const i = this.thread.x;
  const currentSample = samples[i];
  
  // 1. Peak detection using a lookahead window
  let peak = 0.0;
  for (let j = -lookahead; j <= lookahead; j++) {
    const idx = i + j;
    if (idx >= 0 && idx < this.constants.bufferSize) {
      const val = Math.abs(samples[idx]);
      if (val > peak) {
        peak = val;
      }
    }
  }

  // 2. Linear to Decibel conversion
  const peakDb = 20.0 * Math.log10(Math.max(peak, 0.00001));

  // 3. Dynamic Range Compression Curve (Soft Knee)
  let gainDb = 0.0;
  const halfKnee = knee / 2.0;

  if (peakDb > threshold + halfKnee) {
    // Above knee: full ratio compression
    gainDb = (threshold + (peakDb - threshold) / ratio) - peakDb;
  } else if (peakDb > threshold - halfKnee) {
    // Inside knee: quadratic interpolation
    const excess = peakDb - threshold + halfKnee;
    gainDb = ((1.0 / ratio - 1.0) * (excess * excess)) / (2.0 * knee);
  }

  // 4. Decibel to Linear Gain conversion
  const targetGain = Math.pow(10.0, gainDb / 20.0);
  let outputSample = currentSample * targetGain;

  // 5. Hard Limiter / Ceiling Enforcement
  if (outputSample > ceiling) {
    outputSample = ceiling;
  } else if (outputSample < -ceiling) {
    outputSample = -ceiling;
  }

  return outputSample;
}, {
  constants: { bufferSize: BUFFER_SIZE },
  output: [BUFFER_SIZE],
  precision: 'single',
  pipeline: false
});

3. Integrate with the Web Audio API

To stream audio through the GPU in real time, capture raw audio using an AudioWorklet (or a ScriptProcessorNode for legacy targets), dispatch the buffer to the compiled kernel, and output the result.

async function setupAudioPipeline() {
  const audioCtx = new (window.AudioContext || window.webkitAudioContext)();
  
  // Source setup (e.g., microphone or element)
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const source = audioCtx.createMediaStreamSource(stream);

  // Script processor buffer interface
  const processor = audioCtx.createScriptProcessor(BUFFER_SIZE, 1, 1);

  // Compression Parameters
  const threshold = -18.0; // dB
  const ratio = 4.0;       // 4:1 compression
  const knee = 6.0;        // 6 dB knee width
  const ceiling = 0.95;    // Linear amplitude limit (~ -0.45 dBFS)

  processor.onaudioprocess = function(e) {
    const inputData = e.inputBuffer.getChannelData(0);
    const outputData = e.outputBuffer.getChannelData(0);

    // Run parallel dynamics processing on the GPU
    const result = processAudioKernel(
      inputData,
      threshold,
      ratio,
      knee,
      ceiling,
      LOOKAHEAD_SAMPLES
    );

    // Populate the output buffer
    for (let i = 0; i < BUFFER_SIZE; i++) {
      outputData[i] = result[i];
    }
  };

  source.connect(processor);
  processor.connect(audioCtx.destination);
}

setupAudioPipeline();

Performance and Latency Considerations

  • Data Transfer Overhead: Passing data between the CPU (RAM) and GPU (VRAM) involves memory bus latency. A small buffer size (e.g., 256 samples) can introduce CPU-GPU synchronization bottlenecks, while large buffers (e.g., 8192 samples) increase perceived audio latency. A buffer size of 1024 or 2048 samples balances GPU utilization and real-time responsiveness.
  • Lookahead Delay: The lookahead window introduces a fixed delay equal to lookahead / sampleRate seconds. Using a window of 64 samples at a 44.1 kHz sample rate adds only 1.45 ms of algorithmic latency.
  • Texture Recycling: If chaining multiple GPU audio effects, set pipeline: true in the GPU.js kernel configuration to keep the textures directly on the GPU without downloading them to the CPU between stages.
