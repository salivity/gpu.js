Custom WebGL Blending Modes in GPU.js Kernels

This article examines whether custom WebGL blending modes can be enabled during the execution of graphical kernels in gpu.js. While gpu.js provides a high-level abstraction for running parallel computations and rendering graphics via WebGL, it lacks native API settings for configuring WebGL blend equations and functions. However, developers can achieve custom blending either by directly accessing the underlying WebGL context or by calculating blend equations mathematically within the kernel code.

Native Support in gpu.js

When creating a graphical kernel in gpu.js using { graphical: true }, the library sets up an internal WebGL pipeline configured to output pixels directly to an HTML5 canvas. The standard gpu.js API does not expose direct configuration flags for WebGL state management features like gl.enable(gl.BLEND) or gl.blendFunc(). Because gpu.js is primarily designed for general-purpose computing on the GPU (GPGPU), its default behavior is to replace pixel values in the target framebuffer rather than blend them with existing color data.

Method 1: Intercepting the Underlying WebGL Context

You can attempt hardware-level blending by directly modifying the WebGL rendering context managed by gpu.js. The underlying context can be accessed through the GPU instance via gpu.context.

To apply a custom WebGL blend mode:

  1. Retrieve the context: const gl = gpu.context;
  2. Enable blending manually before running the kernel: gl.enable(gl.BLEND);
  3. Specify your blend equation and factors, for example: gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA);
  4. Execute the graphical kernel.

While this approach relies on standard WebGL calls, it can be fragile. Internal execution steps in gpu.js may clear buffers, alter viewport states, or reset certain WebGL flags between draw calls, which can override your custom blending settings.

Method 2: Shader-Based Software Blending

The most reliable way to implement custom blending in gpu.js is to compute the blend logic directly inside the kernel function. Because gpu.js allows textures and canvases to be passed as inputs, you can implement a two-texture or ping-pong approach:

  1. Pass the existing canvas or background frame into the kernel as an input texture.
  2. Read the source color and the destination color for the current pixel coordinate.
  3. Apply standard blend formulas manually (such as additive, multiply, screen, or alpha compositing) using JavaScript math inside the kernel.
  4. Output the final computed color using this.color(r, g, b, a).

Conclusion

Direct API support for WebGL blending modes does not exist in gpu.js. While you can configure gl.blendFunc() directly on gpu.context, performing the blending math explicitly within the kernel shader provides greater control, stability, and predictability across graphical operations.
