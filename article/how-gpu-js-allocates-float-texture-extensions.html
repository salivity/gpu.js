How GPU.js Allocates Float Texture Extensions

GPU.js determines whether to allocate the OES_texture_float or EXT_color_buffer_float extension by inspecting the active WebGL context version and querying the browser's GPU driver capabilities at runtime. Because floating-point texture support differs significantly between WebGL 1 and WebGL 2 specifications, GPU.js separates these checks into distinct kernel paths, attempting to load the appropriate extension to allow writing and reading 32-bit floating-point data to and from textures.

WebGL Context Detection

During initialization, GPU.js detects whether the rendering context is an instance of WebGL2RenderingContext or WebGLRenderingContext. This context selection directly controls which float extension strategy the library employs:

  • WebGL 2 Context: Uses EXT_color_buffer_float.
  • WebGL 1 Context: Uses OES_texture_float.

WebGL 2 and EXT_color_buffer_float

In WebGL 2, basic floating-point textures are part of the core specification for sampling and storage, meaning OES_texture_float is neither necessary nor valid. However, WebGL 2 does not inherently support rendering into 32-bit float textures (using them as color attachments in framebuffers) or reading float pixels back via gl.readPixels().

To achieve floating-point computation outputs in WebGL 2, GPU.js calls:

gl.getExtension('EXT_color_buffer_float');

If this extension is available, GPU.js marks 32-bit float output as supported, allowing kernels to render full 32-bit floats directly to framebuffer textures using internal formats such as RGBA32F or R32F.

WebGL 1 and OES_texture_float

In WebGL 1, floating-point textures are not part of the core standard. To enable 32-bit float textures, GPU.js queries:

gl.getExtension('OES_texture_float');

This extension allows GPU.js to allocate textures with the gl.FLOAT type. To write to these textures via framebuffers in WebGL 1, GPU.js also checks for accompanying buffer extensions such as WEBGL_color_buffer_float.

Runtime Capability Probing

GPU.js does not rely solely on gl.getExtension() returning a non-null object. Due to driver bugs and varying mobile hardware support, an extension may be reported as present while failing during actual render or read operations.

To verify actual functionality, GPU.js executes a dynamic capability test during initialization:

  1. It attempts to instantiate an offscreen framebuffer bound to a float texture.
  2. It executes a minimal test shader that writes float values to the texture.
  3. It calls gl.readPixels() to verify if the float data can be read back directly.

If the probe succeeds, GPU.js locks in the native float pipeline. If the required extension fails to load or the probe fails, GPU.js falls back to alternative precision modes, such as half-precision floats via OES_texture_half_float / EXT_color_buffer_half_float, or 8-bit integer encoding (packing 32-bit floats across four standard RGBA channels).
