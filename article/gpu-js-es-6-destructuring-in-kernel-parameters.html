GPU.js ES6 Destructuring in Kernel Parameters

GPU.js compiles JavaScript functions into WebGL or WebGPU shader code (GLSL), which imposes strict limitations on JavaScript language features. This article explains how GPU.js processes function arguments, why ES6 destructuring syntax fails inside kernel function parameter lists, and the standard conventions required to pass data into a kernel correctly.

The Transpilation Process and AST Parsing

GPU.js relies on an Abstract Syntax Tree (AST) parser to analyze the source code of a provided kernel function. During kernel initialization, it reads the JavaScript function's string representation, parses the AST, and translates JavaScript operations into strictly typed GLSL.

In standard JavaScript, an ES6 destructuring parameter list looks like this:

const kernel = gpu.createKernel(function({ x, y }, [first, second]) {
  return x + first;
});

When the GPU.js AST parser encounters this syntax, it attempts to map the parameters to GLSL inputs, such as uniforms or textures. In the AST, standard parameters are identified as simple Identifier nodes. Destructured parameters, however, are represented as ObjectPattern or ArrayPattern nodes.

How GPU.js Handles Parameter Destructuring

GPU.js does not support ObjectPattern or ArrayPattern nodes within the kernel parameter list. When a kernel function is defined using destructuring syntax, GPU.js fails during the transpilation phase. Depending on the version of GPU.js, this results in:

  1. Compilation Errors: An uncaught exception indicating an unsupported AST node type or an invalid identifier token.
  2. Invalid GLSL Output: The transpiler fails to register the parameters as valid GLSL uniforms, resulting in WebGL shader compilation failure downstream.

GLSL requires statically typed, explicitly named uniform declarations at the top level of a shader. Because GLSL has no concept of JavaScript objects or dynamic destructuring, the GPU.js compiler requires direct 1:1 mappings between a JavaScript parameter name and a GLSL uniform variable name.

Proper Alternatives to Destructuring

To supply data to a GPU.js kernel, all parameters must be defined as simple identifiers.

1. Flat Parameter Lists

Instead of destructuring an object, pass each property as an individual argument:

const kernel = gpu.createKernel(function(x, y, multiplier) {
  return (x + y) * multiplier;
}).setOutput([1]);

// Call with separate arguments
kernel(data.x, data.y, config.multiplier);

2. Passing Arrays Directly

If handling list-based data, pass the array directly without destructuring it in the parameter list. Inside the kernel, access elements using index lookups:

const kernel = gpu.createKernel(function(arr) {
  return arr[0] + arr[1];
}).setOutput([1]);

kernel([10, 20]);

By keeping the parameter signature restricted to standard identifiers, GPU.js can properly analyze parameter types and generate the appropriate GLSL uniforms to execute the kernel on the GPU.
