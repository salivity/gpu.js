How GPU.js Compiles Math.exp and Math.log

GPU.js accelerates JavaScript calculations by transpiling standard JavaScript functions into WebGL shader code that runs directly on the GPU. When handling mathematical operations like Math.exp and Math.log, GPU.js parses the JavaScript code into an Abstract Syntax Tree (AST), maps these method calls to their corresponding OpenGL Shading Language (GLSL) intrinsics, and bundles them into a fragment shader. Once sent to the graphics driver, these GLSL instructions are compiled into native machine instructions executed by the GPU’s Special Function Units (SFUs), providing massive parallel performance.

Abstract Syntax Tree Parsing

When you define a kernel in GPU.js, the library does not execute the function in the standard V8 or JavaScript runtime engine. Instead, it serializes the JavaScript function into a string and parses it into an AST using a JavaScript parser (such as Acorn).

During this traversal, the parser looks for CallExpression nodes where the callee is a MemberExpression referencing the Math object:

  • Math.exp(x) is identified as an exponential function call.
  • Math.log(x) is identified as a natural logarithm function call.

Transpilation to GLSL Intrinsics

Once identified in the AST, GPU.js's internal code generator translates JavaScript syntax into GLSL string representations suitable for WebGL fragment shaders.

WebGL GLSL already provides native built-in functions for base-\(e\) calculations:

  • Math.exp(x) is translated directly to exp(x).
  • Math.log(x) is translated directly to log(x).

Because GLSL is statically typed, GPU.js also handles type inference and casting. It ensures that the arguments passed into exp() or log() match the expected floating-point precision (typically highp float in GPU.js kernels), converting integer literals or variables to floats if necessary.

Shader Generation and Compilation

After translating the entire AST, GPU.js wraps the resulting GLSL instructions inside a boilerplate fragment shader. This template handles input textures (which represent your input arrays), coordinate lookups based on thread IDs, and packing floating-point outputs into WebGL textures.

GPU.js passes this generated GLSL source string to the WebGL context using the following standard browser APIs:

  1. gl.createShader(gl.FRAGMENT_SHADER) creates the shader container.
  2. gl.shaderSource(shader, sourceCode) uploads the transpiled GLSL source.
  3. gl.compileShader(shader) instructs the platform's graphics driver to compile the GLSL code into native GPU machine instructions.

Hardware-Level Execution via SFUs

At the silicon level, modern GPUs do not calculate logarithms and exponentials using general-purpose Arithmetic Logic Units (ALUs). Instead, the compiled shader instructions target dedicated hardware blocks known as Special Function Units (SFUs).

  • Base-2 Transformation: Most GPU architectures (such as NVIDIA and AMD) implement hardware-level instructions natively in base-2, specifically \(2^x\) (EX2) and \(\log_2(x)\) (LG2). The driver-level compiler transforms natural logarithm and exponential functions into these base-2 operations using constant scaling factors: \[\ln(x) = \log_2(x) \times \frac{1}{\log_2(e)}\] \[e^x = 2^{x \times \log_2(e)}\]
  • Hardware Approximation: The SFUs evaluate these base-2 operations in very few clock cycles using high-speed hardware polynomial approximations (such as minimax algorithms or piecewise Chebyshev polynomials) combined with small lookup tables embedded on the chip.

Through this pipeline—AST parsing, GLSL syntax mapping, WebGL shader compilation, and SFU hardware routing—GPU.js achieves near-native graphics card throughput for complex mathematical operations defined entirely in JavaScript.
