Iterative Mirror Reflections in gpu.js

This article explains how to approximate recursive mirror reflections in gpu.js by converting recursion into unrolled, iterative ray-tracing steps. Because WebGL and GPU hardware generally prohibit recursive call stacks, ray tracers running in gpu.js cannot use traditional recursive functions to trace bouncing light. Instead, developers can achieve photorealistic multi-bounce reflections by employing a bounded iterative loop that advances ray states step by step across consecutive surface intersections.

The GPU Recursion Limitation

Graphics hardware is designed for massive parallelism rather than complex control flow. In standard WebGL—the underlying compilation target for gpu.js—functions cannot call themselves recursively because shaders do not maintain a dynamic execution stack. Writing a recursive function in a gpu.js kernel will either cause a transpilation error or result in invalid GLSL that fails shader compilation.

The Iterative Approximation

A recursive reflection algorithm calculates light by casting a primary ray, finding the intersection point, and recursively calling the ray-tracing function with a new reflected direction. Physically, this represents a linear sequence of events for a single photon path:

  1. Intersect a surface.
  2. Calculate the reflection angle using the surface normal.
  3. Attenuate the ray energy by the material's reflectivity.
  4. Repeat for subsequent surfaces until energy dissipates or an environment boundary is hit.

Because each bounce depends only on the output state of the previous bounce, this linear chain does not require a call tree. It can be fully simulated using a fixed-iteration loop that updates ray properties in place.

Implementation Mechanics in gpu.js

To approximate multi-bounce reflections iteratively, maintain the state of the ray throughout the kernel execution:

  1. Ray State Variables: Declare variables for current ray origin, ray direction, accumulated color, and the throughput mask (color attenuation).
  2. Fixed-Count Loop: Use a standard for loop with a constant maximum depth (for example, 3 to 8 iterations). Gpu.js can translate this into a bounded GLSL loop or an unrolled sequence of instructions.
  3. Intersection and Normal Calculation: In each iteration, test the current ray against the scene geometry to find the nearest hit point. If no hit occurs, sample the background/skybox color, multiply it by the throughput mask, add it to the accumulated color, and break the loop.
  4. Reflection Vector: If a reflective surface is struck, compute the reflection vector using the formula: \[R = D - 2(D \cdot N)N\] where \(D\) is the normalized incident ray direction and \(N\) is the surface normal.
  5. Ray Update and Offset: Set the new ray direction to \(R\). Update the ray origin to the intersection point, adding a small floating-point epsilon along the normal vector (\(O_{new} = P + N \times 0.001\)) to prevent self-intersection artifacts known as surface acne.
  6. Energy Attenuation: Multiply the throughput mask by the surface's specular color or reflection coefficient.

Performance and Precision

Unrolling the iterative loop or keeping the iteration count bounded guarantees that the shader compiler knows execution limits at compile time. Higher bounce counts improve optical accuracy inside mirror mazes or between parallel reflectors, but each additional step increases the instruction count and register pressure within the kernel. For most real-time WebGL applications written with gpu.js, setting the loop limit between 3 and 5 bounces provides convincing recursive mirror reflections without degrading frame rates.
