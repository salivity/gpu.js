GPU.js Multi-Channel Texture Unpacking to CPU

This article details how GPU.js processes and unpacks multi-channel WebGL texture data during readback operations from the GPU to the CPU. When a kernel executes, results are written into WebGL framebuffers mapped across color channels, requiring GPU.js to read the underlying pixel buffer, decode any channel-encoded floating-point representations, and reconstruct the values into structured JavaScript arrays or typed arrays.

Framebuffer Rendering and Multi-Channel Storage

GPU.js executes kernels by compiling JavaScript into GLSL fragment shaders. In WebGL, output targets are textures attached to a Framebuffer Object (FBO). Because native GPU textures are formatted with up to four color channels (Red, Green, Blue, Alpha), GPU.js structures its output across these channels depending on the kernel settings, WebGL capability, and data type.

When returning data to the CPU, GPU.js calls WebGL’s gl.readPixels() method. This function reads a specified rectangular block of pixels from the bound framebuffer into a contiguous CPU-side typed array, typically a Uint8Array or a Float32Array.

IEEE 754 Float Packing and Decoding

When running in environments where floating-point textures or float color buffer extensions (such as OES_texture_float or EXT_color_buffer_float) are unsupported, GPU.js cannot natively render 32-bit floating-point numbers directly to a single channel. To bypass this hardware limitation, GPU.js uses a 4-channel encoding technique:

  1. GPU Packing: Inside the generated GLSL fragment shader, a single 32-bit IEEE 754 floating-point result is split across four 8-bit color channels (\(R, G, B, A\)) using bitwise operations and modulo arithmetic.
  2. CPU Readback: The CPU retrieves the raw pixel data as a contiguous Uint8Array using gl.readPixels(..., gl.RGBA, gl.UNSIGNED_BYTE, ...).
  3. CPU Unpacking: GPU.js loops through the Uint8Array in 4-byte increments. It reconstructs the original 32-bit floating-point values either via bit-shift arithmetic reproducing IEEE 754 decoding or by wrapping the underlying ArrayBuffer in a Float32Array or DataView.

Native Float Reading and Direct Channel Mapping

When native float textures and float render targets are supported and enabled, packing is bypassed. The shader writes single or multi-channel values directly into the framebuffer texture:

  • For standard numeric kernels, the calculated scalar is stored in the designated channel (typically the Red channel), and gl.readPixels directly populates a Float32Array.
  • For graphical or multi-channel vector kernels (such as kernels configured with graphical output or multiple sub-outputs), all four channels (\(RGBA\)) store discrete values. GPU.js reads these as interleaved sets of four values \([R_0, G_0, B_0, A_0, R_1, G_1, B_1, A_1, \dots]\).

Reshaping into Target Dimensions

Once the raw data is read and any channel-level decoding is finished, the resulting buffer is a flat, one-dimensional collection of values. GPU.js transforms this flat array according to the output dimensions defined on the kernel:

  • 1D Kernels: The flat array is either returned directly as a typed array or sliced into a standard JavaScript array.
  • 2D and 3D Kernels: GPU.js traverses the flat data using nested loops based on the kernel's thread dimensions (\(x, y, z\)). It extracts rows and planes by calculating memory offsets, reshaping the linear pixel sequence back into the nested array structure (\([z][y][x]\)) expected by the user. If the kernel is configured to return typed arrays, the reshaping is omitted or returned as a flat structure with dimension metadata to avoid CPU allocation overhead.
