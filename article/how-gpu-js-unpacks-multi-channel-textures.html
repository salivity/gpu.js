How GPU.js Unpacks Multi-Channel Textures

This article explains how GPU.js unpacks multi-channel vector textures when they are passed as inputs to downstream kernels. When chaining GPU operations using pipeline mode or sub-kernels, GPU.js retains data in GPU memory as WebGL textures rather than serializing it back to the CPU. Understanding how GPU.js synthesizes custom GLSL accessor functions, calculates UV coordinates, and decodes multi-component RGBA texels clarifies how downstream kernels transparently retrieve vector elements.

WebGL Texture Storage and Pipelines

In GPU.js, enabling pipeline: true forces a kernel to return a GPUTexture object rather than a typed array or native JavaScript array. Under the hood, this texture is backed by a WebGL frame buffer object (FBO) attachment. Because WebGL standard render targets write to four-channel color buffers (Red, Green, Blue, Alpha), any multi-dimensional vector, sub-kernel output, or packed floating-point value is mapped across these four channels (vec4).

When this GPUTexture is fed into a second, downstream kernel, GPU.js binds the underlying WebGL texture to a sampler2D uniform assigned to that input variable.

Automatic GLSL Sampler Generation

Downstream kernels do not require the developer to write raw texture sampling logic. Instead, the GPU.js compiler inspects the argument signature and metadata attached to the incoming GPUTexture. It automatically injects an accessor function into the generated GLSL fragment shader corresponding to the argument name.

If the incoming parameter is named upstreamData, GPU.js injects:

  1. A uniform declaration: uniform sampler2D user_upstreamData;
  2. Size and dimension uniforms detailing the width, height, and depth of the texture.
  3. A wrapper function that accepts indices (such as 1D index, 2D [x, y], or 3D [x, y, z]) and returns the appropriate scalar or vector value.

Index-to-UV Coordinate Mapping

Inside the auto-generated GLSL accessor, GPU.js converts discrete array indices into normalized UV coordinates bounded between 0.0 and 1.0. The calculation offsets indices by 0.5 pixels to ensure lookups target the center of each texel, avoiding linear interpolation artifacts:

vec2 uv = (indexCoords + vec2(0.5, 0.5)) / textureDimensions;
vec4 texel = texture2D(user_upstreamData, uv);

Channel Unpacking Strategies

Once the vec4 texel is retrieved via texture2D, the downstream kernel unpacks it depending on the upstream output mode:

1. Native Multi-Channel Vectors

If the upstream kernel explicitly produced vector outputs (such as 2, 3, or 4-element arrays or sub-kernels), the elements map directly to texel.r, texel.g, texel.b, and texel.a.

  • When the downstream code accesses a specific sub-index (e.g., upstreamData[y][x][0]), the compiler replaces the JavaScript array access with GLSL swizzling (texel.r).
  • If the kernel accesses the vector as a whole, the GLSL accessor returns a vec4 (or vec2/vec3 depending on the channel count).

2. Packed High-Precision Floats

In environments lacking floating-point texture support (such as certain WebGL 1 configurations without OES_texture_float), GPU.js encodes a single 32-bit float across all four 8-bit RGBA channels using an IEEE 754 emulation routine. When a downstream kernel accesses this texture, GPU.js includes an internal decode function:

float decode32(vec4 rgba) {
  const vec4 shift = vec4(1.0, 1.0 / 255.0, 1.0 / 65025.0, 1.0 / 16581375.0);
  return dot(rgba, shift);
}

In this scenario, the multi-channel nature of the texture acts as bit storage for a single scalar value. The downstream kernel automatically runs the texel through the decoding dot product before returning the scalar value to the computation.

Sub-Kernel Output Separation

When using sub-kernels that return multiple named outputs from a single pass, GPU.js either binds separate render targets (in WebGL 2 via Multiple Render Targets / drawBuffers) or encodes the outputs into designated channel masks of a single texture. Downstream kernels receiving a specific sub-kernel reference are supplied with a GLSL accessor tied exclusively to that output's bound texture or its corresponding swizzled channel mask (.r, .g, .b, or .a).
