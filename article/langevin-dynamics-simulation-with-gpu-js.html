Langevin Dynamics Simulation with GPU.js

This article explains how to model Brownian motion and Langevin dynamics for colloidal suspensions using GPU.js to achieve hardware-accelerated performance in JavaScript. You will learn the theoretical equations governing colloidal motion, how to implement parallelized force and stochastic integration kernels using WebGL, and how to handle pseudo-random noise generation natively on the graphics processor.

The Physical Model: Langevin Dynamics

Colloidal particles suspended in a solvent experience three primary forces: interparticle interactions (such as electrostatic repulsion or Lennard-Jones potentials), solvent drag, and random thermal collisions from solvent molecules.

The translational motion of a particle \(i\) with mass \(m\) is governed by the Langevin equation:

\[m \frac{d\mathbf{v}_i}{dt} = \mathbf{F}_i^{\text{inter}}(\mathbf{r}) - \gamma \mathbf{v}_i + \mathbf{F}_i^{\text{random}}(t)\]

Where:

  • \(\mathbf{F}_i^{\text{inter}}(\mathbf{r})\) is the net deterministic conservative force exerted by neighboring particles.
  • \(-\gamma \mathbf{v}_i\) is the Stokes friction coefficient (\(\gamma = 6\pi\eta a\) for a spherical particle of radius \(a\) in viscosity \(\eta\)).
  • \(\mathbf{F}_i^{\text{random}}(t)\) is Gaussian white noise satisfying the fluctuation-dissipation theorem: \(\langle \mathbf{F}_i(t) \cdot \mathbf{F}_j(t') \rangle = 6 k_B T \gamma \delta_{ij} \delta(t - t')\).

In the overdamped regime (Brownian dynamics), inertia is negligible (\(m \frac{d\mathbf{v}}{dt} \approx 0\)), simplifying the equation to an integration of displacements directly from forces and thermal diffusion.

Why GPU.js for Colloidal Simulations

Simulating \(N\) colloidal particles requires calculating up to \(O(N^2)\) pairwise interactions per time step. Running this sequentially in JavaScript limits real-time rendering to a few hundred particles. GPU.js compiles JavaScript functions into WebGL fragment shaders, executing particle calculations concurrently across thousands of GPU threads without writing raw GLSL.

Step-by-Step GPU.js Implementation

1. Generating On-GPU Random Numbers

Standard WebGL shaders lack a native random number generator. To simulate thermal fluctuations, implement a hash-based pseudo-random number generator (PRNG) inside a GPU kernel:

function hashPRNG(seed1, seed2) {
  let s = Math.sin(seed1 * 12.9898 + seed2 * 78.233) * 43758.5453;
  return s - Math.floor(s);
}

Using the Box-Muller transform, map two uniform random variables into normally distributed random numbers required for the stochastic Langevin force.

2. Setting Up the Simulation Kernels

Represent particle coordinates and velocities as flattened 1D arrays or matrices (e.g., positions[N][2] for 2D space) and update them using GPU.js kernels.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel to compute pairwise forces and update positions
const updateLangevin = gpu.createKernel(function(positions, velocities, N, dt, gamma, kBT, seed) {
  const i = this.thread.x;
  const px = positions[i][0];
  const py = positions[i][1];
  let vx = velocities[i][0];
  let vy = velocities[i][1];

  let fx = 0.0;
  let fy = 0.0;

  // Compute pairwise Weeks-Chandler-Andersen (WCA) repulsion
  for (let j = 0; j < N; j++) {
    if (i !== j) {
      let dx = px - positions[j][0];
      let dy = py - positions[j][1];
      let distSq = dx * dx + dy * dy + 0.0001; // Avoid division by zero
      
      // Repulsive threshold (sigma^2)
      let cutoff = 1.0; 
      if (distSq < cutoff) {
        let invDist2 = 1.0 / distSq;
        let invDist6 = invDist2 * invDist2 * invDist2;
        let forceMag = 48.0 * invDist6 * (invDist6 - 0.5) * invDist2;
        fx += forceMag * dx;
        fy += forceMag * dy;
      }
    }
  }

  // Random noise calculation (Box-Muller transform)
  let u1 = Math.sin(i * 12.9898 + seed * 78.233) * 43758.5453;
  u1 = u1 - Math.floor(u1);
  let u2 = Math.sin(i * 39.346 + seed * 11.135) * 43758.5453;
  u2 = u2 - Math.floor(u2);
  
  let r = Math.sqrt(-2.0 * Math.log(u1 + 0.000001));
  let theta = 2.0 * 3.1415926535 * u2;
  let noiseX = r * Math.cos(theta);
  let noiseY = r * Math.sin(theta);

  let stdDev = Math.sqrt(2.0 * gamma * kBT / dt);

  // Velocity update using Euler-Maruyama
  vx += ((fx - gamma * vx + stdDev * noiseX) * dt);
  vy += ((fy - gamma * vy + stdDev * noiseY) * dt);

  // Position update
  let newX = px + vx * dt;
  let newY = py + vy * dt;

  return [newX, newY, vx, vy];
}).setOutput([N]).setPipeline(true);

3. Executing the Simulation Loop

Keep particle data on the GPU between frames by enabling pipeline mode (setPipeline(true)). This avoids CPU-GPU memory bandwidth bottlenecks.

const N = 10000;
let positions = [];
let velocities = [];

// Initialize particle positions and zero velocities
for (let i = 0; i < N; i++) {
  positions.push([Math.random() * 100, Math.random() * 100]);
  velocities.push([0.0, 0.0]);
}

const dt = 0.001;
const gamma = 1.0;
const kBT = 1.0;

function step(time) {
  // Pass current time as seed to vary stochastic noise
  const result = updateLangevin(positions, velocities, N, dt, gamma, kBT, time);
  
  // Update state for next step
  requestAnimationFrame(step);
}

requestAnimationFrame(step);

Performance Considerations

  1. Memory Bandwidth: Use setPipeline(true) so output arrays remain as GPU textures between iterations. Pull data back to the CPU using .toArray() only when rendering to an HTML canvas or logging data.
  2. Spatial Partitioning: For very large \(N\) (\(N > 20,000\)), calculate forces using neighbor lists or cell lists stored in 2D textures instead of an \(O(N^2)\) global loop.
  3. Precision: Standard GPU.js operates on 32-bit single-precision floats (float32). Ensure that \(dt\) and scale parameters are normalized to avoid floating-point underflow in force evaluations.
