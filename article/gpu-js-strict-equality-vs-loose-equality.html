gpu.js Strict Equality vs Loose Equality

This article explores how gpu.js handles comparison operators within GPU-accelerated kernel functions. In standard JavaScript, the strict equality operator (===) checks both value and type without coercion, while the loose equality operator (==) coerces operands to a common type before comparing. However, because gpu.js compiles JavaScript into statically typed shader code (such as WebGL GLSL), it treats both operators identically, relying entirely on the target shading language's native equality rules.

Transpilation to Shader Code

When you write a kernel in gpu.js, the library parses the JavaScript Abstract Syntax Tree (AST) and converts the logic into GLSL (OpenGL Shading Language). GLSL is a strictly typed language derived from C. It does not support JavaScript's dynamic runtime evaluation or type coercion mechanisms.

During AST parsing:

  • === is translated to the GLSL == operator.
  • == is also translated to the GLSL == operator.

Because both symbols map to the identical GLSL token, there is zero functional or performance difference between == and === within a compiled gpu.js kernel.

The Absence of Type Coercion

In standard JavaScript environments (like Node.js or the browser's main thread), loose equality allows expressions such as 1 == "1" or 0 == false to evaluate to true.

In a gpu.js kernel, type coercion does not occur:

  • Shaders do not have mixed-type comparison tables.
  • Every variable in the kernel is assigned a concrete GLSL type (such as float, int, or a vector).
  • Attempting to compare two inherently different types without an explicit cast will lead to a GLSL compilation error rather than coerced comparison.

For example, comparing an integer to a floating-point number using either == or === without explicit conversion will cause the shader compilation to fail:

// This fails compilation under both == and ===
if (intVal == floatVal) { ... }
if (intVal === floatVal) { ... }

// Correct approach: explicitly match types
if (float(intVal) == floatVal) { ... }

Best Practices for Equality in gpu.js

  1. Expect Static Typing: Treat kernel code like a statically typed language. Ensure that operands on both sides of any equality check evaluate to the exact same GPU data type.
  2. Consistency: While === works without issue, using standard JavaScript conventions (preferring ===) helps maintain clean code that passes standard linters like ESLint, even though gpu.js treats it as ==.
  3. Explicit Type Casting: When comparing mixed numerical types, always use explicit conversion functions (such as float(...) or int(...)) to prevent shader compiler errors.
