Prevent VRAM Memory Leaks in gpu.js

Running intensive GPU tasks in JavaScript using gpu.js can rapidly deplete Video RAM (VRAM) if resources are not explicitly managed. Because the browser's standard garbage collector manages CPU memory rather than WebGL contexts and GPU-allocated buffers, running kernels in loops or pipelines often causes memory leaks. This article explains why these leaks occur and demonstrates how to manually destroy textures, kernels, and GPU instances to keep your GPU memory footprint clean and stable.

Why VRAM Leaks Occur

JavaScript relies on automatic garbage collection (GC) to free unreferenced memory. However, WebGL textures and framebuffer objects reside in GPU memory. The garbage collector does not prioritize freeing native GPU handles simply because VRAM is full. If you continuously generate new kernels or process intermediate textures without manually dereferencing them, your application will eventually crash with an "Out of Memory" or "Context Lost" error.

Releasing Texture Memory

When using pipeline mode (pipeline: true), a kernel outputs a Texture object instead of a flat JavaScript array. This keeps data on the GPU for the next kernel in the pipeline, dramatically boosting performance. However, every intermediate texture allocates VRAM.

To release a texture immediately after you are finished using it, invoke the delete() method:

const myKernel = gpu.createKernel(function(a) {
  return a[this.thread.x] * 2;
}, {
  output: [512],
  pipeline: true
});

// Run kernel and get texture output
const resultTexture = myKernel(inputData);

// Use the texture in a subsequent operation...
const finalKernel = gpu.createKernel(function(texture) {
  return texture[this.thread.x] + 1;
}, { output: [512] });

const finalArray = finalKernel(resultTexture);

// Explicitly free the intermediate texture from VRAM
resultTexture.delete();

Destroying Kernels

If your application dynamically generates kernels based on user input or varying dimensions, old kernels will retain WebGL programs and framebuffers in memory. To clean up a kernel that is no longer needed, call its destroy() method:

const dynamicKernel = gpu.createKernel(function() {
  return this.thread.x;
}, { output: [1024] });

// Execute kernel
dynamicKernel();

// Manually destroy the kernel and its compiled WebGL program
dynamicKernel.destroy();

Note: Instead of creating and destroying kernels frequently, reuse existing kernels with fixed configurations whenever possible to minimize overhead.

Tearing Down the GPU Instance

When completing a batch task, unmounting a UI component, or closing an execution pipeline, you should destroy the main GPU instance. Calling destroy() on the instance disposes of all child kernels, textures, and the underlying WebGL context:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Perform calculations...

// Fully dispose of the WebGL context and all associated VRAM
gpu.destroy();

Memory Management Best Practices

  1. Avoid Creating Kernels in Loops: Never instantiate gpu.createKernel() inside a for loop or requestAnimationFrame. Define kernels once and call them repeatedly.
  2. Dispose Intermediate Textures: Always track and call .delete() on textures generated in multi-step pipelines once downstream kernels have consumed them.
  3. Handle WebGL Context Loss: Listen to WebGL context loss events if your application is long-running to gracefully restart the GPU instance if the browser force-purges VRAM.
