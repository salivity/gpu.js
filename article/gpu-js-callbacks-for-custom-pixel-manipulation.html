GPU.js Callbacks for Custom Pixel Manipulation

This article examines whether you can pass JavaScript callback functions into a GPU.js kernel for custom pixel manipulation. Because GPU.js transpiles JavaScript code into WebGL/GLSL shaders executed directly on the GPU, traditional runtime JavaScript callbacks cannot be executed within a kernel. Below, we explore the technical reasons for this limitation and provide the standard architectural workarounds—specifically using gpu.addFunction(), conditional uniform parameters, and multi-pass kernel pipelines—to achieve dynamic pixel processing.

Why Standard Callbacks Do Not Work

GPU.js works by parsing a JavaScript function's Abstract Syntax Tree (AST) at compile time and converting that code into GLSL (OpenGL Shading Language). The resulting program runs entirely on the graphics hardware across thousands of parallel threads.

A standard JavaScript callback function relies on the JavaScript runtime environment, the CPU's memory heap, and the event loop. The GPU cannot dynamically halt shader execution to jump back into the CPU context to run an arbitrary JavaScript function pointer. Consequently, passing a native JavaScript function as an argument to a kernel will result in a compilation error or an unsupported argument failure.

Alternative 1: Registering Functions with gpu.addFunction

If your goal is modular code reuse across your pixel shaders, GPU.js allows you to register predefined helper functions using gpu.addFunction(). While these are not dynamic runtime callbacks, they allow you to define standalone subroutines that can be invoked directly inside your kernel.

const gpu = new GPU();

// Define a custom manipulation function
function applyContrast(colorValue, factor) {
  return (colorValue - 0.5) * factor + 0.5;
}

// Register the function with the GPU instance
gpu.addFunction(applyContrast);

// Use the function inside the kernel
const kernel = gpu.createKernel(function(image, factor) {
  const pixel = image[this.thread.y][this.thread.x];
  const r = applyContrast(pixel[0], factor);
  const g = applyContrast(pixel[1], factor);
  const b = applyContrast(pixel[2], factor);
  
  this.color(r, g, b, 1);
}).setOutput([width, height]).setGraphical(true);

Functions registered this way must strictly follow GLSL-compatible arithmetic and cannot reference external closure variables.

Alternative 2: Control Logic via Arguments (Uniforms)

When different pixel manipulation behaviors are required conditionally, the typical graphics programming approach is to pass configuration parameters or operation flags as arguments. These behave as WebGL uniforms:

const kernel = gpu.createKernel(function(image, mode, intensity) {
  const pixel = image[this.thread.y][this.thread.x];
  let r = pixel[0];
  let g = pixel[1];
  let b = pixel[2];

  // Mode 0: Invert, Mode 1: Grayscale, Mode 2: Brightness
  if (mode === 0) {
    r = 1.0 - r;
    g = 1.0 - g;
    b = 1.0 - b;
  } else if (mode === 1) {
    const avg = (r + g + b) / 3.0;
    r = avg;
    g = avg;
    b = avg;
  } else if (mode === 2) {
    r += intensity;
    g += intensity;
    b += intensity;
  }

  this.color(r, g, b, 1);
}).setOutput([width, height]).setGraphical(true);

Alternative 3: Kernel Composition and Pipelining

For fully decoupled workflows, break custom manipulations into discrete kernels and chain them together using setPipeline(true). This preserves the data as textures in GPU memory without reading back to the CPU between steps, allowing you to selectively execute arbitrary sequences of kernels based on application logic:

const blurKernel = gpu.createKernel(function(image) {
  // Blur implementation
}).setOutput([width, height]).setPipeline(true);

const colorGradeKernel = gpu.createKernel(function(texture) {
  // Color grade implementation
}).setOutput([width, height]).setGraphical(true);

// Dynamically compose passes on the CPU
const blurred = blurKernel(inputImage);
colorGradeKernel(blurred);

While true JavaScript callbacks are impossible due to hardware architectural separation, utilizing gpu.addFunction(), uniform state flags, and chained pipeline kernels provides complete flexibility for custom pixel manipulation.
