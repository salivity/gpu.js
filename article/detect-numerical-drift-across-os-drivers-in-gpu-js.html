Detect Numerical Drift Across OS Drivers in GPU.js

Numerical drift occurs when identical GPU-accelerated computations yield slightly different floating-point results across different operating systems, graphics hardware, and display drivers. When using gpu.js, this divergence stems from variations in how underlying graphics APIs (WebGL, DirectX, Metal, Vulkan) and vendor-specific drivers implement IEEE 754 floating-point standards and shader compiler optimizations. Detecting numerical drift requires establishing a deterministic baseline, implementing tolerance-based assertions across varied hardware environments, and automating cross-platform matrix testing.

Establish a Canonical CPU Baseline

To detect drift, you need a deterministic control reference. While different GPU drivers might handle fast-math optimizations or reciprocal approximations differently, standard CPU floating-point operations in Node.js or browser V8 engines strictly adhere to standard IEEE 754 precision.

Configure your gpu.js kernel to produce a reference dataset using the CPU execution mode:

const gpu = new GPU();

// Reference Kernel on CPU
const cpuKernel = gpu.createKernel(function(a, b) {
  return a[this.thread.x] * b[this.thread.x];
}, {
  output: [1024],
  mode: 'cpu'
});

const baselineOutput = cpuKernel(inputA, inputB);

Run this reference calculation once with fixed, seeded pseudo-random input data to serve as the ground truth for your validation suite.

Replace Strict Equality with Drift Metrics

Never use strict equality assertions (such as assert.strictEqual) when comparing GPU kernel outputs across environments. Instead, quantify drift using mathematically sound distance metrics:

  • Absolute Error: \(|y_{gpu} - y_{cpu}|\)
  • Relative Error: \(\frac{|y_{gpu} - y_{cpu}|}{|y_{cpu}|}\)
  • Mean Squared Error (MSE): Measures the average squared difference across the entire output array.
  • Maximum Absolute Error (MAE): Identifies the single worst deviation in the dataset.

Implement a comparison function that enforces tolerances suitable for 32-bit single-precision floats (Float32Array), which GPUs typically rely on:

function evaluateDrift(actual, baseline, absoluteTolerance = 1e-5, relativeTolerance = 1e-4) {
  let maxDrift = 0;
  
  for (let i = 0; i < baseline.length; i++) {
    const diff = Math.abs(actual[i] - baseline[i]);
    const maxAllowed = absoluteTolerance + relativeTolerance * Math.abs(baseline[i]);
    
    if (diff > maxDrift) {
      maxDrift = diff;
    }
    
    if (diff > maxAllowed) {
      throw new Error(`Drift threshold exceeded at index ${i}: baseline=${baseline[i]}, actual=${actual[i]}, diff=${diff}`);
    }
  }
  
  return { maxDrift };
}

Monitor Bitwise Drift Using TypedArrays

Drivers often implement trigonometric functions (sin, cos) or division using hardware-level approximations (like reciprocal square root instructions). These micro-optimizations do not always produce large deviations, but they alter the least significant bits of the float mantissa.

To catch subtle driver updates that change precision profiles, convert the raw output buffers into integer representations to track Unit in the Last Place (ULP) shifts:

function getBitDifference(floatA, floatB) {
  const buf = new ArrayBuffer(4);
  const f32 = new Float32Array(buf);
  const u32 = new Uint32Array(buf);

  f32[0] = floatA;
  const bitsA = u32[0];

  f32[0] = floatB;
  const bitsB = u32[0];

  return Math.abs(bitsA - bitsB);
}

Recording maximum ULP values across driver versions alerts you when a vendor driver patch alters compiler heuristics.

Automate Testing via Cross-Platform CI Runners

Because drivers are tied to the operating system, you must run automated tests on native hardware across target operating systems rather than containerized virtual environments with software renderers.

  1. Deploy Self-Hosted CI Runners: Use dedicated bare-metal runners for:
    • Windows: DirectX / ANGLE WebGL translation layers (NVIDIA, AMD, Intel drivers).
    • macOS: Metal-backed WebGL pipelines (Apple Silicon and legacy AMD drivers).
    • Linux: Mesa, proprietary NVIDIA, and Vulkan backends.
  2. Execute Headless Browsers with Hardware Flags: When running Playwright or Puppeteer, pass flags that force real hardware acceleration rather than SwiftShader or software rendering: 
    google-chrome --enable-gpu --use-gl=desktop --headless=new test-runner.html
  3. Log Hardware Metadata with Results: Ensure your test reporter captures execution context alongside drift metrics:
    • Driver version
    • Operating system build
    • Unmasked GPU vendor and renderer string (via WEBGL_debug_renderer_info)

Track Drift Telemetry Over Time

Store the output drift profiles (MAE, MSE, and Max ULP) as structured artifacts in your continuous integration pipeline. By tracking these metrics over successive OS and driver updates, you can distinguish between acceptable low-order precision differences and critical regressions caused by driver updates altering mathematical execution paths.
