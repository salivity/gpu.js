Math.abs Edge Cases with Extreme Floats in gpu.js

Using Math.abs() on extreme floating-point values in gpu.js frequently leads to unexpected behavior due to the fundamental differences between JavaScript execution and WebGL shader compilation. While JavaScript natively executes mathematical operations using 64-bit double-precision floats (IEEE 754), gpu.js translates kernel functions into GLSL shaders that default to 32-bit single-precision floats. This article examines the primary edge cases encountered when applying Math.abs to extreme floats in gpu.js, detailing how hardware constraints, precision loss, and non-standard driver behaviors affect numerical stability.

1. Overflow to Infinity (Precision Downcasting)

JavaScript allows numbers up to approximately \(1.79 \times 10^{308}\). In standard gpu.js configurations, numbers passed to or computed within a kernel are converted into 32-bit floats, which have an upper finite limit of roughly \(3.40 \times 10^{38}\).

If an input value is less than \(-3.40 \times 10^{38}\), passing it to a kernel and calling Math.abs(x) does not yield a large positive finite float. Instead:

  • The GPU immediately registers the value as negative infinity (-Infinity) prior to or during evaluation.
  • Math.abs(-Infinity) yields Infinity, discarding the mantissa entirely.
  • If precision clamping is enabled in certain legacy WebGL environments, extreme negative numbers may wrap around or truncate abruptly, producing corrupt positive outputs.

2. Flush-to-Zero on Subnormal Numbers (Underflow)

Numbers extremely close to zero (between \(-1.18 \times 10^{-38}\) and \(0\)) fall into the subnormal or denormal range of 32-bit floats.

Unlike standard JavaScript engines, many mobile and desktop GPUs enforce a "Flush-to-Zero" (FTZ) optimization to maximize throughput. When calling Math.abs(x) on an extreme negative subnormal value:

  • The GPU hardware frequently flushes the number directly to +0.0 or -0.0 before the abs operation can retain its fractional significance.
  • Downstream calculations that rely on the non-zero magnitude of tiny numbers will face zero-division errors (1.0 / Math.abs(x) resulting in Infinity instead of an expected large scalar).

3. Non-Compliant NaN and Infinity Implementations

The IEEE 754 standard mandates that Math.abs(-Infinity) equals Infinity and Math.abs(NaN) equals NaN. However, GLSL implementations vary significantly across hardware vendors:

  • Sign Bit on NaN: Passing a negative NaN (such as values resulting from invalid negative operations) into Math.abs() does not guarantee a standardized bit pattern output. Some GPUs may strip the sign bit, while others leave the internal representation untouched or propagate an implementation-specific quiet NaN.
  • Indeterminate Values: Some older mobile GPUs return an arbitrary float or zero instead of Infinity when applying Math.abs() to overflowed negative numbers, diverging completely from standard JavaScript behavior.

4. Preservation of Negative Zero (-0.0)

JavaScript strictly distinguishes between -0 and +0, with Math.abs(-0) strictly returning +0. In GLSL:

  • The expression maps to the native GLSL abs() function.
  • While abs(-0.0) evaluates to 0.0 mathematically, the underlying IEEE sign bit removal is not uniformly guaranteed on all GPU architectures. If the result is subsequently cast or packed into low-level byte arrays, the sign bit may persist, leading to unexpected parity failures when read back into the CPU context.

5. Resolution and Step Errors Near the Limits

At the far ends of the 32-bit range (both very large and very small exponents), floating-point resolution degrades significantly. Applying Math.abs() directly does not alter the scale, but intermediate operations surrounding it (such as computing absolute differences via Math.abs(a - b)) will encounter severe cancellation errors:

  • If a and b are both extreme negative numbers, computing Math.abs(a - b) inside the GPU kernel often produces catastrophic cancellation where the precision between consecutive representable numbers is larger than the actual difference, collapsing the absolute result to 0.0.
