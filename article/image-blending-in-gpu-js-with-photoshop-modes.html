Image Blending in GPU.js with Photoshop Modes

GPU.js can efficiently blend multiple image layers using standard Photoshop-style blending modes by running parallelized math operations directly on the graphics card. This article examines how Photoshop blend formulas translate into GPU.js kernels, how to handle layer stacking and alpha transparency, and the practical implementation steps required to achieve real-time, hardware-accelerated image composition in the browser.

The Math Behind Photoshop Blend Modes

Photoshop blending modes rely on standard algebraic formulas applied to normalized color channels. When working with digital images, pixel values range from 0 to 255. Before blending, these channels must be mapped to a floating-point range between 0.0 and 1.0.

GPU.js excels at this operation because it converts standard JavaScript into WebGL fragment shaders, executing identical pixel-level calculations across millions of threads simultaneously. Common formulas include:

  • Multiply: Multiplies the base layer (\(A\)) by the blend layer (\(B\)). \[\text{Result} = A \times B\]
  • Screen: Inverts both layers, multiplies them, and inverts the result. \[\text{Result} = 1.0 - (1.0 - A) \times (1.0 - B)\]
  • Overlay: Combines Multiply and Screen depending on the base layer value. \[\text{Result} = A < 0.5 \ ? \ (2.0 \times A \times B) : (1.0 - 2.0 \times (1.0 - A) \times (1.0 - B))\]
  • Darken / Lighten: Compares both layers and retains the minimum or maximum value. \[\text{Darken} = \min(A, B), \quad \text{Lighten} = \max(A, B)\]

Implementing Blends in a GPU.js Kernel

To composite two layers, you load both images onto HTML5 canvas elements or extract their ImageData, passing them into a GPU.js kernel as textures or 2D/3D arrays.

Inside the kernel function, you query the exact pixel coordinates using this.thread.x and this.thread.y. The kernel retrieves the red, green, blue, and alpha values for both the base and blend layers, applies the chosen blend mode function channel-by-channel, and outputs the resulting RGBA vector.

Handling Opacity and Alpha Compositing

Standard blend modes determine how two fully opaque colors interact. To replicate Photoshop accurately, you must also incorporate layer opacity and alpha channels using linear interpolation:

\[\text{Final Channel} = (\text{Blended Channel} \times \text{Opacity}) + (\text{Base Channel} \times (1.0 - \text{Opacity}))\]

If layers have transparent backgrounds, standard Porter-Duff compositing rules must be combined with the blend mode math so that transparent areas do not incorrectly darken or wash out underlying content.

Managing Multiple Layers

When blending more than two layers, GPU.js offers two primary architectural patterns:

  1. Array Stacking in a Single Kernel: Pass a 3D array or multiple texture inputs representing all layers into a single kernel. The kernel iterates through the layers from bottom to top in a loop, iteratively updating the base color. This approach minimizes WebGL draw calls.
  2. Kernel Pipelining: Use the GPU.js pipeline: true option. The output of blending Layer 1 and Layer 2 remains on the GPU as a texture, which is immediately passed as the base input for a second kernel run with Layer 3. This approach is more modular and dynamic if layers are toggled frequently.

Performance Advantages

Executing Photoshop-style blend modes via the standard HTML5 2D Canvas context (CanvasRenderingContext2D) is computationally expensive for large images or complex multi-layer stacks. While standard CSS and Canvas 2D support basic globalCompositeOperation modes, GPU.js allows you to implement non-standard formulas, customize transparency logic, and maintain high framerates at 4K resolutions by leveraging direct GPU hardware acceleration.
