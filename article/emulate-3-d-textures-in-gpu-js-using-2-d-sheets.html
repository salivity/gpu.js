Emulate 3D Textures in gpu.js Using 2D Sheets

3D volumetric textures can be effectively emulated in gpu.js by packing volumetric data into a tiled 2D texture sheet, commonly known as a texture atlas or flipbook. Because WebGL 1.0 environments and high-level wrappers like gpu.js often restrict direct manipulation of native 3D hardware textures, flattening a volume of dimensions \(X \times Y \times Z\) into a grid of 2D slices allows developers to bypass native constraints. This technique enables volume rendering, fluid simulations, and medical scan visualizations directly in the browser with high performance.

The 2D Texture Atlas Structure

To store a 3D dataset within a 2D texture, the depth axis (\(Z\)) is sliced into individual 2D cross-sections of dimension \(X \times Y\). These slices are arranged in a regular grid containing \(C\) columns and \(R\) rows, such that \(C \times R \ge Z\).

For example, a volume of dimensions \(64 \times 64 \times 64\) can be mapped onto a single 2D texture of size \(512 \times 512\) pixels by organizing the 64 depth slices into an \(8 \times 8\) grid of \(64 \times 64\) tiles.

Coordinate Transformation Algorithm

Inside the gpu.js kernel, continuous or discrete 3D coordinates \((x, y, z)\) must be translated into the corresponding \((u, v)\) positions on the 2D texture sheet.

  1. Identify the Tile Index: The integer slice corresponding to depth is \(S = \lfloor z \rfloor\).
  2. Compute Grid Position:
    • Column index: \(col = S \pmod{\text{columns}}\)
    • Row index: \(row = \lfloor S / \text{columns} \rfloor\)
  3. Calculate 2D Sheet Coordinates:
    • Offset the local \((x, y)\) coordinate by the tile’s position:
      • \(u = (col \times \text{sliceWidth}) + x\)
      • \(v = (row \times \text{sliceHeight}) + y\)

In a gpu.js kernel, these operations resolve to simple arithmetic operations, mapping 3D indices to the flattened 1D or 2D array representation of the source texture.

Emulating Trilinear Interpolation

Native 3D textures provide automatic trilinear filtering across all three axes. When emulating 3D textures with 2D sheets, standard hardware interpolation only smooths along the \(X\) and \(Y\) axes (bilinear filtering). To achieve true volumetric continuity along the \(Z\) axis, manual interpolation is required:

  1. Determine the two adjacent bounding slices: \(S_0 = \lfloor z \rfloor\) and \(S_1 = S_0 + 1\).
  2. Sample the 2D coordinate inside tile \(S_0\) to retrieve value \(V_0\).
  3. Sample the 2D coordinate inside tile \(S_1\) to retrieve value \(V_1\).
  4. Calculate the depth fractional weight: \(f = z - \lfloor z \rfloor\).
  5. Blend the two samples using linear interpolation: \(\text{Value} = (1 - f) \times V_0 + f \times V_1\).

Practical Considerations and Constraints

  • Tile Bleeding: When sampling near the edge of a slice, bilinear filtering can erroneously sample texels from an adjacent tile. To prevent visual seams, clamp coordinates inside each tile's boundaries or insert a 1-pixel border (gutter) around every slice.
  • Maximum Texture Size: WebGL devices impose limits on maximum 2D texture dimensions (typically 4096×4096 or 8192×8192 pixels). A volume must fit within these overall resolution limits when tiled.
  • Memory Footprint: 2D atlas packing maintains identical memory density to native 3D textures, but managing multiple large volumes may require splitting data across multiple 2D texture sheets if the slice grid exceeds the maximum texture size supported by the GPU.
