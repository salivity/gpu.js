Mobile GPU Precision Banding in gpu.js Explained

When running mathematical kernels via gpu.js on mobile devices, developers frequently encounter visible stepping or banding artifacts when evaluating trigonometric functions. This phenomenon stems from the interplay between mobile hardware constraints and WebGL shader compilation, where 16-bit half-precision floating-point limits, hardware-level domain reduction errors, and mobile driver approximations corrupt transcendental calculations. Understanding the mechanics of mobile floating-point units and how gpu.js structures its WebGL shaders reveals why these artifacts emerge and how to mitigate them.

Floating-Point Precision: Desktop vs. Mobile GLSL

Desktop GPUs typically execute fragment shaders using standard IEEE-754 32-bit single-precision floating-point numbers (fp32), offering 24 bits of mantissa (roughly 7 decimal digits of precision). Mobile System-on-Chips (SoCs), such as ARM Mali, Qualcomm Adreno, and Imagination PowerVR, are heavily optimized for thermal efficiency and power consumption.

In mobile WebGL contexts, fragment shaders often default to or fallback onto mediump (16-bit half-precision, or fp16) floating-point operations. A standard fp16 value allocates only 10 bits to the mantissa, yielding a meager 3 to 4 decimal digits of precision. When gpu.js compiles JavaScript kernels into WebGL fragment shaders, calculations running under mediump lack the dynamic range and resolution necessary to represent smooth gradients.

Domain Reduction and Catastrophic Cancellation

Trigonometric functions such as \(\sin(x)\) and \(\cos(x)\) are periodic over \(2\pi\). Before a GPU calculates the sine of an arbitrary input, it performs "domain reduction"—subtracting multiples of \(2\pi\) until the value lies within a base interval such as \([-\pi, \pi]\) or \([0, \frac{\pi}{2}]\).

Under 16-bit precision, this process suffers from catastrophic cancellation:

  1. Resolution Loss: As the input value \(x\) increases, the spacing between consecutive representable numbers in fp16 widens significantly.
  2. Modulo Imprecision: Computing \(x \pmod{2\pi}\) using a low-precision constant for \(2\pi\) introduces massive rounding errors.
  3. Quantized Outputs: The GPU's arithmetic logic unit (ALU) maps large spans of input values to the exact same reduced angle.

When mapped to spatial coordinates or color outputs, this quantization creates flat, stepped plateaus rather than continuous curves, resulting in severe visual banding.

Mobile ALU Trigonometric Approximations

Desktop architectures often feature dedicated transcendental evaluation units with extended internal precision. In contrast, many mobile architectures implement trigonometric instructions via low-order polynomial approximations (such as minimax or Taylor expansions) or low-resolution Look-Up Tables (LUTs) hardcoded into the silicon.

These mobile hardware shortcuts prioritize rendering throughput over mathematical accuracy. When high-frequency trigonometric queries pass through these approximations, the hardware cannot interpolate the fine distinctions between adjacent values, amplifying the discretization produced by low-precision variables.

gpu.js Compilation and Buffer Limitations

gpu.js translates pure JavaScript functions into GLSL strings and manages data transfer using WebGL textures. Several factors within this pipeline exacerbate precision loss on mobile devices:

  • Context Capability Mismatches: If a mobile browser does not expose robust support for OES_texture_float or EXT_color_buffer_float, gpu.js falls back to encoding values across standard 8-bit RGBA channels or reduced-precision textures.
  • Implicit Type Coercion: If precision qualifiers are not explicitly forced to highp across all intermediate steps inside the generated GLSL string, mobile drivers optimize register allocation by demoting internal operations to mediump.

Mitigation Strategies

To resolve precision banding in trigonometric gpu.js computations on mobile devices, apply the following architectural adjustments:

  • Pre-Reduce Input Domains: Never pass unconstrained or monotonically increasing variables (such as large timestamps or pixel indices) directly into trigonometric functions. Perform domain reduction in JavaScript or as an initial kernel step to constrain inputs strictly to \([0, 2\pi]\) before applying Math.sin() or Math.cos().
  • Enforce Precision Settings: Ensure the WebGL context creation requests highp precision, and confirm that the target device's mobile GPU actually supports true 32-bit floats in the fragment stage by inspecting gl.getShaderPrecisionFormat().
  • Scale and Center Coordinates: Normalize spatial coordinate spaces to \([-1.0, 1.0]\) rather than using raw canvas pixel dimensions to keep mantissa bits focused on fractional detail rather than large integer components.
