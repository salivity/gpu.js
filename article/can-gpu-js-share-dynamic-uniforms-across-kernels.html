Can GPU.js Share Dynamic Uniforms Across Kernels?

In GPU.js, uniform variables cannot be shared dynamically across multiple kernels through a single internal GPU memory state. Because each kernel compiles into a distinct WebGL shader program with its own isolated uniform bindings, GPU.js does not provide a native mechanism to bind a single uniform reference directly across independent kernels on the hardware level. However, developers can easily achieve synchronized, dynamic behavior across multiple kernels by managing uniform values from the JavaScript host environment or by using GPU.js pipelines.

Understanding Uniforms in GPU.js

In WebGL and GPU.js, a uniform is a read-only variable passed from the CPU (JavaScript) to the GPU before execution. When you create a kernel:

const gpu = new GPU();
const kernel = gpu.createKernel(function(dynamicFactor) {
    return this.thread.x * dynamicFactor;
}).setOutput([100]);

The parameter dynamicFactor acts as a uniform. This value is uploaded to the specific WebGL program context created for this kernel. If you define a second kernel, it compiles into a separate shader program with its own memory space for uniforms.

Why Native Cross-Kernel Uniform Sharing Is Not Supported

  1. Independent Program Contexts: Each kernel instance manages its own WebGL program state. There is no shared uniform buffer object (UBO) exposed by GPU.js that multiple kernels can bind to concurrently.
  2. Execution Decoupling: GPU.js kernels execute sequentially on the GPU. Changing a dynamic uniform on one kernel does not trigger a state change in another kernel unless explicitly invoked with the new value.

How to Dynamically Share Values Across Multiple Kernels

To use the same dynamic values across several kernels, you can manage the state on the JavaScript side or chain your computations.

1. Invocation-Time Dynamic Arguments

The standard approach is to pass your dynamic variables into each kernel during their respective JavaScript function calls.

const gpu = new GPU();

const kernelA = gpu.createKernel(function(val) {
    return this.thread.x + val;
}).setOutput([100]);

const kernelB = gpu.createKernel(function(val) {
    return this.thread.x * val;
}).setOutput([100]);

// Dynamic value maintained in JavaScript
let sharedDynamicValue = 5.0;

// Both kernels receive the current value dynamically
const resultA = kernelA(sharedDynamicValue);
const resultB = kernelB(sharedDynamicValue);

// Update value dynamically at runtime
sharedDynamicValue = 10.0;
const updatedResultA = kernelA(sharedDynamicValue);
const updatedResultB = kernelB(sharedDynamicValue);

2. Using GPU.js Pipelines

If the output of one kernel serves as the input to the next while sharing dynamic configuration values, enable the pipeline: true mode. This keeps data in texture format on the GPU, avoiding CPU-GPU transfer bottlenecks, while uniforms can still be passed dynamically to each step in the pipeline.

const renderStep1 = gpu.createKernel(function(data, modifier) {
    return data[this.thread.x] * modifier;
}).setOutput([100]).setPipeline(true);

const renderStep2 = gpu.createKernel(function(data, modifier) {
    return data[this.thread.x] + modifier;
}).setOutput([100]);

const initialData = [/* array of numbers */];
let sharedFactor = 2.5;

// Intermediate texture stays on GPU; shared factor is passed to both
const step1Result = renderStep1(initialData, sharedFactor);
const finalResult = renderStep2(step1Result, sharedFactor);

While GPU.js does not feature shared internal uniform memory between kernels, synchronizing dynamic values across multiple kernels is fully feasible by controlling the inputs through JavaScript invocation.
