Invert this.thread.y Axis in gpu.js Kernel

Inverting or flipping the axis orientation of this.thread.y in a gpu.js kernel is a common task when reconciling WebGL's default coordinate system with standard 2D image and screen coordinates. While this.thread.y itself is a read-only built-in variable that cannot be directly mutated or reconfigured at the kernel dispatch level, you can easily invert the vertical axis programmatically within the kernel body using arithmetic based on the output dimensions.

Why the Axis Needs Inversion

WebGL coordinates typically place the origin (0, 0) at the bottom-left corner, meaning this.thread.y increases as you move upward. In contrast, standard web APIs, the HTML5 Canvas 2D context, and common image formats position (0, 0) at the top-left corner, with the Y-axis increasing downward. When reading from or writing to 2D arrays and textures, this mismatch often results in upside-down output unless the vertical coordinate is explicitly flipped.

The Solution: Arithmetic Inversion

Because this.thread.y is an immutable hardware thread index, you cannot reassign it directly (e.g., this.thread.y = ... will cause a compilation error). Instead, define a local variable inside the kernel that calculates the inverted position relative to the total height of the output.

The formula to flip the index is:

const flippedY = (this.output.y - 1) - this.thread.y;

Implementation Example

Below is a demonstration of how to sample an input array or image using an inverted Y-axis:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const width = 512;
const height = 512;

const flipKernel = gpu.createKernel(function(inputMatrix) {
    // Invert the Y coordinate
    const invertedY = (this.output.y - 1) - this.thread.y;
    const x = this.thread.x;

    // Sample the data from the inverted vertical index
    return inputMatrix[invertedY][x];
}).setOutput([width, height]);

Working with Graphical Output

If your kernel uses .setGraphical(true) to render directly to a canvas, WebGL renders the output buffer to the screen automatically. If your input texture or calculation renders upside down on the canvas, applying the arithmetic inversion to your texture lookup coordinates ensures that the final rendered image displays with the correct orientation.
