gpu.js floatTextures False on Limited WebGL

Setting floatTextures to false in gpu.js forces the library to encode floating-point numbers into standard 8-bit integer textures instead of relying on native 32-bit floating-point textures. On platforms with limited WebGL extensions, this setting acts as a crucial fallback mechanism that prevents hardware incompatibility errors and crashes, ensuring broad cross-device compatibility at the cost of additional mathematical encoding overhead and potential precision limitations.

Overcoming Missing WebGL Extensions

By default, gpu.js utilizes native floating-point textures to handle decimal data within WebGL kernels. This capability requires specific WebGL extensions, most notably OES_texture_float in WebGL 1.0 or EXT_color_buffer_float in WebGL 2.0. On constrained platforms—such as older mobile devices, budget smartphones, or specific embedded browsers—these extensions are often missing or disabled by vendor implementations.

When these extensions are absent and floatTextures remains enabled, the WebGL context fails to allocate suitable render buffers or texture targets, resulting in runtime initialization errors. Disabling floatTextures bypasses the requirement for these extensions entirely, allowing gpu.js to run on nearly any hardware supporting basic WebGL.

8-Bit RGBA Texture Packing

When floatTextures: false is configured, gpu.js adapts by using standard 8-bit unsigned normalized integer textures (RGBA). Because a standard 8-bit channel can only store whole numbers between 0 and 255 (normalized to 0.0–1.0), 32-bit floating-point values cannot be saved directly into a single channel.

To resolve this, gpu.js automatically inserts packing and unpacking logic into the compiled GLSL shaders:

  • Output Packing: Floating-point outputs generated by the kernel are deconstructed into four distinct 8-bit components via bit-shifting and mathematical division, then written into the Red, Green, Blue, and Alpha channels of a single pixel.
  • Input Unpacking: When these textures are passed to downstream kernels or read back into JavaScript, the shader or read-back function recombines the four 8-bit channels into the original floating-point number.

Performance and Precision Implications

While setting floatTextures to false maximizes hardware reach, it introduces specific technical trade-offs:

  • Computational Overhead: Encoding and decoding floats on the GPU requires extra arithmetic operations inside the fragment shader. This reduces overall execution speed compared to native hardware float operations.
  • Bandwidth and Memory: Passing multi-channel packed data can consume additional texture lookups when managing multi-dimensional arrays or matrix operations that otherwise would have occupied a single channel.
  • Precision Artifacts: While standard IEEE 754 float packing generally preserves 32-bit precision, mathematical operations on platforms with low native shader precision (mediump or lowp) can occasionally introduce minor rounding errors during the packing and unpacking stages.

Practical Use Cases

Setting floatTextures: false is recommended when developing web applications for mass-market mobile browsers, legacy hardware, or environments where graceful degradation is preferred over raw computational throughput. For applications where maximum performance is critical and target hardware is modern and predictable, keeping native float textures enabled remains the optimal configuration.
