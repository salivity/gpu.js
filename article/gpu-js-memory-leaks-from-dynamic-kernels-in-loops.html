GPU.js Memory Leaks From Dynamic Kernels in Loops

Creating GPU.js kernels dynamically inside a loop leads to severe memory leaks and performance degradation. When you instantiate a kernel, GPU.js compiles JavaScript code into WebGL shader programs and allocates hardware-accelerated resources in GPU memory (VRAM). This article explains the technical mechanics behind GPU.js memory leaks, why standard JavaScript garbage collection fails to resolve them, and how to properly structure your code to prevent application crashes.

Why Dynamic Kernel Creation Causes Leaks

In GPU.js, calling gpu.createKernel() is not a lightweight function call; it is an expensive compilation step. During this step, the library performs several actions:

  1. Transpiles your JavaScript function into a GLSL (OpenGL Shading Language) shader.
  2. Allocates WebGL state machines, shader programs, framebuffers, and textures directly in VRAM.
  3. Attaches internal WebGL bindings and closures within the JavaScript execution context.

When gpu.createKernel() is placed inside a for, while, or render loop, a brand-new WebGL program and its associated GPU textures are allocated on every iteration.

JavaScript engines rely on garbage collection (GC) for managing system memory. However, the garbage collector operates on the CPU/RAM heap and is unaware of the memory consumption taking place in the GPU's VRAM. Even if the JavaScript reference to a kernel falls out of scope, the underlying WebGL context and GPU resources often remain pinned in video memory. Over successive iterations, this leads to rapid VRAM exhaustion, WebGL context loss (webglcontextlost), and eventually crashes the browser tab or Node.js process.

How to Prevent GPU.js Memory Leaks

To maintain stability and performance, avoid generating kernels dynamically. Apply the following design patterns instead:

1. Compile Once, Run Repeatedly

The primary rule of GPU.js is to define kernels once outside of repetitive execution paths. Once compiled, a kernel can be invoked multiple times with updated arguments without any additional memory overhead.

const gpu = new GPU();

// Good: Compile the kernel once outside the loop
const computeKernel = gpu.createKernel(function(data) {
    return data[this.thread.x] * 2;
}).setOutput([1000]);

// Run the precompiled kernel inside the loop
for (let i = 0; i < 100; i++) {
    const inputData = getDataset(i);
    const result = computeKernel(inputData);
    processResult(result);
}

2. Explicitly Destroy Dynamic Kernels

If your application design requires creating unique kernels on the fly—such as when changing the output dimensions dynamically or using completely different shader logic—you must manually free the allocated GPU resources when the kernel is no longer needed using the destroy() method.

for (let i = 0; i < 100; i++) {
    const dynamicSize = calculateDynamicSize(i);

    const temporaryKernel = gpu.createKernel(function() {
        return this.thread.x;
    }).setOutput([dynamicSize]);

    const result = temporaryKernel();
    processResult(result);

    // Explicitly release GPU textures and WebGL programs
    temporaryKernel.destroy();
}

3. Clean Up the Parent GPU Instance

If you are repeatedly instantiating new new GPU() instances within an application lifecycle (such as within component mounts or unit tests), the parent instance must also be cleaned up. Calling gpu.destroy() ensures all active kernels, contexts, and canvas elements linked to that instance are completely discarded from memory.
