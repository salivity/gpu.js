Understanding the Immutable Flag in GPU.js Kernels

In GPU.js, the immutable kernel flag governs how memory buffers for input textures are managed during execution, preventing the runtime from recycling or overwriting texture memory. This article explains the purpose of the immutable setting, why texture recycling happens by default in GPU-accelerated JavaScript, and how to use this flag to preserve data integrity across chained and iterative computations.

Texture Recycling in GPU.js

By default, GPU.js aggressively optimizes GPU memory (VRAM) allocation. When kernels are configured with pipeline: true, the output of a kernel is returned as a WebGL texture rather than a raw JavaScript array. This prevents expensive readbacks from VRAM to CPU memory.

To maintain performance and prevent memory leaks, GPU.js utilizes an internal texture pool. When a texture is passed as an input to another kernel, the engine assumes that the input data is disposable unless configured otherwise. Once the operation completes, the input texture's underlying WebGL framebuffer can be overwritten or recycled for the next output.

The Role of the immutable Flag

Setting immutable: true in the kernel configuration forces GPU.js to treat input textures as read-only, non-recyclable resources.

When immutable is set to true:

  • Prevents Memory Reuse: GPU.js will not return the input texture's buffer to the internal memory pool.
  • Preserves Texture Integrity: The data inside the input texture remains intact in VRAM, allowing the same texture to be safely passed into multiple separate kernels or referenced across multiple frames.
  • Eliminates Race Conditions: In complex execution pipelines, it stops subsequent operations from modifying or corrupting an input texture while it is still required by another branch of computation.

Configuration Example

You define the immutable flag inside the kernel options object during initialization:

const gpu = new GPU();

const computeKernel = gpu.createKernel(function(textureA) {
    return textureA[this.thread.y][this.thread.x] * 2;
}, {
    output: [512, 512],
    pipeline: true,
    immutable: true
});

When to Use immutable: true

The immutable flag is essential in specific architectures:

  1. Branching Pipelines: When a single texture serves as the input for two or more distinct kernels executing sequentially.
  2. Iterative Simulations: In simulations like Conway's Game of Life or physics solvers where a baseline texture needs to be referenced repeatedly without being corrupted by intermediate steps.
  3. Static Lookup Tables: When using a pre-calculated texture as a persistent read-only lookup table throughout the application's lifecycle.

Memory Trade-offs

While immutable: true ensures safe data handling, it increases VRAM consumption because GPU.js cannot automatically reclaim texture memory. When using immutable textures, you must manually manage texture lifecycles and explicitly release memory using the texture.delete() method once the data is no longer needed.
