Dynamic Memory Allocation in GPU.js Kernels

GPU.js accelerates JavaScript code by compiling functions into WebGL shaders that run directly on the graphics processing unit. However, developers frequently encounter architectural limitations when attempting to manage data, specifically regarding memory allocation during execution. You cannot create new dynamic arrays, push elements to existing structures, or allocate dynamic memory inside an executing GPU.js kernel. This article explains the underlying technical constraints of GPU hardware that prevent dynamic memory allocation and details how to properly structure your data pipeline using fixed output dimensions and pre-allocated buffers.

Why Dynamic Allocation Is Unsupported

GPU.js kernels do not execute in standard JavaScript engines like V8. Instead, the library parses the JavaScript function and translates it into a WebGL fragment shader written in GLSL (OpenGL Shading Language).

GLSL enforces strict constraints due to the parallel nature of graphics hardware:

  1. No Dynamic Heap: GPUs run thousands of threads concurrently across hardware execution units. There is no central heap memory or dynamic memory manager (such as malloc or JavaScript's garbage-collected memory model) available to individual shader threads.
  2. Fixed Register and Stack Limits: Every variable instantiated within a thread must have a predictable, static size known at compile time. Variable-length arrays, dynamic resizing (such as array.push()), and object instantiation are forbidden.
  3. Execution Model: In GPU computing, the output buffer memory is pre-allocated by the host (the CPU) before the kernel launches. Each thread is assigned a coordinate in that memory space and simply writes its computed value to its corresponding location.

Managing Output Dimensions Upfront

Because a kernel cannot create or resize an array on the fly, you must declare the shape and size of your output data before executing the kernel. This is accomplished using the .setOutput() method.

The return value of the kernel function determines the value written to that thread's position in the pre-allocated output array. For instance, rather than building an array iteratively inside a loop:

const gpu = new GPU();

const computeKernel = gpu.createKernel(function(inputData) {
  // Access current coordinates
  const index = this.thread.x;
  
  // Return a single scalar or vector value for this slot
  return inputData[index] * 2.0;
}).setOutput([1000]);

const result = computeKernel(myInputArray);

In this setup, GPU.js creates a fixed-size 1D array of length 1,000 in video memory. Each thread executes concurrently for indices 0 through 999 and writes its return value directly into its pre-assigned memory slot.

Working with Fixed Local Storage

While dynamic arrays are not allowed, you can use local, fixed-size variables to store intermediate results during a thread's calculation.

To perform multi-step arithmetic inside a thread:

  • Use primitive variables (let, const) representing numbers (floats or integers).
  • Avoid any JavaScript array methods like .concat(), .slice(), or .push().
  • If you need a small collection of items inside a thread, represent them as separate scalar variables (e.g., let val1 = 0; let val2 = 0;) rather than a dynamic list.

Passing Pre-Allocated Arrays and Multi-Pass Workflows

If an algorithm requires intermediate arrays or expanding dataset transformations, the host JavaScript environment must manage the allocations between kernel runs.

Multi-Pass Architectures

If an algorithm requires multiple computational steps where step two depends on the full output of step one, run them as separate kernels or use GPU.js pipelines:

  1. Kernel A (First Pass): Allocates an output buffer via .setOutput([N]) and writes intermediate data.
  2. Transfer or Pipe: The resulting texture remains in GPU memory if using .setPipeline(true).
  3. Kernel B (Second Pass): Reads the output of Kernel A as an input parameter and writes to another pre-allocated buffer via its own .setOutput([M]).

Resizing and Filtering Data

Because a kernel cannot dynamically discard or add elements, operations like filtering (removing elements from an array) cannot shrink an array in-place inside the GPU. To filter or resize data:

  1. Flag unwanted values using a sentinel number (like NaN or -1) inside the kernel output.
  2. Read the fixed-dimension array back to the CPU.
  3. Use native JavaScript methods (such as Array.prototype.filter()) on the CPU side to construct the final dynamic array.
