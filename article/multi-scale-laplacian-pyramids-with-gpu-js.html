Multi-Scale Laplacian Pyramids with GPU.js

Multi-scale Laplacian pyramid decomposition and reconstruction can be successfully implemented using GPU.js. By compiling JavaScript functions into WebGL compute shaders, GPU.js allows developers to execute the highly parallel image processing operations—such as Gaussian blurring, decimation, interpolation, and pixel-wise arithmetic—directly on the graphics hardware within a browser or Node.js environment. This article breaks down how to construct the multi-resolution pipeline, perform the forward decomposition and backward reconstruction, and optimize memory usage using GPU.js features.

Understanding the Pipeline Requirements

A multi-scale Laplacian pyramid breaks an image down into bandpass-filtered sub-bands at varying resolutions, alongside a low-frequency residual. Building and reversing this structure involves four fundamental operations:

  1. Gaussian Filtering: Convolving the image with a smoothing kernel (typically a 5x5 separable binomial filter).
  2. Downsampling (Reduce): Subsampling the blurred image by a factor of two to create the next Gaussian level.
  3. Upsampling (Expand): Interpolating the downsampled image back to the previous scale and smoothing it to match dimensions.
  4. Subtraction and Addition: Computing difference images for decomposition and summing them for reconstruction.

All of these tasks are massively parallel per-pixel calculations, making them naturally suited for GPU execution.

Implementing Decomposition with GPU.js

The decomposition process starts with the base image (\(G_0\)) and iteratively produces Gaussian layers (\(G_k\)) and Laplacian detail layers (\(L_k\)).

  1. Blurring and Decimation: Define a GPU.js kernel that combines a 2D convolution with a step factor of two. For each target pixel (x, y) in the output, the kernel samples a \(5 \times 5\) window centered at (2x, 2y) in the source texture, multiplying by standard Gaussian weights. This produces the downsampled level \(G_{k+1}\) directly, cutting down redundant texture fetches.

  2. Upsampling (Expansion): A separate GPU.js kernel takes \(G_{k+1}\) and maps each pixel (x, y) back to the original resolution. Pixels at even coordinates receive values directly from the coarser grid, while odd coordinates are interpolated using adjacent values, followed by a smoothing pass.

  3. Computing the Laplacian Level: A simple subtraction kernel calculates \(L_k = G_k - \text{Expand}(G_{k+1})\). This step isolates the high-frequency bandpass data for that scale.

Repeat this process for \(N\) levels. The final representation consists of the Laplacian levels \(L_0, L_1, \dots, L_{N-1}\) and the coarsest Gaussian residual \(G_N\).

Implementing Reconstruction

Reconstruction restores the original image from the top of the pyramid downward without loss of detail:

  1. Begin with the lowest-resolution Gaussian residual, \(G_N\).
  2. Upsample \(G_N\) using the expansion kernel to match the dimensions of \(L_{N-1}\).
  3. Run an addition kernel to compute \(G_{N-1} = L_{N-1} + \text{Expand}(G_N)\).
  4. Repeat this step recursively until \(G_0\) is fully restored at the original resolution.

Crucial Implementation Considerations in GPU.js

While the mathematics are straightforward, achieving high performance in GPU.js requires specific architectural choices:

  • Enable Pipeline Mode: By default, GPU.js reads texture data back to the CPU as a typed array after every kernel execution. To avoid severe PCIe transfer bottlenecks, set pipeline: true on your kernels. This keeps the pyramid layers in VRAM as WebGL textures throughout the entire decomposition and reconstruction sequence.
  • Dynamic Kernel Output Sizes: Each level of the pyramid halves the output dimensions. Because GPU.js kernels have fixed output dimensions upon creation, you must either dynamically update kernel output bounds using .setOutput([newWidth, newHeight]) between iterations or instantiate dedicated kernels pre-sized for each specific octave.
  • Separable Filtering vs. 2D Kernels: In raw GLSL, separable 1D passes (horizontal then vertical) are often preferred for efficiency. In GPU.js, chaining two separate 1D kernels introduces overhead in kernel invocation. A single \(5 \times 5\) 2D convolution kernel often provides an optimal balance between execution speed and code simplicity for pyramids up to 4 or 5 levels deep.
  • Floating-Point Precision: Laplacian layers contain both positive and negative values. Standard 8-bit RGBA representations will clamp negative values to zero. Ensure your GPU.js instance uses float textures (enabled by default in modern WebGL2 environments) to preserve high dynamic range and negative detail coefficients accurately.
