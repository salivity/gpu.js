Parallelize Black-Scholes Across Strikes in GPU.js

This article explains how to parallelize the Black-Scholes European call option pricing model across an array of strike prices using gpu.js. By mapping individual GPU threads to distinct strike prices, computational workloads shift from sequential CPU loops to massively parallel WebGL compute shaders. You will learn how the analytical model translates into a gpu.js kernel, how to approximate the cumulative normal distribution function on the GPU, and how to structure inputs for optimal throughput.

Understanding the Parallel Mapping Strategy

The Black-Scholes formula for a European call option requires five parameters: the current underlying price (\(S\)), the strike price (\(K\)), the risk-free interest rate (\(r\)), time to maturity in years (\(T\)), and volatility (\(\sigma\)).

The call option price (\(C\)) is calculated as:

\[C = S \cdot N(d_1) - K \cdot e^{-rT} \cdot N(d_2)\]

where: \[d_1 = \frac{\ln(S / K) + (r + \frac{\sigma^2}{2})T}{\sigma \sqrt{T}}\] \[d_2 = d_1 - \sigma \sqrt{T}\]

When evaluating an option surface or a volatility smile across hundreds of thousands of strike prices, \(S\), \(r\), \(T\), and \(\sigma\) remain constant while \(K\) varies. In gpu.js, this problem is parallelized using a 1D kernel dimension where the output dimension matches the length of the strike price array (K.length).

Each GPU thread uses its unique identifier, this.thread.x, to fetch its assigned strike price from the input array, evaluate \(d_1\) and \(d_2\), evaluate the cumulative normal distribution \(N(\cdot)\), and write the resulting option price directly to the output buffer in parallel.

Implementing the Kernel in gpu.js

Because standard WebGL shaders lack a native Cumulative Normal Distribution function (\(N(x)\)), an approximation must be implemented within the kernel. The Abramowitz and Stegun numerical approximation is standard for GPU compute due to its balance of single-precision accuracy and computational efficiency.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Kernel creation
const computeCallOptionChain = gpu.createKernel(function(S, r, T, sigma, strikes) {
    const K = strikes[this.thread.x];
    const sqrtT = Math.sqrt(T);
    const sigmaSqrtT = sigma * sqrtT;
    
    const d1 = (Math.log(S / K) + (r + 0.5 * sigma * sigma) * T) / sigmaSqrtT;
    const d2 = d1 - sigmaSqrtT;

    // Approximation constants for Cumulative Normal Distribution
    const b1 =  0.319381530;
    const b2 = -0.356563782;
    const b3 =  1.781477937;
    const b4 = -1.821255978;
    const b5 =  1.330274429;
    const p  =  0.2316419;
    const c  =  0.3989422804014327; // 1 / sqrt(2 * PI)

    // Calculate N(d1)
    const absD1 = Math.abs(d1);
    const t1 = 1.0 / (1.0 + p * absD1);
    let poly1 = t1 * (b1 + t1 * (b2 + t1 * (b3 + t1 * (b4 + t1 * b5))));
    let nd1 = 1.0 - c * Math.exp(-0.5 * d1 * d1) * poly1;
    if (d1 < 0.0) {
        nd1 = 1.0 - nd1;
    }

    // Calculate N(d2)
    const absD2 = Math.abs(d2);
    const t2 = 1.0 / (1.0 + p * absD2);
    let poly2 = t2 * (b1 + t2 * (b2 + t2 * (b3 + t2 * (b4 + t2 * b5))));
    let nd2 = 1.0 - c * Math.exp(-0.5 * d2 * d2) * poly2;
    if (d2 < 0.0) {
        nd2 = 1.0 - nd2;
    }

    // Black-Scholes Call Price: S * N(d1) - K * exp(-r * T) * N(d2)
    const callPrice = S * nd1 - K * Math.exp(-r * T) * nd2;
    
    return callPrice;
})
.setOutput([100000]); // Matches strikes array length

Executing the Calculation

To invoke the parallelized kernel, compile the input data as JavaScript floating-point numbers and a typed array for optimal memory packing:

const S = 100.0;       // Underlying stock price
const r = 0.05;        // Risk-free interest rate (5%)
const T = 1.0;         // Time to expiration (1 year)
const sigma = 0.20;    // Volatility (20%)

const strikeCount = 100000;
const strikes = new Float32Array(strikeCount);

// Generate varying strike prices from $50 to $150
for (let i = 0; i < strikeCount; i++) {
    strikes[i] = 50.0 + (i / strikeCount) * 100.0;
}

// Execute parallel kernel on GPU
const callPrices = computeCallOptionChain(S, r, T, sigma, strikes);

Key Technical Considerations

  1. Precision: WebGL 1.0 kernels operate on 32-bit floating-point numbers. Ensure that option values with extreme moneyness (very deep in-the-money or out-of-the-money) do not produce NaN due to underflow in the standard normal distribution exponential term.
  2. Buffer Transfer Overhead: Transferring large arrays between CPU memory and GPU VRAM introduces latency. Parallelizing across strike prices is computationally advantageous when processing batches exceeding tens of thousands of elements; smaller arrays may execute faster on the CPU using single-instruction, multiple-data (SIMD) paths.
  3. Pipeline Pipelining: If repeatedly calculating pricing for animated graphs or streaming ticker updates, set .setPipeline(true) on the kernel to keep output data on the GPU texture memory instead of converting it back to CPU arrays after every computation.
