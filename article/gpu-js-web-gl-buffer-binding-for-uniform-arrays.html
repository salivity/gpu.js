GPU.js WebGL Buffer Binding for Uniform Arrays

This article explores how GPU.js manages WebGL buffer binding targets when updating uniform array buffers across different hardware contexts. It covers the mechanics of target selection between WebGL 1 and WebGL 2, how gl.UNIFORM_BUFFER targets are bound and populated, the fallback mechanisms used when uniform arrays exceed size limits, and the internal state cleanup required to maintain WebGL pipeline integrity.

Uniform Array Handling Across WebGL Contexts

GPU.js dynamically compiles JavaScript operations into GLSL shaders and manages the corresponding WebGL pipeline. When passing uniform array data into a kernel, GPU.js evaluates whether the active rendering context is WebGL 1 or WebGL 2, as this determines how uniform arrays are stored and updated in GPU memory.

In WebGL 1, true uniform array buffers (Uniform Buffer Objects, or UBOs) do not exist. GPU.js handles standard uniform arrays by setting values directly via program state using methods such as gl.uniform1fv or gl.uniform4fv. These standard uniform updates target internal shader uniform locations rather than dedicated buffer targets.

In WebGL 2, GPU.js can take advantage of Uniform Buffer Objects. In this scenario, uniform arrays can be managed as actual buffer objects using the gl.UNIFORM_BUFFER binding target, allowing shared, re-usable data across multiple shader invocations without re-uploading individual uniform variables.

The gl.UNIFORM_BUFFER Binding Workflow

When a WebGL 2 kernel requires an update to a uniform array represented by a UBO, GPU.js executes a strict sequence to ensure the buffer target is properly configured:

  1. Target Selection: GPU.js assigns gl.UNIFORM_BUFFER as the active target for the array buffer operation.
  2. Buffer Binding: The framework invokes gl.bindBuffer(gl.UNIFORM_BUFFER, webGlBuffer). This establishes the designated WebGL buffer as the active recipient for subsequent uniform data modifications.
  3. Memory Updating:
    • If the size of the array has changed, GPU.js calls gl.bufferData(gl.UNIFORM_BUFFER, data, gl.STATIC_DRAW) (or gl.DYNAMIC_DRAW) to reallocate the storage on the GPU.
    • If the array size is unchanged, it employs gl.bufferSubData(gl.UNIFORM_BUFFER, 0, data) to overwrite the existing memory without the performance cost of reallocating buffer memory.
  4. Binding Point Association: To make the buffer data readable by the compiled shader, GPU.js binds the buffer to an indexed uniform block binding point using gl.bindBufferBase(gl.UNIFORM_BUFFER, index, webGlBuffer) or gl.bindBufferRange.

Handling Large Arrays via Texture Targets

Hardware implementations enforce strict memory limits on uniforms via MAX_UNIFORM_BLOCK_SIZE or MAX_VERTEX_UNIFORM_VECTORS. Because numerical compute tasks frequently exceed these hardware thresholds, GPU.js bypasses uniform buffer targets entirely for large arrays.

When an array argument is deemed too large for a uniform target:

  • GPU.js converts the uniform array into a float texture.
  • Instead of using gl.UNIFORM_BUFFER or standard uniform setters, it binds the target to gl.TEXTURE_2D using gl.bindTexture.
  • Updates are handled via gl.texSubImage2D or gl.texImage2D.
  • The shader then reads the array elements via texture lookups (texelFetch or texture2D) rather than standard uniform indexing.

State Cleanup and Unbinding

To prevent side effects across different kernels or interfering with external WebGL libraries sharing the context, GPU.js manages buffer target state cleanup. Once an update to a uniform buffer is finalized, GPU.js unbinds the target by passing null to the target binding call:

gl.bindBuffer(gl.UNIFORM_BUFFER, null);

Unbinding the target ensures that subsequent operations targeting other buffers (such as vertex attributes using gl.ARRAY_BUFFER or index buffers using gl.ELEMENT_ARRAY_BUFFER) do not inadvertently overwrite uniform data or encounter state collision errors during execution.
