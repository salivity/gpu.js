Parallel Coordinates Density Estimation with GPU.js

This article explains how to implement density estimation for parallel coordinate plots using GPU.js to eliminate visual clutter and overplotting in high-dimensional datasets. By delegating the computationally intensive point-to-line kernel density calculations to the GPU via WebGL shaders, you can achieve interactive rendering of dense datasets directly in the browser. Below, you will find the mathematical approach, a complete GPU.js kernel implementation, and instructions for mapping density values to color palettes.

The Overplotting Challenge

Parallel coordinates map multi-dimensional data by representing each data entry as a continuous polyline intersecting parallel, equidistant vertical axes. When visualizing tens of thousands of records, polylines overlap entirely, obscuring underlying distributions, clusters, and correlations.

Density estimation resolves this by transforming discrete lines into a continuous 2D scalar field across the space between each pair of adjacent axes. Rather than drawing individual lines, you calculate the local density of line segments passing through or near each screen pixel using a Gaussian kernel.

Architectural Approach with GPU.js

GPU.js compiles a subset of JavaScript into WebGL fragment shaders. Because WebGL operates on an embarrassingly parallel per-pixel pipeline, the optimal strategy is:

  1. Define a canvas representing the space between two adjacent axes.
  2. For every pixel \((x, y)\), calculate the interpolated line height for every record in the dataset at coordinate \(x\).
  3. Compute the vertical distance between the pixel's \(y\) coordinate and the line's interpolated position.
  4. Accumulate kernel density contributions (e.g., Gaussian weights) for all records.
  5. Map the accumulated density to a color scale and output the pixel color directly.

Mathematical Formulation

Given two normalized adjacent axes \(A_1\) and \(A_2\) with values in the range \([0, 1]\), a record \(i\) has values \(y_{1,i}\) and \(y_{2,i}\).

For a screen region of width \(W\) and height \(H\), let the pixel coordinate be \((x, y)\) where \(x \in [0, W]\) and \(y \in [0, H]\). The normalized horizontal position is:

\[t = \frac{x}{W}\]

The expected vertical coordinate of line \(i\) at position \(t\) is:

\[\hat{y}_i(t) = H \cdot \left( y_{1,i} + t \cdot (y_{2,i} - y_{1,i}) \right)\]

Using a Gaussian kernel with bandwidth \(\sigma\), the density contribution of line \(i\) to pixel \((x, y)\) is:

\[K(y, \hat{y}_i(t)) = \exp\left( -\frac{(y - \hat{y}_i(t))^2}{2\sigma^2} \right)\]

The total density \(D(x, y)\) is the sum of contributions over all \(N\) records:

\[D(x, y) = \sum_{i=0}^{N-1} K(y, \hat{y}_i(t))\]

GPU.js Kernel Implementation

Install GPU.js via npm (npm install gpu.js) or include it via a CDN. The following implementation generates a density field between two axes on an HTML canvas.

import { GPU } from 'gpu.js';

const width = 400;   // Distance between adjacent axes
const height = 600;  // Height of the axes
const numPoints = 20000;

// Initialize GPU.js targeting an HTML canvas
const canvas = document.createElement('canvas');
const gpu = new GPU({ canvas: canvas, mode: 'webgl2' });

// Sample normalized data: [val_axis1, val_axis2]
const dataAxis1 = new Float32Array(numPoints);
const dataAxis2 = new Float32Array(numPoints);

for (let i = 0; i < numPoints; i++) {
  dataAxis1[i] = Math.random();
  dataAxis2[i] = Math.pow(dataAxis1[i], 2); // Non-linear relationship
}

// Define the GPU kernel
const renderDensity = gpu.createKernel(function(axis1, axis2, totalRecords, sigma, maxDensity) {
  const x = this.thread.x;
  const y = this.thread.y;
  const width = this.output.x;
  const height = this.output.y;

  const t = x / width;
  let density = 0.0;
  const twoSigmaSq = 2.0 * sigma * sigma;

  // Accumulate density from all lines
  for (let i = 0; i < totalRecords; i++) {
    const yLine = height * (axis1[i] + t * (axis2[i] - axis1[i]));
    const dist = y - yLine;
    density += Math.exp(-(dist * dist) / twoSigmaSq);
  }

  // Normalize density for visualization
  const normDensity = Math.min(density / maxDensity, 1.0);

  // Apply a basic heat color scale (Dark Blue -> Green -> Yellow)
  const r = Math.max(0.0, 2.0 * normDensity - 1.0);
  const g = normDensity < 0.5 ? 2.0 * normDensity : 2.0 * (1.0 - normDensity);
  const b = Math.max(0.0, 1.0 - 2.0 * normDensity);

  this.color(r, g, b, 1.0);
})
.setOutput([width, height])
.setGraphical(true);

// Execute the kernel
const bandwidth = 3.0;     // Smoothing radius in pixels
const maxExpectedDensity = 150.0; // Calibration factor for color mapping

renderDensity(dataAxis1, dataAxis2, numPoints, bandwidth, maxExpectedDensity);

document.body.appendChild(canvas);

Performance Optimizations

  1. Array Flattening: Always pass typed 1D arrays (Float32Array) into GPU.js. Multidimensional standard arrays incur serialization and texture upload penalties.
  2. Loop Unrolling and Chunking: GPUs maintain execution timeouts on shaders to prevent driver crashes. If the data size exceeds 100,000 records, process records in batches and accumulate the result onto a floating-point framebuffer texture before color mapping.
  3. Axis Pairing: For plots with \(M\) dimensions, instantiate \(M-1\) separate canvases or stitch them inside a single wide kernel by partitioning this.thread.x based on axis intervals:
const axisIndex = Math.floor(this.thread.x / segmentWidth);
const localX = this.thread.x % segmentWidth;

This ensures complete parallel coordinates plots are rendered in a single draw pass.
