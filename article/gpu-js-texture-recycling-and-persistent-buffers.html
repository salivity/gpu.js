GPU.js Texture Recycling and Persistent Buffers

This article examines whether developers can disable automatic texture recycling in GPU.js to retain persistent buffers across execution calls. While GPU.js does not offer a dedicated configuration flag to globally toggle texture recycling off, developers can achieve buffer persistence and prevent automatic overwrites by using pipeline mode combined with explicit texture cloning and manual lifecycle management.

Texture Recycling in GPU.js

By default, GPU.js converts computed results from WebGL textures back into standard JavaScript arrays on the CPU. To keep data on the GPU across multiple kernel executions, developers enable pipeline mode by setting { pipeline: true } in the kernel options. In this mode, the kernel returns a Texture instance rather than an array.

To optimize memory usage and avoid frequent VRAM allocations, GPU.js internally recycles WebGL framebuffers and textures between runs. The library does not provide a native configuration option such as disableTextureRecycling: true to turn off this behavior globally. Consequently, executing the same kernel repeatedly can overwrite the underlying WebGL texture data of a previously returned result if that texture remains bound to the kernel's internal recycling pool.

How to Retain Persistent Buffers

To keep texture data persistent across calls without it being mutated or reclaimed by subsequent kernel executions, you must explicitly detach or duplicate the buffer.

1. Using texture.clone()

The most reliable way to retain a persistent buffer across calls is to clone the output texture. Calling the clone() method creates a distinct WebGL texture allocation that is completely removed from the kernel's automatic recycling pipeline.

const kernel = gpu.createKernel(function(data) {
  return data[this.thread.x] * 2;
}, {
  output: [512],
  pipeline: true
});

// Run kernel
const initialTexture = kernel(inputData);

// Retain as a persistent buffer by cloning
const persistentBuffer = initialTexture.clone();

// Subsequent calls can safely recycle the internal texture
const nextResult = kernel(inputData);

2. Manual Memory Management with texture.delete()

Because cloned textures bypass GPU.js's automated memory recycling, the garbage collector will not immediately free the associated VRAM. To avoid memory leaks when retaining buffers across multiple frames or iterations, manually release the texture once it is no longer required:

persistentBuffer.delete();

3. Ping-Pong Buffering

When running iterative computations (such as simulations or cellular automata), you do not need to disable recycling. Instead, use two persistent texture references and alternate their roles as input and output on each step:

let currentBuffer = kernel(initialData).clone();
let nextBuffer;

for (let i = 0; i < iterations; i++) {
  nextBuffer = kernel(currentBuffer);
  currentBuffer.delete();
  currentBuffer = nextBuffer.clone();
}

Summary

You cannot natively disable texture recycling through a global configuration flag in GPU.js. However, you can retain persistent GPU buffers across calls by enabling { pipeline: true }, creating dedicated copies via texture.clone(), and manually freeing allocations with texture.delete() when they are no longer needed.
