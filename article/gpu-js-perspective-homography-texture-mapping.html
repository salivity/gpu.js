GPU.js Perspective Homography Texture Mapping

Perspective homography transformations can be mapped onto image textures using a single kernel in gpu.js. By applying an inverse projective transformation matrix directly inside the kernel execution pipeline, each output thread computes its corresponding source coordinate in parallel. This approach avoids output gaps, maximizes GPU throughput via WebGL, and processes the transformation in a single draw pass without requiring intermediate render targets.

Understanding the Inverse Mapping Strategy

A perspective homography relates two planar projections using a 3x3 transformation matrix (\(H\)). While forward mapping multiplies source coordinates by \(H\) to find destination coordinates, doing so on a GPU leads to holes, overlapping pixels, and aliasing because multiple source pixels might land on the same target pixel while others are skipped.

To achieve continuous mapping in a single kernel, the algorithm relies on backward (inverse) mapping. The kernel calculates the color for every destination pixel coordinate \((x, y)\) by multiplying by the inverse homography matrix (\(H^{-1}\)):

  1. Input: The inverse 3x3 matrix coefficients and the source image texture.
  2. Coordinate Evaluation: Treat the destination pixel position (this.thread.x, this.thread.y) as a homogeneous coordinate vector \([x, y, 1]^T\).
  3. Projection: Compute the intermediate homogeneous coordinates:
    • \(u = H^{-1}_{00}x + H^{-1}_{01}y + H^{-1}_{02}\)
    • \(v = H^{-1}_{10}x + H^{-1}_{11}y + H^{-1}_{12}\)
    • \(w = H^{-1}_{20}x + H^{-1}_{21}y + H^{-1}_{22}\)
  4. Perspective Division: Normalize by the projective scale factor to obtain the source coordinates: \(x_{src} = u / w\) and \(y_{src} = v / w\).

Single Kernel Architecture in gpu.js

gpu.js compiles JavaScript functions into GLSL fragment shaders. In a 2D kernel configuration, each thread represents a single pixel of the output canvas. Because every thread independently resolves its corresponding location in the input texture, the entire operation fits cleanly within one kernel function.

const gpu = new GPU();

const transformKernel = gpu.createKernel(function(image, invH) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Apply inverse 3x3 homography
    const u = invH[0] * x + invH[1] * y + invH[2];
    const v = invH[3] * x + invH[4] * y + invH[5];
    const w = invH[6] * x + invH[7] * y + invH[8];

    // Perspective divide
    const srcX = Math.floor(u / w);
    const srcY = Math.floor(v / w);

    // Boundary check
    if (srcX < 0 || srcX >= this.constants.sourceWidth || 
        srcY < 0 || srcY >= this.constants.sourceHeight || 
        w <= 0.0) {
        this.color(0, 0, 0, 0); // Transparent or background color
    } else {
        const pixel = image[srcY][srcX];
        this.color(pixel.r, pixel.g, pixel.b, pixel.a);
    }
})
.setOutput([outputWidth, outputHeight])
.setConstants({ sourceWidth, sourceHeight })
.setGraphical(true);

Sampling and Precision Considerations

  • Interpolation: The baseline implementation uses nearest-neighbor lookup via Math.floor(). To eliminate blocky artifacts, manual bilinear interpolation can be computed inside the same kernel by fetching the four neighboring pixels ((x0, y0), (x1, y0), (x0, y1), (x1, y1)) and weighting them according to the fractional offsets of \(x_{src}\) and \(y_{src}\).
  • Matrix Inversion: The inverse matrix (\(H^{-1}\)) must be computed on the CPU prior to kernel execution. Performing 3x3 matrix inversion on the CPU avoids redundant per-pixel inversion on the GPU.
  • Negative W Clamping: When \(w \le 0\), the projected point lies behind the projection center. Explicitly checking for \(w > 0\) prevents mirrored distortion artifacts from appearing in the output space.
