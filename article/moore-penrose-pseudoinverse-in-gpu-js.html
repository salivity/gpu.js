Moore-Penrose Pseudoinverse in gpu.js

This guide explains how to efficiently compute the Moore-Penrose pseudoinverse of a non-square matrix using gpu.js. Because traditional Singular Value Decomposition (SVD) is branching-heavy and inefficient to implement directly in WebGL shaders, the recommended approach relies on the iterative Newton-Schulz algorithm or the normal equations method. By framing the computation around parallel General Matrix Multiply (GEMM) operations, gpu.js can rapidly converge on an accurate pseudoinverse entirely on the GPU.

Why Avoid Direct SVD on the GPU

The textbook definition of the Moore-Penrose pseudoinverse (\(A^+\)) relies on Singular Value Decomposition:

\[A^+ = V \Sigma^+ U^T\]

While SVD handles matrices of arbitrary rank, implementing two-sided Jacobi rotations or bidiagonalization with QR iterations in gpu.js introduces massive pipeline stalls, sequential dependencies, and excessive thread synchronization. As a result, exact SVD in shader environments performs poorly compared to GEMM-centric algorithms.

Recommended Method: Newton-Schulz Iteration

The Newton-Schulz method is a matrix-inversion analogue of Newton-Raphson iteration. It approximates the pseudoinverse using only matrix multiplication and subtraction, which are natively suited to WebGL fragment shaders in gpu.js.

The update formula is:

\[X_{k+1} = X_k (2I - A X_k)\]

Where:

  • \(A\) is the input \(m \times n\) matrix.
  • \(X_k\) is the current approximation of \(A^+\), with dimensions \(n \times m\).
  • \(I\) is the \(m \times m\) identity matrix.

Step 1: Initialize \(X_0\)

Convergence requires a stable starting matrix \(X_0\). A standard, robust initialization is:

\[X_0 = \alpha A^T\]

where:

\[\alpha = \frac{1}{\|A\|_1 \|A\|_\infty}\]

Here, \(\|A\|_1\) is the maximum absolute column sum and \(\|A\|_\infty\) is the maximum absolute row sum. Computing \(\alpha\) can be done quickly on the CPU prior to passing the data to the GPU.

Step 2: Implement GPU Kernels in gpu.js

Newton-Schulz requires two primary GPU kernels:

  1. Matrix Multiplication Kernel: Multiplies two matrices (\(C = AB\)).
  2. Residual Update Kernel: Multiplies \(X_k\) by \((2I - AX_k)\).
const { GPU } = require('gpu.js');
const gpu = new GPU();

// Parallel Matrix Multiplication
const multiplyMatrices = gpu.createKernel(function(a, b, commonDim) {
    let sum = 0;
    for (let i = 0; i < commonDim; i++) {
        sum += a[this.thread.y][i] * b[i][this.thread.x];
    }
    return sum;
}).setOutput([/* cols */, /* rows */]);

// Scaled Subtraction Kernel: (2 * I) - AX
const computeResidual = gpu.createKernel(function(ax, m) {
    let identity = (this.thread.x === this.thread.y) ? 2.0 : 0.0;
    return identity - ax[this.thread.y][this.thread.x];
}).setOutput([m, m]);

Step 3: Run the Iteration Loop

Keep intermediate textures in GPU memory to prevent readback overhead. Run the iteration until the difference \(\|X_{k+1} - X_k\|\) drops below your desired tolerance threshold (typically 10 to 15 iterations are sufficient for moderate condition numbers).

Alternative Method: Normal Equations (Full-Rank Matrices)

If your matrix is guaranteed to have full rank, you can avoid iterative methods by solving the normal equations directly:

  • Full Column Rank (\(m > n\)): \[A^+ = (A^T A)^{-1} A^T\]
  • Full Row Rank (\(m < n\)): \[A^+ = A^T (A A^T)^{-1}\]

Implementation Steps:

  1. Compute the Gram matrix (\(A^T A\) or \(A A^T\)) using a gpu.js matrix multiplication kernel. The result is a small, symmetric positive-definite square matrix.
  2. Invert the small square matrix. For matrices smaller than roughly \(100 \times 100\), transfer the Gram matrix to the CPU and use standard Cholesky decomposition or LU inversion via an optimized library (such as mathjs).
  3. Send the inverted square matrix back to gpu.js and execute a final multiplication with \(A^T\).

Summary Recommendation

  • Use the Newton-Schulz iterative method if your matrix is large, close to square, or if you require an end-to-end GPU pipeline without round-trip data transfers between the CPU and GPU.
  • Use the Normal Equations hybrid method if the matrix has a small inner dimension (\(n \ll m\) or \(m \ll n\)) and full rank, as the square matrix inversion becomes computationally trivial on the CPU.
