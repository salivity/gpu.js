Handling Null and Undefined in GPU.js Kernels

GPU.js compiles JavaScript functions into WebGL shaders, translating standard JavaScript code into strongly typed GLSL (OpenGL Shading Language). Because GLSL does not possess native concepts of null or undefined, passing these values as kernel arguments can disrupt the compilation and uniform binding processes. This guide explains how GPU.js processes null and undefined inputs, the operational differences between GPU and CPU modes, and how to safely handle absent data.

The Underlying Issue: GLSL Static Typing

In standard JavaScript, variables are dynamically typed and can freely hold null or undefined. Conversely, WebGL shaders require static types such as float, int, vec4, or sampler2D. When you invoke a GPU.js kernel, the library inspects the supplied arguments to determine how to map them to WebGL uniforms.

Because null and undefined have no direct GLSL equivalents, GPU.js cannot reliably infer their target shader types.

Behavior in GPU Mode

When executing on the GPU via WebGL, passing null or undefined produces the following outcomes:

  1. Type Inference Failures: GPU.js evaluates the type of an argument at runtime to bind it to the correct WebGL uniform function (such as gl.uniform1f or gl.uniform1i). If the argument is undefined, the type cannot be resolved, commonly throwing an error such as TypeError: Cannot read properties of undefined or triggering an unhandled type exception inside the argument processing pipeline.
  2. WebGL Uniform Errors: If null passes initial argument parsing, it is often coerced into 0 by lower-level JavaScript operations, or it causes the WebGL API to throw an error when attempting to populate uniform arrays or textures. If an array parameter is passed as null, any attempt by GPU.js to read its dimensions or upload texture data will throw an immediate runtime exception.

Behavior in CPU Fallback Mode

If WebGL is unsupported or if the kernel is explicitly configured to run on the CPU (mode: 'cpu'), the behavior changes entirely:

  • Pure JavaScript Execution: The kernel executes as standard JavaScript inside a loop.
  • Type Coercion: A parameter with a value of null will be coerced to 0 in standard arithmetic operations (e.g., null + 5 equals 5).
  • NaN Propagation: A parameter with a value of undefined will resolve to NaN in numeric operations (e.g., undefined + 5 results in NaN).

This creates a significant divergence: a kernel that silently produces 0 or NaN in CPU mode may completely crash when running in GPU mode.

How to Safely Handle Missing Values

To avoid runtime exceptions and keep kernel behavior consistent across both CPU and GPU targets, always sanitize data before passing it into a kernel:

  • Use Sentinel Values: Substitute null or undefined with numeric placeholders, such as -1, 0, or Infinity, depending on your domain logic.
  • Use Dedicated Flags: If 0 is a valid calculation value, pass an accompanying boolean or integer flag (e.g., hasValue: 1 or 0) to conditionally branch inside the kernel.
  • Pre-validate Inputs: Implement a wrapper around the kernel call that checks parameter validity prior to dispatching work to the GPU pipeline.
