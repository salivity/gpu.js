Verlet Integration in GPU.js for Dynamic Simulations

This article outlines how to implement high-performance Verlet integration using gpu.js to simulate dynamic kinematic particle systems. By offloading numerical integration from the CPU to WebGL shaders via gpu.js, you can simulate thousands of interacting bodies in real time within the browser. The following sections break down the core mathematics of Verlet integration, the setup of parallel GPU kernels, and state management across animation frames.

Understanding Verlet Integration

Verlet integration is a numerical method used to integrate Newton's equations of motion. It is frequently preferred over Euler integration in dynamic simulations because it offers superior numerical stability and time reversibility.

The standard position Verlet formula computes the next position \(x_{t+\Delta t}\) using the current position \(x_t\), the previous position \(x_{t-\Delta t}\), and the current acceleration \(a_t\):

\[x_{t+\Delta t} = 2x_t - x_{t-\Delta t} + a_t \cdot \Delta t^2\]

With a velocity damping factor \(d\) (\(0 < d \le 1\)), the equation becomes:

\[x_{t+\Delta t} = x_t + (x_t - x_{t-\Delta t}) \cdot d + a_t \cdot \Delta t^2\]

Setting Up GPU.js

Install gpu.js in your project via npm or include it via CDN. Initialize the GPU context:

import { GPU } from 'gpu.js';

const gpu = new GPU();

Particle data is typically flattened into contiguous 1D or 2D typed arrays to optimize data transfer between CPU memory and GPU textures. For a 2D simulation with \(N\) particles, each array contains \(N \times 2\) elements representing alternating \(x\) and \(y\) components.

Writing the Verlet Integration Kernel

In gpu.js, a kernel executes simultaneously across all parallel threads defined by its output dimensions. The integration kernel takes current positions, previous positions, accelerations, time step size (\(\Delta t\)), and damping as inputs, returning the newly computed positions.

const updateParticlesKernel = gpu.createKernel(function(currentPos, previousPos, accel, dt, damping) {
    const i = this.thread.x;
    
    const current = currentPos[i];
    const previous = previousPos[i];
    const a = accel[i];
    
    // Position Verlet step: x_next = x + (x - x_prev) * damping + a * dt^2
    const next = current + (current - previous) * damping + a * (dt * dt);
    
    return next;
})
.setOutput([NUM_PARTICLES * 2])
.setPipeline(true); // Keeps output on GPU as a texture for continuous calculations

Using .setPipeline(true) prevents costly readbacks from GPU memory to CPU memory after every frame.

Simulation Loop and State Management

A kinematic simulation relies on updating state step-by-step. In Verlet integration, state management requires tracking three states: previous, current, and next.

  1. Calculate Forces/Accelerations: Compute dynamic kinematic influences (such as gravity, wind, or constraints).
  2. Execute Kernel: Run the Verlet kernel to compute \(x_{next}\).
  3. Cycle Buffers (Ping-Pong): Shift \(x_{current}\) to \(x_{previous}\) and \(x_{next}\) to \(x_{current}\).
const NUM_PARTICLES = 10000;
const dt = 0.016; // ~60 FPS
const damping = 0.99;

// Flattened [x0, y0, x1, y1, ...]
let currentPos = new Float32Array(NUM_PARTICLES * 2);
let previousPos = new Float32Array(NUM_PARTICLES * 2);
let accelerations = new Float32Array(NUM_PARTICLES * 2);

// Initialize particle positions and initial velocity offsets
for (let i = 0; i < NUM_PARTICLES * 2; i += 2) {
    currentPos[i] = Math.random() * 800;     // X
    currentPos[i + 1] = Math.random() * 600; // Y
    
    previousPos[i] = currentPos[i];
    previousPos[i + 1] = currentPos[i + 1];
    
    accelerations[i] = 0.0;                  // Zero horizontal acceleration
    accelerations[i + 1] = 9.81;             // Gravity acting downward
}

function stepSimulation() {
    // Run GPU kernel
    const nextPosTexture = updateParticlesKernel(
        currentPos, 
        previousPos, 
        accelerations, 
        dt, 
        damping
    );

    // Update state references
    previousPos = currentPos;
    currentPos = nextPosTexture;

    requestAnimationFrame(stepSimulation);
}

stepSimulation();

Handling Boundary Constraints

Boundary conditions (such as walls or floor collisions) can be handled directly inside the integration kernel to avoid switching contexts back to the CPU:

const constrainedVerletKernel = gpu.createKernel(function(currentPos, previousPos, accel, dt, damping, width, height) {
    const i = this.thread.x;
    const isYAxis = i % 2 === 1;
    
    const current = currentPos[i];
    const previous = previousPos[i];
    const a = accel[i];
    
    let next = current + (current - previous) * damping + a * (dt * dt);
    
    // Boundary collision resolution
    const limit = isYAxis ? height : width;
    if (next < 0.0) {
        next = 0.0;
    } else if (next > limit) {
        next = limit;
    }
    
    return next;
}).setOutput([NUM_PARTICLES * 2]);

Executing both the motion integration and simple geometric collision checks inside the same gpu.js kernel minimizes memory overhead and maximizes parallel throughput.
