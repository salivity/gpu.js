Branch Divergence and If-Statements in gpu.js

In gpu.js, using if-else statements within compute kernels can severely reduce execution speed due to a hardware phenomenon known as branch divergence. Because gpu.js compiles JavaScript functions into WebGL shaders that run across massive arrays of parallel GPU threads, introducing conditional logic forces threads within the same execution group to serialize their workloads. This article explains the mechanics of branch divergence in gpu.js, outlines its measurable impact on kernel runtime, and provides strategies to minimize performance loss.

Understanding GPU Execution: The SIMT Model

Modern GPUs process computations using a Single Instruction, Multiple Threads (SIMT) architecture. Instead of managing threads independently like a multi-core CPU, a GPU schedules threads in fixed-size batches—typically 32 threads (known as a "warp" on NVIDIA hardware) or 64 threads (a "wavefront" on AMD hardware).

All threads in a single warp execute the exact same instruction at the exact same clock cycle, but each operates on different data elements.

The Mechanics of Branch Divergence

Branch divergence occurs when threads within the same warp evaluate a conditional statement (an if condition) differently.

For example, consider a kernel processing an array where even indices take the if branch and odd indices take the else branch:

const kernel = gpu.createKernel(function (data) {
  if (data[this.thread.x] > 0) {
    return this.thread.x * 2.0;
  } else {
    return this.thread.x * -2.0;
  }
}).setOutput([1024]);

Because adjacent threads share the same warp, the hardware cannot execute both branches simultaneously. To resolve this:

  1. The GPU disables (masks off) the threads where the condition evaluated to false while executing the if block.
  2. The GPU then reverses the mask, executing the else block for the remaining threads while idling the first group.

The Impact on Execution Speed

When branch divergence occurs in gpu.js, execution time transitions from being determined by the fastest path to the sum of all paths:

  • Additive Latency: The execution time of a divergent warp is roughly equal to the runtime of the if block plus the runtime of the else block (\(T_{\text{total}} \approx T_{\text{true}} + T_{\text{false}}\)).
  • Reduced Hardware Utilization: Half or more of the processing cores allocated to a warp remain idle during branch execution, cutting compute throughput significantly.
  • Nested Conditional Penalties: Nesting multiple if-else blocks compounds the divergence exponentially, forcing threads through numerous serialized passes and destroying GPU acceleration benefits.

If every thread in a warp evaluates the condition in the same direction (uniform branching), no divergence occurs, and performance remains high. The penalty only applies when threads within the same execution group disagree.

How to Mitigate Divergence in gpu.js

To preserve high throughput in gpu.js kernels, conditional logic should be avoided or refactored:

  • Arithmetic Replacement: Replace binary conditions with mathematical equivalents. Instead of branching to set values to zero, multiply results by zero or one using comparisons converted into numerical values.
  • Built-in Functions: Leverage GPU-friendly functions such as Math.min(), Math.max(), or GLSL-native equivalents like clamp() and step(), which are often implemented as single, branchless hardware instructions.
  • Data Pre-sorting: If conditional logic is unavoidable, pre-sort the input data on the CPU before passing it to the GPU. Grouping similar data together ensures that adjacent threads follow the same execution branch, eliminating divergence within warps.
