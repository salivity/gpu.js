GPU.js Draw Primitive for Fragment Rasterization

This article examines the underlying WebGL rendering mechanics of GPU.js, specifically detailing how the library maps general-purpose parallel computation onto the GPU graphics pipeline. It identifies the exact geometric draw primitive GPU.js employs to rasterize fragments across the compute viewport and explains why this approach is standard for WebGL-based GPGPU tasks.

The Primitive: gl.TRIANGLE_STRIP

To execute general-purpose computations via WebGL, GPU.js converts JavaScript code into GLSL fragment shaders. Because fragment shaders execute per fragment during rasterization, the library must draw geometry that completely covers the target output frame. To achieve this, GPU.js uses the gl.TRIANGLE_STRIP draw primitive.

How GPU.js Sets Up the Viewport

GPU.js renders a full-screen quad over the Normalized Device Coordinate (NDC) range from -1.0 to 1.0 on both the X and Y axes. The setup consists of the following steps:

  1. Vertex Buffer Definition: GPU.js defines a static array of four 2D vertex coordinates: 
    [-1, -1,   1, -1,  -1,  1,   1,  1]
  2. Buffer Binding: These four points represent the bottom-left, bottom-right, top-left, and top-right corners of the viewport space.
  3. Execution Call: During kernel execution, GPU.js calls: 
    gl.drawArrays(gl.TRIANGLE_STRIP, 0, 4);

Why gl.TRIANGLE_STRIP Is Used

A triangle strip constructs a continuous surface using shared vertices between consecutive triangles. Drawing four vertices with gl.TRIANGLE_STRIP creates two connected triangles that form a flat bounding rectangle (quad) covering the entire viewport:

  • The first three vertices ([-1, -1], [1, -1], [-1, 1]) form the first triangle.
  • The last three vertices ([1, -1], [-1, 1], [1, 1]) form the second triangle.

Using gl.TRIANGLE_STRIP requires only four vertices (8 floating-point values) to cover the entire render target. This eliminates the need for an index buffer or the redundant six vertices required by individual gl.TRIANGLES. Rasterizing this strip guarantees that every output texel in the target frame buffer corresponds directly to a single execution of the kernel's fragment shader.
