GPU.js Memory Alignment for Non-Multiple of 4 Outputs

This article explains how GPU.js manages memory alignment and data packing when kernel thread outputs are not multiples of four. Because WebGL fundamentally relies on four-channel (RGBA) framebuffers and textures for data transfer, managing irregular output dimensions requires specialized internal handling. GPU.js solves this by recalculating 2D texture dimensions, mapping linear thread indices within generated GLSL shaders, padding unused sub-pixel channels or boundary texels, and truncating the returned typed arrays during CPU readback.

WebGL 4-Channel Architectural Constraints

WebGL processes data primarily through textures formatted with four color channels: Red, Green, Blue, and Alpha (RGBA). When GPU.js compiles a JavaScript kernel into GLSL (OpenGL Shading Language), it binds an off-screen framebuffer backed by these textures to store computation results.

In hardware-accelerated graphic pipelines, standard memory fetches and vector operations (vec4) are optimized for 32-bit, four-component alignment (128 bits total). When a kernel's output shape is an arbitrary number that does not align with this four-element boundary—such as an array of 5, 13, or 23 elements—the GPU cannot natively write fractional texels. It must always write to full texels composed of four components.

2D Texture Dimension Fitting

When you define an output configuration such as output: [7], GPU.js determines the smallest 2D texture grid capable of holding the required number of outputs. Depending on whether pipeline mode or packed texture mode is enabled, GPU.js evaluates:

  1. Unpacked (Scalar) Mode: Each scalar output occupies an individual pixel, using one channel or all four channels (encoding single precision floats across RGBA). GPU.js calculates texture dimensions (\(W \times H\)) such that \(W \times H \ge \text{Total Threads}\). If the output count is prime or odd, the texture width and height are sized to rectangular bounds that exceed the total thread count, leaving trailing texels idle.
  2. Packed Mode: GPU.js packs up to four independent array elements into the four vector slots (R, G, B, A) of a single texel. If the total length \(N\) is not divisible by 4, the number of allocated texels is \(\lceil N / 4 \rceil\). The final texel contains between 1 and 3 valid elements, with the remaining components left unwritten or padded with dummy data.

Coordinate Translation and Bounds Checking in GLSL

GPU.js injects mathematical coordinate conversions directly into the compiled fragment shader to map the 2D hardware raster coordinate (gl_FragCoord.xy) back to your specified logical thread space (1D, 2D, or 3D).

When executing threads:

  • The shader computes a linearized index: \[\text{index} = \lfloor gl\_FragCoord.x \rfloor + \lfloor gl\_FragCoord.y \rfloor \times \text{textureWidth}\]
  • In packed mode, this linear index is further multiplied by 4 to address individual channel offsets (index * 4 + channelIndex).
  • If the calculated index meets or exceeds the user-configured thread bounds, the shader either suppresses the calculation, outputs zeroed components for inactive channels, or issues a discard command to prevent overwriting valid memory.

This ensures that threads outside the logical range do not perform out-of-bounds calculations or corrupt adjacent data blocks within the allocated WebGL texture.

CPU Readback and Memory Slicing

Once the kernel execution completes on the GPU, the data must be transferred back to the CPU via gl.readPixels(). WebGL transfers the entire allocated texture region as a contiguous block into a JavaScript typed array (such as Float32Array).

Because the allocated texture may contain padding to satisfy both the internal four-channel format and row-alignment constraints (like gl.pixelStorei(gl.PACK_ALIGNMENT, 4)):

  1. Raw Extraction: gl.readPixels() downloads the full rectangular buffer, including empty tail texels or unused channels.
  2. Buffer Truncation: GPU.js automatically cleans the memory on the CPU side before returning the result to the caller. It reads the logical dimensions specified in the kernel configuration and uses typed array slicing (Array.prototype.slice or subarray views) to strip away all trailing components and padding rows.
  3. Data Reshaping: If multi-dimensional outputs were specified (e.g., a \(3 \times 3\) matrix, totaling 9 elements), GPU.js reconstructs the nested JavaScript arrays using only the valid indices, effectively masking the GPU's internal 4-multiple alignment from the final output.
