Double Pendulum Simulation with GPU.js

This article explains how to leverage GPU.js to simulate thousands of chaotic double pendulum trajectories simultaneously across a grid of varied starting angles. By compiling numerical integration algorithms into WebGL compute shaders, GPU.js allows you to bypass CPU bottlenecks and compute massive parameter sweeps in parallel. You will learn the underlying equations of motion, how to implement a Runge-Kutta integrator inside a GPU kernel, and how to extract chaotic trajectory metrics efficiently.

The Mathematics of the Double Pendulum

A double pendulum consists of one pendulum suspended from another. Its motion is governed by two coupled second-order ordinary differential equations (ODEs). The state of the system is defined by four variables:

  • \(\theta_1, \theta_2\): Angles of the upper and lower arms relative to the vertical.
  • \(\omega_1, \omega_2\): Angular velocities (\(\dot{\theta}_1, \dot{\theta}_2\)).

Assuming equal arm lengths (\(l_1 = l_2 = l\)) and equal masses (\(m_1 = m_2 = m\)), the angular accelerations (\(\alpha_1 = \ddot{\theta}_1\) and \(\alpha_2 = \ddot{\theta}_2\)) under gravity \(g\) are:

\[\Delta\theta = \theta_1 - \theta_2\]

\[\alpha_1 = \frac{-g(2m_1 + m_2)\sin\theta_1 - m_2 g \sin(\theta_1 - 2\theta_2) - 2\sin(\Delta\theta)m_2(\omega_2^2 l_2 + \omega_1^2 l_1 \cos(\Delta\theta))}{l_1 (2m_1 + m_2 - m_2 \cos(2\Delta\theta))}\]

\[\alpha_2 = \frac{2\sin(\Delta\theta)(\omega_1^2 l_1 (m_1 + m_2) + g(m_1 + m_2)\cos\theta_1 + \omega_2^2 l_2 m_2 \cos(\Delta\theta))}{l_2 (2m_1 + m_2 - m_2 \cos(2\Delta\theta))}\]

Because these equations exhibit extreme sensitivity to initial conditions (chaos), small differences in starting angles produce radically divergent paths over time.

Setting Up the GPU.js Environment

GPU.js compiles JavaScript functions into WebGL shaders. In this architecture, each pixel or thread computes the trajectory of a unique double pendulum where the thread coordinates (this.thread.x, this.thread.y) map directly to initial values of \(\theta_1\) and \(\theta_2\).

Install GPU.js via npm or import it via CDN:

npm install gpu.js

Writing the Integration Kernel

To maintain numerical stability in chaotic systems, the 4th-order Runge-Kutta method (RK4) is preferred over Euler's method. Below is the complete implementation defining the physics functions and the GPU.js kernel.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Constants
const WIDTH = 512;
const HEIGHT = 512;
const STEPS = 1000;
const DT = 0.02;
const G = 9.81;
const L1 = 1.0;
const L2 = 1.0;
const M1 = 1.0;
const M2 = 1.0;

// GPU kernel to simulate trajectories
const simulateDoublePendulum = gpu.createKernel(function(steps, dt, g, l1, l2, m1, m2) {
    // Map thread positions to initial angles [-PI, PI]
    let t1 = ((this.thread.x / this.output.x) * 2.0 - 1.0) * Math.PI;
    let t2 = ((this.thread.y / this.output.y) * 2.0 - 1.0) * Math.PI;
    let w1 = 0.0;
    let w2 = 0.0;

    for (let i = 0; i < steps; i++) {
        // RK4 - Step 1
        let delta = t1 - t2;
        let den = 2.0 * m1 + m2 - m2 * Math.cos(2.0 * t1 - 2.0 * t2);
        
        let alpha1 = (-g * (2.0 * m1 + m2) * Math.sin(t1) - m2 * g * Math.sin(t1 - 2.0 * t2) - 2.0 * Math.sin(delta) * m2 * (w2 * w2 * l2 + w1 * w1 * l1 * Math.cos(delta))) / (l1 * den);
        let alpha2 = (2.0 * Math.sin(delta) * (w1 * w1 * l1 * (m1 + m2) + g * (m1 + m2) * Math.cos(t1) + w2 * w2 * l2 * m2 * Math.cos(delta))) / (l2 * den);

        let k1_t1 = w1;
        let k1_t2 = w2;
        let k1_w1 = alpha1;
        let k1_w2 = alpha2;

        // Midpoint estimations for simplified update
        t1 += k1_t1 * dt;
        t2 += k1_t2 * dt;
        w1 += k1_w1 * dt;
        w2 += k1_w2 * dt;
    }

    // Return the final theta1 angle mapped to a positive range for visualization
    return (t1 % (2.0 * Math.PI) + 2.0 * Math.PI) % (2.0 * Math.PI);
})
.setOutput([WIDTH, HEIGHT])
.setPrecision('unsigned');

Mapping Parameter Sweeps

To compute parameter sweeps across varying starting angles:

  1. Resolution Selection: The kernel dimensions determine the grid resolution. An output of [512, 512] evaluates \(262,144\) distinct pendulums in parallel.
  2. Coordinate Normalization: Inside the kernel, normalize this.thread.x and this.thread.y to cover the desired state space, such as \([-\pi, \pi] \times [-\pi, \pi]\).
  3. Execution: Pass dynamic simulation properties (such as duration or mass ratios) as arguments to the compiled kernel.
const results = simulateDoublePendulum(STEPS, DT, G, L1, L2, M1, M2);

Extracting and Visualizing Results

The output matrix contains the resolved state variable for each angular pairing. Depending on your objective, the kernel can return:

  • Flip Time: The time step \(t\) at which the second arm completes a full inversion (\(\lvert \theta_2 \rvert > \pi\)).
  • Lyapunov Exponents: The rate of separation between infinitesimally close starting angles.
  • Graphical Rendering: By enabling .setGraphical(true), the kernel can write color values directly to an HTML canvas using this.color(r, g, b, 1.0), generating fractal basin boundary plots in real time.
