Procedural Parallax Occlusion Mapping in GPU.js

This guide demonstrates how to implement Parallax Occlusion Mapping (POM) on procedural surfaces using GPU.js. By leveraging GPU.js to transpile JavaScript functions into WebGL shaders, you can calculate per-pixel ray-marched depth displacements directly on the GPU without external image textures. You will learn how to define an analytical procedural height function, march view rays through the virtual displacement layer, find the accurate surface intersection via linear interpolation, and render the resulting relief with dynamic shading.

Understanding Parallax Occlusion Mapping

Parallax Occlusion Mapping is an enhancement of bump mapping and parallax mapping that traces a view vector through an apparent height field. Instead of shifting texture coordinates based on a single height sample, POM marches along the view ray across multiple layers until it determines that the ray has intersected the geometry. It then performs an interpolation step between the layer before the collision and the layer after the collision to find the precise intersection point, producing accurate self-occlusion, motion parallax, and depth perception on flat surfaces.

When working procedurally, the height value is computed mathematically within the shader on demand rather than sampled from a pre-baked texture.

1. Setting Up GPU.js

GPU.js allows you to write high-performance compute kernels using a subset of JavaScript syntax. First, instantiate your GPU context and configure it to output to a canvas.

const gpu = new GPU({
  mode: 'webgl2' // WebGL2 provides better loop and precision handling
});

2. Defining the Procedural Height Function

Because GPU.js compiles functions into GLSL, procedural generation functions must use standard math operations compatible with GPU.js. You can register custom functions using gpu.addFunction.

Below is a procedural height function using layered sinusoidal functions:

gpu.addFunction(function getProceduralHeight(u, v) {
  let scale = 10.0;
  let x = u * scale;
  let y = v * scale;
  
  // Layered wave functions simulating a bumpy surface
  let h1 = Math.sin(x) * Math.cos(y);
  let h2 = Math.sin(x * 2.0 + y) * 0.5;
  let h3 = Math.cos(y * 3.0 - x) * 0.25;
  
  // Normalize result between 0.0 and 1.0
  let total = (h1 + h2 + h3) / 1.75;
  return (total + 1.0) * 0.5;
});

3. Calculating Procedural Normals

To light the displaced surface, compute surface normals at the intersection point using finite differences:

gpu.addFunction(function getProceduralNormal(u, v, eps) {
  let hL = getProceduralHeight(u - eps, v);
  let hR = getProceduralHeight(u + eps, v);
  let hD = getProceduralHeight(u, v - eps);
  let hU = getProceduralHeight(u, v + eps);

  // Normal approximation from gradient
  let nx = hL - hR;
  let ny = hD - hU;
  let nz = 2.0 * eps;

  let len = Math.sqrt(nx * nx + ny * ny + nz * nz);
  return [nx / len, ny / len, nz / len];
});

4. Writing the POM Ray-Marching Kernel

The core POM logic samples the procedural height along the view ray. In a full 3D pipeline, calculations occur in tangent space; in a direct screen-space compute kernel, we simulate a fixed or variable view angle directly across normalized UV coordinates.

const renderPOM = gpu.createKernel(function(viewDirX, viewDirY, viewDirZ, lightDirX, lightDirY, lightDirZ, heightScale) {
  // Normalize UV coordinates [0, 1]
  let u = this.thread.x / this.output.x;
  let v = this.thread.y / this.output.y;

  // Configuration for POM quality
  let minLayers = 8.0;
  let maxLayers = 32.0;
  
  // Dynamically scale sample count based on viewing angle
  let numLayers = minLayers + (maxLayers - minLayers) * Math.abs(viewDirZ);
  let layerDepth = 1.0 / numLayers;
  
  // Ray step displacement vector
  let deltaUV_X = (viewDirX / viewDirZ) * heightScale / numLayers;
  let deltaUV_Y = (viewDirY / viewDirZ) * heightScale / numLayers;

  let currentUV_X = u;
  let currentUV_Y = v;
  let currentLayerDepth = 0.0;
  let currentHeight = 1.0 - getProceduralHeight(currentUV_X, currentUV_Y);

  // Linear search along the ray
  while (currentLayerDepth < currentHeight) {
    currentUV_X -= deltaUV_X;
    currentUV_Y -= deltaUV_Y;
    currentHeight = 1.0 - getProceduralHeight(currentUV_X, currentUV_Y);
    currentLayerDepth += layerDepth;
  }

  // Linear interpolation for exact intersection
  let prevUV_X = currentUV_X + deltaUV_X;
  let prevUV_Y = currentUV_Y + deltaUV_Y;
  let prevLayerDepth = currentLayerDepth - layerDepth;
  let prevHeight = 1.0 - getProceduralHeight(prevUV_X, prevUV_Y);

  let afterDepth = currentHeight - currentLayerDepth;
  let beforeDepth = prevHeight - prevLayerDepth;
  let weight = afterDepth / (afterDepth - beforeDepth);

  let finalU = prevUV_X * weight + currentUV_X * (1.0 - weight);
  let finalV = prevUV_Y * weight + currentUV_Y * (1.0 - weight);

  // Compute normal at the displaced coordinate
  let normal = getProceduralNormal(finalU, finalV, 0.005);
  
  // Diffuse Lambertian Lighting
  let diffuse = normal[0] * lightDirX + normal[1] * lightDirY + normal[2] * lightDirZ;
  if (diffuse < 0.0) diffuse = 0.0;
  
  let ambient = 0.1;
  let finalColor = diffuse + ambient;

  this.color(finalColor, finalColor, finalColor, 1.0);
})
.setOutput([512, 512])
.setGraphical(true);

5. Execution and Rendering

To display the procedural POM effect, initialize normalized view and light vectors and execute the kernel on a render loop:

document.body.appendChild(renderPOM.canvas);

function render() {
  // Example view direction (looking down and slightly angled)
  let vx = 0.3, vy = 0.3, vz = 0.9;
  let vLen = Math.sqrt(vx * vx + vy * vy + vz * vz);

  // Example light direction
  let lx = 0.5, ly = 0.5, lz = 0.7;
  let lLen = Math.sqrt(lx * lx + ly * ly + lz * lz);

  let heightScale = 0.08;

  renderPOM(
    vx / vLen, vy / vLen, vz / vLen,
    lx / lLen, ly / lLen, lz / lLen,
    heightScale
  );

  requestAnimationFrame(render);
}

render();

Performance Considerations

  1. Layer Count Tuning: Set the minimum and maximum step counts carefully. Because procedural functions recompute mathematical expressions at every step instead of reading a cached texture memory fetch, excessive iterations rapidly degrade frame rates.
  2. Mathematical Complexity: Keep the procedural height function computationally lean. Transcendental operations (Math.sin, Math.cos, Math.pow) are hardware-accelerated, but cascading multiple octaves directly impacts ray-marching speed.
  3. Boundary Handling: If coordinates step outside the [0, 1] UV domain during steep viewing angles, clamp or wrap coordinates using modulo arithmetic (u % 1.0) to avoid edge artifacts.
