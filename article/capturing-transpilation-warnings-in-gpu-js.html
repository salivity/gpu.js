Capturing Transpilation Warnings in GPU.js

This guide explains how to configure and capture internal transpilation warnings generated when GPU.js converts JavaScript functions into WebGL-compatible GLSL code. By combining kernel-level debug configurations with standard stream redirection and explicit execution modes, developers can intercept compiler warnings, inspect generated shader code, and identify unsupported syntax before runtime failures occur.

Enabling Kernel Debug Mode

GPU.js does not expose a dedicated external logger object in its constructor; instead, it relies on an internal debug flag. Enabling debug: true forces the internal abstract syntax tree (AST) transpiler to output compilation details, warnings, and the final generated GLSL shader directly to the console.

You can enable debug mode globally on the GPU instance or individually per kernel:

const { GPU } = require('gpu.js');

// Global debug configuration
const gpu = new GPU({
  mode: 'gpu',
  debug: true
});

// Or per-kernel debug configuration
const kernel = gpu.createKernel(function(a, b) {
  return a[this.thread.x] + b[this.thread.x];
}, {
  output: [100],
  debug: true
});

When debug is active, GPU.js logs detailed compilation steps, including any AST transformations where standard JavaScript semantics cannot be mapped directly to GLSL types.

Intercepting console.warn for Transpilation Warnings

Because GPU.js emits transpilation notices and non-fatal compilation fallbacks through the standard console.warn interface, programmatic capture requires wrapping or intercepting the console stream during kernel compilation:

function compileWithWarningCapture(gpuInstance, kernelFunction, kernelOptions = {}) {
  const capturedWarnings = [];
  const originalWarn = console.warn;

  // Intercept warnings during AST transpilation
  console.warn = (...args) => {
    capturedWarnings.push(args.join(' '));
    originalWarn.apply(console, args);
  };

  let kernel;
  try {
    kernel = gpuInstance.createKernel(kernelFunction, {
      ...kernelOptions,
      debug: true
    });
    // Trigger build step to invoke transpilation
    kernel.build();
  } finally {
    // Restore standard console behavior
    console.warn = originalWarn;
  }

  return { kernel, warnings: capturedWarnings };
}

Preventing Silent CPU Fallbacks

By default, GPU.js operates with automatic fallback. If a function contains syntax that the transpiler cannot convert into GLSL (such as non-numeric operations or dynamic recursion), GPU.js may silently fall back to running the kernel on the CPU instead of halting.

To ensure compilation warnings and errors are not masked by silent fallbacks, explicitly enforce the target mode:

const gpu = new GPU({
  mode: 'gpu' // Restricts execution to WebGL; throws compile errors instead of falling back to CPU
});

Using mode: 'gpu' or mode: 'webgl' forces the compiler to raise explicit errors when it encounters untranspilable syntax, making it easier to log and debug kernel issues.

Inspecting Transpiled GLSL Code

To diagnose the underlying cause of transpilation warnings, you can extract and inspect the compiled GLSL shader directly from the kernel instance:

const kernel = gpu.createKernel(function(data) {
  return Math.sin(data[this.thread.x]);
}, { output: [64] });

// Calling toString() outputs the full generated GLSL source
const glslSource = kernel.toString();
console.log(glslSource);

Examining the emitted source alongside captured warnings reveals where variable coercions, precision changes, or unsupported JS constructs were modified during the transpilation pipeline.
