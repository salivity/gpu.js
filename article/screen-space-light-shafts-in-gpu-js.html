Screen-Space Light Shafts in gpu.js

Volumetric light shafts, commonly referred to as "god rays," can be successfully implemented in gpu.js by adapting the screen-space radial blur technique popularized by modern real-time rendering pipelines. By projecting a light source to 2D screen coordinates, masking out occluding geometry, and running a directional radial blur kernel over the occlusion texture, gpu.js can leverage WebGL acceleration to generate the ray scattering effect. While gpu.js is primarily a general-purpose GPU (GPGPU) library rather than a rendering engine, its ability to ingest HTML canvas elements or image textures and execute parallel pixel manipulation makes post-processing effects like radial blurs entirely feasible.

The Screen-Space Radial Blur Technique

The screen-space approximation of volumetric scattering works entirely in 2D post-processing, avoiding expensive 3D ray marching. The pipeline requires three fundamental phases:

  1. Occlusion Mapping: Generating a high-contrast buffer where the light source is rendered at full brightness and all foreground objects that block the light are rendered in solid black.
  2. Radial Blur Sampling: For every pixel on the screen, a ray is cast toward the light’s screen-space position \((x, y)\). Samples are gathered along this vector at fixed intervals, attenuated by decay and density parameters, and summed together.
  3. Compositing: The resulting blurred ray texture is additively blended over the primary color buffer of the rendered scene.

Implementing the Radial Blur in gpu.js

Because gpu.js compiles JavaScript functions into WebGL fragment shaders, the ray-casting algorithm can be written as a custom kernel operating on an input canvas or texture.

To achieve this in gpu.js, a kernel is created with graphical output enabled:

const gpu = new GPU();

const lightShaftKernel = gpu.createKernel(function(image, lightX, lightY, samples, density, decay, weight, exposure) {
    const px = this.thread.x;
    const py = this.thread.y;
    
    // Compute vector from current pixel to light position
    let deltaX = (px - lightX) * (1.0 / samples) * density;
    let deltaY = (py - lightY) * (1.0 / samples) * density;
    
    let curX = px;
    let curY = py;
    let illuminationDecay = 1.0;
    let totalColorR = 0.0;
    let totalColorG = 0.0;
    let totalColorB = 0.0;

    // Sample along the vector toward the light
    for (let i = 0; i < 100; i++) {
        if (i < samples) {
            curX -= deltaX;
            curY -= deltaY;

            // Sample from input image texture
            const pixel = image[Math.floor(curY)][Math.floor(curX)];
            
            totalColorR += pixel[0] * illuminationDecay * weight;
            totalColorG += pixel[1] * illuminationDecay * weight;
            totalColorB += pixel[2] * illuminationDecay * weight;

            illuminationDecay *= decay;
        }
    }

    this.color(
        totalColorR * exposure,
        totalColorG * exposure,
        totalColorB * exposure,
        1.0
    );
})
.setOutput([width, height])
.setGraphical(true);

Technical Considerations and Limitations

While functional, several architectural constraints of gpu.js require consideration when building screen-space effects:

  • Static Loop Bounds: WebGL 1.0 requires loops within shaders to possess static, compile-time unroll limits. In gpu.js, dynamic loop bounds must be simulated using a fixed maximum iteration count coupled with internal conditional breaks or checks.
  • Texture Filtering: Standard WebGL shaders apply hardware-accelerated bilinear filtering to smooth out radial blur artifacts. gpu.js reads discrete indices from textures, meaning undersampled radial steps can produce banding artifacts unless manual interpolation or high sample counts are implemented.
  • Pipeline Overhead: For real-time performance, the input to gpu.js must remain on the GPU. Supplying an HTMLCanvasElement or WebGL texture avoids severe CPU-to-GPU data transfer bottlenecks. If the base scene is rendered using Three.js or raw WebGL, feeding the render target directly into the gpu.js kernel ensures interactive frame rates.

By feeding a pre-pass occlusion canvas into a gpu.js kernel and using additive blending on the final render target, screen-space light shafts provide a lightweight, convincing volumetric lighting effect without requiring complex 3D ray marching.
