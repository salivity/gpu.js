GPU.js Helper Function Argument and Return Types

GPU.js bridges the gap between JavaScript's dynamic typing and WebGL’s strictly typed shader language (GLSL) by analyzing, inferring, and explicitly defining data types in user-defined functions. When compiling JavaScript functions to run on the GPU, helper functions added via gpu.addFunction() must declare or implicitly resolve specific argument and return types so the underlying compiler can generate valid GLSL code. This article explains how GPU.js manages these types, how to define them explicitly, and best practices for avoiding compilation errors.

The Underlying Challenge: JS to GLSL Translation

JavaScript does not require type annotations, but GPUs execute static shader code where every variable, parameter, and return value must have a fixed type (such as float, int, or vector arrays). When you write a helper function, GPU.js parses its Abstract Syntax Tree (AST) to translate JavaScript operations into equivalent GLSL operations. Because ambiguity can lead to invalid shaders, GPU.js must know the exact type of each input parameter and the output.

Explicit Type Declaration with gpu.addFunction()

The most reliable way GPU.js handles types in helper functions is through explicit definition in the options object passed to gpu.addFunction(). You provide an object mapping argument names to their respective types, along with a specified returnType.

function addVectors(a, b) {
  return a + b;
}

gpu.addFunction(addVectors, {
  argumentTypes: { a: 'Float', b: 'Float' },
  returnType: 'Float'
});

When defined explicitly, the transpiler skips guessing and directly maps the parameters to native shader types:

  • 'Float' maps to float
  • 'Integer' maps to int
  • 'Boolean' maps to bool
  • 'Array' or 'Array(n)' maps to fixed-size arrays or GLSL vectors (such as vec2, vec3, vec4)

Automatic Type Inference

If you register a helper function without specifying argumentTypes or returnType, GPU.js attempts automatic type inference:

  1. Call-Site Inspection: GPU.js inspects the calling kernel. If the kernel passes a variable known to be a float into the helper function, GPU.js assumes the corresponding parameter is a Float.
  2. AST Evaluation: The compiler tracks mathematical operations and literal values within the helper function body. For example, expressions containing decimal numbers (e.g., 1.0) hint at floating-point arithmetic.
  3. Return Inference: The resolved types inside the function dictate the inferred returnType.

While convenient, type inference can easily fail in complex logic, loops, or when a helper function is called with different types across separate kernels. For production code, relying on automatic inference is discouraged.

Handling Arrays and Vectors

When dealing with multi-dimensional data, helper functions require precise array sizing in their signatures. GPU.js handles array arguments and returns by matching them to GLSL vectors or arrays:

function getMagnitude(vec) {
  return Math.sqrt(vec[0] * vec[0] + vec[1] * vec[1]);
}

gpu.addFunction(getMagnitude, {
  argumentTypes: { vec: 'Array(2)' },
  returnType: 'Float'
});

Specifying the length via Array(length) allows GPU.js to allocate the correct vector type in memory. Returning arrays requires matching dimensions; helper functions cannot return dynamically sized arrays.

Strict Typing Rules and Limitations

To ensure smooth compilation, user-defined helper functions must adhere to strict typing constraints:

  • Single Return Type: A function cannot conditionally return different types (e.g., returning an Integer in one branch and a Float in another). Every exit path must resolve to the identical declared type.
  • No Implicit Type Coercion: Unlike standard JavaScript, which freely converts numbers to strings or floats to ints, GPU.js expects matched types in binary operations within the helper. Adding an integer directly to a float without explicit casting can trigger compilation failures.
  • No Object Types: Complex JavaScript objects, closures, or class instances cannot be passed as arguments or returned from helper functions. Only primitives and fixed-size arrays are supported.
