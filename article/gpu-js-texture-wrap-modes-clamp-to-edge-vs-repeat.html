GPU.js Texture Wrap Modes: CLAMP_TO_EDGE vs REPEAT

In gpu.js, texture wrap modes define how the underlying WebGL context handles texture coordinates that fall outside the normalized range of zero to one. Because gpu.js translates JavaScript functions into GLSL shaders for general-purpose GPU computing, it manages data buffers as textures behind the scenes. By default, gpu.js enforces CLAMP_TO_EDGE across its texture-handling pipelines to accommodate arbitrary, non-power-of-two array dimensions and prevent out-of-bounds sampling errors, while wrapping behaviors like REPEAT must typically be handled manually at the kernel logic level.

The Underlying WebGL Texture Setup

gpu.js operates by converting input arrays, matrices, and numeric data into WebGL textures. When initializing these textures in the WebGL context, the library explicitly sets texture wrapping parameters:

  • TEXTURE_WRAP_S: The horizontal wrapping mode.
  • TEXTURE_WRAP_T: The vertical wrapping mode.

In standard WebGL implementations, especially WebGL 1.0, textures that have non-power-of-two (NPOT) dimensions are strictly required to use CLAMP_TO_EDGE for both TEXTURE_WRAP_S and TEXTURE_WRAP_T. NPOT textures in WebGL 1 cannot use REPEAT or MIRRORED_REPEAT without generating WebGL errors or rendering black textures. Because arbitrary data matrices (such as a 500x300 array) rarely have power-of-two dimensions (like 256x256 or 512x512), gpu.js standardizes on CLAMP_TO_EDGE.

How CLAMP_TO_EDGE Operates

Under CLAMP_TO_EDGE, any texture read that attempts to sample coordinates beyond the bounds of the texture will be clamped to the nearest edge pixel value.

  • If an index calculates a coordinate less than 0.0, it reads from 0.0.
  • If an index calculates a coordinate greater than 1.0, it reads from 1.0.

In gpu.js, when data is passed between kernels as texture outputs using pipeline: true, the resulting Texture object retains these parameters. The memory addresses of the matrix edges are preserved, preventing artifacts or undefined reads when sampling data close to the matrix perimeter.

The Absence of Native REPEAT Support

The REPEAT wrap mode causes a texture to tile infinitely by ignoring the integer component of a texture coordinate and only reading the fractional component (effectively wrapping coordinates greater than 1.0 back to 0.0).

gpu.js does not expose high-level kernel configuration flags to switch the internal texture sampler state to gl.REPEAT. This design choice prevents pipeline breakage when working across mixed WebGL 1, WebGL 2, and headless environments where dimension requirements vary.

Simulating REPEAT Within Kernels

Because native REPEAT configuration is restricted by the library's internal WebGL setup, periodic or repeating texture access must be implemented algorithmically within the kernel function. Developers can simulate wrap-around behavior by using modulo arithmetic on thread indices:

const gpu = new GPU();

const repeatingKernel = gpu.createKernel(function(sourceMatrix, sourceWidth, sourceHeight) {
    // Manually wrap the coordinates using the modulo operator
    const wrappedX = this.thread.x % sourceWidth;
    const wrappedY = this.thread.y % sourceHeight;

    return sourceMatrix[wrappedY][wrappedX];
}).setOutput([1024, 1024]);

By computing the index using the modulo of the source dimensions, memory accesses remain strictly within the bounds of the underlying texture, emulating REPEAT behavior while maintaining compatibility with gpu.js's native CLAMP_TO_EDGE texture configurations.
