LSTM Gating Mechanisms with GPU.js Matrix Kernels

This article provides a technical guide on implementing the gating mechanism of a Long Short-Term Memory (LSTM) cell using GPU-accelerated matrix operations in gpu.js. It details the mathematical formulation of LSTM gates, demonstrates how to pack linear transformations into a single general matrix multiplication (GEMM) kernel to minimize GPU dispatch overhead, and provides functional WebGL kernel implementations for computing gate activations, cell state transitions, and hidden state outputs entirely on the GPU.

Mathematical Breakdown of LSTM Gates

An LSTM cell uses gating mechanisms to regulate the flow of information across time steps. Given input vector \(x_t\), previous hidden state \(h_{t-1}\), and previous cell state \(C_{t-1}\), the cell calculates four internal vectors:

  1. Forget Gate (\(f_t\)): \(f_t = \sigma(W_f x_t + U_f h_{t-1} + b_f)\)
  2. Input Gate (\(i_t\)): \(i_t = \sigma(W_i x_t + U_i h_{t-1} + b_i)\)
  3. Candidate Cell State (\(\tilde{C}_t\)): \(\tilde{C}_t = \tanh(W_c x_t + U_c h_{t-1} + b_c)\)
  4. Output Gate (\(o_t\)): \(o_t = \sigma(W_o x_t + U_o h_{t-1} + b_o)\)

Where \(\sigma(z) = \frac{1}{1 + e^{-z}}\) and \(\tanh(z) = \frac{e^z - e^{-z}}{e^z + e^{-z}}\).

The states are updated according to:

  • Cell State (\(C_t\)): \(C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t\)
  • Hidden State (\(h_t\)): \(h_t = o_t \odot \tanh(C_t)\)

Optimizing via Kernel Fused Linear Projection

Executing individual matrix multiplications for each of the four gates causes memory transfer bottlenecks and kernel dispatch overhead. To maximize GPU parallelization in gpu.js, concatenate the input weights, recurrent weights, and biases:

  • Combined Weight Matrix: \(W_{gate} \in \mathbb{R}^{4D \times M}\)
  • Combined Recurrent Matrix: \(U_{gate} \in \mathbb{R}^{4D \times D}\)
  • Combined Bias Vector: \(b_{gate} \in \mathbb{R}^{4D}\)

Where \(M\) is the input feature dimension and \(D\) is the hidden state dimension. The pre-activations for all four gates can be computed in a single kernel execution:

\[Z = W_{gate} x_t + U_{gate} h_{t-1} + b_{gate}\]

The resulting vector \(Z\) of length \(4D\) is partitioned into four contiguous blocks of size \(D\):

  • Indices \([0, D-1]\): Forget pre-activation
  • Indices \([D, 2D-1]\): Input pre-activation
  • Indices \([2D, 3D-1]\): Candidate pre-activation
  • Indices \([3D, 4D-1]\): Output pre-activation

Step 1: Linear Transformation Kernel

The following gpu.js kernel computes the combined matrix-vector products and adds the bias term:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const createLSTMLinearKernel = (hiddenDim, inputDim) => {
  return gpu.createKernel(function(W, U, x, h, b) {
    let sum = b[this.thread.x];

    // Compute W * x
    for (let i = 0; i < this.constants.inputDim; i++) {
      sum += W[this.thread.x][i] * x[i];
    }

    // Compute U * h
    for (let j = 0; j < this.constants.hiddenDim; j++) {
      sum += U[this.thread.x][j] * h[j];
    }

    return sum;
  }, {
    constants: { inputDim, hiddenDim },
    output: [4 * hiddenDim],
    pipeline: true // Keeps output in WebGL texture memory
  });
};

Step 2: Activation and State Update Kernel

Once the concatenated pre-activations vector \(Z\) is calculated, a second kernel computes the non-linear activations (\(\sigma\) and \(\tanh\)), performs element-wise operations with the historical cell state \(C_{t-1}\), and outputs the updated states \(C_t\) and \(h_t\).

Because gpu.js kernels return a single matrix or vector per execution, we evaluate \(C_t\) and \(h_t\) as a \(2 \times D\) output array, where row 0 is \(C_t\) and row 1 is \(h_t\):

const createLSTMStateKernel = (hiddenDim) => {
  return gpu.createKernel(function(Z, C_prev) {
    const d = this.thread.x;
    const hiddenDim = this.constants.hiddenDim;

    // Pre-activations from concatenated vector Z
    const z_f = Z[d];
    const z_i = Z[d + hiddenDim];
    const z_c = Z[d + 2 * hiddenDim];
    const z_o = Z[d + 3 * hiddenDim];

    // Compute non-linearities
    const f = 1.0 / (1.0 + Math.exp(-z_f));
    const i = 1.0 / (1.0 + Math.exp(-z_i));
    const c_tilde = Math.tanh(z_c);
    const o = 1.0 / (1.0 + Math.exp(-z_o));

    // Update cell state
    const c_t = (f * C_prev[d]) + (i * c_tilde);

    // Row 0: Cell State (C_t)
    if (this.thread.y === 0) {
      return c_t;
    }

    // Row 1: Hidden State (h_t)
    return o * Math.tanh(c_t);
  }, {
    constants: { hiddenDim },
    output: [hiddenDim, 2],
    pipeline: true
  });
};

Step 3: Slicing the States for Subsequent Steps

To feed \(h_t\) and \(C_t\) into the next recurrent time step without pulling data back to the CPU, a helper kernel splits the \(2 \times D\) texture back into two 1D textures:

const createExtractRowKernel = (hiddenDim) => {
  return gpu.createKernel(function(statesMatrix, rowIndex) {
    return statesMatrix[rowIndex][this.thread.x];
  }, {
    output: [hiddenDim],
    pipeline: true
  });
};

Step 4: Full Step Execution Pipeline

Combining these kernels maintains intermediate tensors in GPU texture memory throughout the step:

const hiddenDim = 128;
const inputDim = 64;

// Initialize kernels
const linearKernel = createLSTMLinearKernel(hiddenDim, inputDim);
const stateKernel = createLSTMStateKernel(hiddenDim);
const extractRow = createExtractRowKernel(hiddenDim);

function lstmStep(x_t, h_prev, C_prev, W_gate, U_gate, b_gate) {
  // 1. Compute pre-activations on GPU
  const Z = linearKernel(W_gate, U_gate, x_t, h_prev, b_gate);

  // 2. Compute non-linearities and combined state matrix [C_t, h_t]
  const states = stateKernel(Z, C_prev);

  // 3. Extract separate states for the next iteration
  const C_next = extractRow(states, 0);
  const h_next = extractRow(states, 1);

  return { C_next, h_next };
}

Setting pipeline: true ensures that matrix projections and element-wise gate modifications execute on the GPU hardware shaders sequentially without transferring intermediate arrays back to JavaScript runtime memory.
