Spatial Hashing for Particle Search in GPU.js

This article explains how to implement spatial hash grids to accelerate neighboring particle searches in GPU.js from an \(O(N^2)\) brute-force check to near \(O(N)\) complexity. You will learn the mechanics of mapping continuous coordinates into discrete buckets, navigating the limitations of WebGL-based fragment shaders, structuring memory textures for fast lookups, and writing the final neighbor-query kernel to handle physical interactions efficiently.

The Spatial Hashing Concept

Direct pairwise distance calculations across \(N\) particles require \(N^2\) operations, quickly overwhelming the GPU when simulating thousands of elements. A spatial hash grid divides continuous simulation space into a uniform grid of cells, where each cell's dimension equals or slightly exceeds the maximum interaction radius \(R\).

Particles only interact with other particles residing in their immediate cell or directly adjacent neighboring cells (9 cells in 2D, 27 cells in 3D). By indexing particles into these spatial bins, the search space is limited to a bounded local subset.

Managing GPU.js Constraints

GPU.js compiles JavaScript functions into WebGL fragment shaders. Because fragment shaders execute concurrently and lack atomic write operations (scatter operations) in standard configurations, particles cannot arbitrarily push their IDs into dynamic cell arrays on the GPU without write conflicts.

To manage this within GPU.js, use one of two architectures:

  1. CPU Binning with GPU Search: The CPU computes cell assignments, sorts the particle indices, and packs a fixed-size texture passed as an input to GPU.js.
  2. Fixed-Capacity Grid Matrix on GPU: Each grid cell is represented by a pre-allocated fixed-length slot array (e.g., up to \(M\) particles per cell) to avoid race conditions and dynamic memory allocation.

For maximum throughput entirely within the GPU pipeline, the fixed-capacity texture approach avoids the costly CPU-to-GPU bandwidth bottleneck.

Step 1: Mapping Coordinates to Grid Cells

Map a particle’s continuous position to a 2D or 3D integer coordinate, and then flatten that coordinate into a single hash key.

function getCellX(posX, cellSize) {
  return Math.floor(posX / cellSize);
}

function getCellY(posY, cellSize) {
  return Math.floor(posY / cellSize);
}

function hashCell(cx, cy, gridWidth) {
  return cy * gridWidth + cx;
}

Ensure cellSize matches the maximum search radius. Making cells smaller requires checking more adjacent rings, while making them larger introduces false positives that slow down distance checks.

Step 2: Populating the Grid Texture

Represent the spatial grid as a 2D texture. Each row represents a grid cell ID, and each column contains the index of a particle residing within that cell.

To initialize this in GPU.js without atomic writes, compute a multi-pass structure:

  1. Cell Count Pass: Count how many particles fall into each cell.
  2. Cell Offset Pass: Create a prefix-sum array determining the start index of each cell in a contiguous sorted particle list.
  3. Particle Sorting Pass: Reorder the particle buffer so particles within the same cell reside contiguously in memory.

If using a hybrid loop where particle count is moderate (e.g., under 50,000), construct the contiguous cell lookup table on the CPU and upload it as a 2D array:

const grid = new Int32Array(totalCells * maxParticlesPerCell).fill(-1);
const cellCounters = new Int32Array(totalCells).fill(0);

for (let i = 0; i < particleCount; i++) {
  const cx = Math.floor(positions[i * 2] / cellSize);
  const cy = Math.floor(positions[i * 2 + 1] / cellSize);
  const cellId = cy * gridWidth + cx;

  const count = cellCounters[cellId];
  if (count < maxParticlesPerCell) {
    grid[cellId * maxParticlesPerCell + count] = i;
    cellCounters[cellId]++;
  }
}

Step 3: Executing the Neighbor Search Kernel

The GPU.js kernel processes each particle in parallel, reads its position, identifies the surrounding grid cells, and evaluates only the particles stored in those specific cells.

const gpu = new GPU();

const computeForces = gpu.createKernel(function(positions, grid, gridWidth, gridHeight, cellSize, maxParticlesPerCell, searchRadius) {
  const i = this.thread.x;
  const px = positions[i * 2];
  const py = positions[i * 2 + 1];

  const cx = Math.floor(px / cellSize);
  const cy = Math.floor(py / cellSize);

  let forceX = 0;
  let forceY = 0;

  // Iterate over neighbor offsets: -1, 0, 1
  for (let ox = -1; ox <= 1; ox++) {
    for (let oy = -1; oy <= 1; oy++) {
      const neighborCellX = cx + ox;
      const neighborCellY = cy + oy;

      // Boundary check for grid dimensions
      if (neighborCellX >= 0 && neighborCellX < gridWidth && 
          neighborCellY >= 0 && neighborCellY < gridHeight) {
        
        const cellIndex = neighborCellY * gridWidth + neighborCellX;

        // Iterate through particles assigned to this cell
        for (let slot = 0; slot < maxParticlesPerCell; slot++) {
          const neighborIndex = grid[cellIndex * maxParticlesPerCell + slot];

          if (neighborIndex !== -1 && neighborIndex !== i) {
            const nx = positions[neighborIndex * 2];
            const ny = positions[neighborIndex * 2 + 1];

            const dx = nx - px;
            const dy = ny - py;
            const distSq = dx * dx + dy * dy;

            if (distSq < searchRadius * searchRadius && distSq > 0.0001) {
              const dist = Math.sqrt(distSq);
              // Accumulate forces (e.g., repulsion)
              forceX += (dx / dist) * (1.0 - dist / searchRadius);
              forceY += (dy / dist) * (1.0 - dist / searchRadius);
            }
          }
        }
      }
    }
  }

  return [forceX, forceY];
})
.setOutput([particleCount]);

Optimization Considerations

  • Loop Unrolling: Constant-size loops inside the kernel allow GPU.js to generate unrolled GLSL instructions, maximizing execution speed. Avoid non-deterministic loop conditions where possible.
  • Cell Size Tuning: Set cellSize strictly equal to searchRadius. Setting it smaller requires expanding the search to a \(5 \times 5\) cell neighborhood (25 lookups in 2D), which increases texture read overhead.
  • Memory Limits: Keep maxParticlesPerCell low enough to prevent wasted GPU memory, but high enough to avoid dropping particles during high-density clustering.
