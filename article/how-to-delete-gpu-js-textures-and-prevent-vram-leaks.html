How to Delete gpu.js Textures and Prevent VRAM Leaks

When processing data with gpu.js using pipelined kernels or texture outputs, GPU memory (VRAM) is not immediately reclaimed by JavaScript's garbage collector. To prevent application crashes and out-of-memory errors caused by VRAM leaks, you must explicitly call the .delete() method on unused texture instances. This guide explains how to properly dispose of gpu.js textures, safely manage memory within iterative loops, and completely tear down the GPU context.

Why VRAM Leaks Occur in gpu.js

When you configure a gpu.js kernel with pipeline: true or set its output mode to return a texture, the calculation stays on the GPU as a WebGL texture rather than converting back to a JavaScript array on the CPU.

While the JavaScript runtime handles memory on the host system, it does not deterministically free underlying WebGL texture buffers on the graphics card when variables fall out of scope. If you overwrite or abandon texture references without deallocating them, the underlying WebGL textures persist in VRAM, steadily consuming memory until WebGL context loss occurs.

The Proper Method: texture.delete()

The correct and standard way to free a texture from VRAM is to invoke the built-in .delete() method on the returned texture object:

const myTexture = myKernel();

// Perform operations with myTexture...

// Free the VRAM allocated for this texture
myTexture.delete();

Calling .delete() invokes WebGL's native gl.deleteTexture() under the hood, instantly deallocating the memory from your graphics hardware.

Preventing Leaks in Iterative Loops

VRAM leaks most commonly occur inside loops or render cycles where a kernel executes repeatedly, generating a new texture on each iteration. In these scenarios, you must store the reference to the prior texture and delete it once the next step has completed.

const gpu = new GPU();

const stepKernel = gpu.createKernel(function(prevTexture) {
  return prevTexture[this.thread.y][this.thread.x] + 1;
})
.setOutput([512, 512])
.setPipeline(true);

let currentTexture = initialTexture;

for (let i = 0; i < 1000; i++) {
  // Generate the next texture state
  const nextTexture = stepKernel(currentTexture);

  // Delete the old texture to prevent VRAM accumulation
  currentTexture.delete();

  // Advance the reference
  currentTexture = nextTexture;
}

// Convert final result to a CPU array and clean up the final texture
const finalResult = currentTexture.toArray();
currentTexture.delete();

In this pattern, only the active textures necessary for calculation remain in memory at any given point, avoiding memory bloat.

Complete Context Cleanup with gpu.destroy()

If your application is unmounting a component, switching tasks, or shutting down entirely, deleting individual textures may not be sufficient. You should also destroy the root GPU instance:

gpu.destroy();

Calling gpu.destroy() cleans up all compiled kernels, releases any internally cached buffers, and loses the active WebGL context, returning all allocated GPU resources to the operating system.
