Set Custom Canvas Dimensions in GPU.js

In GPU.js, graphical kernels automatically bind their output array dimensions to the internal rendering buffer of the canvas element. This article explains how to set custom canvas dimensions that differ from your kernel output dimensions using CSS viewport scaling and offscreen canvas blitting techniques.

Understanding GPU.js Graphical Output

When creating a graphical kernel in GPU.js using the { graphical: true } setting, the kernel output defined via .setOutput([width, height]) directly overwrites the canvas rendering buffer dimensions (canvas.width and canvas.height). Because the kernel maps each thread to an individual pixel in the WebGL context, changing the internal pixel dimensions requires changing the kernel output.

To achieve differing canvas dimensions relative to computation size, you must decouple the internal buffer resolution from the visible display resolution.

Method 1: Decoupling Display Size via CSS Scaling

If you want the computation to run at a lower or higher resolution while the canvas element occupies a different size on the webpage, adjust the canvas element's CSS styling rather than its internal attributes.

const gpu = new GPU();

// 1. Define computation resolution (e.g., 200x200 for performance)
const render = gpu.createKernel(function() {
    this.color(this.thread.x / 200, this.thread.y / 200, 0.5, 1);
})
.setOutput([200, 200])
.setGraphical(true);

render();

// 2. Access the generated canvas
const canvas = render.canvas;
document.body.appendChild(canvas);

// 3. Set custom physical display dimensions
canvas.style.width = '800px';
canvas.style.height = '600px';
canvas.style.imageRendering = 'pixelated'; // Optional: prevents blur on upscaling

In this method:

  • The internal computation and render buffer remain 200x200.
  • The browser scales the visual output to 800x600.
  • The aspect ratio can be stretched or preserved based on the CSS rules applied.

Method 2: Offscreen Rendering to a Custom Buffer Canvas

If your application requires the actual canvas pixel buffer (canvas.width and canvas.height) to differ from the kernel computation grid without relying on CSS stretching, use an offscreen blit. This is essential when exporting data or integrating with other WebGL/2D pipelines.

// Target display canvas with custom dimensions
const displayCanvas = document.getElementById('my-canvas');
displayCanvas.width = 1920;
displayCanvas.height = 1080;
const ctx = displayCanvas.getContext('2d');

// GPU.js instance running at a different resolution
const gpu = new GPU();
const kernel = gpu.createKernel(function() {
    this.color(this.thread.x / 640, this.thread.y / 360, 0, 1);
})
.setOutput([640, 360])
.setGraphical(true);

function drawFrame() {
    // Run GPU kernel calculation
    kernel();

    // Draw the GPU output canvas onto the target canvas
    ctx.drawImage(
        kernel.canvas, 
        0, 0, 640, 360,           // Source bounds
        0, 0, displayCanvas.width, displayCanvas.height // Destination bounds
    );
}

drawFrame();

Passing a Pre-existing Canvas

You can pass a pre-existing canvas into the GPU instance via the constructor:

const customCanvas = document.createElement('canvas');
const gpu = new GPU({ canvas: customCanvas });

When using a graphical kernel with an existing canvas, kernel.setOutput([width, height]) will still overwrite customCanvas.width and customCanvas.height to match the output array. To maintain distinct dimensions, apply Method 1 (CSS properties) or Method 2 (2D blitting) depending on whether you need visual scaling or a distinct pixel buffer.
