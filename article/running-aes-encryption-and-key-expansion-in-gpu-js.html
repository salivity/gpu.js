Running AES Encryption and Key Expansion in gpu.js

This article examines whether the Advanced Encryption Standard (AES), specifically key expansion and round transformations, can be executed using the gpu.js library. It breaks down the mathematical and architectural requirements of AES, maps them to the capabilities and limitations of gpu.js, and evaluates the practicality of performing hardware-accelerated symmetric cryptography inside a browser or Node.js environment.

Feasibility Overview

AES key expansion and round transformations can both be executed using gpu.js. Because gpu.js transpiles a constrained subset of JavaScript into WebGL or WebGPU compute shaders, it can execute the matrix operations, substitutions, and bitwise arithmetic required by AES. However, the architectural fit differs significantly between key expansion and round transformations due to how data parallelism operates on graphics hardware.

Executing AES Key Expansion in gpu.js

Key expansion transforms a 128-, 192-, or 256-bit cipher key into a series of round keys using rotational shifts, S-box byte substitutions (SubWord), and XOR operations with round constants (Rcon).

  • Single-Key Scenarios: For standard single-message encryption, computing key expansion on the GPU is inefficient. Key expansion is inherently sequential; round key \(i\) directly depends on round key \(i-1\). GPUs excel at data parallelism (SIMD), not recursive, single-thread sequential tasks. The overhead of compiling the kernel and transferring data between CPU and GPU memory outweighs any computational benefit. In standard implementations, key expansion should be handled on the CPU before passing the generated round keys to the GPU.
  • Multi-Key Scenarios: If you are performing parallel operations across millions of distinct keys (such as in cryptanalysis, brute-force testing, or high-throughput batch generation), key expansion maps exceptionally well to gpu.js. Each GPU thread can independently expand a distinct key in parallel.

Executing AES Round Transformations in gpu.js

AES round transformations process a 4x4 array of bytes (the State) through four primary operations: SubBytes, ShiftRows, MixColumns, and AddRoundKey. These operations map cleanly to gpu.js kernels:

  1. SubBytes: Implemented either as a lookup table (LUT) stored in a texture array or calculated dynamically via Galois Field \(\text{GF}(2^8)\) inversion. A static 256-byte substitution array passed into the kernel provides constant-time lookup performance.
  2. ShiftRows: A cyclical byte permutation that requires simple array indexing offsets, easily resolved in parallel across all blocks.
  3. MixColumns: A matrix multiplication over \(\text{GF}(2^8)\) where each column of four bytes is transformed. This can be implemented in gpu.js using conditional bit-shifts (xtimes multiplication) or precomputed multiplication tables.
  4. AddRoundKey: A standard bitwise XOR operation between the state matrix and the corresponding round key.

Because round transformations operate independently on individual 16-byte blocks, parallel modes of operation such as CTR (Counter) or ECB (Electronic Codebook) achieve massive throughput on the GPU. Modes with serial dependencies, such as CBC (Cipher Block Chaining) during encryption, cannot be parallelized across blocks.

Technical Limitations in gpu.js

While functional, implementing AES in gpu.js requires managing several library-specific constraints:

  • Bitwise Operator Requirements: AES relies heavily on bitwise operations (^, &, <<, >>). WebGL 1 does not natively support integer bitwise operations, forcing them to be emulated mathematically with floating-point calculations, which introduces severe performance penalties. To run AES efficiently, gpu.js must operate in WebGL 2 mode, which natively supports 32-bit signed and unsigned integers and bitwise operators.
  • Data Representation: gpu.js processes outputs as textures (usually floating-point or integer vectors). Bytes must be packed into 32-bit integers or mapped across RGBA channels to maximize memory bandwidth and avoid excessive memory overhead.
  • Data Transfer Bottlenecks: Passing small payloads to the GPU creates PCIe bus bottlenecks. gpu.js only delivers a performance advantage over native CPU implementations (like Web Crypto API or Node.js crypto) when encrypting very large contiguous datasets or processing thousands of independent blocks concurrently.
