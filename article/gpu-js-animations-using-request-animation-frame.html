GPU.js Animations Using requestAnimationFrame

You can build high-performance, interactive animations in the browser by executing a graphical GPU.js kernel inside a requestAnimationFrame loop. By configuring GPU.js to output directly to an HTML5 canvas via WebGL shaders, you can calculate millions of pixels in parallel on each frame while binding user inputs—such as mouse coordinates and clicks—directly to the execution cycle. This approach provides a massive performance boost over standard 2D canvas drawing when rendering complex mathematics, procedural textures, particle fields, or cellular automata.

How Graphical GPU.js Kernels Work

GPU.js typically transpiles JavaScript functions into WebGL shaders to accelerate heavy mathematical calculations. When configured with the graphical: true setting, a kernel bypasses standard array data output and instead renders directly to an internal HTML <canvas> element using WebGL fragment shaders. Inside the kernel, you call this.color(r, g, b, a) to define the pixel color for each coordinate in the output matrix.

Setting Up the Animation Loop

To create an animation, you execute the compiled kernel recursively within a browser rendering loop managed by requestAnimationFrame. Instead of static values, you pass dynamic parameters—such as an incrementing time variable, elapsed delta time, and viewport dimensions—into the kernel on every frame.

Here is the fundamental structure:

const gpu = new GPU();

// 1. Create a graphical kernel
const renderKernel = gpu.createKernel(function(time, mouseX, mouseY) {
    // Normalizing coordinates
    const x = this.thread.x / this.output.x;
    const y = this.thread.y / this.output.y;

    // Interactive graphical logic
    const dist = Math.sqrt((x - mouseX) * (x - mouseX) + (y - mouseY) * (y - mouseY));
    const wave = Math.sin(dist * 20.0 - time * 5.0);

    this.color(wave, x, y, 1);
})
.setOutput([800, 600])
.setGraphical(true);

// 2. Attach the generated canvas to the DOM
const canvas = renderKernel.canvas;
document.body.appendChild(canvas);

// 3. Track interactive state
let mouseX = 0.5;
let mouseY = 0.5;

canvas.addEventListener('mousemove', (e) => {
    const rect = canvas.getBoundingClientRect();
    mouseX = (e.clientX - rect.left) / canvas.width;
    mouseY = 1.0 - (e.clientY - rect.top) / canvas.height; // Invert Y for WebGL coordinates
});

// 4. Run the animation loop
let startTime = performance.now();

function animate() {
    const currentTime = (performance.now() - startTime) / 1000;

    // Execute the kernel on the GPU
    renderKernel(currentTime, mouseX, mouseY);

    requestAnimationFrame(animate);
}

requestAnimationFrame(animate);

Adding Interactivity

Interactivity is achieved by binding event listeners to the DOM and passing the updated states into the kernel arguments during each iteration of requestAnimationFrame.

  • Mouse and Touch Events: Capture mousemove, mousedown, or touchmove events, normalize the coordinates to match the kernel's output dimensions, and pass them as floats.
  • Audio Inputs: Extract frequency data using the Web Audio API's AnalyserNode and pass normalized frequency arrays to animate visuals based on sound.
  • Keyboard Controls: Maintain a key state object updated by keydown and keyup listeners, allowing directional input to shift spatial offsets inside the kernel calculation.

Key Performance Best Practices

  • Avoid Kernel Recompilation: Never call gpu.createKernel() inside the loop. Compiling a kernel creates WebGL shaders, which is an expensive operation. Compile once during initialization and only invoke the resulting function inside requestAnimationFrame.
  • Coordinate Inversion: WebGL coordinates originate from the bottom-left corner (0, 0), whereas browser DOM coordinates originate from the top-left. Always flip the Y-axis (1.0 - normalizedY) when mapping pointer inputs.
  • Memory Management: Keep argument types consistent. Passing dynamic arguments with changing data types forces GPU.js to recompile the kernel, which drops frame rates drastically. Maintain strict numerical types (floats or integers) on each tick.
