How GPU.js Recycles WebGL Texture Buffers

GPU.js accelerates parallel computation in JavaScript by translating functions into WebGL shaders that use textures as memory buffers. Constantly allocating and deallocating native WebGL textures introduces severe CPU-GPU synchronization bottlenecks and garbage collection pauses. To mitigate this overhead, GPU.js manages an internal recycling queue known as recycledTextures within its WebGL backend kernel implementations, enabling rapid reuse of discarded texture buffers without repeatedly calling native WebGL allocation APIs.

When a GPU.js kernel executes, it outputs computational results onto an off-screen framebuffer backed by a WebGLTexture. In standard WebGL workflows, freeing these resources requires gl.deleteTexture(), which discards the GPU-side allocation. GPU.js avoids this churn by wrapping native textures inside its own Texture abstraction class. When a consumer disposes of an output texture—either manually using .delete(), or automatically when extracting values through .toArray()—the underlying WebGLTexture reference is diverted away from destruction and pushed directly into the kernel's recycledTextures array.

The recycledTextures structure functions as a memory pool. When the kernel is called again, it checks the recycling queue before instantiating new texture memory. For a recycled texture to be reused, its specifications must match the requirements of the incoming kernel run, including:

  • Dimensions: Width and height must be identical to the output dimensions expected by the framebuffer.
  • Internal Format and Type: The data representation (such as floating-point precision textures or standard integer channels) must match the kernel's output configuration.
  • Context Compatibility: The texture must belong to the active WebGL rendering context.

If an existing texture in the recycledTextures queue meets these criteria, GPU.js extracts it from the pool, binds it to the current framebuffer, and writes the new kernel output directly into that existing buffer. If no compatible texture exists in the queue, only then does GPU.js issue a gl.createTexture() call to allocate a fresh buffer.

By retaining and re-queuing discarded texture references in recycledTextures, GPU.js maintains high throughput during iterative operations, such as deep learning training loops or physics simulations, where the output of one step repeatedly demands memory allocation of identical sizes and types.
