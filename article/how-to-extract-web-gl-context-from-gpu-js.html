How to Extract WebGL Context from GPU.js

GPU.js accelerates JavaScript calculations by compiling code to run on the GPU via WebGL, but developers often need direct access to the underlying graphical context for rendering, texture manipulation, or custom pipeline integration. You can directly extract and interact with both the raw WebGLRenderingContext and WebGL2RenderingContext instances managed by GPU.js. This guide details how to retrieve the active context from the main GPU instance, access it through individual kernels, or provide your own pre-existing context during initialization.

Accessing the Context via the GPU Instance

When you initialize GPU.js, it creates an internal canvas and initializes the best available WebGL rendering context based on browser support and configuration. You can directly read the underlying context through the context property of the GPU instance.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Access the raw WebGL context
const gl = gpu.context;

if (gl instanceof WebGL2RenderingContext) {
  console.log('Running on WebGL2:', gl);
} else if (gl instanceof WebGLRenderingContext) {
  console.log('Running on WebGL1:', gl);
} else {
  console.log('Context not available or running in fallback mode.');
}

Retrieving the Context via the Internal Canvas

GPU.js also exposes its internal <canvas> element via the canvas property. If needed, you can reference the canvas directly to verify attributes or inspect the active context:

const gpu = new GPU();

const canvas = gpu.canvas;
const gl = canvas.getContext('webgl2') || canvas.getContext('webgl');

Note that requesting a different context type than the one GPU.js already established on that specific canvas will return null, as a canvas cannot change context types once bound.

Accessing Context from a Specific Kernel

If your workflow centers around compiled kernels, individual kernel instances also maintain a reference to the active context used during execution:

const gpu = new GPU();

const kernel = gpu.createKernel(function () {
  return this.thread.x;
}).setOutput([10]);

kernel(); // Initialize and run kernel

const gl = kernel.context;

Supplying an Existing WebGL Context

Instead of extracting an internally generated context, you can share an existing WebGLRenderingContext or WebGL2RenderingContext with GPU.js. This is useful for sharing textures and buffers between custom WebGL rendering routines (like Three.js or Babylon.js) and compute passes:

const canvas = document.createElement('canvas');
const myGLContext = canvas.getContext('webgl2');

// Inject the existing context into GPU.js
const gpu = new GPU({
  context: myGLContext,
  canvas: canvas
});

// Verify shared reference
console.log(gpu.context === myGLContext); // true

Considerations for Headless and CPU Modes

  • CPU Mode: If GPU.js falls back to CPU execution (either automatically or forced via { mode: 'cpu' }), gpu.context will be null because no WebGL context is initialized.
  • Headless Environments: In Node.js environments using headless-gl, the returned context is an instance of the headless-gl implementation representing a WebGL 1 context rather than a browser-native context.
