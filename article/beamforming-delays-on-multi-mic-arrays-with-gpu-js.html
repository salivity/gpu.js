Beamforming Delays on Multi-Mic Arrays with GPU.js

This article evaluates how gpu.js can be utilized to calculate acoustic beamforming delays across multi-microphone arrays. By translating standard JavaScript mathematical functions into WebGL-enabled GPU shaders, gpu.js provides the massive parallel processing power necessary to calculate spatial distances, sample delays, and phase shifts across multi-dimensional coordinate grids in real time.

Understanding Beamforming Delay Calculations

Acoustic beamforming aims to filter sound based on spatial location using an array of microphones. In traditional delay-and-sum (DAS) beamforming, the system calculates the time difference of arrival (TDOA) for an acoustic wave traveling from a designated focal point \((x, y, z)\) to each individual microphone element \(m_i\).

The mathematical delay \(\tau_i\) for a given microphone \(i\) is calculated using Euclidean distance:

\[\tau_i = \frac{\|\mathbf{p}_{\text{focus}} - \mathbf{p}_{m_i}\|}{c}\]

Where:

  • \(\mathbf{p}_{\text{focus}}\) is the 3D coordinate of the sound source or scan point.
  • \(\mathbf{p}_{m_i}\) is the 3D coordinate of the \(i\)-th microphone.
  • \(c\) is the speed of sound in air (approximately 343 m/s at room temperature).

When mapping acoustic energy over a 2D or 3D field (such as in acoustic cameras or directional tracking), this delay must be calculated for every point in a spatial search grid across every microphone in the array. For an array of 64 microphones scanning a modest \(100 \times 100\) point plane, this equates to 640,000 independent geometric calculations per audio block.

How gpu.js Handles the Computation

gpu.js is an open-source JavaScript library that compiles simplified JavaScript code into WebGL/WebGPU compute shaders. Calculating spatial delays across a microphone array is an "embarrassingly parallel" problem, meaning every grid point and microphone pair can be evaluated independently of the others.

By offloading this logic to gpu.js:

  1. Thread Distribution: Each GPU thread calculates the Euclidean distance and corresponding sample delay for a single coordinate in the scanning grid.
  2. Speed Improvements: Calculations that would otherwise block the single-threaded JavaScript runtime or slow down Web Workers are distributed across hundreds or thousands of GPU cores.
  3. Multi-Channel Scaling: Large microphone arrays (e.g., 32, 64, or 128 elements) scale efficiently because GPU hardware excels at large-scale matrix operations.

Kernel Implementation Strategy

Calculating delays with gpu.js requires defining a GPU kernel that accepts the microphone position array, the speed of sound, and the audio sample rate as inputs.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel to compute sample delays for a 2D grid
const calculateSampleDelays = gpu.createKernel(function(micX, micY, micZ, numMics, speedOfSound, sampleRate) {
    // Thread coordinates map to the scanning grid
    const gridX = this.thread.x;
    const gridY = this.thread.y;
    const gridZ = 1.0; // Distance plane (e.g., 1 meter away)

    // Current microphone index passed via 3rd dimension or loop
    let micIndex = this.thread.z;

    // Euclidean distance calculation
    let dx = gridX - micX[micIndex];
    let dy = gridY - micY[micIndex];
    let dz = gridZ - micZ[micIndex];
    let distance = Math.sqrt(dx * dx + dy * dy + dz * dz);

    // Convert time delay into discrete audio sample shifts
    let timeDelay = distance / speedOfSound;
    return timeDelay * sampleRate;
}).setOutput([100, 100, 64]); // 100x100 spatial grid for 64 microphones

Once computed, the resulting delay matrix indicates exactly how many samples each microphone channel must be shifted before summing to reinforce acoustic energy at every specific coordinate.

Performance Bottlenecks and Considerations

While gpu.js handles the mathematical calculations effectively, real-time audio systems must address several architectural trade-offs:

  • CPU-to-GPU Transfer Overhead: Transferring continuous multichannel audio buffers to GPU memory introduces latency. For optimal performance, compute the static delay matrix once on the GPU and apply it to incoming audio buffers via Web Audio API or AudioWorklet nodes, rather than sending raw audio samples to gpu.js on every frame.
  • Precision Constraints: WebGL outputs 32-bit floating-point numbers by default. While insufficient for some scientific high-precision simulation, 32-bit precision is more than adequate for spatial acoustic beamforming delays and phase offsets.
  • Fractional Delay Interpolation: Since sample delays rarely fall on integer sample boundaries, beamforming typically requires sinc or linear interpolation. Implementing interpolation within a gpu.js kernel increases shader complexity but can be executed in parallel alongside the geometric delay computation.

Conclusion

gpu.js is fully capable of calculating acoustic beamforming delays across multi-microphone arrays. Its ability to compile JavaScript to GPU shaders eliminates the primary performance bottlenecks associated with multi-channel geometric calculations, enabling complex acoustic imaging and spatial filtering to run smoothly in web and Node.js environments.
