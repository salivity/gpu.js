Handle WebGL Context Lost and Restored in GPU.js

Handling WebGL context loss is critical for maintaining reliable browser-based computations with GPU.js. This article explains how to detect the webglcontextlost and webglcontextrestored events using the underlying canvas element of GPU.js, prevent default browser behaviors that permanently invalidate the context, and re-initialize your compute kernels once the GPU recovers.

Understanding WebGL Context Loss in GPU.js

GPU.js relies on an underlying HTML5 canvas and a WebGL (or WebGL2) rendering context to execute parallel computations. A WebGL context can be lost at any time due to external factors such as OS-level GPU driver crashes, high VRAM pressure from other applications, or the device entering a power-saving state.

When a context is lost, any subsequent calls to GPU.js kernels will fail silently or throw errors. To recover, you must intercept the loss event, tell the browser you intend to restore the context, and recreate your kernels when the context becomes available again.

Step 1: Prevent Default on Context Loss

To allow the browser to restore the context after a crash, you must attach an event listener to the canvas used by GPU.js and call event.preventDefault(). If preventDefault() is not called on webglcontextlost, the browser will not attempt to fire webglcontextrestored.

You can access the canvas directly from the GPU instance via gpu.canvas.

const gpu = new GPU();

gpu.canvas.addEventListener('webglcontextlost', (event) => {
  event.preventDefault();
  console.warn('WebGL context lost. Pausing GPU computations.');
  // Pause any active requestAnimationFrame loops or queued tasks here
}, false);

Step 2: Re-initialize Kernels on Context Restoration

Once the operating system or browser recovers the GPU state, the webglcontextrestored event fires on the canvas.

Because the GPU memory state, compiled shaders, and textures are wiped during a context loss, existing GPU.js kernel functions become invalid. You must re-instantiate your GPU instance (or recreate the kernels bound to the new context) to resume work.

let gpu = new GPU();
let computeKernel;

function setupKernels() {
  computeKernel = gpu.createKernel(function (a, b) {
    return a[this.thread.x] + b[this.thread.x];
  }).setOutput([512]);
}

function bindContextEvents(canvas) {
  canvas.addEventListener('webglcontextlost', (event) => {
    event.preventDefault();
    console.warn('WebGL context lost. Halting computation.');
  }, false);

  canvas.addEventListener('webglcontextrestored', () => {
    console.info('WebGL context restored. Rebuilding GPU.js kernels.');
    
    // Dispose of the stale GPU instance to free dangling references
    gpu.destroy();

    // Create a new instance and recreate kernels
    gpu = new GPU();
    bindContextEvents(gpu.canvas);
    setupKernels();

    // Resume computation with fresh state
    executeComputation();
  }, false);
}

// Initial setup
bindContextEvents(gpu.canvas);
setupKernels();

function executeComputation() {
  const result = computeKernel([1, 2, 3], [4, 5, 6]);
  console.log(result);
}

Step 3: Providing a CPU Fallback

If high memory consumption consistently triggers context loss, you should implement a fallback mechanism. GPU.js supports multiple execution modes (gpu, cpu, and dev). If repeated context loss is detected, switch the instance mode to cpu to guarantee the calculation finishes, albeit at a lower processing speed:

let lossCount = 0;

gpu.canvas.addEventListener('webglcontextlost', (event) => {
  event.preventDefault();
  lossCount++;

  if (lossCount > 2) {
    console.error('Frequent WebGL context loss detected. Falling back to CPU mode.');
    gpu.destroy();
    gpu = new GPU({ mode: 'cpu' });
    setupKernels();
    executeComputation();
  }
}, false);

By intercepting webglcontextlost on gpu.canvas, explicitly preventing the default browser behavior, and recreating your compute kernels inside webglcontextrestored, you ensure that applications powered by GPU.js recover smoothly from transient hardware interruptions.
