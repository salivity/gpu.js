Passing Objects and JSON to a gpu.js Kernel

This article explores whether custom JavaScript objects or JSON structures can be passed directly into a gpu.js kernel function. In short, gpu.js cannot accept arbitrary JavaScript objects or JSON strings directly because it compiles JavaScript into WebGL shaders (GLSL), which require flat, strongly-typed numeric data. Below, we examine the technical reasons behind this constraint and the standard workarounds used to process complex data structures on the GPU, including data flattening, parallel typed arrays, and kernel constants.

Why gpu.js Rejects Arbitrary Objects and JSON

When gpu.js runs code on the GPU, it translates the JavaScript kernel into GLSL (OpenGL Shading Language) and passes inputs as WebGL textures or uniforms. GPUs are designed for massive parallel computation over raw memory buffers containing primitive types such as floats and integers.

Because of this architectural design:

  • No dynamic memory or references: WebGL shaders do not support dynamic JavaScript object references, key-value lookups, or variable-length nested objects.
  • No string parsing: The GPU cannot parse or manipulate strings, making raw JSON payloads unusable inside the kernel.
  • Strict typing: Kernel arguments must map directly to supported WebGL data types: numbers, booleans, or 1D/2D/3D numeric arrays.

Passing an object like { x: 10.5, y: 20.2 } or a JSON string directly as a kernel parameter will result in a runtime compilation error or evaluate to unexpected values.

Solutions for Handling Complex Data

To compute over structured data with gpu.js, you must reshape your data into formats the GPU understands before invoking the kernel.

1. Data Flattening (Array of Arrays)

Convert an array of objects into a nested numeric array. If you have an array of 2D coordinates:

// Unsupported format
const points = [
  { x: 1.0, y: 2.0 },
  { x: 3.0, y: 4.0 }
];

// GPU-compatible format
const flattenedPoints = [
  [1.0, 2.0],
  [3.0, 4.0]
];

Within the kernel, access the properties via numeric indices instead of named keys (e.g., index 0 for x, index 1 for y).

2. Structure of Arrays (SoA)

Instead of passing an array containing objects (Array of Structures), separate the properties into individual parallel arrays. This pattern is optimal for GPU memory bandwidth:

const xCoordinates = [1.0, 3.0];
const yCoordinates = [2.0, 4.0];

const kernel = gpu.createKernel(function(xArr, yArr) {
  return xArr[this.thread.x] + yArr[this.thread.x];
}).setOutput([2]);

kernel(xCoordinates, yCoordinates);

3. Using Kernel Constants for Fixed Configuration

If your object contains static configuration values or metadata that do not change on every thread, you can pass them via the kernel's constants option during creation:

const config = {
  multiplier: 2.5,
  offset: 10.0
};

const kernel = gpu.createKernel(function(data) {
  return (data[this.thread.x] * this.constants.multiplier) + this.constants.offset;
}, {
  constants: config,
  output: [100]
});

gpu.js inlines these constants into the compiled shader source code as static uniform values, allowing you to use object-like configurations without passing them as dynamic kernel arguments.
