Using console.log in gpu.js Kernels

Using console.log inside a gpu.js kernel function will cause a compilation failure because the library cannot translate standard JavaScript console APIs into GPU shader code. When gpu.js runs, it transpiles JavaScript into WebGL or WebGPU shader language (GLSL), an environment that lacks standard system I/O and browser runtime features. This article explains why console.log fails inside kernels, the exact mechanism behind the failure, and alternative ways to inspect your data during development.

Why console.log Fails

gpu.js works by parsing the Abstract Syntax Tree (AST) of your JavaScript function and translating valid operations into GLSL. GPUs are specialized for high-throughput mathematical computations and do not have access to standard host environment APIs like the Document Object Model (DOM), the window object, or the console object.

Because GLSL has no native concept of standard output or console logging, the gpu.js compiler does not recognize console.log as a valid GPU operation. When you attempt to call it inside a kernel running on the GPU, the transpiler throws an error during the compilation phase, preventing the kernel from ever executing.

The CPU Mode Exception

The only scenario where console.log will work inside a gpu.js kernel is if the kernel executes in CPU mode. If you explicitly configure the kernel with { mode: 'cpu' }, or if the browser environment lacks WebGL support and falls back to CPU execution, gpu.js runs the kernel as standard JavaScript inside a series of nested for loops.

In CPU mode, console.log executes normally. However, because kernels iterate thousands or millions of times across a thread grid, a single console.log statement can log an overwhelming number of times and severely degrade browser performance.

Alternative Debugging Strategies

Since you cannot log directly to the console from a GPU-accelerated kernel, you must use alternative debugging techniques:

  • Temporarily Switch to CPU Mode: Set the kernel mode to cpu during development to enable step-debugging with standard browser dev tools and console.log. Once the logic is verified, switch back to gpu mode and remove the log statements.
  • Return Diagnostic Values: Instead of logging a variable, return the specific value you want to inspect as the kernel's output. You can then log the resulting array or texture in standard JavaScript on the host CPU.
  • Inspect via Graphical Output: If your kernel outputs to a canvas, map intermediate variables to RGB color channels. Visualizing unexpected color changes across the canvas can quickly highlight where a mathematical function is misbehaving.
