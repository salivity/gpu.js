Parallelizing Dilated Convolutions with GPU.js

This article explains how to implement and parallelize dilated causal 1D convolutions for WaveNet-style neural network architectures using gpu.js. By mapping output sequence timesteps and feature channels to a two-dimensional GPU execution grid, you can bypass the sequential processing of CPU loops and compute feedforward inference or training passes across full audio sequences concurrently.

Understanding Dilated Causal 1D Convolutions

In WaveNet models, dilated causal 1D convolutions allow the network to handle long-range temporal dependencies with an exponentially growing receptive field while preventing future information leakage.

Mathematically, for a 1D input sequence \(x\), filter weights \(W\) of size \(K\), and dilation rate \(d\), the causal dilated convolution at time \(t\) for a given channel is defined as:

\[y[t] = \sum_{k=0}^{K-1} W[k] \cdot x[t - k \cdot d] + b\]

The operation is strictly causal because \(y[t]\) depends only on inputs at time \(t, t-d, t-2d, \dots\). Inputs where \(t - k \cdot d < 0\) are treated as zero (zero-padding).

Parallelization Strategy in GPU.js

While autoregressive generation (sample-by-sample output) is inherently sequential, evaluating a WaveNet layer over an entire input sequence during training or teacher-forced inference is embarrassingly parallel. Every output sample \(y[t]\) at every channel \(c_{out}\) can be evaluated independently.

In gpu.js, this parallelization is structured by creating a compute kernel with a 2D output topology:

  • X-dimension (this.thread.x): Temporal dimension (sequence length \(T\)).
  • Y-dimension (this.thread.y): Output channel dimension (\(C_{out}\)).

Each GPU thread computes the dot product between the kernel weights and the dilated inputs for its designated time index and output channel.

GPU.js Kernel Implementation

To implement this kernel in gpu.js, the inputs, weights, and bias are supplied as arrays or textures.

const { GPU } = require('gpu.js');
const gpu = new GPU();

const createDilatedConv1DKernel = (seqLength, inChannels, outChannels, kernelSize) => {
  return gpu.createKernel(function(input, weights, bias, dilation) {
    const t = this.thread.x;        // Current time step
    const outC = this.thread.y;     // Current output channel
    
    let sum = bias[outC];

    // Convolve over kernel width and input channels
    for (let k = 0; k < this.constants.kernelSize; k++) {
      const sourceTime = t - (k * dilation);
      
      // Enforce causality with zero-padding for past boundaries
      if (sourceTime >= 0) {
        for (let inC = 0; inC < this.constants.inChannels; inC++) {
          // Flattened indices:
          // input shape assumed: [inChannels, seqLength]
          // weights shape assumed: [outChannels, inChannels, kernelSize]
          const inputVal = input[inC][sourceTime];
          const weightVal = weights[outC][inC][k];
          
          sum += inputVal * weightVal;
        }
      }
    }

    return sum;
  })
  .setConstants({ kernelSize, inChannels })
  .setOutput([seqLength, outChannels]);
};

Execution Pipeline

  1. Kernel Compilation: Define the kernel using static constants (kernelSize and inChannels) so the WebGL/WebGPU shader compiler can unroll inner loops for higher instruction-level parallelism.
  2. Dilation Scheduling: In a stacked WaveNet architecture, invoke the kernel sequentially across layers, multiplying the dilation parameter by 2 at each layer (e.g., \(d \in \{1, 2, 4, 8, \dots, 512\}\)).
  3. Pipeline Chaining: Set pipeline: true on the gpu.js kernel options to keep intermediate representations on the GPU as textures, avoiding expensive round-trip memory transfers between the CPU host and GPU device memory between layers.

Performance Considerations

  • Branch Divergence: The conditional check sourceTime >= 0 introduces minimal branch divergence because it only diverges for the first \((K - 1) \cdot d\) threads of the sequence. For long audio sequences (e.g., \(T \ge 16,000\)), this overhead is negligible.
  • Memory Layout: Passing inputs as 2D arrays where spatial/temporal coordinates occupy the fastest-moving memory axis optimizes texture cache locality during reads.
