Parallel Marching Squares with GPU.js

This article provides a practical guide on implementing the Marching Squares algorithm in parallel using GPU.js to rapidly extract vector boundaries from 2D scalar fields. By offloading cell evaluations and linear interpolations to the GPU via WebGL shaders, you can achieve real-time contouring performance in JavaScript that significantly outperforms standard CPU loops.

The Parallel Approach

Marching Squares calculates isolines by dividing a scalar field into a grid of cells. Each cell has four corner values. By comparing these values against an isovalue threshold, an 8-bit or 4-bit state index (from 0 to 15) is assigned to the cell, determining which edges are intersected by the contour line.

Because each cell's edge intersections depend entirely on its local corner values, this process is an embarrassingly parallel problem. The GPU evaluates every grid cell simultaneously, generating edge coordinate data stored in an output texture or typed array.

Step 1: Initializing GPU.js and Kernel Configuration

GPU.js converts standard JavaScript functions into WebGL shaders. To parallelize Marching Squares, define a kernel that maps one GPU thread to each cell in your scalar grid \((W-1 \times H-1)\).

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Kernel outputs 4 values per cell: [x1, y1, x2, y2] representing the segment
const marchingSquaresKernel = gpu.createKernel(function(field, width, height, threshold) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Corner sampling: Top-Left (tl), Top-Right (tr), Bottom-Right (br), Bottom-Left (bl)
    const tl = field[y + 1][x];
    const tr = field[y + 1][x + 1];
    const br = field[y][x + 1];
    const bl = field[y][x];

    // Compute binary index (0 - 15)
    let caseId = 0;
    if (tl >= threshold) caseId += 8;
    if (tr >= threshold) caseId += 4;
    if (br >= threshold) caseId += 2;
    if (bl >= threshold) caseId += 1;

    // Reject fully interior or exterior cells
    if (caseId === 0 || caseId === 15) {
        return [-1, -1, -1, -1];
    }

    // Normalized edge crossing calculations using linear interpolation
    // Top Edge (between tl and tr)
    const topX = x + (threshold - tl) / (tr - tl);
    const topY = y + 1.0;

    // Bottom Edge (between bl and br)
    const bottomX = x + (threshold - bl) / (br - bl);
    const bottomY = y;

    // Left Edge (between bl and tl)
    const leftX = x;
    const leftY = y + (threshold - bl) / (tl - bl);

    // Right Edge (between br and tr)
    const rightX = x + 1.0;
    const rightY = y + (threshold - br) / (tr - br);

    // Segment mappings based on case ID
    // Note: Saddle points (cases 5 and 10) are resolved with standard default choices
    if (caseId === 1 || caseId === 14) return [leftX, leftY, bottomX, bottomY];
    if (caseId === 2 || caseId === 13) return [bottomX, bottomY, rightX, rightY];
    if (caseId === 3 || caseId === 12) return [leftX, leftY, rightX, rightY];
    if (caseId === 4 || caseId === 11) return [topX, topY, rightX, rightY];
    if (caseId === 6 || caseId === 9)  return [topX, topY, bottomX, bottomY];
    if (caseId === 7 || caseId === 8)  return [leftX, leftY, topX, topY];

    // Default return for unresolved ambiguity
    return [-1, -1, -1, -1];
})
.setOutput([GRID_WIDTH - 1, GRID_HEIGHT - 1])
.setOutputOrder('x')
.setPipeline(false);

Step 2: Extracting Line Segments

Run the kernel by passing your 2D data matrix, grid dimensions, and target threshold. The GPU executes all cell calculations in parallel and returns an array of coordinates:

const width = 512;
const height = 512;
const threshold = 0.5;

// Generate or supply a 2D scalar field: number[height][width]
const scalarField = getScalarField(width, height);

// Execute kernel on GPU
const rawSegments = marchingSquaresKernel(scalarField, width, height, threshold);

Step 3: Vector Stitching on the CPU

The GPU output is a list of disconnected line segments, marked by [-1, -1, -1, -1] where no contour passes through. To produce final vector boundaries (such as SVG paths or GeoJSON Polygons), post-process the output on the CPU:

  1. Filter Valid Segments: Iterate through the GPU output and discard elements where coordinates are -1.
  2. Key-Based Chaining: Insert the endpoints into a spatial hash map where keys are quantized vertex strings (e.g., "x,y").
  3. Trace Polylines: Iterate through segment connections to assemble contiguous paths and close loop vectors.
function extractPolylines(segments) {
    const validSegments = [];
    
    for (let i = 0; i < segments.length; i++) {
        const seg = segments[i];
        if (seg[0] !== -1) {
            validSegments.push([
                [seg[0], seg[1]],
                [seg[2], seg[3]]
            ]);
        }
    }
    
    return validSegments;
}

Performance Considerations

  • Memory Layout: Flattening dynamic arrays into fixed-size Float32 arrays ensures continuous memory operations when passing data to WebGL.
  • Saddle Points: Ambiguous cases (5 and 10) require calculating an average cell center value to determine topological connectivity. If high visual fidelity is required, add a center-point sample check within the kernel branch.
  • Resolution: Since GPU execution eliminates CPU iterative overhead, large grids (e.g., \(2048 \times 2048\)) can be processed within single-digit milliseconds, making this approach well-suited for dynamic heatmaps, terrain contouring, and procedural generation.
