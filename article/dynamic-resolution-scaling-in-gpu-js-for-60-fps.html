Dynamic Resolution Scaling in GPU.js for 60 FPS

This article outlines how to implement Dynamic Resolution Scaling (DRS) in gpu.js to maintain a stable 60 frames per second (FPS) on low-tier mobile devices. By continuously tracking frame times via requestAnimationFrame and dynamically resizing the compute output or the target WebGL canvas, you can shed rendering workload during heavy operations before frame drops occur. The following sections break down the performance budget, scaling algorithm, and practical implementation details needed to keep your GPU-accelerated web applications fluid.

The 60 FPS Budget on Low-Tier Hardware

To maintain 60 FPS, the GPU and CPU combined have a strict frame budget of 16.67 milliseconds. Low-end smartphone chipsets typically suffer from limited memory bandwidth and weak fill rates. When high-resolution mobile screens (often 1080p to 1440p) are coupled with compute-heavy gpu.js kernels, the fill rate bottleneck quickly causes frame times to exceed 16.67ms.

Dynamic Resolution Scaling solves this by decoupling internal calculation resolution from the native display resolution. When frame times rise, the calculation resolution drops; when frame times normalize, resolution is restored.

Managing GPU.js Kernels Efficiently

Calling kernel.setOutput([width, height]) dynamically in gpu.js can trigger an expensive pipeline recompilation or framebuffer reallocation if done incorrectly. For optimal performance on mobile:

  1. Avoid Frequent Recompilation: Quantize scaling factors (e.g., scale steps of 1.0, 0.85, 0.75, 0.5) rather than recalculating arbitrary resolutions every frame.
  2. Use Integer Scaling Dimensions: Ensure resulting dimensions are rounded to even integers to prevent WebGL coordinate alignment issues.
  3. Upscale via CSS: Render the gpu.js output to an offscreen canvas or smaller canvas element, then let the hardware compositor stretch it across the screen using CSS (image-rendering: auto or bilinear).

Implementation Strategy

The implementation consists of three core components:

  • A Frame Timer: Measures delta time over a rolling average to filter out single-frame outliers.
  • A Dynamic Scaler: Evaluates performance against upper (e.g., > 18ms) and lower (e.g., < 14ms) thresholds.
  • A Kernel Controller: Updates the dimensions passed to gpu.js and resizes the target canvas.

Complete Implementation

// 1. Initialize GPU.js
const gpu = new GPU();

let currentScale = 1.0;
const minScale = 0.5;
const maxScale = 1.0;
const scaleStep = 0.1;

const baseWidth = window.innerWidth;
const baseHeight = window.innerHeight;

// 2. Create the kernel
// Render to a canvas to allow CSS upscaling
const renderKernel = gpu.createKernel(function(width, height) {
    const x = this.thread.x / width;
    const y = this.thread.y / height;
    
    // Example compute work: plasma effect
    const v = Math.sin(x * 10.0) + Math.cos(y * 10.0);
    this.color(v, v * 0.5, 1.0 - v, 1.0);
})
.setOutput([Math.round(baseWidth * currentScale), Math.round(baseHeight * currentScale)])
.setGraphical(true);

const canvas = renderKernel.canvas;
document.body.appendChild(canvas);

// Ensure CSS fills the viewport while internal resolution changes
canvas.style.width = "100vw";
canvas.style.height = "100vh";

// 3. Setup performance monitoring
let lastTime = performance.now();
let rollingDelta = 16.67;
const smoothingFactor = 0.9; // Exponential moving average

function updateResolution(newScale) {
    currentScale = Math.min(maxScale, Math.max(minScale, newScale));
    const newWidth = Math.round(baseWidth * currentScale);
    const newHeight = Math.round(baseHeight * currentScale);
    
    renderKernel.setOutput([newWidth, newHeight]);
}

// 4. Execution Loop
function render(now) {
    const delta = now - lastTime;
    lastTime = now;

    // Calculate smoothed frame time
    rollingDelta = (rollingDelta * smoothingFactor) + (delta * (1.0 - smoothingFactor));

    // Dynamic scaling logic
    // Thresholds: drop scale if over 18ms (below ~55 FPS), increase if under 14ms (above ~70 FPS headroom)
    if (rollingDelta > 18.0 && currentScale > minScale) {
        updateResolution(currentScale - scaleStep);
    } else if (rollingDelta < 14.0 && currentScale < maxScale) {
        updateResolution(currentScale + scaleStep);
    }

    const activeWidth = Math.round(baseWidth * currentScale);
    const activeHeight = Math.round(baseHeight * currentScale);

    // Run compute kernel
    renderKernel(activeWidth, activeHeight);

    requestAnimationFrame(render);
}

requestAnimationFrame(render);

Mobile Optimization Considerations

To ensure the scaling algorithm behaves reliably on mobile browsers:

  • Thermal Throttling Hysteresis: Low-tier smartphones drop performance significantly as they heat up. Implement an asymmetrical scaling speed—drop resolution quickly when frames stutter, but delay scale increases to prevent oscillation.
  • Device Pixel Ratio (DPR): Never render at native DPR (which can be 2.0x to 3.0x on low-end phones) for heavy compute workloads. Cap your baseWidth and baseHeight to a logical CSS size (window.innerWidth, window.innerHeight) before applying resolution scaling factors.
  • Garbage Collection: Avoid instantiating arrays, objects, or strings inside the rendering loop to prevent garbage collection pauses, which mimic GPU lag and trigger unnecessary downscaling.
