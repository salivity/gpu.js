How gpu.js Serializes Data for the GPU

This article explains the internal mechanism gpu.js uses to convert JavaScript argument data into formats compatible with graphics hardware. While scalar primitives are converted directly into GLSL uniforms, complex multi-dimensional arrays cannot fit into standard uniform registers. Instead, gpu.js flattens these data structures, converts them into typed arrays, and packs them into WebGL textures to be sampled inside the compiled shader.

Primitive Types and Uniform Mapping

When arguments are simple scalar values, such as numbers or booleans, gpu.js handles them directly using WebGL uniforms. The library inspects the runtime type of each parameter and matches it to the corresponding WebGL API call:

  • Floats and Integers: Passed to the GPU via calls such as gl.uniform1f or gl.uniform1i.
  • Booleans: Converted into integers (1 or 0) and uploaded as integer uniforms.

Because uniforms reside in constant register memory accessible by all GPU threads, passing primitives requires almost no serialization overhead.

Array Flattening and TypedArray Conversion

GLSL kernels cannot directly consume standard dynamic JavaScript arrays. To prepare arrays (1D, 2D, or 3D) for the GPU, gpu.js serializes them into flat, continuous blocks of memory:

  1. Shape Detection: The library recursively reads the dimensions of the input array to determine its rank (1D, 2D, or 3D) and size.
  2. Flattening: Nested arrays are unrolled into a single continuous sequence.
  3. TypedArray Instantiation: The flattened values are cast into a typed array, predominantly a Float32Array.

This step eliminates JavaScript's dynamic array overhead and arranges the values into a layout that graphics memory can parse directly.

Texture Packing

WebGL limits the maximum size and memory footprint of standard uniform buffers. To handle large datasets, gpu.js serializes flattened arrays into 2D WebGL textures rather than uniform buffers:

  • Dimension Calculation: Textures must conform to the GPU's maximum texture size constraints. gpu.js calculates an optimal 2D dimension (width and height) capable of containing the total number of elements.
  • Channel Mapping: WebGL textures store data in pixel channels (Red, Green, Blue, Alpha). If WebGL 2 or floating-point texture extensions (OES_texture_float) are available, data can be written directly to floating-point textures. When limited to standard 8-bit RGBA textures, gpu.js encodes 32-bit floating-point numbers across the four 8-bit color channels (RGBA) using bitwise operations.
  • GPU Upload: The serialized typed array is bound to a texture target and uploaded to VRAM using gl.texImage2D.

Accompanying Metadata Uniforms

Along with the encoded texture, gpu.js automatically sends metadata to the shader program via standard uniforms. This metadata includes:

  • The texture's width and height.
  • The original shape dimensions of the input array.
  • Bit-depth and decoding flags (if byte-packing was used).

The auto-generated GLSL kernel uses this metadata to map array indices (such as arr[y][x]) back to precise texture coordinates (u, v), decode the pixel values, and retrieve the original values inside the compute loop.

Texture Optimization (Texture Pipelining)

If the output of a preceding kernel is passed directly as an argument to a subsequent kernel, gpu.js bypasses serialization entirely. The output remains in GPU VRAM as a WebGL texture, skipping both the readback to JavaScript memory and the subsequent re-flattening step.
