Can GPU.js Compile JavaScript Labelled Statements?

GPU.js cannot compile standard JavaScript labelled statements, and attempting to use them inside a GPU kernel function will result in compilation errors. Because GPU.js converts standard JavaScript syntax into WebGL GLSL (OpenGL Shading Language) shader code, it only supports a restricted subset of the JavaScript language. Labelled statements—typically used to break or continue specific outer loops in nested iteration—are neither supported by GPU.js's abstract syntax tree (AST) transpiler nor natively supported by the underlying GLSL specification.

When you define a kernel in GPU.js, the library parses the JavaScript function using an AST parser and translates supported node types into corresponding GLSL code. WebGL 1.0 and 2.0 shading languages do not feature labels or multi-level break and continue syntax. Consequently, GPU.js does not implement an AST handler for LabeledStatement nodes. When the compiler encounters a label declaration (such as myLoop: for (...)), the kernel compilation fails, throwing an unsupported syntax or unhandled node error during initialization.

To achieve the desired control flow inside a GPU kernel without labelled statements, you must rewrite nested loops using standard control structures. You can simulate labelled breaks by declaring boolean flag variables inside the kernel to track when an inner loop has met a termination condition, allowing the outer loop to evaluate that flag and exit via a standard break statement. Alternatively, logic can often be restructured or flattened into sequential passes using multiple GPU kernels to avoid deeply nested branching entirely.
