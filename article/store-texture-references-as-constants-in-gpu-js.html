Store Texture References as Constants in GPU.js

This article examines whether texture references can be stored as persistent constants within a gpu.js instance. It explores the technical constraints of the GPU.js compilation model, clarifies the difference between kernel constants and WebGL texture bindings, and outlines the correct methods for persistently reusing texture data across multiple kernel executions without sacrificing performance.

The Short Answer: No Direct Texture Constants

In GPU.js, you cannot pass or store a Texture object directly inside the constants configuration object of a kernel.

When you define constants in GPU.js using the kernel settings (for example, { constants: { myValue: 42 } }), the library injects these values directly into the generated WebGL GLSL shader code as compile-time constants or preprocessor macros. Because WebGL textures require dedicated texture units, texture targets, and uniform samplers (sampler2D), they cannot be inlined as standard GLSL constants. Attempting to assign a texture object into the constants map will cause compilation errors or unexpected behavior.

How to Persist Textures Across Kernel Executions

While you cannot declare a texture as an internal constant in the kernel configuration, you can achieve the exact same performance benefits—avoiding costly CPU-to-GPU data uploads—by persisting the texture in memory and passing it as an argument.

1. Enable Pipeline Mode

GPU.js provides pipeline mode specifically for handling persistent textures. When pipeline mode is enabled, the kernel outputs a WebGL texture instead of converting the output data back into a JavaScript array.

const gpu = new GPU();

const generateTextureKernel = gpu.createKernel(function() {
    return this.thread.x * 0.5;
}).setOutput([512, 512]).setPipeline(true);

const processTextureKernel = gpu.createKernel(function(inputTexture) {
    return inputTexture[this.thread.y][this.thread.x] * 2.0;
}).setOutput([512, 512]).setPipeline(true);

2. Store the Texture Reference in JavaScript Scope

Run the initial kernel once to create the texture on the GPU. Keep the resulting reference in a standard variable within your application's scope:

// The texture remains allocated on the GPU
const persistentTexture = generateTextureKernel();

3. Pass the Stored Texture as a Parameter

Whenever you run downstream kernels, pass the persistent texture reference directly as a kernel parameter. Because the texture already lives on the GPU, passing it introduces virtually zero CPU-to-GPU transfer overhead:

// Reusing the persistent texture across multiple frames or iterations
for (let i = 0; i < 60; i++) {
    const resultTexture = processTextureKernel(persistentTexture);
    // Use or display result...
}

Memory Management

Because persistent textures reside in VRAM on the GPU, they are not automatically garbage-collected by the JavaScript runtime immediately. If you replace or discard a persistent texture reference, explicitly delete it to prevent WebGL memory leaks:

persistentTexture.delete();

Summary

GPU.js does not support storing textures inside the static constants dictionary due to the underlying requirements of WebGL GLSL compilation. However, full persistence is natively supported by enabling setPipeline(true), retaining the resulting Texture reference in your application logic, and passing it as a regular argument to subsequent kernel calls.
