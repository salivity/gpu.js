Inject Raw GLSL Code into GPU.js Kernels

GPU.js bridges high-performance parallel computing and web development by transpiling standard JavaScript functions into GLSL shaders executed on the GPU. While GPU.js is designed to abstract away shader programming, developers frequently encounter scenarios requiring low-level hardware optimizations or unsupported GLSL capabilities. Developers cannot directly write unquoted GLSL inline inside a JavaScript kernel, but GPU.js explicitly supports injecting raw GLSL through custom functions, bridging the gap between high-level JavaScript and low-level shader routines.

Can You Inject Raw GLSL Directly?

You cannot write raw GLSL directly inside the body of a standard gpu.createKernel() JavaScript function. Because GPU.js relies on abstract syntax tree (AST) parsing to transpile JavaScript into WebGL shaders, unrecognized GLSL syntax written inside a standard JavaScript function will result in a JavaScript syntax error before GPU.js ever parses the code.

However, GPU.js provides a native workaround using the gpu.addFunction() method. This API allows developers to define a custom GLSL function as a string and inject it into the generated shader program. Once injected, this GLSL function can be called seamlessly from within the JavaScript kernel.

How to Inject GLSL Using gpu.addFunction()

To introduce raw GLSL into your pipeline, register the function with the GPU instance using the source argument. You must also supply argument and return types so the transpiler understands how to interface with the native shader code.

const gpu = new GPU();

// Define and inject the raw GLSL function
gpu.addFunction(function customMath(val) {}, {
  source: `
    float customMath(float val) {
      return sin(val) * cos(val);
    }
  `,
  argumentTypes: { val: 'Float' },
  returnType: 'Float'
});

// Consume the injected function within a kernel
const kernel = gpu.createKernel(function(data) {
  return customMath(data[this.thread.x]);
}).setOutput([512]);

In this pattern, the placeholder JavaScript function signature allows your code editor and linting tools to recognize the function name, while the source string completely replaces the function body with raw GLSL inside the final WebGL shader.

Why Inject Raw GLSL?

  1. Accessing Unsupported Features: GPU.js does not support every native GLSL operation, built-in function, or variable type. Custom GLSL allows access to native texture lookups, complex math libraries, and specialized vector transformations.
  2. Performance Optimization: Writing raw GLSL lets developers write tightly optimized shader loops, utilize direct vector operations (such as vec4), and eliminate overhead introduced by JavaScript-to-shader transpilation.
  3. Reusing Existing Shaders: If an algorithm is already implemented in GLSL (e.g., from an existing WebGL or OpenGL project), you can reuse the code directly rather than rewriting and debugging it in JavaScript.

Key Considerations and Limitations

When injecting raw GLSL code, strict adherence to shader constraints is required:

  • Type Safety: You must accurately declare input and return types using GPU.js conventions (e.g., 'Float', 'Integer', 'Array(3)'). Mismatched signatures can cause shader compilation to fail silently or trigger runtime WebGL context errors.
  • Environment Differences: Injected GLSL must be compatible with the target WebGL version (typically WebGL 1.0 or WebGL 2.0 depending on the client’s browser and GPU.js configuration).
  • Debugging Complexity: Errors in raw GLSL strings bypass standard JavaScript debugging tools. Syntax errors in injected strings are reported as WebGL shader compilation failures, which provide less descriptive call stacks than native JavaScript errors.
