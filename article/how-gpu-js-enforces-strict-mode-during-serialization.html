How GPU.js Enforces Strict Mode During Serialization

This article explains how the GPU.js library guarantees strict mode compliance when serializing JavaScript functions into WebGL-compatible shaders. When compiling JavaScript kernels to run on the GPU, GPU.js extracts, parses, and validates user code. By using syntax tree analysis, prohibiting dynamic JavaScript runtime behaviors, and verifying strict variable declarations, the library ensures that serialized functions adhere strictly to static typing and scoping rules before converting them into GLSL.

String Extraction and AST Parsing

The serialization stage begins by converting the JavaScript kernel function into raw source text using Function.prototype.toString(). GPU.js uses an underlying JavaScript parser (such as Acorn) to transform this code string into an Abstract Syntax Tree (AST).

During this initial parsing pass, strict mode constraints are introduced automatically if the source file or the function body includes the "use strict"; directive. Even without an explicit directive, GPU.js evaluates the AST under strict-like assumptions because the target runtime—the GPU via WebGL—cannot support relaxed JavaScript semantics like dynamic scope lookups, implicit globals, or dynamic typing.

Prohibition of Dynamic Scope Constructs

Strict mode explicitly disallows legacy features that obscure static scope, notably the with statement and indirect eval(). During AST traversal, GPU.js analyzes each node's type. If the transpiler encounters disallowed syntax constructs, it halts compilation immediately and throws an error:

  • with Statements: Detected at the AST level as WithStatement nodes. GPU.js rejects these outright, preventing unresolvable identifier scopes.
  • Dynamic Code Execution: Direct calls to eval() or the Function constructor are blocked, ensuring that all variable names and references are fully resolvable ahead of time.
  • Context Binding (this): Dynamic re-binding of this is constrained. Within a GPU.js kernel, this.thread and built-in constants exist within a fixed execution context, preventing accidental access to the global window or worker scope.

Enforcing Variable Declarations and Immutability

In standard JavaScript without strict mode, assigning a value to an undeclared identifier silently creates a global variable. In GLSL and GPU compilation pipelines, undeclared identifiers cause low-level shader compilation failures.

To enforce strict behavior:

  1. Declaration Tracking: GPU.js registers declared identifiers during the parsing phase. Each variable initialized in a kernel must be explicitly declared using let, const, or var.
  2. Scope Validation: Assignments to identifiers that do not exist within the local scope tree, parameter list, or kernel constants are flagged as unresolved.
  3. Read-Only Safeguards: Assigning new values to immutable parameters, thread indices (such as this.thread.x), or reserved constants triggers serialization errors, mirroring strict mode's assignment errors on non-writable properties.

Type and Syntax Normalization for GLSL

GLSL is a statically typed language that requires strict semantic definitions. During the AST-to-GLSL translation step, GPU.js performs type inference based on declared operations and literal values. Strict mode semantics directly enable this process by eliminating unpredictable object mutations and variable shadowing ambiguities. By requiring explicit declarations and rejecting non-deterministic runtime features early in the serialization pipeline, GPU.js ensures that the resulting code cleanly maps to the strict, deterministically compiled environment of the GPU.
