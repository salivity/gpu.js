How GPU.js Verifies OES_texture_half_float on Mobile

GPU.js detects and validates OES_texture_half_float on mobile browsers by pairing WebGL extension querying with active functional rendering tests. Because mobile GPU drivers frequently advertise extension support while failing actual computation or texture attachment, GPU.js does not rely solely on the browser's extension registry. Instead, it queries the context, verifies auxiliary rendering extensions, and builds an in-memory test harness to confirm whether 16-bit floating-point textures can be reliably allocated, written to, and read.

Querying the WebGL Context

The verification process begins during the initialization of the WebGL rendering context. When running on WebGL 1, GPU.js requests the extension directly from the context:

const gl = this.context;
const halfFloatExt = gl.getExtension('OES_texture_half_float');

If gl.getExtension() returns null, the browser or underlying mobile hardware does not expose half-precision floating-point textures. In this case, GPU.js immediately marks the feature as unsupported and falls back to standard 32-bit float textures (OES_texture_float) or integer-encoded 8-bit RGBA channels.

Validating Framebuffer Renderability

On mobile chipsets (such as ARM Mali, Qualcomm Adreno, and Apple GPUs), a driver might support half-float textures for sampling inside a shader, but lack the ability to render calculation outputs directly into them. Because GPU.js relies on GPU kernels outputting results into textures via Framebuffer Objects (FBOs), read-only support is insufficient.

To verify renderability, GPU.js performs a runtime capability probe:

  1. Texture Creation: It creates a WebGL texture object and configures it with the gl.HALF_FLOAT_OES type token provided by the extension.
  2. FBO Attachment: It binds a test framebuffer and attaches the half-float texture to the framebuffer's color attachment point (gl.COLOR_ATTACHMENT0).
  3. Status Check: It queries gl.checkFramebufferStatus(gl.FRAMEBUFFER).

If the returned status is not gl.FRAMEBUFFER_COMPLETE, the mobile browser cannot use half-float textures as render targets, causing GPU.js to disable half-float output modes.

Checking Supplementary Extensions

Half-precision math often requires additional capabilities to function correctly in general-purpose GPU computing. Alongside OES_texture_half_float, GPU.js checks for:

  • EXT_color_buffer_half_float: Often required in mobile WebGL implementations to permit rendering to half-float textures.
  • OES_texture_half_float_linear: Checked if linear interpolation or filtering across half-float values is required for specific kernel operations.

Practical Execution and Readback

Even if a framebuffer reports complete status, mobile drivers can produce silent failures or NaN values during pixel readback. GPU.js runs a lightweight test kernel using a minimal 1x1 or 2x2 texture. It writes known numeric data to the texture, executes a minimal shader pass, and either reads the result back using gl.readPixels() or binds it to a subsequent pass. If the values match the expected output within half-precision tolerances, GPU.js flags the half-float pipeline as fully operational for that mobile session.
