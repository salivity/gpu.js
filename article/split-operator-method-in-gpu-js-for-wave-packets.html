Split-Operator Method in GPU.js for Wave Packets

This article explains how to simulate quantum wave packet propagation by solving the time-dependent Schrödinger equation using the split-operator Fourier method accelerated by gpu.js. You will learn the theoretical framework behind operator splitting, how complex wavefunctions and spatial grids are represented on the GPU, and how to structure the computational pipeline across coordinate and momentum spaces using WebGL-accelerated JavaScript kernels.

Theoretical Foundation: Split-Operator Fourier Method

The one-dimensional time-dependent Schrödinger equation is defined as:

\[i\hbar \frac{\partial \psi(x,t)}{\partial t} = \left[ -\frac{\hbar^2}{2m}\frac{\partial^2}{\partial x^2} + V(x) \right] \psi(x,t) = (\hat{T} + \hat{V})\psi(x,t)\]

Because the kinetic operator \(\hat{T}\) and potential operator \(\hat{V}\) do not commute, the time evolution operator \(e^{-i(\hat{T}+\hat{V})\Delta t / \hbar}\) is approximated using the symmetric Strang-splitting (second-order Trotter-Suzuki) scheme:

\[e^{-i(\hat{T}+\hat{V})\Delta t / \hbar} = e^{-i\hat{V}\frac{\Delta t}{2\hbar}} e^{-i\hat{T}\frac{\Delta t}{\hbar}} e^{-i\hat{V}\frac{\Delta t}{2\hbar}} + \mathcal{O}(\Delta t^3)\]

The algorithm executes in three phases per time step:

  1. Apply the potential evolution operator for \(\Delta t / 2\) in position space.
  2. Transform the wavefunction to momentum space using a Fast Fourier Transform (FFT), apply the kinetic evolution operator for \(\Delta t\), and transform back via Inverse FFT (IFFT).
  3. Apply the potential evolution operator again for \(\Delta t / 2\) in position space.

Data Representation in GPU.js

gpu.js executes WebGL shaders by taking JavaScript arrays and returning new arrays or textures. Because native WebGL 1.0/2.0 fragment shaders do not natively support complex numbers, a complex wavefunction \(\psi(x) = R(x) + i I(x)\) is represented using interleaved floats or two parallel 1D arrays: one for the real component and one for the imaginary component.

Complex multiplication \((a + ib)(c + id) = (ac - bd) + i(ad + bc)\) must be explicitly computed inside each shader kernel.

Setting Up Grid and Constants

Initialize the spatial domain, momentum domain, and physical constants:

const N = 1024; // Power of 2 for FFT
const L = 20.0;
const dx = L / N;
const dt = 0.01;
const hbar = 1.0;
const mass = 1.0;

// Spatial grid and momentum grid
const x = new Float32Array(N);
const k = new Float32Array(N);
const dk = (2.0 * Math.PI) / L;

for (let i = 0; i < N; i++) {
  x[i] = -L / 2 + i * dx;
  k[i] = (i < N / 2 ? i : i - N) * dk;
}

Implementing GPU.js Kernels

1. Potential Operator Kernel

The potential operator phase shift \(e^{-i V(x) \Delta t / (2\hbar)} = \cos(\theta_V) - i\sin(\theta_V)\), where \(\theta_V = \frac{V(x)\Delta t}{2\hbar}\).

const gpu = new GPU();

const applyPotential = gpu.createKernel(function(real, imag, V, dt, hbar) {
  const i = this.thread.x;
  const theta = -(V[i] * dt) / (2.0 * hbar);
  const cosT = Math.cos(theta);
  const sinT = Math.sin(theta);

  // Complex multiplication: (real + i*imag) * (cosT + i*sinT)
  const r = real[i] * cosT - imag[i] * sinT;
  const im = real[i] * sinT + imag[i] * cosT;

  return [r, im];
}).setOutput([N]);

2. Fast Fourier Transform (FFT) on the GPU

The split-operator method requires transforming data between real and momentum space. On the GPU, a radix-2 Cooley-Tukey FFT is implemented through \(\log_2(N)\) distinct dispatch passes:

const fftStep = gpu.createKernel(function(real, imag, step, N, direction) {
  const i = this.thread.x;
  const halfStep = step / 2;
  const k = i % step;
  const j = Math.floor(i / step) * step;

  let angle = (2.0 * Math.PI * (k % halfStep)) / step * direction;
  let cosA = Math.cos(angle);
  let sinA = Math.sin(angle);

  let targetIdx = 0;
  let partnerIdx = 0;

  if (k < halfStep) {
    targetIdx = j + k;
    partnerIdx = j + k + halfStep;
    return [
      real[targetIdx] + (cosA * real[partnerIdx] - sinA * imag[partnerIdx]),
      imag[targetIdx] + (sinA * real[partnerIdx] + cosA * imag[partnerIdx])
    ];
  } else {
    targetIdx = j + (k - halfStep);
    partnerIdx = j + k;
    return [
      real[targetIdx] - (cosA * real[partnerIdx] - sinA * imag[partnerIdx]),
      imag[targetIdx] - (sinA * real[partnerIdx] + cosA * imag[partnerIdx])
    ];
  }
}).setOutput([N]);

3. Kinetic Operator Kernel

In momentum space, \(\hat{T} = \frac{\hbar^2 k^2}{2m}\). The kinetic evolution phase shift is \(e^{-i \frac{\hbar k^2}{2m} \Delta t} = \cos(\theta_T) - i\sin(\theta_T)\), where \(\theta_T = \frac{\hbar k^2 \Delta t}{2m}\).

const applyKinetic = gpu.createKernel(function(real, imag, k, dt, hbar, mass) {
  const i = this.thread.x;
  const kVal = k[i];
  const theta = -(hbar * kVal * kVal * dt) / (2.0 * mass);
  const cosT = Math.cos(theta);
  const sinT = Math.sin(theta);

  const r = real[i] * cosT - imag[i] * sinT;
  const im = real[i] * sinT + imag[i] * cosT;

  return [r, im];
}).setOutput([N]);

The Time Evolution Execution Loop

To execute the propagation without moving data back and forth to the CPU on every pass, enable pipeline mode (pipeline: true) on all kernels so that output textures remain in GPU memory.

The complete step sequence:

function timeStep(real, imag, potential, kValues) {
  // Step 1: V(x) evolution for dt / 2
  let psi = applyPotential(real, imag, potential, dt, hbar);

  // Step 2: Forward FFT to k-space
  for (let s = 2; s <= N; s <<= 1) {
    psi = fftStep(extractReal(psi), extractImag(psi), s, N, -1.0);
  }

  // Step 3: T(k) evolution for dt
  psi = applyKinetic(extractReal(psi), extractImag(psi), kValues, dt, hbar, mass);

  // Step 4: Inverse FFT back to x-space
  for (let s = 2; s <= N; s <<= 1) {
    psi = fftStep(extractReal(psi), extractImag(psi), s, N, 1.0);
  }
  psi = scaleIFFT(extractReal(psi), extractImag(psi), 1.0 / N);

  // Step 5: V(x) evolution for dt / 2
  psi = applyPotential(extractReal(psi), extractImag(psi), potential, dt, hbar);

  return psi;
}

This sequence advances the wave packet by \(\Delta t\) with second-order accuracy. Repeating this loop drives real-time quantum dynamics, such as barrier tunneling or harmonic oscillation, directly inside the browser.
