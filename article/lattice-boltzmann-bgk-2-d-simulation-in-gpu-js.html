Lattice Boltzmann BGK 2D Simulation in GPU.js

This article provides an end-to-end guide to implementing the Lattice Boltzmann Method (LBM) using the Bhatnagar-Gross-Krook (BGK) collision model on two-dimensional grids with gpu.js. It explains the mechanics of the standard D2Q9 lattice, outlines the mathematical formulations for macroscopic moments and equilibrium distributions, and demonstrates how to fuse streaming and collision operations into high-performance GPU kernels using WebGL shaders.

D2Q9 Lattice Formulation

The standard D2Q9 model discretizes 2D space into a square lattice where fluid packets travel in nine discrete directions \(\mathbf{e}_i\) (\(i \in \{0, \dots, 8\}\)):

  • \(\mathbf{e}_0 = (0, 0)\)
  • \(\mathbf{e}_{1, 3} = (\pm 1, 0)\), \(\mathbf{e}_{2, 4} = (0, \pm 1)\)
  • \(\mathbf{e}_{5, 7} = (\pm 1, \pm 1)\), \(\mathbf{e}_{6, 8} = (\mp 1, \pm 1)\)

Each direction has an associated lattice weight \(w_i\):

  • \(w_0 = 4/9\)
  • \(w_{1..4} = 1/9\)
  • \(w_{5..8} = 1/36\)

Macroscopic Quantities

Macroscopic fluid density \(\rho\) and momentum \(\rho \mathbf{u} = (\rho u_x, \rho u_y)\) at cell \((x, y)\) are derived from the directional distribution functions \(f_i\):

\[\rho = \sum_{i=0}^{8} f_i\] \[\mathbf{u} = \frac{1}{\rho} \sum_{i=0}^{8} f_i \mathbf{e}_i\]

BGK Collision and Equilibrium

The BGK approximation relaxes populations toward a local Maxwell-Boltzmann equilibrium distribution \(f_i^{eq}\):

\[f_i^{eq} = w_i \rho \left(1 + 3(\mathbf{e}_i \cdot \mathbf{u}) + \frac{9}{2}(\mathbf{e}_i \cdot \mathbf{u})^2 - \frac{3}{2}(\mathbf{u} \cdot \mathbf{u})\right)\]

The post-collision state \(f_i^*\) is governed by the single relaxation time parameter \(\tau\):

\[f_i^*(x, y) = f_i(x, y) - \frac{1}{\tau} (f_i(x, y) - f_i^{eq}(x, y))\]

Fusing Streaming and Collision on the GPU

Standard LBM splits execution into two steps: streaming \(f_i(x + \mathbf{e}_i, t + \Delta t) = f_i^*(x, t)\) and collision. In a GPU computing environment, splitting these operations incurs high memory bandwidth overhead.

The most efficient approach uses a pull-streaming scheme fused with the BGK collision in a single kernel pass:

  1. Determine the source coordinate \((x - e_{ix}, y - e_{iy})\) for each velocity direction \(i\).
  2. Read the corresponding distribution functions from the source locations.
  3. Compute the local density \(\rho\) and velocity components \((u_x, u_y)\).
  4. Compute \(f_i^{eq}\) for all 9 directions.
  5. Relax the distribution functions toward equilibrium and write the output into a double-buffered grid.

Implementing the Kernel in gpu.js

In gpu.js, three-dimensional kernels can output arrays with dimensions [width, height, 9]. The thread indices are accessed via this.thread.x, this.thread.y, and this.thread.z.

Kernel Definition

import { GPU } from 'gpu.js';

const gpu = new GPU();

const width = 256;
const height = 256;
const tau = 0.6; // Relaxation time (viscosity = (2*tau - 1)/6)

const lbmKernel = gpu.createKernel(function(grid, tau, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;
    const i = this.thread.z;

    // Lattice velocities (cx, cy)
    // 0: (0,0), 1: (1,0), 2: (0,1), 3: (-1,0), 4: (0,-1)
    // 5: (1,1), 6: (-1,1), 7: (-1,-1), 8: (1,-1)
    const cx = [0, 1, 0, -1, 0, 1, -1, -1, 1];
    const cy = [0, 0, 1, 0, -1, 1, 1, -1, -1];
    const w  = [
        4.0 / 9.0,
        1.0 / 9.0, 1.0 / 9.0, 1.0 / 9.0, 1.0 / 9.0,
        1.0 / 36.0, 1.0 / 36.0, 1.0 / 36.0, 1.0 / 36.0
    ];

    // 1. Pull Streaming: fetch populations from neighbor cells
    // Apply periodic boundary conditions using modulo arithmetic
    let f0 = grid[(x - cx[0] + width) % width][(y - cy[0] + height) % height][0];
    let f1 = grid[(x - cx[1] + width) % width][(y - cy[1] + height) % height][1];
    let f2 = grid[(x - cx[2] + width) % width][(y - cy[2] + height) % height][2];
    let f3 = grid[(x - cx[3] + width) % width][(y - cy[3] + height) % height][3];
    let f4 = grid[(x - cx[4] + width) % width][(y - cy[4] + height) % height][4];
    let f5 = grid[(x - cx[5] + width) % width][(y - cy[5] + height) % height][5];
    let f6 = grid[(x - cx[6] + width) % width][(y - cy[6] + height) % height][6];
    let f7 = grid[(x - cx[7] + width) % width][(y - cy[7] + height) % height][7];
    let f8 = grid[(x - cx[8] + width) % width][(y - cy[8] + height) % height][8];

    // 2. Macroscopic density
    let rho = f0 + f1 + f2 + f3 + f4 + f5 + f6 + f7 + f8;

    // 3. Macroscopic velocity
    let ux = (f1 + f5 + f8 - (f3 + f6 + f7)) / rho;
    let uy = (f2 + f5 + f6 - (f4 + f7 + f8)) / rho;

    let uSq = ux * ux + uy * uy;

    // 4. Equilibrium distribution for the current thread index (i)
    let ci_u = cx[i] * ux + cy[i] * uy;
    let feq = w[i] * rho * (1.0 + 3.0 * ci_u + 4.5 * ci_u * ci_u - 1.5 * uSq);

    // Get the streamed distribution corresponding to thread i
    let fi = 0.0;
    if (i === 0) fi = f0;
    else if (i === 1) fi = f1;
    else if (i === 2) fi = f2;
    else if (i === 3) fi = f3;
    else if (i === 4) fi = f4;
    else if (i === 5) fi = f5;
    else if (i === 6) fi = f6;
    else if (i === 7) fi = f7;
    else if (i === 8) fi = f8;

    // 5. BGK Relaxation
    return fi - (1.0 / tau) * (fi - feq);
})
.setOutput([width, height, 9])
.setPipeline(true)
.setImmutable(true);

Ping-Pong Buffer Execution Loop

WebGL prohibits reading and writing to the same texture during a render pass. Double buffering (ping-ponging) alternates input and output textures between iterations.

// Initialize grid with uniform equilibrium (rho = 1.0, u = [0, 0])
function createInitialGrid(w, h) {
    const weights = [4/9, 1/9, 1/9, 1/9, 1/9, 1/36, 1/36, 1/36, 1/36];
    const data = [];
    for (let x = 0; x < w; x++) {
        data[x] = [];
        for (let y = 0; y < h; y++) {
            data[x][y] = [];
            for (let i = 0; i < 9; i++) {
                // Initialize with slight velocity perturbation to trigger dynamics
                const pert = (y === Math.floor(h / 2)) ? 0.01 : 0.0;
                data[x][y][i] = weights[i] * (1.0 + 3.0 * pert);
            }
        }
    }
    return data;
}

let currentGrid = createInitialGrid(width, height);

function stepSimulation(iterations) {
    for (let step = 0; step < iterations; step++) {
        const nextGrid = lbmKernel(currentGrid, tau, width, height);
        
        // Delete previous GPU texture to prevent memory leaks when pipeline is enabled
        if (typeof currentGrid.delete === 'function') {
            currentGrid.delete();
        }
        
        currentGrid = nextGrid;
    }
}

Performance Considerations

  • Pipeline Mode: Enabling .setPipeline(true) ensures intermediate frame buffers remain on the GPU as textures, eliminating GPU-to-CPU data transfer overhead.
  • Immutable Textures: Utilizing .setImmutable(true) allows gpu.js to optimize frame buffer binding and avoids automatic memory cloning.
  • Coordinate Branching: Modulo operations (x + dx + width) % width can introduce overhead inside inner shader loops; storing coordinates directly via clamped textures or using explicit bounds checks can further optimize hardware execution.
