How GPU.js Converts JavaScript to GLSL

GPU.js accelerates mathematical operations by compiling standard JavaScript functions into GLSL (OpenGL Shading Language) shaders that run directly on the GPU. This transpilation process relies on parsing the JavaScript function into an Abstract Syntax Tree (AST), performing static type inference to satisfy GLSL's strict typing requirements, translating JavaScript arithmetic and Math functions into hardware-native GLSL operations, and compiling the resulting shader via WebGL.

1. Function Stringification and AST Generation

The conversion begins by taking the JavaScript kernel function and converting it into a string using Function.prototype.toString(). GPU.js then uses a JavaScript parser (such as Acorn) to analyze the source code and generate an Abstract Syntax Tree (AST). The AST breaks down the code into a hierarchical tree of programmatic nodes, representing statements, variable declarations, binary expressions, and function calls.

2. Type Inference

JavaScript is dynamically typed, whereas GLSL requires strict, static typing where every variable must be explicitly defined (e.g., float, int, vec4). Because GLSL cannot interpret dynamic JavaScript types, GPU.js traverses the AST to infer the data types of variables and inputs:

  • Float-first Arithmetic: By default, GPU.js treats numbers in mathematical expressions as 32-bit floating-point values (float), aligning with standard GPU hardware architecture.
  • Argument Inspection: Input arrays and matrix dimensions passed to the kernel at runtime are analyzed to determine whether they should be represented as uniform textures or arrays.
  • Variable Tracking: Local variable declarations (let, const, var) are inspected based on their initial values and assigned a corresponding GLSL type for their scope.

3. Syntax and Operation Translation

Once types are established, GPU.js walks through the AST nodes and translates JavaScript constructs into valid GLSL code:

  • Mathematical Functions: Native JavaScript Math object methods are replaced with native GLSL functions. For example, Math.sin(x) maps directly to sin(x), Math.floor(x) maps to floor(x), and Math.pow(x, y) translates to pow(x, y).
  • Arithmetic Operators: Standard operators (+, -, *, /, %) are converted to their GLSL equivalents, with automatic type-casting inserted if operations combine differing types (such as adding an integer to a float).
  • Control Flow: Standard loops (for, while) and conditional branches (if, else) are converted into C-style control structures accepted by GLSL.
  • Thread Indexing: The special GPU.js context variables, such as this.thread.x and this.thread.y, are mapped to coordinate calculations derived from the fragment's pixel position via gl_FragCoord.

4. Fragment Shader Assembly and Compilation

After the function logic is fully translated, GPU.js wraps the resulting code inside a WebGL fragment shader template. This template includes the required precision qualifiers, uniforms for input data, and routines for decoding data textures.

The generated GLSL string is then passed to the WebGL API (gl.shaderSource and gl.compileShader). The graphics driver compiles this code into GPU machine instructions, enabling the JavaScript math logic to execute in parallel across thousands of GPU cores.
