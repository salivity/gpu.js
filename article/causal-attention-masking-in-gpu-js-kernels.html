Causal Attention Masking in GPU.js Kernels

Causal attention masking for generative language models can be implemented directly within a gpu.js kernel. By leveraging the WebGL-accelerated parallel execution of gpu.js, developers can compute scaled dot-product attention while enforcing autoregressive constraints. This article explains how causal masking operates, how to map token coordinates to gpu.js thread dimensions, and how to write an efficient kernel that masks future tokens using browser-based hardware acceleration.

How Causal Attention Masking Works

In autoregressive generative models like GPT, a token at index \(i\) must only attend to itself and preceding tokens at indices \(j \le i\). During the computation of the attention score matrix:

\[\text{Scores} = \frac{QK^T}{\sqrt{d_k}}\]

A causal mask applies a large negative value (such as \(-10000.0\) or \(-\infty\)) to all elements where \(j > i\). When the subsequent softmax function is applied across the row, these masked positions evaluate to zero probability, preventing future tokens from influencing the current prediction.

Thread Mapping in gpu.js

gpu.js maps arrays into 2D or 3D execution grids using WebGL fragment shaders. Within a 2D kernel:

  • this.thread.x corresponds to the column index (Key position \(j\)).
  • this.thread.y corresponds to the row index (Query position \(i\)).

Because of this layout, enforcing an upper-triangular mask requires checking whether the column index exceeds the row index.

Kernel Implementation

The following example demonstrates computing the scaled dot-product attention scores with an integrated causal mask in gpu.js:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const seqLength = 4;
const dK = 64;
const sqrtDk = Math.sqrt(dK);

const causalAttentionKernel = gpu.createKernel(function(Q, K, seqLen, scale) {
    const j = this.thread.x; // Key index (column)
    const i = this.thread.y; // Query index (row)

    // Apply causal mask: mask out future tokens where key index > query index
    if (j > i) {
        return -10000.0;
    }

    // Dot product between Q[i] and K[j]
    let sum = 0.0;
    for (let d = 0; d < 64; d++) {
        sum += Q[i][d] * K[j][d];
    }

    return sum / scale;
})
.setOutput([seqLength, seqLength]);

Technical Considerations for gpu.js

  1. Infinity Handling in WebGL: Standard WebGL shaders frequently encounter compatibility issues with -Infinity. Using a sufficiently large negative constant such as -10000.0 or -1e9 prevents NaN propagation while ensuring \(e^x \approx 0\) during the softmax step.
  2. Dynamic Loop Bounds: WebGL shaders require compile-time loop limits. If embedding the dot product loop directly inside the causal masking kernel, dimension parameters (like \(d_k\)) must be known at initialization or hardcoded in the loop boundary.
  3. Pipelining with Softmax: To optimize performance, the output of this kernel can be passed as a texture (pipeline: true) directly into a subsequent row-wise softmax kernel, avoiding expensive data readbacks to the CPU.
