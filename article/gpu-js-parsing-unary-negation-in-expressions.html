GPU.js Parsing Unary Negation in Expressions

This article explains how the GPU.js transpiler interprets, decomposes, and generates WebGL-compatible GLSL code when a unary negation operator (-) is applied to complex parenthesized expressions in JavaScript kernel functions. It covers the JavaScript AST generation step, the internal traversal logic used by GPU.js, GLSL precedence management, and type preservation for nested numeric operations.

JavaScript AST Generation

When a kernel function is passed to GPU.js, the library first parses the function into an Abstract Syntax Tree (AST) using the Acorn parser. In standard JavaScript AST formats (such as ESTree):

  • Parentheses do not produce an explicit ParenthesizedExpression node by default; instead, grouping is represented structurally by nesting the inner operation as the child of the outer operation.
  • A unary negation applied to grouped logic, such as -(a + b * c), generates a UnaryExpression node.
  • The UnaryExpression node contains metadata including operator: "-", prefix: true, and an argument property. The argument property points directly to the root of the inner complex structure (in this case, a BinaryExpression).

Because the grouping is captured by the hierarchy of the AST nodes, GPU.js inherently recognizes that the negation applies to the final evaluated value of the entire nested tree rather than just the first identifier.

AST Traversal and Node Handling

GPU.js processes the AST via internal visitor methods implemented inside its core compiler classes (typically inheriting from WebGLKernel or GLSLKernel). When encountering a UnaryExpression:

  1. Visitor Dispatch: The compiler calls its unary expression handler (e.g., astUnaryExpression).
  2. Operator Evaluation: The compiler verifies whether the operator is an allowed GLSL unary operator (-, +, or !).
  3. Recursive Resolution: The compiler passes the node's argument back to its generic AST dispatcher (astGeneric).

When resolving the child node, GPU.js evaluates whether the inner operation involves operations with equal or lower precedence than unary negation. If the argument is a complex subexpression—such as another BinaryExpression—the generator wraps the inner compiled string in explicit GLSL parentheses: -(...). This prevents the generated GLSL compiler from misinterpreting operator precedence.

Type Resolution and GLSL Output

GLSL enforces strict static typing, unlike JavaScript. Therefore, GPU.js must ensure that the negated compound expression maintains consistent numeric types:

  • Type Deduction: GPU.js tracks the return types of expressions during AST traversal. If the parenthesized operation yields a float, the unary minus must negate a float. If it resolves to an integer, it is negated as an integer.
  • Vector and Scalar Normalization: If the parenthesized expression evaluates to a vector calculation (e.g., in operations utilizing array outputs), GPU.js maps the negation across the resulting GLSL vector components or emits a native GLSL vector negation (-vec).
  • Emission: The final GLSL emission concatenates the negation symbol directly with the bracketed sub-tree string, producing valid shader code such as -(v_a + (v_b * v_c)).

By relying on tree nesting to define scope and enforcing parentheses during string assembly, GPU.js guarantees that complex parenthesized expressions retain their intended mathematical order of operations when executed on the GPU.
