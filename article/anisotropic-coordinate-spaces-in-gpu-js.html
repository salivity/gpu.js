Anisotropic Coordinate Spaces in gpu.js

This article explains how to handle anisotropic coordinate spaces—environments where spatial dimensions operate at radically different scales—using gpu.js. By translating discrete GPU thread indices into scaled continuous domains, passing dimension-specific transformation vectors, and mitigating single-precision floating-point artifacts in WebGL, developers can accurately execute physical simulations, financial models, and scientific calculations on highly non-uniform grids.

Thread Index Decoupling

In gpu.js, the execution grid is defined by the setOutput([x, y, z]) method. This configuration specifies the discrete compute dimensions—the total number of threads allocated on the GPU. Because hardware threads operate strictly on integer indices (this.thread.x, this.thread.y, this.thread.z), gpu.js does not inherently impose an isotropic (uniform) coordinate system.

To model an anisotropic domain, the physical coordinate space must be decoupled from the compute grid. The discrete thread indices are mapped to continuous, anisotropic coordinates using transformation coefficients inside the kernel function:

const kernel = gpu.createKernel(function(scaleX, scaleY, originX, originY) {
    const posX = originX + (this.thread.x * scaleX);
    const posY = originY + (this.thread.y * scaleY);
    
    // Kernel operations in anisotropic space
    return posX / posY;
}).setOutput([1024, 1024]);

In this setup, scaleX and scaleY represent the metric step size per thread (\(\Delta x\) and \(\Delta y\)). If dimension \(X\) covers a span of \(10^{-6}\) meters while dimension \(Y\) covers \(10^{3}\) meters, the threads can remain equally balanced in resolution while the algorithmic math reflects the actual scale variance.

Handling Radical Scale Discrepancies

When working with radically divergent scales, standard 32-bit floating-point arithmetic (GLSL highp float) poses numerical stability challenges. A direct computation combining extremely large and extremely small numbers can lead to catastrophic cancellation or underflow/overflow.

Coordinate Normalization

To prevent precision degradation, map all spatial dimensions to a normalized reference space \([0.0, 1.0]\) within the kernel before computing metric-dependent equations:

\[\hat{x} = \frac{\text{this.thread.x}}{\text{dimX} - 1}\] \[\hat{y} = \frac{\text{this.thread.y}}{\text{dimY} - 1}\]

Equations are then evaluated in their dimensionless or normalized form, and dimensional constants are aggregated into scalar dimensionless parameters (such as aspect ratios or Reynolds numbers) passed as uniforms.

Local Reference Frames

If the computation involves interactions between distant coordinate points (such as calculating Euclidean distance in an anisotropic grid), compute distance components independently along each axis using relative offsets:

const dx = (x2 - x1) * scaleX;
const dy = (y2 - y1) * scaleY;
const distanceSquared = (dx * dx) + (dy * dy);

This prevents scale divergence from dominating the lower-magnitude dimension during matrix manipulations or vector calculations.

Tensor Operations and Metric Tensors

For complex spatial transformations, such as non-Cartesian or warped anisotropic domains, gpu.js accommodates metric tensors passed as uniform matrices or flattened 1D/2D arrays.

By defining a metric tensor \(g_{ij}\) representing the non-uniform geometric properties of the space, spatial steps and gradient approximations inside the kernel are adjusted based on the direction of traversal:

\[ds^2 = g_{xx}dx^2 + 2g_{xy}dxdy + g_{yy}dy^2\]

This mathematical approach allows finite difference methods (FDM) and spatial differential operators (such as Laplacian or divergence calculations) to correctly weight derivative approximations when grid intervals vary drastically across axes:

\[\frac{\partial^2 u}{\partial x^2} \approx \frac{u_{i+1,j} - 2u_{i,j} + u_{i-1,j}}{\Delta x^2}\] \[\frac{\partial^2 u}{\partial y^2} \approx \frac{u_{i,j+1} - 2u_{i,j} + u_{i,j-1}}{\Delta y^2}\]

Passing \((\Delta x)^{-2}\) and \((\Delta y)^{-2}\) as precalculated uniforms ensures the GPU minimizes runtime division while accurately preserving the anisotropic behavior of the system.
