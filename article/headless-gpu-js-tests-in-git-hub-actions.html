Headless gpu.js Tests in GitHub Actions

Running gpu.js integration tests in GitHub Actions requires handling headless CI environments that lack physical graphics hardware. This guide explains how to configure a GitHub Actions workflow to run gpu.js tests headlessly by leveraging software-based WebGL rasterization, virtual framebuffers, and headless graphics libraries in an Ubuntu-based continuous integration runner.

The Challenge with GPU.js in CI

GPU.js relies on WebGL or native GPU access to accelerate JavaScript computations. Standard GitHub-hosted runners (ubuntu-latest) do not possess dedicated physical GPUs. When executing integration tests in these environments, attempting to initialize a WebGL context will fail unless fallback software rendering or headless implementations are explicitly configured.

Prerequisites

Depending on your test target, gpu.js runs in either a Node.js environment (via the gl package) or a headless browser (such as Chrome via Puppeteer or Playwright).

  1. For Node.js testing: Ensure gpu.js and gl (headless-gl) are declared in your package.json dependencies.
  2. For Browser testing: Ensure your runner starts Chromium with software rendering flags such as --use-gl=swiftshader or --use-gl=angle.

Node.js Headless Testing Workflow

When running tests directly in Node.js, headless-gl provides the WebGL context. On Linux, this requires system-level OpenGL and X11 libraries along with xvfb (X Virtual Framebuffer) to simulate a display server.

Create a workflow file at .github/workflows/gpu-tests.yml:

name: GPU.js Integration Tests

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install system dependencies for headless GL
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libgl1-mesa-dev \
            libxi-dev \
            libxext-dev \
            libgl1-mesa-glx \
            mesa-utils \
            xvfb

      - name: Install project dependencies
        run: npm ci

      - name: Run tests with Xvfb
        run: xvfb-run --auto-servernum --server-args="-screen 0 1024x768x24" npm test

Browser-Based Headless Testing Workflow

If your integration tests run inside a browser instance (such as Karma, Jest with Puppeteer, or Playwright), you must force the browser to use CPU-based rasterization (SwiftShader) instead of hardware acceleration.

Configure your browser launch arguments within your test configuration:

// Example Puppeteer launch configuration
const browser = await puppeteer.launch({
  headless: 'new',
  args: [
    '--no-sandbox',
    '--disable-setuid-sandbox',
    '--use-gl=swiftshader',
    '--enable-webgl',
  ]
});

Then, use the following minimal GitHub Actions workflow:

name: Browser GPU.js Tests

on: [push, pull_request]

jobs:
  test-browser:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Execute browser tests
        run: npm run test:browser
        env:
          CI: true

Validating GPU Fallback in Test Code

To ensure tests execute reliably regardless of hardware variations, configure the GPU instance to fall back gracefully if WebGL fails, or explicitly assert that the headless WebGL mode is active:

const { GPU } = require('gpu.js');

const gpu = new GPU({
  mode: 'headlessgl' // Forces use of headless-gl in Node environments
});

// Verify context initialization before running kernels
test('GPU.js initializes successfully in CI', () => {
  const kernel = gpu.createKernel(function () {
    return this.thread.x;
  }).setOutput([5]);

  const result = kernel();
  expect(Array.from(result)).toEqual([0, 1, 2, 3, 4]);
  gpu.destroy();
});

Using xvfb-run combined with SwiftShader or headless-gl provides a reliable pipeline that prevents WebGL initialization crashes and verifies your computational kernels directly inside standard GitHub Actions runners.
