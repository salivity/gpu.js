How GPU.js Emulates Parallel Execution on the CPU

GPU.js accelerates JavaScript calculations by compiling code to run on the GPU via WebGL, but it also features a robust CPU fallback mode for environments lacking graphics hardware. When operating strictly on the CPU, GPU.js maintains full API compatibility by compiling the same kernel logic into standard JavaScript. Instead of dispatching computation across thousands of physical hardware cores, it emulates parallel thread architectures using structured nested loops, mocked thread coordinate states, and direct memory manipulation via TypedArrays.

Transpiling Kernels into Nested Loops

When a kernel is compiled for the GPU, GPU.js parses the JavaScript Abstract Syntax Tree (AST) and converts the function into GLSL (OpenGL Shading Language). In CPU mode, the compilation pipeline takes a different path: it transforms the kernel function into an optimized, pure JavaScript function wrapped inside nested for loops.

The depth and bounds of these loops are defined by the kernel’s .setOutput() configuration:

  • A 1D output [x] compiles to a single loop iterating from 0 to x - 1.
  • A 2D output [x, y] creates an outer loop for y and an inner loop for x.
  • A 3D output [x, y, z] creates a three-level deep loop structure.

By iterating sequentially through every coordinate defined in the output domain, the single-threaded CPU sequentially walks through the exact coordinate matrix that a GPU would compute simultaneously.

Simulating the Thread Context

On hardware GPUs, individual threads implicitly know their position within the computational grid through built-in shader coordinates such as gl_FragCoord. To recreate this programming model in JavaScript, GPU.js exposes the this.thread interface (this.thread.x, this.thread.y, and this.thread.z).

Inside the CPU runner's generated loops, GPU.js updates the coordinate context before invoking the kernel logic for that specific iteration:

for (let y = 0; y < height; y++) {
  this.thread.y = y;
  for (let x = 0; x < width; x++) {
    this.thread.x = x;
    output[y * width + x] = kernelFunction.call(this);
  }
}

By binding the loop control variables to this.thread, the user's kernel code can access its execution coordinates without altering its logic, preserving complete code parity between GPU and CPU execution pathways.

Memory Allocation via TypedArrays

A critical factor in parallel processing is how memory is written and accessed. On the GPU, thread outputs write directly into memory structures like framebuffers or textures.

In CPU mode, GPU.js bypasses regular JavaScript arrays—which are dynamic, sparse, and non-contiguous in memory—in favor of native TypedArrays (such as Float32Array or Int32Array). Memory is pre-allocated as a single contiguous buffer matching the total size of the output matrix. During each loop iteration, GPU.js calculates the linear 1D memory offset:

\[\text{Index} = x + (y \times \text{width}) + (z \times \text{width} \times \text{height})\]

Writing the result of each simulated thread directly to a fixed memory address mirrors the independent write behavior of hardware threads while minimizing garbage collection overhead.

JIT Optimization and Thread Isolation

GPU threads are designed to run in isolation without access to external shared mutable states or complex JavaScript runtime features like closures and external scope variables. When GPU.js compiles the kernel for the CPU, this isolation enables host JavaScript engines (such as V8 in Chrome and Node.js, or SpiderMonkey in Firefox) to aggressively optimize the code.

Because the generated loop contains simple arithmetic, predictable memory writes to typed arrays, and no unexpected property lookups, the engine's Just-In-Time (JIT) compiler can optimize the loop into highly efficient machine code. In some environments, the JIT compiler can even apply SIMD (Single Instruction, Multiple Data) vectorization at the machine level, executing multiple numeric operations within a single CPU cycle.

Through this combination of AST-to-loop translation, state mocking via this.thread, contiguous memory layouts, and JIT-friendly code structures, GPU.js emulates the complete mental model of massively parallel thread execution strictly within a single-threaded CPU environment.
