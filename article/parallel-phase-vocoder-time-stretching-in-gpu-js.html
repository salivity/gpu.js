Parallel Phase Vocoder Time-Stretching in GPU.js

This article details how to accelerate phase vocoder time-stretching algorithms by offloading signal-processing computations to the GPU using GPU.js. You will learn the mathematical pipeline of the phase vocoder—including Short-Time Fourier Transform (STFT) decomposition, phase unwrapping, phase advancement, and inverse transformation—and how to translate these steps into parallel GPU compute kernels. By mapping independent frame transformations and frequency bin operations to WebGL fragment shaders via GPU.js, you can achieve high-performance audio time-stretching directly in JavaScript.

The Phase Vocoder Pipeline

A phase vocoder alters the duration of an audio signal without affecting its pitch by decoupling the time and frequency domains. The process follows four distinct stages:

  1. Analysis (STFT): Windowed frames of the input signal are extracted using an analysis hop size \(R_a\) and transformed into frequency domain representations via the Discrete Fourier Transform (DFT), producing magnitude and phase spectra.
  2. Phase Calculation: For each frequency bin, the phase difference between successive frames is computed to estimate the instantaneous frequency.
  3. Phase Propagation (Synthesis Phase): The instantaneous frequencies are accumulated across an altered synthesis hop size \(R_s = \alpha \cdot R_a\) (where \(\alpha\) is the stretch factor) to prevent phase cancellation artifacts.
  4. Synthesis (ISTFT & Overlap-Add): Modified complex spectra are converted back into the time domain using the Inverse Discrete Fourier Transform (IDFT) and windowed frames are summed with overlap-add synthesis.

Because frequency bins and frame transformations execute identical operations independently across large arrays, they are prime candidates for massive data parallelism.

Data Representation for GPU.js

GPU.js maps JavaScript numerical arrays to GPU textures. To process audio:

  • Store the windowed time-domain audio as a 2D matrix where the dimension \([N, M]\) represents \(N\) frames of window size \(M\).
  • Split complex spectral data into two separate 2D buffers: real parts and imaginary parts, or magnitudes and phases.
const { GPU } = require('gpu.js');
const gpu = new GPU();

const FRAME_SIZE = 1024; // M (Window Size)
const NUM_FRAMES = 512;  // N (Number of frames)
const PI = 3.141592653589793;

Step 1: Parallel Analysis Kernel (DFT)

While Fast Fourier Transform (FFT) algorithms are optimal for CPUs, a direct DFT can be executed with high parallelism on a GPU when frame counts are moderate. GPU.js executes this kernel across all frames and frequency bins simultaneously.

const computeDFT = gpu.createKernel(function(audioFrames, frameSize) {
    const k = this.thread.x; // Frequency bin index (0 to frameSize - 1)
    const frameIdx = this.thread.y; // Frame index

    let real = 0.0;
    let imag = 0.0;

    for (let n = 0; n < frameSize; n++) {
        // Apply Hann window and Fourier basis functions
        const windowValue = 0.5 * (1.0 - Math.cos((2.0 * 3.141592653589793 * n) / (frameSize - 1.0)));
        const sample = audioFrames[frameIdx][n] * windowValue;
        const angle = (2.0 * 3.141592653589793 * k * n) / frameSize;

        real += sample * Math.cos(angle);
        imag -= sample * Math.sin(angle);
    }

    const magnitude = Math.sqrt(real * real + imag * imag);
    const phase = Math.atan2(imag, real);

    // Return magnitude and phase packed or as components
    return [magnitude, phase];
}, {
    output: [FRAME_SIZE, NUM_FRAMES],
    pipeline: true // Keep result in GPU memory
});

Step 2: Parallel Phase Accumulation

The synthesis phase \(\theta_{synth}(m, k)\) for frame \(m\) and bin \(k\) requires calculating the deviation of the true frequency from the nominal frequency \(\omega_k\):

  1. Calculate phase difference: \(\Delta \Phi = \phi(m, k) - \phi(m - 1, k)\).
  2. Calculate nominal bin phase advance: \(\Delta \Phi_{nominal} = \frac{2\pi k R_a}{M}\).
  3. Unwrap the difference into \((-\pi, \pi]\): \(\delta\Phi = \Delta \Phi - \Delta \Phi_{nominal} - 2\pi \cdot \text{round}\left(\frac{\Delta \Phi - \Delta \Phi_{nominal}}{2\pi}\right)\).
  4. Compute instantaneous frequency: \(\hat{\omega} = \omega_k + \frac{\delta\Phi}{R_a}\).
  5. Accumulate synthesis phase: \(\theta_{synth}(m, k) = \theta_{synth}(m - 1, k) + R_s \cdot \hat{\omega}\).

Because each frame depends sequentially on the previous frame's synthesized phase, accumulate phases frame-by-frame on the GPU or parallelize the cumulative sum along time using prefix-sum techniques. For sequential frame processing on the GPU:

const advancePhaseKernel = gpu.createKernel(function(currentPhase, prevPhase, prevSynthPhase, stretchFactor, Ra, M) {
    const k = this.thread.x;
    const pi = 3.141592653589793;

    const nominalPhaseAdvance = (2.0 * pi * k * Ra) / M;
    let phaseDiff = currentPhase[k] - prevPhase[k] - nominalPhaseAdvance;

    // Phase unwrapping into [-PI, PI]
    phaseDiff = phaseDiff - (2.0 * pi * Math.floor((phaseDiff + pi) / (2.0 * pi)));

    // Calculate instantaneous frequency
    const trueFreq = (nominalPhaseAdvance + phaseDiff) / Ra;

    // Advance phase for synthesis hop
    const Rs = Ra * stretchFactor;
    return prevSynthPhase[k] + (Rs * trueFreq);
}, {
    output: [FRAME_SIZE]
});

Step 3: Parallel Synthesis Kernel (IDFT)

Once the synthesis phase \(\theta_{synth}\) is resolved, it is combined with the original magnitudes to reconstruct the time-domain frames:

const computeIDFT = gpu.createKernel(function(magnitudes, synthPhases, frameSize) {
    const n = this.thread.x; // Time sample index (0 to frameSize - 1)
    const frameIdx = this.thread.y; // Frame index

    let signal = 0.0;
    const pi = 3.141592653589793;

    for (let k = 0; k < frameSize; k++) {
        const mag = magnitudes[frameIdx][k];
        const phase = synthPhases[frameIdx][k];

        // Polar to rectangular form
        const real = mag * Math.cos(phase);
        const imag = mag * Math.sin(phase);

        const angle = (2.0 * pi * k * n) / frameSize;
        signal += real * Math.cos(angle) - imag * Math.sin(angle);
    }

    // Windowing for synthesis
    const windowValue = 0.5 * (1.0 - Math.cos((2.0 * pi * n) / (frameSize - 1.0)));
    return (signal / frameSize) * windowValue;
}, {
    output: [FRAME_SIZE, NUM_FRAMES]
});

Step 4: Overlap-Add Reconstruction

The synthesized time frames must be placed at synthesis hop intervals \(R_s\):

  1. Download the reconstructed frame buffer using .toArray() from GPU memory back to CPU memory.
  2. Allocate an output array of length \((N - 1) \cdot R_s + M\).
  3. Sum each synthesized frame \(m\) into the output buffer starting at index \(m \cdot R_s\).
  4. Normalize the resulting waveform by the overlapping window gain factor.

Performance Considerations

  • Pipeline Mode: Always set { pipeline: true } on intermediate GPU.js kernels to retain data inside VRAM as textures rather than copying it over the PCIe bus between CPU and GPU.
  • Complexity vs. Threading: An \(O(M^2)\) direct DFT per frame on the GPU often outperforms an \(O(M \log M)\) CPU-based FFT when processing thousands of frequency bins across hundreds of frames in parallel. For large frame sizes (\(M > 2048\)), consider structuring a multi-pass Cooley-Tukey FFT kernel in GPU.js to reduce thread iteration counts.
  • Precision: WebGL shaders frequently use 32-bit floating-point precision (float). Phase accumulation across many frames can drift over long files; periodically normalize phases to the range \([-\pi, \pi]\) to prevent loss of precision in the GPU calculations.
