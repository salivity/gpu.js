Image Padding and Clamping in GPU.js Convolutions

Applying convolution kernels to images using GPU.js requires handling out-of-bounds pixel access along image borders. When neighbor sampling offsets cross the boundary of an image matrix, shaders can sample undefined memory or return artifacts. This guide demonstrates how to implement zero padding and edge clamping directly within GPU.js kernel functions to ensure seamless 2D image processing.

The Border Problem in Convolutions

A standard 2D convolution kernel (such as a 3x3 blur, sharpen, or Sobel filter) calculates each output pixel by weighting adjacent input pixels relative to a center coordinate (x, y). When calculating pixels on the perimeter where x = 0, y = 0, x = width - 1, or y = height - 1, offset indices become negative or exceed the image dimensions.

In WebGL and GPU.js, accessing an array index out of bounds does not throw a traditional JavaScript error; instead, it yields unexpected results or black artifacts. You must handle boundary logic inside the kernel using conditional checks or mathematical constraints.

Method 1: Edge Clamping (Replicate Padding)

Edge clamping restricts sample coordinates to the valid dimensions of the image. Any sample request falling outside the border is mapped back to the nearest valid pixel on the edge. This avoids creating dark fringes around filtered images.

Because GPU.js compiles JavaScript into WebGL GLSL shaders, using Math.max and Math.min maps directly to hardware-accelerated GLSL clamp operations.

const gpu = new GPU();

const clampConvolution = gpu.createKernel(function(image, kernel, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;
    let sum = 0;

    // Standard 3x3 convolution
    for (let ky = -1; ky <= 1; ky++) {
        for (let kx = -1; kx <= 1; kx++) {
            // Clamp coordinates to image boundaries
            const sampleX = Math.min(Math.max(x + kx, 0), width - 1);
            const sampleY = Math.min(Math.max(y + ky, 0), height - 1);

            const pixel = image[sampleY][sampleX];
            const weight = kernel[ky + 1][kx + 1];

            sum += pixel * weight;
        }
    }

    return sum;
}).setOutput([width, height]);

Method 2: Zero Padding (Constant Padding)

Zero padding treats any coordinate outside the image boundary as having a value of 0 (black or transparent). This method is commonly used in convolutional neural networks (CNNs) to preserve spatial dimensions without repeating edge data.

In GPU.js, zero padding is implemented using an if-else condition to test whether the calculated coordinate is within the valid range before sampling the array.

const zeroPaddingConvolution = gpu.createKernel(function(image, kernel, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;
    let sum = 0;

    for (let ky = -1; ky <= 1; ky++) {
        for (let kx = -1; kx <= 1; kx++) {
            const sampleX = x + kx;
            const sampleY = y + ky;

            // Check if sampling coordinates fall within the valid bounds
            if (sampleX >= 0 && sampleX < width && sampleY >= 0 && sampleY < height) {
                const pixel = image[sampleY][sampleX];
                const weight = kernel[ky + 1][kx + 1];
                sum += pixel * weight;
            }
            // Out-of-bounds coordinates implicitly add 0 to the sum
        }
    }

    return sum;
}).setOutput([width, height]);

Performance and Pipeline Considerations

  1. Avoid Branch Divergence: Edge clamping via Math.min and Math.max is generally faster across GPU architectures than branching (if/else) because GPUs execute arithmetic instructions uniformly across thread warps.
  2. Dimension Arguments: Always pass width and height as kernel arguments rather than relying on dynamic lookups like .length, which are not supported within the GPU execution context.
  3. Multi-Channel Processing: If handling RGBA image data, apply clamping logic to the spatial (x, y) coordinates while preserving the color channel index (0 to 3).
