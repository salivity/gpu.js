How gpu.js Compiles JS While Loops to GLSL

This article explores how the gpu.js compiler parses JavaScript while loops and transforms them into valid OpenGL Shading Language (GLSL) code. It covers the abstract syntax tree (AST) traversal, type inference, conditional expression translation, and how gpu.js addresses target-specific WebGL constraints to ensure GPU-compatible iteration.

1. Abstract Syntax Tree (AST) Parsing

gpu.js begins compilation by serializing the kernel JavaScript function and passing it through an internal parser (such as Acorn) to produce an Abstract Syntax Tree (AST).

When the parser encounters a JavaScript while loop, it identifies a WhileStatement node. This node consists of two main properties:

  • test: The condition evaluated before each iteration.
  • body: The block of code executed when the test evaluates to true.

The compiler’s code generator traverses this node using a visitor pattern, mapping the dynamic JavaScript structure to a static GLSL equivalent.

2. Condition Normalization and Boolean Coercion

In JavaScript, loop conditions rely on dynamic truthiness (e.g., while (count) terminates when count becomes 0). GLSL, however, strictly enforces that all loop conditions must evaluate to a native scalar bool.

During code generation, gpu.js analyzes the AST's test expression:

  • Explicit Booleans: Expressions such as i < 10 map directly to GLSL relational operations.
  • Implicit Truthiness: Non-boolean identifiers or expressions are converted into explicit boolean checks. For instance, an integer counter while (n) is rewritten in GLSL as while (n != 0) or while (n > 0), matching GLSL's strict typing rules.

3. Type Inference and Variable Tracking

GLSL requires all variables to be statically typed before or upon assignment. Because a while loop frequently modifies variables declared outside its scope (such as accumulators or counters), gpu.js must determine their types prior to writing the loop.

The compiler performs an initial inference pass over the kernel function to track variable assignments. If an outer variable is modified inside the WhileStatement body, gpu.js ensures:

  1. The variable is declared with an explicit GLSL type (int, float, etc.) prior to the loop.
  2. Any assignments within the loop body cast values appropriately (e.g., converting a JavaScript floating-point number into a GLSL float).

4. Constructing the GLSL Loop Structure

In WebGL 2.0 (GLSL ES 3.00), dynamic loops are natively supported. The code generator writes the AST WhileStatement directly into a standard GLSL while loop:

while (condition) {
    // Transpiled body statements
}

If the target environment is restricted to WebGL 1.0 (GLSL ES 1.00), dynamic while loops face strict hardware and specification constraints. In GLSL ES 1.00, loop indices and iteration limits often require constant expressions to permit static loop unrolling by graphics drivers.

To overcome these limitations in constrained targets, gpu.js can transform unbounded or dynamic while loops into fixed for loops bounded by a predefined maximum iteration threshold, using an internal break statement:

for (int i = 0; i < MAX_ITERATIONS; i++) {
    if (!condition) {
        break;
    }
    // Transpiled body statements
}

5. Loop Body Transpilation

Finally, gpu.js recursively translates the statements contained in the AST's body block. JavaScript statements like break and continue map directly to their identical GLSL keywords. Any mathematical operators or built-in functions (such as Math.sin or Math.floor) used inside the loop body are substituted with their native GLSL counterparts (sin, floor) to produce optimized, hardware-accelerated shader code.
