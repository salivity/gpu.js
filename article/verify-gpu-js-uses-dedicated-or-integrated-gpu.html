Verify GPU.js Uses Dedicated or Integrated GPU

When running computationally intensive tasks with GPU.js on a multi-GPU system, JavaScript execution might silently default to a low-power integrated GPU (iGPU) rather than a high-performance dedicated GPU (dGPU). Because GPU.js operates on top of WebGL in browser environments or headless contexts in Node.js, you can determine exactly which physical graphics card executes your kernels by querying the underlying WebGL context's unmasked renderer information or by monitoring hardware activity at the operating system level.

Query the WebGL Context via GPU.js

GPU.js exposes its underlying graphics context through the context property on the main GPU instance. You can interrogate this context using the WEBGL_debug_renderer_info extension to retrieve the unmasked vendor and renderer strings of the active device.

const { GPU } = require('gpu.js'); // or imported via <script> tag in the browser
const gpu = new GPU();

// Create a simple kernel to ensure the context is initialized
const kernel = gpu.createKernel(function() {
    return this.thread.x;
}).setOutput([1]);

kernel();

// Inspect the underlying rendering context
const gl = gpu.context;
const debugInfo = gl.getExtension('WEBGL_debug_renderer_info');

if (debugInfo) {
    const vendor = gl.getParameter(debugInfo.UNMASKED_VENDOR_WEBGL);
    const renderer = gl.getParameter(debugInfo.UNMASKED_RENDERER_WEBGL);
    
    console.log('Vendor:', vendor);
    console.log('Renderer:', renderer);
} else {
    console.log('WEBGL_debug_renderer_info is unavailable or masked by browser privacy settings.');
}

Interpreting the Renderer Output

  • Integrated GPU (iGPU): The renderer string typically displays Intel HD/UHD/Iris Graphics, AMD Radeon Vega Mobile, or Apple M-series integrated cores.
  • Dedicated GPU (dGPU): The renderer string displays discrete chips such as NVIDIA GeForce/RTX/Quadro or AMD Radeon RX.

If the extension returns generic names like "WebKit WebGL" or "Mesa OffScreen," your browser or environment has enabled fingerprinting protection, masking direct hardware identifiers.

Verify Kernel Execution Mode

Before checking hardware identity, confirm that GPU.js actually executed on WebGL rather than falling back to the CPU. If WebGL fails or errors occur during shader compilation, GPU.js automatically switches to pure JavaScript execution.

// Check the execution mode of the instance
console.log('Active Mode:', gpu.mode); // Expected output: 'gpu'

// Check the kernel execution mode
console.log('Kernel Subpath:', kernel.subpath); // Expected output: 'webgl' or 'webgl2'

If gpu.mode reports 'cpu', the pipeline did not execute on any GPU.

Requesting the Dedicated GPU

If the renderer shows that execution occurs on the integrated GPU, you can explicitly request the high-performance adapter when creating the GPU instance by passing context attributes:

const gpu = new GPU({
    mode: 'gpu',
    webGl: {
        powerPreference: 'high-performance'
    }
});

Setting powerPreference: 'high-performance' prompts the browser and operating system compositor to activate the discrete GPU rather than the power-saving integrated processor.

Real-Time Hardware Monitoring

Software queries can occasionally reflect the adapter associated with the display compositor rather than the compute engine. To verify execution with absolute certainty:

  1. Write a kernel that loops over a large dataset (setOutput([1000000])) repeatedly in a requestAnimationFrame loop or setInterval.
  2. Open your operating system monitor:
    • Windows: Open Task Manager (Ctrl + Shift + Esc), navigate to the Performance tab, and monitor GPU 0 (iGPU) versus GPU 1 (dGPU) under the 3D or Compute graphs.
    • macOS: Open Activity Monitor and navigate to the GPU History window (Cmd + 4).
    • Linux: Run nvidia-smi -l 1 for NVIDIA hardware or radeontop for AMD hardware.
  3. Observe which physical device registers utilization spikes while the GPU.js pipeline is running.
