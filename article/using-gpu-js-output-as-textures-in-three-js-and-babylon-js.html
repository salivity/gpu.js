Using GPU.js Output as Textures in Three.js and Babylon.js

Graphical output generated by GPU.js can directly serve as dynamic textures in both Three.js and Babylon.js 3D scenes. By configuring GPU.js kernels to run in graphical mode, computational results render onto an internal HTML canvas element. Both Three.js and Babylon.js provide dedicated texture wrappers capable of consuming this canvas element, allowing real-time mathematical simulations, procedural patterns, and cellular automata computed on the GPU to project onto 3D meshes.

Configuring GPU.js for Graphical Output

To produce visual output rather than raw numerical arrays, GPU.js must be configured with graphical mode enabled:

const gpu = new GPU();
const renderKernel = gpu.createKernel(function() {
    // Math operations mapped to normalized colors (0.0 to 1.0)
    this.color(this.thread.x / 512, this.thread.y / 512, 0.5, 1);
})
.setOutput([512, 512])
.setGraphical(true);

renderKernel();
const canvas = renderKernel.canvas;

Inside a graphical kernel, this.color(r, g, b, a) sets the pixel values for each coordinate, outputting the result directly to renderKernel.canvas.

Using the Output in Three.js

Three.js natively supports canvas-based textures via THREE.CanvasTexture. To map the GPU.js canvas to a mesh:

  1. Create a THREE.CanvasTexture passing renderKernel.canvas as the source.
  2. Assign the texture to a material, such as THREE.MeshBasicMaterial or THREE.MeshStandardMaterial.
  3. Call renderKernel() in the animation loop to update the compute state.
  4. Set texture.needsUpdate = true after each execution to tell Three.js to re-upload the canvas buffer to the GPU.
const texture = new THREE.CanvasTexture(renderKernel.canvas);
const material = new THREE.MeshBasicMaterial({ map: texture });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

function animate() {
    requestAnimationFrame(animate);
    renderKernel();
    texture.needsUpdate = true;
    renderer.render(scene, camera);
}

Using the Output in Babylon.js

Babylon.js handles canvas inputs using BABYLON.HtmlElementTexture:

  1. Instantiate BABYLON.HtmlElementTexture, passing a unique name, the renderKernel.canvas, and the Babylon scene instance.
  2. Assign this texture to the diffuseTexture or albedoTexture channel of a standard or PBR material.
  3. In the render loop, execute renderKernel().
  4. Call texture.update() whenever the computation advances.
const texture = new BABYLON.HtmlElementTexture("gpuJsTexture", renderKernel.canvas, scene, {
    generateMipMaps: false,
    samplingMode: BABYLON.Texture.BILINEAR_SAMPLINGMODE
});

const material = new BABYLON.StandardMaterial("mat", scene);
material.diffuseTexture = texture;
mesh.material = material;

scene.registerBeforeRender(() => {
    renderKernel();
    texture.update();
});

Performance Considerations

While GPU.js executes on the GPU, it maintains its own distinct WebGL rendering context. When Three.js or Babylon.js reads the canvas, the browser must copy image data across these separate WebGL contexts. To maintain high frame rates:

  • Keep the GPU.js output resolution aligned to powers of two (e.g., 256x256, 512x512).
  • Disable mipmap generation on the target texture to avoid unnecessary GPU overhead during real-time updates.
  • Limit kernel executions strictly to frames where state changes occur.
