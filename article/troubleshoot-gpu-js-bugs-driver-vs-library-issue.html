Troubleshoot GPU.js Bugs: Driver vs Library Issue

When developing with gpu.js, unexpected outputs, kernel crashes, or silent failures can stem from either the library’s internal abstract syntax tree (AST) transpilation or quirks in your hardware's graphics drivers. This article outlines a methodical troubleshooting process to isolate the root cause, walking through CPU fallback execution, generated shader analysis, cross-environment validation, and WebGL diagnostic tools to definitively determine whether the issue lies within gpu.js or your graphics driver.

1. Test Against the CPU Fallback Mode

The fastest way to isolate the JavaScript-to-GLSL transpilation logic from GPU execution is to force gpu.js to run on the CPU.

Initialize your kernel using the CPU mode:

const gpu = new GPU({ mode: 'cpu' });
const kernel = gpu.createKernel(function() {
  // your kernel logic
}).setOutput([width, height]);

const result = kernel();
  • If the error persists on the CPU: The bug is strictly within gpu.js's JavaScript parser, your input math, or an unsupported JavaScript construct within the kernel body.
  • If it works on the CPU but fails on the GPU: The issue is located in the generated GLSL, WebGL context handling, or the GPU driver itself.

2. Force Different WebGL Contexts

gpu.js attempts to use WebGL 2 by default and falls back to WebGL 1 if unavailable. Hardware drivers often implement WebGL 1 and WebGL 2 specifications with varying stability.

Force specific rendering targets during initialization:

// Test explicitly with WebGL 2
const gpuWebgl2 = new GPU({ mode: 'webgl2' });

// Test explicitly with WebGL 1
const gpuWebgl = new GPU({ mode: 'webgl' });

If an operation succeeds in webgl but fails or crashes in webgl2 (or vice-versa), this strongly suggests an edge case in how the GPU driver handles specific GLSL features (such as 32-bit floating-point textures or uniform buffer objects) rather than a pure library logic bug.

3. Inspect and Validate the Generated GLSL

gpu.js converts your JavaScript function into a GLSL fragment shader. A bug in gpu.js may produce invalid or non-compliant GLSL that the driver rejects, or it may produce valid GLSL that triggers a compiler crash inside the driver.

Extract the generated GLSL string after building the kernel:

const kernel = gpu.createKernel(function(a) {
  return a[this.thread.x] * 2;
}).setOutput([512]);

// Trigger compilation
kernel.build([1, 2, 3]);

// Output the compiled shader code
console.log(kernel.getModes());
console.log(kernel.subKernels);
console.log(kernel.compiledFragmentShader);

Take the output of kernel.compiledFragmentShader and evaluate it:

  • Use an online GLSL validator (such as the Khronos WebGL Shader Validator or glslangValidator).
  • If the validator reports syntax errors or specification violations, gpu.js is at fault for generating invalid GLSL.
  • If the GLSL passes validation cleanly but crashes the context at runtime, the driver is likely failing during shader compilation or resource allocation.

4. Check Browser GPU Diagnostics

Browsers maintain detailed internal logs of GPU processes and driver crashes. If a kernel triggers a driver-level reset or context loss, it will be logged by the browser.

  • In Google Chrome or Microsoft Edge, navigate to chrome://gpu.
  • In Mozilla Firefox, navigate to about:support and scroll to the "Graphics" section.

Look for:

  • GPU process crash counts: A high or newly incremented count indicates that the driver crashed and restarted.
  • Reset notification strategy: Check if EXT_robustness reported a reset.
  • Problems Detected: Check if your specific GPU driver version is subject to active browser workarounds or blacklists.

5. Perform Cross-Device and Cross-Vendor Testing

GPU driver bugs are typically vendor-specific (e.g., specific to NVIDIA, AMD, Intel, or Apple Silicon) or platform-specific (Windows DirectX/ANGLE translation layer vs. macOS Metal vs. Linux native OpenGL).

  • Test the exact same gpu.js script across machines containing hardware from different GPU vendors.
  • If the failure occurs exclusively on a single GPU vendor or on a specific driver version, it is a driver-specific defect or an unhandled driver quirk.
  • If the behavior is identical across distinct platforms and vendors, the issue is an inherent bug or unhandled edge case within the gpu.js runtime.
