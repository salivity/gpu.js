4D Tensor Operations in GPU.js via 3D Outputs

GPU.js accelerates web applications by compiling JavaScript functions into WebGL shaders, but it natively limits output dimensions to a maximum of three axes ([x, y, z]). When working with deep learning models, batch image processing, or physics simulations requiring four-dimensional tensors (such as [batch, channels, height, width]), developers must bypass this restriction. This article details how to execute 4D tensor operations in GPU.js by decomposing the fourth dimension and mapping it across a standard 3D execution grid.

The Dimension Folding Strategy

GPU.js defines kernel grids through the setOutput([width, height, depth]) method. To process a 4D tensor with shape [B, C, H, W] (Batch, Channel, Height, Width):

  1. Retain spatial axes: Assign W to the X-axis and H to the Y-axis.
  2. Decompose and combine non-spatial axes: Combine B and C into a single composite dimension assigned to the Z-axis, with a total depth of B * C.
  3. Decode coordinates in the kernel: Within the GPU kernel, decode the combined index back into the original 4D coordinates using integer division and modulo arithmetic.

Given an execution index along the Z-axis (this.thread.z), the original batch index b and channel index c are retrieved using:

  • \(c = \text{this.thread.z} \pmod C\)
  • \(b = \lfloor \text{this.thread.z} / C \rfloor\)

Implementation Example

The following code demonstrates element-wise addition across two 4D tensors using 3D decomposition in GPU.js.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Define 4D tensor dimensions: [Batch, Channel, Height, Width]
const B = 2;
const C = 3;
const H = 4;
const W = 4;

// Flattened 3D output allocation: [W, H, B * C]
const kernel = gpu.createKernel(function (tensorA, tensorB, numChannels) {
    const x = this.thread.x; // Corresponds to Width
    const y = this.thread.y; // Corresponds to Height
    const z = this.thread.z; // Corresponds to (b * numChannels + c)

    // Decode batch and channel indices
    const c = z % numChannels;
    const b = Math.floor(z / numChannels);

    // Perform operation using decomposed indices
    // If input tensors are passed as 1D flat buffers:
    // index = ((b * numChannels + c) * height + y) * width + x;
    return tensorA[b][c][y][x] + tensorB[b][c][y][x];
})
.setOutput([W, H, B * C]);

// Mock 4D Tensor generator
function create4DTensor(b, c, h, w, val) {
    return Array.from({ length: b }, () =>
        Array.from({ length: c }, () =>
            Array.from({ length: h }, () =>
                Array.from({ length: w }, () => val)
            )
        )
    );
}

const tensorA = create4DTensor(B, C, H, W, 1.5);
const tensorB = create4DTensor(B, C, H, W, 2.5);

// Execute kernel
const result3D = kernel(tensorA, tensorB, C);

Reconstructing the 4D Output

The kernel produces an array structured as [B * C][H][W]. To restore the native 4D array shape on the CPU, reshape the resulting structure:

function reshapeTo4D(data3D, batchCount, channelCount, height, width) {
    const tensor4D = [];
    for (let b = 0; b < batchCount; b++) {
        const batch = [];
        for (let c = 0; c < channelCount; c++) {
            const z = b * channelCount + c;
            batch.push(data3D[z]);
        }
        tensor4D.push(batch);
    }
    return tensor4D;
}

const final4DTensor = reshapeTo4D(result3D, B, C, H, W);

Hardware Considerations

  • Texture Limits: WebGL drivers impose maximum texture limits (commonly 2048 to 16384 pixels depending on the GPU). When folding dimensions, verify that B * C does not exceed the hardware's maximum depth/3D texture limits.
  • Flattened Buffer Inputs: When operating on large models, passing nested multi-dimensional arrays from the CPU creates significant serialization overhead. Passing flat 1D Float32Array buffers directly into the kernel and computing the read offsets inside the shader yields substantially faster throughput.
