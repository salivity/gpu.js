How GPU.js Parses vec3 and vec4 Color Vectors

GPU.js allows developers to write standard JavaScript code and transpile it on the fly into WebGL shaders executed on the GPU. When working with colors, the library translates JavaScript array structures, custom API calls, and pixel data into native GLSL (OpenGL Shading Language) vectors such as vec3 and vec4. This article explains how GPU.js analyzes JavaScript Abstract Syntax Trees (AST), converts arrays into shader vector types, normalizes numeric values, and pipes color data directly into the WebGL graphics pipeline.

AST Parsing and Transpilation

At its core, GPU.js relies on an AST parser (built on Acorn) to convert JavaScript function definitions into an intermediary syntax tree. When the transpiler encounters array declarations within kernel functions—such as [r, g, b] or [r, g, b, a]—it inspects the length and types of the elements.

If an array literal contains three or four numeric values, the transpiler maps the AST ArrayExpression node directly to a GLSL vec3 or vec4 constructor. For example:

  • A JavaScript return statement like return [1, 0, 0]; is parsed and converted to return vec3(1.0, 0.0, 0.0);.
  • Variables defined as fixed-size coordinate or color vectors are given corresponding GLSL vector types rather than dynamic arrays, enabling high-performance, parallel SIMD (Single Instruction, Multiple Data) execution on the GPU.

Graphical Kernels and this.color()

When executing a kernel configured with graphical: true, GPU.js shifts into a canvas-rendering mode where pixel colors must be written to WebGL's native fragment output. In this mode, GPU.js provides the specialized this.color(r, g, b, a) method.

  1. AST Detection: During compilation, the AST walker specifically checks for member expressions targeting this.color.
  2. GLSL Translation: The call is transpiled directly into an assignment expression targeting the fragment shader output: gl_FragColor = vec4(r, g, b, a);.
  3. Type Promotion: Because WebGL GLSL requires strict floating-point precision for vector components, integer inputs are automatically promoted to floats (e.g., 0 becomes 0.0).

Value Normalization and Clamping

In WebGL, color vectors expect values normalized within the range of 0.0 to 1.0. GPU.js enforces this convention in its color pipelines:

  • When using this.color(), values are mapped directly to gl_FragColor. WebGL automatically clamps values outside the [0.0, 1.0] range during the rasterization phase.
  • If raw pixel data (such as an HTML ImageData array with values between 0 and 255) is supplied as an input argument, GPU.js textures the data and divides byte values by 255.0 within the generated shader wrapper, turning them into standardized vec4 samples accessible via texture2D.

Memory Packing and Texture Lookup

When non-graphical kernels return 4-element vectors or colors, GPU.js utilizes texture-based memory management to bypass WebGL limitations:

  • Floating-Point Textures: Vector components are stored across the Red, Green, Blue, and Alpha channels of an underlying WebGL texture (RGBA).
  • Subscript Access: If vector elements are accessed via indices in JavaScript (e.g., myVec[0] or myVec[2]), the transpiler rewrites these index lookups to native GLSL swizzle operations (.r / .x and .b / .z), eliminating array indexing overhead on the GPU hardware.
