Benchmark Memory Transfer vs Calculation in GPU.js

Benchmarking memory transfer bandwidth separately from kernel calculation time in gpu.js requires isolating CPU-to-GPU data uploads, GPU-to-CPU data readbacks, and raw shader execution. By leveraging texture inputs, gpu.js’s pipelining mode (pipeline: true), and explicit array readbacks via .toArray(), you can eliminate overhead overlap and calculate accurate throughput metrics (GB/s) for memory transfers versus compute operations.

The Challenge of GPU.js Timing

When you execute a standard gpu.js kernel passing native JavaScript arrays, three sequential stages occur:

  1. Host-to-Device (Upload): JavaScript arrays are converted into WebGL textures and bound to the GPU.
  2. Execution (Compute): The fragment shader executes across the specified output dimensions.
  3. Device-to-Host (Download): WebGL reads pixels back from the GPU memory and serializes them into typed arrays or JavaScript arrays.

Because WebGL executes commands asynchronously, calling standard JavaScript timers like performance.now() across a standard kernel call measures all three stages combined.

Step 1: Isolating Host-to-Device Transfer (Upload)

To measure the time it takes to push data from system RAM to GPU memory, create an ingestion kernel that does virtually no math, but takes the large dataset as an argument and outputs a texture using pipeline: true.

const gpu = new GPU();

const dataSize = 1024 * 1024 * 4; // 4 million 32-bit floats (16 MB)
const inputData = new Float32Array(dataSize).fill(1.5);

// Ingestion kernel: keeps data on GPU as a texture
const uploadKernel = gpu.createKernel(function(data) {
  return data[this.thread.x];
})
.setOutput([dataSize])
.setPipeline(true);

// Benchmark Upload
const uploadStart = performance.now();
const gpuTexture = uploadKernel(inputData);
// gpuTexture is now stored in VRAM
const uploadTimeMs = performance.now() - uploadStart;

const bytesTransferred = dataSize * 4; // Float32 = 4 bytes
const uploadBandwidthGBs = (bytesTransferred / (uploadTimeMs / 1000)) / 1e9;

console.log(`Upload Time: ${uploadTimeMs.toFixed(2)} ms`);
console.log(`Upload Bandwidth: ${uploadBandwidthGBs.toFixed(2)} GB/s`);

Step 2: Isolating Pure Calculation Time

To measure computation without transfer interference, both the input and output must remain entirely on the GPU. Pass the texture generated in Step 1 to your compute kernel, and configure the compute kernel with pipeline: true so it outputs another texture instead of transferring data back to the CPU.

To ensure proper synchronization, run a loop of iterations to account for WebGL warm-up.

const computeKernel = gpu.createKernel(function(tex) {
  let val = tex[this.thread.x];
  // Complex math computation
  for (let i = 0; i < 100; i++) {
    val = Math.sqrt(val * 1.01 + 0.05);
  }
  return val;
})
.setOutput([dataSize])
.setPipeline(true);

// Warm-up pass
let computeResultTexture = computeKernel(gpuTexture);

// Benchmark Calculation
const iterations = 50;
const computeStart = performance.now();

for (let i = 0; i < iterations; i++) {
  computeResultTexture = computeKernel(gpuTexture);
}

const computeTimeMs = (performance.now() - computeStart) / iterations;

console.log(`Pure Kernel Execution Time: ${computeTimeMs.toFixed(2)} ms`);

Step 3: Isolating Device-to-Host Transfer (Download)

The output from the computation step is currently a GPU texture reference. The transfer back to the CPU only occurs when you invoke .toArray() on the pipelined texture. This method forces a GPU flush and synchronizes the memory back to the host, allowing you to time readback latency directly.

// Benchmark Download (Readback)
const downloadStart = performance.now();
const cpuArray = computeResultTexture.toArray();
const downloadTimeMs = performance.now() - downloadStart;

const downloadBandwidthGBs = (bytesTransferred / (downloadTimeMs / 1000)) / 1e9;

console.log(`Download Time: ${downloadTimeMs.toFixed(2)} ms`);
console.log(`Download Bandwidth: ${downloadBandwidthGBs.toFixed(2)} GB/s`);

Cleanup and Accuracy Guidelines

  • Memory Garbage Collection: Call .delete() on intermediate textures (e.g., gpuTexture.delete()) when tests finish to avoid VRAM exhaustion.
  • Warm-up Cycles: WebGL compiles shaders on first invocation. Always discard the first kernel run when calculating execution benchmarks.
  • Data Sizing: Memory transfer overhead dominates small array sizes. Use payloads of at least 16 MB to 64 MB to accurately measure saturated PCI-e bandwidth.
