Running Granular Pitch Shifting in GPU.js

Granular pitch shifting without tempo distortion can successfully run in GPU.js, particularly for offline and batch audio processing. This article examines the mechanics of parallelizing granular synthesis via WebGL compute shaders, outlines how an output-driven overlap-add (OLA) model maps to GPU threads, and evaluates the critical performance bottlenecks and architectural constraints encountered when attempting real-time implementation on the web.

The Granular Pitch Shifting Algorithm

Granular pitch shifting decouples pitch modification from playback speed by dividing an audio signal into small segments called "grains"—typically between 10 and 50 milliseconds long.

To shift pitch without altering tempo:

  1. Grains are sampled from the source audio buffer at a modified playback rate corresponding to the desired transposition ratio.
  2. Each grain is smoothed using a window function (such as a Hann or Hamming window) to prevent abrupt boundary discontinuities and phase clicks.
  3. The windowed grains are overlappingly summed into the destination buffer at original-time intervals, maintaining the initial duration of the audio clip.

Implementing Granular Transposition in GPU.js

GPU.js compiles a restricted subset of JavaScript into WebGL fragment shaders, executing operations across thousands of parallel GPU cores.

Standard CPU implementations typically iterate sequentially through grain positions and sum samples into an accumulation buffer (input-driven overlap-add). Because standard WebGL lacks atomic write operations, an input-driven scatter approach causes race conditions when multiple grains write to the same output index simultaneously.

To implement granular pitch shifting in GPU.js, the algorithm must be inverted into an output-driven gather model:

  • Kernel Dimension: The GPU kernel is dispatched across a 1D array matching the length of the output audio buffer.
  • Per-Sample Thread: Each GPU thread computes the value of a single output sample index \(n\).
  • Grain Determination: Inside the kernel, mathematical indexing determines which active grains overlap index \(n\). For a 50% overlap, typically two to four grains overlap any given sample.
  • Local Accumulation: The thread reads the corresponding source samples from an input texture, evaluates the window equation dynamically, and sums the weighted samples directly into the final return value for that thread.

Strengths of GPU Acceleration

  • Massive Parallelism for Offline Processing: Long audio files (e.g., several minutes of multi-channel audio) can be processed almost instantaneously. A two-minute stereo track at 44.1 kHz contains over 10 million samples; mapping these across thousands of GPU cores drastically outperforms single-threaded CPU loops.
  • Predictable Branching: In a fixed-hop granular configuration, every thread executes nearly identical arithmetic paths, minimizing thread divergence and keeping GPU execution pipelines saturated.
  • Window Calculation: Calculating trigonometric windowing functions directly on the GPU is efficient, as hardware-accelerated math routines handle floating-point sine and cosine operations natively.

Architectural Limitations and Real-Time Viability

While offline transposition works reliably, utilizing GPU.js for low-latency, real-time audio playback faces significant constraints:

1. AudioWorklet Context Restrictions

The modern standard for web-based real-time audio is the AudioWorklet, which runs synchronously on a dedicated, real-time rendering thread. AudioWorkletGlobalScope does not have access to the DOM or the HTML canvas element, meaning WebGL contexts—and consequently GPU.js—cannot run natively inside an AudioWorklet processor.

2. GPU-to-CPU Readback Latency

Running GPU.js on the main thread or inside a standard Web Worker requires transferring audio chunks to the GPU as textures, rendering the computation, and reading the results back to the CPU via operations like gl.readPixels. This readback pipeline introduces asynchronous synchronization delays (often 10 to 30 milliseconds or more), exceeding typical low-latency audio buffer requirements (e.g., 128 samples at 44.1 kHz, or roughly 2.9 milliseconds).

Technical Verdict

Granular transposition algorithms without tempo distortion can run efficiently in GPU.js for offline rendering, batch processing, and non-real-time audio synthesis pipelines. However, due to GPU readback latency and the absence of WebGL contexts in the Web Audio API rendering thread, GPU.js is unsuitable for live, zero-latency audio worklets. High-performance offline rendering remains its optimal use case.
