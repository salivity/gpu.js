WebGL Extensions for GPU.js Float Textures

This article explains the specific WebGL extensions required by web browsers to support floating-point textures in gpu.js. Depending on whether your browser environment uses WebGL 1 or WebGL 2, different extensions must be active to allow gpu.js to allocate, read, and write high-precision 32-bit floating-point data on the GPU.

WebGL 1 Extensions

In a WebGL 1 context, floating-point textures are not part of the core specification. To enable 32-bit floating-point textures and computations in gpu.js under WebGL 1, the browser must support:

  • OES_texture_float: Enables the use of 32-bit floating-point data formats for textures, allowing gpu.js to store and read high-precision floating-point arrays.
  • WEBGL_color_buffer_float: Allows rendering directly to 32-bit floating-point textures using framebuffers. Because gpu.js executes compute kernels by drawing to an off-screen framebuffer texture, this extension is mandatory for float output.
  • OES_texture_float_linear (Optional): Enables linear interpolation and filtering on 32-bit float textures. While not strictly required for standard computation, some matrix operations and sampler configurations depend on it.

WebGL 2 Extensions

WebGL 2 includes basic 32-bit floating-point texture creation as a core feature, eliminating the need for OES_texture_float. However, writing computation results to float textures still requires extension support:

  • EXT_color_buffer_float: Enables rendering to 32-bit and 16-bit floating-point formats in a WebGL 2 framebuffer. This is the primary required extension for full floating-point kernel execution in gpu.js on modern browsers.

Half-Float Fallbacks

When full 32-bit float extensions are unsupported by the hardware or browser, gpu.js may fall back to 16-bit half-precision floating-point textures using the following extensions:

  • OES_texture_half_float (WebGL 1 texture creation)
  • EXT_color_buffer_half_float (WebGL 1 framebuffer rendering)

If none of these extensions are accessible in the browser, gpu.js will be unable to run float-based kernels on the GPU and will either degrade precision to unsigned bytes or fall back to the CPU runner.
