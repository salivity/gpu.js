Fast Voronoi and Worley Diagrams with GPU.js

Generating Voronoi and Worley diagrams on the CPU quickly bottlenecks performance because calculating the distance from every screen pixel to every feature point requires millions of operations per frame. By leveraging GPU.js, you can write standard JavaScript that automatically compiles into WebGL fragment shaders, offloading these distance calculations across thousands of parallel GPU threads. This guide covers how to structure your algorithm, configure a GPU.js graphical kernel, and apply rendering optimizations to produce real-time procedural diagrams at high frame rates.

The Algorithmic Concept

A Voronoi diagram divides a plane into regions based on distance to a specified set of feature points (seeds). Each pixel is assigned a color or value based on which seed point is closest (\(F_1\)). Worley noise extends this concept by tracking the \(n\)-th closest seed point (such as \(F_2\) or the difference \(F_2 - F_1\)), producing organic, cell-like textures.

Computing this on the CPU scales at \(O(W \times H \times N)\), where \(W\) is width, \(H\) is height, and \(N\) is the number of points. In a GPU shader, every pixel executes concurrently, dropping the effective runtime complexity per thread to \(O(N)\).

Setting Up the GPU.js Kernel

To achieve maximum performance, configure GPU.js to render directly to an HTML canvas using WebGL rather than returning an array to the CPU. This prevents expensive memory transfers between the GPU and host system.

import { GPU } from 'gpu.js';

const canvas = document.getElementById('voronoi-canvas');
const gpu = new GPU({ canvas, webGl: window.WebGLRenderingContext });

const width = 800;
const height = 600;
const numPoints = 64;

Creating the Voronoi Kernel

GPU.js kernels require static loop limits. You must pass the number of seed points as a constant so the underlying GLSL compiler can unroll or properly bound the iteration.

const renderVoronoi = gpu.createKernel(function(pointsX, pointsY, colorsR, colorsG, colorsB) {
    const px = this.thread.x;
    const py = this.thread.y;

    let minDist = 10000000.0;
    let closestIndex = 0;

    // Iterate through all feature points
    for (let i = 0; i < this.constants.numPoints; i++) {
        const dx = px - pointsX[i];
        const dy = py - pointsY[i];
        
        // Use squared Euclidean distance to avoid costly square root operations
        const distSq = dx * dx + dy * dy;

        if (distSq < minDist) {
            minDist = distSq;
            closestIndex = i;
        }
    }

    // Paint pixel using the color of the nearest seed point
    this.color(
        colorsR[closestIndex],
        colorsG[closestIndex],
        colorsB[closestIndex],
        1.0
    );
})
.setConstants({ numPoints })
.setOutput([width, height])
.setGraphical(true);

Adapting the Kernel for Worley Noise

To create Worley noise (cellular noise), track both the closest distance (\(F_1\)) and the second-closest distance (\(F_2\)). Normalizing the difference produces distinctive cellular walls.

const renderWorley = gpu.createKernel(function(pointsX, pointsY, maxDist) {
    const px = this.thread.x;
    const py = this.thread.y;

    let f1 = 10000000.0;
    let f2 = 10000000.0;

    for (let i = 0; i < this.constants.numPoints; i++) {
        const dx = px - pointsX[i];
        const dy = py - pointsY[i];
        const dist = Math.sqrt(dx * dx + dy * dy);

        if (dist < f1) {
            f2 = f1;
            f1 = dist;
        } else if (dist < f2) {
            f2 = dist;
        }
    }

    // Calculate Worley value (F2 - F1) and normalize between 0.0 and 1.0
    const value = Math.min(Math.max((f2 - f1) / maxDist, 0.0), 1.0);

    this.color(value, value, value, 1.0);
})
.setConstants({ numPoints })
.setOutput([width, height])
.setGraphical(true);

Preparing and Passing Data

Pass data to the kernel as flat 1D Float32Array buffers. Splitting coordinate pairs into separate arrays (pointsX and pointsY) reduces internal packing overhead in WebGL 1.0 contexts.

const pointsX = new Float32Array(numPoints);
const pointsY = new Float32Array(numPoints);
const colorsR = new Float32Array(numPoints);
const colorsG = new Float32Array(numPoints);
const colorsB = new Float32Array(numPoints);

for (let i = 0; i < numPoints; i++) {
    pointsX[i] = Math.random() * width;
    pointsY[i] = Math.random() * height;
    colorsR[i] = Math.random();
    colorsG[i] = Math.random();
    colorsB[i] = Math.random();
}

// Execute the kernel
renderVoronoi(pointsX, pointsY, colorsR, colorsG, colorsB);

Key Optimization Strategies

  1. Avoid Math.sqrt where possible: Standard Voronoi partitioning only requires relative distance comparisons. Comparing squared distances (\(dx^2 + dy^2\)) eliminates the computational cost of square root operations across all pixels.
  2. Use Direct Graphical Output: Setting .setGraphical(true) draws directly to the context bound to this.color(). Calling kernel() in array-return mode forces a round-trip data conversion from GPU memory back to a JavaScript TypedArray, which degrades real-time rendering.
  3. Pre-allocate Input Buffers: When animating points, reuse existing Float32Array instances rather than instantiating new arrays inside a requestAnimationFrame loop. This avoids triggering garbage collection pauses.
  4. Tune Point Counts: GPU threads execute synchronously in blocks. Keeping loop counts identical across all threads via this.constants prevents branching divergence inside the hardware execution units.
