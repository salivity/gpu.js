gpu.js hardValidate Kernel Option Explained

This article provides a detailed breakdown of the hardValidate kernel option in gpu.js, detailing its role in pipeline configuration. Readers will learn how this setting enforces strict validation rules across chained kernels, its impact on data types and texture dimensions, and how it helps developers catch silent GPU pipeline failures during development.

In gpu.js, the pipeline mode (pipeline: true) allows developers to chain multiple kernels together, feeding the output texture of one kernel directly into the next without transferring data back to the CPU. During this process, managing compatibility between consecutive kernels can be challenging due to WebGL constraints regarding texture formats, floating-point precision, and dimension alignment.

The hardValidate kernel option enforces strict validation checks on the pipeline configuration and kernel inputs. When enabled, it alters how gpu.js handles anomalies and type mismatches during both compilation and execution:

1. Strict Exception Throwing

By default, gpu.js may attempt permissive fallbacks or fail silently with WebGL warnings when an unexpected data format or texture configuration is encountered. Setting hardValidate: true forces the library to immediately throw explicit JavaScript exceptions if any input, output, or internal texture does not strictly adhere to expected specifications.

2. Dimension and Texture Format Verification

Pipelines require that the output dimensions and texture layouts of a preceding kernel precisely match the input expectations of the succeeding kernel. hardValidate validates that:

  • Kernel output dimensions match the expected buffer bounds.
  • Sub-pixel textures (such as RGBA channels representing numbers) match the precision and packing format requested by downstream operations.
  • Floating-point texture capabilities are properly supported by the underlying hardware and context before execution begins.

3. Argument and Type Integrity

GPU shaders generated by gpu.js are strictly typed. When hardValidate is active, the configuration phase rigorously validates all passed arguments against their declared types (such as Array, Number, Texture, or Input). It prevents implicit type coercion that might otherwise lead to NaN outputs or graphical glitches within compiled GLSL code.

When to Use hardValidate

Enabling hardValidate introduces minor computational overhead during pipeline initialization due to its thorough inspection routines. Because of this, it is primarily intended for development and debugging environments to identify misconfigured pipelines, mismatched kernel dimensions, and invalid memory accesses before deploying optimized code to production.
