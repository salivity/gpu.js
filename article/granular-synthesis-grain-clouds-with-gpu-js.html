Granular Synthesis Grain Clouds with GPU.js

Granular sound synthesis generates complex acoustic textures by layering thousands of microscopic sound fragments, known as grains, into dense acoustic clouds. This article explores how to harness the parallel processing power of the GPU using the gpu.js library to compute, modulate, and spatially position massive grain clouds in real time within JavaScript environments.

The Challenge of Granular Cloud Density

Granular synthesis involves scheduling hundreds or thousands of overlapping grains per second. Each grain requires individual computation for:

  • Playback Rate: Determining pitch and time-stretch factors.
  • Windowing / Envelopes: Applying functions (such as Hann, Blackman, or Gaussian) to avoid edge clicks.
  • Sample Lookups: Slicing audio data from an existing source buffer.
  • Spatial Positioning: Calculating multi-channel amplitude or 3D coordinates.

Executing these operations per-sample for thousands of concurrent grains on a single CPU thread easily causes buffer underruns. Because each grain or audio sample can be evaluated independently, this workload is an ideal candidate for massive parallelization via WebGL compute shaders through gpu.js.

System Architecture

To produce grain clouds with gpu.js, the synthesis pipeline is split into three phases:

  1. Parameter Generation: Grain parameters (source start position, duration, pitch shift, amplitude, and spatial pan) are generated either mathematically or loaded from control arrays.
  2. GPU Kernel Evaluation: A parallel kernel calculates the audio output. Depending on the design, threads can represent either:
    • Individual grains: Generating discrete audio arrays that are subsequently summed.
    • Output samples: Where each thread computes the sum of all grains active at that exact time index.
  3. Playback via Web Audio API: The output floating-point array is pushed into an AudioBuffer or processed inside an AudioWorkletNode for real-time playback.

Implementing Parallel Grain Generation

The sample-centric approach is the most efficient for memory utilization. In this configuration, each GPU thread calculates the resulting value of a single output sample by iterating over active grains.

1. Initializing GPU.js and Source Buffers

Load the source audio data into a flat array or texture that the GPU kernel can read:

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Configuration
const sampleRate = 44100;
const bufferSize = 4096; // Block size for synthesis
const maxGrains = 256;   // Maximum concurrent grains per block

2. Writing the Synthesis Kernel

The gpu.js kernel evaluates active grains, computes window envelopes, applies pitch scaling, and derives stereo pan positions simultaneously.

const granularKernel = gpu.createKernel(function(
  sourceAudio,
  sourceLength,
  grainPositions,
  grainStartTimes,
  grainDurations,
  grainPitches,
  grainPans,
  numActiveGrains,
  sampleOffset
) {
  // this.thread.x corresponds to the current output sample index
  let currentSample = sampleOffset + this.thread.x;
  let leftChannel = 0.0;
  let rightChannel = 0.0;

  for (let i = 0; i < numActiveGrains; i++) {
    let startTime = grainStartTimes[i];
    let duration = grainDurations[i];
    let elapsed = currentSample - startTime;

    if (elapsed >= 0 && elapsed < duration) {
      // Normalized phase (0.0 to 1.0)
      let phase = elapsed / duration;

      // Hann window envelope
      let window = 0.5 * (1.0 - Math.cos(2.0 * Math.PI * phase));

      // Source lookup position with pitch modification
      let readPos = grainPositions[i] + (elapsed * grainPitches[i]);
      let index = Math.floor(readPos) % sourceLength;
      if (index < 0) index += sourceLength;

      let sampleVal = sourceAudio[index] * window;

      // Spatial positioning (Constant Power Panning)
      let pan = grainPans[i]; // Value from 0.0 (Left) to 1.0 (Right)
      let leftGain = Math.cos(pan * 0.5 * Math.PI);
      let rightGain = Math.sin(pan * 0.5 * Math.PI);

      leftChannel += sampleVal * leftGain;
      rightChannel += sampleVal * rightGain;
    }
  }

  // this.thread.y = 0 for Left, 1 for Right
  if (this.thread.y === 0) {
    return leftChannel;
  } else {
    return rightChannel;
  }
})
.setOutput([bufferSize, 2]) // Width: Samples, Height: Stereo Channels
.setPrecision('single');

Parallel Spatial Positioning

Spatial positioning in grain clouds requires individual panning or 3D localization vectors for every grain to create realistic spatial dispersion.

  • Stereo Clouds: Assign a randomized distribution (such as a Gaussian distribution around a center azimuth) to grainPans. The GPU applies trigonometric gain coefficients per grain without incurring CPU penalties.
  • Binaural / 3D Audio: By extending the kernel, grains can be positioned using interaural time delays (ITD) and interaural level differences (ILD). Because gpu.js executes per-sample lookups in parallel, calculating fractional delays for 3D coordinates can be performed directly inside the sampling loop.

Optimizations and Memory Management

To maintain stable real-time audio playback without stuttering:

  1. Avoid Texture Transfer Overhead: Copying data between the CPU and GPU introduces latency. Keep source waveforms resident on the GPU, and only pass small parameter vectors (such as updated grain positions) per audio block.
  2. Vectorize Grains: Group grain parameters into textures or 4D vectors ([position, duration, pitch, pan]) to maximize GPU memory bandwidth.
  3. Double Buffering: Compute block \(N+1\) on the GPU while the Web Audio API plays block \(N\). This eliminates race conditions and ensures continuous audio streams.
