Compute Kronecker Tensor Product with GPU.js

Computing the Kronecker tensor product of two large matrices rapidly becomes a performance bottleneck on standard CPUs due to the massive expansion of dimensions. This article explains how to efficiently offload this computation to the graphics card using GPU.js, a JavaScript library that compiles code into WebGL shaders. By mapping the mathematical index logic directly to parallel GPU threads, you can calculate the tensor product of large datasets with near-instantaneous execution times.

Mathematical Index Mapping

Given matrix \(A\) of dimensions \(M \times N\) and matrix \(B\) of dimensions \(P \times Q\), their Kronecker product \(C = A \otimes B\) results in a matrix with dimensions \((M \cdot P) \times (N \cdot Q)\).

Because each output cell is independent of every other cell, the operation is an ideal candidate for massive parallelization. To compute any cell \(C[i][j]\) (where \(i\) is the row index and \(j\) is the column index), use the following index transformations:

  • Row index in \(A\): \(\lfloor i / P \rfloor\)
  • Column index in \(A\): \(\lfloor j / Q \rfloor\)
  • Row index in \(B\): \(i \pmod P\)
  • Column index in \(B\): \(j \pmod Q\)

The value of \(C[i][j]\) is calculated as: \[C[i][j] = A\left[\lfloor i / P \rfloor\right]\left[\lfloor j / Q \rfloor\right] \times B[i \pmod P][j \pmod Q]\]

Implementing the GPU.js Kernel

In GPU.js, this.thread.x maps to columns (width), and this.thread.y maps to rows (height). The output dimension must be configured to match the final size [(N * Q), (M * P)].

const { GPU } = require('gpu.js');
const gpu = new GPU();

function createKroneckerKernel(m, n, p, q) {
  return gpu.createKernel(
    function(a, b, pRows, qCols) {
      // this.thread.x corresponds to column index j
      // this.thread.y corresponds to row index i
      const rowA = Math.floor(this.thread.y / pRows);
      const colA = Math.floor(this.thread.x / qCols);
      
      const rowB = Math.floor(this.thread.y % pRows);
      const colB = Math.floor(this.thread.x % qCols);

      return a[rowA][colA] * b[rowB][colB];
    },
    {
      output: [n * q, m * p],
      precision: 'single'
    }
  );
}

// Example usage:
const matrixA = [
  [1, 2],
  [3, 4]
];

const matrixB = [
  [0, 5],
  [6, 7]
];

const M = matrixA.length;
const N = matrixA[0].length;
const P = matrixB.length;
const Q = matrixB[0].length;

const kroneckerKernel = createKroneckerKernel(M, N, P, Q);
const result = kroneckerKernel(matrixA, matrixB, P, Q);

console.log(result);

Key Performance Optimizations

  1. Avoid Recompilation: In GPU.js, calling gpu.createKernel() compiles a shader program, which is expensive. If the matrix dimensions are static, instantiate the kernel once and reuse the compiled function for subsequent matrix operations.

  2. Pipeline Mode for Chained Operations: If the resulting tensor product will be used in another GPU-accelerated operation (such as matrix addition or scalar multiplication), enable .setPipeline(true). This keeps the data stored as a texture in GPU VRAM and avoids transferring large arrays back to the CPU memory space.

  3. Float Precision: By default, WebGL operates on 32-bit floats. If extreme precision is required, you must account for floating-point inaccuracies inherent to 32-bit graphical textures by specifying precision: 'single' or working within bounded ranges.

  4. WebGL Texture Dimension Limits: GPU.js is constrained by the maximum texture size supported by the client's graphics hardware (often 4096, 8192, or 16384 pixels along an edge). If the combined dimensions \((M \cdot P)\) or \((N \cdot Q)\) exceed the hardware limit (queried via gl.getParameter(gl.MAX_TEXTURE_SIZE)), you must partition the inputs and compute the Kronecker product in block tiles.
