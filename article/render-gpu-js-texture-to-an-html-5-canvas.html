Render GPU.js Texture to an HTML5 Canvas

A gpu.js Texture object cannot be painted directly onto a standard 2D HTML5 canvas context without processing, but it can be rendered to a WebGL canvas using a graphical kernel. Because a Texture instance in gpu.js represents an underlying WebGL texture residing in GPU memory, displaying it requires either passing it through a graphical gpu.js kernel or reading its data back to the CPU. The most efficient method is using a graphical kernel, which renders the texture data directly to an HTML5 <canvas> element entirely on the GPU.

Understanding the GPU.js Texture

When you create a kernel in gpu.js with the option pipeline: true, the kernel returns a Texture object instead of a flat JavaScript array. This optimization keeps computation results inside VRAM, allowing subsequent kernels to consume the data without the severe performance penalty of transferring memory back to the CPU.

However, because this data resides in GPU memory as a WebGL texture, an HTML5 canvas running a 2D context (canvas.getContext('2d')) cannot read or display it directly.

Rendering via a Graphical Kernel

The native way to render a Texture to a canvas in gpu.js is to define a secondary kernel configured with { graphical: true }. A graphical kernel exposes the this.color(r, g, b, a) method within the kernel function and outputs pixels straight to its internal <canvas> element.

Here is how to set up the pipeline:

const gpu = new GPU();

// 1. Generate computational data as a Texture
const computeKernel = gpu.createKernel(function () {
  return Math.sin(this.thread.x) * 0.5 + 0.5;
}, {
  output: [512, 512],
  pipeline: true
});

const textureOutput = computeKernel();

// 2. Create a graphical kernel to render the texture
const renderKernel = gpu.createKernel(function (texture) {
  const value = texture[this.thread.y][this.thread.x];
  // Map texture value to RGBA
  this.color(value, value, value, 1);
}, {
  output: [512, 512],
  graphical: true
});

// 3. Render the texture onto the kernel's canvas
renderKernel(textureOutput);

// 4. Attach the generated canvas to your document
document.body.appendChild(renderKernel.canvas);

In this implementation, renderKernel.canvas is a valid HTML5 <canvas> element powered by WebGL. Once attached to the DOM, calling renderKernel(textureOutput) draws the texture frames directly to the screen with zero CPU readback latency.

The CPU Fallback Alternative

If you must render into an existing 2D canvas context rather than the WebGL canvas generated by gpu.js, you must extract the texture data back to the CPU using .toArray():

const rawData = textureOutput.toArray();
const ctx = my2DCanvas.getContext('2d');
const imgData = ctx.createImageData(width, height);

// Populate ImageData from rawData and draw via ctx.putImageData(...)

While functional, this approach introduces synchronous GPU-to-CPU readback overhead. For interactive, visual, or real-time rendering, routing the Texture into a graphical: true kernel remains the proper and performant solution.
