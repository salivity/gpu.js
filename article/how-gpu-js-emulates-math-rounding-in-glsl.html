How gpu.js Emulates Math Rounding in GLSL

This article explores how the gpu.js compiler translates JavaScript's standard rounding methods—Math.floor, Math.ceil, and Math.round—into executable WebGL Shading Language (GLSL) code. While graphics hardware provides native support for some rounding operations, differences between JavaScript's ECMAScript specifications and GLSL ES standards require gpu.js to perform syntax transpilation, emulate missing functions, and resolve floating-point edge cases to maintain uniform behavior across both CPU and GPU execution.

The Abstract Syntax Tree (AST) Transpilation

When a kernel is compiled in gpu.js, the JavaScript function is parsed into an Abstract Syntax Tree (AST). The compiler identifies member expressions matching the Math object and routes them to its GLSL generator. Instead of invoking JavaScript runtime methods, the compiler replaces these calls with corresponding GLSL operations that run directly inside a fragment shader.

Mapping Math.floor and Math.ceil

Both GLSL ES 1.0 (used in WebGL 1.0) and GLSL ES 3.0 (used in WebGL 2.0) provide built-in vector and scalar functions for truncating and rounding up floating-point values:

  • Math.floor(x) maps directly to GLSL's native floor(x). It returns the largest integer floating-point value that is less than or equal to x.
  • Math.ceil(x) maps directly to GLSL's native ceil(x). It returns the smallest integer floating-point value that is greater than or equal to x.

Because GLSL is strictly typed, the gpu.js compiler ensures that inputs to floor() and ceil() are evaluated as float types. If an integer expression is passed, gpu.js injects a type cast (such as float(x)) so the generated shader compiles without type-mismatch errors.

Emulating Math.round

Unlike floor and ceil, the round function presents compatibility challenges:

  1. Lack of Native Support in WebGL 1.0: GLSL ES 1.0 does not have a built-in round() function. While GLSL ES 3.0 introduces round() and roundEven(), gpu.js maintains backward compatibility with WebGL 1.0 pipelines.
  2. Tie-Breaking Semantics: JavaScript's Math.round specifically rounds half-way values toward positive infinity (e.g., Math.round(-1.5) evaluates to -1, and Math.round(1.5) evaluates to 2). Standard hardware rounding often favors "round to even" (banker's rounding).

To solve both issues consistently across all platforms, gpu.js emulates Math.round(x) using an algebraic equivalent based on floor:

floor(x + 0.5)

By substituting Math.round(x) with floor(x + 0.5), the shader executes natively across both WebGL 1.0 and WebGL 2.0 environments while faithfully matching JavaScript’s tie-breaking rules for both positive and negative values.

Precision and Floating-Point Considerations

GPU calculations typically operate under highp precision qualifiers inside gpu.js fragment shaders. However, 32-bit floating-point arithmetic on GPUs can produce minute precision anomalies (for example, evaluating a value as 2.4999998 instead of 2.5).

Because floor(x + 0.5) relies on strict boundaries, gpu.js optimizes shader arithmetic to mitigate rounding artifacts, ensuring that values processed concurrently across thousands of GPU threads yield results identical to single-threaded CPU JavaScript.
