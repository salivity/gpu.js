Compute Softmax Activation in GPU.js

This guide explains how to compute the Softmax activation function across output classes using gpu.js. Implementing Softmax in parallel requires special attention because the denominator relies on a reduction sum of exponentials across all classes. Below, you will learn how to structure the math for numerical stability, write an efficient GPU kernel, and execute it over batches of data.

Understanding the Softmax Calculation

The standard Softmax function converts raw output logits into probabilities that sum to 1:

\[\text{Softmax}(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{C} e^{z_j}}\]

where \(C\) is the number of classes.

Directly computing \(e^{z_i}\) can easily cause floating-point overflow if the logits are large. To prevent this, apply the numerical stability trick by subtracting the maximum logit value (\(\max(z)\)) before exponentiating:

\[\text{Softmax}(z_i) = \frac{e^{z_i - \max(z)}}{\sum_{j=1}^{C} e^{z_j - \max(z)}}\]

GPU.js Kernel Implementation

In gpu.js, kernels execute in parallel across a defined output grid. For a batch of predictions, the output is typically a 2D matrix where the width represents the classes and the height represents the batch size.

Each thread computes the Softmax value for an individual class \(x\) within sample \(y\).

const { GPU } = require('gpu.js');
const gpu = new GPU();

/**
 * Creates a Softmax kernel for a 2D batch of logits.
 * @param {number} numClasses - The number of output classes.
 * @param {number} batchSize - The number of samples in the batch.
 */
function createSoftmaxKernel(numClasses, batchSize) {
  return gpu.createKernel(function(logits, numClasses) {
    const classIdx = this.thread.x;
    const batchIdx = this.thread.y;

    // Step 1: Find the maximum logit for numerical stability
    let maxLogit = -1e9;
    for (let i = 0; i < numClasses; i++) {
      const val = logits[batchIdx][i];
      if (val > maxLogit) {
        maxLogit = val;
      }
    }

    // Step 2: Compute the sum of exponentials
    let sumExp = 0.0;
    for (let i = 0; i < numClasses; i++) {
      sumExp += Math.exp(logits[batchIdx][i] - maxLogit);
    }

    // Step 3: Compute the normalized probability for this thread's class
    const currentExp = Math.exp(logits[batchIdx][classIdx] - maxLogit);
    return currentExp / sumExp;
  })
  .setOutput([numClasses, batchSize]);
}

Running the Kernel

To run the kernel, pass a 2D array of raw logits and the class count to the compiled function:

const batchSize = 2;
const numClasses = 4;

// Sample logits: [batchSize][numClasses]
const rawLogits = [
  [2.0, 1.0, 0.1, 3.0],
  [1.0, 5.0, 2.0, 1.0]
];

const softmaxKernel = createSoftmaxKernel(numClasses, batchSize);
const probabilities = softmaxKernel(rawLogits, numClasses);

console.log(probabilities);
// Output will be an array of Float32Arrays where each row sums to ~1.0

Key Considerations

  1. Memory Ordering: gpu.js assigns this.thread.x to columns and this.thread.y to rows. When passing input dimensions to .setOutput([width, height]), ensure width matches the class count and height matches the batch size.
  2. Loop Reductions: Since pure WebGL fragment shaders lack shared thread memory, each thread computes the row's reduction loop (max and sum) independently. For standard classification sizes (e.g., 10 to 1,000 classes), this approach is computationally negligible and avoids multi-pass pipeline overhead.
  3. Pipeline Mode: If the Softmax output is fed into another GPU kernel (such as cross-entropy loss), enable .setPipeline(true) on the kernel to keep the textures inside GPU VRAM and bypass the CPU readback penalty.
