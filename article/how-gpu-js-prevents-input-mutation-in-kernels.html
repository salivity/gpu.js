How gpu.js Prevents Input Mutation in Kernels

This article explains the mechanisms gpu.js uses to prevent accidental mutation of input arguments within kernel functions. By translating JavaScript into shading language code, utilizing read-only hardware structures like textures and uniforms, and enforcing strict separation between input memory and output render targets, gpu.js makes in-place data modification structurally impossible during GPU execution.

Transpilation into Shading Languages

When a kernel function is defined in gpu.js, it is not executed directly by the JavaScript runtime. Instead, the library parses the JavaScript function's Abstract Syntax Tree (AST) and transpiles it into OpenGL Shading Language (GLSL) for WebGL, or equivalent low-level shader code.

Because the code is converted into a shader, JavaScript's native reference semantics—where passing an array or object allows direct modification of the original reference—no longer apply. The variables defined in JavaScript are remapped to match shader conventions and constraints.

Representation as Read-Only Textures and Uniforms

Inside the generated GLSL shader, input arguments cannot be treated as standard mutable arrays. Modern graphics hardware handles incoming data through specific channels:

  • Arrays and Matrices: Large collections of data are encoded and uploaded into GPU memory as WebGL textures (sampler2D). In GLSL, textures can only be sampled using read operations (such as texture2D). There is no hardware-level instruction to write data back to a texture being actively read within the same pass.
  • Primitive Values: Numbers, booleans, and small vectors are passed as shader uniform variables. By specification, uniforms are read-only constants throughout a single draw call. Any attempt in the kernel code to assign a new value to a uniform will trigger a shader compilation error.

Decoupling Inputs from the Output Buffer

gpu.js enforces an execution model where data reading and data writing are physically separated:

  1. Input Stage: The GPU reads strictly from bound texture units or uniform registers.
  2. Execution Stage: The kernel computes the result for a single thread (corresponding to one coordinate or element).
  3. Output Stage: The result is emitted solely via the kernel's return statement, which routes the value to a separate output framebuffer (gl_FragColor or an off-screen render texture).

Because the output target is distinct from the input memory sources, the kernel cannot overwrite its own input memory during execution.

Transpiler-Level Validation

During the AST parsing phase, gpu.js analyzes assignment operators within the kernel body. If an operation attempts to write to an input identifier using standard JavaScript assignment syntax, the transpiler either flags it as an unsupported operation or isolates the variable to a thread-local register. Consequently, local reassignments only alter temporary register state for that specific execution thread, leaving the source data intact and preventing cross-thread side effects.
