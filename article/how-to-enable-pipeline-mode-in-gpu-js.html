How to Enable Pipeline Mode in GPU.js

This article provides a practical guide on enabling and utilizing pipeline mode in GPU.js using the .setPipeline(true) method. In GPU-accelerated JavaScript applications, passing data back and forth between the CPU and the GPU creates a significant performance bottleneck. By enabling pipeline mode, you keep intermediate output data in the GPU's memory as WebGL textures, allowing sequential kernels to execute rapidly without unnecessary memory transfers.

Understanding Pipeline Mode

By default, when a GPU.js kernel finishes execution, it converts the output from a WebGL texture back into a JavaScript array and transfers it from VRAM to system RAM. This transfer process introduces overhead. When chaining multiple computations, setPipeline(true) tells GPU.js to leave the data on the GPU as a texture so the subsequent kernel can ingest it immediately.

Enabling Pipeline Mode

You enable pipeline mode during the kernel declaration phase by chaining .setPipeline(true) to the gpu.createKernel() call.

Here is how to set up and chain pipelined kernels:

const { GPU } = require('gpu.js'); // or import { GPU } from 'gpu.js' in a browser
const gpu = new GPU();

// First kernel: Pipelined
const multiplyMatrix = gpu.createKernel(function(a, b) {
  let sum = 0;
  for (let i = 0; i < 512; i++) {
    sum += a[this.thread.y][i] * b[i][this.thread.x];
  }
  return sum;
})
  .setOutput([512, 512])
  .setPipeline(true); // Retains output on the GPU

// Second kernel: Consumes the pipelined texture
const addBias = gpu.createKernel(function(matrix, bias) {
  return matrix[this.thread.y][this.thread.x] + bias;
})
  .setOutput([512, 512]); // Pipeline mode is false by default; returns a standard array

Executing Pipelined Kernels

Once configured, pass the texture returned by the first kernel directly into the second kernel as an argument:

const matrixA = /* ...2D Array data... */;
const matrixB = /* ...2D Array data... */;
const biasValue = 5.0;

// Step 1: Execute first kernel. Result is a GPU Texture object, not an array.
const textureResult = multiplyMatrix(matrixA, matrixB);

// Step 2: Pass the GPU Texture directly into the next kernel.
const finalArray = addBias(textureResult, biasValue);

console.log(finalArray); // Outputs the computed JavaScript 2D array

Retrieving Data Directly from a Pipelined Kernel

If you need to retrieve actual JavaScript data directly from an output that was run with pipeline mode enabled, you can manually convert the texture back into an array using the .toArray() method:

const texture = multiplyMatrix(matrixA, matrixB);

// Convert the texture to a standard JavaScript array when needed
const rawArray = texture.toArray();

Best Practices

  • Chain multiple calculations: Use setPipeline(true) on every intermediate kernel in your computation pipeline, only omitting it on the final step where raw CPU-accessible data is needed.
  • Match output dimensions: Ensure that the input dimensions expected by subsequent kernels align correctly with the .setOutput() configuration of the preceding pipelined kernel.
  • Avoid unnecessary reads: Calling .toArray() or logging a pipelined texture forces memory synchronization between the GPU and CPU, which will negate the performance benefits of pipelining.
