Extract Raw Data from a gpu.js Texture

When working with gpu.js, enabling pipeline mode keeps computations on the GPU by returning a WebGL Texture object instead of a standard JavaScript array. While this drastically improves performance by avoiding memory transfers between steps, you must eventually extract the raw numerical data back into CPU memory when the pipeline ends. This article explains how to retrieve your data using the built-in .toArray() method, manage output formats, and clean up GPU memory properly.

Using the .toArray() Method

The primary and most direct method to extract data from a gpu.js Texture is calling .toArray() directly on the texture instance. This method reads the pixels from the WebGL framebuffer and reconstructs the data into standard JavaScript arrays matching the dimensions specified in the kernel's output.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Create a kernel configured for pipelining
const kernel = gpu.createKernel(function () {
  return this.thread.x * 2;
})
.setOutput([5])
.setOutputToTexture(true);

// Execute kernel; result is a Texture object
const textureResult = kernel();

// Extract raw numerical data back to CPU
const rawData = textureResult.toArray();

console.log(rawData); 
// Output: Float32Array(5) [0, 2, 4, 6, 8] or standard Array depending on configuration

Extracting Multi-Dimensional Data

The .toArray() method automatically honors multidimensional output dimensions defined in your kernel. If your output dimensions are multi-axis, such as [width, height], the method will return a nested array reflecting that structure:

const matrixKernel = gpu.createKernel(function () {
  return this.thread.x + this.thread.y;
})
.setOutput([3, 3])
.setOutputToTexture(true);

const textureMatrix = matrixKernel();
const rawMatrix = textureMatrix.toArray();

console.log(rawMatrix);
// Output: [[0, 1, 2], [1, 2, 3], [2, 3, 4]]

Reading Data Using a Terminal Kernel

Alternatively, you can extract your data by passing the texture into a final "terminal" kernel that has .setOutputToTexture(false) (the default behavior). This kernel simply returns the input texture values:

const finalReadKernel = gpu.createKernel(function (t) {
  return t[this.thread.y][this.thread.x];
})
.setOutput([3, 3])
.setOutputToTexture(false);

const finalArray = finalReadKernel(textureMatrix);

While functional, calling .toArray() directly on the texture object is usually faster and avoids the overhead of compiling an extra WebGL shader program.

Memory Management

After extracting data from a Texture, the texture itself remains allocated in GPU VRAM. In long-running applications or loops, failing to release textures can cause WebGL context crashes due to out-of-memory errors.

Call .delete() on the texture object as soon as the CPU readback is complete:

const rawData = textureResult.toArray();

// Free GPU memory
textureResult.delete();

Performance Considerations

Extracting data from a Texture forces a synchronous read operation (gl.readPixels under the hood), halting GPU execution until data transfers across the PCIe bus into host memory. To maintain high throughput:

  • Keep pipelining active across as many consecutive kernels as possible.
  • Only invoke .toArray() once at the absolute end of the computation pipeline.
  • Avoid extracting intermediate results inside tight performance loops.
