How GPU.js Handles Multidimensional Array Inputs

GPU.js processes nested multidimensional JavaScript arrays by flattening their hierarchical structure on the CPU, uploading the resulting linear data as GPU textures, and translating multidimensional coordinate lookups into normalized texture sampling operations inside the compiled WebGL shader. Because graphics hardware does not natively support nested dynamic memory references, the library manages dimensions and index math automatically to allow seamless multidimensional indexing syntax within your kernel functions.

CPU-Side Flattening and Typed Array Conversion

JavaScript arrays can natively nest arrays within arrays, creating structures such as matrices (2D) or volumetric cubes (3D). When a nested array is passed as an argument to a GPU.js kernel, the CPU runtime inspects the structure to determine its shape and dimensions.

Graphics cards execute operations via WebGL or WebGPU pipelines, which rely on continuous memory buffers. GPU.js traverses the nested JavaScript arrays and flattens them into a single, contiguous typed array—typically a Float32Array.

Texture Packaging and Uniforms

Once flattened, GPU.js packages the data into a WebGL data texture:

  • Packing: The flat data is loaded into texture channels (RGBA or floating-point textures depending on hardware support and configuration).
  • Dimension Metadata: GPU.js sends the dimensions of each axis (width, height, depth) to the shader as uniform variables. These variables act as constant references that the shader uses to compute proper memory offsets during execution.

GLSL Translation and Index Resolution

Within the kernel, you might write syntax accessing a 2D or 3D coordinate, such as myMatrix[y][x] or cube[z][y][x]. During compilation from JavaScript to GLSL:

  1. GPU.js intercepts the chained bracket notation.
  2. The index operations are converted into linear index calculations: \[\text{Index}_{2D} = y \times \text{width} + x\] \[\text{Index}_{3D} = z \times (\text{width} \times \text{height}) + y \times \text{width} + x\]
  3. The linear index is converted into UV texture coordinates.
  4. A texture lookup function (such as texture2D) retrieves the data point from the packed texture and unpacks the float value back into the kernel pipeline.

Homogeneity Requirements

Because GPU.js relies on strict geometric strides to resolve indices, input arrays must be strictly rectangular or cubical. "Ragged" or jagged arrays—where sub-arrays have varying lengths—cannot be accurately mapped onto regular textures. If an input contains rows or columns of inconsistent lengths, the index calculation will misalign, leading to corrupt reads or runtime compilation errors.

Performance Implications

While passing nested JavaScript arrays provides code readability, the CPU-side flattening process introduces memory and processing overhead before the kernel executes. For performance-critical applications or large datasets, passing pre-flattened 1D typed arrays or GPU.js-generated textures directly into the kernel avoids CPU overhead and provides faster data transfers.
