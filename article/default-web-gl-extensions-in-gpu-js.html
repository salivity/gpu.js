Default WebGL Extensions in GPU.js

This article explains the specific WebGL extensions automatically initialized and enabled during the bootstrapping phase of GPU.js. When GPU.js prepares a browser context for general-purpose GPU (GPGPU) computation, it queries the underlying graphics hardware and activates specific WebGL extensions required to handle floating-point textures, expanded index buffers, and multiple render targets. Depending on whether a WebGL 1 or WebGL 2 context is created, GPU.js targets distinct sets of extensions to ensure seamless numeric computation.

WebGL 1 Bootstrapping Extensions

When initializing a standard WebGL 1 context (WebGLKernel), GPU.js automatically attempts to enable four core extensions:

  1. OES_texture_float
    Enables 32-bit IEEE floating-point textures. Without this extension, WebGL 1 contexts are restricted to standard 8-bit integer formats per channel, making scientific calculations, continuous numeric algorithms, and high-precision outputs impossible.

  2. OES_texture_float_linear
    Provides linear filtering capabilities for floating-point textures. While nearest-neighbor interpolation is the standard fallback, this extension allows GPU.js to read and sample interpolated float data directly within kernels when required.

  3. OES_element_index_uint
    Extends index buffers to support 32-bit unsigned integers (gl.UNSIGNED_INT). By default, WebGL 1 limits element indices to 16-bit unsigned shorts (up to 65,535 vertices). This extension allows GPU.js to index larger data sets directly across internal geometries.

  4. WEBGL_draw_buffers
    Provides Multiple Render Targets (MRT) functionality. This allows a GPU.js kernel to output values to multiple texture buffers concurrently within a single rendering pass, drastically reducing memory bandwidth overhead during complex matrix calculations.

WebGL 2 Bootstrapping Extensions

When the environment supports WebGL 2 (WebGL2Kernel), many WebGL 1 extensions are already part of the core specification. However, GPU.js still automatically activates specific complementary extensions during startup:

  1. EXT_color_buffer_float
    While WebGL 2 supports 32-bit floating-point textures natively for reading and sampling, rendering directly into them requires this extension. GPU.js enables EXT_color_buffer_float so kernel executions can write 32-bit float data directly to framebuffers.

  2. OES_texture_float_linear
    Carried over from WebGL 1, this extension remains optional in the baseline WebGL 2 specification and is explicitly requested by GPU.js to allow linear interpolation on 32-bit float textures.

Why GPU.js Enables These Extensions

GPU.js operates by compiling JavaScript mathematical functions into GLSL shaders and rendering the results into off-screen framebuffers. Standard graphics pipelines prioritize integer-based color representation (such as RGBA channels between 0 and 255). By automatically requesting these extensions during its context initialization stage, GPU.js reconfigures the graphics pipeline into an arbitrary 32-bit floating-point numeric processor without requiring manual WebGL configuration from the developer.
