Modeling Turing Patterns via Diffusion in gpu.js

Turing morphogenetic pattern formation can be modeled effectively via multi-component reaction-diffusion systems using gpu.js. By translating partial differential equations into parallelized WebGL kernels, developers can run complex, multi-species chemical simulations directly in the browser at 60 frames per second. This article explains the underlying reaction-diffusion mechanics, details how to structure multi-component systems using discrete numerical approximations, and outlines the practical implementation steps required to compute these patterns in gpu.js.

The Mathematical Foundation: Reaction-Diffusion Systems

Alan Turing’s 1952 theory of morphogenesis posits that complex biological patterns—such as stripes, spots, and spirals—arise spontaneously from the interaction of two or more diffusing chemical substances (morphogens). A standard multi-component system consists of:

  1. Activator (\(U\)): Promotes its own production and the production of the inhibitor.
  2. Inhibitor (\(V\)): Suppresses the production of the activator and diffuses at a significantly faster rate than the activator (\(D_v \gg D_u\)).

The state evolution is governed by coupled partial differential equations (PDEs):

\[\frac{\partial U}{\partial t} = D_u \nabla^2 U + R_u(U, V)\] \[\frac{\partial V}{\partial t} = D_v \nabla^2 V + R_v(U, V)\]

Where:

  • \(D_u\) and \(D_v\) are diffusion rates.
  • \(\nabla^2\) is the Laplace operator representing spatial diffusion.
  • \(R_u\) and \(R_v\) represent non-linear reaction kinetics (such as the Gray-Scott, FitzHugh-Nagumo, or Schnakenberg models).

Why Use gpu.js?

Reaction-diffusion models require evaluating diffusion and reaction steps across a discretized grid (e.g., \(512 \times 512\) or \(1024 \times 1024\) points). Calculating the Laplacian for millions of grid cells sequentially using standard JavaScript leads to unacceptable latency.

The gpu.js library solves this by compiling JavaScript functions into WebGL fragment shaders. Because the diffusion and reaction at any given point \((x, y)\) depend only on the immediate local neighborhood and the cell's current values, the entire grid can be computed concurrently across thousands of GPU cores.

Implementing Multi-Component Diffusion in gpu.js

1. Spatial Discretization (The Discrete Laplacian)

Diffusion is approximated using finite difference methods. In a 2D grid, the Laplacian \(\nabla^2 A\) at coordinate \((x, y)\) is computed using a 5-point stencil:

\[\nabla^2 A \approx A_{x+1, y} + A_{x-1, y} + A_{x, y+1} + A_{x, y-1} - 4A_{x, y}\]

For smoother, isotropic diffusion, a 9-point convolution kernel with diagonal weighting is often preferred:

  • Center: \(-1.0\)
  • Orthogonal neighbors (up, down, left, right): \(0.2\)
  • Diagonal neighbors: \(0.05\)

2. Ping-Pong Framebuffering

A shader cannot read from and write to the same texture memory simultaneously. Simulating continuous time steps requires a "ping-pong" architecture:

  1. Allocate two GPU-bound arrays/textures: Texture A (read) and Texture B (write).
  2. Execute the kernel: Read current concentrations from Texture A, compute the reaction and diffusion steps, and output the result to Texture B.
  3. Swap roles: Texture B becomes the input for the next time step, and Texture A becomes the target.

By setting .setOutput([width, height]) and .setPipeline(true) in gpu.js, intermediate states remain on the GPU as textures, eliminating performance-killing CPU-to-GPU memory transfers.

3. Handling Multiple Components

In a multi-component model, each cell must track at least two concentrations (\(U\) and \(V\)). This can be accomplished in gpu.js through two primary methods:

  • Vector Textures: Use graphical output formats where the red channel represents morphogen \(U\) and the green channel represents morphogen \(V\). The kernel reads RGBA values and outputs updated RGBA vectors.
  • Dual Interleaved Kernels: Run two sequential kernels per time step—one updating concentration grid \(U\) and another updating concentration grid \(V\).

4. Numerical Time Stepping

Temporal evolution uses the forward Euler integration method:

\[U_{t+\Delta t} = U_t + \left( D_u \nabla^2 U + R_u(U, V) \right) \Delta t\]

To maintain numerical stability, \(\Delta t\) must adhere to the Courant-Friedrichs-Lewy (CFL) condition:

\[\Delta t \le \frac{\Delta x^2}{4 \cdot \max(D_u, D_v)}\]

If \(\Delta t\) is set too high, the system destabilizes, resulting in numerical overflow and artifact collapse.

Implementation Considerations

  • Floating-Point Precision: Turing patterns are sensitive to tiny numerical perturbations. Ensure WebGL 2 or the OES_texture_float extension is enabled so that intermediate values are stored in 32-bit floating-point textures rather than clamped 8-bit integers.
  • Boundary Conditions: Set appropriate edge conditions inside the kernel. Periodic boundaries (toroidal wrapping via modulo arithmetic on indices) eliminate artificial wall reflections, while Neumann boundaries (clamping indices to edge limits) model closed chemical containers.
  • Perturbation Seed: Turing patterns require an initial break in symmetry. Initialize the concentration grids with uniform steady-state values, then inject random noise into a small cluster of cells to seed morphogenesis.
