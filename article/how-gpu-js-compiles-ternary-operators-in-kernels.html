How GPU.js Compiles Ternary Operators in Kernels

GPU.js accelerates JavaScript by transpiling kernel functions into low-level WebGL or WebGPU shader code that runs directly on graphics hardware. When encountering a ternary operator (condition ? exprIfTrue : exprIfFalse), GPU.js parses the JavaScript syntax tree, validates strict shader data types, and transforms the JavaScript construct into a valid, statically-typed GLSL conditional expression. This overview breaks down the complete compilation pipeline from Abstract Syntax Tree (AST) parsing to final shader output.

AST Parsing and Node Identification

The compilation process begins on the CPU before any shader execution takes place. GPU.js uses an AST parser (traditionally built on Acorn) to convert the kernel's JavaScript source string into a syntax tree.

In the generated AST, a JavaScript ternary operator is represented as a ConditionalExpression node, which contains three primary child nodes:

  • test: The boolean condition being evaluated.
  • consequent: The expression returned if the test evaluates to true.
  • alternate: The expression returned if the test evaluates to false.

GLSL Translation and the Ternary Operator

Unlike control-flow statements such as if-else blocks, which require statement-level handling and branching instructions in shader code, the ternary operator is an inline expression. GLSL (OpenGL Shading Language) natively supports the ternary operator syntax with similar semantics to C and JavaScript.

During the transpilation pass, the GPU.js code generator encounters the ConditionalExpression node and recursively translates each sub-expression into GLSL syntax:

  1. Compiling the Test Expression: The test node is converted to a GLSL expression that must resolve to a boolean (bool). If the JavaScript expression relies on truthy/falsy evaluation (such as an integer or float), GPU.js normalizes it into an explicit comparison (e.g., value != 0.0).
  2. Compiling Consequent and Alternate: Both the consequent and alternate expressions are translated into their corresponding GLSL mathematical or variable representations.
  3. String Emission: GPU.js emits the formatted GLSL string: ((test) ? (consequent) : (alternate)).

Strict Type Enforcement

JavaScript is dynamically typed, meaning a ternary operator can legally return different data types depending on the condition (for example, condition ? 1.5 : 2). In GLSL, both branches of a ternary operator must return identical types.

GPU.js implements static type tracking across kernel compilation:

  • Type Resolution: The compiler checks the resolved return types of both the consequent and alternate branches.
  • Automatic Casting: If one branch yields an integer and the other yields a float, GPU.js automatically casts the integer branch to a float to satisfy GLSL specifications.
  • Type Mismatch Rejection: If the types are fundamentally incompatible (such as a matrix on one side and a scalar on the other) and cannot be implicitly cast, the GPU.js compiler throws a compilation error during the setup phase before dispatching the shader to the GPU.

GPU Execution Behavior

Once compiled into native GLSL, the ternary operator executes within the GPU's streaming multiprocessors. Because GPUs process instructions across wide vector lanes (warps or wavefronts), conditional operations with dynamic outcomes across neighboring threads can cause branch divergence.

For simple mathematical ternaries, modern GPU compilers typically optimize the compiled ternary GLSL instruction into conditional move operations (CMOV or SEL), avoiding actual instruction branching and evaluating the condition with minimal performance overhead.
