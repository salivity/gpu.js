Sphere Tracing Soft Shadows in GPU.js

Approximating realistic soft shadow penumbras using sphere tracing techniques is fully achievable within gpu.js. By combining Signed Distance Functions (SDFs) with ray marching algorithms, developers can compute physically plausible shadow falloffs directly on the GPU using JavaScript syntax. This article details the mathematical principles behind sphere-traced soft shadows, outlines how to implement the technique using gpu.js kernels, and addresses the performance and architectural considerations unique to the library.

The Principle of Sphere-Traced Soft Shadows

Sphere tracing relies on Signed Distance Functions, which return the shortest distance from any point in space to the nearest surface. When casting a primary ray from the camera, the ray steps forward by this distance until it hits a surface.

To compute hard shadows, a shadow ray is cast from the hit point toward the light source. If any step along this ray encounters an object (distance drops below an epsilon threshold), the point is considered fully in shadow.

Soft shadows, however, simulate an area light source by measuring how closely the shadow ray misses intervening geometry. The standard approximation, popularized by Inigo Quilez, tracks the minimum ratio of distance to ray travel distance along the light path:

penumbra_factor = min(penumbra_factor, k * d / t)

In this formula:

  • d is the distance returned by the SDF at the current step.
  • t is the total distance traveled along the shadow ray so far.
  • k is a user-defined scalar controlling shadow softness (lower values yield softer edges, higher values produce sharper edges).

The resulting factor clamps between 0.0 (fully occluded) and 1.0 (fully lit), providing a smooth gradient across the penumbra without the high computational cost of distributed ray tracing.

Feasibility in GPU.js

gpu.js compiles a strictly typed subset of JavaScript into WebGL fragment shaders. Because sphere tracing algorithms rely almost entirely on scalar mathematics, 3D vector arithmetic, and bounded for loops, the approach translates cleanly into gpu.js kernels.

Key capabilities in gpu.js that enable this:

  • Loop support: Iterative ray stepping loops can be expressed via standard JavaScript for loops, which compile directly into GLSL loops.
  • Math functions: Native access to Math.min, Math.max, Math.sqrt, and vector math routines enables writing standard SDF primitives (spheres, boxes, planes).
  • Graphical output: Kernels configured with the graphical output mode (output: [width, height], graphical: true) write color outputs directly to an HTML5 canvas via WebGL.

Implementation Architecture

To implement soft shadows in gpu.js, the kernel structure follows these steps:

  1. Camera Ray Generation: Determine the ray origin and normalized direction vector based on the current thread coordinates (this.thread.x, this.thread.y).
  2. Primary Intersection: Step along the ray using the global SDF until reaching a surface or the maximum view distance.
  3. Shadow Ray Evaluation: If an intersection occurs, compute the surface normal and start a secondary ray offset slightly along that normal toward the light position.
  4. Penumbra Tracking: While marching toward the light:
    • Sample the scene SDF.
    • If the sampled distance is less than zero or an occlusion threshold, return 0.0 (fully shadowed).
    • Update the soft shadow factor using the minimum value of k * d / t.
    • Advance the ray by d.
  5. Lighting Combination: Multiply the diffuse/specular lighting components by the calculated penumbra factor to produce the final pixel color.

An enhanced variant of the formula avoids penumbra artifacts when the ray starts close to the surface by tracking the closest approach using geometric right triangles:

y = d * d / (2.0 * previous_d);
d_corrected = sqrt(d * d - y * y);
factor = min(factor, k * d_corrected / max(0.0, t - y));

This improved calculation can also be implemented within gpu.js using native JavaScript math operators.

Constraints and Performance Considerations

While sphere tracing soft shadows works in gpu.js, several constraints must be managed:

  • Loop Bounds: WebGL requires statically bounded loops. Dynamic while-loops must be avoided; ray marching steps must use fixed iterations (e.g., 64 to 128 maximum steps) paired with conditional break statements.
  • Transpiler Restrictions: gpu.js does not support custom object types, complex classes, or array closures within kernels. Math operations must be written in flat scalar code (handling x, y, and z components individually) or using flat fixed-size arrays.
  • Branch Divergence: Rays traversing different parts of the screen will terminate at different loop counts. While modern GPUs handle this, heavily divergent scenes will impact frame rates.
  • Precision: WebGL default float precisions can introduce banding or self-shadowing acne. Adding small offsets (surface biases) along the surface normal before launching the shadow ray is essential.

Sphere tracing soft shadows in gpu.js is a fully viable technique. It enables the creation of real-time, aesthetically rich 3D graphics in the browser using familiar JavaScript syntax while harnessing GPU acceleration.
