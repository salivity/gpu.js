Implementing Gauss-Seidel for Sparse Systems in gpu.js

This article explains how to adapt and implement the Gauss-Seidel relaxation method for sparse linear systems using the gpu.js library. Because standard Gauss-Seidel relies on sequential updates that conflict with the massive parallelism of graphics processors, executing it in WebGL/WebGPU contexts requires restructuring the algorithm via multi-coloring, flattening sparse data structures into GPU-friendly textures, and handling iterative state through ping-pong memory buffers.

The Parallelization Challenge: Red-Black Ordering

Standard Gauss-Seidel updates each unknown sequentially using already computed values from the current iteration:

\[x_i^{(k+1)} = \frac{1}{A_{ii}} \left( b_i - \sum_{j < i} A_{ij} x_j^{(k+1)} - \sum_{j > i} A_{ij} x_j^{(k)} \right)\]

Because GPU kernels execute in parallel across thousands of threads, simultaneous reads and writes to vector \(x\) cause race conditions. To resolve this constraint, the system must be decoupled using graph coloring, most commonly Red-Black Gauss-Seidel:

  1. Partition unknowns into two disjoint sets: "Red" and "Black", where no two nodes of the same color share an edge (non-zero matrix entry).
  2. Update all Red nodes in parallel using values from the Black nodes.
  3. Update all Black nodes in parallel using the newly updated Red values.

Formatting Sparse Matrices for gpu.js

gpu.js lacks native support for dynamic pointer-based structures. Standard Compressed Sparse Row (CSR) formats use variable-length rows, which cause severe thread divergence on the GPU. The ELLPACK format is better suited for WebGL kernels because it pads all rows to a uniform maximum degree (\(M\) non-zero elements per row).

Represent the system \(Ax = b\) using flattened 2D arrays of dimensions [N, M]:

  • val[row][k]: The non-zero values for each row.
  • col[row][k]: The corresponding column indices.
  • diag[row]: Pre-extracted diagonal values (\(A_{ii}\)) for fast division.
  • b[row]: The right-hand side vector.
  • color[row]: A binary mask (0 for Red, 1 for Black).

Handling Iterative State with Double Buffering

gpu.js runs kernels as pure functions that return new textures rather than mutating inputs in place. To preserve state across iterations without expensive GPU-to-CPU memory readbacks, configure the kernels with pipeline: true and swap the inputs and outputs between successive steps (ping-pong buffering).

Implementation

The following setup configures the gpu.js kernel and runs the iterative solver.

const { GPU } = require('gpu.js');
const gpu = new GPU();

const N = 1024; // Number of equations
const MAX_DEGREE = 4; // Max non-zero entries per row (excluding or including diagonal)

// Define the update kernel
const updateColor = gpu.createKernel(function(x, b, diag, val, col, colorMask, targetColor, maxDegree) {
    const i = this.thread.x;

    // Only update nodes matching the current target color phase
    if (colorMask[i] !== targetColor) {
        return x[i];
    }

    let sum = 0;
    for (let k = 0; k < maxDegree; k++) {
        const j = col[i][k];
        if (j >= 0) { // -1 represents padding
            sum += val[i][k] * x[j];
        }
    }

    return (b[i] - sum) / diag[i];
})
.setOutput([N])
.setPipeline(true)
.setImmutable(true);

function solve(b, diag, val, col, colorMask, iterations) {
    // Initial guess x0 = 0
    let xCurrent = gpu.createKernel(function() { return 0; }).setOutput([N]).setPipeline(true)();

    for (let iter = 0; iter < iterations; iter++) {
        // Phase 1: Update Red elements (targetColor = 0)
        const xRed = updateColor(xCurrent, b, diag, val, col, colorMask, 0, MAX_DEGREE);
        
        // Clean up previous texture reference to avoid memory leaks
        if (iter > 0) xCurrent.delete();

        // Phase 2: Update Black elements (targetColor = 1)
        const xBlack = updateColor(xRed, b, diag, val, col, colorMask, 1, MAX_DEGREE);
        xRed.delete();

        xCurrent = xBlack;
    }

    // Read result back to CPU
    const result = xCurrent.toArray();
    xCurrent.delete();
    return result;
}

Engineering Constraints and Optimization

  • Loop Bounds: gpu.js requires loop limits to be constant or bounded integers known at compilation. The maxDegree parameter must bound the inner iteration.
  • Index Alignment: Unused slots in the ELLPACK matrix arrays must be filled with -1 for indices and 0 for values to prevent out-of-bounds lookups.
  • Precision: WebGL shaders commonly run single-precision 32-bit floating-point numbers (float). Ensure your sparse system is well-conditioned, as numerical stability issues appear earlier than in 64-bit CPU implementations.
  • Texture Read Overhead: Keeping intermediate results on the GPU using .setPipeline(true) prevents costly WebGL framebuffer readbacks until convergence criteria are met or total iterations expire.
