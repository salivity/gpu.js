Integer vs Float Division in GPU.js Kernels

This article provides an overview of how gpu.js handles division operations within compute kernels, detailing how the library transpiles JavaScript into OpenGL Shading Language (GLSL). Because JavaScript abstracts variable types while GPUs enforce strict typing, gpu.js must translate standard JavaScript division into either native GLSL floating-point division or integer-truncated operations depending on variable types, mathematical helper functions, and the target WebGL environment.

The GLSL Transpilation Context

When gpu.js compiles a JavaScript kernel, it converts the JavaScript Abstract Syntax Tree (AST) into WebGL shader code. In standard JavaScript, the division operator (/) always produces a floating-point result, even when dividing two whole numbers (for example, 7 / 2 yields 3.5).

In GLSL, however, operations are strictly typed. Dividing an integer by an integer performs truncated integer division, while dividing floats performs standard floating-point division. Furthermore, mixing types without explicit casting (such as float / int) causes compilation errors in WebGL. Consequently, gpu.js must enforce strict type management during the compilation step.

Floating-Point Division Implementation

By default, gpu.js treats generic numeric inputs, standard constants, and internal calculations as 32-bit floating-point values (highp float). This design ensures compatibility with WebGL 1.0, which has limited support for native integer computation, and preserves standard JavaScript mathematical behavior.

When you write:

const result = a / b;

gpu.js transpiles this directly into GLSL's native floating-point division:

float result = a / b;

If either operand is identified as an integer, the compiler inserts GLSL type casts (such as float(a) / float(b)) to ensure the GPU executes a floating-point operation on its floating-point units (FPUs) rather than throwing a type mismatch error.

Implementing Integer Division

Because JavaScript lacks a native integer division operator (such as // in Python), integer division cannot be expressed using the / token alone. Instead, developers must emulate integer division using standard JavaScript math functions inside the kernel:

const result = Math.floor(a / b);

During transpilation, gpu.js maps Math.floor() to the native GLSL floor() function:

float result = floor(a / b);

In standard kernels, this operation still runs on floating-point hardware: the values are divided as 32-bit floats, and the hardware truncates the fractional part downward. While this achieves the mathematical result of integer division, it is subject to floating-point rounding quirks near extreme precision boundaries.

WebGL 2 and Explicit Integer Typing

When running on WebGL 2, gpu.js supports true integer types (int and unsigned int). If kernel arguments or variables are explicitly typed as integers using the gpu.js argument typing API:

const kernel = gpu.createKernel(function(a, b) {
  return a / b;
}, {
  argumentTypes: { a: 'Integer', b: 'Integer' }
});

Under WebGL 2, the transpiler emits native GLSL integer types:

int result = a / b;

In this scenario, the operation executes directly on the GPU’s integer arithmetic logic units (ALUs). Unlike Math.floor() (which rounds toward negative infinity), native GLSL integer division truncates toward zero, matching the behavior of integer division in languages like C, C++, and Java.
