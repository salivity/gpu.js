Using gpu.js for L-System Plant Growth

Evaluating and rasterizing Lindenmayer systems (L-systems) with gpu.js is technically possible, but it requires dividing the pipeline between symbolic logic and parallel numerical processing. While the parallel rewriting of strings is restricted by the memory and data-type constraints of WebGL shaders, gpu.js excels at computing spatial transformations, evaluating numerical branch positions, and rasterizing final branch structures to an HTML5 canvas.

Evaluating L-System Rewrite Rules

gpu.js compiles a subset of JavaScript into WebGL fragment shaders. Because WebGL shaders lack dynamic memory allocation, pointers, and native string manipulation, you cannot run standard string-based L-system rewriting directly inside a gpu.js kernel.

To evaluate production rules using gpu.js, the system must be converted into a matrix- or array-based numeric representation:

  • Numeric Encoding: Replace alphabet symbols (such as F, +, -, [, ]) with integer tokens.
  • Fixed-Memory Buffers: Pre-allocate maximum buffer sizes for generation steps. Because GPU threads cannot easily append dynamic amounts of data, a kernel must evaluate token expansion using parallel prefix sums (stream compaction) to compute output offsets.
  • Array-to-Array Transformations: Each thread inspects an input token and writes the corresponding expansion into an allocated output array.

Due to the architectural overhead of managing stream compaction in WebGL via gpu.js, evaluating the symbolic string rewrite on the CPU and sending the resulting numerical data to the GPU is often more practical for small to medium iteration depths.

Interpreting Turtle Graphics on the GPU

Standard L-system interpretation relies on "turtle graphics," which processes symbols sequentially using a state stack ([ to push state, ] to pop state). This sequential dependency presents a bottleneck for standard parallel architectures.

To process this step efficiently with gpu.js:

  1. Pre-compute Line Segments: The CPU can perform a single-pass turtle traversal to build a flat buffer of line segments represented by starting coordinates \((x_1, y_1, z_1)\) and ending coordinates \((x_2, y_2, z_2)\), along with branch thickness and angles.
  2. Parallel Coordinate Transformations: If growth over time involves wind physics, bending, or scale interpolation, gpu.js can run a kernel over every branch segment simultaneously, applying matrix transformations in parallel across thousands of nodes.

Rasterizing L-Systems with gpu.js

gpu.js provides a graphical: true mode that allows a kernel to output directly to an HTML5 canvas using WebGL. You can rasterize an L-system plant using one of two primary GPU techniques:

1. Distance Field Raymarching (Volumetric Rasterization)

Each pixel on the screen corresponds to a thread in the gpu.js kernel. By passing the array of line segments as flat uniform arrays into the kernel:

  • The kernel computes the shortest distance from the pixel's world-space coordinate to each line segment (capsule or cylinder distance function).
  • The pixel color is determined by the minimum distance found, creating smooth, anti-aliased branches with native support for lighting, shadows, and ambient occlusion.

2. Screen-Space Line Accumulation

For 2D L-systems, each pixel thread checks whether it lies within the bounding box and width of any segment in the array. If the distance falls within the branch radius, the kernel writes the color value to that pixel.

Summary of Feasibility

  • Symbolic Evaluation: Poorly suited for native gpu.js execution due to the absence of native string handling and dynamic memory in WebGL shaders. Requires encoding symbols as numeric arrays and implementing custom stream compaction.
  • Spatial Transformation: Highly suited. gpu.js can manipulate thousands of branch endpoints, apply growth vectors, and compute wind deformation in parallel.
  • Rasterization: Highly suited. By leveraging graphical: true, gpu.js can rasterize the resulting geometry using signed distance fields or screen-space projection directly to an interactive canvas.
