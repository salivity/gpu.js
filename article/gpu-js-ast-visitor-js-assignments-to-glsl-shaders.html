GPU.js AST Visitor: JS Assignments to GLSL Shaders

This article explores how GPU.js leverages the Abstract Syntax Tree (AST) visitor pattern to translate standard JavaScript assignment operators into statically typed, valid WebGL shader code (GLSL). By parsing JavaScript into an AST, traversing nodes through specialized visitor methods, inferring types, and rewriting compound expressions, GPU.js seamlessly bridges the gap between dynamic JavaScript execution and strict GPU-side compilation.

Parsing JavaScript into an Abstract Syntax Tree

Before any transformation occurs, GPU.js passes the user-defined kernel function into a parser, typically Acorn, to generate an ESTree-compliant Abstract Syntax Tree. In this tree structure, every statement and expression is categorized into discrete nodes. When a JavaScript function contains a variable assignment, such as let x = 5; or total += value[i];, the parser produces structural nodes classified primarily as VariableDeclarator or AssignmentExpression.

The Role of the AST Visitor Pattern

GPU.js utilizes the visitor pattern to separate the AST data structure from the code-generation algorithms. The core code generator implements traversal methods corresponding to each AST node type.

When the traversal encounters an assignment node, it invokes a dedicated handler—traditionally named AssignmentExpression(node) or an equivalent generator method within the transpiler pipeline. This visitor method is responsible for three tasks:

  1. Recursively visiting the left-hand side (the target identifier or member expression).
  2. Recursively visiting the right-hand side (the expression producing the value).
  3. Emitting the synthesized GLSL string that represents the assignment.

Type Inference and Scope Management

Unlike JavaScript, GLSL is a statically typed language that strictly forbids implicit type conversions between scalars, vectors, and integers. During assignment traversal, the visitor checks its internal symbol table and scope tracker:

  • Variable Declarations: If an assignment represents the initial definition of a variable (often routed through a VariableDeclaration visitor), GPU.js inspects the right-hand side node to deduce the data type (such as float, int, vec2, vec3, or vec4). It then prepends the appropriate GLSL type specifier before the variable name.
  • Reassignment: If the variable was previously declared, the visitor verifies that the assigned value conforms to the expected type. If there is a type mismatch—such as assigning an integer literal to a declared float—the visitor inserts explicit GLSL type-casting functions, turning x = 1 into x = float(1).

Handling Compound and Complex Operators

JavaScript allows various compound assignments, such as +=, -=, *=, and /=. GLSL natively supports many of these operators for basic types, but differences arise when dealing with multidimensional arrays, matrix operations, or vector math.

The visitor evaluates the operator property of the AssignmentExpression node:

  • Direct Mapping: If the types on both sides natively support the operator in GLSL, the visitor directly outputs the left-hand identifier, the operator, and the converted right-hand expression (e.g., a += b;).
  • Decomposition and Adaptation: When JavaScript operations do not have a 1:1 GLSL equivalent—such as certain bitwise assignments or operations involving custom internal representations like color matrices—the visitor decomposes the operation into an explicit reassignment. For instance, it can rewrite the expression into target = target operator (cast_expression).

Target Resolution for Arrays and Vectors

In GPU kernels, assignments frequently target multi-dimensional arrays or pixel components. When the left-hand side of an assignment is a MemberExpression, the visitor processes it to determine whether it maps to an array index, a texture coordinate lookup, or a vector component swizzle (such as .r, .g, or .x). The visitor writes out the target using valid GLSL component accessors, ensuring the assignment correctly updates the target memory slot on the GPU.
