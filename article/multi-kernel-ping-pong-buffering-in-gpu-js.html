Multi-Kernel Ping-Pong Buffering in GPU.js

Multiple GPU.js kernels can share textures using a ping-pong buffer technique by enabling pipeline mode. By setting the pipeline option to true, GPU.js retains kernel output as WebGL textures on the GPU rather than transferring data back to the CPU as standard JavaScript arrays. This allows different kernels to pass, consume, and alternate textures back and forth seamlessly, maximizing performance for iterative algorithms, physics simulations, and image processing filters.

Enabling Texture Output with Pipeline Mode

By default, GPU.js reads input data, runs the calculation on the GPU, and automatically serializes the result back to the CPU as a typed array or multidimensional array. This transfer introduces significant performance overhead.

To enable texture sharing between kernels, configure each participating kernel with the pipeline: true option:

const gpu = new GPU();

const kernelA = gpu.createKernel(function(inputTexture) {
    return inputTexture[this.thread.y][this.thread.x] * 1.5;
}, {
    output: [512, 512],
    pipeline: true
});

const kernelB = gpu.createKernel(function(inputTexture) {
    return inputTexture[this.thread.y][this.thread.x] + 0.5;
}, {
    output: [512, 512],
    pipeline: true
});

When pipeline: true is active, executing the kernel returns a Texture instance instead of an array.

Implementing the Ping-Pong Technique

The ping-pong technique relies on alternating between two texture buffers: one serves as the read target (source), while the other acts as the write target (destination). In the subsequent step, their roles reverse.

When using multiple distinct kernels, you can chain their execution by feeding the output texture of the first kernel directly into the second, and vice versa:

// Initial state data
let initialData = getInitialDataArray();

// Generate initial texture
let textureA = kernelA(initialData);
let textureB = null;

const iterations = 100;

for (let i = 0; i < iterations; i++) {
    // Kernel B reads Texture A and outputs Texture B
    textureB = kernelB(textureA);

    // Optional: Process further with additional kernels using textureB

    // Kernel A reads Texture B and writes back to Texture A
    textureA = kernelA(textureB);
}

// Extract final values back to CPU when processing finishes
const finalResult = textureA.toArray();

Memory Management and Preventing VRAM Leaks

When kernels continuously generate new textures inside a loop, WebGL texture memory can accumulate quickly if not managed correctly. GPU.js handles internal textures automatically in simple pipelines, but complex ping-pong loops across multiple kernels can cause memory leaks if old references are abandoned.

To manage memory safely:

  1. Delete Unused Intermediate Textures: Call .delete() on textures that are no longer needed in the swap cycle: 
    oldTexture.delete();
  2. Use Immutable Pipeline Mode: If your kernels do not need to clone textures internally, set immutable: true along with pipeline: true. This prevents GPU.js from maintaining unnecessary texture clones, giving you manual control over buffer cleanup.

When to Read Data Back to the CPU

Keep all textures on the GPU for the entire duration of your compute loop. Only call .toArray() on the final texture once all iterations and kernel passes are complete. Reading data back to the CPU mid-loop stalls the GPU pipeline and negates the performance benefits of using ping-pong buffers.
