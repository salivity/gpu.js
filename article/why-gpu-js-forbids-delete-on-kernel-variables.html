Why gpu.js Forbids Delete on Kernel Variables

This article explains why the gpu.js library does not allow developers to use JavaScript's delete operator on variables within a kernel. While gpu.js lets developers write compute shaders using JavaScript syntax, it functions by compiling that code into low-level shading languages like WebGL and GLSL. Because GPU architectures rely on statically typed, fixed-memory allocation rather than dynamic heaps, dynamic memory deallocation via delete cannot be mapped to the GPU, making the operator strictly prohibited inside kernel functions.

Transpilation to GLSL

The primary reason for this restriction stems from how gpu.js works under the hood. When you define a kernel function in JavaScript, it is not executed directly by a standard JavaScript engine such as V8 or SpiderMonkey. Instead, the gpu.js compiler parses the JavaScript Abstract Syntax Tree (AST) and transpiles the logic into GLSL (OpenGL Shading Language) or WebGL shader code to run natively on the graphics hardware.

Because the target environment is a GPU pipeline, every valid JavaScript expression inside the kernel must have a direct, logical equivalent in GLSL.

Static Hardware Registers vs. Dynamic Heaps

JavaScript is a high-level, dynamically typed language. In standard JavaScript, variables and objects live on a managed heap, and the delete operator is designed to remove properties from an object or mutate dynamic memory structures.

Conversely, GPU execution models depend entirely on fixed, predictable execution pipelines:

  • No Dynamic Memory Allocation: GLSL does not support dynamic memory allocation, garbage collection, or heap manipulation.
  • Hardware Register Mapping: Local variables declared inside a GPU kernel are directly mapped to physical GPU registers or a fixed thread stack.
  • Fixed Lifespans: Memory for these variables is allocated when the shader thread begins execution and deallocated only when the thread terminates.

Because registers and stack allocations cannot be destroyed, detached, or resized dynamically mid-execution, there is no hardware-level mechanism on the GPU to implement the semantics of delete.

Absence of JavaScript Object Semantics

In JavaScript, delete primarily targets object properties. Inside a gpu.js kernel, object support is extremely constrained. Full JavaScript object prototypes, hash maps, and dynamic key-value pairs do not exist within a shader context. Since a kernel cannot create or manipulate a true dynamic JavaScript object in GPU memory, the operations associated with mutating an object's structure—such as deleting one of its keys—are inherently unsupported.

Compiler Enforcement

If gpu.js allowed the delete operator to pass through the compilation phase, the resulting shader would either produce invalid GLSL syntax or generate undefined behavior on the graphics hardware. To ensure thread safety, predictable performance, and valid shader generation, the gpu.js transpiler enforces strict AST validation. When the compiler encounters an unsupported language construct like the delete operator, it halts compilation and throws an error immediately.

Proper Memory Handling in gpu.js

Instead of attempting to delete variables or clear values from memory within a kernel:

  • Let variables naturally fall out of scope when the kernel thread completes.
  • Overwrite existing variables with default values (such as 0 or 0.0) if a value should no longer be considered valid.
  • Structure data in flat arrays or matrices outside the kernel and pass them as input buffers, rather than trying to perform dynamic collection cleanup inside the GPU pipeline.
