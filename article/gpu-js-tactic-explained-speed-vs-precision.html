GPU.js Tactic Explained: Speed vs Precision

In GPU.js, configuring the tactic setting to either 'speed' or 'precision' directly alters the generated WebGL Shading Language (GLSL) code and the GPU driver's execution profile. This setting dictates whether the transpiler prioritizes execution throughput or numerical fidelity, primarily influencing floating-point qualifiers, compiler optimization flags, and mathematical intrinsic functions during runtime shader compilation.

Floating-Point Precision Qualifiers

The most direct modification occurs at the top of the generated GLSL fragment shader. In WebGL, variables require precision qualifiers to tell the GPU how many bits to allocate for numbers.

  • tactic: 'precision': Forces the compiler to emit precision highp float; and precision highp int; declarations. This guarantees standard 32-bit IEEE 754 floating-point behavior across devices that support it, minimizing cumulative rounding errors in iterative calculations or large matrix operations.
  • tactic: 'speed': May emit precision mediump float; (or allow the GPU's default medium-precision configuration, especially on mobile architectures). Medium precision typically uses 16-bit floating-point numbers (half precision), which drastically limits the dynamic range and significant digits but halves memory bandwidth consumption.

Mathematical Operations and Intrinsics

The compiled output changes how common arithmetic and transcendentals (such as trigonometry, square roots, and exponentiation) are translated into GPU instructions:

  • Approximation vs. Accuracy: Under 'speed', the shader compiler instructs the GPU driver to map functions like sin(), cos(), pow(), and reciprocal division (1.0 / x) to hardware-level fast-math intrinsic approximations. Under 'precision', the compiled output preserves standards-compliant, software-emulated, or high-accuracy hardware routines to prevent drift.
  • Denormalized Numbers: 'speed' permits the GPU hardware to flush denormalized numbers to zero (FTZ), speeding up processing pipelines at the expense of underflow precision. 'precision' enforces standard IEEE handling of subnormal values.

Register Allocation and GPU Occupancy

Because 'precision' enforces 32-bit data types throughout the generated GLSL variable assignments, the compiled binary consumes more hardware registers per thread. This higher register pressure can reduce active thread occupancy on streaming multiprocessors.

Conversely, the 'speed' output reduces register pressure by allowing 16-bit registers where supported, allowing the GPU scheduler to run more parallel threads simultaneously. The resulting trade-off manifests as higher throughput and reduced execution time under 'speed', contrasted with strict mathematical determinism under 'precision'.
