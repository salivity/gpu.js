High-DPI Displays and GPU.js Canvas Resolution

High-DPI and Retina displays impact the visual output of gpu.js by introducing a discrepancy between CSS display pixels and the physical hardware pixels of the screen. When rendering graphical kernels, gpu.js maps its output dimensions directly to the WebGL drawing buffer, which defaults to standard display scaling. Without manual adjustments for the browser’s device pixel ratio, canvas outputs appear blurry or pixelated on high-resolution screens, while pure computation kernels remain entirely unaffected.

The Device Pixel Ratio Discrepancy

Modern high-DPI displays utilize a higher physical pixel density than standard displays. Browsers handle this via the window.devicePixelRatio property, which defines the ratio of physical device pixels to logical CSS pixels. On a standard display, this ratio is 1, while Retina displays typically range from 2 to 3.

When a canvas element is added to the DOM, it has two sets of dimensions:

  1. The drawing buffer size: The internal resolution controlled by the width and height attributes of the canvas element.
  2. The display size: The visual dimensions defined by CSS styles (width and height in CSS pixels).

How GPU.js Interacts with Canvas Dimensions

In gpu.js, graphical kernels are initialized with a designated output size using the .setOutput([width, height]) method. When configured with { graphical: true }, gpu.js binds this output directly to an underlying WebGL canvas:

const render = gpu.createKernel(function() {
    this.color(this.thread.x / 500, this.thread.y / 500, 0, 1);
})
.setOutput([500, 500])
.setGraphical(true);

render();
document.body.appendChild(render.canvas);

By default, the internal buffer becomes 500x500 pixels. If this canvas is displayed on a display with a devicePixelRatio of 2, the browser scales the 500x500 raster buffer up to fill 500x500 CSS pixels. Because 500 CSS pixels require 1000 physical pixels on this display, the browser upsamples the image via bilinear filtering, resulting in noticeably soft or blurry edges.

Achieving Crisp Rendering on Retina Displays

To produce sharp visuals on high-DPI screens, the kernel's output dimensions must be multiplied by the device pixel ratio, while the canvas's CSS dimensions remain scaled to logical screen units.

To adapt gpu.js to Retina displays:

  1. Calculate Dimensions: Multiply the target CSS width and height by window.devicePixelRatio.
  2. Set Kernel Output: Pass the scaled physical dimensions to setOutput().
  3. Set CSS Dimensions: Explicitly set the CSS width and height of the canvas to the logical pixel size.
const dpr = window.devicePixelRatio || 1;
const logicalWidth = 500;
const logicalHeight = 500;

const render = gpu.createKernel(function() {
    // Math adjusts to the scaled coordinate space
    this.color(this.thread.x / this.output.x, this.thread.y / this.output.y, 0, 1);
})
.setOutput([logicalWidth * dpr, logicalHeight * dpr])
.setGraphical(true);

render();

const canvas = render.canvas;
canvas.style.width = `${logicalWidth}px`;
canvas.style.height = `${logicalHeight}px`;
document.body.appendChild(canvas);

This ensures that the WebGL drawing buffer contains a 1:1 mapping with the screen's physical hardware pixels, eliminating upscaling artifacts.

Performance Considerations

Scaling canvas resolution to match high-DPI displays increases the workload on the GPU. A display with a devicePixelRatio of 2 requires four times the number of pixels to be computed compared to a standard display (\(2 \times 2 = 4\)). On a display with a ratio of 3, the workload increases ninefold. Complex fragment shaders or intensive mathematical computations run within graphical kernels may experience reduced frame rates or performance bottlenecks when scaled up to native Retina resolutions.

Pure Computation vs. Graphical Kernels

The high-DPI scaling issue strictly applies to graphical kernels that write directly to the screen via WebGL canvases. If gpu.js is used strictly for parallel mathematical computation (such as matrix multiplication or numeric simulations without { graphical: true }), screen resolution and display pixel ratios have zero impact on the output, internal buffer precision, or computational accuracy.
