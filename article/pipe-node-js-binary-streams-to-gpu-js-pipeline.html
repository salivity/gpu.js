Pipe Node.js Binary Streams to GPU.js Pipeline

Piping raw binary streams directly into a GPU.js compute pipeline in Node.js allows you to process high-throughput data using hardware-accelerated kernels without loading massive datasets entirely into memory. This article demonstrates how to construct a Node.js Transform stream that ingests raw binary Buffer chunks, maps them to native TypedArrays with zero memory duplication, executes parallel GPU computations via gpu.js, and streams the computed results downstream.

Understanding the Pipeline Architecture

Node.js reads I/O operations as binary Buffer instances, which represent fixed-width allocations outside the V8 heap. GPU.js, running in a headless Node.js environment via WebGL or OpenCL bindings, executes compute shaders over multi-dimensional arrays or TypedArrays (such as Float32Array).

To connect these two paradigms without blocking the event loop or causing massive garbage collection churn, your pipeline must:

  1. Accumulate stream chunks to match the exact dimensional requirements of your GPU kernel.
  2. View the chunk memory directly as a TypedArray using Buffer.buffer, Buffer.byteOffset, and Buffer.byteLength.
  3. Pass the TypedArray into the GPU.js kernel.
  4. Convert the GPU output back into a Buffer to push it to the next stream consumer.

Implementing the GPU Transform Stream

The standard way to build a pipeline in Node.js is extending the Transform stream class. Below is a complete implementation showing how to process raw binary chunks of 32-bit floating-point numbers through a GPU.js kernel.

const { Transform } = require('stream');
const { GPU } = require('gpu.js');

class GPUTransformStream extends Transform {
  constructor(kernelDimensions, options = {}) {
    super(options);
    
    this.dimensions = kernelDimensions;
    this.elementSize = Float32Array.BYTES_PER_ELEMENT; // 4 bytes per float
    this.chunkByteLength = this.dimensions * this.elementSize;
    
    // Internal accumulator for partial stream chunks
    this.tailBuffer = Buffer.alloc(0);

    // Initialize headless GPU instance
    this.gpu = new GPU({ mode: 'gpu' });

    // Define compute kernel (Example: Multiply each value by 2.0 and apply an offset)
    this.kernel = this.gpu.createKernel(function (inputData) {
      return inputData[this.thread.x] * 2.0 + 0.5;
    })
    .setOutput([this.dimensions])
    .setPipeline(false); // Set to true if chaining multiple kernels on GPU memory
  }

  _transform(chunk, encoding, callback) {
    // Combine any remainder from the previous write with the incoming chunk
    let data = this.tailBuffer.length > 0 
      ? Buffer.concat([this.tailBuffer, chunk]) 
      : chunk;

    // Process all full blocks that match the kernel's execution width
    let offset = 0;
    while (offset + this.chunkByteLength <= data.length) {
      // Create a TypedArray view directly on top of the Buffer's underlying ArrayBuffer
      const inputTypedArray = new Float32Array(
        data.buffer,
        data.byteOffset + offset,
        this.dimensions
      );

      // Execute on GPU
      const result = this.kernel(inputTypedArray);

      // Cast kernel results (Float32Array) back to a binary Buffer
      const resultBuffer = Buffer.from(
        result.buffer,
        result.byteOffset,
        result.byteLength
      );

      this.push(resultBuffer);
      offset += this.chunkByteLength;
    }

    // Retain any partial block that cannot fill the kernel dimensions yet
    this.tailBuffer = data.slice(offset);
    callback();
  }

  _flush(callback) {
    // Zero-pad any remaining bytes at EOF to ensure execution completion if required
    if (this.tailBuffer.length > 0) {
      const paddedBuffer = Buffer.alloc(this.chunkByteLength);
      this.tailBuffer.copy(paddedBuffer);

      const inputTypedArray = new Float32Array(
        paddedBuffer.buffer,
        paddedBuffer.byteOffset,
        this.dimensions
      );

      const result = this.kernel(inputTypedArray);
      const resultBuffer = Buffer.from(
        result.buffer,
        result.byteOffset,
        result.byteLength
      );

      this.push(resultBuffer);
    }
    this.gpu.destroy();
    callback();
  }
}

Piping Data Through the Pipeline

Once the Transform class is defined, connect it to any standard Node.js readable source (such as fs.createReadStream, an incoming network socket, or a hardware sensor feed) and output to a writable destination.

const fs = require('fs');

const BATCH_SIZE = 1024 * 1024; // Process 1,048,576 floats per GPU run (4MB)

const sourceStream = fs.createReadStream('raw_sensor_data.bin');
const gpuStream = new GPUTransformStream(BATCH_SIZE);
const outputStream = fs.createWriteStream('processed_sensor_data.bin');

sourceStream
  .pipe(gpuStream)
  .pipe(outputStream)
  .on('finish', () => {
    console.log('Stream computation finished successfully.');
  })
  .on('error', (err) => {
    console.error('Pipeline error:', err);
  });

Key Performance Practices

  • Zero-Copy Views: Always construct your TypedArray using the (buffer, byteOffset, length) signature. Calling new Float32Array(chunk) creates a duplicate copy of the array on the heap, degrading throughput.
  • Byte Alignment: TypedArrays require byteOffset to be an exact multiple of the element size (e.g., multiples of 4 for Float32Array). Slicing or shifting bytes unevenly will throw a RangeError: start offset of Float32Array should be a multiple of 4.
  • Kernel Pipeline Mode: If your algorithm involves multiple sequential transformations, pass setPipeline(true) to createKernel(). This retains the computed output directly as a WebGL texture on the GPU memory, enabling subsequent kernels to consume it without transferring memory back to Node.js until the final stage.
