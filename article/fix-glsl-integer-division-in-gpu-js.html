Fix GLSL Integer Division in GPU.js

In gpu.js, executing mathematical operations across heterogeneous hardware can introduce unexpected truncation errors during integer division due to differences in floating-point precision between the CPU and GPU. The fixIntegerDivisionAccuracy option resolves this discrepancy by injecting an algorithmic correction into the compiled GLSL shader code, preventing off-by-one inaccuracies caused by GPU-level floating-point rounding when calculating integer quotients.

The Cause of GLSL Truncation Discrepancies

JavaScript engines handle numbers as double-precision 64-bit floats (IEEE 754), whereas WebGL and GLSL kernels typically execute using 32-bit single-precision floats (or even medium precision on mobile chipsets). When JavaScript code performing integer division—such as Math.floor(a / b) or integer casts—is transpiled to GLSL, the operation is often mapped to floating-point operations.

On various GPU architectures, dividing two numbers that should theoretically produce an exact whole integer can yield an infinitesimal under-representation. For instance, calculating 10.0 / 2.0 might evaluate internally to 4.9999995. When a standard GLSL floor() function or int() type cast is applied to this result, it aggressively truncates the value downward to 4 instead of the expected 5. This discrepancy leads to silent data corruption and divergences between CPU and GPU execution outputs.

How fixIntegerDivisionAccuracy Solves the Issue

When the fixIntegerDivisionAccuracy flag is set to true in the GPU kernel settings, the gpu.js compiler alters the generated GLSL string for division operations:

  1. Epsilon Offset Addition: Instead of generating a direct GLSL floor(x / y) or simple cast, gpu.js introduces a small floating-point epsilon (a microscopic offset) to the dividend before truncation occurs.
  2. Preventing Under-Truncation: By evaluating floor((x / y) + epsilon), results like 4.9999995 are bumped safely back over the whole-integer threshold (e.g., to 5.0000005).
  3. Preserving True Fractional Bounds: The value of the epsilon is small enough that it does not artificially push legitimate fractional values over the next integer threshold (for example, 4.9 remains below 5.0).

Practical Configuration

To apply this resolution, enable the flag within the kernel options:

const gpu = new GPU();
const kernel = gpu.createKernel(function(a, b) {
    return Math.floor(a[this.thread.x] / b[this.thread.x]);
}, {
    output: [100],
    fixIntegerDivisionAccuracy: true
});

Enabling this option introduces a negligible GPU instruction overhead while ensuring mathematical parity across mobile GPUs, desktop GPUs, and the JavaScript CPU fallback mode.
