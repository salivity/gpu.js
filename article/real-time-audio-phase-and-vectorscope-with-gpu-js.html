Real-Time Audio Phase and Vectorscope with GPU.js

Calculating real-time audio phase correlation and stereo vectorscope data using gpu.js is entirely possible in modern web browsers. By offloading parallel mathematical reductions and coordinate transformations to the GPU via WebGL shaders, gpu.js can process standard audio frame buffers (such as 1024 to 4096 samples) within typical display refresh intervals (16.6ms for 60 FPS). However, achieving optimal real-time performance requires structuring the pipeline to minimize CPU-to-GPU data transfer overhead, which is often the primary bottleneck rather than the mathematical workload itself.

Audio Phase Correlation on the GPU

Audio phase correlation measures the phase alignment between stereo channels, yielding a value between -1.0 (completely out of phase) and +1.0 (mono/fully in phase). The calculation requires three discrete parallel sums across the buffer: the dot product of the left and right channels, the sum of squares for the left channel, and the sum of squares for the right channel:

\[\text{Correlation} = \frac{\sum (L_i \times R_i)}{\sqrt{\sum (L_i^2) \times \sum (R_i^2)}}\]

In gpu.js, this is accomplished by running an element-wise multiplication kernel across the channel arrays, followed by a parallel reduction to compute the final sums. Because standard audio buffers are relatively small (usually 2048 floats per channel), gpu.js can compute these sums in fractions of a millisecond.

Stereo Vectorscope Data Generation

A stereo vectorscope (or goniometer) maps stereo audio onto a visual plane, typically rotated 45 degrees to display mid/side relationships:

  • Mid (Vertical axis): \((L + R) \times 0.7071\)
  • Side (Horizontal axis): \((L - R) \times 0.7071\)

gpu.js is well-suited for transforming raw \(L/R\) samples into \((X, Y)\) coordinate matrices. If the vectorscope is generated as an intensity map (a 2D persistence display showing sample density), gpu.js can maintain an accumulator grid as a dynamic texture. The kernel takes the coordinate pairs, computes their decay, and maps the intensity values directly on the GPU without round-tripping coordinates back to the CPU.

Performance and Pipeline Bottlenecks

While gpu.js has the raw compute capacity to process these calculations, real-time performance depends on specific architectural factors:

  1. Buffer Transfer Latency: Standard Web Audio API buffers reside on the CPU via an AudioWorkletNode or AnalyserNode. Uploading these arrays to the GPU as textures introduces memory transfer latency. Because the sample count per frame is relatively low, the transfer overhead can rival the compute time.
  2. GPU Readback Costs: If phase correlation values must be read back to JavaScript (using kernel()), CPU synchronization stalls can occur. To maintain smooth frame rates, the pipeline should either render the metrics directly to an HTML canvas using gpu.js graphical output modes or batch the readbacks asynchronously.
  3. GPU vs. CPU Trade-off: For purely scalar phase correlation calculations, modern CPU SIMD instructions executed in WebAssembly or directly in an AudioWorklet are often fast enough to run without GPU assistance. However, when generating high-resolution, high-density visual vectorscopes with thousands of plotted points and phosphor-decay effects, gpu.js significantly outperforms CPU-based 2D canvas rendering.

Practical Implementation Approach

To achieve reliable 60+ FPS performance:

  • Capture continuous audio chunks inside an AudioWorkletProcessor to avoid main-thread UI jank.
  • Pass Float32Array buffers directly into gpu.js kernels without intermediate object allocations.
  • Set the gpu.js output mode to render directly to a WebGL canvas (graphical: true) for vectorscope plotting, keeping the frame data entirely inside GPU memory.
  • Execute phase correlation reduction as a secondary lightweight kernel, reading the single resulting scalar back to the CPU only when necessary for UI telemetry.
