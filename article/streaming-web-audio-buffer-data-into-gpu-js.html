Streaming Web Audio Buffer Data into gpu.js

Processing high-throughput audio on the web requires offloading intensive mathematical computations to the GPU. This guide details how to extract raw pulse-code modulation (PCM) data from Web Audio API structures, format it, and continuously feed it into a gpu.js computing pipeline for parallelized digital signal processing.

Understanding the Pipeline Architecture

The Web Audio API handles raw audio as 32-bit floating-point numbers (Float32Array) ranging between -1.0 and 1.0. gpu.js compiles JavaScript functions into WebGL shaders that operate directly on these arrays.

To stream data efficiently:

  1. Extract PCM samples from an AudioBuffer or an active AudioWorkletNode.
  2. Pass the underlying Float32Array directly into a pre-compiled gpu.js kernel.
  3. Retrieve the processed output as a typed array or render texture.

Initializing the gpu.js Kernel

Create a persistent GPU kernel before processing any audio frames. Re-compiling kernels per audio frame creates unacceptable latency in real-time pipelines.

import { GPU } from 'gpu.js';

const gpu = new GPU();
const BUFFER_SIZE = 1024; // Standard Web Audio frame size

// Compile the kernel once
const processAudioKernel = gpu.createKernel(function(audioFrame, factor) {
  // Example operation: simple amplify/distortion transformation
  return Math.tanh(audioFrame[this.thread.x] * factor);
})
.setOutput([BUFFER_SIZE])
.setOutputToTexture(false); // Set to false to return a Float32Array

Extracting and Streaming Static AudioBuffer Data

If processing an existing AudioBuffer (such as a decoded sound file), iterate over the buffer in fixed chunk sizes matching your kernel's output dimensions:

function processEntireBuffer(audioBuffer, kernel, chunkSize = 1024) {
  const channelData = audioBuffer.getChannelData(0); // Left channel
  const totalSamples = channelData.length;
  const processedOutput = new Float32Array(totalSamples);

  for (let i = 0; i < totalSamples; i += chunkSize) {
    // Slice or view a segment matching the kernel output size
    const chunk = channelData.subarray(i, i + chunkSize);

    // If the last chunk is smaller, handle padding
    let inputChunk = chunk;
    if (chunk.length < chunkSize) {
      inputChunk = new Float32Array(chunkSize);
      inputChunk.set(chunk);
    }

    // Execute on GPU
    const result = kernel(inputChunk, 2.0);
    processedOutput.set(result.subarray(0, chunk.length), i);
  }

  return processedOutput;
}

Real-Time Streaming via AudioWorklet

For continuous streams (microphones, live synthesizers), capture audio frames on the audio thread with an AudioWorkletProcessor and transfer them to the main thread where the gpu.js instance lives.

1. Define the AudioWorklet Processor (audio-stream-processor.js)

class StreamProcessor extends AudioWorkletProcessor {
  process(inputs, outputs, parameters) {
    const input = inputs[0];
    if (input && input[0]) {
      // Transfer the Float32Array to the main thread
      this.port.postMessage(input[0]);
    }
    return true;
  }
}

registerProcessor('stream-processor', StreamProcessor);

2. Connect the Audio Graph to the gpu.js Pipeline

async function startAudioStreaming(audioContext) {
  await audioContext.audioWorklet.addModule('audio-stream-processor.js');

  const streamNode = new AudioWorkletNode(audioContext, 'stream-processor');
  
  // Set kernel size to Web Audio default quantum (128 samples)
  const realTimeKernel = gpu.createKernel(function(samples) {
    return samples[this.thread.x] * 1.5;
  })
  .setOutput([128])
  .setOutputToTexture(false);

  streamNode.port.onmessage = (event) => {
    const rawPCM = event.data; // Float32Array of length 128
    
    // Execute GPU processing
    const processedFrame = realTimeKernel(rawPCM);

    // Handle processed audio (e.g., visualization or queue for output)
    handleProcessedAudio(processedFrame);
  };

  // Connect source (e.g., microphone) to the processor
  const micStream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const source = audioContext.createMediaStreamSource(micStream);
  source.connect(streamNode);
}

Performance Best Practices

  • Avoid Memory Allocation: Reuse typed arrays rather than re-instantiating arrays inside callback loops. Frequent garbage collection spikes cause audible dropouts.
  • Batching: The default Web Audio quantum is 128 samples. For large-scale parallel processing, accumulate frames in a FIFO buffer (e.g., 512, 1024, or 2048 samples) before passing them to gpu.js to amortize GPU invocation overhead.
  • Texture Mode: If chaining multiple GPU processing steps, use .setOutputToTexture(true) to keep intermediate results in GPU VRAM, converting back to CPU-accessible memory only after the final step.
