Mercator to Polar Map Reprojection in GPU.js

Real-time reprojection of geospatial raster tiles from Web Mercator to Polar Stereographic projections requires high-throughput pixel manipulation that standard CPU operations cannot deliver smoothly. This guide demonstrates how to achieve 60 FPS raster map reprojection in the browser using GPU.js to offload reverse coordinate transformation math to WebGL shaders. By mapping each pixel in the target polar canvas back to its source location on a Mercator tile, you can transform high-resolution satellite or cartographic rasters dynamically without server-side processing.

Mathematical Foundations of the Reprojection

Direct raster transformation causes gaps or stretching if projected forward (source to destination). Reprojection shaders rely on inverse mapping: for every destination pixel \((x, y)\) in the Polar projection, compute its geographic coordinate \((\text{latitude}, \text{longitude})\), and then locate that geographic point inside the source Web Mercator raster \((u, v)\).

1. Polar Screen Coordinates to Geographic (Lat/Lon)

Assuming a north-polar stereographic projection centered on the canvas:

\[\theta = \text{atan2}(y - y_c, x - x_c)\] \[r = \sqrt{(x - x_c)^2 + (y - y_c)^2}\]

Where \((x_c, y_c)\) is the canvas center. The longitude corresponds directly to the angle \(\theta\):

\[\lambda = \theta\]

The latitude \(\phi\) is determined by the radial distance from the pole:

\[\phi = \frac{\pi}{2} - 2 \cdot \text{atan}\left(\frac{r}{R}\right)\]

Where \(R\) is a scale factor determining the zoom level of the polar projection.

2. Geographic (Lat/Lon) to Web Mercator \((u, v)\)

Once latitude \(\phi\) and longitude \(\lambda\) (both in radians) are determined, compute the normalized texture coordinates \((u, v) \in [0, 1]\) in the Web Mercator source image:

\[u = \frac{\lambda + \pi}{2\pi}\] \[v = 0.5 - \frac{\ln(\tan(\frac{\pi}{4} + \frac{\phi}{2}))}{2\pi}\]

Implementation with GPU.js

Install GPU.js via npm or import it via a CDN:

<script src="https://cdn.jsdelivr.net/npm/gpu.js@latest/dist/gpu-browser.min.js"></script>

Step 1: Initialize the Canvas and GPU Instance

Set up your target dimensions and initialize GPU.js with WebGL2 support for faster floating-point math:

const width = 1024;
const height = 1024;

const gpu = new GPU({
  mode: 'webgl2'
});

Step 2: Build the Reprojection Kernel

The GPU.js kernel runs in parallel for every pixel in the polar output canvas. Note that GPU.js places the origin (0, 0) at the bottom-left corner of the canvas.

const reprojectKernel = gpu.createKernel(function(image, width, height, scale) {
  const PI = 3.141592653589793;
  const xc = width / 2;
  const yc = height / 2;

  // Destination pixel coordinates relative to center
  const dx = this.thread.x - xc;
  const dy = this.thread.y - yc;

  const r = Math.sqrt(dx * dx + dy * dy);

  // Define the outer boundary of the polar hemisphere
  if (r > xc) {
    // Transparent or background color outside the polar disk
    this.color(0, 0, 0, 0);
    return;
  }

  // 1. Polar Screen to Geographic
  const lon = Math.atan2(dy, dx);
  const lat = (PI / 2) - 2 * Math.atan(r / scale);

  // Clamp latitude to Mercator limits (~85.0511 degrees in radians)
  const maxLat = 1.4844222;
  if (lat < -maxLat || lat > maxLat) {
    this.color(0, 0, 0, 0);
    return;
  }

  // 2. Geographic to Mercator Texture Coordinates (0.0 to 1.0)
  let u = (lon + PI) / (2 * PI);
  let v = 0.5 + Math.log(Math.tan(PI / 4 + lat / 2)) / (2 * PI);

  // Map to source image pixel dimensions
  const srcX = Math.floor(u * width);
  const srcY = Math.floor(v * height);

  // Sample pixel from Web Mercator texture
  const pixel = image[srcY][srcX];

  this.color(pixel.r, pixel.g, pixel.b, pixel.a);
})
.setOutput([width, height])
.setGraphical(true);

Step 3: Feeding the Raster to the Kernel

Load a Web Mercator raster image into an HTML image element or canvas, and pass it directly to the kernel:

const img = new Image();
img.crossOrigin = "anonymous";
img.src = "path/to/mercator-tile.png";

img.onload = () => {
  // Center scale factor determines polar zoom
  const scale = width / 2;

  // Execute kernel on the GPU
  reprojectKernel(img, width, height, scale);

  // Append generated WebGL canvas to the DOM
  document.body.appendChild(reprojectKernel.canvas);
};

Optimizing for Real-Time Interaction

When panning, rotating, or animating:

  1. Enable Texture Recycling: Use image inputs as WebGL textures rather than raw arrays to avoid CPU-to-GPU transfer bottlenecks.
  2. Apply Bilinear Filtering: The raw Math.floor() sampling causes aliasing at steep projection angles. Sample four neighboring pixels ((srcX, srcY), (srcX+1, srcY), etc.) and calculate a weighted average based on the fractional parts of u * width and v * height.
  3. Pipeline Mode: If chaining transformations (e.g., applying hillshade or color ramps to reprojected data), add .setPipeline(true) to keep the frame buffer entirely in VRAM between calls.
