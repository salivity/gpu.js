Historical Value at Risk with GPU.js

Calculating historical Value at Risk (VaR) for complex, multi-asset portfolios requires processing large matrices of historical asset price returns and asset allocations across thousands of time horizons. By leveraging gpu.js, developers can offload these intensive matrix-vector multiplications and scenario aggregations from the single-threaded Node.js or browser CPU directly to the GPU via WebGL shaders. This article covers the mathematical fundamentals of historical VaR, how to map multi-asset portfolio data to GPU memory, and the practical implementation of high-throughput gpu.js kernels to extract quantile risk metrics rapidly.

Understanding Historical Multi-Asset VaR

Historical Value at Risk estimates the maximum expected loss over a specific time horizon at a defined confidence level (such as 95% or 99%) by simulating how the current portfolio would have performed under actual past market conditions.

For a portfolio containing \(M\) assets evaluated across \(N\) historical trading days:

  1. Asset Return Matrix (\(R\)): An \(N \times M\) matrix where \(R_{t, i}\) represents the relative return of asset \(i\) at historical period \(t\).
  2. Portfolio Weights (\(w\)): A vector of length \(M\) representing the capital allocation to each asset, where \(\sum_{i=1}^M w_i = 1\).
  3. Simulated Portfolio Returns (\(R_p\)): An \(N\)-element vector where each entry is the dot product of historical asset returns and the portfolio weights: \[R_{p, t} = \sum_{i=1}^{M} R_{t, i} \cdot w_i\]
  4. VaR Extraction: The array \(R_p\) is sorted in ascending order. At a confidence level \(1 - \alpha\) (for example, \(\alpha = 0.05\) for 95% confidence), the VaR corresponds to the absolute value of the \(\alpha\)-percentile return multiplied by the total portfolio value.

Setting Up GPU.js

Install the gpu.js package in a Node.js project:

npm install gpu.js

In the browser, gpu.js can be loaded via a standard script tag or bundled via Vite/Webpack. It will compile native WebGL shaders on the fly to execute calculations in parallel across thousands of GPU cores.

Implementing the GPU Calculation Kernel

The primary bottleneck in multi-asset historical VaR is evaluating the dot product between the weights vector and hundreds of asset returns across thousands of historical days or Monte Carlo-generated historical paths. This operation is embarrassingly parallel and ideal for a GPU kernel.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Kernel: Compute portfolio return for each historical time step
function createHistoricalReturnKernel(numAssets, numPeriods) {
  return gpu.createKernel(function (returnsMatrix, weights) {
    let portfolioReturn = 0;
    for (let i = 0; i < this.constants.numAssets; i++) {
      portfolioReturn += returnsMatrix[this.thread.x][i] * weights[i];
    }
    return portfolioReturn;
  })
  .setConstants({ numAssets })
  .setOutput([numPeriods]);
}

In this kernel:

  • this.thread.x maps each GPU thread directly to a specific historical day \(t \in [0, N-1]\).
  • Every thread iterates through the assets for its assigned day, computing the weighted return in parallel.

Calculating Portfolio VaR

Once the simulated portfolio return vector is computed on the GPU, it is read back into host memory to extract the target percentile using an efficient quickselect algorithm or standard sorting:

function calculateHistoricalVaR(returnsMatrix, weights, confidenceLevel = 0.95, portfolioValue = 1000000) {
  const numPeriods = returnsMatrix.length;
  const numAssets = weights.length;

  const returnKernel = createHistoricalReturnKernel(numAssets, numPeriods);

  // Execute kernel on GPU
  const rawPortfolioReturns = returnKernel(returnsMatrix, weights);

  // Convert Float32Array to standard array and sort ascendingly
  const sortedReturns = Array.from(rawPortfolioReturns).sort((a, b) => a - b);

  // Determine the cutoff index corresponding to alpha
  const alpha = 1 - confidenceLevel;
  const index = Math.floor(alpha * numPeriods);

  const percentileReturn = sortedReturns[index];

  // Value at Risk is expressed as a positive currency loss amount
  const varAbsolute = Math.max(0, -percentileReturn * portfolioValue);

  return {
    confidenceLevel,
    percentileReturn,
    historicalVaR: varAbsolute
  };
}

// Example usage:
const NUM_PERIODS = 2520; // ~10 years of trading days
const NUM_ASSETS = 100;

// Mock historical return data (2520 x 100)
const returnsMatrix = Array.from({ length: NUM_PERIODS }, () =>
  Array.from({ length: NUM_ASSETS }, () => (Math.random() - 0.495) * 0.04)
);

// Balanced portfolio weights summing to 1
const weights = Array(NUM_ASSETS).fill(1 / NUM_ASSETS);

const result = calculateHistoricalVaR(returnsMatrix, weights, 0.99, 10000000);

console.log(`99% Historical VaR: $${result.historicalVaR.toFixed(2)}`);

Performance Optimization and Large-Scale Portfolios

When scaling to thousands of assets and multiple sub-portfolios, consider the following technical constraints:

  1. Memory Layout and Flattened Arrays: WebGL textures have dimension limits depending on host hardware. Passing a 1D flattened array (size \(N \times M\)) instead of nested arrays reduces memory allocation overhead and prevents serialization delays between the CPU and GPU.
  2. Reusing Kernels: Compiling a kernel with gpu.createKernel() carries compilation overhead. Always instantiate the kernel once during initialization and reuse it across multiple calculation requests.
  3. Pipeline Mode for Extended Metrics: If additional risk measures like Conditional Value at Risk (CVaR / Expected Shortfall) or historical stress testing are required, set pipeline: true on the kernel. This preserves the return vector in GPU VRAM as a texture, allowing downstream kernels to consume the intermediate output directly without transferring data back to the CPU.
