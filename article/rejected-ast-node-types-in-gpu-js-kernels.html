Rejected AST Node Types in GPU.js Kernels

GPU.js accelerates JavaScript applications by compiling standard functions into GPU-compatible shaders, predominantly written in WebGL/GLSL. During the compilation process, the library parses the JavaScript function into an Abstract Syntax Tree (AST) using an ESTree-compliant parser. Because graphics hardware operates on a strictly typed, parallelized, and memory-constrained architecture, GPU.js rejects a significant subset of dynamic JavaScript AST node types during lexical analysis and AST validation, throwing compilation errors before code execution occurs.

Object-Oriented and Dynamic Memory Nodes

GLSL lacks a runtime heap and does not support dynamic object instantiation, prototype chaining, or pointer referencing. As a result, GPU.js rejects any AST node that attempts to allocate or manipulate standard JavaScript objects:

  • NewExpression: Constructing objects using the new keyword cannot be mapped to static memory allocations in a shader.
  • ClassDeclaration and ClassExpression: GPU kernels do not support class structures, inheritance, or prototypes.
  • ThisExpression: Execution scope within a kernel is decoupled from the typical JavaScript execution context, making dynamic context binding invalid.
  • ObjectExpression: Creating inline object literals inside kernel loops or logic is unsupported, as GLSL cannot handle dynamic key-value dictionaries.

Asynchronous and Generator Constructs

GPU shaders execute purely synchronous code per pipeline invocation. As a consequence, non-blocking asynchronous syntax and stateful generators are strictly rejected:

  • AwaitExpression: Asynchronous waiting cannot exist within the execution pipeline of a fragment shader.
  • YieldExpression: Generators and coroutines require call-stack persistence that hardware shader units cannot maintain.

Advanced Control Flow and Exception Handling

GLSL enforces deterministic execution paths and provides no mechanism for software-based stack unwinding or exception handling. The following control flow AST nodes are rejected:

  • TryStatement, CatchClause, and ThrowStatement: Hardware shader languages lack an exception model; runtime errors terminate the pipeline or produce undefined hardware states rather than catching exceptions.
  • SwitchStatement and SwitchCase: While modern GLSL (such as WebGL 2.0) supports switch-case structures, GPU.js restricts or rejects dynamic SwitchStatement nodes to maintain portability and deterministic branching across older WebGL 1.0 fallbacks.

Iteration and Collection Traversal Nodes

Iteration on the GPU requires deterministic, statically analyzable loop bounds. GPU.js rejects dynamic collection traversal nodes:

  • ForInStatement: Prototype key enumeration requires reflection, which does not exist in compiled GPU shader environments.
  • ForOfStatement: Relies on the JavaScript iterable protocol and dynamic iterator objects, making it incompatible with GLSL for loops.
  • DoWhileStatement: GPU.js predominantly restricts non-deterministic looping structures, favoring standard ForStatement and strictly bounded WhileStatement constructs to avoid infinite loops that could lock the GPU driver.

Modern Syntax and Dynamic Literals

Several modern JavaScript syntax features that abstract over memory structures or dynamic types are disallowed:

  • SpreadElement and RestElement: Dynamic unpacking and variable-length arguments violate GLSL's strict typing and static stack size requirements.
  • ArrayPattern and ObjectPattern: Destructuring assignments rely on object/array introspection and temporary object allocation.
  • TemplateLiteral and TaggedTemplateExpression: String operations and runtime string interpolation are non-existent in GLSL, leading to the immediate rejection of string-template AST nodes.
  • RegExpLiteral: Regular expressions require dedicated evaluation engines that cannot be converted to parallelized numeric vector pipelines.
  • DebuggerStatement: Hardware debugging requires vendor-specific tooling; standard JavaScript debug traps cannot be embedded in compiled shader binaries.
