Accessing Properties on Null in GPU.js Kernels

When a kernel in GPU.js attempts to access properties on a null argument, the operation fails and triggers a host-side JavaScript runtime exception (typically a TypeError). Because GPU.js relies on CPU-side JavaScript to parse arguments and prepare GPU uniforms or textures before execution, passing null where an object or array is expected halts the process before any GPU shader code can run.

Why the Error Occurs

GPU.js works by transpiling JavaScript functions into WebGL shaders (GLSL). Unlike JavaScript, GLSL is a statically typed language that does not possess dynamic objects, references, or a null primitive.

When you invoke a compiled kernel with arguments, the GPU.js runtime performs two critical tasks on the CPU before launching the GPU pipeline:

  1. Type and Dimension Inspection: GPU.js inspects arguments to determine how to upload them to the GPU. For arrays and objects, it checks properties such as .length or individual fields to construct textures or uniforms.
  2. Uniform Binding: The CPU assigns the input values to the appropriate WebGL uniform locations.

If an argument is passed as null and your kernel code attempts property access (such as arg.x or arg[0]), the CPU-side preparation logic immediately fails when attempting to read the underlying data structure, resulting in:

TypeError: Cannot read properties of null (reading '...')

Behavior in GPU Mode vs. CPU Fallback Mode

The failure manifests slightly differently depending on the execution mode, but both result in an immediate crash:

  • WebGL / WebGL2 Mode: The error is raised on the CPU during the argument serialization and validation phase. The GPU never receives the execution command, preventing invalid memory reads or shader crashes at the hardware level.
  • CPU Fallback Mode: If GPU.js falls back to JavaScript execution (for debugging or on unsupported hardware), standard JavaScript rules apply. The kernel function executes as a regular loop on the CPU, directly hitting the property access on null and throwing an identical TypeError.

Transpilation Restrictions

GLSL cannot handle dynamic null-checking. In standard JavaScript, you might write code like:

const val = myArg ? myArg.property : 0;

GPU.js cannot transpile this pattern into valid GLSL if myArg is an object. GLSL requires fixed uniform structures defined at compile time. Therefore, attempting to pass optional or nullable objects directly into a kernel is not supported by the underlying abstraction.

How to Prevent the Error

To avoid runtime exceptions when working with potentially null data:

  • Validate Arguments Host-Side: Ensure all arguments are non-null and fully populated prior to calling the kernel.
  • Deconstruct Objects: Pass individual primitive values (numbers, floats, or booleans) instead of complex objects containing nullable fields.
  • Use Sentinel Values: If an input must represent an empty state, pass a typed array filled with predefined sentinel values (such as -1 or 0) alongside an explicit flag parameter rather than passing null.
