Rendering CSG Operations in GPU.js

Constructive Solid Geometry (CSG) operations such as union, intersection, and difference can be rendered in gpu.js by utilizing raymarching combined with Signed Distance Functions (SDFs). Because gpu.js compiles JavaScript functions into WebGL shaders, it provides the parallel processing power required to compute pixel-by-pixel mathematical geometry on the GPU. While gpu.js is primarily designed for general-purpose parallel computing, its graphical output mode allows developers to render complex CSG scenes directly to a canvas.

The Mechanism: SDFs and Raymarching

Traditional mesh-based CSG requires complex polygon clipping algorithms, which are difficult to implement efficiently on a parallel GPU pipeline. In a shader-based environment like gpu.js, CSG is implemented using Signed Distance Functions (SDFs) and sphere tracing (raymarching).

An SDF is a mathematical function that takes a point in 3D space and returns the shortest distance from that point to the surface of a shape. Positive values represent points outside the shape, negative values represent points inside, and zero represents the exact surface.

Mathematical CSG Operations

In an SDF-based raymarcher, Boolean CSG operations between two shapes (\(A\) and \(B\)) reduce to simple mathematical comparisons:

  • Union (\(A \cup B\)): The combined volume of both shapes.
    Formula: Math.min(distanceA, distanceB)
  • Intersection (\(A \cap B\)): The overlapping volume shared by both shapes.
    Formula: Math.max(distanceA, distanceB)
  • Difference (\(A - B\)): Shape \(A\) with the overlapping volume of shape \(B\) subtracted.
    Formula: Math.max(distanceA, -distanceB)

Implementing in gpu.js

To render these operations using gpu.js, you configure a kernel with the graphical: true setting. The basic workflow involves:

  1. Camera and Ray Setup: For each pixel processed by the kernel, calculate a ray starting at the camera origin and pointing through the screen space coordinate (this.thread.x, this.thread.y).
  2. The Marching Loop: Step along the ray in discrete increments. At each step, evaluate the scene's global SDF. The step size is equal to the distance returned by the SDF.
  3. Evaluating CSG: The scene's SDF combines primitive shapes (such as spheres, cubes, or cylinders) using the Math.min and Math.max rules defined above.
  4. Surface Detection and Shading: If the distance returned by the SDF is smaller than a tiny threshold (e.g., 0.001), a surface hit is registered. You can then calculate surface normals using finite differences to apply lighting, and call this.color(r, g, b, a) to render the pixel.

Limitations and Considerations

While entirely possible, rendering CSG via gpu.js has specific constraints:

  • Branching and Loops: gpu.js translates JavaScript loops into GLSL. Raymarching requires fixed-bound loops, as dynamic while-loops can cause compilation issues or performance bottlenecks in WebGL.
  • Primitive Geometry: SDF-based CSG works best with mathematically defined shapes. Rendering arbitrary 3D triangle meshes using this method requires generating distance fields beforehand, which introduces significant memory overhead.
  • Abstraction Overhead: gpu.js introduces a layer of abstraction over raw GLSL. For purely visual raymarching and advanced CSG rendering, writing native GLSL inside a standard WebGL or Three.js pipeline is often more flexible and easier to debug. However, if your project already relies on gpu.js for compute tasks, rendering CSG directly within the same pipeline is fully achievable.
