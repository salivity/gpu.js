How GPU.js Handles Terser and UglifyJS Minification

GPU.js converts JavaScript functions into WebGL shaders at runtime by stringifying and parsing their source code, a process that code minifiers like Terser and UglifyJS can inadvertently disrupt. While GPU.js uses an internal Abstract Syntax Tree (AST) parser to reconstruct the logic of minified kernels, aggressive optimizations—such as variable mangling, syntax simplification, and dead code elimination—can still trigger transpilation errors. This article explains the technical mechanics behind GPU.js kernel compilation, how minification affects the process, and how to configure your build pipeline to avoid runtime failures.

The Transpilation Mechanism of GPU.js

GPU.js works by compiling high-level JavaScript functions into low-level OpenGL Shading Language (GLSL) shaders to execute them on the graphics card. Unlike traditional JavaScript libraries that execute functions directly via the JavaScript engine, GPU.js takes the kernel function passed to gpu.createKernel() and calls .toString() on it at runtime.

Once the function is converted to a string, GPU.js uses an internal parser (built on Acorn) to analyze its AST. The library maps standard JavaScript loops, assignments, math operations, and conditionals directly to GLSL equivalents. Because the compilation happens dynamically inside the browser, GPU.js requires the function's structural syntax to remain predictable.

How Minification Conflicts with Kernel Compilation

Tools like Terser, UglifyJS, and ESBuild optimize bundle sizes by transforming code into the shortest possible valid JavaScript. While valid for standard JavaScript runtimes, these transformations often break the assumptions GPU.js makes when converting code to GLSL:

  1. Syntax Modernization and Simplification: Minifiers often convert standard if/else branches into ternary expressions or rewrite traditional for loops into unconventional patterns. GPU.js relies on standard for loop structures to map iterations to WebGL texture coordinates; heavily rewritten loops can fail AST conversion.
  2. Variable Mangling: Minifiers rename variables to single letters to save space. While GPU.js can generally map renamed local variables, issues arise when minifiers alter function argument names or eliminate names required for internal variable tracking within the shader context.
  3. Inlining and Expression Simplification: Aggressive dead code removal and constant folding can evaluate calculations at build time that GPU.js might expect to parse as dynamic GPU expressions, potentially causing syntax mismatch during GLSL generation.

How GPU.js Accommodates Minified Code

To prevent outright failures, GPU.js includes an AST parser capable of handling compressed code formats. It normalizes whitespace, parses single-line blocks, and handles shorthand variable assignments produced by standard minifier passes.

However, GPU.js cannot reverse-engineer structural modifications, such as transformed loop logic or hoisted logic that moves outside the kernel boundary. It handles superficial minification (such as whitespace removal and standard variable shortening) automatically, but relies on developer configuration when build tools alter the underlying execution flow.

Strategies for Reliable Build Configurations

To prevent Terser or UglifyJS from corrupting GPU.js kernels, implement the following best practices in your build pipeline:

1. Pass Kernels as Strings

GPU.js allows you to pass kernel functions as raw strings rather than native JavaScript functions. When code is represented as a string literal, minifiers will not compress or alter the contents:

const kernelFunction = `function(a, b) {
  return a[this.thread.x] + b[this.thread.x];
}`;

const kernel = gpu.createKernel(kernelFunction).setOutput([100]);

2. Configure Minifier Settings

If defining kernels as standard functions, configure your minifier to avoid destructive transformations on files containing GPU.js logic:

  • Disable Mangling for Kernels: Add kernel function names to the reserved list in Terser or UglifyJS configuration options.
  • Keep Class and Function Names: Set keep_fnames: true and keep_classnames: true to prevent renaming of GPU.js internals.
  • Turn Off Dangerous Compressions: In Terser, disable transformations such as sequences, conditionals, or loops if you encounter runtime syntax errors from GPU.js.

3. Isolate Kernels in Unminified Modules

Place complex GPU kernels in separate files or external assets that bypass the minification step of your bundler (such as Webpack, Rollup, or Vite) entirely, importing them as raw strings using standard loaders.
