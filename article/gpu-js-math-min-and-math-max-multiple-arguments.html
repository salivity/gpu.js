gpu.js Math.min and Math.max Multiple Arguments

In gpu.js, running mathematical operations on the GPU requires transpiling JavaScript code into OpenGL Shading Language (GLSL). While standard JavaScript allows Math.min and Math.max to accept an arbitrary number of arguments, native GLSL only permits two arguments per function call. To bridge this gap, gpu.js transpiles multi-argument calls into nested, two-argument GLSL functions, though this behavior comes with strict limitations regarding dynamic arrays, argument counts, and type consistency.

The Transpilation Mechanism

When writing kernels in gpu.js, JavaScript Abstract Syntax Trees (ASTs) are parsed and converted to GLSL shaders. Native GLSL defines min() and max() strictly as binary operations:

genType min(genType x, genType y);
genType max(genType x, genType y);

When a kernel function contains a call such as Math.min(a, b, c, d), the gpu.js transpiler detects the excess arguments and flattens them into nested binary calls. The expression is rewritten in GLSL as:

min(a, min(b, min(c, d)))

Similarly, Math.max(w, x, y, z) is converted into:

max(w, max(x, max(y, z)))

This tree-like nesting ensures that GPU hardware can process multiple values using its high-throughput, paired register comparisons without requiring a custom loop.

Limitations and Edge Cases

While static, comma-separated lists of arguments work seamlessly, certain JavaScript patterns fail during transpilation:

1. The Spread Operator and Dynamic Arrays

In standard JavaScript, finding the minimum value in an array is commonly written as Math.min(...array). In gpu.js, this syntax is invalid inside kernels:

  • No Dynamic Unrolling: The transpiler cannot dynamically expand arrays at compile time unless the array length and structure are completely fixed and known to the compiler.
  • Lack of Spread Support: Spread syntax (...) is generally unsupported in kernel parsing because GLSL requires fixed-size stack allocations.

To find the minimum or maximum across an array within a kernel, you must manually iterate through the array using a fixed-length for loop, updating an accumulator variable with a two-argument Math.min or Math.max call on each iteration.

2. Zero or Single Arguments

  • Math.min() / Math.max() with no arguments: In JavaScript, these return Infinity and -Infinity respectively. In gpu.js, transpiling a call with zero arguments triggers a compilation error, as GLSL cannot generate a valid min() or max() call without parameters.
  • Single argument (Math.min(x)): Standard JavaScript returns x. In gpu.js, passing a single argument often results in a GLSL syntax error because the transpiler directly maps to the binary GLSL signature without inserting identity fallbacks.

3. Type Uniformity

GLSL enforces strict static typing. In JavaScript, Math.min(1, 2.5) automatically coerces values to numbers. In gpu.js, mixing integers and floating-point literals across multiple arguments (for example, Math.max(1, 2.0, 3)) will cause the shader compilation to fail due to a type mismatch. All arguments passed to multi-argument calls must share identical data types, typically standard floats.
