Nelson-Siegel-Svensson Modeling with gpu.js

Interest rate yield curves can be effectively modeled and evaluated using the Nelson-Siegel-Svensson (NSS) model within gpu.js. By translating the mathematical formulation of NSS into WebGL-accelerated JavaScript functions, developers and financial engineers can compute yields across extensive sets of maturities concurrently. This article details the mathematical structure of the NSS model, demonstrates how gpu.js handles curve evaluation and parameter optimization, and highlights performance benefits along with technical constraints.

The Nelson-Siegel-Svensson Formulation

The Nelson-Siegel-Svensson model extends the standard Nelson-Siegel approach by adding a second curvature component, providing greater flexibility for complex term structures. The zero-coupon yield \(y(t)\) for maturity \(t\) is defined as:

\[y(t) = \beta_0 + \beta_1 \left( \frac{1 - e^{-t/\tau_1}}{t/\tau_1} \right) + \beta_2 \left( \frac{1 - e^{-t/\tau_1}}{t/\tau_1} - e^{-t/\tau_1} \right) + \beta_3 \left( \frac{1 - e^{-t/\tau_2}}{t/\tau_2} - e^{-t/\tau_2} \right)\]

The model relies on six parameters:

  • \(\beta_0\): Long-term level.
  • \(\beta_1\): Short-term component (slope).
  • \(\beta_2\): Medium-term component (first hump/curvature).
  • \(\beta_3\): Second hump/curvature.
  • \(\tau_1, \tau_2\): Decay parameters governing the positions of the humps.

Why Use gpu.js for Yield Curve Modeling?

gpu.js compiles a restricted subset of JavaScript into WebGL shader language (GLSL), dispatching calculations to the device GPU. Yield curve modeling benefits from gpu.js in two distinct scenarios:

  1. Massive Curve Generation: Calculating yields for thousands of maturities across multiple historical dates or Monte Carlo paths can be executed simultaneously rather than through iterative CPU loops.
  2. Parallel Optimization via Grid Search: Calibrating NSS parameters to observed market bond prices requires non-linear optimization. Because the objective function often contains local minima, running parallelized evaluations across candidate pairs of \((\tau_1, \tau_2)\) allows for rapid identification of global optimal parameters.

Implementation Architecture in gpu.js

Executing the NSS formula requires instantiating a kernel that receives arrays of maturities and parameter sets.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel to calculate yields across an array of maturities
const calculateNSSYields = gpu.createKernel(function(maturities, b0, b1, b2, b3, tau1, tau2) {
    const t = maturities[this.thread.x];
    
    // Prevent division by zero
    if (t <= 0.0) {
        return b0 + b1;
    }
    
    const exp1 = Math.exp(-t / tau1);
    const exp2 = Math.exp(-t / tau2);
    
    const term1 = (1.0 - exp1) / (t / tau1);
    const term2 = term1 - exp1;
    const term3 = ((1.0 - exp2) / (t / tau2)) - exp2;
    
    return b0 + (b1 * term1) + (b2 * term2) + (b3 * term3);
}).setOutput([1000]); // Number of maturities evaluated

For calibration, a 2D or 3D kernel can compute the sum of squared errors between market yields and theoretical NSS yields across a dense grid of \((\tau_1, \tau_2)\) values simultaneously:

const calculateGridErrors = gpu.createKernel(function(marketYields, maturities, b0, b1, b2, b3, tauStep) {
    const tau1 = (this.thread.x + 1) * tauStep;
    const tau2 = (this.thread.y + 1) * tauStep;
    let sumSquaredError = 0.0;
    
    for (let i = 0; i < 100; i++) {
        const t = maturities[i];
        const exp1 = Math.exp(-t / tau1);
        const exp2 = Math.exp(-t / tau2);
        const term1 = (1.0 - exp1) / (t / tau1);
        const term2 = term1 - exp1;
        const term3 = ((1.0 - exp2) / (t / tau2)) - exp2;
        
        const modelYield = b0 + (b1 * term1) + (b2 * term2) + (b3 * term3);
        const diff = modelYield - marketYields[i];
        sumSquaredError += diff * diff;
    }
    
    return sumSquaredError;
}).setOutput([256, 256]); // Evaluates 65,536 tau combinations in parallel

Technical Considerations and Limitations

  • Precision: Standard WebGL contexts in gpu.js often default to 32-bit single-precision floating-point arithmetic. High-precision financial calculations requiring 64-bit float representations may exhibit minor rounding discrepancies compared to pure CPU implementations.
  • Data Transfer Overhead: Passing data between the CPU memory space and the GPU incurs latency. gpu.js provides peak efficiency when running batched calculations or large computational grids rather than isolated single-maturity queries.
  • Algorithmic Restrictions: Complex iterative optimizers with variable step branching (such as Levenberg-Marquardt) are non-trivial to implement directly in a single GPU kernel. A hybrid approach—using the GPU for brute-force surface search or objective evaluation, and the CPU for final gradient-based convergence—yields the best balance of speed and precision.
