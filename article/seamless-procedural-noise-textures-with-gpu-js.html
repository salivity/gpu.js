Seamless Procedural Noise Textures with GPU.js

GPU.js is fully capable of generating seamless procedural textures, including Perlin and Simplex noise. By compiling standard JavaScript functions into WebGL fragment shaders, GPU.js runs noise algorithms concurrently across thousands of GPU threads. Achieving seamless, tileable textures simply requires tailoring the noise mathematics to wrap periodically at the texture boundaries, which can be accomplished through modular arithmetic or higher-dimensional sampling.

How GPU.js Executes Noise Algorithms

GPU.js translates a subset of JavaScript into GLSL (OpenGL Shading Language). When generating a texture, each thread corresponds to a specific output pixel identified by this.thread.x and this.thread.y. Because procedural noise generation relies entirely on independent mathematical operations per pixel—such as hashing, coordinate scaling, dot products, and interpolation—the task is inherently parallel and well-suited for execution on the GPU.

Both classic Perlin noise and Simplex noise can be implemented directly within a GPU.js kernel. You define helper functions to compute gradient vectors and perform interpolation (such as the standard smoothstep or quintic curve), which GPU.js automatically inlines into the resulting shader program.

Techniques for Making Textures Seamless

Standard Perlin or Simplex noise algorithms produce infinite, non-repeating fields. To make them tile seamlessly across a defined resolution (e.g., \(512 \times 512\)), you must force the coordinates to wrap at the boundaries. There are two primary ways to do this in GPU.js:

  1. Periodic Coordinate Wrapping (Modular Arithmetic):
    Classic Perlin noise depends on an integer lattice. By applying a modulo operator to the integer grid coordinates before hashing, you force the noise values at the right and top edges to match the left and bottom edges. The period of the modulo operation must match the frequency of the noise across the canvas dimension.

  2. Higher-Dimensional Sampling (Torus Mapping):
    Simplex noise uses a simplex grid rather than a hypercube lattice, making standard coordinate modulo wrapping complex. Instead, a seamless 2D texture can be produced by sampling 4D Simplex noise. You map the 2D planar coordinates \((x, y)\) onto two separate circles in 4D space: \[X = r_1 \cos(\theta), \quad Y = r_1 \sin(\theta), \quad Z = r_2 \cos(\phi), \quad W = r_2 \sin(\phi)\] Because angles \(\theta\) and \(\phi\) complete full \(2\pi\) rotations over the width and height of the image, the resulting 2D output tiles infinitely without visual seams or distortion.

Implementation Structure in GPU.js

A typical setup initializes a kernel configured for graphical output:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const generateSeamlessNoise = gpu.createKernel(function(scale, width, height) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Normalize coordinates to [0, 1]
    const u = x / width;
    const v = y / height;

    // Example: Torus mapping for 4D Simplex noise
    const PI2 = 6.28318530718;
    const nx = Math.cos(u * PI2) * scale;
    const ny = Math.sin(u * PI2) * scale;
    const nz = Math.cos(v * PI2) * scale;
    const nw = Math.sin(v * PI2) * scale;

    // Evaluate 4D noise function (custom implementation inlined)
    const val = simplex4D(nx, ny, nz, nw);

    // Map noise [-1, 1] to RGB [0, 1]
    const color = (val + 1.0) * 0.5;
    this.color(color, color, color, 1.0);
})
.setOutput([512, 512])
.setGraphical(true);

generateSeamlessNoise(1.5, 512, 512);

Performance and Considerations

  • Float Precision: WebGL shaders handle 32-bit floating-point numbers. Ensure your noise functions do not introduce coordinate offsets that exceed the precision limits of standard GLSL floats, which can cause banding artifacts.
  • Lookup Tables vs. Analytical Hashes: CPU implementations often use pre-computed 256-element permutation tables. In GPU.js, accessing large external arrays within a kernel introduces memory overhead. Using pure analytical pseudo-random hash functions within the shader yields significantly higher frame rates.
  • Direct Canvas Output: By setting graphical: true, the output renders directly to an HTML5 canvas via WebGL, avoiding the costly overhead of copying pixel arrays back to the CPU.
