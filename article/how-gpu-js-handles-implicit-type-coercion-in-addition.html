How gpu.js Handles Implicit Type Coercion in Addition

When executing JavaScript code on the GPU, gpu.js transpiles standard JavaScript functions into WebGL Shading Language (GLSL). Because JavaScript is dynamically typed and performs implicit type coercion automatically, while GLSL is strictly and statically typed, gpu.js must actively parse and normalize addition operations. It achieves this by analyzing the JavaScript Abstract Syntax Tree (AST), tracking variable types, promoting integer types to floating-point types, and appending explicit GLSL type casts to ensure error-free compilation on the GPU.

Abstract Syntax Tree (AST) Parsing

Before code reaches the GPU, gpu.js parses the JavaScript function using an AST parser. When it encounters a binary expression with the addition operator (+), it checks the data types of both the left-hand and right-hand operands.

In standard JavaScript, expressions like 2 + 3.5 automatically evaluate to 5.5. In GLSL, however, an operation between an int and a float results in a compilation failure. The AST parser detects whether the operands share the same type or require alignment.

Literal Promotion

When numeric literals are used in an addition expression alongside floating-point variables, gpu.js evaluates the context of the operation:

  • If a float is added to an integer literal (for example, x + 1 where x is a float), gpu.js automatically appends a decimal point during code generation, converting the literal into 1.0.
  • This ensures that the generated shader code uses matching literal formats required by GLSL syntax.

Explicit Cast Injection

When two variables of differing numeric types are added together—such as a runtime integer and a runtime float—gpu.js injects GLSL constructor calls:

  1. Detection: The transpiler identifies that the left operand is of type Integer and the right operand is of type Float (or vice versa).
  2. Promotion: In numeric addition, gpu.js follows standard numeric hierarchy and promotes the narrower type to the wider type (promoting int to float).
  3. Code Emission: It wraps the integer operand in GLSL's float() cast function. For example, the JavaScript expression intVal + floatVal is compiled into the GLSL equivalent: float(intVal) + floatVal.

Default Float Usage

To minimize type mismatch issues inherent in WebGL shaders, gpu.js defaults most internal number representations to 32-bit floating-point values (highp float). Unless a variable or argument is explicitly declared as an integer, numeric values and arithmetic calculations inside kernels are treated as floats from the start. By standardizing generic numbers to floats prior to transpilation, gpu.js eliminates many potential coercion conflicts before the code is compiled into the final shader program.
