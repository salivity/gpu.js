Parallel FIR Filtering on Streaming Audio with GPU.js

Implementing parallel Finite Impulse Response (FIR) filtering on streaming audio using GPU.js allows web applications to offload intensive discrete convolution operations from the CPU to the GPU. This article explains the mathematics behind parallel FIR execution, details the handling of streaming audio buffers with overlapping state history, and provides a complete, working implementation using GPU.js to process real-time audio blocks.

The Mathematics of Parallel FIR Filtering

A Finite Impulse Response (FIR) filter calculates each output sample \(y[n]\) as a weighted sum of the current input sample and \(N\) previous input samples:

\[y[n] = \sum_{k=0}^{N-1} b_k \cdot x[n - k]\]

Where:

  • \(b_k\) represents the filter coefficients (impulse response) of length \(N\).
  • \(x[n]\) represents the input audio signal.
  • \(y[n]\) represents the filtered output.

Because each output sample \(y[n]\) depends only on the input vector \(x\) and the static coefficients \(b\), each sample in an audio block can be calculated independently. This makes the FIR filter an embarrassingly parallel operation suited for GPU execution.

Managing Streaming Audio Buffers

Audio streams are delivered in discrete frames or chunks (typically 512, 1024, or 2048 samples). When calculating the first few samples of a new chunk, the filter requires samples from the end of the preceding chunk to populate the delay line.

To avoid boundary artifacts:

  1. Maintain a history buffer containing the last \(N - 1\) samples from the previous block.
  2. Concatenate the history buffer with the incoming audio chunk before sending the data to the GPU.
  3. Compute the output chunk of size equal to the incoming audio chunk.
  4. Update the history buffer with the trailing samples of the current chunk for the next cycle.

GPU.js Kernel Implementation

GPU.js compiles JavaScript functions into WebGL compute shaders. In the kernel, the output dimension matches the incoming audio chunk size, and each thread computes the dot product for a single output sample.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Configuration parameters
const CHUNK_SIZE = 2048;
const TAPS = 64; // Number of filter coefficients (N)

// Define FIR filter coefficients (e.g., low-pass, high-pass)
const coefficients = new Float32Array(TAPS);
// Populate coefficients according to your filter design (e.g., windowed-sinc)

// Create the GPU kernel
const firKernel = gpu.createKernel(function(extendedAudio, coefficients, taps) {
    let sum = 0.0;
    const n = this.thread.x;
    
    // Perform convolution for sample n
    for (let k = 0; k < taps; k++) {
        // extendedAudio includes the previous (taps - 1) samples at the beginning
        sum += coefficients[k] * extendedAudio[(n + taps - 1) - k];
    }
    
    return sum;
})
.setOutput([CHUNK_SIZE])
.setDynamicOutput(false)
.setPrecision('single');

Complete Streaming Pipeline

Below is a complete class encapsulating the streaming pipeline. It accepts raw PCM audio chunks, manages the history buffer, executes the GPU kernel, and returns the filtered output.

class GPUAudioFIRFilter {
    constructor(coefficients, chunkSize) {
        this.gpu = new GPU();
        this.coefficients = coefficients;
        this.taps = coefficients.length;
        this.chunkSize = chunkSize;

        // Maintain previous audio tail
        this.history = new Float32Array(this.taps - 1);

        // Pre-allocate extended buffer to prevent garbage collection pauses
        this.extendedBuffer = new Float32Array(this.chunkSize + this.taps - 1);

        // Initialize kernel
        const tapsCount = this.taps;
        this.kernel = this.gpu.createKernel(function(extendedAudio, filterCoeffs) {
            let acc = 0.0;
            const idx = this.thread.x;

            for (let i = 0; i < tapsCount; i++) {
                acc += filterCoeffs[i] * extendedAudio[(idx + tapsCount - 1) - i];
            }

            return acc;
        })
        .setOutput([this.chunkSize])
        .setPrecision('single');
    }

    processChunk(inputChunk) {
        if (inputChunk.length !== this.chunkSize) {
            throw new Error(`Chunk size mismatch. Expected ${this.chunkSize}, received ${inputChunk.length}`);
        }

        // 1. Fill extended buffer: [history] + [current chunk]
        this.extendedBuffer.set(this.history, 0);
        this.extendedBuffer.set(inputChunk, this.history.length);

        // 2. Execute GPU computation
        const output = this.kernel(this.extendedBuffer, this.coefficients);

        // 3. Update history with the tail of the current input chunk
        this.history.set(inputChunk.subarray(this.chunkSize - (this.taps - 1)));

        // Returns Float32Array of length equal to chunkSize
        return output;
    }

    destroy() {
        this.kernel.destroy();
    }
}

Integration with Web Audio API

To hook this pipeline into real-time audio:

const audioContext = new AudioContext();
const sampleRate = audioContext.sampleRate;
const chunkSize = 2048;

// Example: 128-tap Low-pass filter coefficients
const taps = 128;
const filterCoeffs = new Float32Array(taps).fill(1 / taps); // Simple moving average for demonstration

const firFilter = new GPUAudioFIRFilter(filterCoeffs, chunkSize);

// In a real-time environment, stream buffers via an AudioWorklet or ScriptProcessor
function onAudioProcess(incomingPCMData) {
    const filteredPCM = firFilter.processChunk(incomingPCMData);
    return filteredPCM;
}

Performance and Optimization

  1. Memory Allocation: Avoid allocating new typed arrays inside the process loop. Pre-allocate the history and extended buffers to prevent memory churn and garbage collection latency.
  2. Chunk Size vs. Overhead: GPU data transfers incur an overhead. Filtering small blocks (e.g., 128 samples) on the GPU is typically slower than CPU execution. GPU acceleration yields significant performance advantages with larger filter lengths (\(N \ge 64\)) and chunk sizes of 1024 to 4096 samples.
  3. Loop Unrolling: For static filters where the tap count is constant, unrolling the inner convolution loop or hardcoding this.taps directly in the kernel function allows GPU.js and the underlying shader compiler to generate optimized machine instructions.
