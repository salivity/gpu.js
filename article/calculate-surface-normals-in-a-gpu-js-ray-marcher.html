Calculate Surface Normals in a GPU.js Ray Marcher

This guide explains how to compute accurate surface normals for Signed Distance Field (SDF) geometries inside a GPU.js ray marcher using finite difference gradients. In ray marching, rendering realistic lighting, reflections, and shadows requires knowing the orientation of the surface at the point of ray intersection. Because SDFs are defined mathematically rather than by explicit polygonal meshes, you must approximate the normal vector by sampling the distance gradient around the hit point using small step offsets.

The Concept of the Gradient in SDFs

A Signed Distance Function returns the shortest distance from any 3D coordinate \(\mathbf{p} = (x, y, z)\) to the nearest surface. The surface itself is defined by the isosurface where \(\text{SDF}(\mathbf{p}) = 0\).

The surface normal at any point on an isosurface corresponds to the normalized spatial gradient vector \(\nabla f(\mathbf{p})\):

\[\nabla f(\mathbf{p}) = \left( \frac{\partial f}{\partial x}, \frac{\partial f}{\partial y}, \frac{\partial f}{\partial z} \right)\]

Because an analytical derivative can be complex or impossible to derive for combined or distorted SDFs, numerical differentiation via finite differences is used.

The Central Difference Method

The central difference method provides a second-order accurate approximation of the partial derivatives. By evaluating the SDF slightly forward and backward along each axis by a tiny offset \(\epsilon\) (epsilon), the normal components are calculated as:

\[n_x = \text{SDF}(x + \epsilon, y, z) - \text{SDF}(x - \epsilon, y, z)\] \[n_y = \text{SDF}(x, y + \epsilon, z) - \text{SDF}(x, y - \epsilon, z)\] \[n_z = \text{SDF}(x, y, z + \epsilon) - \text{SDF}(x, y, z - \epsilon)\]

Once the gradient components are calculated, the resulting vector must be normalized to ensure it has a unit length of 1.

Implementation in GPU.js

GPU.js compiles JavaScript functions into WebGL shaders. Because of this, custom functions passed to the kernel must use simple control flow and standard numeric operations.

First, define the scene SDF and register it with gpu.addFunction:

// Example SDF: Sphere of radius r at the origin
function sceneSDF(x, y, z) {
  const radius = 1.0;
  const distance = Math.sqrt(x * x + y * y + z * z) - radius;
  return distance;
}
gpu.addFunction(sceneSDF);

Next, define the finite difference normal calculation. Because GPU.js functions cannot easily instantiate dynamic objects, return values are typically handled via single components or array buffers. Alternatively, perform the calculation directly within the kernel or via a helper function:

function estimateNormalX(x, y, z, eps) {
  return sceneSDF(x + eps, y, z) - sceneSDF(x - eps, y, z);
}
function estimateNormalY(x, y, z, eps) {
  return sceneSDF(x, y + eps, z) - sceneSDF(x, y - eps, z);
}
function estimateNormalZ(x, y, z, eps) {
  return sceneSDF(x, y, z + eps) - sceneSDF(x, y, z - eps);
}

gpu.addFunction(estimateNormalX);
gpu.addFunction(estimateNormalY);
gpu.addFunction(estimateNormalZ);

Integrating with the Ray Marching Loop

Within the main ray marching kernel, when a ray hits a surface (i.e., distance falls below a defined hit threshold), compute the normal using the hit coordinate:

const renderKernel = gpu.createKernel(function(cameraX, cameraY, cameraZ) {
  // Ray generation and marching logic...
  // Assume (hitX, hitY, hitZ) is the point of intersection
  
  const EPSILON = 0.001;

  // Calculate unnormalized gradient components
  const nx = estimateNormalX(hitX, hitY, hitZ, EPSILON);
  const ny = estimateNormalY(hitX, hitY, hitZ, EPSILON);
  const nz = estimateNormalZ(hitX, hitY, hitZ, EPSILON);

  // Normalize the gradient to get the surface normal
  const len = Math.sqrt(nx * nx + ny * ny + nz * nz);
  const normalX = nx / len;
  const normalY = ny / len;
  const normalZ = nz / len;

  // Use the normal for Lambertian diffuse shading
  const lightDirX = 0.577;
  const lightDirY = 0.577;
  const lightDirZ = 0.577;

  const diffuse = Math.max(0.0, normalX * lightDirX + normalY * lightDirY + normalZ * lightDirZ);

  this.color(diffuse, diffuse, diffuse, 1.0);
}).setOutput([800, 600]).setGraphical(true);

Optimization Considerations

  • Choosing Epsilon: An \(\epsilon\) that is too large will smooth out sharp geometrical edges, whereas an \(\epsilon\) that is too small will encounter 32-bit floating-point precision artifacts. Values between 0.0005 and 0.002 are typically optimal for scenes normalized near the origin.
  • Tetrahedral Technique (Alternative): The central difference technique requires six evaluations of the sceneSDF. If performance becomes a bottleneck in complex scenes, you can reduce this to four evaluations by sampling along the vertices of a regular tetrahedron around the hit point.
