How to View Generated GLSL Code in GPU.js

This guide explains how to extract and inspect the human-readable GLSL (OpenGL Shading Language) shader code generated by GPU.js kernels. While GPU.js abstracts WebGL and GLSL compilation behind familiar JavaScript syntax, inspecting the generated shader code is essential for diagnosing compilation errors, debugging unexpected numerical results, and analyzing pipeline performance.

Using the getGLSL() Method

The primary and most reliable method to retrieve the compiled GLSL source code is the getGLSL() function available on any kernel instance.

Because GPU.js compiles kernels lazily based on the types and dimensions of the input arguments, you must pass the target execution arguments directly into getGLSL() just as you would when executing the kernel.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// 1. Define the kernel function
const kernel = gpu.createKernel(function(a, b) {
  return a[this.thread.x] + b[this.thread.x];
}).setOutput([5]);

// 2. Prepare mock or test data
const arrayA = [1, 2, 3, 4, 5];
const arrayB = [5, 4, 3, 2, 1];

// 3. Retrieve the compiled GLSL string
const glslSource = kernel.getGLSL(arrayA, arrayB);

// 4. Output the shader code to the console
console.log(glslSource);

Accessing GLSL After Kernel Execution

If the kernel has already executed at least once, GPU.js has already compiled the underlying WebGL program. In this state, you can also access the GLSL code directly from the internal kernel reference without passing the arguments again:

// Execute kernel
kernel(arrayA, arrayB);

// Inspect the underlying WebGL kernel instance
if (kernel.kernel) {
  console.log(kernel.kernel.getGLSL());
}

Enabling Debug Mode for Compilation Warnings

When troubleshooting shader compilation failures where getGLSL() does not render or throws a WebGL error, initialize the GPU instance with the debug flag enabled:

const gpu = new GPU({ mode: 'gpu', debug: true });

When debug: true is active, GPU.js logs compiler output, precision qualifiers, and detailed WebGL shader translation steps to the browser or Node.js console.

What to Look for in the GLSL Output

Inspecting the output of getGLSL() reveals several key elements:

  • Preamble and Precision: Settings such as precision highp float; define floating-point precision on the target hardware.
  • Input Uniforms and Textures: Arrays and matrices mapped to uniform sampler textures (sampler2D) used to transfer data into the GPU.
  • Thread Mapping: The transformation of this.thread.x, this.thread.y, or this.thread.z into WebGL texture coordinates (gl_FragCoord).
  • Kernel Body: Your original JavaScript logic translated into native C-like GLSL statements within the shader's main() function.
