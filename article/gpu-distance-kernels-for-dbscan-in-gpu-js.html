GPU Distance Kernels for DBSCAN in gpu.js

Computing DBSCAN spatial neighborhood queries using distance kernels in gpu.js is entirely feasible and significantly accelerates performance by offloading the \(O(N^2)\) pairwise distance calculations to the GPU. By compiling JavaScript functions into WebGL shaders, gpu.js allows developers to evaluate whether points lie within a specific neighborhood radius (\(\epsilon\)) in parallel. This article explains how to design gpu.js distance kernels for DBSCAN, how data flows between the GPU and CPU, and the practical considerations of this hybrid architecture.

The DBSCAN Bottleneck and GPU Parallelism

Density-Based Spatial Clustering of Applications with Noise (DBSCAN) requires identifying all points within a spatial radius \(\epsilon\) of every point \(p\) in a dataset. In high-dimensional spaces or arbitrary metric layouts where spatial index trees (such as k-d trees or R-trees) degrade toward linear scans, computing these \(\epsilon\)-neighborhoods demands evaluating an \(N \times N\) distance matrix.

Because each pairwise distance calculation is independent of every other calculation, calculating distances is an embarrassingly parallel task. The GPU excels at this exact computational pattern by dispatching thousands of lightweight shader threads concurrently.

Formulating the Neighborhood Query in gpu.js

In gpu.js, a kernel is written as a JavaScript function that the library compiles into a fragment shader. To execute spatial neighborhood queries, you define a 2D kernel with dimensions equal to the number of points (\(N \times N\)).

The kernel can be designed in two distinct ways:

  1. Full Distance Matrix Computation: The kernel calculates the Euclidean or Manhattan distance between point \(i\) and point \(j\) and outputs the raw scalar distance.
  2. Boolean Adjacency Matrix Computation: The kernel computes the distance between point \(i\) and point \(j\), directly compares it to \(\epsilon\), and returns a binary value (1 if within the radius, 0 otherwise).

Returning a boolean adjacency matrix or neighbor count is typically more efficient because it offloads the thresholding logic directly into the GPU pipeline.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel returning 1 if points are within epsilon, 0 otherwise
const neighborhoodKernel = gpu.createKernel(function(points, numDimensions, epsilon) {
    let sumSquares = 0;
    for (let d = 0; d < numDimensions; d++) {
        let diff = points[this.thread.y][d] - points[this.thread.x][d];
        sumSquares += diff * diff;
    }
    let distance = Math.sqrt(sumSquares);
    return distance <= epsilon ? 1 : 0;
}).setOutput([numPoints, numPoints]);

The Hybrid Execution Model

While neighborhood discovery benefits dramatically from GPU execution, the standard cluster expansion step of DBSCAN does not. Cluster expansion relies on breadth-first search (BFS) or depth-first search (DFS) with dynamic queues, tracking visited states, and branch-heavy logic—patterns that do not map efficiently to simple WebGL fragment shaders.

The recommended architectural approach is a hybrid pipeline:

  1. Neighborhood Phase (GPU): Pass the coordinate data to the gpu.js kernel. The GPU outputs an \(N \times N\) adjacency lookup or neighbor indices array.
  2. Cluster Expansion Phase (CPU): Read the GPU output back into CPU memory. Iterate through unvisited points, using the precomputed neighbor lists to quickly expand clusters and label core, border, and noise points.

Key Considerations and Limitations

  • Data Transfer Overhead: Copying data from CPU memory to the GPU and reading the output texture back into JavaScript introduces a performance penalty. For small datasets (e.g., fewer than 1,000 points), the overhead of compiling shaders and transferring memory often exceeds the time required for a pure CPU implementation.
  • Texture Dimension Limits: gpu.js maps kernel outputs to WebGL textures. WebGL implementations have maximum texture size limits (often 4096×4096, 8192×8192, or 16384×16384). If the dataset size \(N\) exceeds the maximum texture dimension, the distance matrix must be tiled across multiple kernel dispatches.
  • Precision Constraints: WebGL contexts can vary in their support for high-precision 32-bit floating-point arithmetic. If the dataset requires high numerical accuracy for very small \(\epsilon\) thresholds, ensure the execution environment reliably supports 32-bit floats.
