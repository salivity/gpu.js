Debugging gpu.js Kernel Outputting All Zeros

When running computations on the GPU using gpu.js, receiving an array entirely filled with zeros usually points to a silent execution failure, improper memory dimensions, or WebGL texture rendering issues. This guide outlines systematic debugging strategies to troubleshoot and fix zero-value outputs in gpu.js kernels, starting from basic runtime mode switching to WebGL float support and dimensional validation.

1. Fall Back to CPU Mode

The fastest way to isolate whether a bug is algorithmic or hardware-related is to force the kernel to execute on the CPU. By default, gpu.js compiles JavaScript functions into WebGL shaders, which fail silently on unsupported operations.

const kernel = gpu.createKernel(function(a) {
  return a[this.thread.x] * 2;
})
.setOutput([100])
.setMode('cpu'); // Force CPU mode

const result = kernel(myInput);

If the kernel produces correct values on the CPU but returns all zeros on the GPU, the issue is related to WebGL limitations, unsupported JavaScript constructs, or shader compilation failures.

2. Validate Thread Coordinates and Output Dimensions

If your defined output dimensions do not align with how you access thread coordinates, the kernel may execute over an unintended memory space or map output values outside the target buffer.

  • Thread indexing: In a 2D kernel, verify that you access this.thread.x and this.thread.y correctly relative to your array's row-major or column-major layout.
  • Output size: Ensure setOutput([width, height]) matches the dimensions of your expected output. If you specify [0] or an empty array, the output buffer will default to empty or zeroed allocations.

3. Check WebGL Float Texture Support

Zero-output bugs often occur when writing floating-point numbers on devices where WebGL floating-point textures are unsupported or disabled. When WebGL cannot write 32-bit floats, values may underflow or silently truncate to zero.

  • Explicitly define the kernel precision: 
    kernel.setPrecision('single'); // Use 32-bit floats
// or
kernel.setPrecision('unsigned'); // Constrain to 8-bit integers if decimals are not needed
  • Check if your environment supports floating-point readbacks. Older mobile browsers and specific headless environments (like standard Node.js without a properly configured headless-gl context) often lack OES_texture_float support, causing all float returns to be zeroed out.

4. Review Pipeline Settings and Texture Extraction

If you have enabled pipeline mode (kernel.setPipeline(true)), the kernel does not return a standard JavaScript array; instead, it outputs an internal WebGL texture to keep data on the GPU for subsequent kernels.

Attempting to read this texture directly via console.log or passing it directly to a non-gpu.js function will display empty metadata or zeroed buffers. To extract the raw data, use:

const texture = kernel(inputData);
const actualArray = texture.toArray(); // Converts WebGL texture back to a JS array

5. Remove Unsupported JavaScript Constructs

The gpu.js transpiler converts JavaScript into GLSL (OpenGL Shading Language). If your kernel includes non-transpilable code, the shader compilation may fail or generate a default empty return value:

  • No arbitrary objects or strings: Kernels only accept numbers, arrays of numbers, or image elements. Passing nested objects can lead to unhandled parameters interpreted as 0.0.
  • No dynamic array lengths: Loops inside the kernel must have predictable, constant bounds. Dynamic loop conditions often evaluate to false in GLSL, bypassing computation entirely.
  • No native JS methods: Avoid using methods like Array.prototype.map(), Math.random(), or console.log() inside the kernel function.

6. Verify Input Data Normalization

Shaders treat non-numeric inputs like NaN, null, or undefined as undefined behavior, which WebGL drivers frequently default to 0.0. Check that input matrices do not contain missing indices or uninitialized array slots prior to sending them to the GPU. Ensure all inputs contain valid floating-point or integer values.
