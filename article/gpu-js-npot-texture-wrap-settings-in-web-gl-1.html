GPU.js NPOT Texture Wrap Settings in WebGL 1

In WebGL 1, GPU.js configures texture wrap parameters strictly to gl.CLAMP_TO_EDGE for both horizontal and vertical axes whenever dealing with non-power-of-two (NPOT) textures. Because the base WebGL 1 specification prohibits repeat modes on NPOT dimensions without specific extensions, GPU.js enforces these clamping parameters along with disabling mipmapping to ensure shaders compile cleanly and data textures execute without runtime render failures.

WebGL 1 NPOT Limitations

The WebGL 1.0 specification imposes strict requirements on textures with dimensions that are not powers of two (\(2^n \times 2^m\)). According to the specification, an NPOT texture cannot:

  1. Use gl.REPEAT or gl.MIRRORED_REPEAT as wrapping modes.
  2. Use minification filters that require mipmaps (such as gl.NEAREST_MIPMAP_NEAREST or gl.LINEAR_MIPMAP_LINEAR).

If an application attempts to sample an NPOT texture under an unsupported wrap or filter configuration, WebGL treats the texture as incomplete and returns solid black (0, 0, 0, 1) pixels.

GPU.js Texture Configuration Implementation

When compiling kernels and generating input or output textures, GPU.js operates primarily as a General-Purpose Computing on GPU (GPGPU) engine. Because matrix sizes, arrays, and compute payloads rarely match power-of-two boundaries, GPU.js enforces strict compliance with the WebGL 1 state machine during texture initialization.

During texture setup on the underlying WebGLRenderingContext, GPU.js sets the wrap parameters using texParameteri:

gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE);
  • gl.TEXTURE_WRAP_S: Configured to gl.CLAMP_TO_EDGE, forcing coordinate sampling along the horizontal axis to stop at the border of the pixel matrix.
  • gl.TEXTURE_WRAP_T: Configured to gl.CLAMP_TO_EDGE, forcing coordinate sampling along the vertical axis to stop at the border.

Filter Configuration Requirement

Setting CLAMP_TO_EDGE is only half of the WebGL 1 NPOT requirement. GPU.js simultaneously configures the minification and magnification filters to avoid mipmap generation:

gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.NEAREST);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.NEAREST);

Using gl.NEAREST guarantees that calculations remain deterministic without blending adjacent data elements, while also satisfying the WebGL 1 rule that minification on an NPOT texture must be either gl.NEAREST or gl.LINEAR.

Impact on GPU Computations

In standard computer graphics, clamping stretches the edge pixels when coordinates exceed the \([0.0, 1.0]\) UV range. In GPU.js, texture coordinates are directly calculated from thread indices:

\[\text{coordinate} = \frac{\text{index} + 0.5}{\text{dimension}}\]

Because GPU.js maps output coordinates precisely to memory offsets on a 1:1 basis, sampling outside the valid range is fundamentally prevented by the generated shader logic. Forcing gl.CLAMP_TO_EDGE fulfills the WebGL 1 validation rules while preserving complete data integrity across all compute array dimensions.
