Parallel Rainbow Table Lookups with GPU.js

This article explains how to implement parallel rainbow table lookups for hash collision analysis using the GPU.js library. By leveraging WebGL-accelerated parallel computing within JavaScript, developers and security researchers can offload computationally intensive reduction chains and endpoint lookups to the GPU. You will learn the mechanics of rainbow tables, the design of GPU compute kernels, and practical code patterns for accelerating collision searches.

Understanding Rainbow Tables and Parallelism

A rainbow table is a precomputed data structure designed to invert cryptographic hash functions using a time-memory trade-off. Rather than storing every individual plaintext-hash pair, the table stores chains generated by alternating between a hash function (\(H\)) and a reduction function (\(R\)):

\[P_0 \xrightarrow{H} h_1 \xrightarrow{R_1} P_1 \xrightarrow{H} \dots \xrightarrow{R_k} P_k\]

Only the starting points (\(P_0\)) and endpoints (\(P_k\)) are stored on disk. When analyzing an unknown hash \(h\), the algorithm applies the reduction and hash sequence repeatedly, checking after each step whether the resulting intermediate value matches an endpoint in the table.

Because each step in a chain can be calculated independently across multiple candidate chains, this process is an ideal candidate for parallel processing on a Graphics Processing Unit (GPU).

Setting Up GPU.js for Cryptographic Compute

GPU.js compiles JavaScript functions into WebGL shader code, allowing matrix operations and array processing to execute across hundreds or thousands of GPU cores simultaneously.

To begin, install the library via npm:

npm install gpu.js

Initialize the GPU instance within your script:

const { GPU } = require('gpu.js');
const gpu = new GPU();

Designing the Lookup Kernel

When verifying if a target hash belongs to a chain, the reduction and hash cycle must be evaluated from multiple chain positions. The parallel approach maps each GPU thread to an independent chain offset or candidate start point.

Because GPU.js compiles to WebGL, standard 64-bit integer operations and native bitwise shifts often present constraints. Computations are typically structured around 32-bit unsigned integers or normalized vector arrays.

Below is a simplified example demonstrating parallel execution of an iterative modular reduction function over a batch of potential collision points:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel to execute chains in parallel
const executeChainsKernel = gpu.createKernel(function (targetHashes, chainLength, tableSize) {
    // Unique thread ID corresponding to the chain index
    const id = this.thread.x;
    let currentHash = targetHashes[id];

    // Traverse the chain backwards to locate endpoints
    for (let step = 0; step < chainLength; step++) {
        // Simplified reduction function: map hash back to an integer space
        let reduced = (currentHash + step) % tableSize;

        // Simplified toy hash simulation (e.g., linear congruential cycle)
        // In practice, implement standard primitives like MD5 or SHA round functions
        currentHash = (reduced * 1664525 + 1013904223) % 4294967296;
    }

    return currentHash;
}).setOutput([1024]); // Number of concurrent threads

Executing the Lookup Workflow

The host application coordinates data transfer between CPU memory and the GPU context using three distinct phases:

  1. Batch Generation: The CPU reads the target hash value to be analyzed and generates an array containing the hash repeated across all target chain lengths.
  2. Kernel Dispatch: The host dispatches the array to the executeChainsKernel. The GPU computes the subsequent chain values across all designated threads simultaneously.
  3. Endpoint Matching: The GPU returns the resulting potential endpoints to the JavaScript runtime. The CPU runs a binary search or hash-map lookup against the pre-indexed endpoints stored in the rainbow table.
const chainLength = 500;
const threadCount = 1024;
const tableSize = 1000000;

// Input vector representing target hashes to process
const targetHash = 3456789;
const inputVector = new Float32Array(threadCount).fill(targetHash);

// Execute lookup kernel on GPU
const potentialEndpoints = executeChainsKernel(inputVector, chainLength, tableSize);

// Match against precomputed database
function checkEndpoints(endpoints, precomputedTable) {
    for (let i = 0; i < endpoints.length; i++) {
        const ep = endpoints[i];
        if (precomputedTable.has(ep)) {
            console.log(`Collision candidate detected at chain index ${i}: Endpoint ${ep}`);
            return { index: i, endpoint: ep };
        }
    }
    return null;
}

Performance Considerations

  • Memory Transfer Overhead: Transferring arrays between host RAM and GPU VRAM via WebGL textures introduces latency. Batch your lookups into large buffers rather than invoking kernels on individual hashes.
  • Precision Constraints: WebGL 1.0 does not natively support true 32-bit integer bitwise operations. Ensure your environment supports WebGL 2.0 or compute shaders via headless GL to avoid floating-point inaccuracies in hash calculations.
  • Branch Divergence: Keep the execution path inside the kernel identical for all threads. Avoid conditional statements (if/else) inside loops to prevent GPU execution stalls.
