Implement SVM Kernel Functions Using GPU.js

This article explains how to leverage GPU.js to accelerate Support Vector Machine (SVM) kernel computations directly in JavaScript. You will learn the mechanics of calculating pairwise Gram matrices on the GPU, followed by ready-to-use implementations of the Linear, Polynomial, and Radial Basis Function (RBF) kernels.

Why Accelerate SVM Kernels with GPU.js?

Training an SVM or evaluating predictions with non-linear kernels requires computing an \(N \times N\) Gram matrix, where each element \((i, j)\) represents the kernel evaluation \(K(x_i, x_j)\) between two data points. For a dataset of size \(N\) with dimensionality \(D\), this requires \(O(N^2 \cdot D)\) operations.

Because each cell in the Gram matrix can be computed independently, this task is embarrassingly parallel. GPU.js compiles JavaScript functions into WebGL shaders (or OpenCL in Node.js), allowing thousands of threads to calculate matrix entries concurrently.

Setup and Data Format

GPU.js operates best with primitive data types such as flattened arrays or 2D matrices of numbers. Prepare your dataset as a 2D array where each row represents a feature vector.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Sample dataset: 4 samples with 3 features each
const data = [
  [1.0, 2.0, 1.5],
  [0.5, 1.5, 2.0],
  [3.0, 1.0, 0.5],
  [2.0, 2.5, 1.0]
];
const numSamples = data.length;
const numFeatures = data[0].length;

1. Linear Kernel

The Linear kernel is the standard dot product between two vectors:

\[K(x_i, x_j) = x_i \cdot x_j = \sum_{k=0}^{D-1} x_{ik} \cdot x_{jk}\]

GPU.js Implementation:

const linearKernel = gpu.createKernel(function(data, numFeatures) {
  let sum = 0.0;
  for (let k = 0; k < numFeatures; k++) {
    sum += data[this.thread.y][k] * data[this.thread.x][k];
  }
  return sum;
})
.setOutput([numSamples, numSamples]);

const linearGramMatrix = linearKernel(data, numFeatures);

In GPU.js, this.thread.x and this.thread.y represent the current column and row of the output matrix. Thread \((x, y)\) computes the dot product between data[y] and data[x].

2. Polynomial Kernel

The Polynomial kernel captures feature interactions up to degree \(d\):

\[K(x_i, x_j) = (x_i \cdot x_j + c)^d\]

GPU.js Implementation:

const polyKernel = gpu.createKernel(function(data, numFeatures, c, degree) {
  let sum = 0.0;
  for (let k = 0; k < numFeatures; k++) {
    sum += data[this.thread.y][k] * data[this.thread.x][k];
  }
  return Math.pow(sum + c, degree);
})
.setOutput([numSamples, numSamples]);

const degree = 3;
const c = 1.0;
const polyGramMatrix = polyKernel(data, numFeatures, c, degree);

3. Radial Basis Function (RBF) Kernel

The RBF (Gaussian) kernel measures similarity based on Euclidean distance:

\[K(x_i, x_j) = \exp(-\gamma \|x_i - x_j\|^2)\]

GPU.js Implementation:

const rbfKernel = gpu.createKernel(function(data, numFeatures, gamma) {
  let squaredDistance = 0.0;
  for (let k = 0; k < numFeatures; k++) {
    let diff = data[this.thread.y][k] - data[this.thread.x][k];
    squaredDistance += diff * diff;
  }
  return Math.exp(-gamma * squaredDistance);
})
.setOutput([numSamples, numSamples]);

const gamma = 0.5;
const rbfGramMatrix = rbfKernel(data, numFeatures, gamma);

Computing Cross-Matrices (Train vs. Test)

When classifying new test samples, you must evaluate the kernel between \(M\) test samples and \(N\) training samples, yielding an \(M \times N\) matrix.

const rbfPredictKernel = gpu.createKernel(function(trainData, testData, numFeatures, gamma) {
  let squaredDistance = 0.0;
  for (let k = 0; k < numFeatures; k++) {
    let diff = testData[this.thread.y][k] - trainData[this.thread.x][k];
    squaredDistance += diff * diff;
  }
  return Math.exp(-gamma * squaredDistance);
})

Performance Considerations

  1. Precision: WebGL handles single-precision floats (float32) by default. If your SVM algorithm requires double-precision (float64), pass { precision: 'single' } consciously or use GPU.js configurations that support 64-bit precision where hardware allows.
  2. Data Transfer Overhead: Copying data from the CPU to the GPU incurs overhead. Keep matrices on the GPU using pipeline: true if you intend to feed the Gram matrix directly into subsequent GPU-accelerated solvers.
  3. Loop Limits: GPU.js compiles loops into native shaders. Always pass dimension lengths (like numFeatures) as explicit arguments rather than attempting to read .length properties inside the kernel function.
