Compute Fluid Boundary Layers Using GPU.js

Computing numerical boundary layer approximations involves solving simplified forms of the Navier-Stokes equations—such as the Prandtl boundary layer equations—over a discretized mesh near solid surfaces. By utilizing gpu.js, developers and computational fluid dynamicists can accelerate these calculations directly in JavaScript using WebGL compute shaders. This article details the mathematical formulation, finite difference discretization, and step-by-step implementation of an accelerated boundary layer solver using gpu.js.

The Governing Equations

For a steady, two-dimensional, laminar, incompressible flow over a flat plate aligned with the \(x\)-axis, the Prandtl boundary layer equations govern the velocity fields:

  1. Continuity Equation: \[\frac{\partial u}{\partial x} + \frac{\partial v}{\partial y} = 0\]

  2. Momentum Equation: \[u \frac{\partial u}{\partial x} + v \frac{\partial u}{\partial y} = \nu \frac{\partial^2 u}{\partial y^2}\]

Here, \(u\) and \(v\) are the streamwise (\(x\)) and wall-normal (\(y\)) velocity components, and \(\nu\) is the kinematic viscosity.

The boundary conditions are:

  • At the wall (\(y = 0\)): \(u = 0\), \(v = 0\) (no-slip and no-penetration)
  • Far from the wall (\(y \to \infty\)): \(u \to U_\infty\) (free-stream velocity)
  • Upstream (\(x = 0\)): \(u(0, y) = U_\infty\) for \(y > 0\)

Because boundary layer equations are parabolic in \(x\), downstream values depend exclusively on upstream states. While traditionally computed via one-dimensional space-marching schemes, massively parallel architectures benefit significantly from solving the flow field as an iterative relaxation problem across a 2D structured mesh.

Finite Difference Discretization

To map the momentum equation to GPU threads, we discretize the domain on a uniform 2D grid with spatial steps \(\Delta x\) and \(\Delta y\):

  • Streamwise convection: \[\frac{\partial u}{\partial x} \approx \frac{u_{i, j} - u_{i-1, j}}{\Delta x}\]
  • Wall-normal convection: \[\frac{\partial u}{\partial y} \approx \frac{u_{i, j+1} - u_{i, j-1}}{2\Delta y}\]
  • Viscous diffusion: \[\frac{\partial^2 u}{\partial y^2} \approx \frac{u_{i, j+1} - 2u_{i, j} + u_{i, j-1}}{\Delta y^2}\]

Solving explicitly for the update of \(u_{i, j}\) using a pseudo-transient relaxation scheme gives:

\[u_{i, j}^{n+1} = u_{i, j}^n + \Delta t \left[ \nu \frac{u_{i, j+1}^n - 2u_{i, j}^n + u_{i, j-1}^n}{\Delta y^2} - u_{i, j}^n \frac{u_{i, j}^n - u_{i-1, j}^n}{\Delta x} - v_{i, j}^n \frac{u_{i, j+1}^n - u_{i, j-1}^n}{2\Delta y} \right]\]

The normal velocity \(v_{i, j}\) is updated from the wall upward by numerically integrating the continuity equation:

\[v_{i, j} = v_{i, j-1} - \frac{\Delta y}{\Delta x} (u_{i, j} - u_{i-1, j})\]

Implementing the Solver in GPU.js

1. Setup and Environment

First, import the library and instantiate the GPU context:

const { GPU } = require('gpu.js');
const gpu = new GPU();

2. Streamwise Velocity Kernel

The following kernel executes in parallel across the entire domain, updating the streamwise velocity \(u\):

const updateU = gpu.createKernel(function(u, v, nx, ny, dx, dy, dt, nu, U_inf) {
    const i = this.thread.x; // Streamwise index
    const j = this.thread.y; // Wall-normal index

    // Boundary condition: No-slip at the wall
    if (j === 0) {
        return 0.0;
    }
    // Boundary condition: Free-stream at upper boundary
    if (j === ny - 1) {
        return U_inf;
    }
    // Boundary condition: Inlet at x = 0
    if (i === 0) {
        return U_inf;
    }

    const u_curr = u[j][i];
    const u_left = u[j][i - 1];
    const u_up   = u[j + 1][i];
    const u_down = u[j - 1][i];
    const v_curr = v[j][i];

    // Derivatives
    const du_dx = (u_curr - u_left) / dx;
    const du_dy = (u_up - u_down) / (2.0 * dy);
    const d2u_dy2 = (u_up - 2.0 * u_curr + u_down) / (dy * dy);

    // Momentum equation update
    const du_dt = nu * d2u_dy2 - (u_curr * du_dx) - (v_curr * du_dy);

    return u_curr + dt * du_dt;
})
.setOutput([nx, ny])
.setPipeline(true); // Keeps output in GPU texture memory

3. Normal Velocity Computation

Because continuity requires an integration normal to the surface (\(y\)-direction), \(v\) is updated along columns. In gpu.js, a 1D kernel running across all \(x\)-stations (size nx) calculates \(v\) vertically:

const updateV = gpu.createKernel(function(u, nx, ny, dx, dy) {
    const i = this.thread.x;
    const j = this.thread.y;

    if (j === 0 || i === 0) {
        return 0.0;
    }

    // Integrate continuity equation: v_j = v_{j-1} - (dy/dx)*(u_i - u_{i-1})
    let integrated_v = 0.0;
    for (let k = 1; k <= j; k++) {
        const du_dx = (u[k][i] - u[k][i - 1]) / dx;
        integrated_v -= du_dx * dy;
    }

    return integrated_v;
})
.setOutput([nx, ny])
.setPipeline(true);

4. Running the Simulation Loop

Combine kernels within an iteration loop to achieve steady-state:

const nx = 256;
const ny = 128;
const dx = 0.005;
const dy = 0.0005;
const dt = 0.00001;
const nu = 0.000015; // Kinematic viscosity of air
const U_inf = 1.0;

// Initialize initial velocity matrices
let u = new Array(ny).fill(0).map(() => new Array(nx).fill(U_inf));
let v = new Array(ny).fill(0).map(() => new Array(nx).fill(0.0));

// Enforce initial wall condition
for (let i = 0; i < nx; i++) {
    u[0][i] = 0.0;
}

const iterations = 5000;
for (let step = 0; step < iterations; step++) {
    u = updateU(u, v, nx, ny, dx, dy, dt, nu, U_inf);
    v = updateV(u, nx, ny, dx, dy);
}

// Convert final GPU texture to standard JavaScript array
const finalVelocityProfile = u.toArray();

Performance and Precision Considerations

  1. Pipeline Mode: Always enable .setPipeline(true). This keeps matrix states as textures directly on the GPU, avoiding round-trip CPU-GPU memory latency during iterative loops.
  2. Numerical Stability: The explicit pseudo-time-stepping scheme requires adhering to the Courant-Friedrichs-Lewy (CFL) condition: \[\Delta t \le \min\left( \frac{\Delta x}{U_\infty}, \frac{\Delta y^2}{2\nu} \right)\] Violating this criterion leads to immediate divergence in the boundary layer kernel.
  3. Precision: Standard WebGL contexts in browsers default to single-precision (32-bit) floating-point calculations. When resolving high-gradient shear stresses directly at the wall (\(y \approx 0\)), adjust your non-dimensional scaling to preserve precision and prevent truncation errors.
