Controlling Texture Bit Depth in GPU.js

This article explores whether developers can manually specify the bit depth of intermediate textures generated during kernel operations in gpu.js. It examines the internal texture allocation mechanisms of gpu.js, how the library abstracts WebGL texture formats, the extent of precision configuration available to developers, and alternative approaches when custom bit depth is required.

In gpu.js, developers cannot manually specify the bit depth of intermediate textures. The library is designed as a high-level abstraction over WebGL (WebGL 1 and WebGL 2), prioritizing ease of use and automated cross-browser compatibility over low-level graphics pipeline configuration. As a result, intermediate textures created during kernel execution—particularly when using pipelining (pipeline: true)—have their internal pixel formats and bit depths determined automatically by the underlying engine.

When chaining kernels via pipelining, gpu.js outputs WebGL textures rather than decoding the data back to CPU-accessible arrays. The internal format of these intermediate textures depends on the host environment's WebGL capabilities:

  • WebGL 2 Contexts: gpu.js primarily uses standard 32-bit single-precision floating-point formats (such as RGBA32F) to preserve full numeric accuracy between chained kernels.
  • WebGL 1 Contexts: The library attempts to enable floating-point texture extensions (such as OES_texture_float). If supported, it defaults to 32-bit float textures. If float extensions are unavailable, it falls back to packing 32-bit floating-point values across standard 8-bit integer channels (RGBA 8-bit unsigned bytes).

While developers can set the precision option on a kernel to 'single' or 'unsigned', this setting primarily influences GLSL shader compilation and type handling rather than giving granular control over the texture's internal representation (such as forcing a 16-bit half-float RGBA16F texture).

Because intermediate texture generation is fully encapsulated within the Texture and Kernel classes, developers cannot define parameters like gl.HALF_FLOAT or target custom bit depths without modifying the gpu.js source code directly. For compute workloads where controlling intermediate texture bit depth is essential to reduce VRAM consumption or optimize memory bandwidth, developers must write custom WebGL or WebGPU shaders where framebuffers and textures can be bound to explicit internal formats.
