Parallel Wavefront Pathfinding with GPU.js

This article explains how to implement parallel wavefront pathfinding and Dijkstra-style distance expansion maps using gpu.js. Sequential pathfinding algorithms rely on priority queues that are inefficient on graphics hardware; by reformulating the problem into an iterative relaxation process similar to the Bellman-Ford algorithm or cellular automata, thousands of grid cells can be evaluated simultaneously on the GPU. You will learn the mechanics of parallel relaxation, how to configure a gpu.js kernel for texture-based compute operations, and how to read back paths efficiently.

The Algorithmic Shift: Priority Queue vs. Iterative Relaxation

Standard Dijkstra's algorithm uses a min-priority queue to expand nodes sequentially from the lowest cost outward. This sequential dependency creates a bottleneck on GPUs, which excel at Single Instruction, Multiple Data (SIMD) workloads.

To parallelize wavefront expansion, you must treat the grid as a cellular automaton. At each step:

  1. Every cell concurrently checks its own value and the values of its orthogonal (or diagonal) neighbors.
  2. If a neighbor’s distance plus the transition cost is lower than the cell's current distance, the cell updates its value to that lower sum.
  3. This process repeats across the entire grid until no cell distances change (convergence) or until the target coordinate is reached.

This approach is equivalent to a parallel Bellman-Ford expansion or an expanding wavefront.

1. Grid Representation and Initialization

Represent your environment as two-dimensional arrays (matrices):

  • Obstacle Map: Values where 0 represents passable terrain and 1 represents an impassable barrier.
  • Distance Map: Floating-point values where the starting cell is initialized to 0.0, and all other reachable cells are set to a very large number (representing infinity, such as 999999.0). Obstacles can also be marked with infinity.
const width = 512;
const height = 512;
const INF = 999999.0;

// Initialize obstacle map and distance map
const obstacles = [];
const distanceMap = [];

for (let y = 0; y < height; y++) {
  const obsRow = [];
  const distRow = [];
  for (let x = 0; x < width; x++) {
    obsRow.push(0); // 0 = free, 1 = obstacle
    distRow.push(INF);
  }
  obstacles.push(obsRow);
  distanceMap.push(distRow);
}

// Set start node
const startX = 10;
const startY = 10;
distanceMap[startY][startX] = 0.0;

2. Implementing the gpu.js Kernel

The kernel computes one wave expansion step. Because WebGL kernels cannot read from and write to the same buffer concurrently, you must use ping-pong buffering: one texture acts as the read buffer while the other acts as the write buffer, alternating roles on each iteration.

const { GPU } = require('gpu.js'); // or window.GPU in the browser
const gpu = new GPU();

const wavefrontStep = gpu.createKernel(function(currentDistances, obstacles, width, height) {
  const x = this.thread.x;
  const y = this.thread.y;

  // If this cell is an obstacle, keep it impassable
  if (obstacles[y][x] === 1) {
    return 999999.0;
  }

  let minDistance = currentDistances[y][x];

  // Up
  if (y > 0) {
    const up = currentDistances[y - 1][x] + 1.0;
    if (up < minDistance) minDistance = up;
  }
  // Down
  if (y < height - 1) {
    const down = currentDistances[y + 1][x] + 1.0;
    if (down < minDistance) minDistance = down;
  }
  // Left
  if (x > 0) {
    const left = currentDistances[y][x - 1] + 1.0;
    if (left < minDistance) minDistance = left;
  }
  // Right
  if (x < width - 1) {
    const right = currentDistances[y][x + 1] + 1.0;
    if (right < minDistance) minDistance = right;
  }

  return minDistance;
})
.setOutput([width, height])
.setPipeline(true); // Keeps output in GPU memory as a texture

setPipeline(true) is essential. It prevents the GPU from transferring the grid array back to the CPU after every iteration, avoiding substantial PCI-e bus bottlenecks.

3. Running the Expansion Loop

Execute the kernel iteratively to propagate the wavefront across the grid.

let current = distanceMap;
const iterations = Math.max(width, height) * 2; // Upper bound for worst-case path

for (let i = 0; i < iterations; i++) {
  // Current serves as the input texture, output stays on GPU
  current = wavefrontStep(current, obstacles, width, height);
}

// Convert the final GPU texture back to a standard JavaScript array
const finalDistanceMap = current.toArray();

4. Extracting the Optimal Path

Once the wavefront map is generated, backtracking from the target coordinate to the start node can be done on the CPU in \(O(N)\) time (where \(N\) is the number of steps in the path). Starting from the goal, inspect adjacent cells and continuously step to the neighbor with the minimum value until reaching the cell with value 0.0.

function extractPath(distanceMap, goalX, goalY) {
  const path = [[goalX, goalY]];
  let currX = goalX;
  let currY = goalY;

  while (distanceMap[currY][currX] !== 0) {
    let lowestVal = distanceMap[currY][currX];
    let nextX = currX;
    let nextY = currY;

    const neighbors = [
      [currX, currY - 1],
      [currX, currY + 1],
      [currX - 1, currY],
      [currX + 1, currY]
    ];

    for (const [nx, ny] of neighbors) {
      if (nx >= 0 && nx < width && ny >= 0 && ny < height) {
        if (distanceMap[ny][nx] < lowestVal) {
          lowestVal = distanceMap[ny][nx];
          nextX = nx;
          nextY = ny;
        }
      }
    }

    // Dead end or disconnected path check
    if (nextX === currX && nextY === currY) {
      return null; // Unreachable
    }

    currX = nextX;
    currY = nextY;
    path.push([currX, currY]);
  }

  return path.reverse();
}

Performance Considerations

  • Grid Size: The GPU approach outperforms standard CPU algorithms like \(A^*\) or sequential Dijkstra on very large maps (e.g., \(1024 \times 1024\) and above) or in situations where multiple target points share the same destination (all-pairs or multi-agent routing).
  • Early Termination: By reading a single pixel at the target location or using a sub-kernel reduction to detect convergence, you can break the loop early once the path reaches the goal.
  • Diagonal Movement: To add 8-directional movement, expand the neighbor checks in the kernel to include diagonals, adding \(\sqrt{2} \approx 1.414\) to diagonal neighbor costs instead of \(1.0\).
