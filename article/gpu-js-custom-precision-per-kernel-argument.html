GPU.js Custom Precision per Kernel Argument

This article examines whether gpu.js allows developers to specify custom precision qualifiers for individual kernel arguments using configuration maps. While gpu.js provides granular control over argument data types and global floating-point modes, it does not support per-argument precision qualifiers (such as lowp, mediump, or highp). Below is a direct breakdown of how precision works in gpu.js, how argument mapping is structured, and the available workarounds.

Argument Configuration in gpu.js

In gpu.js, you can define the types of incoming parameters using the argumentTypes configuration map when creating a kernel. This configuration informs the internal transpiler how to handle the values inside the generated WebGL shader code:

const kernel = gpu.createKernel(function(a, b) {
  return a[this.thread.x] + b;
}, {
  output: [100],
  argumentTypes: {
    a: 'Array',
    b: 'Float'
  }
});

The supported values for argumentTypes designate abstract types such as 'Array', 'Float', 'Integer', or dimensions like 'Array(2)'. However, this mapping system does not accept GLSL-style precision qualifiers. You cannot map an argument to declarations such as 'mediump Float' or 'lowp Array'.

Global Kernel Precision

Precision in gpu.js is defined globally at the kernel level rather than on a per-argument or per-variable basis. When building a kernel, you configure precision via the precision property:

const kernel = gpu.createKernel(function(x) {
  return x[this.thread.x] * 2.0;
}, {
  output: [512],
  precision: 'single' // Options: 'single' (high/full 32-bit float) or 'unsigned'
});

When compiled to WebGL 1 or WebGL 2, gpu.js sets a uniform precision directive (typically precision highp float;) at the top of the generated GLSL fragment shader. Because this directive applies across the entire shader execution, all float calculations and input uniforms share this global precision tier.

Workarounds for Precision Control

If your application demands distinct precision constraints across different inputs or operations, consider the following alternatives:

  1. Kernel Splitting: Segregate operations requiring different precision profiles into distinct kernels. Use a high-precision kernel (precision: 'single') for sensitive calculations and a standard or unsigned kernel for routines that can tolerate lower precision.
  2. Typed Arrays for Input Memory: Control the precision and memory footprint of your inputs in JavaScript prior to GPU transfer using specific TypedArray views (such as Float32Array, Int32Array, or Uint8Array).
  3. Raw WebGL Shaders: If explicit control over qualifiers like lowp, mediump, and highp on specific uniform arguments is critical for performance or hardware compatibility, implement the pipeline using raw WebGL shaders instead of the gpu.js abstraction layer.
