Parallelizing Dilation and Erosion Using GPU.js

Morphological operations such as dilation and erosion can be significantly accelerated in the browser and Node.js by parallelizing them on the graphics card using gpu.js. Because both operations evaluate pixel neighborhoods independently across an image grid, they are categorized as embarrassingly parallel workloads. By compiling simple JavaScript functions into WebGL shaders, gpu.js maps each pixel’s computation to a separate GPU thread, bypassing single-threaded CPU bottlenecks and enabling real-time performance on high-resolution images.

Understanding Dilation and Erosion on the GPU

Morphological operations work by sliding a structuring element—often a small matrix such as a 3x3 square or cross—over a binary or grayscale image:

  • Dilation: Assigns the output pixel the maximum value found among all pixels covered by the structuring element. This expands foreground boundaries.
  • Erosion: Assigns the output pixel the minimum value found among all pixels covered by the structuring element. This shrinks foreground boundaries.

Because calculating the minimum or maximum value within the local window of pixel (x, y) requires only read access to the input image and writes strictly to an independent output buffer, no race conditions exist between neighboring pixels. This localized read-only dependency makes morphological filters mathematically identical to spatial 2D convolutions in terms of memory access patterns, fitting the GPU execution model perfectly.

Implementing Morphological Kernels with gpu.js

With gpu.js, JavaScript functions are compiled directly into GLSL fragment shaders. The library maps the coordinates of the target image to this.thread.x and this.thread.y, invoking a parallel instance of the kernel for every pixel.

Dilation Kernel Example

const { GPU } = require('gpu.js');
const gpu = new GPU();

const dilateKernel = gpu.createKernel(function(image, width, height, radius) {
    let maxVal = 0.0;

    for (let dy = -radius; dy <= radius; dy++) {
        for (let dx = -radius; dx <= radius; dx++) {
            const x = this.thread.x + dx;
            const y = this.thread.y + dy;

            // Boundary checks
            if (x >= 0 && x < width && y >= 0 && y < height) {
                const pixel = image[y][x];
                if (pixel > maxVal) {
                    maxVal = pixel;
                }
            }
        }
    }

    return maxVal;
}).setOutput([imageWidth, imageHeight]);

const dilatedImage = dilateKernel(inputImageMatrix, imageWidth, imageHeight, 1);

Erosion Kernel Example

Erosion uses the exact same structure but initializes the tracking variable to the maximum possible intensity (such as 1.0 or 255.0) and looks for the lowest value in the neighborhood:

const erodeKernel = gpu.createKernel(function(image, width, height, radius) {
    let minVal = 1.0;

    for (let dy = -radius; dy <= radius; dy++) {
        for (let dx = -radius; dx <= radius; dx++) {
            const x = this.thread.x + dx;
            const y = this.thread.y + dy;

            if (x >= 0 && x < width && y >= 0 && y < height) {
                const pixel = image[y][x];
                if (pixel < minVal) {
                    minVal = pixel;
                }
            }
        }
    }

    return minVal;
}).setOutput([imageWidth, imageHeight]);

const erodedImage = erodeKernel(inputImageMatrix, imageWidth, imageHeight, 1);

Key Performance Considerations

To maximize throughput when parallelizing morphological operations with gpu.js, consider the following technical factors:

  1. Memory Transfer Overhead: Moving image data between the CPU (JavaScript main thread) and the GPU via WebGL textures introduces latency. For single passes on small images, CPU execution might be faster. GPU parallelization demonstrates its greatest advantage on large images (Full HD and above) or when chaining operations (such as opening, closing, or morphological gradient computation) directly on the GPU using { pipeline: true }.
  2. Pipeline Mode for Compound Operations: Complex morphological transformations like morphological opening (erosion followed by dilation) should keep the intermediate textures in VRAM. Setting pipeline: true on the gpu.js kernel prevents unnecessary GPU-to-CPU data round trips between steps.
  3. Kernel Structuring Elements: For large structuring elements, 2D nested loops inside the shader can become computationally expensive. Where possible, decompose separable structuring elements (such as rectangles) into two consecutive 1D passes (horizontal pass followed by a vertical pass) to reduce complexity from \(O(N^2)\) to \(O(2N)\) per pixel.
