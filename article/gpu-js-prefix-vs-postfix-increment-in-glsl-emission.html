GPU.js Prefix vs Postfix Increment in GLSL Emission

This article explores how GPU.js differentiates between prefix and postfix increment operators when translating JavaScript functions into WebGL-compatible GLSL shaders. By parsing JavaScript code into an Abstract Syntax Tree (AST), GPU.js inspects the structural metadata of update expressions—specifically evaluating the prefix boolean flag—to accurately position the operator relative to the operand during GLSL string emission.

AST Generation with Acorn

GPU.js relies on an internal JavaScript parser (derived from Acorn) to convert JavaScript kernel functions into an ESTree-compliant Abstract Syntax Tree (AST). Within the ESTree specification, both prefix (++x) and postfix (x++) increments are categorized under the same node type: UpdateExpression.

An UpdateExpression node contains three critical properties:

  • operator: A string representing the operation ("++" or "--").
  • argument: The identifier or member expression being modified.
  • prefix: A boolean value indicating the position of the operator.

When the parser encounters ++i, it generates an UpdateExpression with prefix: true. Conversely, when it encounters i++, it generates an identical node except that prefix is set to false.

The GLSL Translation Pipeline

During the compilation step, GPU.js traverses the AST using an internal code generator class (specifically within its WebGL or WebGL2 kernel backends). When the visitor reaches an UpdateExpression, it delegates the node to an emission handler responsible for writing out raw GLSL source code.

The emission logic inspects the AST node properties directly:

  1. Identifier Resolution: GPU.js first translates the argument property to ensure the variable name and its type are mapped properly to a valid GLSL variable (e.g., converting a local JS loop counter into a GLSL int or float).
  2. Boolean Check on prefix: The generator evaluates node.prefix.
    • If node.prefix is true, the generator outputs the operator string followed immediately by the compiled argument: ${node.operator}${argument}.
    • If node.prefix is false, the generator outputs the compiled argument followed by the operator string: ${argument}${node.operator}.

Semantic Compatibility in GLSL

Because GLSL inherits C-style syntax and operator semantics, it shares the exact evaluation rules that JavaScript uses for increment operators:

  • A prefix increment (++i) increments the variable and immediately returns the newly updated value.
  • A postfix increment (i++) increments the variable but yields the original value before the modification took place.

Because modern GLSL compilers natively support both prefix and postfix expressions with identical side-effect timing to JavaScript, GPU.js does not need to decompose these operations into multi-line temporary assignments in most standard contexts (such as for loop headers or standalone statements). Preserving the placement via the prefix flag allows the generated shader to retain the exact operational sequence and semantic intent of the original JavaScript kernel.
