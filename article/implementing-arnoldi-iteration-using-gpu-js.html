Implementing Arnoldi Iteration Using gpu.js

This article explains how to implement the Arnoldi iteration method to construct an orthonormal basis of a Krylov subspace using gpu.js. It details the mathematical formulation of the algorithm, identifies the core parallel computing bottlenecks, and provides complete, accelerated WebGL/GPU kernel implementations for matrix-vector multiplication, dot products, and vector updates in JavaScript.

Understanding the Arnoldi Iteration

The Arnoldi iteration is an algorithm based on Gram-Schmidt orthogonalization used to compute eigenvalues of large, sparse, or dense non-Hermitian matrices and to project linear systems onto Krylov subspaces.

Given an \(n \times n\) matrix \(A\) and a non-zero initial vector \(b\), the Krylov subspace of degree \(m\) is defined as:

\[\mathcal{K}_m(A, b) = \text{span}\{b, Ab, A^2b, \dots, A^{m-1}b\}\]

The algorithm constructs:

  1. An \(n \times m\) matrix \(V_m = [v_1, v_2, \dots, v_m]\) with orthonormal columns.
  2. An \((m+1) \times m\) upper Hessenberg matrix \(H_m\) such that \(A V_m = V_m H_m + h_{m+1,m} v_{m+1} e_m^T\).

Algorithm Steps

  1. Normalize initial vector: \(v_1 = b / \|b\|_2\).
  2. For \(j = 1, 2, \dots, m\):
    • Compute vector \(w = A v_j\).
    • For \(i = 1, 2, \dots, j\):
      • \(h_{i,j} = w \cdot v_i\)
      • \(w = w - h_{i,j} v_i\)
    • \(h_{j+1,j} = \|w\|_2\)
    • If \(h_{j+1,j} < \epsilon\), stop (invariant subspace reached).
    • \(v_{j+1} = w / h_{j+1,j}\)

GPU Acceleration Strategy with gpu.js

The computational hotspots that scale with matrix dimension \(n\) are:

  • Matrix-Vector Multiplication (\(w = A v_j\)): \(O(n^2)\) complexity, highly parallelizable on the GPU.
  • Dot Products (\(w \cdot v_i\) and \(\|w\|_2\)): \(O(n)\) complexity, mapped across GPU threads.
  • Vector Updates (AXPY: \(w = w - h v_i\)): \(O(n)\) element-wise operations.

Because Arnoldi constructs vectors sequentially (\(j = 1 \dots m\)), the outer loop remains on the CPU, while the inner \(O(n)\) and \(O(n^2)\) vector-matrix primitives execute on the GPU.

Implementation

1. Setup and Kernel Definitions

const { GPU } = require('gpu.js');
const gpu = new GPU();

// 1. Matrix-Vector Multiplication: w = A * v
const matVecMultKernel = gpu.createKernel(function (A, v, n) {
  let sum = 0;
  for (let i = 0; i < n; i++) {
    sum += A[this.thread.x][i] * v[i];
  }
  return sum;
}).setOutput([n]);

// 2. Element-wise Multiplication for Dot Product: temp[k] = a[k] * b[k]
const vecMultiplyKernel = gpu.createKernel(function (a, b) {
  return a[this.thread.x] * b[this.thread.x];
}).setOutput([n]);

// 3. Vector Subtraction (AXPY): w = w - h * v
const vecSubScaledKernel = gpu.createKernel(function (w, v, h) {
  return w[this.thread.x] - (h * v[this.thread.x]);
}).setOutput([n]);

// 4. Vector Scaling: v = w / norm
const vecScaleKernel = gpu.createKernel(function (w, norm) {
  return w[this.thread.x] / norm;
}).setOutput([n]);

2. Reduction Helper for Sums

While gpu.js computes element-wise kernels in parallel, calculating vector sums (such as dot products and norms) requires reduction. For smaller vectors or intermediate operations, sums can be performed on the CPU using the output array, or via hierarchical GPU reduction passes for larger \(n\).

function computeDotProduct(a, b, n) {
  const products = vecMultiplyKernel(a, b);
  let sum = 0;
  for (let i = 0; i < n; i++) {
    sum += products[i];
  }
  return sum;
}

function computeNorm(v, n) {
  return Math.sqrt(computeDotProduct(v, v, n));
}

3. Complete Arnoldi Iteration Function

function arnoldiIteration(A, b, m, n) {
  // Initialize matrices
  // V will store m + 1 orthonormal vectors of size n
  const V = [];
  // H is the upper Hessenberg matrix of size (m + 1) x m
  const H = Array.from({ length: m + 1 }, () => new Float32Array(m).fill(0));

  // Compute v1 = b / ||b||
  const bNorm = computeNorm(b, n);
  if (bNorm === 0) {
    throw new Error("Initial vector cannot be zero.");
  }
  
  V.push(vecScaleKernel(b, bNorm));

  for (let j = 0; j < m; j++) {
    // Step 1: w = A * v_j
    let w = matVecMultKernel(A, V[j], n);

    // Step 2: Modified Gram-Schmidt orthogonalization
    for (let i = 0; i <= j; i++) {
      const h_ij = computeDotProduct(w, V[i], n);
      H[i][j] = h_ij;
      w = vecSubScaledKernel(w, V[i], h_ij);
    }

    // Step 3: Compute norm of the residual vector
    const h_next = computeNorm(w, n);
    H[j + 1][j] = h_next;

    // Breakdown check (subspace is invariant)
    if (h_next < 1e-12) {
      console.warn(`Invariant subspace found at iteration ${j + 1}.`);
      return { V, H, iterations: j + 1 };
    }

    // Step 4: v_{j+1} = w / h_{j+1, j}
    V.push(vecScaleKernel(w, h_next));
  }

  return { V, H, iterations: m };
}

Memory and Precision Considerations

  • Data Transfer Overhead: Passing data between the CPU and GPU introduces latency. For matrices where \(n > 1024\), keep intermediate vectors stored as GPU textures by setting { pipeline: true } in gpu.createKernel() options.
  • Floating-Point Precision: Standard WebGL contexts in gpu.js often default to 16-bit or 32-bit single-precision floats (Float32Array). Because the Gram-Schmidt process accumulates rounding errors that lead to loss of orthogonality, double re-orthogonalization or tracking precision loss is critical when \(m\) is large.
