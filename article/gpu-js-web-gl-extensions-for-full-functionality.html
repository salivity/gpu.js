GPU.js WebGL Extensions for Full Functionality

GPU.js accelerates JavaScript calculations by compiling code into GLSL shaders executed directly on the graphics card via WebGL. To unlock full computational precision, large data processing, and optimal performance, the library queries the host environment for several key WebGL extensions during its context initialization phase. Without these extensions, GPU.js must either degrade numeric precision or fall back to CPU emulation.

1. 32-Bit Floating-Point Texture Support

Standard WebGL 1 defaults to 8-bit normalized integer channels (RGBA8), which is insufficient for general-purpose mathematical computing. GPU.js checks for floating-point extensions to feed and extract 32-bit floating-point arrays directly to and from GPU memory:

  • OES_texture_float (WebGL 1): Allows GPU.js to allocate and read textures containing standard 32-bit IEEE floating-point data, enabling kernels to ingest high-precision numerical matrices without manual byte-packing.
  • WEBGL_color_buffer_float (WebGL 1) / EXT_color_buffer_float (WebGL 2): Grants the GPU framebuffer the ability to render directly into 32-bit float textures. This extension is critical for retrieving float calculation outputs from the kernel. Without it, GPU.js must pack 32-bit floats across four 8-bit channels (RGBA), incurring shader overhead and CPU decoding penalties.

2. Half-Precision Floating-Point Fallbacks

When full 32-bit rendering is unavailable on constrained devices (such as mobile GPUs), GPU.js inspects extensions providing 16-bit float capabilities:

  • OES_texture_half_float: Allows the allocation of 16-bit floating-point textures as input storage.
  • EXT_color_buffer_half_float: Enables the framebuffer to render to 16-bit float textures. This serves as a secondary compute pathway when 32-bit float output buffers fail to initialize.

3. Texture Filtering Extensions

  • OES_texture_float_linear: Provides hardware bilinear filtering and linear sampling across 32-bit float textures.
  • OES_texture_half_float_linear: Provides the same linear filtering functionality for 16-bit textures. While GPU.js frequently relies on nearest-neighbor lookups (gl.NEAREST) for discrete array indices, linear extensions ensure texture sampling routines operate uniformly across diverse GPU driver implementations.

4. Geometry and Index Range

  • OES_element_index_uint (WebGL 1): Standard WebGL 1 limits vertex indices to 16 bits (a maximum index value of 65,535). GPU.js checks for this extension to enable unsigned 32-bit integer indices (gl.UNSIGNED_INT). This allows rendering primitives and dispatch meshes to scale past 65,535 elements when handling massive data arrays.

5. Multiple Render Targets (MRT)

  • WEBGL_draw_buffers (WebGL 1): By default, a WebGL 1 fragment shader writes to a single output buffer. GPU.js queries WEBGL_draw_buffers to enable kernels to write to multiple output textures simultaneously in a single compute pass. This feature is standard in WebGL 2 core, but requires this extension in WebGL 1.

WebGL 2 Context Initialization

GPU.js prioritizes a webgl2 context over webgl. In WebGL 2, extensions such as OES_texture_float, OES_element_index_uint, and WEBGL_draw_buffers are built directly into the core specification. However, rendering directly to 32-bit floating-point textures still requires an explicit check for EXT_color_buffer_float. If this extension is absent in WebGL 2, GPU.js falls back to encoding outputs or downgrades to an alternative execution pipeline.
