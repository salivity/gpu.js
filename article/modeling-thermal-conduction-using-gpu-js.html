Modeling Thermal Conduction Using GPU.js

Thermal conduction and heat dissipation across heterogeneous materials can be modeled effectively in a web environment using GPU.js. By translating the heat diffusion equation into numerical approximations via the Finite Difference Method (FDM), GPU.js leverages WebGL shaders to compute spatial temperature updates concurrently across thousands of grid points. This article explains the underlying physics, the implementation strategy in GPU.js, how to handle varying material properties, and the practical limits of this approach.

The Physics: Discretizing the Heat Equation

Thermal conduction in a continuous medium is governed by Fourier’s Law and the heat equation:

\[\frac{\partial T}{\partial t} = \alpha \nabla^2 T\]

where \(T\) is temperature, \(t\) is time, and \(\alpha\) is the thermal diffusivity of the material, defined as:

\[\alpha = \frac{k}{\rho c_p}\]

In this formula, \(k\) is thermal conductivity, \(\rho\) is mass density, and \(c_p\) is specific heat capacity.

To simulate this process computationally, space and time must be discretized using the Finite Difference Method (FDM). On a two-dimensional grid, the Laplacian operator \(\nabla^2 T\) is approximated using a five-point stencil:

\[\nabla^2 T \approx \frac{T_{x+1, y} + T_{x-1, y} + T_{x, y+1} + T_{x, y-1} - 4T_{x, y}}{\Delta x^2}\]

Calculating this formula for every cell in a large grid becomes computationally expensive on a single CPU thread. Because every cell's next state depends solely on its immediate neighbors from the previous time step, the problem is embarrassingly parallel, making it an ideal candidate for GPU computation.

Implementing the Kernel in GPU.js

GPU.js compiles standard JavaScript functions into WebGL fragment shaders, executing operations across a defined output dimension.

To simulate thermal conduction:

  1. State Storage: The simulation grid is represented as a 2D array of temperatures.
  2. Double Buffering: GPUs cannot reliably read from and write to the same buffer simultaneously. Two texture buffers are used: one stores the current state (\(T^n\)), while the GPU writes the computed next state (\(T^{n+1}\)) to the other.
  3. Execution: The GPU kernel reads the center cell and its orthogonal neighbors (north, south, east, west) to compute the updated temperature based on the forward Euler integration step:

\[T^{n+1}_{x, y} = T^n_{x, y} + \alpha \Delta t \left( \frac{T_{x+1, y} + T_{x-1, y} + T_{x, y+1} + T_{x, y-1} - 4T_{x, y}}{\Delta x^2} \right)\]

For the explicit forward Euler method to remain numerically stable, the time step must satisfy the Courant-Friedrichs-Lewy (CFL) condition:

\[\Delta t \le \frac{\Delta x^2}{4\alpha_{\max}}\]

Modeling Interfaces Across Different Materials

Real-world assemblies consist of multiple materials, such as a copper heat spreader attached to a silicon die or an aluminum heatsink. In such systems, \(\alpha\) is not constant across the grid.

To model heterogeneous media:

  • Property Grids: Maintain secondary 2D arrays passed as textures to the kernel representing spatial properties (conductivity \(k\), density \(\rho\), and heat capacity \(c_p\)) for each cell.
  • Interface Conductivity: When heat flows between two cells of different materials (e.g., cell \(A\) and cell \(B\)), using the arithmetic mean of their conductivities leads to non-physical results. Instead, the effective interface conductivity must be calculated using the harmonic mean:

\[k_{\text{eff}} = \frac{2 \cdot k_A \cdot k_B}{k_A + k_B}\]

The kernel calculates heat fluxes individually across each of the four cell faces using the appropriate interface conductivities, sums the net energy entering the cell, and divides by the local volumetric heat capacity (\(\rho \cdot c_p\)) to determine the temperature change.

Incorporating Heat Dissipation and Boundaries

Heat dissipation into the environment occurs at the system's boundaries or across its exposed surface area. GPU.js kernels can incorporate these mechanics directly:

  • Convective Dissipation (Newton’s Law of Cooling): Heat lost to ambient air is modeled as \(q = h(T - T_{\text{ambient}})\), where \(h\) is the convective heat transfer coefficient. Cells designated as exposed surface boundaries subtract this loss during each time step.
  • Radiative Dissipation (Stefan-Boltzmann Law): For high-temperature systems, radiation can be modeled as \(q = \epsilon \sigma (T^4 - T_{\text{ambient}}^4)\), where \(\epsilon\) is emissivity and \(\sigma\) is the Stefan-Boltzmann constant.
  • Fixed Temperature Sources (Dirichlet Conditions): Cells representing constant heat sources (e.g., an active processor core) or thermal sinks are hardcoded within the kernel to maintain a designated value.
  • Insulated Boundaries (Neumann Conditions): Outer edges of the grid replicate the temperature of their adjacent inner neighbor, setting the spatial gradient \(\frac{\partial T}{\partial n} = 0\) to prevent heat from leaving the boundary.

Performance Considerations and Limitations

While GPU.js enables real-time 2D and low-resolution 3D thermal simulations directly in a browser, certain technical trade-offs exist:

  • Floating-Point Precision: GPU.js relies on WebGL textures. Many mobile or older implementations lack support for 64-bit double-precision floating-point numbers (float64), defaulting to 32-bit floats. In iterative numerical differential equations, 32-bit floats can accumulate rounding errors over millions of cycles.
  • CPU-GPU Memory Transfer Overhead: Transferring large data arrays from the GPU back to the CPU memory (via .toArray()) is a blocking operation that stalls the pipeline. To achieve high frame rates, simulations should keep state data entirely on the GPU and render output using canvas rendering targets rather than reading numeric matrices back to JavaScript on every step.
  • Explicit vs. Implicit Solvers: GPU.js is well-suited for explicit time-stepping schemes. However, explicit solvers are constrained by the CFL stability criterion, requiring extremely small time steps when modeling materials with high thermal conductivity or grids with very fine spatial resolution. Implementing implicit solvers (like Crank-Nicolson), which eliminate this time-step limit, requires solving large sparse linear systems—an operation that is significantly more complex to architect within simple fragment shaders.
