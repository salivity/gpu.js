Map Hexagonal Grids to GPU.js Thread Lattices

Mapping hexagonal grid coordinate systems onto rectangular thread lattices in gpu.js bridges the gap between non-Cartesian spatial layouts and standard GPU compute pipelines. This guide explains how to convert gpu.js 2D thread indices into axial and cube hexagonal coordinate systems, calculate accurate spatial positions, access hexagonal neighbors in parallel, and execute hex-based simulations directly on the GPU.

The Challenge of Hexagonal Thread Mapping

GPU hardware processes execution units (threads) arranged in linear, 2D, or 3D Cartesian grids. In gpu.js, kernels define output dimensions via setOutput([width, height]), exposing thread locations via this.thread.x and this.thread.y.

Hexagonal layouts do not share direct orthogonal symmetry with rectangular lattices. To process a hex grid on the GPU, you must map the rectangular (x, y) thread coordinates to a discrete hexagonal coordinate system—most notably Offset, Axial, or Cube coordinates.

Coordinate Systems: Selection and Conversion

The standard mapping models are:

  1. Offset Coordinates: Easiest for storage allocation because an \(M \times N\) hex grid maps directly to an \(M \times N\) 2D array.
  2. Axial Coordinates (\(q, r\)): The most mathematically efficient for vector distance, rotation, and line-drawing calculations.
  3. Cube Coordinates (\(x, y, z\)): A 3D projection where \(x + y + z = 0\), ideal for complex geometric operations.

1. "Odd-r" Horizontal Layout (Pointy-Topped Hexagons)

In an odd-r layout, rows are staggered horizontally. Threads directly correspond to the row and column:

const col = this.thread.x;
const row = this.thread.y;

// Convert Offset to Axial (q, r)
const r = row;
const q = col - Math.floor(row / 2);

// Convert Axial to Cube (x, y, z)
const cubeX = q;
const cubeZ = r;
const cubeY = -cubeX - cubeZ;

2. "Odd-q" Vertical Layout (Flat-Topped Hexagons)

In an odd-q layout, columns are staggered vertically:

const col = this.thread.x;
const row = this.thread.y;

// Convert Offset to Axial (q, r)
const q = col;
const r = row - Math.floor(col / 2);

// Convert Axial to Cube (x, y, z)
const cubeX = q;
const cubeZ = r;
const cubeY = -cubeX - cubeZ;

Calculating World Coordinates Inside the Kernel

To map discrete threads to world-space coordinates (e.g., rendering or distance fields), compute the continuous Cartesian position based on hexagon radius \(R\).

For a pointy-topped grid:

  • Hex Width = \(\sqrt{3} \times R\)
  • Hex Height = \(2 \times R\)
  • Horizontal Spacing = \(\sqrt{3} \times R\)
  • Vertical Spacing = \(\frac{3}{2} \times R\)

GPU.js implementation:

const R = 10.0; // Hex outer radius
const sqrt3 = 1.7320508;

const col = this.thread.x;
const row = this.thread.y;

// Offset row calculation
const xOffset = (row % 2 === 1) ? (sqrt3 * R) / 2 : 0;
const worldX = col * sqrt3 * R + xOffset;
const worldY = row * 1.5 * R;

Neighbor Traversal in gpu.js Kernels

Simulations such as cellular automata require sampling the six adjacent neighbors of each hexagon. Because GPU threads read from rectangular memory buffers, neighbors must be sampled using either axial math or direct offset lookups.

Using odd-r offset coordinates, the parity of the current row determines neighbor locations:

// Predefined neighbor offsets for odd-r hex grids
// Even rows: [dx, dy]
// Odd rows:  [dx, dy]

function getNeighborValue(grid, width, height, col, row, direction) {
  const isOdd = row % 2;
  let nCol = col;
  let nRow = row;

  if (direction === 0) { nCol += 1; }                          // East
  else if (direction === 1) { nCol += isOdd ? 1 : 0; nRow -= 1; } // North-East
  else if (direction === 2) { nCol += isOdd ? 0 : -1; nRow -= 1; } // North-West
  else if (direction === 3) { nCol -= 1; }                          // West
  else if (direction === 4) { nCol += isOdd ? 0 : -1; nRow += 1; } // South-West
  else if (direction === 5) { nCol += isOdd ? 1 : 0; nRow += 1; } // South-East

  // Boundary check
  if (nCol >= 0 && nCol < width && nRow >= 0 && nRow < height) {
    return grid[nRow][nCol];
  }
  return 0;
}

Complete gpu.js Kernel Example

The following script sets up a basic GPU kernel that computes continuous world coordinates and neighbor averages across a hexagonal grid:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const WIDTH = 512;
const HEIGHT = 512;

const hexSimulationKernel = gpu.createKernel(function(grid) {
  const col = this.thread.x;
  const row = this.thread.y;
  const isOdd = row % 2;

  let sum = 0;
  
  // Directions: E, NE, NW, W, SW, SE
  const dColsOdd = [1, 1, 0, -1, 0, 1];
  const dColsEven = [1, 0, -1, -1, -1, 0];
  const dRows = [0, -1, -1, 0, 1, 1];

  for (let i = 0; i < 6; i++) {
    const dc = (isOdd === 1) ? dColsOdd[i] : dColsEven[i];
    const dr = dRows[i];

    const nc = col + dc;
    const nr = row + dr;

    if (nc >= 0 && nc < 512 && nr >= 0 && nr < 512) {
      sum += grid[nr][nc];
    }
  }

  return sum / 6.0;
}).setOutput([WIDTH, HEIGHT]);

Performance Considerations

  • Branching Minimization: Using conditional ternary checks based on row % 2 can cause branch divergence across warp execution. Flatten logic using bitwise operations (row & 1) or precomputed parity coefficients when optimizing hot loops.
  • Texture Storage: Store hex attributes in 2D RGBA textures where each texel maps directly to (col, row). This ensures contiguous memory reads when fetching adjacent horizontal neighbors.
