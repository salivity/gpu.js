Dynamic Thread Scaling in GPU.js Grids

Implementing multi-resolution grid hierarchies in gpu.js requires an understanding of how WebGL handles execution grids. While thread coordinates (this.thread.x, this.thread.y, this.thread.z) are read-only hardware indices determined at kernel launch, you can dynamically scale their effective spatial mapping using uniform arithmetic or pipeline multi-pass kernels. This approach enables quadtree structures, mipmapping, and adaptive resolution modeling directly inside WebGL compute shaders via gpu.js.

Thread Coordinate Immutability

In gpu.js, this.thread represents the integer index of the current execution unit derived from kernel.setOutput([width, height]). These values are read-only registers injected by the WebGL runtime and cannot be reassigned or mutated directly within the kernel body.

// This will cause a compilation error or be ignored:
this.thread.x = this.thread.x * scale;

Because direct reassignment is impossible, dynamic scaling must be achieved mathematically during coordinate lookup or by structuring data pipelines across different output dimensions.

Virtual Scaling Through Uniform Parameters

The most common way to implement multi-resolution hierarchies within a single kernel is to introduce dynamic scaling variables passed as arguments. By applying integer division, bit shifting, or floating-point normalization to the thread coordinates, you map multiple fine threads to common coarse cells, or conversely sample coarse grids at higher granularities.

const kernel = gpu.createKernel(function(data, scale) {
    const coarseX = Math.floor(this.thread.x / scale);
    const coarseY = Math.floor(this.thread.y / scale);
    return data[coarseY][coarseX];
}).setOutput([1024, 1024]);

By varying scale between execution runs, you dynamically change the resolution layer being sampled without triggering costly WebGL shader recompilations.

Multi-Pass Hierarchical Pipelines

For true spatial hierarchies—such as image pyramids, restricted quadtrees, or multigrid solvers—relying on a single flat output resolution can result in massive thread redundancy. In these scenarios, chaining multiple kernels with distinct output sizes provides optimal performance.

  1. Pipeline Mode: Set kernel.setPipeline(true) to keep output buffers directly in GPU memory as textures without transferring data back to the CPU.
  2. Dimension Decimation: Create separate kernels configured with scaled output dimensions (e.g., [512, 512], [256, 256], [128, 128]).
  3. Inter-Level Traversal: Pass the output texture of a fine-resolution kernel into a coarse-resolution kernel, using normalized coordinates or fixed downsampling strides to compute aggregate values.
const downsample = gpu.createKernel(function(sourceTexture) {
    const srcX = this.thread.x * 2;
    const srcY = this.thread.y * 2;
    
    // Average a 2x2 fine cell cluster into one coarse cell
    return (
        sourceTexture[srcY][srcX] +
        sourceTexture[srcY][srcX + 1] +
        sourceTexture[srcY + 1][srcX] +
        sourceTexture[srcY + 1][srcX + 1]
    ) * 0.25;
})
.setOutput([256, 256])
.setPipeline(true);

Dynamic Resizing Trade-Offs

While kernel.setOutput([newWidth, newHeight]) can be invoked dynamically on an existing kernel, calling it frequently introduces overhead because gpu.js must reallocate underlying WebGL framebuffers and textures. To maintain high frame rates, preallocate kernels for each fixed level of the hierarchy or execute virtual coordinate mapping over a fixed maximum bound.
