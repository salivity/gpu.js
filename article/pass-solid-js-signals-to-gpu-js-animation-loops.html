Pass Solid.js Signals to GPU.js Animation Loops

Integrating reactive state from Solid.js into a continuous GPU.js render loop requires bridging Solid's push-based reactivity with the browser's pull-based animation cycle. This guide explains how to pass reactive signals directly into a persistent requestAnimationFrame loop without causing redundant kernel re-creations or unnecessary DOM updates, ensuring smooth, hardware-accelerated rendering driven by UI controls.

The Challenge: Push vs. Pull Architecture

Solid.js uses fine-grained reactivity where changes to signals notify dependent effects and UI elements directly (push). Conversely, GPU animations driven by requestAnimationFrame pull the latest data every frame to compute the next visual state.

Re-creating a GPU.js kernel on every signal update introduces massive overhead because kernel compilation is computationally expensive. The optimal approach is to compile the kernel once, maintain a persistent render loop, and sample the latest signal values directly inside each iteration.

Implementation Steps

1. Compile the Kernel Once

Initialize the GPU instance and compile the kernel inside an onMount hook. Ensure you set the graphical: true flag and configure the output size so GPU.js outputs directly to an HTML canvas element.

2. Sample Signals Inside the Loop

Because Solid.js signal getters simply return their current value when called, you can invoke them inside the animation callback. Calling a signal outside a tracking context (like createEffect) reads its value without creating a subscription, which is ideal for a requestAnimationFrame loop.

3. Clean Up Resources

Use onCleanup to cancel the animation frame request and destroy the GPU instance when the component unmounts to prevent memory leaks and WebGL context loss.

Complete Code Example

import { createSignal, onMount, onCleanup } from "solid-js";
import { GPU } from "gpu.js";

export default function GpuCanvas() {
  let canvasRef;
  const [speed, setSpeed] = createSignal(1.0);
  const [zoom, setZoom] = createSignal(1.5);

  onMount(() => {
    // 1. Initialize GPU.js using the existing canvas
    const gpu = new GPU({
      canvas: canvasRef,
      mode: "webgl2",
    });

    // 2. Define and compile the kernel once
    const renderKernel = gpu
      .createKernel(function (time, speedMultiplier, zoomLevel) {
        const x = this.thread.x / this.output.x;
        const y = this.thread.y / this.output.y;

        const red = Math.sin(x * zoomLevel + time * speedMultiplier);
        const green = Math.cos(y * zoomLevel + time * speedMultiplier);
        const blue = Math.sin((x + y) * zoomLevel);

        this.color(red, green, blue, 1);
      })
      .setOutput([canvasRef.width, canvasRef.height])
      .setGraphical(true);

    let animationFrameId;
    let startTime = performance.now();

    // 3. Continuous render loop
    const loop = () => {
      const elapsed = (performance.now() - startTime) * 0.001;

      // Sample Solid.js signals by invoking the getters directly
      const currentSpeed = speed();
      const currentZoom = zoom();

      // Pass the sampled values into the kernel
      renderKernel(elapsed, currentSpeed, currentZoom);

      animationFrameId = requestAnimationFrame(loop);
    };

    // Start the continuous loop
    animationFrameId = requestAnimationFrame(loop);

    // 4. Teardown
    onCleanup(() => {
      cancelAnimationFrame(animationFrameId);
      gpu.destroy();
    });
  });

  return (
    <div>
      <canvas ref={canvasRef} width={500} height={500} />
      <div>
        <label>
          Speed:
          <input
            type="range"
            min="0.1"
            max="5.0"
            step="0.1"
            value={speed()}
            onInput={(e) => setSpeed(parseFloat(e.target.value))}
          />
        </label>
        <label>
          Zoom:
          <input
            type="range"
            min="0.5"
            max="10.0"
            step="0.1"
            value={zoom()}
            onInput={(e) => setZoom(parseFloat(e.target.value))}
          />
        </label>
      </div>
    </div>
  );
}

Performance Best Practices

  • Avoid Wrapping the Loop in createEffect: Do not wrap the requestAnimationFrame setup inside a Solid.js createEffect. This would cancel and restart the loop on every user interaction, leading to stuttering.
  • Keep Array Inputs Stable: If your signal passes an array of data rather than primitive floats or integers into the kernel, ensure you pass flat typed arrays (Float32Array) to prevent GPU.js from performing runtime array serialization on every frame.
  • Pause When Inactive: If the canvas is not visible or user interaction is paused, cancel the loop conditionally to conserve GPU and battery resources.
