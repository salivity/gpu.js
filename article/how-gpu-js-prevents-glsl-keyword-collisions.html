How gpu.js Prevents GLSL Keyword Collisions

When compiling JavaScript functions into WebGL-compatible shaders, gpu.js parses JavaScript source code into an Abstract Syntax Tree (AST) and cross-references all declared identifiers against a predefined registry of reserved GLSL keywords. By performing AST-level checks on variable declarations, function names, and parameter lists, the compiler detects keyword collisions before the shader is sent to the GPU, preventing cryptic WebGL compilation failures and guaranteeing that valid GLSL code is generated.

Abstract Syntax Tree (AST) Parsing

gpu.js initiates validation by reading the JavaScript kernel function using a JavaScript parser (such as Acorn). The parser converts the function into an AST, breaking down the source code into programmatic nodes such as:

  • VariableDeclarator (local variable names)
  • FunctionDeclaration (sub-function names)
  • Identifier (references and arguments)
  • Function parameter lists passed into the kernel

By analyzing the structure at the AST level rather than relying on regular expressions, gpu.js accurately isolates true variable identifiers from raw string literals, comments, or property names where GLSL keywords might otherwise appear safely.

Comparison Against the GLSL Reserved Keyword Dictionary

The gpu.js compiler maintains an internal lookup list containing all keywords, types, and built-in identifiers reserved by the target GLSL specification (such as GLSL ES 1.0 or GLSL ES 3.0). This list includes:

  • Data types: float, int, bool, vec2, vec3, vec4, mat2, mat3, mat4, sampler2D, samplerCube
  • Qualifiers and control keywords: attribute, varying, uniform, const, discard, precision, lowp, mediump, highp
  • Built-in functions and variables: gl_Position, gl_FragColor, gl_FragCoord, texture2D, dot, cross, sin, cos

During the AST traversal phase, the compiler visits every node defining or referencing a name. It queries the identifier name against this reserved keyword dictionary.

Error Handling and Variable Mangling

When gpu.js encounters an identifier that matches an entry in the reserved GLSL list, it prevents the invalid shader string from reaching the WebGL pipeline through one of two mechanisms:

  1. Throwing Immediate Transpilation Errors: For user-facing declarations (such as argument names or kernel-level variables), gpu.js throws a clear JavaScript runtime error indicating that the chosen identifier is a reserved keyword in GLSL and must be renamed.
  2. Internal Namespace Prefixing: For internally generated variables, loops, and intermediate calculations created by the compiler itself, gpu.js applies dedicated prefixes (such as user_, kernel_, or unique numerical suffixes). This scope isolation ensures that runtime-injected variables cannot accidentally mirror reserved GLSL syntax or clash with user-defined identifiers.

By coupling AST inspection with strict dictionary lookups and namespace isolation, gpu.js provides early, actionable feedback to developers and ensures all generated shaders adhere to WebGL GLSL naming rules.
