GPU Texture Cache and Array Layouts in GPU.js

This article explores how modern graphics processing unit (GPU) texture caches dictate optimal memory access patterns when traversing multidimensional arrays in gpu.js. Because gpu.js encodes array data as 2D WebGL textures under the hood, hardware-level texture samplers and spatial caching architectures heavily influence performance. Understanding the relationship between texture memory layout, coordinate addressing, and cache line population allows developers to eliminate bandwidth bottlenecks and structure kernels for maximum computational throughput.

How GPU.js Represents Arrays

GPU.js compiles JavaScript functions into WebGL compute shaders. Standard WebGL implementations—particularly WebGL 1 and 2—lack general-purpose arbitrary read/write memory buffers (SSBOs) across all target hardware. To work around this, gpu.js stores input arrays by packing their floating-point elements into the color channels (RGBA) of 2D textures.

When you pass a 2D or 3D array to a gpu.js kernel, the library flattens or tiles that data across a two-dimensional grid of pixels. Reading an element from an array inside the kernel function translates into a texture fetch using normalized or integer coordinate samplers.

Architecture of the GPU Texture Cache

Central Processing Units (CPUs) utilize standard L1/L2/L3 caches built for linear, one-dimensional spatial locality. When a CPU loads an element, it loads an entire contiguous 64-byte cache line, heavily favoring flat, row-major iteration.

In contrast, GPU texture caches are engineered for graphics rendering, where adjacent pixels across both the horizontal (\(X\)) and vertical (\(Y\)) axes are rendered simultaneously. Modern GPUs employ a 2D spatial locality cache structure, often organizing internal texture memory using space-filling curves, such as Morton order (Z-order curve) or tiled micro-blocks (e.g., \(4 \times 4\) or \(8 \times 8\) texels).

When a thread requests a single texel from a texture, the memory controller fetches a small 2D block of surrounding texels into the texture cache. This ensures that accessing neighboring points in two-dimensional space—whether horizontally or vertically—results in low-latency cache hits.

The Impact on Reading Order in Multi-Dimensional Arrays

The hardware structure of the texture cache directly influences how you should structure reading orders in your kernels:

1. Alignment with Thread Execution (Warp/Wavefront Coalescing)

GPU threads execute in lockstep groups known as warps (NVIDIA) or wavefronts (AMD), typically 32 or 64 threads wide. GPU.js maps its thread coordinates (this.thread.x, this.thread.y, this.thread.z) to these hardware lanes:

  • this.thread.x corresponds to adjacent threads running concurrently within the same warp.
  • When adjacent threads in a warp access adjacent coordinates along the fastest-moving axis of your array, their texture requests merge into a minimal number of cache transactions.
  • If threads in a warp read with large strides along a secondary dimension (such as iterating down columns while executing across rows), each thread accesses a different cache block, triggering high cache miss rates and pipeline stalls.

2. Flattened 3D Arrays and Tile Striding

When handling 3D arrays, gpu.js must fold the third dimension into the 2D texture plane by tiling. If your kernel traverses the \(Z\)-axis (depth) faster than the \(X\)- and \(Y\)-axes, reads hop across discontiguous tiles in the underlying 2D texture. Because the texture cache favors localized 2D footprints, jumping across large vertical or horizontal offsets causes constant cache eviction (cache thrashing).

3. Spatial Locality in Convolution and Stencil Operations

Algorithms that read neighboring cells—such as image processing filters, matrix multiplication, or cellular automata—reap significant performance gains from the texture cache. Because reading \((x+1, y)\), \((x-1, y)\), \((x, y+1)\), and \((x, y-1)\) falls directly within the pre-fetched 2D cache block, structuring reads to focus on local 2D neighborhoods significantly outperforms wide 1D strided scans.

Best Practices for Structuring Data in GPU.js

To align kernel performance with the texture cache:

  • Keep this.thread.x on the innermost dimension: Ensure that adjacent values of this.thread.x read contiguous indices in your source data arrays.
  • Avoid non-unit strides: Incrementing indices by arbitrary values or transposing reads without reorganizing memory layouts disrupts both warp coalescing and 2D spatial cache hits.
  • Group 2D operations together: Design kernel pipelines so that algorithms process complete 2D regions before stepping into third-dimensional strata, matching the physical 2D layout of WebGL textures.
