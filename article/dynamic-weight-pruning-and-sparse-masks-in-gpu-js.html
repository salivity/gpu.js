Dynamic Weight Pruning and Sparse Masks in GPU.js

Dynamic weight pruning and sparse parameter masks can be applied using gpu.js by executing conditional shader kernels directly on the GPU. While the underlying WebGL architecture enforces a fixed-memory, dense tensor model that limits true physical memory compression, gpu.js allows developers to dynamically compute pruning masks and apply element-wise zeroing across neural network weights during both training and inference.

How Dynamic Pruning Works in gpu.js

Dynamic pruning requires evaluating weight magnitudes or gradient thresholds at runtime and disabling specific connections without taking the model offline. In gpu.js, this is achieved by treating weights and masks as 2D or 3D arrays executed within custom compute kernels.

  1. Dynamic Mask Generation: A kernel evaluates current weight matrices against an updated threshold or percentile. If a weight’s absolute value falls below the cutoff, the kernel outputs a 0 to the mask matrix; otherwise, it outputs a 1.
  2. Mask Application (Hadamard Product): A matrix-multiplication or element-wise kernel computes the effective weights by multiplying the raw parameter matrix by the sparse mask matrix in parallel.
  3. In-Kernel Pruning: Instead of maintaining a separate mask matrix, dynamic pruning can be calculated inline within the forward pass kernel. The kernel checks the threshold on-the-fly, returning zero for pruned parameters to eliminate the memory overhead of an auxiliary mask tensor.

Code Pattern for Masked Operations

The standard approach uses two coordinated gpu.js kernels: one to generate the sparse mask dynamically, and another to apply it to matrix multiplications.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel to dynamically generate a binary mask based on a threshold
const createPruneMask = gpu.createKernel(function(weights, threshold) {
  const val = weights[this.thread.y][this.thread.x];
  return Math.abs(val) >= threshold ? 1 : 0;
}).setOutput([width, height]);

// Kernel to compute masked dense matrix multiplication
const maskedMatMul = gpu.createKernel(function(A, B, Mask) {
  let sum = 0;
  for (let i = 0; i < this.constants.sharedDim; i++) {
    const maskVal = Mask[this.thread.y][i];
    if (maskVal === 1) {
      sum += A[this.thread.y][i] * B[i][this.thread.x];
    }
  }
  return sum;
})
.setConstants({ sharedDim: width })
.setOutput([outWidth, outHeight]);

Architectural Constraints and Performance Realities

While dynamic sparse masking is functional in gpu.js, developers must account for the hardware execution model of WebGL:

  • Dense Storage Overhead: WebGL textures require rigid dimensional bounds. gpu.js cannot dynamically reallocate memory into Compressed Sparse Row (CSR) or Compressed Sparse Column (CSC) formats without custom encoding schemes. Pruned networks still consume the same GPU memory footprint as dense networks.
  • Warp Branch Divergence: Conditional statements inside gpu.js kernels (if (mask === 1)) do not always bypass computation. Modern GPU architectures execute instructions in lockstep (warps or wavefronts). If adjacent threads within the same warp take different branches, both branches are executed, mitigating the compute savings of unstructured dynamic pruning.
  • Pipeline Synchronization: Computing dynamic thresholds (such as determining the bottom 20% of weights across a layer) requires reductions. Reductions in gpu.js require multi-pass rendering, introducing latency if performed on every training step.

Structured vs. Unstructured Masking

To achieve real performance gains with dynamic pruning in gpu.js, structured pruning should be favored over unstructured pruning. Structured pruning zeros out entire rows, columns, or channels. By removing entire blocks, you can dynamically slice kernel output dimensions, reducing the actual grid dispatch size and achieving measurable execution speedups within WebGL's constraints.
