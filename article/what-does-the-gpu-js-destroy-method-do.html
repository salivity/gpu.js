What Does the GPU.js destroy() Method Do?

Calling the destroy() method on a GPU.js instance completely tears down the instance and frees the hardware resources allocated to it. In browser environments, high-performance computing tasks heavily rely on WebGL contexts to execute code on the graphics card. Calling destroy() ensures that internal WebGL contexts, compiled shaders, framebuffers, and allocated VRAM textures are deleted, preventing severe memory leaks and system context limits from crashing your application.

Deallocation of VRAM and Textures

GPU.js transfers data arrays to the graphics card by encoding them as WebGL textures. Over time, recurring calculations generate large numbers of textures in Video RAM (VRAM). When you execute gpu.destroy(), the method iterates through all stored texture references and calls WebGL's native gl.deleteTexture() function. This immediately deallocates memory on the graphics card, preventing the host machine's VRAM from saturating.

Kernel and Shader Termination

Every kernel created by a GPU.js instance compiles custom JavaScript logic into GLSL (OpenGL Shading Language) shader code. When destroy() is called:

  • All associated kernels linked to the GPU instance are dismantled.
  • Native WebGL shader objects (both vertex and fragment shaders) are deleted using gl.deleteShader().
  • The linked WebGL programs hosting the compiled pipeline are removed via gl.deleteProgram().

Disposal of the WebGL Context and Framebuffers

Browsers enforce strict limits on the number of active WebGL contexts that can exist simultaneously (often between 8 and 16 contexts). If you repeatedly create new GPU.js instances without cleaning up old ones, the browser will forcibly terminate older contexts. The destroy() method detaches active framebuffers via gl.deleteFramebuffer(), loses the WebGL context intentionally using available context extensions (such as WEBGL_lose_context), and clears references to the canvas element.

Instance Invalidation

Once destroy() is invoked, the target GPU instance becomes permanently inert. Any subsequent attempt to invoke previously compiled kernels or call methods like gpu.createKernel() will fail and throw runtime errors. To run further GPU-accelerated tasks, a new GPU instance must be instantiated.

When to Call destroy()

Calling destroy() is critical in long-running applications, such as Single Page Applications (SPAs) or progressive web apps, where components mount, compute data, and unmount. Whenever a GPU-dependent component reaches the end of its lifecycle, invoking destroy() guarantees that system resources return to a clean state.
