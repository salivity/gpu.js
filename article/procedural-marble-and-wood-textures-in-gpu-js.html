Procedural Marble and Wood Textures in GPU.js

Procedural marble and wood grain textures can be synthesized dynamically in the browser using GPU.js, an acceleration library that compiles JavaScript functions into WebGL shaders. By leveraging the parallel processing power of the graphics card, GPU.js can execute complex mathematical formulas and procedural noise algorithms per-pixel in real time. This article explains how GPU.js handles these calculations, the mathematical models required for both patterns, and the technical considerations for dynamic synthesis.

How GPU.js Handles Texture Generation

GPU.js works by transpiling a subset of JavaScript into GLSL (OpenGL Shading Language) and executing it on the GPU via WebGL. Texture synthesis is inherently parallel: computing the color of a specific coordinate \((x, y)\) does not depend on adjacent coordinates.

To synthesize textures dynamically, you define a GPU.js kernel sized to your target output resolution (for example, \(512 \times 512\)). Within the kernel function, the built-in this.thread.x and this.thread.y variables provide the current pixel coordinate. The kernel outputs values directly to an HTML5 canvas or returns a 2D/3D numerical array representing pixel color values (RGB or RGBA).

Synthesizing Procedural Marble

Marble patterns are generated by combining a periodic carrier wave—typically a sine function—with procedural turbulence based on Perlin or Simplex noise.

  1. Coordinate Normalization: Scale this.thread.x and this.thread.y to coordinate space between \(0.0\) and \(1.0\).
  2. Turbulence Calculation: Calculate fractional Brownian motion (fBm) by layering multiple octaves of noise at increasing frequencies and decreasing amplitudes.
  3. Perturbation: Displace the sine function input using the noise value: \[\text{pattern} = \sin((x \cdot \text{frequency}) + (\text{turbulence} \cdot \text{amplitude}))\]
  4. Color Interpolation: Map the resulting sine value (normalized between \(0.0\) and \(1.0\)) between marble vein colors (such as deep gray or black) and the base stone color (such as white or cream).

Because GPU.js supports user-defined functions, the noise generator and interpolation functions can be written in JavaScript and compiled directly into the shader pipeline.

Synthesizing Procedural Wood Grain

Wood grain textures are modeled around concentric cylinders representing tree rings, perturbed by noise to simulate organic irregularities.

  1. Center Offset: Compute the Euclidean distance from the current coordinate to a defined trunk center point: \[r = \sqrt{(x - x_0)^2 + (y - y_0)^2}\]
  2. Wobble and Grain Noise: Add low-frequency noise to \(r\) to create natural, non-circular warping across the rings. High-frequency noise stretched along one axis can be added to simulate micro-fibers and grain variations.
  3. Ring Generation: Apply a periodic modulation, such as: \[\text{ring} = (\sin(r \cdot \text{ring\_frequency} + \text{noise}) + 1.0) \times 0.5\]
  4. Color Mapping: Interpolate between earlywood (lighter, wider growth) and latewood (darker, denser boundary rings) based on the calculated ring factor.

Dynamic Interaction and Performance

Dynamic synthesis means parameters such as animation time, ring scale, noise frequency, and color palettes can change on every frame. GPU.js supports this through kernel arguments:

  • Passing Uniforms: Variables like time elapsed, cursor positions, or UI slider inputs can be passed directly as arguments to the kernel on each render loop.
  • Canvas Output: Setting graphical: true in the GPU.js kernel initialization directs output directly to a WebGL canvas context, eliminating the performance bottleneck of transferring data buffers back to the CPU.
  • Limitations: GPU.js transpilation restricts code to a strictly typed, C-like subset of JavaScript. Recursion is prohibited, array allocations inside kernels are restricted, and loops must have statically determinable boundaries for shader unrolling. Noise algorithms must be implemented iteratively rather than recursively.
