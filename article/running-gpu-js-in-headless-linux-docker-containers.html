Running gpu.js in Headless Linux Docker Containers

Running gpu.js inside a Linux Docker container without a physical monitor is entirely possible and a common practice for headless compute workloads. Because gpu.js relies on Node.js bindings to interface with the graphics pipeline on servers, it does not require an active display monitor or a desktop environment. This guide outlines how headless execution works in gpu.js, the requirements for hardware acceleration in Docker, and how to configure your container environment.

How gpu.js Operates Without a Monitor

In a standard browser, gpu.js uses the browser's WebGL implementation, which typically connects to the operating system's windowing system. In a Node.js environment, such as inside a standard Linux container, gpu.js utilizes headless-gl (the gl npm package) to create an off-screen WebGL context.

Because headless-gl renders off-screen using system OpenGL or software rasterization libraries, it completely bypasses the need for an X11 server, Wayland, or a connected monitor.

Requirements for Hardware-Accelerated Docker

To leverage actual GPU hardware inside Docker rather than falling back to CPU emulation, your host and container must meet specific criteria:

  1. NVIDIA GPU on the Host: The physical machine or cloud instance must have a supported GPU with the proprietary NVIDIA drivers installed.
  2. NVIDIA Container Toolkit: The host must have the NVIDIA Container Toolkit installed. This allows Docker to expose the GPU devices to the container runtime via the --gpus all flag.
  3. Build Dependencies for headless-gl: The gl package compiles native C++ bindings upon installation. The container must have the necessary build tools and OpenGL development libraries installed.

Configuring the Dockerfile

A Debian- or Ubuntu-based Dockerfile must install native dependencies before installing gpu.js. A minimal setup includes Python, build compilers, and X11/Mesa development headers required to build the headless context.

FROM node:18-bullseye

# Install dependencies required by headless-gl
RUN apt-get update && apt-get install -y \
    build-essential \
    python3 \
    libxi-dev \
    libglu1-mesa-dev \
    libglew-dev \
    pkg-config \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /usr/src/app

# Install gpu.js and headless-gl
RUN npm install gpu.js gl

COPY . .

CMD ["node", "index.js"]

Running the Container

When starting the container, pass the host GPU directly to Docker:

docker run --rm --gpus all my-gpu-app

Inside your application, initialize gpu.js normally:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Verify mode: should output 'gpu' rather than 'cpu'
console.log('Mode:', gpu.mode);

CPU Fallback Behavior

If the host lacks a dedicated GPU, or if the NVIDIA Container Toolkit is not properly configured, gpu.js gracefully handles the absence of hardware. By default, if the WebGL context fails to initialize, gpu.js falls back to multi-threaded or single-threaded CPU execution. This ensures the code remains functional, though computation times will be significantly higher than with hardware acceleration.
