Running gpu.js on Google Cloud Run with GPUs

This guide details the exact configurations required to run hardware-accelerated gpu.js workloads on Google Cloud Run. By combining Cloud Run's Nvidia L4 GPU support with a properly configured Node.js container that includes headless OpenGL dependencies, you can run server-side GPU computations seamlessly in a fully managed serverless environment.

1. Prerequisites and Infrastructure Constraints

Cloud Run requires specific resource allocations to attach GPU hardware:

  • Execution Environment: Must be set to Second Generation (gen2).
  • CPU Allocation: CPU must be allocated for the entire lifecycle (--no-cpu-throttling).
  • GPU Type: Cloud Run supports Nvidia L4 GPUs (nvidia-l4).
  • Hardware Sizing: Each Nvidia L4 GPU requires at least 4 vCPUs and a minimum of 16 GiB of memory.
  • Regions: The deployment must target a region where Cloud Run GPU support is available (e.g., us-central1).

2. Container Configuration (Dockerfile)

gpu.js in a headless Node.js environment relies on headless-gl to interface with graphics drivers. The container must include native compilation tools and the required OpenGL libraries.

Create a Dockerfile with the following configuration:

FROM node:20-bookworm-slim

# Install dependencies required by headless-gl and X11/OpenGL bindings
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    python3 \
    libxi-dev \
    libglu1-mesa-dev \
    libglew-dev \
    pkg-config \
    mesa-utils \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /usr/src/app

COPY package*.json ./

# Install application dependencies, including gpu.js and gl
RUN npm install

COPY . .

ENV PORT=8080
EXPOSE 8080

CMD ["node", "index.js"]

3. Node.js Initialization

In your Node.js code, explicitly pass the headless-gl instance to GPU to ensure the library attempts hardware WebGL initialization before falling back:

const { GPU } = require('gpu.js');
const gl = require('gl');

// Instantiate GPU with the headless-gl context
const gpu = new GPU({
  mode: 'gpu',
  webGl: gl(1, 1)
});

// Example kernel
const matMult = gpu.createKernel(function(a, b) {
  let sum = 0;
  for (let i = 0; i < 512; i++) {
    sum += a[this.thread.y][i] * b[i][this.thread.x];
  }
  return sum;
}).setOutput([512, 512]);

4. Deployment Command

Deploy the image using the Google Cloud CLI (gcloud). You must explicitly configure the GPU, CPU, memory, and concurrency flags to satisfy Cloud Run constraints.

gcloud beta run deploy gpu-js-service \
    --image gcr.io/YOUR_PROJECT_ID/gpu-js-service:latest \
    --region us-central1 \
    --execution-environment gen2 \
    --gpu 1 \
    --gpu-type nvidia-l4 \
    --cpu 4 \
    --memory 16Gi \
    --no-cpu-throttling \
    --concurrency 8 \
    --max-instances 5

5. Verification

To verify that gpu.js is utilizing the GPU rather than falling back to CPU mode, log the kernel runner mode inside your application:

console.log('GPU mode:', gpu.mode);

If configured correctly, gpu.mode resolves to gpu. If the container environment lacks access to the driver or OpenGL dependencies, gpu.js will output a warning and switch to cpu.
