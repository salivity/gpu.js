Configuring GPU.js Execution Modes

GPU.js allows developers to accelerate JavaScript functions by compiling them into WebGL shaders that run directly on the graphics processor. When initializing a GPU instance, the mode setting determines the target execution environment and hardware backend used to process computational kernels. Understanding the valid configuration values ensures optimal performance, reliable fallbacks, and predictable debugging behavior across different platforms and devices.

Setting the Execution Mode

You define the execution mode when instantiating the main GPU object by passing an options object:

const gpu = new GPU({ mode: 'gpu' });

Valid Execution Mode Settings

GPU.js supports several valid strings for the mode parameter:

  • 'gpu' (Default): Instructs GPU.js to automatically select the best available graphics acceleration method. It typically attempts to use WebGL 2 first, falls back to WebGL 1 if WebGL 2 is unsupported, and automatically falls back to CPU execution if no GPU capabilities are detected.

  • 'cpu': Completely bypasses graphics hardware and runs calculations directly on the CPU using pure JavaScript loops. This mode is useful for debugging code logic, running tests in environments without graphics drivers, or comparing performance between GPU and CPU processing.

  • 'webgl': Enforces the use of the standard WebGL 1 API in browser environments. If WebGL 1 is unavailable, kernel execution will fail rather than falling back to CPU or other contexts unless explicitly configured otherwise.

  • 'webgl2': Strictly targets the WebGL 2 API. This mode provides access to advanced GPU features, broader floating-point support, and improved precision. If the host platform does not support WebGL 2, initialization will fail.

  • 'headlessgl': Intended specifically for server-side environments such as Node.js. It forces GPU.js to use the headless-gl package to emulate a WebGL context without needing a physical display or browser window.

Best Practices

For cross-platform web applications, leaving the mode set to 'gpu' provides the best balance between hardware acceleration and automatic resilience. For backend tasks or continuous integration pipelines, explicitly specifying 'cpu' or 'headlessgl' prevents unexpected runtime exceptions caused by missing graphics hardware.
