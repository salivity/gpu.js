Code Reuse in GPU.js Kernels Using gpu.addFunction

The gpu.addFunction method in GPU.js allows developers to write modular, reusable JavaScript functions that can be shared across multiple GPU kernels. Because GPU kernels are compiled into WebGL or WebGPU shader code at runtime, standard external JavaScript functions cannot normally be called from within a kernel. By using gpu.addFunction, GPU.js translates standalone JavaScript helper functions into valid shading language routines, enabling clean separation of concerns, eliminating redundant code, and maintaining high performance across computational pipelines.

The Problem with Kernel Isolation

In GPU.js, kernel functions execute directly on the graphics card. To make this possible, the library parses the JavaScript function's Abstract Syntax Tree (AST) and transpiles it into OpenGL Shading Language (GLSL).

Because the resulting code runs on the GPU, standard JavaScript runtime features—such as closures, global variables, and imported modules—are inaccessible inside a kernel. Without a mechanism to inject external logic, any shared computation (such as matrix transformations, distance formulas, or color conversions) would need to be manually duplicated inside every individual kernel function.

How gpu.addFunction Works

The gpu.addFunction method solves this isolation problem by registering a custom function at the GPU instance level. When a helper function is passed to gpu.addFunction, GPU.js analyzes its syntax, converts it to a reusable GLSL function, and includes it in the header of every shader generated by that GPU instance.

Once added, the helper function behaves like a native GLSL function, allowing any kernel created by that instance to invoke it directly within its execution loop.

Basic Implementation

Registering a helper function requires defining a pure JavaScript function and passing it to the gpu.addFunction method before compiling the kernels:

const gpu = new GPU();

// Define a reusable mathematical utility
function euclideanDistance(x1, y1, x2, y2) {
  const dx = x1 - x2;
  const dy = y1 - y2;
  return Math.sqrt(dx * dx + dy * dy);
}

// Register the function with the GPU instance
gpu.addFunction(euclideanDistance);

// Kernel 1: Generates a radial proximity mask
const proximityKernel = gpu.createKernel(function(pointsX, pointsY, targetX, targetY) {
  const dist = euclideanDistance(pointsX[this.thread.x], pointsY[this.thread.x], targetX, targetY);
  return dist < 10.0 ? 1 : 0;
}).setOutput([1024]);

// Kernel 2: Calculates force interactions using the same utility
const forceKernel = gpu.createKernel(function(p1X, p1Y, p2X, p2Y) {
  const dist = euclideanDistance(p1X[this.thread.x], p1Y[this.thread.x], p2X[this.thread.x], p2Y[this.thread.x]);
  return dist > 0.0 ? 1.0 / (dist * dist) : 0.0;
}).setOutput([1024]);

In this example, euclideanDistance is defined once but compiled into both proximityKernel and forceKernel, ensuring consistency across the pipeline.

Managing Types with argumentTypes and returnType

While GPU.js can often infer variable types, complex functions—especially those accepting arrays or returning structured data—require explicit typing to ensure correct GLSL generation. The gpu.addFunction method accepts an optional configuration object to enforce specific parameter and return types:

function vectorAdd(v1, v2) {
  return [v1[0] + v2[0], v1[1] + v2[1]];
}

gpu.addFunction(vectorAdd, {
  argumentTypes: { v1: 'Array(2)', v2: 'Array(2)' },
  returnType: 'Array(2)'
});

Specifying types ensures that the shader compiler assigns proper data structures (like vec2, vec3, or fixed-size float arrays) in the generated shader, preventing runtime compilation failures and type mismatches across kernels.

Architectural Benefits

  • Maintainability (DRY Principle): Critical mathematical algorithms and utility routines reside in single, maintainable units rather than being copy-pasted across distinct kernels.
  • Pipeline Composition: Multi-stage rendering or computational pipelines (e.g., blur passes, physics updates, or post-processing) can establish a shared library of domain-specific primitives.
  • CPU and GPU Parity: Functions passed to gpu.addFunction remain valid JavaScript functions, allowing the exact same function to be used for CPU fallback execution or unit testing without modification.

Constraints and Best Practices

To ensure a function can be successfully converted and reused across kernels, it must adhere to GPU computing limits:

  • Purity: Functions must be pure. They cannot modify variables outside their scope or produce side effects.
  • Deterministic Execution: Functions cannot rely on standard JavaScript APIs like Date.now(), DOM elements, or asynchronous promises.
  • Fixed Control Flow: Dynamic features such as unbounded recursion are not supported by the underlying GPU hardware and cannot be used inside functions registered with gpu.addFunction.
