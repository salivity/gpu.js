How to Pass Array Data as GPU.js Kernel Constants

In GPU.js, you can pass array data into a kernel as a constant rather than passing it as a runtime function argument. GPU.js provides a built-in constants configuration option that embeds fixed data structures—including 1D, 2D, or 3D arrays—directly into the kernel execution context. This article explains how to define and access array constants, discusses performance benefits, and highlights key differences compared to standard kernel arguments.

Defining and Accessing Array Constants

To pass an array as a constant, specify it inside the constants configuration object when creating the kernel using gpu.createKernel(). Inside the kernel function, constant arrays are accessed via the this.constants namespace.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Define constant array data
const lookupTable = [10.5, 20.2, 30.8, 40.1];

const myKernel = gpu.createKernel(function() {
  // Access the array using this.constants
  const val = this.constants.factors[this.thread.x];
  return val * 2;
}, {
  constants: { factors: lookupTable },
  output: [4]
});

console.log(myKernel()); // Output: Float32Array [21, 40.4, 61.6, 80.2]

You can also update constants on an existing kernel instance without recreating it from scratch by using the setConstants() method:

myKernel.setConstants({ factors: [1.0, 2.0, 3.0, 4.0] });
console.log(myKernel()); // Output: Float32Array [2, 4, 6, 8]

When to Use Constants Instead of Arguments

Passing arrays as constants is optimal in specific execution patterns:

  • Lookup Tables and Fixed Weights: If an array represents static weights, masks, or lookup tables that do not change between successive kernel runs, declaring it as a constant clearly defines its immutable intent.
  • Kernel Specialization: GPU.js treats constants as fixed parameters during shader compilation, which can allow the underlying WebGL shader compiler to perform loop unrolling and optimization passes that are not possible with dynamic arguments.
  • Cleaner Invocation Signatures: Keeping immutable configuration data inside constants simplifies repetitive function calls, requiring only dynamic input data to be passed into the kernel execution.

Limitations and Considerations

While passing arrays as constants is straightforward, keep the following considerations in mind:

  • Read-Only Access: Array constants are strictly read-only inside the kernel. You cannot mutate elements of a constant array within the GPU thread.
  • Recompilation Overhead: When significantly altering constant structures or using certain complex data arrangements, changing constants via setConstants() may cause GPU.js to rebind textures or recompile portions of the shader pipeline, which is slower than passing different array references as standard arguments per iteration.
  • Memory Constraints: Just like array arguments, large constant arrays are typically uploaded to the GPU as textures. Ensure the array dimensions adhere to the maximum texture size supported by the client hardware.
