Simulating Kuramoto Synchronization Using GPU.js

This article explains how to simulate Kuramoto synchronization dynamics across thousands of coupled oscillators using GPU.js for hardware acceleration. It covers the core mathematical formulation of the Kuramoto model, demonstrates how to structure phase and frequency data for GPU memory, provides an optimized compute kernel for parallel numerical integration, and outlines key performance strategies for real-time WebGL execution.

The Kuramoto Model Dynamics

The Kuramoto model describes the synchronization behavior of a population of \(N\) weakly coupled limit-cycle oscillators. The phase \(\theta_i\) of the \(i\)-th oscillator evolves over time according to:

\[\frac{d\theta_i}{dt} = \omega_i + \frac{K}{N} \sum_{j=1}^{N} \sin(\theta_j - \theta_i)\]

Where:

  • \(\theta_i\) is the phase angle of oscillator \(i\), defined on the interval \([0, 2\pi)\).
  • \(\omega_i\) is the oscillator's intrinsic natural frequency, typically drawn from a distribution such as a Gaussian or Lorentzian.
  • \(K\) is the global coupling strength controlling the attraction between phases.
  • \(N\) is the total population size.

When \(N\) scales into the thousands or tens of thousands, calculating the pairwise interactions requires \(O(N^2)\) computations per time step. Offloading this calculation to the GPU via GPU.js parallelizes the summation over index \(j\) for every oscillator \(i\) simultaneously.

Setting Up GPU.js

Install gpu.js in your JavaScript environment via npm or include it via a CDN:

npm install gpu.js

Initialize the main GPU instance and define simulation parameters:

import { GPU } from 'gpu.js';

const gpu = new GPU();

const N = 4096;          // Number of oscillators
const DT = 0.01;         // Integration time step
const K = 1.5;           // Coupling strength
const TWO_PI = 2 * Math.PI;

// Generate initial states
const initialPhases = new Float32Array(N);
const naturalFrequencies = new Float32Array(N);

for (let i = 0; i < N; i++) {
  initialPhases[i] = Math.random() * TWO_PI;
  // Natural frequencies centered around 1.0 with standard normal variation
  naturalFrequencies[i] = 1.0 + (Math.random() - 0.5) * 0.5;
}

Implementing the GPU Kernel

Using an explicit Euler integration scheme, the kernel evaluates the interaction sum and advances the phases by \(dt\). The output of each step is wrapped into the range \([0, 2\pi)\).

const updateKuramoto = gpu.createKernel(function(phases, frequencies, K, N, dt) {
  const i = this.thread.x;
  const currentPhase = phases[i];
  let couplingSum = 0;

  // Compute interaction against all other oscillators
  for (let j = 0; j < N; j++) {
    couplingSum += Math.sin(phases[j] - currentPhase);
  }

  // Differential equation: dTheta/dt = omega_i + (K/N) * sum
  const dTheta = frequencies[i] + (K / N) * couplingSum;
  let nextPhase = currentPhase + dTheta * dt;

  // Keep phase within [0, 2*PI)
  const twoPi = 6.283185307179586;
  nextPhase = nextPhase % twoPi;
  if (nextPhase < 0) {
    nextPhase += twoPi;
  }

  return nextPhase;
})
.setOutput([N])
.setPipeline(true); // Retain output as a texture on the GPU

Running the Simulation Loop

Enabling .setPipeline(true) prevents textures from being read back to the CPU on every frame, eliminating PCI-e bandwidth bottlenecks.

let currentPhases = initialPhases;

function stepSimulation() {
  currentPhases = updateKuramoto(
    currentPhases,
    naturalFrequencies,
    K,
    N,
    DT
  );
}

// Execute 1,000 steps
for (let step = 0; step < 1000; step++) {
  stepSimulation();
}

// Retrieve final state back to CPU memory
const finalPhases = currentPhases.toArray();

Monitoring Synchronization via the Order Parameter

The global degree of phase coherence is measured using the Kuramoto order parameter \(r(t) \in [0, 1]\):

\[r(t) e^{i \psi(t)} = \frac{1}{N} \sum_{j=1}^{N} e^{i \theta_j(t)}\]

To evaluate \(r(t)\) without transferring the complete phase array back to the CPU, create a reduction kernel:

const computeOrderParameter = gpu.createKernel(function(phases, N) {
  let realSum = 0;
  let imagSum = 0;

  for (let j = 0; j < N; j++) {
    realSum += Math.cos(phases[j]);
    imagSum += Math.sin(phases[j]);
  }

  const r = Math.sqrt(realSum * realSum + imagSum * imagSum) / N;
  return r;
})
.setOutput([1]);

const coherence = computeOrderParameter(currentPhases, N)[0];

An \(r\) value near 0 indicates complete incoherence (random phases), while an \(r\) approaching 1 indicates full phase synchronization.

Optimizations for High-Density Systems

  1. Mean-Field Approximation: Standard Kuramoto all-to-all coupling can be re-expressed using the order parameter as \(\frac{d\theta_i}{dt} = \omega_i + K r \sin(\psi - \theta_i)\). If explicit pairwise connectivity (e.g., a dynamic adjacency matrix) is not required, compute \(r\) and \(\psi\) once per step in an \(O(N)\) pass, then update each oscillator in \(O(1)\) time, allowing populations exceeding \(10^5\) elements on modern GPUs.
  2. 2D Texture Layouts: Standard WebGL 1 context implementations have a maximum 1D texture dimension limit (often 4,096 or 8,192 pixels). For \(N > 8,192\), configure kernel output as a 2D grid (.setOutput([width, height])) and map thread.x and thread.y to a 1D oscillator index.
  3. Higher-Order Integration: For stiff systems or larger \(dt\) intervals, implement a 4th-order Runge-Kutta (RK4) integration method across multiple ping-pong kernel passes to preserve numerical stability.
