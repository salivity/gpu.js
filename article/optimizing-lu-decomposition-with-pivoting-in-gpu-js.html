Optimizing LU Decomposition with Pivoting in GPU.js

Implementing LU matrix decomposition with partial pivoting (LUP) in gpu.js presents unique performance challenges due to the sequential nature of pivot hunting and the latency of WebGL data readbacks. To achieve optimal throughput, developers must adopt a hybrid execution strategy that uses texture pipelining to keep matrix data on the GPU, minimizes CPU-GPU memory synchronization, and leverages 2D parallel compute kernels for Gaussian elimination updates. This article outlines the architecture and execution pipeline required to achieve maximum performance for LUP decomposition in gpu.js.

The Architectural Bottleneck of Partial Pivoting

Standard LU decomposition factorizes an \(n \times n\) matrix \(A\) into a lower triangular matrix \(L\) and an upper triangular matrix \(U\). Partial pivoting adds a permutation matrix \(P\) such that \(PA = LU\), stabilizing the algorithm against division by zero and numerical instability.

In each iteration \(k\) (from \(0\) to \(n-1\)), the algorithm must:

  1. Find the maximum absolute value in the sub-column \(k\) (rows \(k\) to \(n-1\)).
  2. Swap row \(k\) with the pivot row.
  3. Compute the multipliers \(L_{i,k} = A_{i,k} / A_{k,k}\) for \(i > k\).
  4. Update the trailing submatrix: \(A_{i,j} = A_{i,j} - L_{i,k} \times A_{k,j}\) for \(i, j > k\).

Step 4 is embarrassingly parallel, making it an ideal candidate for WebGL acceleration. However, Steps 1 and 2 introduce sequential synchronization barriers that can easily degrade performance if matrix buffers repeatedly transfer between the GPU and CPU.

1. Enable Kernel Pipelining to Eliminate Readback

By default, gpu.js downloads computation results back to the CPU as a JavaScript array after each kernel run. Transferring an \(n \times n\) array across the PCI-e bus \(n\) times introduces massive latency that outweighs any compute acceleration.

To optimize this:

  • Enable pipeline: true on the elimination kernel.
  • Keep the matrix representation inside GPU VRAM as a WebGL texture across all \(n\) iterations.
  • Run the algorithm iteratively by passing the output texture of step \(k\) directly as the input to step \(k+1\) (ping-pong buffering).

2. Streamline Pivot Selection

Finding the maximum element along an axis (reduction) is structurally inefficient in WebGL fragment shaders compared to standard compute shaders. To handle pivot selection without stalling the execution pipeline, choose one of two strategies based on matrix dimension:

  • Parallel Tree Reduction (For \(n \ge 1024\)): Implement a dedicated 1D reduction kernel that halves the search space iteratively on the GPU until the max element and row index are determined.
  • Batched Sub-vector Readback (For \(n < 1024\)): Extract only the active column segment (\(n - k\) floats) to the CPU rather than the full \(n \times n\) matrix. The CPU then performs a fast, single-threaded search to determine the pivot index, which is passed as a uniform variable to the GPU for the elimination phase.

3. Virtual Row Swapping in the Elimination Kernel

Physically copying entire rows in GPU memory during each pivot step incurs significant memory bandwidth overhead. Instead of executing a dedicated row-swapping kernel:

  1. Maintain an index map (permutation array) on the CPU or in a 1D texture.
  2. Update the permutation array logically when a pivot is selected.
  3. Provide the pivot index directly to the trailing submatrix kernel as a uniform parameter (uniform int pivotRow, uniform int currentRow).
  4. Inside the kernel shader, dynamically read from pivotRow whenever accessing values from currentRow, effectively performing the swap inline during the read phase of the elimination step.

4. Fused Multiplier and Trailing Matrix Elimination

Rather than splitting the multiplier calculation and trailing submatrix subtraction into separate kernel calls, combine them into a single 2D kernel.

const lupStep = gpu.createKernel(function(A, k, pivotRow, n) {
    let row = this.thread.y;
    let col = this.thread.x;

    // Determine virtual indices accounting for the pivot swap
    let actualRow = row;
    if (row === k) actualRow = pivotRow;
    else if (row === pivotRow) actualRow = k;

    // Leave previously factored components intact
    if (actualRow < k || col < k) {
        return A[actualRow][col];
    }

    // Compute multiplier on the active column
    if (col === k && actualRow > k) {
        return A[actualRow][k] / A[k][k];
    }

    // Update trailing submatrix
    if (actualRow > k && col > k) {
        let multiplier = A[actualRow][k] / A[k][k];
        return A[actualRow][col] - (multiplier * A[k][col]);
    }

    return A[actualRow][col];
}, {
    pipeline: true,
    immutable: true
});

Summary of Performance Gains

The most efficient approach combines texture pipelining, virtual row pivoting via shader uniforms, and a single fused elimination pass. This guarantees that:

  • Matrix values remain bound to texture memory for the duration of the factorization.
  • CPU-GPU synchronization is restricted strictly to pivot row resolution.
  • GPU memory writes are minimized to a single render pass per outer-loop iteration.
