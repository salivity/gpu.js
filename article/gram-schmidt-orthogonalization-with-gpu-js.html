Gram-Schmidt Orthogonalization with GPU.js

Gram-Schmidt orthogonalization transforms a set of linearly independent vectors into an orthonormal basis, but computing it sequentially on high-dimensional vectors causes significant CPU bottlenecks. While the process across vectors is inherently sequential, the vector-vector operations—such as dot products, vector scaling, and vector projections—can be heavily parallelized. This article demonstrates how to implement the Modified Gram-Schmidt (MGS) algorithm using GPU.js, utilizing WebGL-accelerated parallel kernels to drastically speed up inner-product and component-wise operations on high-dimensional vector sets.

Algorithmic Approach: Modified Gram-Schmidt (MGS)

The Classical Gram-Schmidt (CGS) process is prone to numerical instability due to the accumulation of floating-point rounding errors. For high-dimensional computing, the Modified Gram-Schmidt (MGS) method is preferred.

Given a set of \(k\) vectors \(\{v_1, v_2, \dots, v_k\}\) in an \(n\)-dimensional space (where \(n \gg k\)):

  1. For each vector \(v_i\), compute its Euclidean norm: \(\|v_i\| = \sqrt{v_i \cdot v_i}\).
  2. Normalize \(v_i\): \(q_i = \frac{v_i}{\|v_i\|}\).
  3. For every remaining vector \(v_j\) (where \(j > i\)):
    • Compute the projection scalar: \(c = q_i \cdot v_j\).
    • Subtract the projection in parallel across all \(n\) dimensions: \(v_j = v_j - c \cdot q_i\).

Designing the GPU.js Kernels

GPU.js allows JavaScript functions to be compiled into WebGL shaders. To minimize CPU-GPU memory transfer overhead, vector operations remain on the GPU using pipelining.

Three core GPU kernels are required:

  1. Dot Product Kernel: Computes the inner product between two vectors.
  2. Vector Subtraction Kernel: Scales an orthogonalized vector by the projection scalar and subtracts it from the target vector.
  3. Normalization Kernel: Divides each component of a vector by its Euclidean norm.

Implementation

const { GPU } = require('gpu.js');
const gpu = new GPU();

/**
 * Kernel to compute the dot product of two vectors of size N.
 */
const dotProductKernel = gpu.createKernel(function (a, b, length) {
    let sum = 0;
    for (let i = 0; i < length; i++) {
        sum += a[i] * b[i];
    }
    return sum;
})
.setOutput([1]);

/**
 * Kernel to normalize a vector by dividing each element by the norm.
 */
const normalizeKernel = gpu.createKernel(function (v, norm) {
    return v[this.thread.x] / norm;
})
.setOutput([/* dimension */])
.setPipeline(true);

/**
 * Kernel to perform projection subtraction: v_j[x] - (proj * q_i[x])
 */
const projectAndSubtractKernel = gpu.createKernel(function (v_j, q_i, proj) {
    return v_j[this.thread.x] - (proj * q_i[this.thread.x]);
})
.setOutput([/* dimension */])
.setPipeline(true);

/**
 * Runs Modified Gram-Schmidt on an array of high-dimensional vectors.
 * @param {Array<Float32Array>} vectors - Array of k vectors, each of dimension n.
 * @returns {Array<Float32Array>} - Orthonormal basis vectors.
 */
function gpuGramSchmidt(vectors) {
    const k = vectors.length;
    const n = vectors[0].length;

    // Dynamically adjust kernel dimensions to match input dimensionality
    normalizeKernel.setOutput([n]);
    projectAndSubtractKernel.setOutput([n]);

    let Q = [];
    let currentVectors = vectors.map(v => v);

    for (let i = 0; i < k; i++) {
        // Step 1: Compute norm of currentVectors[i]
        const selfDot = dotProductKernel(currentVectors[i], currentVectors[i], n)[0];
        const norm = Math.sqrt(selfDot);

        if (norm < 1e-10) {
            throw new Error(`Vector at index ${i} is linearly dependent or near zero.`);
        }

        // Step 2: Normalize to get orthonormal basis vector q_i
        const q_i = normalizeKernel(currentVectors[i], norm);
        
        // Step 3: Project and subtract q_i from remaining vectors
        for (let j = i + 1; j < k; j++) {
            // Read back q_i array representation for inner product if necessary,
            // or pass pipeline textures directly into dotProductKernel.
            const proj = dotProductKernel(q_i, currentVectors[j], n)[0];
            
            // In-place update using GPU pipeline texture
            currentVectors[j] = projectAndSubtractKernel(currentVectors[j], q_i, proj);
        }

        // Save result (convert texture to JavaScript typed array)
        Q.push(q_i.toArray());
    }

    return Q;
}

Execution Considerations

  • Memory Pipelining: Setting setPipeline(true) instructs GPU.js to leave the output on the GPU as a WebGL texture rather than serializing it back to a CPU Float32Array. This is critical when iteratively updating \(v_j\), as transferring millions of components over the PCIe bus introduces heavy latency.
  • Precision: WebGL traditionally operates on 32-bit floating-point values (Float32Array). In high-dimensional Gram-Schmidt processes, numerical drift occurs faster in 32-bit precision than in standard 64-bit CPU math. If orthogonality degrades over large sets (\(k > 100\)), apply a second pass of re-orthogonalization (MGS2).
  • Workgroup Sizing: Ensure dimension \(n\) aligns well with the hardware thread group limits. For ultra-high dimensions (e.g., \(n > 100,000\)), standard GPU.js 1D thread allocations handle vector processing efficiently by scheduling across available shader compute cores.
