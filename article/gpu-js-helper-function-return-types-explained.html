GPU.js Helper Function Return Types Explained

When developing kernels with gpu.js, helper functions cannot return arbitrary complex JavaScript structures such as objects, dynamic lists, or custom classes. Because gpu.js transpiles JavaScript code into WebGL shading language (GLSL), helper functions are bound by the strict constraints of the GPU hardware. As a result, functions executed on the GPU are limited to returning primitive scalar types or fixed-size array vectors that directly map to native GLSL types.

Supported Return Types

Helper functions run directly inside the GPU pipeline and must output data types that GLSL natively understands:

  • Primitives (Numbers and Booleans): Single values such as integers, floating-point numbers, and booleans are fully supported.
  • Fixed-Length Arrays (Vectors): You can return small, fixed-length arrays containing 2, 3, or 4 numeric elements. Under the hood, gpu.js compiles these arrays into GLSL vector types (vec2, vec3, and vec4).

Unsupported Return Types

The following JavaScript data structures will cause compilation errors or runtime failures when returned from a helper function:

  • JavaScript Objects: Structures with key-value pairs (e.g., { x: 1, y: 2 }) cannot be compiled because GLSL does not support dynamic object models.
  • Dynamic Arrays: Arrays with arbitrary or variable lengths cannot be evaluated by the static memory model of the GPU.
  • Strings and Complex Entities: Non-numeric types such as strings, class instances, functions, and deeply nested arrays are completely unsupported.

How to Handle Complex Return Data

If your helper function needs to compute and return multiple related values, you must flatten the data structure. The standard pattern is to return a fixed-size array representing a vector:

// Valid: Returning a fixed-size 3-element vector (compiles to vec3)
gpu.addFunction(function calculateCoordinates(offset) {
  const x = offset * 1.5;
  const y = offset * 2.5;
  const z = 0.0;
  return [x, y, z];
});

// Invalid: Returning an object will cause a compilation error
gpu.addFunction(function getPoint(offset) {
  return { x: offset, y: offset * 2 };
});

To extract values returned by a vector-returning helper function within your kernel, access the indices directly:

const point = calculateCoordinates(this.thread.x);
const xCoord = point[0];
const yCoord = point[1];

By keeping return types restricted to numbers, booleans, or fixed-length 2-to-4 element arrays, your helper functions will compile cleanly and maintain optimal GPU execution performance.
