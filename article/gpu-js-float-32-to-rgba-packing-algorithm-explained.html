GPU.js Float32 to RGBA Packing Algorithm Explained

This article explores the packing algorithm used by gpu.js to encode a 32-bit floating-point number across four 8-bit RGBA channels. Because older WebGL 1.0 implementations often lack support for rendering directly to 32-bit floating-point textures, gpu.js utilizes a mathematical emulation of the IEEE 754 single-precision standard. By dissecting a 32-bit float into its sign, exponent, and mantissa components using standard arithmetic operations, gpu.js can serialize high-precision numerical data into standard 8-bit color components and retrieve it accurately without data loss.

The WebGL 1.0 Precision Challenge

In native WebGL 1.0 environments, fragment shaders write output to a default 32-bit color buffer consisting of four 8-bit channels: Red, Green, Blue, and Alpha (RGBA). Without extensions such as OES_texture_float and render-to-float capabilities, GPUs cannot natively store raw float32 values in textures. Furthermore, GLSL ES 1.0 lacks native bitwise integer operators (such as bit-shifts >> or bitwise-AND &), preventing straightforward binary manipulation.

To overcome this constraint, gpu.js implements an IEEE 754 bit-packing algorithm entirely through floating-point arithmetic (log2, floor, fract, and mod).

The IEEE 754 Deconstruction Algorithm

The single-precision IEEE 754 standard defines a 32-bit float using three distinct segments:

  • Sign (1 bit): Indicates positive (0) or negative (1).
  • Exponent (8 bits): Biased by 127, ranging effectively from -126 to +127.
  • Mantissa / Fraction (23 bits): Represents the normalized fractional precision.

The gpu.js packing algorithm processes an arbitrary input float value through the following mathematical steps:

1. Handling Zero and Extremes

If the input value is zero, the algorithm immediately outputs vec4(0.0, 0.0, 0.0, 0.0). Special handling is applied to infinities and NaN values using predefined sentinel patterns.

2. Extracting Sign and Exponent

For non-zero values, the algorithm determines the sign and isolates the absolute value:

  • The sign bit is 1.0 if value < 0.0, otherwise 0.0.
  • The exponent is computed using the base-2 logarithm: floor(log2(abs(value))).
  • The algorithm adds the IEEE 754 bias of 127 to the exponent: biasedExponent = exponent + 127.0.

3. Calculating the 23-bit Mantissa

Once the exponent is removed, the remaining significand falls in the range [1.0, 2.0). The algorithm subtracts the implicit leading 1 to leave the fractional mantissa:

  • mantissa = (abs(value) / exp2(exponent)) - 1.0.
  • The mantissa is scaled across 23 bits by multiplying by \(2^{23}\) (8,388,608.0).

4. Distributing Across Four 8-Bit Bytes

The combined 32 bits (1 sign bit + 8 exponent bits + 23 mantissa bits) are mapped into four distinct 8-bit integers (\(B_0, B_1, B_2, B_3\)) using modulo and division arithmetic:

  • Byte 0 (R): Holds the sign bit (shifted into bit 7) combined with the upper 7 bits of the biased exponent.
  • Byte 1 (G): Holds the least significant bit of the biased exponent (shifted into bit 7) combined with the upper 7 bits of the mantissa.
  • Byte 2 (B): Holds the middle 8 bits of the mantissa.
  • Byte 3 (A): Holds the lowest 8 bits of the mantissa.

5. Normalization to RGBA

Because WebGL framebuffers expect normalized color values in the range [0.0, 1.0], each computed byte is divided by 255.0 before being assigned to gl_FragColor:

\[\text{gl\_FragColor} = \text{vec4}\left(\frac{B_0}{255.0}, \frac{B_1}{255.0}, \frac{B_2}{255.0}, \frac{B_3}{255.0}\right)\]

Unpacking the Value

When reading the texture back to the CPU via gl.readPixels, the 4-byte Uint8Array sequence directly maps to the binary layout of a standard JavaScript Float32Array. By creating a Float32Array view over the underlying ArrayBuffer containing the pixels, the encoded bytes are instantly reinterpreted as native 32-bit floating-point numbers without requiring costly manual decompression on the CPU.
