Render Flow-Field Particle Trails with GPU.js

This article explains how to efficiently render massive flow-field particle trails for wind and ocean current visualizations in the browser using GPU.js. It covers representing vector fields and particle states in GPU memory, writing compute kernels to advect particles according to velocity vectors, and using texture persistence techniques to draw fading trails without overwhelming system memory.

Vector Field Representation

To simulate wind or ocean currents, you need a vector field defining velocity components—typically horizontal (\(u\)) and vertical (\(v\)) directions. In GPU.js, store this field in flat arrays or 2D textures representing a regular grid. For a grid of width \(W\) and height \(H\), the components can be stored as two separate arrays or packed into a single array where indices alternate between \(u\) and \(v\).

const gridWidth = 512;
const gridHeight = 256;
const uVelocities = new Float32Array(gridWidth * gridHeight);
const vVelocities = new Float32Array(gridWidth * gridHeight);

Managing Particle States

Simulating tens or hundreds of thousands of particles requires keeping particle state minimal. Each particle needs only four values: current \(X\) coordinate, current \(Y\) coordinate, current age, and maximum lifespan.

Group particles into parallel typed arrays or pass them as structured 2D arrays to GPU.js. Lifespan is critical for visual continuity: when a particle's age exceeds its limit, or when it leaves the canvas bounds, reset it to a random position on the grid.

Creating the Advection Kernel

Particle movement is calculated using advection. In each frame, a GPU.js kernel takes the current particle coordinates, looks up the corresponding velocity in the vector field, and updates the coordinates.

Bilinear interpolation should be implemented inside the kernel to smoothly blend velocities between grid cells, preventing stepped or jittery movement:

const gpu = new GPU();

const updateParticles = gpu.createKernel(function(particles, uGrid, vGrid, gridW, gridH, speedScale) {
    const i = this.thread.x;
    let x = particles[i][0];
    let y = particles[i][1];
    let age = particles[i][2];
    const maxAge = particles[i][3];

    // Compute grid cell coordinates
    const gx = Math.floor(x);
    const gy = Math.floor(y);

    if (x < 0 || x >= gridW - 1 || y < 0 || y >= gridH - 1 || age >= maxAge) {
        // Respawn particle using thread-based pseudo-random coordinates
        x = (Math.sin(i + age) * 0.5 + 0.5) * (gridW - 1);
        y = (Math.cos(i + age) * 0.5 + 0.5) * (gridH - 1);
        age = 0;
    } else {
        const index = gy * gridW + gx;
        const u = uGrid[index];
        const v = vGrid[index];

        x += u * speedScale;
        y += v * speedScale;
        age += 1;
    }

    return [x, y, age, maxAge];
}).setOutput([particleCount]);

Rendering Trails with Framebuffer Persistence

Storing the historical positions of 100,000 particles across 30 to 60 frames in memory is prohibitive. Instead, generate trails visually using a screen-space persistence technique:

  1. Draw Current Particles: Render the updated particle positions as individual pixels or short lines onto an HTML5 2D canvas or a WebGL framebuffer.
  2. Apply Trail Decay: Before drawing the new particle positions, apply a semi-transparent full-screen quad or global alpha composite over the existing canvas using globalCompositeOperation = 'destination-in' or a fade-out rectangle (fillStyle = 'rgba(0, 0, 0, 0.96)').
  3. Persist the Frame: By drawing on top of the previously decayed frame, older positions gradually fade out into the background, creating smooth, continuous, and memory-efficient trails.
// Fade existing canvas content slightly
ctx.fillStyle = 'rgba(0, 0, 0, 0.95)';
ctx.fillRect(0, 0, canvas.width, canvas.height);

// Draw updated particles
ctx.fillStyle = '#4fa3e3';
for (let i = 0; i < particleCount; i++) {
    const p = updatedParticles[i];
    ctx.fillRect(p[0], p[1], 1.5, 1.5);
}

Optimization Strategies

  • Keep Data on the GPU: When chaining multiple simulation passes, configure GPU.js kernels with pipeline: true. This keeps output data in GPU texture memory, bypassing the performance bottleneck of transferring Float32 arrays back to the CPU each frame.
  • Canvas Direct Rendering: If maximum throughput is needed, configure the GPU.js kernel with graphical: true. This allows the kernel to output directly to the canvas context using this.color(r, g, b, a), entirely skipping CPU memory round-trips.
  • Vector Field Normalization: Pre-normalize velocity components on data load so the GPU kernel only performs minimal scaling operations per frame.
