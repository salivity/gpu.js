Implementing Granular Synthesis in GPU.js

Granular synthesis deconstructs audio into microscopic acoustic fragments called grains, typically between 10 and 100 milliseconds long, and recombines them into dense, evolving soundscapes. Implementing granular synthesis using gpu.js leverages the massive parallel processing power of the GPU via WebGL shaders, allowing you to compute thousands of overlapping grains in real time without choking the main JavaScript audio thread. This guide demonstrates how to structure audio buffers, handle dynamic grain positioning, apply analytical window envelopes, and sum overlapping grains using a parallel "gather" architecture in gpu.js.

The Gather Architecture for GPU Audio

Traditional CPU-based granular synthesizers use a "scatter" model where each grain independently writes its values into an output buffer. On a GPU, multiple threads writing to the same memory address creates race conditions, and gpu.js does not support atomic floating-point additions.

To overcome this limitation, you must invert the synthesis architecture to a "gather" model:

  • Every GPU thread corresponds to a single output sample.
  • Each thread inspects all currently active grains.
  • If a grain spans the thread's sample index, the thread calculates the grain's read position in the source audio, computes the window attenuation, and adds the result to an accumulator.

1. Structuring Grain and Audio Data

The source audio is passed as a 1D array of floats (normalized between -1.0 and 1.0). Each grain requires four key parameters:

  1. Spawn Time (\(S\)): The output sample index where the grain starts.
  2. Grain Length (\(L\)): The total duration of the grain in samples.
  3. Source Offset (\(O\)): The starting sample position within the source audio buffer.
  4. Playback Rate (\(R\)): The speed and pitch modifier (1.0 = normal, 2.0 = octave up, 0.5 = octave down).

Because passing structured objects to GPU kernels can introduce serialization overhead, pack grain data into flat parallel arrays or a 2D array.

const maxGrains = 512;
const grainSpawnTimes = new Float32Array(maxGrains);
const grainLengths = new Float32Array(maxGrains);
const grainSourceOffsets = new Float32Array(maxGrains);
const grainPlaybackRates = new Float32Array(maxGrains);

2. Grain Positioning Logic

For any given output sample \(n\), a grain is active if \(n \ge S\) and \(n < S + L\).

The relative sample progress of the grain is:

\[\text{grainIndex} = n - S\]

The read position inside the source audio buffer is calculated by scaling the progress by the playback rate:

\[\text{sourceIndex} = \lfloor O + (\text{grainIndex} \times R) \rfloor\]

If sourceIndex exceeds the length of the source buffer, it can be clamped or wrapped using modulo operations to prevent out-of-bounds reading.

3. Envelope Shaping (Windowing)

Without windowing, grains produce audible clicks at their boundaries due to phase discontinuities. An analytical Hann (cosine-squared) window is ideal for GPU kernels because it avoids extra texture lookups:

\[w(t) = 0.5 \times \left(1.0 - \cos\left(\frac{2\pi \times \text{grainIndex}}{L - 1}\right)\right)\]

This function outputs 0.0 at the start, ramps to 1.0 at the midpoint, and returns to 0.0 at the grain's termination.

4. Kernel Implementation in GPU.js

The following gpu.js kernel implements positioning, Hann envelope calculation, and overlapping accumulation.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Function to synthesize a block of samples
const granularKernel = gpu.createKernel(function(
  sourceAudio,
  sourceLength,
  spawnTimes,
  lengths,
  offsets,
  rates,
  activeGrainCount,
  bufferStartSample
) {
  // Current global output sample index
  const currentSample = bufferStartSample + this.thread.x;
  let accumulatedSample = 0.0;
  const PI = 3.141592653589793;

  for (let i = 0; i < 512; i++) {
    if (i < activeGrainCount) {
      const spawn = spawnTimes[i];
      const length = lengths[i];

      // Check if grain overlaps the current output sample
      if (currentSample >= spawn && currentSample < spawn + length) {
        const grainPhase = currentSample - spawn;
        
        // 1. Positioning
        const rate = rates[i];
        const offset = offsets[i];
        let readPos = Math.floor(offset + (grainPhase * rate));
        readPos = readPos % sourceLength;
        if (readPos < 0) readPos += sourceLength;

        const rawSample = sourceAudio[readPos];

        // 2. Envelope Shaping (Hann Window)
        const envelope = 0.5 * (1.0 - Math.cos((2.0 * PI * grainPhase) / (length - 1.0)));

        // 3. Overlapping: sum weighted sample
        accumulatedSample += rawSample * envelope;
      }
    }
  }

  return accumulatedSample;
})
.setOutput([512]); // Generates 512 samples per call (e.g., matching Web Audio block sizes)

5. Integrating with Real-Time Audio Output

To pipe the generated audio back into the Web Audio API:

  1. Instantiate an AudioWorkletNode or a ScriptProcessorNode to drive audio playback.
  2. Maintain a ring buffer of active grains on the CPU.
  3. Every time an audio frame requests new data, pass the current sample counter via bufferStartSample.
  4. Run granularKernel(...) to receive an array of samples.
  5. Copy the kernel output into the audio context's output channel buffer.

Performance Considerations

  • Grain Limit Capping: GPUs require static loop boundaries. Set a fixed maximum (e.g., 512 in the for loop) and break or guard using the dynamic activeGrainCount.
  • Interpolation: For high-quality pitch transposition without aliasing, replace nearest-neighbor rounding (Math.floor) with linear interpolation between sourceAudio[readPos] and sourceAudio[readPos + 1].
  • Output Normalization: Because many overlapping grains can cause amplitude clipping, divide accumulatedSample by a gain factor proportional to the average grain density.
