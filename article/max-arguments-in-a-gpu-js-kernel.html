Max Arguments in a GPU.js Kernel

GPU.js allows developers to accelerate JavaScript operations by compiling functions into WebGL shaders that run on the GPU. While GPU.js does not enforce a strict, hardcoded limit on the number of arguments a kernel function can accept, the actual maximum is strictly bound by underlying WebGL specifications and GPU hardware constraints. This article explains how texture units and uniform vector limits determine the maximum parameter count for GPU.js kernels.

The Deciding Factors: Textures vs. Uniforms

Because GPU.js converts JavaScript functions into WebGL GLSL shaders, the type of arguments you supply directly determines how they are handled at the graphics hardware level.

1. Array and Matrix Arguments (Texture Units)

When you pass arrays or matrices into a GPU.js kernel, they are uploaded to the GPU as textures. The hardware limit for this is governed by the WebGL parameter MAX_TEXTURE_IMAGE_UNITS (or MAX_COMBINED_TEXTURE_IMAGE_UNITS).

  • On most modern desktop GPUs, this limit is typically 16 to 32 units.
  • On mobile devices or integrated graphics, the limit can be as low as 8 to 16 units.
  • GPU.js uses some texture bindings internally for rendering and output buffers.

Consequently, you generally cannot pass more than 16 to 32 array-based arguments into a single kernel without encountering WebGL texture binding errors.

2. Primitive Arguments (Uniform Vectors)

When you pass primitive values—such as numbers, floats, or booleans—GPU.js injects them into the compiled shader as uniforms. The maximum number of uniforms is determined by MAX_FRAGMENT_UNIFORM_VECTORS.

  • In WebGL 1 and 2, this limit is usually between 256 and 1024 uniform vectors depending on the hardware.
  • Each scalar float occupies a vector slot or a portion of one.
  • GPU.js reserves several uniforms to manage internal state (such as thread dimensions, output bounds, and loop variables).

Therefore, you can pass several hundred scalar primitive arguments before exhausting the available uniform memory.

JavaScript Function Call Limits

At the JavaScript engine level (such as V8 in Chrome and Node.js), functions can technically define up to 65,535 arguments. However, in GPU.js, hardware-level WebGL limitations will always be reached long before standard JavaScript execution limits become an issue.

Practical Workarounds for Parameter Limits

If your application exceeds these constraints, consider the following strategies:

  • Pack Multiple Arrays: Combine multiple separate arrays into a single multidimensional array or combine numeric channels (e.g., using RGBA vectors) so that multiple data streams consume only a single texture unit.
  • Pack Scalar Values: Pack multiple floating-point values into flattened 1D arrays or upload them inside a lookup texture rather than passing dozens of discrete scalar parameters.
