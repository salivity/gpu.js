GPU.js Pressure Projection for Fluid Simulation

Enforcing mass conservation and a zero-divergence velocity field in incompressible fluid simulations relies on the Chorin pressure-projection method. In a Eulerian grid, an intermediate velocity field computed after advection and external forces often violates incompressibility (\(\nabla \cdot \mathbf{u} \neq 0\)). By formulating and solving a Poisson pressure equation, the divergent component of the velocity field is calculated and subsequently subtracted. This article explains how to translate this mathematical projection into parallelized GPU compute kernels using gpu.js via divergence computation, Jacobi iteration, and gradient subtraction.

Mathematical Foundation of Pressure Projection

The Helmholtz-Hodge decomposition states that any vector field can be uniquely resolved into a divergence-free component and a curl-free (gradient of a scalar) component:

\[\mathbf{w} = \mathbf{u} + \nabla p\]

Where:

  • \(\mathbf{w}\) is the non-divergence-free intermediate velocity field.
  • \(\mathbf{u}\) is the divergence-free velocity field (\(\nabla \cdot \mathbf{u} = 0\)).
  • \(p\) is the scalar pressure field.

Taking the divergence of both sides yields the Poisson equation for pressure:

\[\nabla^2 p = \nabla \cdot \mathbf{w}\]

Once \(p\) is solved, the final divergence-free velocity is recovered by subtracting the pressure gradient:

\[\mathbf{u} = \mathbf{w} - \nabla p\]

Step 1: Compute Divergence Kernel

The first step evaluates the divergence field across the discrete 2D grid. Central differences are applied to determine how much fluid is entering or leaving each cell.

const computeDivergence = gpu.createKernel(function(velocity, dx) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Handle boundaries with zero-velocity assumption or clamp
    const left   = (x > 0) ? velocity[y][x - 1][0] : -velocity[y][x][0];
    const right  = (x < this.constants.width - 1) ? velocity[y][x + 1][0] : -velocity[y][x][0];
    const bottom = (y > 0) ? velocity[y - 1][x][1] : -velocity[y][x][1];
    const top    = (y < this.constants.height - 1) ? velocity[y + 1][x][1] : -velocity[y][x][1];

    // Divergence: (du/dx + dv/dy)
    return 0.5 * ((right - left) + (top - bottom)) / dx;
})
.setConstants({ width: N, height: N })
.setOutput([N, N])
.setPipeline(true);

Step 2: Solve the Pressure Poisson Equation

The Poisson equation (\(\nabla^2 p = \text{div}\)) forms a sparse linear system. While conjugate gradient methods converge in fewer iterations, the Jacobi iterative method maps efficiently to GPU architectures because each cell updates simultaneously based exclusively on neighbor values from the previous iteration.

The discrete Laplacian update rule is:

\[p^{k+1}_{i,j} = \frac{p^k_{i+1,j} + p^k_{i-1,j} + p^k_{i,j+1} + p^k_{i,j-1} - (\Delta x^2) \cdot \text{div}_{i,j}}{4}\]

In gpu.js, this requires a kernel executed over multiple iterations (typically 20 to 80 iterations for visual plausibility). Neumann boundary conditions (\(\frac{\partial p}{\partial n} = 0\)) are enforced at the edges so fluid does not artificially escape the domain.

const solveJacobi = gpu.createKernel(function(pressure, divergence, dx) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Neumann boundary conditions: copy neighboring pressure at borders
    const pL = (x > 0) ? pressure[y][x - 1] : pressure[y][x];
    const pR = (x < this.constants.width - 1) ? pressure[y][x + 1] : pressure[y][x];
    const pB = (y > 0) ? pressure[y - 1][x] : pressure[y][x];
    const pT = (y < this.constants.height - 1) ? pressure[y + 1][x] : pressure[y][x];

    const div = divergence[y][x];

    return (pL + pR + pB + pT - (div * dx * dx)) * 0.25;
})
.setConstants({ width: N, height: N })
.setOutput([N, N])
.setPipeline(true);

To execute this without memory read/write race conditions, alternate the input and output textures using ping-pong buffering between two allocated pressure buffers:

let pIn = initialPressureTexture;
let pOut = alternatePressureTexture;

for (let i = 0; i < 40; i++) {
    pOut = solveJacobi(pIn, divergenceTexture, dx);
    // Swap references for next iteration
    const temp = pIn;
    pIn = pOut;
    pOut = temp;
}

Step 3: Gradient Subtraction Kernel

After calculating the pressure field, its spatial gradient \(\nabla p\) is subtracted from the intermediate velocity \(\mathbf{w}\) to yield the mass-conserving velocity field \(\mathbf{u}\).

const projectVelocity = gpu.createKernel(function(velocity, pressure, dx) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Enforce boundary clamping on pressure field
    const pL = (x > 0) ? pressure[y][x - 1] : pressure[y][x];
    const pR = (x < this.constants.width - 1) ? pressure[y][x + 1] : pressure[y][x];
    const pB = (y > 0) ? pressure[y - 1][x] : pressure[y][x];
    const pT = (y < this.constants.height - 1) ? pressure[y + 1][x] : pressure[y][x];

    // Compute central difference gradient
    const gradX = 0.5 * (pR - pL) / dx;
    const gradY = 0.5 * (pT - pB) / dx;

    const u = velocity[y][x][0] - gradX;
    const v = velocity[y][x][1] - gradY;

    return [u, v];
})
.setConstants({ width: N, height: N })
.setOutput([N, N]);

Critical GPU.js Considerations

  1. Pipeline Mode: Use .setPipeline(true) across intermediate steps. This prevents the GPU from reading back textures to CPU memory between the divergence, Jacobi, and gradient subtraction steps, maintaining full VRAM residency.
  2. Floating-Point Precision: Pressure solves require high dynamic range. Ensure gpu.js operates with 32-bit float textures enabled (precision: 'single') in your initialization parameters, as the default half-precision or packed integers will introduce accumulation drift and compromise mass conservation.
  3. Boundary Enforcements: Discrepancies between boundary checks in the divergence step and the gradient subtraction step can artificially introduce divergence at domain borders. Ensure both stages mirror identical solid-wall or periodic boundary conditions.
