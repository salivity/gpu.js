Inspect gpu.js AST Before GLSL Conversion

Developers can inspect the intermediate abstract syntax tree (AST) generated by gpu.js prior to its compilation into WebGL GLSL shaders. While gpu.js is primarily designed to handle parsing and shader translation automatically behind the scenes, its internal architecture parses JavaScript functions into standard AST structures before generating shader code. By accessing internal kernel properties or utilizing underlying parsing utilities, developers can retrieve and examine this intermediate representation for debugging and optimization purposes.

To translate JavaScript into GLSL, gpu.js parses the input kernel function into an AST using an embedded JavaScript parser. Once the AST is formed, the compiler traverses these nodes, validates that only supported operations are used, and translates the operations into equivalent GLSL code. Because this AST is maintained during the lifecycle of the kernel object, it is accessible to developers who want to inspect how their JavaScript is interpreted before shader generation completes.

The most direct way to inspect the AST is through the instantiated kernel object. When you create a kernel with gpu.createKernel(function() { ... }), the internal representation parses your function and attaches the AST to the kernel instance. Developers can inspect properties such as kernel.ast directly via console.log(kernel.ast). If the kernel has already compiled or if you are debugging a failure during the GLSL conversion phase, this property retains the JSON-compatible tree structure of the parsed function.

Alternatively, developers can invoke internal parsing methods directly. gpu.js exposes or packages internal parser helpers that accept raw JavaScript functions and output the AST representation without executing the full WebGL context or running the shader generation pipeline. By passing a function directly into these parser modules, you can isolate the syntax tree representation from any environment-specific GPU constraints.

Inspecting the AST is particularly valuable when diagnosing compilation errors. Certain JavaScript features—such as non-numeric arrays, complex object manipulations, or unsupported native functions—cannot be converted into GLSL. Reviewing the intermediate AST allows developers to verify the exact node types being generated, identify the exact location of syntax mismatches, and see how variables are scoped before the compiler attempts to output the final GLSL shader source code.
