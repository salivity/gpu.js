Ray Marching Mandelbulb Fractals in gpu.js

This article explains how to implement ray marching and distance estimation for 3D fractals like the Mandelbulb using gpu.js. By executing mathematical computations directly on the GPU through WebGL shaders, developers can render complex, procedural 3D fractals within the browser. The following sections break down the Mandelbulb distance estimator formula, map the sphere-tracing algorithm to the gpu.js computing model, and provide an implementation example.

Understanding the Mandelbulb Distance Estimator

Ray marching non-Euclidean surfaces requires a Distance Estimator (DE), a function that returns an approximation of the shortest distance from a given point in 3D space to the fractal surface.

The standard Mandelbulb is defined in spherical coordinates using power \(n\) (commonly \(n = 8\)). For a point \(\mathbf{c} = (x_0, y_0, z_0)\), the system iterates:

\[\mathbf{v}_{k+1} = \mathbf{v}_k^n + \mathbf{c}\]

Alongside tracking the vector coordinates, the running derivative \(dr\) must be calculated to approximate the scale factor for the distance estimator:

\[dr_{k+1} = |\mathbf{v}_k|^{n-1} \cdot n \cdot dr_k + 1.0\]

Once the vector escapes a threshold radius (typically \(r > 2.0\)) or reaches the maximum iteration limit, the estimated distance \(d\) is computed as:

\[d = 0.5 \cdot \frac{\ln(r) \cdot r}{dr}\]

Designing the Algorithm for gpu.js

gpu.js compiles JavaScript functions into WebGL fragment shaders. Because it operates on a restricted subset of JavaScript, certain architectural rules apply:

  1. No Dynamic Objects: Vector structures like custom Vector3 classes cannot be instantiated dynamically inside the kernel. Math must be performed using primitive arrays (e.g., [x, y, z]) or scalar components (x, y, z).
  2. Fixed Loops: Ray marching steps and fractal iterations must use constant iteration counts with early breaks.
  3. Pointers and Inlining: Distance evaluation should either be written directly within the kernel function or declared as a helper function via gpu.addFunction().

Implementation

Below is a complete implementation using gpu.js to render the Mandelbulb via ray marching.

const { GPU } = require('gpu.js'); // or import from window.GPU in browser
const gpu = new GPU();

// 1. Register the Distance Estimator as a GPU function
gpu.addFunction(function mandelbulbDE(px, py, pz) {
  let x = px;
  let y = py;
  let z = pz;
  let dr = 1.0;
  let r = 0.0;
  const power = 8.0;

  for (let i = 0; i < 15; i++) {
    r = Math.sqrt(x * x + y * y + z * z);
    if (r > 2.0) {
      break;
    }

    // Convert Cartesian coordinates to spherical coordinates
    let theta = Math.acos(z / r);
    let phi = Math.atan2(y, x);
    
    // Scale derivative
    dr = Math.pow(r, power - 1.0) * power * dr + 1.0;

    // Scale spherical coordinates
    const zr = Math.pow(r, power);
    theta = theta * power;
    phi = phi * power;

    // Convert back to Cartesian and add offset
    x = zr * Math.sin(theta) * Math.cos(phi) + px;
    y = zr * Math.sin(theta) * Math.sin(phi) + py;
    z = zr * Math.cos(theta) + pz;
  }

  return 0.5 * Math.log(r) * r / dr;
});

// 2. Define the Ray Marching Kernel
const renderMandelbulb = gpu.createKernel(function(width, height, camX, camY, camZ) {
  // Normalize screen coordinates from -1.0 to 1.0
  const u = (this.thread.x / width) * 2.0 - 1.0;
  const v = (this.thread.y / height) * 2.0 - 1.0;

  // Setup ray origin and normalized ray direction
  const roX = camX;
  const roY = camY;
  const roZ = camZ;

  let rdX = u;
  let rdY = v;
  let rdZ = -1.2; // Focal length

  const len = Math.sqrt(rdX * rdX + rdY * rdY + rdZ * rdZ);
  rdX /= len;
  rdY /= len;
  rdZ /= len;

  // Ray Marching loop (Sphere Tracing)
  let totalDist = 0.0;
  const maxDist = 10.0;
  const surfaceThreshold = 0.001;
  let hit = 0.0;
  let stepsTaken = 0;

  for (let i = 0; i < 64; i++) {
    const curX = roX + rdX * totalDist;
    const curY = roY + rdY * totalDist;
    const curZ = roZ + rdZ * totalDist;

    const dist = mandelbulbDE(curX, curY, curZ);

    if (dist < surfaceThreshold) {
      hit = 1.0;
      stepsTaken = i;
      break;
    }

    totalDist += dist;

    if (totalDist > maxDist) {
      break;
    }
  }

  // Shading based on iteration count (Ambient Occlusion approximation)
  if (hit === 1.0) {
    const shade = 1.0 - (stepsTaken / 64.0);
    this.color(shade, shade * 0.8, shade * 0.6, 1.0);
  } else {
    this.color(0.05, 0.05, 0.08, 1.0); // Background color
  }
})
.setOutput([800, 600])
.setGraphical(true);

// 3. Render the output to canvas
renderMandelbulb(800, 600, 0.0, 0.0, 2.5);

// Append the canvas to the DOM if running in a browser environment
document.body.appendChild(renderMandelbulb.canvas);

Optimizations and Enhancements

  1. Step Relaxation: The standard distance estimation can overestimate distances near tight folds, leading to artifacts or missed intersections. Multiplying the stepped distance by an under-relaxation factor (such as dist * 0.75) reduces artifacts at the cost of requiring more iterations.
  2. Surface Normals: Compute analytical or numerical normals using a small offset vector \(\epsilon\) around the intersection point to enable Phong or Blinn-Phong lighting models: \[N = \text{normalize}\left(\begin{matrix} DE(x+\epsilon, y, z) - DE(x-\epsilon, y, z) \\ DE(x, y+\epsilon, z) - DE(x, y-\epsilon, z) \\ DE(x, y, z+\epsilon) - DE(x, y, z-\epsilon) \end{matrix}\right)\]
  3. Bounding Volumes: Prior to executing the distance loop, intersect the ray with an analytical bounding sphere of radius \(2.0\). If the ray misses the bounding sphere entirely, skip the ray marching loop.
