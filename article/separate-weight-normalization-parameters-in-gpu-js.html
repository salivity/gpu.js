Separate Weight Normalization Parameters in gpu.js

This article explains how weight normalization layers can be decoupled into distinct magnitude and direction parameters using gpu.js. It covers the mathematical formulation of weight reparameterization, how to implement the separated components using GPU-accelerated JavaScript kernels, and performance considerations for forward and backward passes.

Weight normalization decouples the length of a weight vector from its direction to accelerate the convergence of stochastic gradient descent. Mathematically, any weight vector \(\mathbf{w}\) is reparameterized as:

\[\mathbf{w} = \frac{g}{\|\mathbf{v}\|} \mathbf{v}\]

where \(\mathbf{v}\) is a parameter vector determining direction, \(\|\mathbf{v}\|\) is its Euclidean norm, and \(g\) is a scalar parameter determining magnitude.

In gpu.js, weight normalization layers can indeed be separated into these magnitude and direction components. Because gpu.js compiles JavaScript functions into GLSL shaders that run on the GPU, you can define custom data buffers and computation kernels to handle \(g\) and \(\mathbf{v}\) independently.

Implementing the Forward Pass

To separate these parameters in gpu.js, you maintain two separate data structures: a 2D array representing the direction tensor \(\mathbf{v}\) (for a dense or convolutional layer) and a 1D array representing the scalar magnitudes \(g\) (one scalar per output neuron or filter).

The forward computation can be implemented in two ways:

  1. Two-Stage Kernel Pipeline: First, a kernel computes the L2 norm of each row or filter vector in \(\mathbf{v}\). A second kernel computes the normalized weight matrix \(\mathbf{w}\) by scaling each element \(v_{ij}\) by \(g_i / \|\mathbf{v}_i\|\). The resulting \(\mathbf{w}\) is then passed into standard matrix multiplication kernels.
  2. Fused Dense Layer Kernel: To reduce GPU memory bandwidth overhead, the normalization step can be fused directly into the layer's forward pass. The kernel takes the input activations \(\mathbf{x}\), the direction tensor \(\mathbf{v}\), and the magnitude array \(g\). For each output node, the kernel calculates the norm \(\|\mathbf{v}\|\), scales the weights on the fly, and computes the dot product with the input features.

Implementing the Backward Pass

During backpropagation, gradients must be split between the direction parameter \(\mathbf{v}\) and the magnitude parameter \(g\). In gpu.js, this requires writing dedicated backward kernels based on the chain rule:

  • Gradient with respect to \(g\): Computed by projecting the incoming weight gradient \(\nabla_{\mathbf{w}} L\) onto the normalized direction vector: \[\nabla_g L = \frac{\nabla_{\mathbf{w}} L \cdot \mathbf{v}}{\|\mathbf{v}\|}\]
  • Gradient with respect to \(\mathbf{v}\): Computed by scaling and projecting out the parallel component: \[\nabla_{\mathbf{v}} L = \frac{g}{\|\mathbf{v}\|} \left( \nabla_{\mathbf{w}} L - \frac{\nabla_g L}{\|\mathbf{v}\|} \mathbf{v} \right)\]

Because gpu.js supports outputting arrays and multi-dimensional textures, these gradient formulas can be translated directly into GLSL-compatible arithmetic operations across parallel threads.

Technical Considerations in gpu.js

  • Numerical Stability: A small epsilon value (e.g., \(10^{-7}\)) must be added inside the square root when computing \(\|\mathbf{v}\| = \sqrt{\sum v_i^2 + \epsilon}\) to prevent division by zero during GPU execution.
  • Floating-Point Precision: Standard WebGL contexts in gpu.js often default to 16-bit or 32-bit floats depending on hardware support. Ensure that 32-bit floating-point textures are enabled (precision: 'single') to prevent precision loss when calculating norms and gradients.
  • Pipeline Overhead: Decoupling the parameters increases the total number of kernel invocations if not fused. For maximum throughput in gpu.js, keep the intermediate tensors on the GPU by setting pipeline: true on the kernels, avoiding costly readbacks to the CPU.
