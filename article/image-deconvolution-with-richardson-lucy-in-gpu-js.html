Image Deconvolution with Richardson-Lucy in GPU.js

Image deconvolution using the Richardson-Lucy iterative algorithm can be effectively implemented in JavaScript using gpu.js. By translating the mathematical pipeline—consisting of spatial 2D convolutions, element-wise array divisions, and element-wise multiplications—into WebGL-accelerated kernels, gpu.js allows developers to execute computationally demanding image restoration tasks directly on the GPU within a browser or Node.js environment.

The Richardson-Lucy Algorithm Overview

The Richardson-Lucy (RL) algorithm is an iterative technique designed to recover an underlying latent image that has been degraded by a known Point Spread Function (PSF) and Poisson noise. The update formula for iteration \(t+1\) is defined mathematically as:

\[I_{t+1} = I_t \odot \left( \frac{Y}{I_t * P} * P^* \right)\]

Where:

  • \(I_t\) represents the estimated image at iteration \(t\).
  • \(Y\) is the observed blurry image.
  • \(P\) is the known Point Spread Function.
  • \(P^*\) is the flipped (adjoint) Point Spread Function.
  • \(*\) denotes a 2D convolution operation.
  • \(\odot\) denotes element-wise multiplication.
  • The fraction denotes element-wise division.

Implementing the Steps in gpu.js

Because gpu.js compiles JavaScript functions into GLSL shaders that run on GPU textures, the algorithm must be broken into discrete kernel functions.

1. 2D Convolution Kernel

Convolution is the heaviest computational component. In gpu.js, a 2D spatial convolution kernel slides the PSF matrix over the image matrix:

  • The kernel iterates over the local neighborhood of each pixel using the dimensions of the PSF.
  • Two convolution functions are needed (or one reusable parameterized function): forward convolution with \(P\) and backward convolution with the mirrored PSF \(P^*\).

2. Element-Wise Division Kernel

Once the current estimate is convolved with \(P\), the observed image \(Y\) is divided by this blurred estimate. In gpu.js, this is a lightweight kernel mapping directly over pixel coordinates (this.thread.x, this.thread.y) that calculates Y[y][x] / blurredEstimate[y][x]. A small epsilon value should be added to the denominator to prevent division-by-zero errors in dark regions.

3. Element-Wise Multiplication Kernel

The result of the backward convolution is multiplied by the current estimate \(I_t\). Another basic gpu.js kernel takes the correction factor texture and multiplies it by the previous iteration's texture to produce \(I_{t+1}\).

Optimization and Pipelining

Running dozens of iterations can create significant memory overhead if data is constantly transferred between CPU and GPU memory. To ensure high performance:

  • Use Kernel Pipelining: Configure all gpu.js kernels with pipeline: true. This keeps textures stored inside WebGL framebuffers on the GPU across all iterations, eliminating the overhead of transferring data back to JavaScript arrays until the final iteration completes.
  • Float Texture Support: Richardson-Lucy calculations require floating-point precision to prevent truncation artifacts. Ensure float textures are enabled in the gpu.js initialization settings.
  • Kernel Size Limits: Direct spatial convolution in gpu.js is \(O(N^2 \cdot K^2)\) where \(N\) is image dimension and \(K\) is PSF dimension. This spatial approach works exceptionally well for small to moderate PSF kernels (e.g., up to \(15 \times 15\) or \(31 \times 31\)). For very large blur kernels, a Fast Fourier Transform (FFT) approach is mathematically superior, though implementing full 2D FFTs natively in gpu.js requires custom butterfly network kernels.

Practical Conclusion

Performing Richardson-Lucy deconvolution in gpu.js is entirely feasible and delivers significant speedups over CPU-bound JavaScript loops. By chaining spatial convolution, division, and multiplication kernels using pipeline mode, real-time or near-real-time optical restoration can be achieved entirely client-side.
