What Object Does a GPU.js Pipeline Kernel Return?

When pipelining is enabled on a GPU.js kernel, the execution returns an internal Texture object rather than a standard JavaScript array or typed array. This article explains the exact nature of this returned Texture object, why GPU.js uses it in pipeline mode, and how to work with it or extract standard array data when computation finishes.

The Pipeline Return Object: Texture

In standard GPU.js execution, a kernel calculates results on the GPU and immediately reads the output back to the CPU, returning either a standard multi-dimensional array or a Float32Array.

When you enable pipelining using .setPipeline(true), the kernel skips this expensive readback step. Instead, it returns a GPU.js Texture instance. This object wraps an underlying WebGL texture that remains allocated directly inside GPU VRAM.

Why GPU.js Returns a Texture

Reading data from the GPU back to the CPU requires WebGL calls like readPixels, which stall the GPU pipeline and introduce significant latency.

By returning a Texture object:

  • Memory stays on the GPU: Intermediate calculation results never transfer across the system bus to the CPU.
  • Direct kernel chaining: You can pass the returned Texture directly as an argument into another pipeline-enabled or standard GPU.js kernel. The subsequent kernel samples the texture directly in GPU memory, resulting in massive performance gains for multi-step algorithms.

How to Extract Data from the Texture

Because the returned object is a Texture and not an array, you cannot read individual elements using standard array index notation like result[0].

To retrieve standard JavaScript data from the pipeline-returned Texture, use its built-in conversion method:

const textureResult = pipelineKernel(inputData);
const standardArray = textureResult.toArray();

Calling .toArray() triggers the delayed readback process, pulling the data from GPU memory and converting it into a standard nested JavaScript array (or typed array, depending on your kernel configuration). You should typically only call .toArray() on the final kernel output of your processing chain to preserve pipeline performance.
