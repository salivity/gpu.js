Supply a Custom WebGL Context to GPU.js

This article explains how to pass an existing, custom WebGL context directly into the GPU.js constructor. By using the constructor's configuration options, you can integrate GPU.js computations into existing rendering pipelines, share a single WebGL context across multiple libraries, or run accelerated calculations within headless environments using Node.js.

The Constructor Configuration

By default, GPU.js automatically creates its own off-screen <canvas> element and initializes a WebGL context internally. However, the GPU constructor accepts an options object containing the context property, which lets you override the default context creation.

The constructor signature accepts:

const gpu = new GPU({
  context: customWebGLContext
});

The customWebGLContext can be either a WebGLRenderingContext (WebGL 1) or a WebGL2RenderingContext (WebGL 2).

Browser Implementation

To supply your own context in a browser environment, obtain the WebGL context from an existing HTML <canvas> element and pass it to the constructor:

// 1. Create or retrieve an existing canvas element
const canvas = document.getElementById('my-canvas') || document.createElement('canvas');

// 2. Request a WebGL 2 or WebGL 1 context
const gl = canvas.getContext('webgl2') || canvas.getContext('webgl');

if (!gl) {
  throw new Error('WebGL is not supported in this browser.');
}

// 3. Pass the custom context directly into GPU.js
const gpu = new GPU({
  context: gl,
  canvas: canvas // Optional: pass the associated canvas if needed
});

// 4. Create and run your kernel as usual
const kernel = gpu.createKernel(function() {
  return this.thread.x * 2;
}).setOutput([5]);

console.log(kernel()); // Output: Float32Array [0, 2, 4, 6, 8]

Headless / Server-Side Implementation (Node.js)

In a Node.js environment without a DOM, you can supply a headless WebGL context using packages like gl. This allows server-side operations to utilize GPU acceleration:

const createHeadlessContext = require('gl');
const { GPU } = require('gpu.js');

// Initialize a headless WebGL context with defined dimensions
const width = 512;
const height = 512;
const headlessGl = createHeadlessContext(width, height);

// Supply the headless context to the GPU constructor
const gpu = new GPU({
  context: headlessGl
});

const kernel = gpu.createKernel(function(a, b) {
  return a[this.thread.x] + b[this.thread.x];
}).setOutput([4]);

console.log(kernel([1, 2, 3, 4], [5, 6, 7, 8]));

Important Considerations

  • Context Loss and State Mutation: GPU.js modifies WebGL state (binds textures, framebuffers, and shaders) during kernel compilation and execution. If you share this context with a renderer like Three.js or PixiJS, remember to reset or synchronize the state between draw calls to prevent rendering artifacts.
  • Feature Support: Supplying a WebGL 1 context limits GPU.js to WebGL 1 capabilities, disabling features that depend on WebGL 2 (such as integer math precision and specific texture formats). Where possible, prioritize passing a webgl2 context.
  • Canvas Association: If you provide a custom context, GPU.js infers the underlying canvas from gl.canvas. If your context is unbound or headless, passing canvas explicitly in the options object is recommended to avoid reference errors in internal routines.
