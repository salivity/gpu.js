Tone Mapping with GPU.js: Reinhard and ACES

Tone-mapping algorithms like Reinhard and ACES filmic curves can be efficiently applied in the browser using gpu.js. Because tone mapping is an embarrassingly parallel, per-pixel operation, gpu.js compiles written JavaScript math into WebGL fragment shaders that run directly on the GPU. This guide explains how tone mapping functions in gpu.js and provides direct implementations for both standard Reinhard and the ACES filmic curve approximation.

How Tone Mapping Works in GPU.js

Tone mapping transforms High Dynamic Range (HDR) color values—where pixel luminosities can exceed standard bounds (\(> 1.0\))—into Low Dynamic Range (LDR) values constrained between \(0.0\) and \(1.0\) for display screens.

gpu.js processes 2D data arrays or HTML canvas elements by assigning each pixel evaluation to a GPU thread. By writing the tone-mapping transfer function inside a kernel, each RGB channel is mapped simultaneously across millions of pixels with minimal CPU overhead.

Implementing Reinhard Tone Mapping

The Reinhard tone-mapping curve is one of the simplest luminance compression operators. The basic formula is:

\[\text{Color}_{\text{out}} = \frac{\text{Color}_{\text{in}}}{1.0 + \text{Color}_{\text{in}}}\]

To implement this with gpu.js:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel expects an array of pixels: [width, height, 3]
const reinhardKernel = gpu.createKernel(function(image) {
    const r = image[this.thread.y][this.thread.x][0];
    const g = image[this.thread.y][this.thread.x][1];
    const b = image[this.thread.y][this.thread.x][2];

    const mappedR = r / (1.0 + r);
    const mappedG = g / (1.0 + g);
    const mappedB = b / (1.0 + b);

    this.color(mappedR, mappedG, mappedB, 1.0);
})
.setOutput([width, height])
.setGraphical(true);

reinhardKernel(hdrImageData);

Using .setGraphical(true) outputs the computed values directly to a WebGL canvas using the this.color() method, which automatically clamps output values to the \([0, 1]\) range required by standard framebuffers.

Implementing the ACES Filmic Tone Mapping Curve

The Academy Color Encoding System (ACES) filmic curve provides a more cinematic look than Reinhard by introducing high-contrast "toe" and "shoulder" regions to preserve highlights and deepen shadows.

The widely adopted Krzysztof Narkowicz analytical approximation can be written directly inside a gpu.js kernel:

const acesKernel = gpu.createKernel(function(image) {
    const a = 2.51;
    const b = 0.03;
    const c = 2.43;
    const d = 0.59;
    const e = 0.14;

    const r = image[this.thread.y][this.thread.x][0];
    const g = image[this.thread.y][this.thread.x][1];
    const b = image[this.thread.y][this.thread.x][2];

    // Apply ACES fit: (x * (a * x + b)) / (x * (c * x + d) + e)
    const mappedR = Math.max(0.0, Math.min(1.0, (r * (a * r + b)) / (r * (c * r + d) + e)));
    const mappedG = Math.max(0.0, Math.min(1.0, (g * (a * g + b)) / (g * (c * g + d) + e)));
    const mappedB = Math.max(0.0, Math.min(1.0, (b * (a * b + b)) / (b * (c * b + d) + e)));

    this.color(mappedR, mappedG, mappedB, 1.0);
})
.setOutput([width, height])
.setGraphical(true);

acesKernel(hdrImageData);

Considerations When Using GPU.js for Tone Mapping

  1. Input Precision: To preserve HDR detail before mapping, input data should be fed as 32-bit floating-point arrays (Float32Array) rather than 8-bit clamped arrays.
  2. Color Space: Filmic curves like ACES expect linear color inputs. If your source data has gamma correction applied, convert the values to linear space before computing the tone map, or include an inverse gamma function directly within the kernel.
  3. Array vs. Graphical Mode: If the processed values need to be exported as raw numeric data instead of drawn onto a screen, set .setGraphical(false) and return an array of floats instead of calling this.color().
