Understanding optimizeFloatMemory in gpu.js

The optimizeFloatMemory setting in gpu.js is a configuration option designed to significantly reduce Video RAM (VRAM) consumption when processing floating-point arrays on the GPU. By altering how floating-point numbers are packed and stored within WebGL textures, this feature enables applications to process larger datasets without exhausting available graphics memory. This article explains how optimizeFloatMemory works under the hood, its performance implications, and when you should enable it.

How WebGL Textures Handle Floats

Under the hood, gpu.js compiles JavaScript functions into WebGL shaders and uses WebGL textures to hold input and output data. Standard WebGL textures are structured around four color channels per pixel: Red, Green, Blue, and Alpha (RGBA).

When working with floating-point calculations without memory optimization, gpu.js often allocates an entire RGBA pixel to represent a single floating-point number. In many hardware environments, especially those relying on 32-bit floating-point textures (OES_texture_float), this results in underutilized channels and substantial memory overhead, as three out of the four channels may sit empty or consume redundant space.

What optimizeFloatMemory Does

When you set optimizeFloatMemory: true, gpu.js changes its underlying memory allocation strategy by packing multiple float values into the individual channels of a single texture pixel:

  1. 4x Memory Reduction: Instead of mapping one float value to one RGBA pixel, gpu.js packs four distinct floating-point numbers into the R, G, B, and A channels of a single pixel. This reduces the raw texture size required to hold arrays by up to 75%.
  2. Reduced VRAM Allocation: By shrinking texture dimensions, the GPU requires far less dedicated memory to hold large matrices, tensors, and multi-dimensional float arrays.
  3. Prevention of Out-of-Memory Errors: Browsers enforce strict VRAM and texture dimension limits. Packing floats enables you to run substantially larger computational kernels that would otherwise exceed maximum texture size limits or crash the WebGL context.

Performance Trade-offs

While optimizeFloatMemory dramatically lowers memory usage, it introduces trade-offs in execution speed:

  • Bandwidth vs. Computation: Packing four floats per pixel reduces memory bandwidth demands because fewer texture lookups are required to fetch data. On memory-bandwidth-bound tasks, this can actually increase overall throughput.
  • Packing and Unpacking Overhead: Shaders must execute additional instructions to decode (unpack) values when reading from textures and encode (pack) them when writing output. For compute-bound kernels with very light memory footprints, this arithmetic overhead can result in a minor performance penalty.
  • Pipeline Compatibility: When chaining multiple kernels together (pipelining), keeping data packed in memory prevents unnecessary conversions between GPU textures and CPU memory buffers.

How to Enable optimizeFloatMemory

You can enable this setting either globally during the initialization of the GPU instance or locally on a per-kernel basis.

Global Configuration

const gpu = new GPU({
  optimizeFloatMemory: true
});

Kernel-Level Configuration

const kernel = gpu.createKernel(function(a, b) {
  return a[this.thread.x] + b[this.thread.x];
}, {
  output: [1000000],
  optimizeFloatMemory: true
});

When to Use It

Enable optimizeFloatMemory if your application:

  • Processes large floating-point datasets, such as neural networks, image processing pipelines, or massive matrix multiplications.
  • Frequently encounters WebGL context losses or maximum texture size limit errors.
  • Runs on low-end or mobile hardware with strictly constrained GPU memory.

Leave optimizeFloatMemory disabled if your arrays are small, your operations are strictly compute-heavy, and you want to avoid the minor shader overhead required for packing and unpacking texture data.
