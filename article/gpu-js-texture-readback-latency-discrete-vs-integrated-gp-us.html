gpu.js Texture Readback Latency: Discrete vs Integrated GPUs

Texture readback latency in gpu.js refers to the performance bottleneck encountered when transferring computed data from the GPU's memory back to the CPU's JavaScript runtime. Because gpu.js relies on WebGL underneath, converting GPU-resident textures back into JavaScript arrays requires a readback operation that stalls the CPU-GPU pipeline. The latency of this operation differs fundamentally between discrete GPUs (dGPUs) and integrated GPUs (iGPUs) due to their contrasting physical memory architectures, bus interfaces, and synchronization overheads.

The Nature of gpu.js Texture Readback

When executing a kernel in gpu.js, computations output results into an off-screen WebGL framebuffer texture. If your application requires access to this data in JavaScript (for instance, via standard kernel return values rather than leaving the output as a texture), gpu.js invokes gl.readPixels or its WebGPU equivalent.

This invocation forces a synchronous stall: the CPU must halt and wait for the GPU to finish all scheduled commands and flush its rendering pipeline before the pixel data can be serialized and copied back to host memory.

Latency on Integrated GPUs (iGPUs)

Integrated GPUs, such as Intel Iris Xe or AMD Radeon 600M/700M series, share physical system RAM (DDR4, DDR5, or LPDDR5) with the CPU via a Unified Memory Architecture (UMA).

  • Zero PCIe Overhead: Because the CPU and iGPU share physical memory channels, data does not need to cross an external bus like PCIe. The transfer is primarily an internal memory copy or a pointer remapping.
  • Lower Readback Penalty for Small to Medium Payloads: For smaller data arrays, iGPUs frequently exhibit lower raw readback latency than dGPUs because they avoid the communication serialization overhead inherent to an external expansion bus.
  • Bandwidth Limitations: While the physical transfer path is short, standard system RAM has significantly lower bandwidth (typically 40–100 GB/s) compared to dedicated video memory. Consequently, extremely large texture readbacks can suffer from memory contention between the CPU and the integrated graphic cores.

Latency on Discrete GPUs (dGPUs)

Discrete GPUs (such as NVIDIA GeForce/RTX or AMD Radeon RX series) feature dedicated high-bandwidth memory (GDDR6, GDDR6X, or HBM) and communicate with the host system over the PCIe interface.

  • PCIe Bus Latency: Every readback operation requires traversing the PCIe bus. Even across modern PCIe 4.0 or 5.0 lanes, initiating a host transfer introduces fixed latency overheads related to driver commands, bus arbitration, and host-memory mapping.
  • Pipeline Synchronization Stalls: Because dGPUs process instructions asynchronously with high degrees of queueing, issuing a readback command causes a severe pipeline flush. The CPU must idle while the dGPU clears its command queues and serializes the GDDR payload across the PCIe lanes.
  • Throughput vs. Latency Trade-off: While dGPUs possess massive internal memory bandwidth (ranging from 300 GB/s to well over 1000 GB/s) that executes compute kernels significantly faster than an iGPU, the readback latency specifically remains higher for small datasets due to the fixed round-trip time over PCIe.

Performance Comparison Summary

Factor Integrated GPUs (iGPU) Discrete GPUs (dGPU)
Physical Location Same silicon/die as CPU Separate card across PCIe
Memory Architecture Shared System RAM (UMA) Dedicated VRAM (GDDR/HBM)

Mitigating Readback Bottlenecks in gpu.js

Regardless of hardware type, readback is almost always the slowest stage of a WebGL-based compute pipeline. To minimize the performance impact:

  1. Keep Output on the GPU: Use { output: 'texture' } in kernel configurations. Chaining kernels together without reading values back into JavaScript avoids the synchronization stall entirely until the final step.
  2. Batch Transfers: Instead of reading back small results frequently, aggregate calculations into a single texture readback. This amortizes the fixed PCIe or pipeline flush latency across a larger volume of data.
  3. Select Execution Hardware Appropriately: For lightweight, latency-sensitive compute tasks where frequent reads are unavoidable, iGPUs may outperform dGPUs in wall-clock execution time simply by avoiding PCIe round-trip penalties. Conversely, for heavy compute tasks where execution time dwarfs readback costs, dGPUs remain superior.
