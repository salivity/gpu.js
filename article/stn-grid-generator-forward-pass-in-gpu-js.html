STN Grid Generator Forward Pass in GPU.js

Executing the forward pass of a Spatial Transformer Network (STN) grid generator is entirely possible and highly efficient in gpu.js. This article explains how the affine transformation underlying the grid generator maps onto GPU kernels, why gpu.js is well-suited for the task, and how the mathematical operations are structured in a browser or Node.js environment.

Mathematical Foundation of the STN Grid Generator

A Spatial Transformer Network consists of three core components: a localization network, a grid generator, and a sampler. The grid generator creates a sampling grid—a set of points where the input map should be sampled to produce the transformed output.

Given a predicted \(2 \times 3\) affine transformation matrix \(\theta\) from the localization network:

\[ \theta = \begin{bmatrix} \theta_{11} & \theta_{12} & \theta_{13} \\ \theta_{21} & \theta_{22} & \theta_{23} \end{bmatrix} \]

The grid generator maps each target output coordinate \((x_t, y_t)\) to a corresponding source coordinate \((x_s, y_s)\) in normalized space (typically spanning \([-1, 1]\)):

\[ \begin{bmatrix} x_s \\ y_s \end{bmatrix} = \begin{bmatrix} \theta_{11} & \theta_{12} & \theta_{13} \\ \theta_{21} & \theta_{22} & \theta_{23} \end{bmatrix} \begin{bmatrix} x_t \\ y_t \\ 1 \end{bmatrix} \]

This equation expands to:

  • \(x_s = \theta_{11} x_t + \theta_{12} y_t + \theta_{13}\)
  • \(y_s = \theta_{21} x_t + \theta_{22} y_t + \theta_{23}\)

Why GPU.js is Well-Suited

gpu.js compiles specialized JavaScript functions into WebGL shaders (GLSL), allowing them to run on the GPU. The STN grid generation step is an embarrassingly parallel operation: every output coordinate \((x_t, y_t)\) is independent of every other coordinate.

Because each point requires only basic arithmetic (six multiplications and four additions per coordinate pair), GPU kernels can compute thousands of coordinate mappings simultaneously, avoiding the CPU bottlenecks typical of standard JavaScript loops.

Execution Strategy in GPU.js

To implement the forward pass in gpu.js:

  1. Kernel Dimensions: Configure the output dimensions of the kernel to match the target image dimensions \((W, H)\). Since two values \((x_s, y_s)\) are produced per pixel, the output can be structured either as a 3D kernel of dimensions \([2, W, H]\) or as two distinct 2D kernels—one computing \(x_s\) and the other computing \(y_s\).
  2. Coordinate Normalization: Inside the kernel, convert thread indices (this.thread.x and this.thread.y) into normalized coordinates \(x_t, y_t \in [-1, 1]\):
    • \(x_t = \frac{2 \cdot \text{this.thread.x}}{W - 1} - 1\)
    • \(y_t = \frac{2 \cdot \text{this.thread.y}}{H - 1} - 1\)
  3. Affine Transformation: Apply the matrix vector multiplication directly inside the kernel using parameters passed as uniforms/arguments.
  4. Pipeline Chaining: If the subsequent bilinear sampler is also written as a gpu.js kernel, the output texture of the grid generator can be kept directly in GPU memory using the pipeline: true option, eliminating costly GPU-to-CPU data transfer overhead.
