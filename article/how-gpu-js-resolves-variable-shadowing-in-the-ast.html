How gpu.js Resolves Variable Shadowing in the AST

This article explains the mechanism through which gpu.js handles variable scope shadowing within nested JavaScript blocks during its transpilation to shader languages such as GLSL. Because JavaScript allows lexical re-declarations using let and const inside inner blocks, while target GPU environments require explicit and unambiguous variable resolution, gpu.js utilizes an Abstract Syntax Tree (AST) parser alongside a visitor-based symbol management system. Through hierarchical scope stack tracking, identifier lookup ordering, and identifier mangling, gpu.js ensures that shadowed inner-scope variables do not conflict with or overwrite outer-scope declarations in the final compiled GPU kernel.

The Problem of Shadowing Across Transpilation Targets

In modern JavaScript, declaring a variable with the same identifier in an inner block creates a shadowed variable:

let x = 10;
if (condition) {
    let x = 20; // Shadows the outer x
}

Target shading languages, such as WebGL's GLSL (specifically versions targeting WebGL 1.0/2.0), handle variable scope and re-declarations more rigidly. Certain GPU drivers exhibit inconsistencies when compiling shaders with nested re-declarations of identical names, and register allocation in low-level shader compilers can lead to undefined behavior or compile-time failures. To address this, the AST engine in gpu.js must normalize and resolve scoping before outputting shader code.

Lexical Scope Tracking via the Scope Stack

When a kernel function is passed to gpu.js, the library parses the function string into an AST using a JavaScript parser (such as Acorn). Transpilation relies on internal compiler classes—principally extending WebGLFunctionNode—to traverse the syntax nodes.

  1. Entering Blocks: When the AST walker encounters block-inducing nodes (e.g., BlockStatement, ForStatement, FunctionDeclaration), a new scope frame is pushed onto a lexical scope stack.
  2. Recording Declarations: When a VariableDeclaration node is parsed, the declared identifiers are added directly to the current (top-most) frame on the scope stack along with their inferred or explicit types.
  3. Exiting Blocks: Upon finishing the traversal of a block's child nodes, the current scope frame is popped, discarding the local visibility of those identifiers for subsequent sibling statements.

Identifying Shadowed Declarations

During the traversal of a VariableDeclaration, the compiler queries the scope stack to see if the declared identifier already exists in any enclosing (parent) frame:

  • If the identifier exists in the current scope frame, the parser treats it as an invalid re-declaration (consistent with JavaScript’s let/const rules).
  • If the identifier exists only in an outer scope frame, a shadowing condition is detected.

Disambiguation and Name Mangling

Once a shadowed variable is identified, gpu.js prevents naming collisions in the generated GLSL by applying a renaming transformation (name mangling):

  • Unique Suffix Assignment: The inner variable is assigned a unique generated identifier, typically formed by appending a counter, block index, or scope-depth identifier (for example, transforming an inner x into x_1 or _gpu_x).
  • Symbol Mapping: The transformed identifier is mapped to the current scope frame. Any subsequent Identifier node evaluated within that nested block checks the active scope hierarchy from top to bottom (innermost to outermost).
  • Target Mapping: The lookup resolves to the nearest declaration, which now maps to the uniquely mangled identifier.

Reference Resolution and GLSL Output

When AST expressions referencing identifiers (such as BinaryExpression or AssignmentExpression) are visited, the compiler runs an identifier resolution algorithm:

  1. The compiler traverses the scope stack from the innermost frame outward.
  2. It selects the first matching entry, ensuring standard lexical scope resolution order.
  3. The identifier in the generated GLSL abstract tree or output buffer is replaced with the corresponding unique or mangled name.

Through this scope-stack-driven traversal and automatic identifier renaming, gpu.js flattens nested lexical scopes safely, producing valid, deterministic GLSL that strictly mirrors the original JavaScript scoping semantics.
