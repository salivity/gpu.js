Prevent GPU.js Kernel Argument Mangling in Bundlers

When bundling JavaScript applications that utilize gpu.js, production minification often mangles function parameter names, breaking the library's ability to inspect and translate functions into WebGL shaders. This article explains why this parameter mangling causes runtime shader compilation failures and details the exact configuration settings needed across Webpack, Vite, Rollup, and esbuild to preserve kernel argument names.

Why gpu.js Breaks Under Minification

The gpu.js library compiles standard JavaScript functions into GLSL shaders at runtime. To accomplish this, the library calls Function.prototype.toString() on the kernel function, parses its Abstract Syntax Tree (AST), and extracts the argument names to establish uniform variables and input bindings.

When a production bundler minifies your code, its mangler alters variable and parameter names (e.g., converting function(matrixA, width) into function(a, b)). If the names are shortened, desynchronized, or collide with reserved GLSL keywords, shader compilation fails with runtime syntax or variable binding errors.

Webpack Configuration (Terser)

Webpack typically uses TerserPlugin for JavaScript minification. You can configure Terser to preserve function names and kernel argument names either globally or specifically for your kernel functions.

Modify the optimization section of your webpack.config.js:

const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  mode: 'production',
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        terserOptions: {
          mangle: {
            keep_fnames: true, // Prevents function name mangling
          },
          keep_fnames: true,
        },
      }),
    ],
  },
};

If you only want to protect specific argument names rather than disabling parameter mangling globally, use the reserved option:

new TerserPlugin({
  terserOptions: {
    mangle: {
      reserved: ['matrixA', 'matrixB', 'width', 'height'],
    },
  },
});

Vite Configuration

Vite uses esbuild by default for production minification. You can preserve names using the esbuild configuration block in vite.config.js:

import { defineConfig } from 'vite';

export default defineConfig({
  esbuild: {
    keepNames: true,
  },
});

If your Vite setup uses Terser for minification (build.minify: 'terser'), provide the terserOptions object under the build configuration:

import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    minify: 'terser',
    terserOptions: {
      mangle: {
        keep_fnames: true,
      },
      keep_fnames: true,
    },
  },
});

Rollup Configuration

When bundling directly with Rollup using @rollup/plugin-terser, pass the identifier preservation rules into the plugin configuration:

import terser from '@rollup/plugin-terser';

export default {
  input: 'src/index.js',
  output: {
    file: 'dist/bundle.js',
    format: 'esm',
  },
  plugins: [
    terser({
      mangle: {
        keep_fnames: true,
      },
      keep_fnames: true,
    }),
  ],
};

esbuild Configuration

If you are using esbuild directly via its CLI or Node.js API, enable the keepNames flag.

Node.js API

require('esbuild').buildSync({
  entryPoints: ['src/index.js'],
  bundle: true,
  minify: true,
  keepNames: true,
  outfile: 'dist/bundle.js',
});

CLI

esbuild src/index.js --bundle --minify --keep-names --outfile=dist/bundle.js

Alternative: Code-Level Isolation

If project constraints prevent you from changing the global bundler settings, you can define your kernel functions outside the minification pipeline:

  1. Pass code as strings: Instead of passing an inline function directly to gpu.createKernel, provide a string containing the unminified function code if your build setup supports string evaluation.
  2. External Module Loading: Keep kernel definitions in an unminified, external script loaded separately via a standard <script> tag or runtime dynamic import where bundler minification is bypassed.
