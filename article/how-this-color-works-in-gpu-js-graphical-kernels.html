How this.color Works in gpu.js Graphical Kernels

In GPU.js, the this.color(r, g, b, a) function allows a kernel to output pixel data directly to an HTML5 canvas by compiling JavaScript into WebGL fragment shaders. Instead of returning raw numerical arrays, a graphical kernel executes across a 2D coordinate space and invokes this.color() to set the Red, Green, Blue, and Alpha channels for the pixel corresponding to the current execution thread. This article explains how graphical kernels are initialized, how normalized color values are processed, and what happens under the hood during the GLSL shader translation.

Enabling Graphical Mode

To use this.color(), you must configure the kernel with the graphical: true flag upon creation. By default, GPU.js kernels compute parallel operations and return multidimensional typed arrays. Enabling graphical mode tells GPU.js to bind the execution to an internal or specified HTML canvas element, turning the kernel into a render pipeline.

const gpu = new GPU();
const render = gpu.createKernel(function() {
    this.color(1.0, 0.0, 0.0, 1.0);
}, {
    output: [800, 600],
    graphical: true
});

When called, the kernel executes and writes output directly to render.canvas.

Color Normalization (0.0 to 1.0)

Unlike typical CSS or standard 8-bit canvas operations that use integers from 0 to 255, this.color(r, g, b, a) operates in normalized floating-point space:

  • r (Red): 0.0 (no red) to 1.0 (full red)
  • g (Green): 0.0 (no green) to 1.0 (full green)
  • b (Blue): 0.0 (no blue) to 1.0 (full blue)
  • a (Alpha): 0.0 (fully transparent) to 1.0 (fully opaque)

Passing values above 1.0 will clamp to full intensity, while values below 0.0 clamp to zero. If you have 8-bit RGB values, you must divide them by 255.0 before passing them to the function (e.g., this.color(255 / 255, 128 / 255, 0 / 255, 1.0)).

WebGL and GLSL Translation

GPU.js works by transpiling JavaScript functions into WebGL Shading Language (GLSL). In a graphical kernel, each execution unit corresponds to a fragment (pixel) being shaded on a 2D quad covering the canvas viewport.

Inside the generated GLSL fragment shader, this.color(r, g, b, a) is translated directly into an assignment to the built-in GLSL variable gl_FragColor:

gl_FragColor = vec4(r, g, b, a);

Because gl_FragColor expects a 4D floating-point vector (vec4), this.color() takes immediate effect on the current pixel.

Pixel Coordinates and Thread Context

Graphical kernels typically run over a two-dimensional output array matching the canvas width and height: output: [width, height]. Inside the kernel, you determine which pixel is being colored using this.thread.x and this.thread.y.

  • this.thread.x ranges from 0 to width - 1 (horizontal axis).
  • this.thread.y ranges from 0 to height - 1 (vertical axis).

By dividing these thread coordinates by the canvas dimensions, you can generate normalized coordinate gradients across your canvas to procedurally render patterns, shapes, or visual simulations:

const render = gpu.createKernel(function() {
    const x = this.thread.x / this.output.x;
    const y = this.thread.y / this.output.y;
    this.color(x, y, 0.5, 1.0);
}, {
    output: [512, 512],
    graphical: true
});

render();
document.body.appendChild(render.canvas);

Execution Rules and Limitations

  1. Terminal Call Behavior: While this.color() sets the pixel color, invoking it multiple times in branching logic will overwrite the current fragment's color value, mirroring standard assignment to gl_FragColor.
  2. Canvas Display: When graphical: true is set, calling the kernel function returns the canvas object itself (or the execution context), rather than an array of numbers.
  3. Alpha Channel Handling: Canvas rendering adheres to the WebGL context's blending rules. An alpha value lower than 1.0 will result in transparency relative to elements positioned behind the canvas on the webpage.
