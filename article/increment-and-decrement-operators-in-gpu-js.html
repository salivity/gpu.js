Increment and Decrement Operators in gpu.js

This article explains how unary increment (++) and decrement (--) operators are processed and evaluated inside arithmetic expressions within gpu.js kernel functions. It explores how gpu.js transpiles these JavaScript update expressions into OpenGL Shading Language (GLSL), the operational differences between prefix and postfix notations, and the execution rules governing variable side effects during GPU shader compilation.

Transpilation to GLSL

gpu.js compiles standard JavaScript kernel functions into GLSL shaders executed directly on the GPU. When the gpu.js AST (Abstract Syntax Tree) parser encounters unary update operators—such as increment (++) and decrement (--)—within arithmetic expressions, it maps them directly to their corresponding GLSL equivalents.

Because the GPU executes the resulting GLSL rather than standard JavaScript runtime code, the evaluation order and side-effect mechanics conform strictly to the GLSL ES specification.

Prefix vs. Postfix Evaluation

The behavior of increment and decrement operators depends on whether prefix or postfix notation is used within an arithmetic expression:

  • Prefix Operators (++x, --x): The variable is modified before its value is read into the surrounding expression. For example, in let result = ++a + b;, the value of a is incremented by 1 first, and the updated value is then added to b.
  • Postfix Operators (x++, x--): The variable's original value is evaluated in the expression before the modification occurs. In let result = a++ + b;, the current value of a is used in the addition, after which a is incremented by 1.

Evaluation Order in Complex Expressions

When unary operators appear in multi-term arithmetic operations, gpu.js relies on GLSL operator precedence and associativity:

  1. Precedence: Unary increment and decrement operators have higher precedence than standard binary arithmetic operators (multiplication, division, addition, and subtraction). They bind directly to their target operand.
  2. Associativity: Prefix operators are evaluated with right-to-left associativity, while postfix operators evaluate with left-to-right associativity.
  3. Execution Environment: In expressions like let y = (x++) * 2 + (--z);, x is evaluated at its current value and scheduled for post-increment, z is immediately decremented, and the arithmetic operations proceed according to standard algebraic order.

Pitfalls and Undefined Behavior

While simple prefix and postfix operations evaluate reliably, modifying the same variable multiple times within a single arithmetic expression can produce undefined behavior.

In GLSL, expressions such as let result = x++ + ++x; do not guarantee a sequence point between the two sub-expressions. Different GPU drivers and underlying graphics pipelines may evaluate sub-expressions in varied orders, causing non-deterministic results across different hardware.

To ensure deterministic execution across all GPU platforms when using gpu.js, extract unary modifications with side effects into separate statements rather than chaining them inside complex arithmetic formulas.
