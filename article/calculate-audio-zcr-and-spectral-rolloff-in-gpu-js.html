Calculate Audio ZCR and Spectral Rolloff in GPU.js

This article explains how to compute the Zero-Crossing Rate (ZCR) and Spectral Rolloff on continuous Pulse-Code Modulation (PCM) audio streams using GPU.js for hardware-accelerated processing. By delegating intensive time-domain and frequency-domain array transformations to WebGL shaders through GPU.js, developers can achieve high-throughput, low-latency audio feature extraction inside web environments or Node.js without blocking the main thread.

Understanding the Audio Features

  • Zero-Crossing Rate (ZCR): A time-domain metric that measures how frequently an audio signal transitions between positive and negative values. It is commonly used to distinguish between voiced and unvoiced speech, percussive elements, and background noise.
  • Spectral Rolloff: A frequency-domain metric defined as the frequency bin below which a designated percentage (typically 85% or 95%) of the total spectral energy is concentrated. It serves as an indicator of the spectral shape and high-frequency content of the audio signal.

Stream Ingestion and Data Preparation

Continuous audio streams arrive via the Web Audio API (AudioWorkletNode or ScriptProcessorNode) or Node.js streams as chunks of raw PCM samples (typically Float32Array).

To compute Spectral Rolloff, the PCM chunk must first be converted into a magnitude spectrum using an FFT (Fast Fourier Transform). You can obtain this spectrum either from a Web Audio AnalyserNode or by using a GPU-based FFT kernel.

import { GPU } from 'gpu.js';

const gpu = new GPU();
const BUFFER_SIZE = 2048; // Common chunk size (must be power of two for FFT)
const SAMPLE_RATE = 44100;
const ROLLOFF_THRESHOLD = 0.85;

Calculating Zero-Crossing Rate (ZCR)

The ZCR for a discrete signal chunk of length \(N\) is calculated by comparing adjacent samples:

\[\text{ZCR} = \frac{1}{2(N - 1)} \sum_{n=1}^{N-1} |\text{sgn}(x[n]) - \text{sgn}(x[n - 1])|\]

In GPU.js, this is achieved in two stages: an element-wise kernel that flags zero crossings, followed by a parallel reduction sum (or by calculating chunk-level zero-crossings across a batch of continuous frames).

// Kernel to flag sign changes across adjacent PCM samples
const detectZeroCrossingsKernel = gpu.createKernel(function(pcm) {
    const i = this.thread.x;
    if (i === 0) {
        return 0;
    }
    const current = pcm[i];
    const prev = pcm[i - 1];
    
    // Check if the sign changes between consecutive samples
    if ((current >= 0.0 && prev < 0.0) || (current < 0.0 && prev >= 0.0)) {
        return 1.0;
    }
    return 0.0;
}).setOutput([BUFFER_SIZE]);

// Reduction kernel to aggregate crossing flags into total count
const sumKernel = gpu.createKernel(function(flags) {
    let sum = 0.0;
    for (let i = 0; i < this.constants.length; i++) {
        sum += flags[i];
    }
    return sum / (this.constants.length - 1);
}, {
    constants: { length: BUFFER_SIZE },
    output: [1]
});

function calculateZCR(pcmData) {
    const flags = detectZeroCrossingsKernel(pcmData);
    const zcrResult = sumKernel(flags);
    return zcrResult[0];
}

Calculating Spectral Rolloff

Spectral Rolloff requires computing the cumulative energy sum of the magnitude spectrum up to the point where it reaches the threshold percentage of the total spectral energy:

\[\sum_{k=0}^{R} |X[k]|^2 \ge \alpha \sum_{k=0}^{N/2} |X[k]|^2\]

where \(\alpha\) is the rolloff threshold (e.g., \(0.85\)), and \(R\) is the rolloff frequency bin.

const HALF_BUFFER = BUFFER_SIZE / 2;

const spectralRolloffKernel = gpu.createKernel(function(magnitudes, threshold) {
    // Step 1: Calculate total spectral energy
    let totalEnergy = 0.0;
    for (let i = 0; i < this.constants.bins; i++) {
        totalEnergy += magnitudes[i] * magnitudes[i];
    }
    
    const targetEnergy = totalEnergy * threshold;
    
    // Step 2: Accumulate energy until threshold is reached
    let cumulativeEnergy = 0.0;
    let rolloffIndex = 0;
    for (let i = 0; i < this.constants.bins; i++) {
        cumulativeEnergy += magnitudes[i] * magnitudes[i];
        if (cumulativeEnergy >= targetEnergy) {
            rolloffIndex = i;
            break;
        }
    }
    
    // Convert bin index to frequency (Hz)
    return (rolloffIndex * this.constants.sampleRate) / (2.0 * this.constants.bins);
}, {
    constants: { 
        bins: HALF_BUFFER,
        sampleRate: SAMPLE_RATE 
    },
    output: [1]
});

function calculateSpectralRolloff(magnitudeSpectrum) {
    const rolloffHz = spectralRolloffKernel(magnitudeSpectrum, ROLLOFF_THRESHOLD);
    return rolloffHz[0];
}

Continuous Stream Pipeline Integration

Connect the GPU kernels directly into an audio ingestion loop (such as the AudioWorkletProcessor message port):

function processAudioChunk(pcmChunk, magnitudeSpectrum) {
    // Execute GPU-accelerated calculations
    const zcr = calculateZCR(pcmChunk);
    const rolloff = calculateSpectralRolloff(magnitudeSpectrum);

    return {
        zcr: zcr,
        rolloffHz: rolloff
    };
}

Optimizations for Continuous PCM Streams

  1. Pipeline Texture Mode: Enable pipeline: true on upstream kernels to keep output data in GPU VRAM memory as WebGL textures. This avoids frequent memory transfers between the CPU and GPU.
  2. Buffer Batching: For ultra-high sample rates, batch multiple consecutive PCM windows into a 2D matrix (dimensions: [BUFFER_SIZE, NUM_CHUNKS]) so the GPU can evaluate dozens of continuous frames concurrently in a single execution pass.
