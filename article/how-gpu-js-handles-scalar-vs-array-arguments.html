How GPU.js Handles Scalar vs Array Arguments

This article provides an overview of the internal mechanisms gpu.js uses to process different data types, contrasting how scalar numerical inputs and multi-dimensional array inputs are translated into GPU-compatible formats. In gpu.js, JavaScript functions are transpiled into WebGL or WebGPU shader code, requiring distinct handling for scalar primitives versus complex data collections to accommodate the constraints of graphics hardware.

Scalar Numerical Arguments

Scalar numerical arguments—such as individual integers or floating-point numbers—are passed directly to the underlying shader as uniform variables (e.g., uniform float or uniform int in GLSL).

Because uniforms remain constant across all concurrent threads during a single kernel execution, they entail minimal overhead:

  • Direct Value Passing: The CPU sends the single numeric value straight to the GPU state without complex serialization.
  • Registers and Caches: Inside the shader, the scalar resides in fast uniform memory, making read access nearly instantaneous for every thread.
  • Read-Only Context: Like all WebGL uniforms, scalars cannot be modified within the kernel execution; they act as read-only constants across the execution grid.

Array Arguments

Because traditional WebGL fragment shaders cannot accept dynamically sized, arbitrary arrays as standard inputs, gpu.js handles array arguments by encoding them into GPU textures.

When you pass a 1D, 2D, or 3D array to a kernel:

  1. Texture Packing: gpu.js serializes the array data into a typed array and uploads it to GPU VRAM as a 2D floating-point texture. If the input is a multidimensional array, the library maps the nested dimensions to specific texture dimensions.
  2. Coordinate Translation: Within the generated shader code, standard array indexing syntax (such as myArray[this.thread.y][this.thread.x]) is transpiled into UV texture coordinate calculations.
  3. Texture Sampling: The shader fetches the requested value by sampling the texture at the calculated coordinates using built-in sampling functions rather than reading directly from system memory.

Architectural and Performance Differences

  • Memory Overhead: Scalar arguments involve almost no transfer latency. In contrast, array arguments require allocating texture memory and copying data from the CPU to the GPU, which can become a bottleneck for large datasets unless inputs are already kept on the GPU using gpu.js textures.
  • Access Mechanics: Scalars are accessed directly by name as uniforms. Array elements require mathematical coordinate transformation and a texture lookup per read, consuming more GPU execution cycles.
  • Size Limitations: Scalar arguments are constrained only by the number of available uniform registers. Arrays are limited by the host machine's MAX_TEXTURE_SIZE limits, which dictate the maximum dimensions of an array that can be successfully encoded into a single texture.
