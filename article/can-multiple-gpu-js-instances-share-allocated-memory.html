Can Multiple GPU.js Instances Share Allocated Memory?

Multiple independent instances of the GPU class in gpu.js cannot directly share allocated GPU memory. Because gpu.js relies primarily on WebGL to execute compute shaders in the browser, each independent instance encapsulates its own separate WebGL rendering context. WebGL contexts are strictly isolated from one another, meaning textures, buffers, and intermediate compute states cannot cross instance boundaries without being transferred through CPU memory.

WebGL Context Isolation

When you instantiate new GPU(), the library initializes an underlying WebGL context (WebGL2 or WebGL1). The WebGL specification does not expose context sharing mechanisms to the JavaScript layer. Textures and framebuffers created within one context are bound exclusively to the state machine of that specific context. If an independent second GPU instance attempts to bind or read a texture handle generated by the first, the underlying graphics driver will reject it as an invalid resource.

How Data Transfer Works Between Instances

Because native GPU-to-GPU memory sharing is not supported across separate instances, passing data requires a CPU round-trip:

  1. Extraction (GPU to CPU): You must pull the data out of the first instance’s memory using .toArray() or by reading from the texture via standard WebGL readback operations (such as readPixels).
  2. Transfer: The data is stored in host RAM as a standard JavaScript Array or a TypedArray (like Float32Array).
  3. Upload (CPU to GPU): The array is passed as an argument to a kernel belonging to the second GPU instance, which re-allocates and re-uploads the data onto its own GPU context.

This round-trip incurs a notable performance penalty due to bus transfer latency and GPU pipeline stalls.

Recommended Approach: Pipeline Mode on a Single Instance

To share allocated memory efficiently between operations, use a single GPU instance instead of multiple independent ones. Gpu.js provides a built-in feature known as "pipeline mode" (pipeline: true).

When kernels belong to the same instance and pipeline mode is enabled, the output of a kernel remains on the GPU as a texture (GPUTexture). This texture can be passed directly as an input to subsequent kernels within that same instance without ever reading the data back to the CPU. Maintaining a single GPU instance is the standard and most performant pattern for chained GPU computations in gpu.js.
