Get ImageData or Data URL from a GPU.js Canvas

Extracting rendered visual outputs from GPU.js is essential when you need to save generated graphics, pass textures to other libraries, or process pixels on the CPU. When configured with graphical mode, a GPU.js kernel renders directly to an HTML canvas backed by a WebGL context. This guide explains how to extract a standard Base64 Data URL or an ImageData object directly from that graphical GPU.js canvas.

Enabling Graphical Mode in GPU.js

Before you can extract any image data, the kernel must be configured to output graphics rather than numerical arrays. Enable this by chaining .setGraphical(true) when creating the kernel:

const gpu = new GPU();

const renderKernel = gpu.createKernel(function() {
    // Example: Output red color across the canvas
    this.color(1, 0, 0, 1);
})
.setOutput([512, 512])
.setGraphical(true);

// Run the kernel to draw to the internal canvas
renderKernel();

Once executed, the underlying canvas element is accessible via the canvas property of the kernel function: renderKernel.canvas.

Retrieving a Data URL

A Data URL represents the canvas contents as a Base64-encoded string (typically PNG or JPEG). You can call the standard HTMLCanvasElement method toDataURL() directly on the kernel's canvas:

const canvas = renderKernel.canvas;
const dataURL = canvas.toDataURL('image/png');

// Example usage: assign to an image element or download
console.log(dataURL); // "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."

Note: Extract the Data URL immediately after running the kernel, or instantiate GPU.js with WebGL options that preserve the drawing buffer, as WebGL contexts may clear their buffers between animation frames.

Retrieving an ImageData Object

Because GPU.js uses a WebGL context, the standard 2D method context.getImageData() is not available directly on the kernel canvas. There are two primary approaches to obtain an ImageData object:

Method 1: Using a Secondary 2D Canvas (Recommended)

The most reliable approach is drawing the GPU.js WebGL canvas onto an offscreen 2D canvas, which handles pixel formatting and coordinate flipping automatically:

function getImageDataFromKernel(kernel) {
    const glCanvas = kernel.canvas;
    const width = glCanvas.width;
    const height = glCanvas.height;

    // Create an offscreen 2D canvas
    const helperCanvas = document.createElement('canvas');
    helperCanvas.width = width;
    helperCanvas.height = height;

    const ctx = helperCanvas.getContext('2d');
    
    // Draw the WebGL canvas onto the 2D canvas
    ctx.drawImage(glCanvas, 0, 0);

    // Extract the ImageData
    return ctx.getImageData(0, 0, width, height);
}

const imageData = getImageDataFromKernel(renderKernel);
console.log(imageData.data); // Uint8ClampedArray containing RGBA pixel values

Method 2: Direct WebGL Pixel Reading (gl.readPixels)

If performance is critical and you wish to avoid creating a secondary canvas, read pixels directly from the kernel's WebGL context. Note that WebGL coordinates start from the bottom-left, so the image data will be vertically flipped relative to standard DOM image conventions:

function getRawImageData(kernel) {
    const glCanvas = kernel.canvas;
    const width = glCanvas.width;
    const height = glCanvas.height;
    const gl = kernel.context;

    // Allocate array for RGBA values
    const pixels = new Uint8Array(width * height * 4);

    // Read pixel buffer from GPU
    gl.readPixels(0, 0, width, height, gl.RGBA, gl.UNSIGNED_BYTE, pixels);

    // Wrap into an ImageData object
    const clampedArray = new Uint8ClampedArray(pixels.buffer);
    return new ImageData(clampedArray, width, height);
}
