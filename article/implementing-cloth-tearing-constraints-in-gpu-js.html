Implementing Cloth Tearing Constraints in GPU.js

This article explains how to implement spring-damper tearing constraints in virtual cloth simulations using the WebGL-accelerated library gpu.js. It covers representing cloth topology with GPU-friendly data textures, computing Hooke's law and damping forces within parallel compute kernels, evaluating elongation thresholds to trigger dynamic tears, and updating mesh connectivity on the GPU without costly CPU-GPU memory transfers.

Cloth Representation and Data Buffers

A standard cloth mesh is modeled as a mass-spring system consisting of particles interconnected by structural, shear, and flexion (bending) springs. Because gpu.js executes computations across 2D grids representing WebGL textures, particle states and connectivity must be structured as uniform matrices:

  1. Position Buffers (X, Y, Z): 2D textures storing the 3D coordinates of each particle indexed by (i, j).
  2. Velocity Buffers (Vx, Vy, Vz): 2D textures holding current velocities.
  3. Connectivity Buffers: Fixed-size neighbor lists per particle. For a regular grid, a particle connects to immediate neighbors (left, right, up, down). Diagonal and two-step neighbors handle shear and bending.
  4. State/Rest-Length Buffers: A multi-channel texture storing the equilibrium distance (\(l_0\)) and an active flag (\(1.0\) for intact, \(0.0\) for severed) for each outgoing spring.

Using a ping-pong buffer technique, alternate between two sets of textures to read the state at time \(t\) and write the state at \(t + \Delta t\).

The Spring-Damper Mathematical Model

The internal force exerted by particle \(j\) on particle \(i\) via a damped spring is governed by:

\[\mathbf{F}_{ij} = -\left( k_s (\|\mathbf{r}_{ij}\| - l_0) + k_d \left( \frac{(\mathbf{v}_i - \mathbf{v}_j) \cdot \mathbf{r}_{ij}}{\|\mathbf{r}_{ij}\|} \right) \right) \frac{\mathbf{r}_{ij}}{\|\mathbf{r}_{ij}\|}\]

Where:

  • \(\mathbf{r}_{ij} = \mathbf{p}_i - \mathbf{p}_j\) is the displacement vector.
  • \(\|\mathbf{r}_{ij}\|\) is the current distance.
  • \(l_0\) is the natural rest length.
  • \(k_s\) is the spring stiffness coefficient.
  • \(k_d\) is the damping coefficient.
  • \(\mathbf{v}_i, \mathbf{v}_j\) are the respective velocities.

Implementing Tearing Constraints

Tearing occurs when the engineering strain along a spring exceeds a predetermined critical threshold:

\[\epsilon = \frac{\|\mathbf{r}_{ij}\| - l_0}{l_0} > \epsilon_{\text{max}}\]

Because WebGL shaders cannot dynamically reallocate memory or alter mesh index buffers on the fly, tearing in gpu.js is implemented using state-masking:

  1. Strain Evaluation: During force computation or a dedicated constraint pass, compute the current length \(\|\mathbf{r}_{ij}\|\).
  2. Spring Invalidation: If \(\epsilon > \epsilon_{\text{max}}\), set the spring's active state to 0.0. Subsequent physics passes multiply the calculated spring force by this state variable, effectively neutralizing the connection.
  3. Topological Decoupling: For visual tearing, duplicate the vertex position buffer entries when adjacent springs break, allowing geometric faces to diverge during rendering.

GPU.js Kernel Implementation

Below is the implementation of the force integration and spring tearing kernel using gpu.js.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Configuration
const WIDTH = 128;
const HEIGHT = 128;
const REST_LENGTH = 1.0;
const KS = 50.0;          // Spring stiffness
const KD = 0.5;           // Damping factor
const MAX_STRAIN = 0.35;  // 35% elongation triggers tear
const DT = 0.016;         // Time step (60 FPS)

// Kernel to compute positions, velocities, and tear springs
const updateClothKernel = gpu.createKernel(function(
  posX, posY, posZ,
  velX, velY, velZ,
  springActive, // [WIDTH, HEIGHT, 4] texture (Left, Right, Up, Down)
  restLength,
  ks, kd, maxStrain, dt
) {
  const x = this.thread.x;
  const y = this.thread.y;

  // Current particle properties
  let px = posX[y][x];
  let py = posY[y][x];
  let pz = posZ[y][x];
  let vx = velX[y][x];
  let vy = velY[y][x];
  let vz = velZ[y][x];

  // Neighbor offsets: Left (-1, 0), Right (1, 0), Down (0, -1), Up (0, 1)
  const offsetsX = [-1, 1, 0, 0];
  const offsetsY = [0, 0, -1, 1];

  let fx = 0.0;
  let fy = -9.81 * 0.1; // Gravity (mass = 0.1)
  let fz = 0.0;

  // Process 4 direct structural neighbors
  for (let i = 0; i < 4; i++) {
    const nx = x + offsetsX[i];
    const ny = y + offsetsY[i];

    // Boundary check
    if (nx >= 0 && nx < this.output.x && ny >= 0 && ny < this.output.y) {
      // Check if spring is active
      const active = springActive[y][x][i];

      if (active > 0.5) {
        const dx = px - posX[ny][nx];
        const dy = py - posY[ny][nx];
        const dz = pz - posZ[ny][nx];
        const dist = Math.sqrt(dx * dx + dy * dy + dz * dz);

        // Check tearing condition
        const strain = (dist - restLength) / restLength;
        if (strain < maxStrain) {
          // Normal Spring-Damper Force
          const normX = dx / dist;
          const normY = dy / dist;
          const normZ = dz / dist;

          const relVx = vx - velX[ny][nx];
          const relVy = vy - velY[ny][nx];
          const relVz = vz - velZ[ny][nx];

          const vRelDotNorm = relVx * normX + relVy * normY + relVz * normZ;
          const totalForce = -(ks * (dist - restLength) + kd * vRelDotNorm);

          fx += totalForce * normX;
          fy += totalForce * normY;
          fz += totalForce * normZ;
        }
      }
    }
  }

  // Symplectic Euler Integration
  const mass = 0.1;
  vx += (fx / mass) * dt;
  vy += (fy / mass) * dt;
  vz += (fz / mass) * dt;

  px += vx * dt;
  py += vy * dt;
  pz += vz * dt;

  // Return updated coordinate (e.g., posX pass)
  return px;
})
.setOutput([WIDTH, HEIGHT])
.setPipeline(true); // Retain output on GPU memory

Managing Spring States via a Tearing Pass

To permanently persist broken springs across simulation steps without recomputing their strain threshold continuously, execute a dedicated constraint validation kernel that updates the springActive state buffer:

const evaluateTearsKernel = gpu.createKernel(function(
  posX, posY, posZ,
  springActive,
  restLength,
  maxStrain
) {
  const x = this.thread.x;
  const y = this.thread.y;
  const edgeIdx = this.thread.z; // 0 to 3

  const offsetsX = [-1, 1, 0, 0];
  const offsetsY = [0, 0, -1, 1];

  let active = springActive[y][x][edgeIdx];
  if (active < 0.5) {
    return 0.0; // Already broken
  }

  const nx = x + offsetsX[edgeIdx];
  const ny = y + offsetsY[edgeIdx];

  if (nx >= 0 && nx < this.output.x && ny >= 0 && ny < this.output.y) {
    const dx = posX[y][x] - posX[ny][nx];
    const dy = posY[y][x] - posY[ny][nx];
    const dz = posZ[y][x] - posZ[ny][nx];
    const dist = Math.sqrt(dx * dx + dy * dy + dz * dz);

    if ((dist - restLength) / restLength > maxStrain) {
      return 0.0; // Break spring
    }
  }

  return 1.0; // Keep intact
})
.setOutput([WIDTH, HEIGHT, 4])
.setPipeline(true);

Performance Optimization

  1. Avoid Pipeline Stalls: Use pipeline: true on all kernels. Extracting data via .toArray() forces a synchronous GPU readback, stalling the render loop. Pass WebGL texture references directly into subsequent kernels.
  2. Sub-stepping: High stiffness values (\(k_s\)) cause numerical instability in explicit Euler integrators. Run multiple physics iterations (e.g., 5 to 10 sub-steps with smaller \(\Delta t\)) per visual frame.
  3. Reciprocal Symmetry: Ensure that if particle \((x, y)\) breaks its connection to \((x+1, y)\), the inverse connection on \((x+1, y)\) to \((x, y)\) is invalidated simultaneously to prevent asymmetric force explosions.
