GPU.js Interactive Mandelbrot and Julia Fractals

GPU.js is capable of rendering both Mandelbrot and Julia set fractals with fluid, interactive zooming capabilities. By transpiling specialized JavaScript functions into WebGL shaders, GPU.js delegates complex mathematical iterations directly to the graphics hardware. This parallel compute capability allows web browsers to calculate escape-time algorithms for millions of pixels simultaneously, making real-time panning and zooming possible at 60 frames per second where traditional CPU-based JavaScript would struggle.

How GPU.js Handles Fractal Computations

Fractals like the Mandelbrot and Julia sets rely on the escape-time algorithm, defined by the formula:

z(n+1) = z(n)^2 + c

To render a fractal, this equation is evaluated repeatedly for each pixel until the magnitude of z exceeds a bailout threshold (commonly 2) or reaches a predefined maximum iteration count. Because the calculation for any given pixel is completely independent of its neighbors, the task is embarrassingly parallel.

GPU.js abstracts the complexity of raw WebGL and GLSL shaders. You define a compute kernel in JavaScript, and the library automatically compiles it into a fragment shader running on the GPU. Each invocation of the kernel maps directly to a coordinate on an HTML5 canvas, outputting color values based on the number of iterations required to escape.

Implementing the Mandelbrot Set

For the Mandelbrot set, the initial value z(0) is set to (0, 0), and the constant c corresponds to the pixel's coordinate mapped onto the complex number plane.

A GPU.js kernel takes parameters such as the viewport's center coordinates (centerX, centerY), the current zoom level, and the maximum iterations. The kernel maps the canvas coordinates to the complex plane:

  • Real part: cr = (this.thread.x - width / 2) / zoom + centerX
  • Imaginary part: ci = (this.thread.y - height / 2) / zoom + centerY

The GPU then iterates through the complex multiplication. Once escaped, the kernel writes an RGB color value representing the iteration count to the screen.

Implementing the Julia Set

The Julia set uses the exact same core iteration logic but reverses the roles of z and c:

  • The constant c remains fixed across the entire canvas.
  • The initial value z(0) is derived directly from the pixel's coordinates on the complex plane.

By passing c as dynamic uniform parameters to the GPU.js kernel, developers can create morphing Julia sets in real time—for example, by updating the constant coordinates based on mouse movement across the screen.

Implementing Interactive Zoom and Pan

To achieve interactive zooming, you bind standard DOM event listeners to the canvas:

  1. Wheel Events (wheel): Multiply or divide the zoom factor based on scroll delta. Adjust centerX and centerY relative to the cursor position so the zoom targets the pointer location.
  2. Pointer/Mouse Drag Events (mousedown, mousemove, mouseup): Offset centerX and centerY by the distance dragged, divided by the current zoom factor.
  3. Render Loop: Wrap the kernel execution inside requestAnimationFrame(). Whenever the zoom or pan state updates, the kernel executes with the new coordinates and redraws the frame instantly.

Hardware Limitations to Consider

While GPU.js handles rendering at high frame rates, deep zooming encounters a hardware barrier: 32-bit floating-point precision. WebGL generally relies on single-precision floats (FP32), which provide roughly 7 decimal digits of precision. Once a user zooms beyond a factor of approximately \(10^7\), visual artifacts and blocky pixelation appear because the precision is exhausted.

Within this standard precision threshold, GPU.js provides one of the fastest and most accessible ways to build interactive fractal explorers directly in the browser without writing raw GLSL shader code.
