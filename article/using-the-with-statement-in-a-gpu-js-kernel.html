Using the With Statement in a GPU.js Kernel

Attempting to use the JavaScript with statement inside a gpu.js kernel results in a compilation failure before the code ever runs on the GPU. Because gpu.js works by parsing JavaScript functions into an Abstract Syntax Tree (AST) and transpiling them into WebGL or WebGPU shader code (GLSL), it only supports a restricted, mathematically focused subset of JavaScript. The dynamic scope resolution required by with cannot be translated into statically typed shader code, causing the gpu.js compiler to throw a syntax or unsupported node error during kernel creation.

The Compilation Pipeline of gpu.js

When you define a kernel using gpu.createKernel(function() { ... }), the library does not execute the function directly within the JavaScript runtime. Instead, it extracts the function's source string, parses it using an AST parser, and traverses each AST node to generate corresponding GLSL code.

Shaders in WebGL require explicit typing, static scoping, and predictable memory layouts. Consequently, gpu.js restricts the syntax inside a kernel to primitive numbers, standard arithmetic operations, static loops, fixed-size arrays, and specific supported built-ins (such as Math functions).

Why the with Statement Fails

The with statement dynamically extends the scope chain for a block of code by adding the specified object to the lexical environment. This design leads to two fundamental incompatibilities within a gpu.js kernel:

  1. AST Node Rejection: The gpu.js transpiler explicitly checks AST node types during the code generation phase. A WithStatement node is not implemented in the internal code generator. When the parser encounters this node type, it throws an error—typically halting execution with an "unsupported syntax" or unhandled AST node exception.
  2. Dynamic Scope Incompatibility: GLSL has no concept of dynamic property lookup or scope injection. In standard JavaScript, an identifier inside a with block could refer to an object property, a local variable, or a global variable depending on runtime evaluation. Shader compilers require static variable resolution at compile time, making dynamic scope injection fundamentally untranslatable to GPU hardware.
  3. Strict Mode Constraints: Modern JavaScript runtimes, ES modules, and tools parsing strict mode will automatically throw a syntax error upon encountering a with statement, as it is deprecated and entirely prohibited in strict mode.

The Error Behavior

If a developer writes code like the following:

const kernel = gpu.createKernel(function(data) {
  with (data) {
    return value * 2;
  }
}).setOutput([1]);

The error will occur synchronously at the gpu.createKernel call, not during the execution of kernel(). The compilation pipeline fails during AST traversal, meaning no WebGL context or shader program is ever created, and the kernel function cannot be invoked.

The Correct Approach

To pass complex structures or coordinate multiple values inside a kernel, avoid dynamic scope extensions. Access variables and data structures explicitly:

  • Use Direct Arguments: Pass flat numeric arrays, textures, or scalar values directly as kernel arguments.
  • Assign to Local Variables: Declare explicit local variables (const or let) inside the kernel body for intermediate calculations.
  • Explicit Array Indexing: Access multi-dimensional data using the built-in thread coordinates (this.thread.x, this.thread.y, this.thread.z) rather than trying to destructure or scope-wrap incoming data.
