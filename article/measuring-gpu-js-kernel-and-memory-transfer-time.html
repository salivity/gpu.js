Measuring GPU.js Kernel and Memory Transfer Time

This article explains how to accurately benchmark and separate raw kernel execution time from memory transfer overhead in gpu.js. By default, running a standard gpu.js kernel bundles host-to-device data upload, shader execution, and device-to-host readback into a single operation. To isolate these metrics, developers must utilize texture outputs via pipeline mode and JavaScript’s High Resolution Timer to measure each phase independently.

Understanding the GPU.js Pipeline Overhead

When executing a kernel with standard JavaScript arrays, gpu.js performs three distinct operations:

  1. CPU-to-GPU Transfer: Converts JavaScript arrays into WebGL textures and uploads them to the GPU.
  2. Kernel Execution: Executes the WebGL fragment shader across the specified output dimensions.
  3. GPU-to-CPU Transfer: Reads pixels back from the GPU frame buffer via gl.readPixels and formats them into a standard JavaScript array.

Because WebGL API calls are asynchronous, timing a basic kernel(array) call measures the sum of all three phases rather than the raw compute speed.

Separating Compute from Transfer with Pipeline Mode

To isolate raw execution time, you must prevent gpu.js from automatically transferring the result back to the CPU. Enabling pipeline: true forces the kernel to return a WebGL texture that remains in GPU memory.

1. Configure the Kernels

Set up an input preparation kernel (or pipeline your input) alongside the computation kernel with pipelining enabled:

const gpu = new GPU();

// Kernel configured with pipeline mode enabled
const computeKernel = gpu.createKernel(function(inputTexture) {
    return inputTexture[this.thread.x] * 2.0;
})
.setOutput([1000000])
.setPipeline(true);

2. Measuring CPU-to-GPU Upload Time

To measure memory upload time, isolate the creation of the input texture on the GPU:

const rawData = new Float32Array(1000000).fill(1.5);

// Measure upload time by creating a GPU-resident texture
const uploadStart = performance.now();
const inputTexture = gpu.createKernel(function(data) {
    return data[this.thread.x];
})
.setOutput([1000000])
.setPipeline(true)(rawData);

const uploadEnd = performance.now();
const cpuToGpuTime = uploadEnd - uploadStart;

3. Measuring Raw Kernel Execution Time

Pass the pre-allocated texture directly into the target kernel. Because the output is retained on the GPU as a texture, CPU readback overhead is eliminated:

const execStart = performance.now();

// Execute kernel: Texture In -> Texture Out
const resultTexture = computeKernel(inputTexture);

const execEnd = performance.now();
const rawExecutionTime = execEnd - execStart;

4. Measuring GPU-to-CPU Readback Time

To capture the device-to-host transfer time, explicitly call .toArray() on the returned texture. This triggers gl.readPixels, synchronizes the execution pipeline, and transfers the data back into system memory:

const downloadStart = performance.now();

// Force GPU synchronization and memory readback
const cpuArray = resultTexture.toArray();

const downloadEnd = performance.now();
const gpuToCpuTime = downloadEnd - downloadStart;

Analyzing the Results

After gathering the measurements:

  • Memory Transfer Time: cpuToGpuTime + gpuToCpuTime represents the total I/O cost of interacting with the graphics hardware.
  • Compute Time: rawExecutionTime reflects only the time spent queuing and running the shader operations.

If the combined memory transfer time significantly exceeds the raw execution time, the algorithm is memory-bound, and operations should be chained together in pipeline mode to minimize CPU-GPU round trips.
