GPU.js dynamicArguments Uniform Buffer Overhead

The dynamicArguments configuration in gpu.js dictates how the library optimizes, compiles, and binds kernel inputs across consecutive executions. By altering how argument types, array lengths, and memory layouts are handled at runtime, this setting directly influences the frequency and performance cost of uniform buffer and uniform value bindings in the underlying WebGL context.

Uniform Handling in gpu.js

When executing a kernel, gpu.js transfers constants, scalar parameters, and structural metadata to the GPU pipeline using uniforms. In WebGL 2 contexts, these parameters are often grouped into Uniform Buffer Objects (UBOs) to enable batch updates and persistent memory mappings. Under default configurations, gpu.js assumes predictable argument structures, allowing it to cache uniform locations, keep buffer bindings active, and push updates with minimal CPU-side validation.

How dynamicArguments Alters Binding Overhead

Enabling dynamicArguments: true instructs gpu.js to anticipate variability in input shapes, types, or dimensions between invocations without triggering a full shader recompilation. This flexibility introduces distinct shifts in binding overhead:

  • Runtime Type and Shape Checking: With dynamic arguments enabled, gpu.js must inspect input arguments prior to every execution. This verification step adds CPU overhead to determine whether existing uniform buffer allocations remain valid for the incoming data.
  • Buffer Re-allocation and Invalidation: If an argument's dimensions change, the existing uniform buffer layout can no longer satisfy the memory offset requirements of the compiled shader. The runtime must allocate or resize the buffer, invalidating the previous binding and forcing a new binding call to glBindBufferBase or glBindBufferRange.
  • State Mutation vs. State Caching: In static mode, gpu.js can skip redundant WebGL state transitions if the arguments occupy the same memory slots across successive draw calls. Dynamic mode necessitates explicit state reassignment and re-binding before each dispatch to guarantee that altered argument offsets correctly match the shader's expectations.

Performance Trade-Offs

While dynamicArguments increases uniform buffer binding and CPU-side overhead per dispatch, it serves as an essential optimization against a much larger performance penalty: shader recompilation.

Without dynamic arguments, passing an array of a different size or altering input structures causes gpu.js to rebuild the kernel program. Shader compilation and program linking in WebGL cause significant pipeline stalls. By accepting a modest, consistent overhead in uniform buffer re-binding and state validation, dynamicArguments eliminates the catastrophic latency of regenerating GPU binaries mid-execution.

Optimal Configuration Strategy

To minimize uniform buffer binding overhead:

  • Keep dynamicArguments disabled (false) for high-frequency render loops or iterative compute tasks where data shapes and types remain static across every call. This maximizes WebGL state caching and minimizes CPU overhead.
  • Enable dynamicArguments (true) when processing variable-sized datasets or streaming workloads where input structures shift dynamically, ensuring smooth execution without triggering pipeline-blocking recompilations.
