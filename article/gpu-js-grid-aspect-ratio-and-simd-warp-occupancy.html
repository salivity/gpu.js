GPU.js Grid Aspect Ratio and SIMD Warp Occupancy

The thread grid aspect ratio in gpu.js directly impacts hardware-level performance by altering how 2D and 3D coordinate spaces map onto physical SIMD execution units. When kernel dimensions fail to align with the underlying GPU warp or wavefront architecture, hardware lanes sit idle, memory access patterns degrade, and instruction pipelines stall. Understanding the relationship between grid geometry, workgroup mapping, and execution units is critical for maximizing SIMD occupancy in web-based parallel computing.

Warp Execution and Linear Thread Mapping

Modern GPUs execute code in lockstep groups called warps (NVIDIA, 32 threads) or wavefronts (AMD, 32 or 64 threads). gpu.js abstracts this hardware layer by allowing developers to define an output array such as [width, height]. Under the hood, gpu.js compiles JavaScript into WebGL fragment shaders or WebGPU compute shaders.

Regardless of the high-level representation, the GPU must serialize multi-dimensional grid coordinates into a one-dimensional hardware execution stream. Threads are scheduled in contiguous chunks corresponding to warp sizes. When the aspect ratio of the grid causes the inner dimension (typically the X-axis) to be misaligned with the hardware warp size, execution units cannot be fully saturated.

The Problem of Skewed Aspect Ratios

An extreme or unbalanced aspect ratio (for example, a grid of [4, 1024] versus [64, 64]) introduces substantial overhead:

  • Boundary Inefficiency and Padding: If the X-dimension is not a multiple of the warp size, individual warps often cross row boundaries. In compute pipelines with fixed 2D workgroup bounds (e.g., \(8 \times 8\) or \(16 \times 16\)), an aspect ratio with narrow edges results in partially populated workgroups. Threads outside the valid range must be masked off, leaving SIMD lanes inactive and dropping overall occupancy.
  • Quad Divergence in WebGL Mode: When gpu.js falls back to WebGL, computation is driven by rendering geometry where pixels are processed in \(2 \times 2\) pixel quads to support derivative calculations. Extremely tall or thin aspect ratios (such as \(1 \times N\)) force the rasterizer to launch quads where only half—or a quarter—of the fragment lanes contain active data, immediately cutting compute efficiency by 50% to 75%.
  • Branch Masking: In gpu.js kernels containing boundary conditions (if (this.thread.x < limit)), mismatched grid bounds cause adjacent threads within the same warp to take divergent execution paths. Because SIMD cores execute branches sequentially by disabling inactive lanes, divergent conditions caused by awkward grid edges reduce effective throughput.

Memory Coalescing and Stride Latency

The thread grid aspect ratio governs how data is fetched from underlying WebGL textures or WebGPU buffers. Hardware memory controllers achieve peak bandwidth when all 32 threads in a warp access contiguous memory addresses simultaneously (coalesced access).

In gpu.js, adjacent threads along the primary axis access adjacent indices. A wide aspect ratio promotes contiguous, coalesced reads across the warp. Conversely, a tall, narrow aspect ratio forces threads within the same warp to span across rows. This creates strided memory access, where each memory request must be fulfilled through separate, serialized transactions, stalling the warp while waiting for high-latency texture caches.

Optimizing Aspect Ratios in gpu.js

To ensure maximum SIMD warp occupancy:

  1. Align Dimensions to Multiples of 32: Set the fastest-moving dimension (the first index in the output array) to a multiple of 32 to guarantee that warp boundaries do not overlap unaligned rows.
  2. Flatten Non-Spatial Datasets: If the kernel does not rely on local 2D neighborhoods (such as matrix convolutions), flatten the output into a single 1D grid. 1D allocations eliminate boundary mismatches and ensure clean warp scheduling.
  3. Pad Irregular Dimensions: When processing irregular matrix sizes, round the output grid up to the nearest warp multiple and discard extraneous calculations with an early exit, rather than running an unpadded, non-standard aspect ratio.
