Positional Encoding for Transformers in GPU.js

This article explains how to implement positional encoding addition for transformer tokens using GPU.js to leverage WebGL-based hardware acceleration. You will learn how positional encodings represent sequence order in token matrices, how to map 2D tensor operations to a GPU.js kernel, and how to efficiently combine token embeddings with precomputed positional encodings directly on the GPU.

Understanding the Operation

In transformer architectures, token embeddings do not natively contain sequence order information. To inject this information, a positional encoding matrix of the exact same shape as the token embedding matrix is added element-wise:

\[\text{Output}[i][j] = \text{Embedding}[i][j] + \text{PositionalEncoding}[i][j]\]

Given:

  • Sequence Length (\(S\)): The number of tokens in the input sequence.
  • Embedding Dimension (\(D\)): The size of the vector representing each token.

Both input matrices have the shape [S, D]. The resulting matrix also has the shape [S, D].

GPU.js Thread Indexing for 2D Matrices

GPU.js maps multi-dimensional arrays to GPU threads using this.thread. When processing a 2D matrix of shape [S, D] (where rows represent tokens and columns represent embedding dimensions):

  • this.thread.x indexes the columns (dimension index, ranging from 0 to D - 1).
  • this.thread.y indexes the rows (token/sequence position, ranging from 0 to S - 1).

The kernel access pattern corresponds to matrix[this.thread.y][this.thread.x].

Implementation

The following code sets up the GPU instance, creates the addition kernel, and executes the positional encoding addition:

const { GPU } = require('gpu.js'); // Use <script src="gpu-browser.min.js"> in browser environments

const gpu = new GPU();

/**
 * Creates a reusable GPU kernel for positional encoding addition.
 * @param {number} seqLength - Number of tokens in sequence (rows).
 * @param {number} embeddingDim - Dimension of each token vector (columns).
 */
function createPositionalEncodingKernel(seqLength, embeddingDim) {
  return gpu.createKernel(
    function (tokens, posEncodings) {
      const col = this.thread.x; // embedding dimension index
      const row = this.thread.y; // token index

      return tokens[row][col] + posEncodings[row][col];
    },
    {
      output: [embeddingDim, seqLength], // [width, height] -> [x, y]
      pipeline: true // Keeps output as a GPU texture for subsequent layers
    }
  );
}

// Example usage:
const seqLength = 4;
const embeddingDim = 6;

// Sample token embedding matrix [4, 6]
const tokenEmbeddings = [
  [0.12, -0.45, 0.88, 0.23, -0.11, 0.54],
  [0.91, 0.33, -0.72, 0.05, 0.62, -0.18],
  [-0.04, 0.77, 0.19, -0.83, 0.41, 0.30],
  [0.65, -0.29, 0.44, 0.99, -0.55, 0.12]
];

// Sample precomputed positional encodings [4, 6] (typically generated via sine/cosine functions)
const positionalEncodings = [
  [0.00, 1.00, 0.00, 1.00, 0.00, 1.00],
  [0.84, 0.54, 0.09, 0.99, 0.01, 1.00],
  [0.90, -0.41, 0.19, 0.98, 0.02, 0.99],
  [0.14, -0.98, 0.29, 0.95, 0.03, 0.99]
];

// Instantiate and run kernel
const addPositionalEncoding = createPositionalEncodingKernel(seqLength, embeddingDim);
const outputTexture = addPositionalEncoding(tokenEmbeddings, positionalEncodings);

// Convert GPU texture back to standard JavaScript array (for verification/debugging)
const finalEmbeddings = outputTexture.toArray();

console.log(finalEmbeddings);

Key Optimizations

  1. Pipeline Mode (pipeline: true): Setting pipeline: true keeps the output matrix in GPU memory as a texture rather than transferring it back to the CPU via JavaScript arrays. This prevents expensive CPU-GPU data transfers when piping the result directly into multi-head self-attention kernels.
  2. Fixed Output Dimensions: The output dimensions are specified as [width, height], which corresponds to [embeddingDim, seqLength]. Transposing these dimensions in the configuration will cause memory corruption or mismatched dimension reads.
  3. Precomputing Encodings: In standard Transformer models (such as "Attention Is All You Need"), sinusoidal positional encodings are deterministic. Precompute them once on initialization or compile them into static constants to avoid dynamic recalculations during the forward pass.
