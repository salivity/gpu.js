gpu.js Type Casting: Floats and Integers Explained

Understanding how gpu.js handles numeric data types is essential for writing high-performance kernel functions. While standard JavaScript dynamically handles numbers as 64-bit floating-point values, gpu.js transpiles your JavaScript code into WebGL shaders that use GLSL (OpenGL Shading Language). Consequently, gpu.js does not provide full, automatic type casting between floats and integers during variable assignment, meaning developers must adhere to strict typing rules to avoid shader compilation errors.

The Underlying GLSL Constraint

In standard JavaScript, assigning an integer to a variable holding a float (or vice versa) happens seamlessly at runtime. However, when gpu.js compiles a kernel, it targets GLSL, a strictly typed language. In GLSL, integers (int) and floating-point numbers (float) are fundamentally different data types that occupy distinct registers. GLSL does not permit implicit type conversion across assignments or arithmetic operations.

How gpu.js Handles Literals vs. Variables

gpu.js employs static analysis and type inference during its Abstract Syntax Tree (AST) parsing phase, which leads to two distinct behaviors:

  1. Numeric Literals: When parsing literal numbers directly in your code, gpu.js can often infer the context. For instance, if you assign 1 to an inferred float variable, the transpiler may automatically convert the literal to 1.0 in the generated shader.
  2. Variable-to-Variable Assignment: gpu.js cannot reliably perform automatic type casting when assigning one variable to another if their inferred types conflict. If an identifier is inferred as an int (for example, derived from an integer loop index or bitwise operation) and you attempt to assign it directly to a variable inferred as a float, the transpiler emits raw GLSL assignments that the WebGL compiler will reject with a type mismatch error.

Best Practices for Handling Types in gpu.js

To prevent shader compilation failures when working with numbers in gpu.js:

  • Explicitly Define Literals: Always use decimal notation (such as 1.0 instead of 1) for floating-point calculations to ensure the transpiler assigns the correct GLSL type from the start.
  • Keep Operations Homogeneous: Avoid mixing integers and floats in the same expression. If you must combine values, ensure that calculations intended for float outputs consistently use floating-point operations.
  • Be Mindful of Return Types: In gpu.js kernels, the output texture type depends on how the kernel is configured. If the kernel is set to output floats, all calculations assigned to the final pixel value must evaluate to floating-point values.
