Procedural Normal Map Synthesis in GPU.js

Procedural brick, cobblestone, and tile texture normal maps can be synthesized directly in gpu.js by computing procedural height fields and calculating their spatial gradients entirely on the GPU. By leveraging WebGL fragment shaders through a JavaScript interface, gpu.js accelerates the parallel evaluation of mathematical functions, such as distance fields, modulo grids, and cellular noise, to derive height values and surface normals for every pixel in real time.

How GPU.js Enables Texture Synthesis

GPU.js compiles a subset of JavaScript into WebGL compute shaders. Because generating procedural textures requires independent, per-pixel calculations across an output grid, it is an inherently parallel task ideal for GPU acceleration. The library maps the execution across a 2D kernel matching the desired texture dimensions (such as 1024x1024 or 2048x2048), writing the resulting tangent-space normal vectors directly to an HTML canvas or raw typed arrays.

Generating Structural Heightmaps

Before deriving normal vectors, a mathematical heightmap defining the structure of the material must be evaluated:

  • Bricks: Generated using modular arithmetic to create a staggered grid. Offsetting alternate rows creates the running-bond pattern, while distance functions define the bevels between the brick face and the recessed mortar.
  • Tiles: Structured similarly to bricks using grid divisions, but typically configured with uniform spacing, square aspect ratios, and smooth continuous bevels along the edges using functions like smoothstep.
  • Cobblestone: Modeled using Voronoi or Worley noise. The kernel evaluates distances to randomized feature points to create organic cell boundaries with rounded profiles, simulating weathered stone edges.

Because GPU.js restricts external function calls, these mathematical patterns are implemented inline or via registered helper functions using standard Math methods.

Deriving the Normal Vectors

Normal maps encode surface angles as RGB color values where the Red, Green, and Blue channels correspond to the X, Y, and Z axes in tangent space. To convert a procedural height function \(H(x, y)\) into a normal map within the kernel, the finite difference method evaluates neighboring values:

  1. Gradient Estimation: The kernel computes the partial derivatives along the X and Y axes by sampling neighboring points:
    • \(dX = H(x + 1, y) - H(x - 1, y)\)
    • \(dY = H(x, y + 1) - H(x, y - 1)\)
  2. Vector Construction: A surface normal vector is constructed as \(\vec{N} = (-dX \cdot \text{strength}, -dY \cdot \text{strength}, 1.0)\).
  3. Vector Normalization: The vector is normalized by dividing each component by its Euclidean length: \(\hat{N} = \frac{\vec{N}}{\|\vec{N}\|}\).
  4. Color Space Encoding: The continuous vector components, which range from \(-1.0\) to \(1.0\), are remapped to the color interval \([0.0, 1.0]\) using the formula: \[\text{Color} = 0.5 \cdot \hat{N} + 0.5\]

A completely flat surface yields the vector \((0, 0, 1)\), mapping to RGB \((0.5, 0.5, 1.0)\), the characteristic light-purple base color of standard tangent-space normal maps.

Performance and Practical Considerations

Synthesizing normal maps procedurally in GPU.js produces seamless, resolution-independent textures without consuming disk storage or network bandwidth. Evaluating procedural math directly inside a single kernel eliminates the memory overhead of intermediate texture reads. However, loops within GPU.js functions must use static bounds to maintain compatibility with WebGL compilation limits. When configured correctly, procedural normal map generation in GPU.js executes in milliseconds, providing an efficient pipeline for dynamic surface detailing in web-based graphics engines.
