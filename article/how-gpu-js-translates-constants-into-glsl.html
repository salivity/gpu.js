How gpu.js Translates Constants into GLSL

When compiling JavaScript kernels to run on the GPU, gpu.js analyzes provided constant values and converts them into either GLSL preprocessor defines (#define) or uniform declarations (uniform). This translation depends on the data type of the constant, kernel optimization strategies, and whether the value must remain immutable at compile time. By distinguishing between static primitives and complex structures, gpu.js ensures both optimal hardware execution and efficient WebGL shader compilation.

AST Analysis and Kernel Initialization

During the initialization of a kernel, gpu.js parses the JavaScript function into an Abstract Syntax Tree (AST) using an internal JavaScript parser. When a developer provides a constants object in the kernel settings:

const kernel = gpu.createKernel(function() {
  return this.constants.factor * 2.0;
}, {
  constants: { factor: 5.5 }
});

The compiler inspects both the AST to locate references to this.constants and the runtime types of the supplied constant values. The transpiler maps identifier nodes associated with the constants namespace directly to designated GLSL names, prepending them or tracking them within a symbol table.

Static Primitives as Preprocessor Defines

For primitive types such as integers, floats, and booleans that are fixed when the kernel is built, gpu.js typically generates preprocessor #define directives directly into the GLSL shader header:

#define factor 5.5

This strategy offers two primary performance advantages:

  1. Loop Unrolling and Constant Folding: Compilers inside graphics drivers can evaluate constant arithmetic at compile time and unroll static loops that rely on fixed upper bounds.
  2. Reduced Register Pressure: Hardcoding numbers via #define eliminates the need to allocate dedicated WebGL uniform locations or use hardware uniform registers.

If a constant is an integer used as an array size or iteration boundary, injecting it as a macro ensures strict GLSL compliance, as array sizes in older WebGL specifications (WebGL 1.0 / GLSL ES 1.00) require compile-time constant expressions.

Complex Types as GLSL Uniforms

When constants represent non-primitive or larger datasets, such as arrays, vectors, or textures, generating #define directives is not syntactically viable in GLSL. In these scenarios, gpu.js registers the values as GLSL uniform variables.

  1. Vectors and Matrices: Small arrays matching standard GLSL vector dimensions (such as 2, 3, or 4 elements) are translated into declarations like uniform vec2, uniform vec3, or uniform mat4.
  2. Flat Arrays and Textures: Because WebGL 1.0 has strict limits on uniform array lengths, larger constant arrays are encoded into 2D floating-point textures. In the GLSL source, gpu.js declares these as uniform sampler2D. It then injects helper lookup functions that sample the texture coordinates corresponding to the requested array index.

Uniform Translation for Dynamic Reusability

In configurations where constants can be updated without triggering a full, expensive shader re-compilation, gpu.js switches from preprocessor substitution to uniform declarations:

uniform float factor;

During execution, gpu.js uses the WebGL API calls (such as gl.uniform1f or gl.uniform1i) to bind the updated constant values to their allocated uniform locations prior to dispatching gl.drawArrays or gl.drawElements.

The Header Injection Process

The final GLSL shader string is assembled in stages by the gpu.js kernel compiler:

  1. Type Resolution: The compiler determines the target GLSL type for each key in the constants map.
  2. Directive Generation: For macros, it appends #define KEY VALUE statements immediately following the GLSL version declaration and precision qualifiers.
  3. Uniform Declaration: For dynamic values or structured data, it adds uniform <type> KEY; lines to the global scope.
  4. AST Replacement: In the generated kernel body, references matching this.constants.KEY are renamed to the sanitized GLSL identifier, allowing the graphics driver to bind or inline the values as designated.
