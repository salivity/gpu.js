How to Analyze gpu.js Shaders with Spector.js

GPU.js compiles standard JavaScript functions into WebGL shaders to execute high-performance parallel computations on the graphics card. Because this compilation happens under the hood, inspecting and optimizing the generated GLSL code requires low-level graphics profiling. This guide explains how to integrate and use the Spector.js WebGL inspection tool to capture GPU.js execution frames, extract auto-generated fragment shaders, and analyze pipeline states.

1. Install and Enable Spector.js

Spector.js can be used either as a browser extension (available for Chrome and Firefox) or as an embedded JavaScript library within your project.

For the extension:

  • Install the Spector.js extension from the Chrome Web Store or Firefox Add-ons.
  • Open your browser's Developer Tools and navigate to the Spector tab, or look for the circular Spector icon in your browser toolbar.

For manual integration in code:

import * as SPECTOR from 'spectorjs';

const spector = new SPECTOR.Spector();
spector.displayUI();

2. Configure Your GPU.js Kernel

GPU.js creates an offscreen or inline HTML <canvas> element to access WebGL or WebGL2 contexts. Ensure your kernel runs in WebGL mode:

const { GPU } = require('gpu.js');
const gpu = new GPU({ mode: 'webgl' }); // Explicitly target WebGL

const kernel = gpu.createKernel(function(a, b) {
    return a[this.thread.x] + b[this.thread.x];
}).setOutput([512]);

If you use manual injection via the Spector.js API, pass the internal canvas instance to the capture method:

const canvas = gpu.canvas;

3. Capture the Execution Frame

GPU.js performs calculations by rendering a quad across a viewport to trigger a fragment shader on every target pixel.

  1. Load your application in the browser.
  2. In the Spector.js interface, click the red Record button to start capturing WebGL commands.
  3. Trigger your GPU.js kernel execution (e.g., call kernel(dataA, dataB)).
  4. If capturing programmatically via the API, wrap the call: 
    spector.startCapture(gpu.canvas, 1);
kernel(dataA, dataB);
spector.stopCapture();

4. Locate the Kernel Draw Call

Once the capture completes, the Spector.js inspection dashboard will automatically open:

  1. Look at the command list on the left-hand panel.
  2. Filter through the commands until you find the draw invocation—typically drawArrays or drawElements.
  3. Select this draw call. GPU.js processes compute outputs via single draw calls that map input arrays to textures and target pixels to execution threads.

5. Inspect the Generated GLSL Shader

With the draw command selected, click on the Program or Shaders tab inside the Spector.js panel:

  • Vertex Shader: GPU.js uses a minimal passthrough vertex shader to map a basic bounding rectangle onto the target render area.
  • Fragment Shader: This contains the compiled output of your original JavaScript function.

In the fragment shader panel, review:

  • Transpiled Logic: Observe how GPU.js translated conditional logic, loops, and math operations from JavaScript into GLSL syntax.
  • Texture Lookups (texture2D / texelFetch): GPU.js encodes input arrays as 2D textures. Analyze how your inputs are sampled to confirm data layout efficiency.
  • Thread Mapping: Check how this.thread.x, this.thread.y, or this.thread.z are computed relative to the fragment coordinates (gl_FragCoord).

6. Analyze Uniforms and Pipeline State

Inside the Spector.js State and Uniforms tabs for the selected draw call:

  • Inspect bound uniform variables to ensure dimensions, bounds, and scalar parameters accurately reflect the inputs passed from JavaScript.
  • Review bound textures in the Textures tab to inspect raw input data before execution and verify dimensions match expected data sizes.
  • Check frame duration and GPU pipeline overhead to identify execution bottlenecks and evaluate whether algorithmic changes reduce fragment shader complexity.
