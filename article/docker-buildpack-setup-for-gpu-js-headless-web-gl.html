Docker Buildpack Setup for gpu.js Headless WebGL

Running gpu.js in a headless Node.js environment requires compiling native OpenGL bindings such as headless-gl, which fail to build without specific operating system graphics libraries and C++ build tools. Because standard Cloud Native Buildpacks (CNBs) for Node.js use minimal base images lacking these native C/C++ and Mesa libraries, you must inject system packages before the Node.js buildpack runs. This guide walks you through configuring buildpack declarations, defining system package requirements, and building a container capable of compiling and running WebGL natively.

1. Identify Required Native Dependencies

The underlying engine used by gpu.js for server-side WebGL compilation requires the following Ubuntu/Debian native libraries:

  • build-essential and python3: Required by node-gyp to compile native C++ addons.
  • libxi-dev: Provides X11 Input extension headers.
  • libglu1-mesa-dev and libglew-dev: Provides OpenGL Utility and Extension Wrangler libraries.
  • mesa-common-dev: Provides core Mesa graphics headers.
  • libxext-dev: Provides common X extensions.

2. Configure the Apt Package Definition

To make these libraries available during the build lifecycle, create an Aptfile in the root directory of your project:

build-essential
python3
libxi-dev
libglu1-mesa-dev
libglew-dev
mesa-common-dev
libxext-dev

3. Configure the Buildpack Ordering with project.toml

Cloud Native Buildpacks execute sequentially. The system package buildpack must run first so the headers and shared objects are available on the system path when the Node.js buildpack executes npm install.

Create a project.toml file in the root of your application to chain the Paketo Apt buildpack before the Node.js buildpack:

[_]
schema-version = "0.2"

[build]
exclude = [
  ".git",
  "node_modules"
]

[[build.buildpacks]]
uri = "paketo-buildpacks/apt"

[[build.buildpacks]]
uri = "paketo-buildpacks/nodejs"

If you are using Heroku buildpacks instead of Paketo, define your buildpacks via the CLI or inside app.json:

  1. heroku-community/apt
  2. heroku/nodejs

4. Build the Docker Image with Pack CLI

Use the Cloud Native Buildpacks pack CLI to compile the container. Ensure you select a builder stack that includes the base system libraries needed for development:

pack build my-gpu-app \
  --builder pkt/builder-jammy-base \
  --descriptor project.toml

During the build phase, the Apt buildpack reads your Aptfile, downloads the .deb archives, unpacks them into a build layer, and exports the CPATH, LIBRARY_PATH, and LD_LIBRARY_PATH environment variables. The Node.js buildpack then detects package.json, invokes node-gyp rebuild for gpu.js dependencies, and links against the Mesa and GLEW headers provided by the preceding layer.

5. Verify Headless Execution

When running the container, software rendering via Mesa will handle WebGL instructions if no physical GPU hardware is passed through. Ensure your runtime environment has access to sufficient shared memory (--shm-size=1g or larger) to avoid buffer allocation errors during heavy compute tasks:

docker run --rm -it --shm-size=1g my-gpu-app
