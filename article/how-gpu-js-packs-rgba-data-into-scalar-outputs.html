How gpu.js Packs RGBA Data into Scalar Outputs

This article explains how the gpu.js library bridges the gap between WebGL's native 4-channel RGBA framebuffers and single scalar JavaScript values. It covers the underlying constraints of WebGL textures, the mathematical techniques used to encode 32-bit floating-point numbers into 8-bit color channels, channel multiplexing strategies, and the reverse unpacking pipeline during CPU readbacks.

The Architectural Constraint of WebGL Textures

WebGL shaders are fundamentally graphics pipelines designed to output vectors representing colors. When a kernel in gpu.js executes, its output is written to a target framebuffer backed by a texture. By default, WebGL framebuffers handle data in 4-component vectors: Red, Green, Blue, and Alpha (RGBA).

JavaScript computations typically work with single scalar numbers (such as floats or integers) arranged in 1D, 2D, or 3D arrays. Because graphics hardware does not natively read and write arbitrary scalar memory layouts without specialized extensions, gpu.js must translate scalar computations into 4-channel formats when writing to textures, and reverse the process when reading the data back.

IEEE-754 Floating-Point Encoding into RGBA

When hardware float texture extensions (OES_texture_float or WebGL 2 EXT_color_buffer_float) are unavailable, textures must store color components as standard 8-bit unsigned normalized integers (Uint8), yielding 32 bits of total storage per pixel across the four RGBA channels.

To store a single 32-bit IEEE-754 floating-point scalar inside a single RGBA pixel, gpu.js utilizes an encoding algorithm inside the fragment shader:

  1. Sign and Exponent Extraction: The GLSL code separates the sign bit, the 8-bit exponent, and the 23-bit mantissa of the scalar number.
  2. Byte Distribution: The 32 bits are split into four 8-bit segments.
  3. Channel Assignment:
    • Red receives the upper bits containing the sign and part of the exponent.
    • Green receives the remainder of the exponent and the upper bits of the mantissa.
    • Blue and Alpha receive the remaining bits of the mantissa.
  4. Normalization: Each 8-bit value is divided by 255.0 to produce a normalized float value between 0.0 and 1.0, which is assigned to gl_FragColor.

When unpacking this data back to a single scalar float during texture reads or CPU transfer, the inverse operation reconstructs the float:

\[\text{Scalar} = \mathbf{V} \cdot \left[ 1.0, \, \frac{1.0}{255.0}, \, \frac{1.0}{65025.0}, \, \frac{1.0}{16581375.0} \right]\]

In WebGL 2 contexts, this manual bit-shifting is bypassed using the native GLSL built-in functions packFloat2x16, unpackFloat2x16, or direct bit-casting via floatBitsToInt and uintBitsToFloat.

Channel Multiplexing (Vector Packing)

In scenarios where float textures are supported but execution throughput is prioritized, gpu.js packs four distinct scalar array elements into a single RGBA pixel rather than splitting one float across four channels.

  • Index Mapping: For an output array of length \(N\), gpu.js allocates a texture of size \(N / 4\).
  • Kernel Evaluation: The fragment shader computes four consecutive output indices \((i, i+1, i+2, i+3)\) simultaneously.
  • Channel Assignment:
    • gl_FragColor.r = output at index \(i\)
    • gl_FragColor.g = output at index \(i+1\)
    • gl_FragColor.b = output at index \(i+2\)
    • gl_FragColor.a = output at index \(i+3\)

This reduces the total number of fragment shader invocations by a factor of four, maximizing GPU vector unit utilization.

Unpacking and CPU Readback

When pulling data out of the GPU back into JavaScript, gl.readPixels() downloads the raw buffer. Depending on the packing mode chosen during kernel compilation, the final retrieval follows one of two paths:

  1. Multiplexed Readout: If four scalars were stored per pixel in a 32-bit float texture, gl.readPixels() reads directly into a Float32Array. Because the RGBA channels correspond sequentially to array indices, the flat memory representation matches standard JavaScript array ordering without additional transformations.
  2. Decoded Byte Reconstruction: If 8-bit fallback packing was used, gl.readPixels() populates a Uint8Array. gpu.js then runs a decoding pass (often via a typed array buffer view) using Float32Array(uint8Array.buffer) to reassemble the four bytes of each pixel into a valid IEEE-754 single-precision float.
