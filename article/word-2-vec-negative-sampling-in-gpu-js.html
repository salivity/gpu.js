Word2Vec Negative Sampling in GPU.js

Word2Vec skip-gram negative sampling (SGNS) loss calculation and weight updates can be fully evaluated in gpu.js by expressing vector operations as parallel WebGL shader kernels. While computing the forward pass and loss is straightforward using parallel dot products and activation functions, performing weight updates requires specific structural design to bypass WebGL limitations regarding concurrent in-place memory writes.

The SGNS Mathematics

Skip-gram with negative sampling optimizes two sets of embeddings: target embeddings (\(V\)) and context embeddings (\(U\)). For a given target word \(w\), a true context word \(c\), and \(k\) negative samples \(\{n_1, n_2, \dots, n_k\}\), the objectives are:

  1. Dot Products: Compute scores \(s_{pos} = v_w \cdot u_c\) and \(s_{neg, i} = v_w \cdot u_{n_i}\).
  2. Sigmoid Outputs: \(\sigma(s_{pos}) = \frac{1}{1 + e^{-s_{pos}}}\) and \(\sigma(-s_{neg, i}) = \frac{1}{1 + e^{s_{neg, i}}}\).
  3. Loss Function: \[\mathcal{L} = -\log(\sigma(s_{pos})) - \sum_{i=1}^{k} \log(\sigma(-s_{neg, i}))\]
  4. Gradients:
    • Error term for context: \(e_{pos} = \sigma(s_{pos}) - 1\)
    • Error term for negative samples: \(e_{neg, i} = \sigma(s_{neg, i})\)
    • Context updates: \(\Delta u_c = -\eta \cdot e_{pos} \cdot v_w\)
    • Negative sample updates: \(\Delta u_{n_i} = -\eta \cdot e_{neg, i} \cdot v_w\)
    • Target update: \(\Delta v_w = -\eta \left( e_{pos} \cdot u_c + \sum_{i=1}^k e_{neg, i} \cdot u_{n_i} \right)\)

Evaluating Loss in gpu.js

The forward pass and loss evaluation map naturally to gpu.js kernels because they represent pure, read-only computations that output new values.

const computeLossKernel = gpu.createKernel(function(targets, contexts, negatives, V, U, k, embeddingDim) {
    let batchIdx = this.thread.x;
    let targetIdx = targets[batchIdx];
    let contextIdx = contexts[batchIdx];

    // Compute positive dot product
    let posDot = 0.0;
    for (let d = 0; d < embeddingDim; d++) {
        posDot += V[targetIdx][d] * U[contextIdx][d];
    }
    let posSigmoid = 1.0 / (1.0 + Math.exp(-posDot));
    let loss = -Math.log(Math.max(posSigmoid, 1e-7));

    // Compute negative sample dot products and loss
    for (let i = 0; i < k; i++) {
        let negIdx = negatives[batchIdx][i];
        let negDot = 0.0;
        for (let d = 0; d < embeddingDim; d++) {
            negDot += V[targetIdx][d] * U[negIdx][d];
        }
        let negSigmoid = 1.0 / (1.0 + Math.exp(-negDot));
        loss += -Math.log(Math.max(1.0 - negSigmoid, 1e-7));
    }

    return loss;
}).setOutput([batchSize]);

Evaluating Weight Updates in gpu.js

Standard Word2Vec in C or CPU implementations uses sparse, in-place updates where threads directly mutate weights at specific word indices. WebGL shaders cannot perform arbitrary random-access writes (scatter operations) to shared memory due to lack of write-locking mechanisms and race conditions.

To execute weight updates in gpu.js, you must use one of two architectural patterns:

1. Delta Matrix Accumulation

You compute a dense gradient matrix \(\Delta V\) and \(\Delta U\) of dimensions [vocabularySize, embeddingDim]. A kernel processes the batch and accumulates updates into these matrices. Once computed, a second element-wise update kernel applies the changes:

const applyUpdateKernel = gpu.createKernel(function(Weights, Gradients, learningRate) {
    return Weights[this.thread.y][this.thread.x] - (learningRate * Gradients[this.thread.y][this.thread.x]);
}).setOutput([embeddingDim, vocabularySize]);

2. Full Matrix Reconstruction Kernel

Instead of computing deltas, a kernel reconstructs the entire embedding matrix on each step. The kernel maps over [embeddingDim, vocabularySize]. For thread (dim, wordIndex), the kernel checks if wordIndex was involved in the current batch:

  • If wordIndex was not in the batch, return the original weight Weights[wordIndex][dim].
  • If wordIndex was in the batch, aggregate the corresponding gradient updates and return the updated weight value.

Performance Considerations

  • Pipeline Mode: Set pipeline: true on gpu.js kernels. This keeps the embedding matrices stored directly as WebGL textures on the GPU between the loss and update steps, avoiding costly transfers over the CPU-GPU bus.
  • Precision: WebGL targets often default to 16-bit or 32-bit single-precision floats. Ensure numeric stability in sigmoid and logarithm operations using clamping (Math.max(val, 1e-7)) to prevent NaN values.
  • Batching: GPU parallelization only becomes efficient with large mini-batch sizes. Processing single \((w, c)\) pairs sequentially on gpu.js causes excessive overhead compared to multi-threaded CPU implementations.
