Why Multiple gpu.js Tabs Cause WebGL Context Loss

Running gpu.js across multiple browser tabs frequently causes the oldest tabs to stop computing or throw errors due to automatic WebGL context eviction. This article examines the underlying browser mechanics responsible for this behavior, specifically focusing on hardware resource limits, the browser’s internal context-caching policies, and how the Least Recently Used (LRU) algorithm forces background gpu.js instances to terminate their graphics pipelines.

The Underlying Dependency on WebGL

gpu.js operates by translating standard JavaScript functions into GLSL (OpenGL Shading Language) and executing them on the device’s graphics processing unit. To communicate with the GPU, the library instantiates a WebGLRenderingContext or WebGL2RenderingContext using an HTML5 <canvas> element behind the scenes. Consequently, gpu.js is bound entirely to the lifecycle rules, security sandboxes, and resource constraints that modern web browsers impose on WebGL.

Browser WebGL Context Limits

Every operating system and GPU driver has a finite amount of video RAM (VRAM) and hardware pipeline handles available to user-space processes. To prevent a malicious or poorly optimized website from consuming all available VRAM, locking the operating system, or crashing graphics drivers, web browsers implement a hard limit on the number of concurrent, active WebGL contexts allowed across all tabs and frames.

In Chromium-based browsers (such as Google Chrome, Microsoft Edge, and Brave) and Mozilla Firefox, this limit typically defaults to between 8 and 16 active contexts, depending on the platform, underlying GPU architecture, and whether hardware acceleration is fully supported.

The Least Recently Used (LRU) Eviction Mechanism

When a browser tab initializes a new gpu.js instance, it requests a new WebGL context. If the total number of open contexts across all open tabs exceeds the browser's predetermined threshold, the browser graphics engine does not refuse the new request. Instead, it frees up resources by evicting an existing context using a Least Recently Used (LRU) eviction strategy.

Under the LRU policy, the browser identifies the context that has remained inactive for the longest duration—which is almost always the oldest background tab. The browser then dispatches a webglcontextlost event to that context, releases its allocated textures, framebuffers, and shaders from VRAM, and hands the freshly cleared hardware resources to the newest tab.

The Impact on gpu.js Kernels

Because gpu.js relies on persistent textures and pre-compiled shaders cached inside the WebGL state machine, an eviction immediately breaks the computation pipeline in the affected tab. If the user returns to the older tab or if that tab attempts to run a background computation:

  • Kernels will fail silently or throw runtime errors indicating that the WebGL context is null or unavailable.
  • Cached data stored inside GPU textures becomes invalid, meaning input matrices and calculated outputs cannot be read back to the CPU.
  • The execution cannot automatically recover unless the application explicitly handles context recreation.

Mitigating Context Loss in gpu.js

To prevent or handle context eviction when running multi-tab or compute-heavy web applications:

  1. Destroy Inactive Instances: Explicitly invoke the destroy() method on the gpu.js instance whenever a calculation completes or when a user navigates away from the page. This immediately releases the WebGL context instead of leaving it in an idle state.
  2. Listen for Context Events: Attach event listeners to the underlying canvas element for webglcontextlost and webglcontextrestored. When lost, prevent default behavior to signal to the browser that recovery is intended, and recompile the required gpu.js kernels when restored.
  3. Use CPU Fallbacks: Initialize gpu.js with fallback settings enabled (mode: 'gpu', which falls back to CPU if initialization fails or context is unavailable) to ensure that background tasks continue executing, albeit at non-accelerated speeds.
