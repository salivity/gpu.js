Bounding Math.asin and Math.acos in gpu.js

In GPU-accelerated computing with gpu.js, evaluating inverse trigonometric functions like Math.asin() and Math.acos() can lead to unexpected NaN values due to minor floating-point inaccuracies that push numbers outside the valid [-1, 1] domain. This article explains why these domain overflow errors occur in GPU kernels and demonstrates how to safely clamp inputs using native JavaScript mathematical functions supported by the gpu.js compiler.

The Problem: Floating-Point Precision and NaN

Both \(\arcsin(x)\) and \(\arccos(x)\) are strictly defined for inputs in the range \(-1 \le x \le 1\). In mathematical theory, intermediate calculations such as vector normalization or dot products naturally fall within this range. However, 32-bit floating-point arithmetic on the GPU often introduces minute rounding errors.

A calculation that should theoretically yield 1.0 might result in 1.000000119. While this discrepancy is negligible in many contexts, passing it to Math.asin() or Math.acos() causes the underlying GLSL shader to return NaN (Not-a-Number). Once introduced, NaN propagates through subsequent operations, invalidating kernel results.

The Solution: Manual Clamping

Standard WebGL and GLSL feature a built-in clamp() function. In gpu.js, the most reliable and idiomatic way to achieve the same result without relying on unsupported language extensions is combining Math.max() and Math.min().

Before passing any value to Math.asin() or Math.acos(), bound the value to the [-1.0, 1.0] interval:

function clampToTrigDomain(val) {
  return Math.max(-1.0, Math.min(1.0, val));
}

Implementing Safe Bounds in a gpu.js Kernel

gpu.js allows helper functions to be passed into kernels or written directly inline. When writing kernels, ensure all numeric bounds are written as floating-point numbers to prevent casting issues in the generated shader code.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel calculating safe arc-cosine of values
const safeAcosKernel = gpu.createKernel(function (values) {
  const rawValue = values[this.thread.x];
  
  // Bound the input strictly between -1.0 and 1.0
  const boundedValue = Math.max(-1.0, Math.min(1.0, rawValue));
  
  return Math.acos(boundedValue);
}).setOutput([values.length]);

Best Practices

  1. Avoid Conditional Branching: Using Math.max() and Math.min() compiles directly to hardware-supported operations (min and max instructions in GLSL), avoiding if/else control flow divergence across GPU threads.
  2. Handle Edge Cases Early: Clamp immediately after the operation that causes instability, such as dot products or vector normalizations, rather than right before the trigonometric call. This ensures downstream calculations remain mathematically sound.
