Unit Testing gpu.js Texture Deallocation

Properly managing GPU memory is essential when working with gpu.js, as orphaned WebGL textures can rapidly exhaust VRAM and degrade performance. This article outlines the specific assertions required in unit tests to verify that gpu.js textures are completely deallocated. By inspecting WebGL context calls, verifying internal object state mutations, and testing post-deletion execution barriers, you can ensure reliable cleanup routines in your computational pipelines.

1. Spy on WebGL deleteTexture Invocations

gpu.js abstracts the underlying WebGL context, but texture deallocation ultimately relies on the WebGL API call gl.deleteTexture(). The most direct assertion verifies that this method was called with the underlying native texture object.

When using a testing environment like Jest or Vitest alongside a mock or headless WebGL context (such as headless-gl), set a spy directly on the active context's deleteTexture method:

const gl = gpu.context;
const deleteTextureSpy = jest.spyOn(gl, 'deleteTexture');

const texture = kernel();
const nativeTexture = texture.texture;

texture.delete();

expect(deleteTextureSpy).toHaveBeenCalledTimes(1);
expect(deleteTextureSpy).toHaveBeenCalledWith(nativeTexture);

This ensures the cleanup request traversed the gpu.js wrapper down to the GPU driver level.

2. Assert Internal Texture References are Nullified

Once deallocated, the texture wrapper should no longer hold references to the native WebGL texture. Retaining the reference inside JavaScript prevents complete garbage collection of the host-side handles.

Assert that internal properties tracking the GPU buffer are cleared:

texture.delete();

expect(texture.texture).toBeNull();

Depending on the version of gpu.js, some internal tracking flags such as texture.isDestroyed or texture.isActive may also be set. Asserting that these lifecycle properties reflect the destroyed state confirms the wrapper has invalidated itself.

3. Assert Post-Deallocation Access Throws Errors

A deallocated texture should be unusable. An effective assertion pattern tests that attempting to read from or bind the deallocated texture produces an immediate failure rather than silently executing with undefined state or reading stale GPU memory.

Assert that downstream conversions or pipeline steps throw:

texture.delete();

expect(() => {
  texture.toArray();
}).toThrow();

expect(() => {
  subsequentKernel(texture);
}).toThrow();

Testing this boundary guarantees that the system cannot proceed using an invalidated WebGL resource.

4. Assert Kernel and Context Cleanup Hooks

When textures are created via intermediate pipeline outputs or mode settings like pipeline: true, kernels often hold an internal cache or reference to output textures. If your workflow uses kernel.destroy() or manual pipeline flushing, write assertions to verify that all retained sub-textures are removed from the kernel's tracking structures:

const initialTexture = kernel();
kernel.destroy();

expect(kernel.subKernels.every(k => k.texture === null)).toBe(true);

Checking that intermediate collection arrays or texture pools are empty ensures that continuous kernel execution does not accumulate leaked textures over time.
