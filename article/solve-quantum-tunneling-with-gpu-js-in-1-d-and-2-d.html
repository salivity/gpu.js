Solve Quantum Tunneling with gpu.js in 1D and 2D

Quantum tunneling through arbitrary one-dimensional (1D) and two-dimensional (2D) potential barriers can indeed be numerically solved using gpu.js. By translating the Time-Dependent Schrödinger Equation (TDSE) into discrete numerical schemes such as finite-difference time-domain (FDTD) or split-operator methods, gpu.js accelerates the required matrix and stencil computations directly in the browser using WebGL shaders. This article explores the mathematical foundations, implementation strategy, and practical computational constraints of running quantum tunneling simulations on the GPU with gpu.js.

Mathematical Framework

Quantum tunneling is governed by the Time-Dependent Schrödinger Equation:

\[i\hbar \frac{\partial \psi(\mathbf{r}, t)}{\partial t} = \left( -\frac{\hbar^2}{2m}\nabla^2 + V(\mathbf{r}) \right) \psi(\mathbf{r}, t)\]

To simulate this equation numerically, the complex wavefunction \(\psi(\mathbf{r}, t)\) is typically split into real (\(R\)) and imaginary (\(I\)) components:

\[\psi(\mathbf{r}, t) = R(\mathbf{r}, t) + i I(\mathbf{r}, t)\]

This decomposition results in two coupled real differential equations:

\[\hbar \frac{\partial R}{\partial t} = -\frac{\hbar^2}{2m}\nabla^2 I + V(\mathbf{r}) I\] \[\hbar \frac{\partial I}{\partial t} = \frac{\hbar^2}{2m}\nabla^2 R - V(\mathbf{r}) R\]

Arbitrary barriers are represented by defining an arbitrary scalar potential field \(V(\mathbf{r})\) on the grid, such as rectangular steps, multiple Gaussian barriers, or complex geometric obstacles in 2D space.

Implementing the Solver with gpu.js

gpu.js compiles standard JavaScript functions into GLSL shaders, executing parallel operations across millions of grid points simultaneously. The simulation loop typically uses a staggered leapfrog finite-difference algorithm:

  1. State Representation: The domain is discretized into a uniform grid. For 1D simulations, this is an array of size \(N\); for 2D, a matrix of size \(N \times M\). Two textures or 2D arrays store the real (\(R\)) and imaginary (\(I\)) components, while a third static array stores the arbitrary potential values \(V\).
  2. Stencil Operations: gpu.js kernels compute the Laplacian (\(\nabla^2\)) using standard central finite-difference stencils:
    • 1D Laplacian: \(\nabla^2 \psi_x \approx \frac{\psi_{x+1} - 2\psi_x + \psi_{x-1}}{\Delta x^2}\)
    • 2D Laplacian: \(\nabla^2 \psi_{x,y} \approx \frac{\psi_{x+1,y} + \psi_{x-1,y} + \psi_{x,y+1} + \psi_{x,y-1} - 4\psi_{x,y}}{\Delta x^2}\)
  3. Alternating Time Updates: A kernel evaluates the update for \(R\) using the spatial derivative of \(I\), followed by a second kernel evaluation updating \(I\) using the newly calculated \(R\).

Because gpu.js allows arbitrary JavaScript arrays to be passed as inputs, users can generate any arbitrary potential function dynamically—such as importing an image mask or drawing custom barriers on an HTML canvas—and bind it directly as the potential matrix \(V(x, y)\).

1D vs. 2D Performance Profile

  • 1D Simulations: For 1D systems (typically \(10^3\) to \(10^4\) points), CPU-based implementations in plain JavaScript or WebAssembly can occasionally match or exceed gpu.js due to CPU-to-GPU data transfer overhead. However, gpu.js handles these trivially at high frame rates.
  • 2D Simulations: For 2D domains (e.g., \(512 \times 512\) or \(1024 \times 1024\) nodes), CPU computations quickly become too slow for real-time rendering. The high degree of data parallelism in evaluating the 2D Laplacian makes gpu.js an ideal tool, providing real-time wavepacket scattering and tunneling visualization directly in web browsers.

Technical Challenges and Constraints

While gpu.js is capable of solving this system, several numerical factors must be managed:

  • Floating-Point Precision: gpu.js primarily operates using 32-bit single-precision floating-point numbers (float32). While sufficient for qualitative visualization and basic quantitative tunneling probabilities, 32-bit precision can introduce phase drift and norm non-conservation over extended simulation runtimes compared to 64-bit scientific desktop codes.
  • Boundary Reflections: Finite numerical grids suffer from unphysical reflections when the wavepacket reaches the boundaries. To accurately measure tunneling transmission coefficients without boundary artifacts, absorbing boundary conditions (such as a complex absorbing potential or perfectly matched layers) must be incorporated into the edge regions of the \(V(\mathbf{r})\) grid.
  • Numerical Stability: The time step \(\Delta t\) and spatial step \(\Delta x\) must satisfy the Courant-Friedrichs-Lewy (CFL) stability criterion:

\[\Delta t < \frac{2m}{\hbar} \left( \frac{1}{\Delta x^2} + \frac{1}{\Delta y^2} \right)^{-1}\]

Exceeding this threshold results in rapid numerical divergence within the gpu.js kernel.
