How GPU.js Restricts External Variable Mutation

GPU.js prevents the mutation of external variables outside a kernel's local scope through a combination of static abstract syntax tree (AST) validation, transpilation into read-only shader structures, and the fundamental memory isolation between the CPU and GPU. Because GPU kernels are designed to execute massively parallel operations across thousands of independent threads, allowing side effects or external variable mutations would break deterministic execution and violate the hardware constraints of graphics processors.

Abstract Syntax Tree (AST) Parsing and Validation

When a JavaScript function is passed into gpu.js to create a kernel, the library does not execute the function directly within the standard JavaScript runtime. Instead, it extracts the function's string representation and parses it into an Abstract Syntax Tree (AST) using a JavaScript parser.

During this parsing phase, GPU.js performs semantic validation on the code:

  • Scope Traversal: The compiler analyzes variable declarations to identify whether an identifier is local to the kernel or defined in an outer scope.
  • Assignment Detection: If the AST detects an assignment operator (such as =, +=, or ++) targeting an identifier that was not declared with let, const, or var inside the kernel block, the compilation process halts immediately.
  • Compile-Time Errors: Instead of allowing the assignment to fail silently or behave unpredictably, GPU.js throws a compile-time error indicating that external variables cannot be modified.

Transpilation to Read-Only Shader Uniforms

GPU.js converts kernel logic into WebGL or WebGPU shader code (typically GLSL). In graphics programming, data passed from the host environment (the CPU) into the shader pipeline (the GPU) is treated as uniform input:

  • Conversion to Uniforms: External variables passed as parameters or referenced via the constants configuration are translated into shader uniform variables.
  • GLSL Immutability Rules: Under GLSL specifications, uniform variables are strictly read-only within the execution of the shader. They represent constant values across all parallel executions of a single draw call.
  • Hardware-Level Rejection: If an assignment to a uniform somehow bypassed the initial JavaScript AST validation, the native GLSL compiler provided by the browser's graphics driver would fail to compile the shader, raising a shader compilation error.

Architectural Memory Isolation

The execution model of GPU hardware naturally restricts external mutations due to the physical separation of CPU and GPU memory:

  • Distinct Memory Pools: JavaScript variables exist within the host system's RAM allocated to the browser process. Shaders run exclusively within the VRAM of the graphics hardware.
  • One-Way Data Transfer: Data sent to the GPU is copied to VRAM buffers or encoded into textures. The kernel threads read from these buffers and write their output exclusively to a designated output framebuffer or target texture.
  • No Pointer Access to the Host Heap: A GPU thread possesses no pointers or references to the JavaScript heap. Consequently, it is physically impossible for a shader running on the GPU to write back to a CPU-bound JavaScript closure variable during execution.

Consistency Across CPU Fallback Mode

When WebGL or WebGPU is unsupported, GPU.js falls back to a multi-threaded or loop-based CPU execution mode. To ensure identical behavior between the GPU and the CPU fallback:

  • The engine enforces the same AST validation checks in CPU mode as it does in GPU mode.
  • External arguments and constants are cloned or scoped strictly to the execution context to prevent accidental mutations of host state.
  • The only supported mechanism for returning data from a kernel remains the kernel's return value, which represents the computed output array or texture.
