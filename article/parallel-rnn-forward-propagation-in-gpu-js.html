Parallel RNN Forward Propagation in GPU.js

Parallelizing recurrent neural network (RNN) forward propagation across time steps in GPU.js requires overcoming the inherently sequential temporal dependency \(h_t = f(W_{hh}h_{t-1} + W_{xh}x_t + b)\). While standard non-linear RNNs enforce step-by-step state propagation, you can achieve massive parallelism across time by separating linear input projections from recurrent updates, reformulating linear recurrences into parallel prefix scans, and parallelizing across batch and feature dimensions simultaneously. This article demonstrates how to decouple these operations and implement them efficiently using GPU.js kernels.

The Fundamental Dependency Problem

In a standard RNN cell, the hidden state at time step \(t\) strictly depends on the hidden state at \(t-1\):

\[h_t = \tanh(W_{xh}x_t + W_{hh}h_{t-1} + b)\]

Because the non-linear activation (\(\tanh\)) wraps the sum of both the current input and the previous hidden state, step \(t\) cannot be computed until step \(t-1\) completes. To optimize this on the GPU using GPU.js, computation must be divided into operations that are independent across time and operations that can be reduced logarithmically.

Strategy 1: Pre-computing Input Transformations

The matrix multiplication \(W_{xh}x_t\) for all time steps \(t \in [1, T]\) is completely independent of the recurrent state. Instead of computing this sequentially inside a loop, you can concatenate all inputs across time into a single matrix and compute the entire sequence projection in parallel with a single 2D or 3D GPU.js kernel.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Parallel dense projection across all time steps and batch items
// Inputs: X [sequence_length, batch_size, input_dim]
// Weights: W_xh [hidden_dim, input_dim]
const precomputeInputKernel = gpu.createKernel(function(X, W_xh, bias, seqLen, inputDim) {
    const hiddenIdx = this.thread.x;
    const batchIdx = this.thread.y;
    const timeIdx = this.thread.z;

    let sum = bias[hiddenIdx];
    for (let i = 0; i < inputDim; i++) {
        sum += W_xh[hiddenIdx][i] * X[timeIdx][batchIdx][i];
    }
    return sum;
})
.setOutput([HIDDEN_DIM, BATCH_SIZE, SEQUENCE_LENGTH]);

Executing this kernel computes all time-step input transformations concurrently across GPU threads, removing the \(W_{xh}x_t\) bottleneck from the temporal loop.

Strategy 2: Parallelizing via Associative Scans (Linear RNNs)

If the recurrence relation is strictly linear (such as in Quasi-RNNs, S4, or Linear Recurrent Units), the sequential update can be written as:

\[h_t = A_t h_{t-1} + B_t x_t\]

Because matrix/scalar multiplication and addition are associative, this recurrence can be framed as a parallel prefix scan (Blelloch scan). This reduces the sequential time complexity from \(O(T)\) to \(O(\log T)\) steps across the time dimension.

In GPU.js, a multi-pass parallel scan works as follows:

  1. Upsweep (Reduction Phase): Compute intermediate cumulative products of the transition coefficients \(A_t\) across pairs of time steps in parallel.
  2. Downsweep Phase: Distribute the computed accumulated states back down the tree to resolve all time steps simultaneously.
// Example: Parallel prefix step across the temporal dimension
const parallelScanStepKernel = gpu.createKernel(function(H, A, offset, seqLen) {
    const t = this.thread.x;
    const featureIdx = this.thread.y;

    if (t >= offset) {
        return H[featureIdx][t] + A[featureIdx][t] * H[featureIdx][t - offset];
    } else {
        return H[featureIdx][t];
    }
})
.setOutput([SEQUENCE_LENGTH, HIDDEN_DIM]);

By iteratively doubling offset (\(1, 2, 4, 8, \dots\)) through separate kernel calls, all \(T\) time steps are fully evaluated in \(\log_2(T)\) GPU iterations instead of \(T\) sequential iterations.

Strategy 3: Pipelined Sequential Execution with Maximum Inner Parallelism

For standard non-linear RNNs (LSTM, GRU, Vanilla RNN) where associative scans cannot bypass the non-linearity, true cross-time parallelization is mathematically restricted. In this scenario, the optimal GPU.js pipeline parallelizes the spatial dimensions (hidden units and batch items) at each time step while driving the temporal loop from JavaScript:

  1. Precompute: Run the 3D tensor kernel for all \(W_{xh} X\) combinations.
  2. Step Loop: Execute a reusable kernel for the state update:
const rnnStepKernel = gpu.createKernel(function(precomputedInputs, h_prev, W_hh, timeStep, hiddenDim) {
    const hIdx = this.thread.x;
    const bIdx = this.thread.y;

    // Retrieve the pre-computed W_xh * x_t value
    let sum = precomputedInputs[timeStep][bIdx][hIdx];

    // Compute recurrent dot product
    for (let i = 0; i < hiddenDim; i++) {
        sum += W_hh[hIdx][i] * h_prev[bIdx][i];
    }

    // Apply non-linearity
    return Math.tanh(sum);
})
.setOutput([HIDDEN_DIM, BATCH_SIZE])
.setPipeline(true); // Keeps texture in GPU memory to prevent CPU-GPU stalls

// Execution loop over time
let currentH = initialHiddenState;
for (let t = 0; t < SEQUENCE_LENGTH; t++) {
    currentH = rnnStepKernel(precomputedInputs, currentH, W_hh, t, HIDDEN_DIM);
}

Summary of Performance Considerations in GPU.js

  • Memory Pipeline: Always enable .setPipeline(true) on sequential step kernels to prevent GPU.js from reading framebuffers back to the CPU between time steps.
  • Dimensional Locality: Map the fastest-moving index (this.thread.x) to the hidden dimension size to maintain coalesced memory reads inside the dot-product loops.
  • Architecture Choice: If full parallelization across time is required, transition the network design from standard tanh/sigmoid recurrent units to linear recurrent layers that natively support prefix scans.
