WebGL Hardware Acceleration in Capacitor for GPU.js

Running high-performance compute tasks with gpu.js inside a Capacitor application requires direct access to the mobile device's graphics hardware through the underlying WebView. By default, hybrid mobile containers may throttle or restrict WebGL contexts to save battery or maintain compatibility, causing gpu.js to silently fall back to slow CPU execution. This guide explains the precise native and web-level configurations required to unlock full WebGL 1.0/2.0 hardware acceleration for gpu.js on Android and iOS.

Android Configuration

Android's default WebView configuration often limits WebGL capabilities unless hardware acceleration is explicitly enforced at the OS level.

  1. Enable Hardware Acceleration in the Manifest: Open android/app/src/main/AndroidManifest.xml and ensure that android:hardwareAccelerated="true" is declared on both the <application> and <activity> tags:

    <application
    android:hardwareAccelerated="true"
    android:hasCode="true"
    ...>
    <activity
        android:name=".MainActivity"
        android:hardwareAccelerated="true"
        ...>
    </activity>
</application>

  2. Force WebView Hardware Layer in MainActivity.java: In some devices, the WebView disables hardware rasterization dynamically. You can enforce it programmatically by modifying android/app/src/main/java/.../MainActivity.java:

    package com.example.app;

import android.os.Bundle;
import android.webkit.WebSettings;
import android.view.View;
import com.getcapacitor.BridgeActivity;

public class MainActivity extends BridgeActivity {
    @Override
    public void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        
        // Enforce hardware acceleration layer on the bridge WebView
        this.bridge.getWebView().setLayerType(View.LAYER_TYPE_HARDWARE, null);
        
        // Ensure DOM storage and WebGL caching are enabled
        WebSettings settings = this.bridge.getWebView().getSettings();
        settings.setJavaScriptEnabled(true);
        settings.setDomStorageEnabled(true);
    }
}

iOS Configuration

iOS uses WKWebView, which runs WebGL workloads through Apple's Metal framework. Full hardware acceleration is standard, but you must prevent the system from throttling background processing and memory allocation.

  1. Configure Capacitor Options (capacitor.config.ts): Ensure limitsNavigationsToAppBoundDomains is disabled unless strictly needed, as it can restrict high-performance APIs inside WKWebView:

    import { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.example.app',
  appName: 'gpu-app',
  webDir: 'dist',
  server: {
    androidScheme: 'https'
  },
  ios: {
    contentInset: 'always',
    preferredContentMode: 'mobile'
  }
};

export default config;

  2. Prevent Background WebGL Context Destruction: Add the following entry to ios/App/App/Info.plist to prevent premature context loss during minor memory spikes:

    <key>WKAppBoundDomains</key>
<array/>

Configuring gpu.js for Hardware Enforcement

To prevent gpu.js from quietly falling back to CPU mode when native WebGL initialization fails, configure the GPU instance to strictly enforce GPU mode and query available extensions.

import { GPU } from 'gpu.js';

// Force GPU mode; this throws an error if WebGL hardware support is missing
const gpu = new GPU({
  mode: 'gpu',
  webGl: null // Allows gpu.js to detect and choose the best available context (WebGL 2 or 1)
});

// Verify hardware execution support
if (!GPU.isGPUSupported) {
  console.error("Hardware-accelerated WebGL is not supported on this device/WebView.");
}

// Handle WebGL context loss events triggered by mobile lifecycle changes
const canvas = gpu.canvas;
if (canvas) {
  canvas.addEventListener('webglcontextlost', (event) => {
    event.preventDefault();
    console.warn("WebGL Context Lost. Halting GPU calculations.");
  }, false);

  canvas.addEventListener('webglcontextrestored', () => {
    console.info("WebGL Context Restored. Re-initializing kernels.");
    // Re-create your gpu.js kernels here
  }, false);
}

By enforcing android:hardwareAccelerated="true", ensuring setLayerType(View.LAYER_TYPE_HARDWARE, null) on the Android bridge, and configuring gpu.js with { mode: 'gpu' }, your Capacitor application will fully utilize the device GPU for matrix operations and parallel compute tasks.
