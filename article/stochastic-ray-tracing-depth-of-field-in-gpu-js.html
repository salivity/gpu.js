Stochastic Ray Tracing Depth-of-Field in gpu.js

Synthesizing realistic depth-of-field (DoF) camera blur using stochastic ray sampling is entirely feasible in gpu.js. By compiling JavaScript functions into WebGL fragment shaders, gpu.js allows developers to implement a thin-lens camera model that simulates real-world optical characteristics directly on the GPU. This article explains how stochastic ray sampling produces physically accurate depth of field, how to implement the math within gpu.js, and the architectural workarounds required to manage GPU-based randomness and sample accumulation.

The Thin-Lens Model

Standard 3D computer graphics often rely on a pinhole camera model, where all visual rays originate from an infinitely small single point in space. This model produces images where every object remains sharply in focus regardless of its distance from the camera.

To achieve physical depth of field, the pinhole must be replaced with a thin-lens camera model:

  1. Aperture: Instead of a single origin point, rays originate from different random locations across a lens disk of a specified radius.
  2. Focal Plane: A specific distance from the camera where objects appear completely sharp.
  3. Focal Point: For any given pixel, a primary ray is calculated to locate the target point on the focal plane. All stochastic rays generated for that pixel across the aperture will converge on this same focal point.

Objects located exactly on the focal plane will align across all samples, remaining sharp. Objects in front of or behind the focal plane will project across different screen positions, naturally creating a soft, blurred circle of confusion (bokeh).

Implementing Stochastic Sampling in gpu.js

Because gpu.js compiles JavaScript into GLSL, it executes within the limitations of standard WebGL shaders. Implementing stochastic DoF requires solving two primary challenges: pseudo-random number generation and sample distribution.

1. Shader-Based Pseudo-Random Numbers

GLSL lacks a native Math.random() function. To produce stochastic variations across rays, you must implement a deterministic pseudo-random number generator (PRNG) inside your gpu.js kernel. A common method is a hash function using the pixel coordinates (this.thread.x, this.thread.y) and an external seed (such as a frame index or time uniform):

function fract(x) {
  return x - Math.floor(x);
}

function random(seed) {
  return fract(Math.sin(seed) * 43758.5453123);
}

2. Aperture Sampling

To position the ray origin on the lens, generate two random values to sample a point within a unit disk. Concentric disk mapping or polar coordinate sampling transforms uniform random variables into circular lens offsets:

  • Sample an angle: \(\theta = 2\pi \times \text{rand}_1\)
  • Sample a radius: \(r = \text{apertureRadius} \times \sqrt{\text{rand}_2}\)
  • Offset origin: \(X_{\text{offset}} = r \times \cos(\theta)\), \(Y_{\text{offset}} = r \times \sin(\theta)\)

3. Calculating the Jittered Ray

For each sample of a target pixel:

  1. Compute the focal point: \(\vec{P}_{\text{focus}} = \vec{O}_{\text{camera}} + \vec{D}_{\text{primary}} \times \text{focalDistance}\).
  2. Shift the ray origin along the camera's local right and up axes by the lens offsets.
  3. Compute the new ray direction: \(\vec{D}_{\text{sampled}} = \text{normalize}(\vec{P}_{\text{focus}} - \vec{O}_{\text{jittered}})\).
  4. Trace the ray into the scene and compute color intersections.

Performance and Noise Management

Stochastic sampling introduces high-frequency visual noise (grain) when sample counts are low. Addressing this in gpu.js requires choosing between multi-sampling and temporal accumulation:

  • Internal Multi-Sampling: Running a loop inside a single gpu.js kernel execution to compute 16–64 samples per pixel. While straightforward, this can lead to GPU execution timeouts (WebGL context loss) if the scene complexity is high.
  • Progressive Temporal Accumulation: The optimal approach is running a single-sample kernel per frame and averaging the output into an accumulation texture over time using a ping-pong buffer technique. When the camera is stationary, the image progressively converges into a smooth, noise-free depth-of-field blur.

Conclusion

Depth-of-field blur using stochastic ray sampling is fully viable in gpu.js. By incorporating a GPU-compatible PRNG, mapping ray offsets to a thin-lens model, and accumulating samples over multiple iterations, developers can produce physically accurate optical blur effects purely through JavaScript-driven WebGL shaders.
