Parallel Pollard's Rho Factorization in GPU.js

This article explains how to implement a parallelized version of Pollard's rho algorithm for integer factorization using GPU.js. By distributing independent pseudo-random polynomial walks across hundreds or thousands of GPU threads, you can significantly accelerate the discovery of non-trivial factors of composite numbers. Below, we cover the parallelization strategy, address hardware constraints such as integer precision in WebGL, and provide an end-to-end implementation.

Understanding Parallel Pollard's Rho

Standard Pollard's rho algorithm uses a polynomial function—typically \(f(x) = (x^2 + c) \pmod N\)—to generate a pseudo-random sequence of numbers. Because the state space is finite, the sequence eventually falls into a cycle. By tracking two pointers (Floyd’s cycle-finding or Brent’s algorithm) and calculating the greatest common divisor \(\gcd(|x - y|, N)\), a non-trivial factor can often be found in \(\mathcal{O}(N^{1/4})\) steps.

To parallelize this process:

  1. Thread Independence: Assign each GPU thread an independent walk with a distinct starting value \(x_0\) or a unique constant \(c\).
  2. Step Execution: Each thread advances its sequence for a fixed number of iterations.
  3. GCD Evaluation: Threads check for factors using Euclid's algorithm periodically or at each step.
  4. Result Collection: If any thread discovers a non-trivial factor (\(1 < \gcd < N\)), that factor is returned to the CPU.

GPU.js Constraints and Considerations

GPU.js compiles JavaScript functions into WebGL shaders. This introduces specific constraints:

  • Precision: Standard WebGL shaders operate with 32-bit floating-point or 32-bit signed integer values. Therefore, intermediate values such as \(x^2\) must not overflow the precision limit. For larger numbers, multi-word modular arithmetic must be implemented manually.
  • Dynamic Control Flow: Avoid deeply nested or highly divergent branch statements to maintain high GPU throughput.
  • Shared Memory: WebGL fragment shaders do not share memory across threads, making independent random walks with fixed iteration counts the ideal approach.

Implementation Steps

1. Setup and Helper Functions

First, install and import gpu.js. Define custom GPU functions for modular arithmetic and the Euclidean algorithm.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Euclidean algorithm for GCD
gpu.addFunction(function gcd(a, b) {
  while (b !== 0) {
    let t = b;
    b = a % b;
    a = t;
  }
  return a;
});

// Modular multiplication to prevent 32-bit overflow when squaring
gpu.addFunction(function modMult(a, b, m) {
  let res = 0;
  let x = a % m;
  let y = b;
  while (y > 0) {
    if (y % 2 === 1) {
      res = (res + x) % m;
    }
    x = (x * 2) % m;
    y = Math.floor(y / 2);
  }
  return res;
});

2. Construct the Pollard's Rho Kernel

Create a kernel where each thread executes an independent walk. The thread index (this.thread.x) is used to seed the initial value \(x_0\) and the constant \(c\).

const maxIterations = 2000;

const pollardsRhoKernel = gpu.createKernel(function (n, maxSteps) {
  const tid = this.thread.x;
  
  // Unique initialization per thread
  let c = (tid % 100) + 1;
  let x = (tid + 2) % n;
  let y = x;
  let factor = 1;

  for (let i = 0; i < maxSteps; i++) {
    // f(x) = (x^2 + c) % n
    x = (modMult(x, x, n) + c) % n;

    // f(f(y))
    y = (modMult(y, y, n) + c) % n;
    y = (modMult(y, y, n) + c) % n;

    let diff = x > y ? x - y : y - x;
    let d = gcd(diff, n);

    if (d > 1 && d < n) {
      factor = d;
      break;
    }
  }

  return factor;
}, {
  output: [1024], // 1024 parallel threads
  pipeline: false
});

3. Execute and Extract Results

Run the kernel with the target composite number \(N\) and iterate over the output array to extract any non-trivial factor.

function factorize(n) {
  const threadCount = 1024;
  const steps = 1000;

  console.log(`Factorizing ${n} using ${threadCount} GPU threads...`);
  
  const results = pollardsRhoKernel(n, steps);

  for (let i = 0; i < results.length; i++) {
    const factor = results[i];
    if (factor > 1 && factor < n) {
      const otherFactor = n / factor;
      return { factor1: factor, factor2: otherFactor };
    }
  }

  return null; // Factor not found within iteration limit
}

// Example usage with a 32-bit composite number:
const target = 10403; // 101 * 103
const result = factorize(target);

if (result) {
  console.log(`Found factors: ${result.factor1} and ${result.factor2}`);
} else {
  console.log("Failed to find factors. Increase steps or thread count.");
}

Optimizations

  • Batching GCDs: Computing the GCD at every step is computationally expensive on the GPU. You can multiply successive differences \((|x - y|)\) modulo \(N\) over a block of 20 to 100 iterations and run a single GCD per block.
  • Output Dimension Tuning: Adjust output: [threads] according to the available GPU compute units. Common values range from 1,024 to 65,536 threads depending on the target device.
