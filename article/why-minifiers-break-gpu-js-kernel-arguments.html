Why Minifiers Break gpu.js Kernel Arguments

GPU.js allows developers to run complex computations on the GPU by translating standard JavaScript functions into GLSL shaders at runtime. However, production build tools and JavaScript minifiers frequently cause runtime errors inside these kernels. This article explains how minifiers manipulate function signatures and variable identifiers via Function.prototype.toString(), why this process disrupts GPU.js's internal string and AST parsers, and how developers can prevent these breakages in production builds.

How GPU.js Interprets Kernel Code

Unlike standard JavaScript libraries that execute functions directly within the JavaScript engine, GPU.js treats the kernel function as a blueprint. At runtime, GPU.js calls .toString() on the provided kernel function to extract its source code. It then parses this code into an Abstract Syntax Tree (AST) to transpile the JavaScript syntax into WebGL-compliant GLSL (OpenGL Shading Language).

Because of this transpilation pipeline, GPU.js relies heavily on the literal source code, including exact parameter names, uniform definitions, and variable references.

The Role of JavaScript Minifiers

Build tools like Terser, esbuild, and UglifyJS optimize code size by mangling variable and parameter names. During the minification step, a function signature like:

const kernel = gpu.createKernel(function(matrixA, matrixB) {
    return matrixA[this.thread.x] + matrixB[this.thread.x];
});

is typically compressed into:

const kernel = gpu.createKernel(function(a, b) {
    return a[this.thread.x] + b[this.thread.x];
});

While this transformation is completely valid in native JavaScript, it creates critical issues when translated into GLSL.

Primary Causes of Kernel Breakage

1. Collisions with GLSL Reserved Words and Swizzling

GLSL has strict naming conventions and reserved keywords that do not exist in JavaScript. When minifiers shorten variable names to single letters such as x, y, z, or w, they often collide with built-in GLSL vector swizzling properties or coordinates. When GPU.js generates the shader code, identifiers renamed to x or r can create invalid GLSL syntax, causing the WebGL shader compilation step to fail immediately.

2. Destruction of Argument-to-Uniform Mapping

GPU.js maps input arguments to WebGL uniforms and texture bindings. It tracks these inputs using parameter indices and identifier strings. When minifiers aggressively optimize parameter lists—such as removing unused arguments, reordering logic, or inlining values—GPU.js can miscalculate the expected uniform types and array dimensions. If the parser expects a 2D array uniform based on initial configuration but encounters an altered identifier context, argument binding breaks.

3. Destruction of Function Body Context

Some aggressive minification settings flatten scope, evaluate constants prematurely, or rewrite standard loops into terser expressions (such as replacing for loops with condensed expressions or comma operators). GPU.js's internal GLSL generator is designed to translate standard, structured JavaScript control flow. Obfuscated or condensed syntax trees often produce patterns that the GPU.js AST-to-GLSL compiler does not recognize, resulting in syntax parsing exceptions before the shader is ever sent to the graphics hardware.

How to Prevent Minification Issues

To ensure GPU.js kernels operate correctly in production environments, implement the following safeguards:

  • Exclude Kernels from Mangling: Configure your bundler (such as Webpack, Vite, or Rollup) to disable variable mangling specifically for kernel functions. In Terser, use the mangle.reserved option to protect specific parameter and variable names.
  • Define Kernels in Separate Unminified Modules: Isolate GPU.js kernel declarations into dedicated files that bypass minification passes during the build pipeline.
  • Avoid Relying on Dynamic Variable Names: Use standardized naming patterns for kernel arguments and avoid single-letter parameter names in source code to minimize the chance of overlapping with GLSL keywords.
