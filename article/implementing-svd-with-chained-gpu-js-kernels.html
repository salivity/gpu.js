Implementing SVD with Chained GPU.js Kernels

Singular Value Decomposition (SVD) can be implemented across chained GPU.js kernels by leveraging the library’s pipeline execution mode to handle iterative matrix transformations directly in GPU memory. While traditional full SVD algorithms such as Golub-Kahan bidiagonalization are poorly suited for high-level shader environments, iterative approaches like the One-Sided Jacobi algorithm or Power Iteration map well to WebGL-based compute architectures. This article examines how to architect an SVD solver using chained GPU.js kernels, the algorithm best suited for this task, and the hardware-level constraints encountered in a browser environment.

Feasibility and Algorithmic Selection

GPU.js compiles a subset of JavaScript into GLSL shaders running via WebGL. Because shaders execute parallel calculations per pixel without cross-thread communication, standard serial linear algebra routines must be restructured into parallel forms.

For general SVD calculation (\(A = U \Sigma V^T\)), the One-Sided Jacobi algorithm (also known as the Hestenes method) is the most viable candidate for GPU implementation. It repeatedly orthogonalizes pairs of matrix columns using 2x2 plane rotations until all columns are mutually orthogonal:

  1. Columns \(i\) and \(j\) of matrix \(A\) are selected.
  2. Inner products \(a_i \cdot a_i\), \(a_j \cdot a_j\), and \(a_i \cdot a_j\) are calculated.
  3. Rotation angles \(\cos(\theta)\) and \(\sin(\theta)\) are computed to cancel the off-diagonal correlation.
  4. Columns \(i\) and \(j\) are updated simultaneously via linear combination.

For truncated SVD (calculating only the top \(k\) singular values), Power Iteration with Deflation or Lanczos Bidiagonalization is preferred, as these rely primarily on repeated matrix-vector multiplications.

Chaining Kernels with Pipeline Mode

Standard execution in GPU.js downloads pixel buffer data back to the CPU after every kernel run, creating a severe memory-transfer bottleneck over the PCIe bus. To make iterative linear algebra performant, GPU.js must be configured with pipeline: true.

When pipeline mode is enabled, the output of a kernel remains on the GPU as an active WebGL texture. This texture can be passed directly as an argument into the next kernel:

const gpu = new GPU();

// Kernel 1: Computes dot products for column pairs
const computeDotProducts = gpu.createKernel(function(A, colI, colJ, height) {
    let dot = 0.0;
    for (let r = 0; r < height; r++) {
        dot += A[r][colI] * A[r][colJ];
    }
    return dot;
}).setOutput([3]).setPipeline(true);

// Kernel 2: Applies plane rotation to update columns in-place
const applyRotation = gpu.createKernel(function(A, c, s, colI, colJ) {
    let val = A[this.thread.y][this.thread.x];
    if (this.thread.x === colI) {
        val = c * A[this.thread.y][colI] - s * A[this.thread.y][colJ];
    } else if (this.thread.x === colJ) {
        val = s * A[this.thread.y][colI] + c * A[this.thread.y][colJ];
    }
    return val;
}).setOutput([width, height]).setPipeline(true);

By chaining computeDotProducts and applyRotation inside a JavaScript execution loop, intermediate matrix states remain in GPU VRAM throughout all Jacobi sweeps.

Addressing Structural Constraints

While chained kernels enable the necessary data flow, several design considerations must be addressed to ensure numerical validity and performance:

  • Convergence Detection: WebGL fragment shaders cannot alter global control flow or signal early exits to the host CPU. Checking whether the off-diagonal elements have converged below an epsilon requires reading data back to the CPU via .toArray(), which stalls the pipeline. To avoid this overhead, implementations typically run a predetermined, fixed number of sweeps rather than dynamic tolerance-based termination.
  • Precision Limits: WebGL 1.0 and 2.0 implementations in GPU.js generally default to 32-bit single-precision floating-point numbers (float). SVD calculations, particularly inner-product accumulations across large dimensions, accumulate rounding errors rapidly in FP32, limiting the precision of singular vectors.
  • Texture Ping-Ponging: WebGL does not allow reading from and writing to the same texture simultaneously. Chained kernels in GPU.js handle this under the hood via framebuffer ping-ponging, but memory overhead doubles relative to the raw input matrix size.

Chained GPU.js kernels are fully capable of executing SVD algorithms, provided the operation is decomposed into streaming matrix transformations and executed via pipeline mode to eliminate CPU-GPU serialization.
