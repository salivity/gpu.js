Check GPU.js Software Emulation on Android

This article explains how to determine whether an Android device is executing gpu.js operations via native hardware acceleration or software emulation. You will learn how to check the execution mode directly through the gpu.js API, query the underlying WebGL context for software-based rasterizers, and use browser diagnostic tools to confirm hardware support.

1. Check the GPU.js Execution Mode

When gpu.js initializes, it automatically falls back to CPU execution if it cannot find a suitable WebGL environment. You can check the current execution mode directly on your GPU instance or individual kernel.

const gpu = new GPU();
const kernel = gpu.createKernel(function() {
    return this.thread.x;
}).setOutput([10]);

kernel();

// Check the kernel run mode
console.log("Kernel Mode:", kernel.subKernelOutput ? kernel.mode : gpu.mode);

If the returned mode is 'cpu', gpu.js was unable to compile the kernel into a WebGL shader or WebGL is disabled entirely, meaning calculations are being emulated on the CPU using pure JavaScript.

2. Inspect the WebGL Hardware Renderer

An Android browser might report that WebGL is active while internally relying on a software rasterizer (such as Google SwiftShader) instead of the physical GPU (such as Qualcomm Adreno or ARM Mali). You can verify whether the browser is using software emulation by querying the WEBGL_debug_renderer_info extension.

Run the following script on the Android device:

function checkRenderer() {
    const canvas = document.createElement('canvas');
    const gl = canvas.getContext('webgl') || canvas.getContext('experimental-webgl');

    if (!gl) {
        return { isSoftware: true, reason: "WebGL not supported" };
    }

    const debugInfo = gl.getExtension('WEBGL_debug_renderer_info');
    if (!debugInfo) {
        return { isSoftware: false, renderer: gl.getParameter(gl.RENDERER) };
    }

    const renderer = gl.getParameter(debugInfo.UNMASKED_RENDERER_WEBGL);
    const vendor = gl.getParameter(debugInfo.UNMASKED_VENDOR_WEBGL);

    // Common software rasterizer identifiers
    const softwareIndicators = ['swiftshader', 'llvmpipe', 'software rasterizer', 'softpipe'];
    const isSoftware = softwareIndicators.some(name => renderer.toLowerCase().includes(name));

    return {
        isSoftware,
        renderer,
        vendor
    };
}

console.log(checkRenderer());
  • Software Emulation: Renderers containing names like SwiftShader, llvmpipe, or generic Software mean the device's CPU is emulating the graphics pipeline.
  • Hardware Acceleration: Names like Adreno (TM) 660, Mali-G78, PowerVR, or Samsung Xclipse indicate that the kernel is dispatched to the physical hardware GPU.

3. Check Android Browser Diagnostics

If you are testing in a Chromium-based browser on Android (such as Chrome, Edge, or Brave):

  1. Open the browser on your Android device.
  2. Navigate to chrome://gpu in the URL bar.
  3. Look at the Graphics Feature Status section:
    • WebGL: Must say Hardware accelerated. If it says Software only or Disabled, the browser is emulating WebGL.
    • WebGL2: Check if supported, as modern gpu.js features benefit from WebGL 2.0.
  4. Scroll to the Driver Information section and inspect GL_RENDERER to view the active rendering backend.

If WebGL is listed as software-rendered or disabled, check Android's Developer Options to ensure that hardware acceleration is not globally disabled or blocked by an outdated Android System WebView component.
