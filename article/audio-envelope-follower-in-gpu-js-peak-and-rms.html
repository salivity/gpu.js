Audio Envelope Follower in GPU.js: Peak and RMS

Computing an audio envelope follower involves extracting the smooth contour of an audio signal's amplitude over time, which is essential for dynamic range compression, gating, visualization, and synthesis. By utilizing gpu.js, you can offload these calculations to the GPU via WebGL shaders, achieving massive parallelism across large audio buffers. This guide explains how to implement both Peak Detection and Root Mean Square (RMS) envelope followers using windowed parallel algorithms tailored for the GPU.

GPU Parallelism vs. Traditional Recursive Filtering

In traditional digital signal processing on a CPU, an envelope follower often relies on a recursive single-pole Infinite Impulse Response (IIR) filter with separate attack and release coefficients:

\[y[n] = (1 - \alpha) \cdot |x[n]| + \alpha \cdot y[n-1]\]

Because each output sample depends directly on the preceding output sample, pure recursive IIR filtering is inherently sequential and poorly suited for parallel execution on a GPU.

To leverage the GPU effectively, you implement a sliding window approach. Each thread computes the envelope value for a single sample index independently by evaluating a local window of past (or centered) samples.

Prerequisites and Setup

Install and import gpu.js:

npm install gpu.js

Initialize the GPU instance:

import { GPU } from 'gpu.js';

const gpu = new GPU();

1. Windowed Peak Detection

Peak detection calculates the maximum absolute value within a given window size. It responds instantaneously to transients, making it ideal for fast limiting, transient shaping, and visual peak meters.

GPU.js Kernel for Peak Detection

const createPeakEnvelopeKernel = (bufferLength) => {
  return gpu.createKernel(function (audioBuffer, windowSize) {
    const i = this.thread.x;
    let maxVal = 0.0;

    // Calculate window bounds looking backward
    const start = Math.max(0, i - windowSize + 1);

    for (let j = start; j <= i; j++) {
      const absSample = Math.abs(audioBuffer[j]);
      if (absSample > maxVal) {
        maxVal = absSample;
      }
    }

    return maxVal;
  }).setOutput([bufferLength]);
};

2. Windowed RMS Detection

Root Mean Square (RMS) detection provides a measure of continuous perceived loudness rather than instantaneous peaks. It squares each sample within a window, computes the mean, and returns the square root:

\[\text{RMS}[i] = \sqrt{\frac{1}{N} \sum_{k=0}^{N-1} (x[i - k])^2}\]

GPU.js Kernel for RMS Detection

const createRMSEnvelopeKernel = (bufferLength) => {
  return gpu.createKernel(function (audioBuffer, windowSize) {
    const i = this.thread.x;
    let sumSquares = 0.0;
    let count = 0.0;

    const start = Math.max(0, i - windowSize + 1);

    for (let j = start; j <= i; j++) {
      const sample = audioBuffer[j];
      sumSquares += sample * sample;
      count += 1.0;
    }

    return Math.sqrt(sumSquares / count);
  }).setOutput([bufferLength]);
};

3. Execution Pipeline

To process audio buffers, determine the appropriate window size based on your audio sample rate and desired time constant (\(\tau\) in seconds):

\[\text{Window Size (samples)} = \tau \times \text{Sample Rate}\]

For example, a 50 ms window at 44,100 Hz requires roughly \(2,205\) samples.

// Example: Process a 1-second mono audio buffer
const sampleRate = 44100;
const durationSeconds = 1;
const totalSamples = sampleRate * durationSeconds;

// Dummy audio signal (sine wave)
const audioSignal = new Float32Array(totalSamples);
for (let i = 0; i < totalSamples; i++) {
  audioSignal[i] = Math.sin((2 * Math.PI * 440 * i) / sampleRate);
}

// 50ms window
const windowSize = Math.floor(sampleRate * 0.05);

// Instantiate kernels
const peakKernel = createPeakEnvelopeKernel(totalSamples);
const rmsKernel = createRMSEnvelopeKernel(totalSamples);

// Execute on GPU
const peakEnvelope = peakKernel(audioSignal, windowSize);
const rmsEnvelope = rmsKernel(audioSignal, windowSize);

4. Hybrid Peak/RMS Detection

You can combine both metrics inside a single kernel pass to output both values simultaneously, reducing GPU dispatch overhead.

const createCombinedEnvelopeKernel = (bufferLength) => {
  return gpu.createKernel(function (audioBuffer, windowSize) {
    // thread.y = 0 -> Peak, thread.y = 1 -> RMS
    const i = this.thread.x;
    const mode = this.thread.y; 

    const start = Math.max(0, i - windowSize + 1);
    let maxVal = 0.0;
    let sumSquares = 0.0;
    let count = 0.0;

    for (let j = start; j <= i; j++) {
      const sample = audioBuffer[j];
      const absSample = Math.abs(sample);

      if (absSample > maxVal) {
        maxVal = absSample;
      }
      sumSquares += sample * sample;
      count += 1.0;
    }

    if (mode === 0) {
      return maxVal;
    } else {
      return Math.sqrt(sumSquares / count);
    }
  }).setOutput([bufferLength, 2]); // Output: 2 rows of size bufferLength
};

Practical Considerations

  • Buffer Transfer Overhead: Transferring data between the CPU and GPU introduces latency. For live audio processing (e.g., small Web Audio API buffers of 128 to 1024 samples), the overhead of uploading textures to the GPU may offset parallel processing gains. GPU execution is most efficient for offline processing, batch jobs, or rendering waveforms across multi-channel, high-duration audio files.
  • Window Size vs. Execution Time: Larger window sizes increase loop iterations within each shader thread. If windows exceed several thousand samples, consider downsampling the input signal before envelope computation to preserve real-time frame rates.
