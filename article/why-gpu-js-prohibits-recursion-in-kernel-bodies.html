Why gpu.js Prohibits Recursion in Kernel Bodies

This article explains why the gpu.js library forbids recursive function calls inside its kernel definitions. In short, gpu.js compiles JavaScript functions into WebGL shader code (GLSL), an environment that fundamentally lacks the dynamic stack memory and architectural support required for recursion. Below is a breakdown of the hardware, language specification, and architectural constraints that enforce this limitation.

GLSL Specification Constraints

Under the hood, gpu.js accelerates JavaScript code by transpiling the kernel function into OpenGL Shading Language (GLSL) to execute on the GPU via WebGL. The GLSL ES specification, which WebGL targets, explicitly forbids recursion.

In GLSL, the call graph must be strictly acyclic. The compiler enforces this rule at parse time; if a function directly or indirectly calls itself, compilation fails immediately. Because gpu.js relies on the underlying graphics drivers to compile and execute the generated GLSL string, it must strictly adhere to these language specifications.

Lack of a Dynamic Call Stack

CPUs handle recursive calls by pushing return addresses, arguments, and local variables onto a dedicated memory region known as the call stack. GPUs, by contrast, are designed for massive data parallelism across thousands of lightweight threads (cores) executing concurrently.

Allocating a dynamic, unbounded call stack for tens of thousands of individual threads would require an enormous amount of high-speed memory. Instead, GPU architectures utilize small, fixed sets of registers per thread to maximize execution throughput. Without a per-thread dynamic call stack, tracking execution state across recursive calls is physically unsupported by the standard pipeline.

Deterministic Register Allocation and Inlining

GPU compilers require static knowledge of a program's execution profile to optimize resource utilization. They analyze kernel code to determine the exact number of registers a thread needs before execution begins.

Because recursive depth cannot typically be determined at compile time, the compiler cannot predict or allocate the necessary registers. As a result, GPU compilers predominantly inline functions—substituting the function call with the actual body of the function. Recursion breaks inlining, as it would cause infinite code expansion during the compilation phase.

Handling Recursive Algorithms in gpu.js

Because recursion is prohibited, algorithms traditionally implemented recursively (such as tree traversal, quicksort, or fractal calculations) must be refactored before execution in a gpu.js kernel.

To run these workloads on the GPU, developers must convert recursive logic into an iterative structure using standard loops (for or while). If the algorithm strictly requires tracking previous states, that state must be maintained manually using fixed-size arrays or pre-allocated buffers that simulate a stack within the kernel's local scope.
