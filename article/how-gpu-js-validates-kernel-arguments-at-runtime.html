How GPU.js Validates Kernel Arguments at Runtime

GPU.js accelerates JavaScript applications by compiling written functions into WebGL-compatible GLSL shaders. Because GLSL requires static typing while JavaScript is dynamically typed, GPU.js utilizes a runtime validation system to ensure provided kernel arguments match the expected hardware formats. When type validation is active, GPU.js intercepts the invocation, inspects the JavaScript data structures, verifies them against kernel signatures, and either confirms compatibility, re-compiles the shader, or throws a detailed runtime error before pushing data to the GPU.

Interception and Argument Inspection

When you call a compiled kernel with argument checking enabled, GPU.js intercepts the function call before any WebGL bindings occur. It loops through the passed arguments and determines their runtime data types through JavaScript type evaluation.

GPU.js checks the following characteristics:

  • Primitives: It evaluates primitive types (primarily numbers and booleans) via standard typeof operators.
  • Typed Arrays and Buffers: It checks whether objects are instances of typed arrays, such as Float32Array or Int32Array.
  • Nested Arrays (Vectors and Matrices): For standard JavaScript arrays, GPU.js traverses the array dimensions to determine if it is a 1D, 2D, or 3D array, as well as checking the consistency of nested lengths.
  • Textures and Custom Objects: It validates instances of specialized GPU.js objects like Texture or Input to ensure they hold proper metadata, dimensions, and texture targets.

Signature Matching

Once the runtime types are identified, GPU.js evaluates them against the kernel's internal parameter definition.

  1. Static Kernels: If the kernel was created with explicitly declared argument types (or locked down after an initial run), GPU.js compares the resolved runtime signature directly with the pre-compiled shader's uniform declarations.
  2. Dynamic Kernels: If explicit types were not hardcoded, GPU.js checks its internal cache of compiled sub-kernels. If the incoming argument signature matches an existing compiled variant, it routes execution to that specific shader program.

Dimension and Boundary Verification

Type validation extends beyond simple data types to shape and memory alignment. When an array, texture, or matrix is passed, the validator verifies that:

  • The dimensions of the input match the uniform layout declared in GLSL.
  • The array elements are not malformed, sparse, or containing non-numeric values (such as null, undefined, or NaN).
  • Memory sizes align with WebGL texture limits (e.g., maximum texture size supported by the user's GPU hardware).

Error Dispatch and Safe Failure

If a mismatch is detected, GPU.js halts execution prior to making WebGL context calls. Rather than allowing WebGL to fail silently or crash with opaque GLSL compilation errors, GPU.js constructs an informative JavaScript error. The resulting exception clearly states which argument index failed, what type was expected by the kernel, and what type was actually detected at runtime.
