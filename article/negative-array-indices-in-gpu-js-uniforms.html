Negative Array Indices in GPU.js Uniforms

When using GPU.js, supplying negative array indices to uniform arguments leads to undefined behavior, returning unexpected values such as zero, clamped edge values, or triggering compilation and runtime WebGL errors. Because GPU.js transpiles JavaScript code into low-level WebGL GLSL (OpenGL Shading Language) shaders, standard JavaScript handling of negative indices does not apply. This article breaks down how GPU.js processes uniform arrays, how negative indices interact with WebGL, and how to properly handle array boundaries in kernels.

How GPU.js Handles Uniform Arrays

In GPU.js, uniform arguments passed to a kernel are translated into WebGL structures. Depending on the size and type of the array, GPU.js represents uniforms either as native GLSL arrays or, more commonly for larger datasets, encodes them into 2D floating-point textures.

When you access an element of a uniform array within a kernel function using syntax like uniformArray[i], GPU.js compiles this operation into an internal sampler function or a direct GLSL array lookup.

Static Negative Indices vs. Dynamic Negative Indices

The behavior varies depending on whether the negative index is a literal constant known at compile time or dynamic value calculated at runtime:

  1. Static/Literal Negative Indices: If you supply a literal negative index directly in your kernel code (e.g., uniformArray[-1]), the GPU.js AST (Abstract Syntax Tree) transpiler attempts to generate GLSL matching that syntax. In GLSL, array indices must be non-negative integers. Compiling a shader with a static negative index causes shader compilation to fail, throwing an error during kernel initialization.

  2. Dynamic Negative Indices: If the negative index is evaluated dynamically during execution (e.g., passing a negative uniform variable or computing i - 1 where i = 0):

    • Small Native Arrays: If the uniform is stored as a standard GLSL uniform array, accessing a negative index results in undefined behavior per the OpenGL ES specification. Different GPU drivers handle this unpredictably; some clamp the read to index 0, some return 0.0, and others read arbitrary memory.
    • Texture-Backed Arrays: For standard large arrays encoded as textures, GPU.js calculates normalized texture coordinates using the provided index: 
      vec2 indexToVec(float index) { ... }
      A negative index produces negative UV coordinates. WebGL textures in GPU.js generally use the CLAMP_TO_EDGE wrap mode. Consequently, negative coordinates typically sample the first texel at index 0. However, edge sampling can introduce precision artifacts, interpolations, or null values depending on internal texture configurations.

Consequences in Kernel Execution

Supplying negative indices to uniform arguments creates several specific issues:

  • Silent Corruption: Instead of throwing a runtime JavaScript RangeError or returning undefined, the GPU kernel continues executing, propagating incorrect data (such as edge elements or zero values) downstream into your output matrix.
  • Platform Inconsistency: Because WebGL delegates out-of-bounds memory behavior to the underlying graphics driver, the same kernel might return 0 on an NVIDIA desktop card, clamp to the first index on an Apple Silicon GPU, or cause pipeline stalls on mobile devices.

Preventing Negative Index Access

Because GPU.js does not provide native bounds checking to preserve execution speed, bounds checking must be implemented explicitly inside the kernel.

Use conditional logic or clamping to ensure indices remain non-negative:

const kernel = gpu.createKernel(function(myUniform, offset) {
    let index = this.thread.x - offset;

    // Prevent negative index access
    if (index < 0) {
        return 0; // Return fallback/safe value
    }

    return myUniform[index];
}).setOutput([512]);

Alternatively, use Math.max to constrain dynamic indices to the lower boundary:

const kernel = gpu.createKernel(function(myUniform, offset) {
    let safeIndex = Math.max(0, this.thread.x - offset);
    return myUniform[safeIndex];
}).setOutput([512]);

Ensuring all uniform accesses are verified prior to sampling guarantees deterministic, cross-platform behavior across all WebGL contexts.
