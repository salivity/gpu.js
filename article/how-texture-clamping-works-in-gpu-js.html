How Texture Clamping Works in GPU.js

Texture clamping in GPU.js defines how kernels handle out-of-bounds coordinate access when sampling data from input arrays, textures, or image buffers. Because GPU.js translates JavaScript functions into WebGL shaders, it relies on underlying WebGL texture wrapping mechanisms to resolve coordinates that fall outside the defined dimensions. This process prevents rendering artifacts, ensures numerical stability in multi-pass computations, and guarantees that edge values are predictably handled rather than returning undefined memory.

The Underlying WebGL Mechanism

When GPU.js uploads data—such as a 2D matrix or an HTML canvas—to the GPU, it stores that data in a WebGL texture. In WebGL, sampling behavior outside the standard coordinate range \([0, 1]\) is dictated by texture wrapping parameters (gl.TEXTURE_WRAP_S and gl.TEXTURE_WRAP_T).

GPU.js predominantly configures textures using gl.CLAMP_TO_EDGE. Under this mode:

  • Any coordinate less than 0.0 is clamped to 0.0.
  • Any coordinate greater than 1.0 is clamped to 1.0.
  • The sampler evaluates the texel at the nearest valid boundary edge rather than repeating the pattern (gl.REPEAT) or mirroring it (gl.MIRRORED_REPEAT).

This configuration is standard in WebGL because non-power-of-two (NPOT) textures strictly require CLAMP_TO_EDGE unless specific WebGL 2.0 or extension capabilities are explicitly handled.

Kernel Sampling and Thread Indices

In GPU.js, kernel operations are driven by the thread hierarchy (this.thread.x, this.thread.y, this.thread.z). When a kernel samples from an input texture using array-like syntax (e.g., inputMatrix[y][x]), GPU.js translates these integer thread indices into normalized texture coordinates inside the generated GLSL fragment shader.

If an algorithm accesses coordinates relative to the current thread—such as in a convolution filter or neighbor-sampling operation (inputMatrix[this.thread.y + offset][this.thread.x + offset]):

  1. Boundary Adherence: When the computed index falls below zero or exceeds the matrix bounds, the normalized coordinates pass outside the \([0, 1]\) interval.
  2. Value Duplication: Due to CLAMP_TO_EDGE, the shader reads the outermost row or column values repeatedly for any coordinate extending past the perimeter.
  3. No Out-of-Bounds Exceptions: WebGL shaders do not throw index-out-of-bounds runtime exceptions. Instead, the hardware mathematically forces the lookup index to remain inside valid texture memory.

Implications for Computational Kernels

Understanding texture clamping is critical when writing algorithms sensitive to boundary conditions:

  • Image Processing: In operations such as Gaussian blur, edge detection (Sobel filtering), or sharpening, edge clamping duplicates the boundary pixels. While this avoids black borders (which occur when missing pixels default to zero), it can slightly amplify border intensity or skew gradient calculations at the perimeter.
  • Cellular Automata and Simulations: Simulations that require toroidal wrapping (where the left edge connects to the right edge) will not work automatically with default clamping. Developers must explicitly implement modular arithmetic inside the kernel (e.g., (this.thread.x + offset) % width) to wrap indices manually.
  • Sub-Pixel Interpolation: When using texture arguments with linear filtering enabled, clamping acts on the outermost center of the boundary texels, blending the edge colors smoothly up to the absolute border.
