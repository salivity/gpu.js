Semi-Lagrangian Fluid Advection in gpu.js

Navier-Stokes fluid advection can be effectively calculated using semi-Lagrangian schemes directly inside gpu.js. By translating JavaScript-like mathematical operations into WebGL fragment shaders, gpu.js enables high-performance, parallel computation across grid cells on the GPU. This approach allows web developers to achieve unconditionally stable, real-time fluid simulations in the browser without writing raw GLSL shader code.

Feasibility and Mechanics

Semi-Lagrangian advection is an ideal candidate for GPU parallelization. In fluid dynamics based on Jos Stam's Stable Fluids method, the advection step solves the non-linear transport equation by looking backward in time. Instead of pushing quantities forward (Eulerian approach), it traces a virtual particle from the current grid cell backward along the local velocity field over a discrete timestep \(\Delta t\), sampling the quantity at the origin point.

Because the value of each grid cell at time \(t + \Delta t\) depends solely on the state of the grid at time \(t\), each cell can be evaluated completely independently. This data-parallel execution model fits the single instruction, multiple threads (SIMT) architecture of graphics hardware, making gpu.js well-suited for the task.

Implementing the Scheme in gpu.js

To calculate semi-Lagrangian advection in gpu.js, the computational grid is represented as a 2D matrix of velocities or densities. The execution requires a dedicated kernel function that performs the following steps:

  1. Coordinate Retrieval: The kernel uses this.thread.x and this.thread.y to determine the current discrete cell coordinates.
  2. Backward Tracing: The kernel queries the current cell's horizontal (\(u\)) and vertical (\(v\)) velocity components and traces backward: \[x_{\text{prev}} = x - u \cdot \Delta t\] \[y_{\text{prev}} = y - v \cdot \Delta t\]
  3. Boundary Clamping: The backward coordinates are clamped to ensure they remain strictly within the physical simulation boundaries.
  4. Bilinear Interpolation: Since the traced coordinates \((x_{\text{prev}}, y_{\text{prev}})\) rarely land precisely on integer grid coordinates, the kernel calculates a weighted average of the four nearest neighboring grid cells to interpolate the field value smoothly.
  5. Output Generation: The interpolated value is returned as the new state for the cell.

Key Considerations in gpu.js

  • Ping-Pong Buffering: WebGL does not allow reading from and writing to the same texture simultaneously. In gpu.js, you must use two separate instances of the grid data, alternating which serves as the input and which receives the kernel's output on each frame.
  • Manual Interpolation: While native WebGL textures support automatic bilinear interpolation via hardware filtering, gpu.js operates over array buffers by default. Developers must explicitly write the bilinear interpolation math inside the gpu.js kernel unless texture-mode outputs and hardware filtering are manually configured.
  • Floating-Point Precision: Advection requires sub-pixel accuracy to prevent rapid numerical dissipation. Ensuring floating-point precision mode is enabled in gpu.js prevents truncation errors during the backward integration step.
