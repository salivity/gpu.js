Export Trained Neural Network Weights in GPU.js

Exporting and serializing trained neural network weights in gpu.js requires transferring computed tensor data out of GPU memory into CPU-accessible JavaScript structures and saving them to disk or local storage. Because gpu.js executes matrix calculations within WebGL or WebGPU contexts, weights must be pulled from the GPU using built-in extraction methods before being serialized into formats such as JSON or raw binary buffers for future inference or checkpointing.

1. Extracting Weights from the GPU Context

During training, gpu.js kernels typically output weight matrices as multidimensional arrays or specialized WebGL textures. To work with these values in standard JavaScript, you must read them back into system memory.

If your kernel outputs textures for performance optimization, use .toArray() to convert the texture back into an accessible nested or flat JavaScript array:

// Assuming 'updateWeightsKernel' returns the updated weights
const updatedWeightsTexture = updateWeightsKernel(inputs, weights, biases);

// Transfer data from GPU texture memory to a JavaScript array
const weightsArray = updatedWeightsTexture.toArray();

2. Structuring Network State

Before serialization, organize all learnable parameters (weights and biases) across all layers into a structured JavaScript object. Including layer metadata, shapes, and activation types ensures that the model can be correctly reconstructed later.

const modelCheckpoint = {
  architecture: ['Dense', 'Dense'],
  timestamp: new Date().toISOString(),
  layers: [
    {
      name: 'layer_1',
      shape: [weightsLayer1.length, weightsLayer1[0].length],
      weights: weightsLayer1.toArray(),
      biases: biasesLayer1.toArray()
    },
    {
      name: 'layer_2',
      shape: [weightsLayer2.length, weightsLayer2[0].length],
      weights: weightsLayer2.toArray(),
      biases: biasesLayer2.toArray()
    }
  ]
};

3. Serializing the Data

Depending on your model size and deployment environment, you can serialize weights to JSON or compact binary formats.

Approach A: JSON Serialization

For small-to-medium networks, JSON is human-readable and straightforward:

const serializedJSON = JSON.stringify(modelCheckpoint);

Approach B: Binary Serialization (TypedArrays)

For large networks, JSON overhead can be excessive. Flatten your nested arrays into Float32Array objects to preserve precision and reduce file size:

const flatWeights = new Float32Array(weightsLayer1.flat());
const buffer = flatWeights.buffer;

4. Exporting the Serialized Weights

The export method depends on whether you run gpu.js in Node.js or directly in a web browser.

Exporting in Node.js

Use the native file system module (fs) to write the serialized data directly to the disk:

const fs = require('fs');

// Save as JSON
fs.writeFileSync('model_weights.json', serializedJSON, 'utf8');

// Or save as binary
fs.writeFileSync('model_weights.bin', Buffer.from(buffer));

Exporting in the Browser

Create an in-memory Blob and trigger a programmatic download link:

function downloadWeights(data, filename, type = 'application/json') {
  const blob = new Blob([data], { type });
  const url = URL.createObjectURL(blob);
  const link = document.createElement('a');
  
  link.href = url;
  link.download = filename;
  document.body.appendChild(link);
  link.click();
  
  document.body.removeChild(link);
  URL.revokeObjectURL(url);
}

// Trigger download
downloadWeights(serializedJSON, 'weights.json');

To reload the network, fetch or read the saved file, parse the JSON or typed array back into memory, and feed the values directly back into your gpu.js prediction kernels as input parameters.
