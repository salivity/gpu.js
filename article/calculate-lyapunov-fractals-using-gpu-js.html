Calculate Lyapunov Fractals Using GPU.js

This guide explains how to accelerate the calculation and visualization of Lyapunov fractals and chaos theory attractors using GPU.js in the browser or Node.js. You will learn the underlying mathematics of the Lyapunov exponent, how to translate recursive chaotic equations into parallel WebGL kernels, and how to render high-resolution fractals directly onto an HTML5 canvas in real time.

Understanding the Mathematics

Lyapunov Fractals

A Lyapunov fractal visualizes the stability and chaos of a population model—most commonly the logistic map—forced by an alternating sequence of two growth parameters, \(a\) and \(b\):

\[x_{n+1} = r_n x_n (1 - x_n)\]

The value of \(r_n\) alternates between \(a\) and \(b\) according to a predefined string (such as "AB" or "AABAB"). The Lyapunov exponent (\(\lambda\)) characterizes the rate of separation of infinitesimally close trajectories:

\[\lambda = \lim_{N \to \infty} \frac{1}{N} \sum_{n=1}^{N} \ln |r_n (1 - 2x_n)|\]

  • If \(\lambda < 0\), the system settles into a stable, periodic orbit.
  • If \(\lambda > 0\), the system enters deterministic chaos.

By mapping a grid of \((a, b)\) coordinates across a 2D plane and calculating \(\lambda\) for each point, the resulting values define the color of each pixel.

Chaos Attractors

Strange attractors, such as the Clifford or Lorenz attractors, represent trajectories in phase space that exhibit sensitive dependence on initial conditions. While continuous systems like the Lorenz attractor rely on differential equations solved step-by-step, discrete attractors like the Clifford attractor can be parallelized effectively:

\[x_{n+1} = \sin(a y_n) + c \cos(a x_n)\] \[y_{n+1} = \sin(b x_n) + d \cos(b y_n)\]

Setting Up GPU.js

GPU.js compiles a subset of JavaScript into WebGL shaders, offloading parallel calculations from the CPU to the graphics card.

Install GPU.js via npm or import it via a CDN:

<script src="https://cdnjs.cloudflare.com/ajax/libs/gpu.js/2.16.0/gpu-browser.min.js"></script>
<canvas id="render-canvas"></canvas>

Initialize the GPU instance with the target canvas:

const canvas = document.getElementById('render-canvas');
const gpu = new GPU({
  canvas: canvas,
  mode: 'gpu'
});

Calculating Lyapunov Fractals with a GPU Kernel

Because every pixel calculation in a Lyapunov fractal is independent, the entire screen can be evaluated in parallel. The GPU.js kernel takes the canvas dimensions, bounds of \(a\) and \(b\), and iteration limits to output RGB color values directly.

const width = 800;
const height = 800;

const renderLyapunov = gpu.createKernel(function(minA, maxA, minB, maxB, iterations, warmup) {
  const x = this.thread.x;
  const y = this.thread.y;

  // Map pixel coordinate to (a, b) parameter space
  const a = minA + (x / this.constants.width) * (maxA - minA);
  const b = minB + (y / this.constants.height) * (maxB - minB);

  let p = 0.5;
  let lambdaSum = 0.0;

  // Pattern definition: 0 for A, 1 for B (Sequence "AB")
  const seqLength = 2;

  for (let n = 0; n < iterations; n++) {
    // Determine whether to use 'a' or 'b'
    const step = n % seqLength;
    const r = (step === 0) ? a : b;

    // Logistic map step
    p = r * p * (1.0 - p);

    // Accumulate the derivative after the warm-up period
    if (n >= warmup) {
      const deriv = Math.abs(r * (1.0 - 2.0 * p));
      if (deriv > 0.00001) {
        lambdaSum += Math.log(deriv);
      }
    }
  }

  const lambda = lambdaSum / (iterations - warmup);

  // Color mapping based on lambda
  if (lambda < 0.0) {
    // Stable region (shades of blue to yellow)
    const val = Math.max(0.0, 1.0 + lambda * 0.5);
    this.color(val, val * 0.8, 0.2, 1.0);
  } else {
    // Chaotic region (dark brown/black)
    const val = Math.min(1.0, lambda * 0.2);
    this.color(val * 0.1, 0.0, val * 0.2, 1.0);
  }
})
.setConstants({ width: width, height: height })
.setOutput([width, height])
.setGraphical(true);

// Execute the kernel
// Parameters: minA, maxA, minB, maxB, iterations, warmup
renderLyapunov(3.4, 4.0, 2.5, 4.0, 300, 50);

Calculating Chaos Attractors with GPU.js

Strange attractors are often drawn by tracing millions of iterations sequentially. With GPU.js, you can compute thousands of distinct trajectories in parallel from varying starting conditions, or compute a density grid for discrete 2D attractors.

The following implementation computes particle trajectories for a Clifford attractor concurrently:

const particleCount = 100000;
const stepsPerFrame = 50;

const updateClifford = gpu.createKernel(function(particles, a, b, c, d) {
  let x = particles[this.thread.x][0];
  let y = particles[this.thread.x][1];

  for (let i = 0; i < stepsPerFrame; i++) {
    const nextX = Math.sin(a * y) + c * Math.cos(a * x);
    const nextY = Math.sin(b * x) + d * Math.cos(b * y);
    x = nextX;
    y = nextY;
  }

  return [x, y];
}).setOutput([particleCount]);

// Initialize random points
let particles = [];
for (let i = 0; i < particleCount; i++) {
  particles.push([Math.random() * 2 - 1, Math.random() * 2 - 1]);
}

// Compute new positions
const a = -1.4, b = 1.6, c = 1.0, d = 0.7;
particles = updateClifford(particles, a, b, c, d);

The resulting array of 2D coordinates can be rendered onto an external 2D canvas context or ingested into WebGL vertex buffers for real-time visualization.

Performance Considerations

  • Warmup Phase: Chaotic systems require a transient phase (warmup) to let points fall onto the attractor before calculating derivatives. Omitting this causes artifacts.
  • Floating-Point Precision: Standard WebGL shaders utilize 32-bit floats. Extreme zooms into the parameter space will encounter precision limits sooner than CPU implementations using 64-bit doubles.
  • Loop Bounds: GPU.js requires loop limits to be deterministic or capped by a fixed maximum constant to allow GLSL unrolling. Avoid non-constant loop terminations where possible.
