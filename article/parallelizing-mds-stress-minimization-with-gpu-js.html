Parallelizing MDS Stress Minimization with GPU.js

Multi-Dimensional Scaling (MDS) is an established technique for dimensionality reduction and data visualization that relies on iterative stress minimization algorithms, such as SMACOF (Scaling by Majorizing a Complicated Function) or gradient descent. Because calculating pairwise distances and coordinate updates scales quadratically at \(O(N^2)\), processing large datasets on a central processor becomes computationally prohibitive. This article explains how the primary mathematical bottlenecks of MDS stress minimization can be parallelized in JavaScript environments using the WebGL-accelerated library gpu.js.

The Computational Bottleneck in MDS

Stress minimization aims to project high-dimensional data points into a lower-dimensional space (typically 2D or 3D) while preserving pairwise dissimilarities. The standard approach involves two repetitive phases per iteration:

  1. Distance Computation: Calculating the Euclidean distances between all \(N(N - 1) / 2\) pairs of projected coordinates.
  2. Matrix Update (The Guttman Transform): In the SMACOF algorithm, coordinates are updated via matrix multiplication involving the B-matrix (which relies on target dissimilarities divided by current distances) and the current configuration matrix.

Both of these steps represent embarrassingly parallel workloads. The calculation of distance and B-matrix entries for point pair \((i, j)\) is completely independent of the calculation for point pair \((k, l)\).

How GPU.js Fits the Problem

GPU.js transforms standard JavaScript functions into WebGL fragment shaders, executing operations across thousands of GPU cores in parallel. It works natively in modern browsers and in Node.js via headless WebGL contexts.

Because GPU.js excels at 2D and 3D array manipulations and matrix transformations, it is well-suited for the structural mathematics of MDS.

Implementing Parallel Steps with GPU.js Kernels

To accelerate MDS stress minimization with gpu.js, the algorithm must be decomposed into dedicated compute kernels:

1. Pairwise Distance Calculation

A 2D kernel computes the current Euclidean distance between every point \(i\) and point \(j\) in the low-dimensional embedding:

const computeDistances = gpu.createKernel(function(coords, dimensions) {
    let sum = 0;
    for (let d = 0; d < dimensions; d++) {
        let diff = coords[this.thread.y][d] - coords[this.thread.x][d];
        sum += diff * diff;
    }
    return Math.sqrt(sum);
}).setOutput([N, N]);

2. Constructing the B-Matrix

The elements of the SMACOF B-matrix \(B(X)\) depend on the original dissimilarity matrix \(\Delta\) and the computed distance matrix \(D(X)\). For \(i \neq j\):

  • \(b_{ij} = -\delta_{ij} / d_{ij}(X)\) if \(d_{ij}(X) > 0\)
  • \(b_{ij} = 0\) if \(d_{ij}(X) = 0\)

This mapping can be executed in a single 2D GPU.js kernel that receives the precomputed distances and the target dissimilarity matrix as input textures.

3. Matrix Multiplication for Coordinate Updates

The primary coordinate update step is expressed as:

\[X_{new} = V^{\dagger} B(X) X\]

Where \(V^{\dagger}\) is the Moore-Penrose pseudoinverse of the normalization matrix (which is static and precalculated once on the CPU). The subsequent matrix products \(B(X) \times X\) and \(V^{\dagger} \times (B(X) X)\) can be executed using standard parallel matrix multiplication kernels in gpu.js.

Key Considerations and Performance Limits

While parallelization delivers significant performance gains, certain trade-offs must be managed:

  • Memory Transfer Overhead: Passing large arrays between the CPU and the GPU on every iteration introduces latency. To maximize efficiency, kernels should be chained using the pipeline: true option in gpu.js. This keeps the intermediate distance and B-matrix arrays inside GPU memory (textures) rather than reading them back into JavaScript RAM.
  • Precision Limits: WebGL often operates with 32-bit floating-point numbers. While sufficient for standard visualization tasks, high-precision scientific convergence may accumulate minor floating-point drift compared to 64-bit CPU implementations.
  • Diagonal Values and Reductions: Calculating the diagonal elements of the B-matrix requires summing each row (\(b_{ii} = -\sum_{j \neq i} b_{ij}\)). Row reductions can be executed efficiently in GPU.js by using a 1D kernel that loops across columns.

Conclusion

Multi-dimensional scaling stress minimization steps can be parallelized effectively using gpu.js. By delegating pairwise distance calculations and matrix-matrix multiplications to WebGL shaders, execution times for large point sets can be reduced dramatically compared to single-threaded CPU implementations.
