JavaScript Integer Coercion in gpu.js Kernels

When executing code on the GPU using gpu.js, JavaScript numbers undergo a translation process to bridge the gap between dynamically typed JavaScript and strictly typed WebGL Shading Language (GLSL). Because JavaScript historically represents all numbers as 64-bit floating-point values, gpu.js must determine whether a given variable should be treated as a 32-bit float or a 32-bit signed integer within the compiled shader. Understanding this coercion mechanism is critical for preventing runtime type mismatches and ensuring arithmetic correctness inside GPU-accelerated functions.

The Dynamic Number Challenge

JavaScript does not have native, distinct primitive types for integers and floating-point numbers; every standard number is an IEEE 754 double-precision float. Conversely, GLSL—the shader language gpu.js compiles JavaScript into—is statically typed and strictly enforces distinctions between int and float types. In GLSL, mixing integers and floats in operations without explicit casting (such as float(myInt) + myFloat) produces a shader compilation error.

Default Coercion Behavior

When a standard JavaScript integer is passed into a gpu.js kernel without explicit configuration, gpu.js defaults to treating it as a 32-bit floating-point number (float in GLSL).

Even if you pass a whole number like 5, gpu.js will typically upload the variable to the GPU as a float uniform using the WebGL API call gl.uniform1f. Inside the kernel, the variable behaves as a floating-point value rather than an integer. If you attempt to use this argument directly in GLSL contexts that strictly require an integer—such as bitwise operations or array indexing—the kernel compilation will fail or cause unexpected behavior unless explicitly cast inside the kernel function.

Explicit Integer Coercion

To coerce a JavaScript integer argument into a native GLSL int, gpu.js provides the argumentTypes configuration object. When declaring a kernel, you can explicitly designate an incoming parameter as an integer:

const kernel = gpu.createKernel(function(x) {
    return x + 1;
}, {
    argumentTypes: { x: 'Integer' }
});

When an argument is marked as 'Integer', gpu.js applies the following coercion rules:

  1. JavaScript-Side Truncation: Before passing the value to the GPU, gpu.js treats the input as a 32-bit signed integer. Any fractional part is truncated, mirroring JavaScript's bitwise coercion (similar to x | 0 or Math.trunc(x)).
  2. Uniform Binding: Instead of using gl.uniform1f, the library binds the argument using gl.uniform1i.
  3. GLSL Type Definition: In the generated shader source code, the variable is declared as uniform int rather than uniform float.

Built-in Integer Variables

Internal index coordinates provided by gpu.js, such as this.thread.x, this.thread.y, and this.thread.z, are automatically coerced and treated as native GLSL int variables. When performing arithmetic between user-defined arguments and thread indices, untyped user arguments (treated as floats) will trigger type mismatch errors. To interoperate with thread indices, input arguments must either be explicitly configured as 'Integer' via argumentTypes or converted using GLSL-supported conversion methods inside the kernel body.
