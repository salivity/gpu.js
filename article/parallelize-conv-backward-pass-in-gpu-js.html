Parallelize Conv Backward Pass in gpu.js

This article explains how to parallelize the backward pass of a convolutional layer to compute filter gradients (\(dW\)) using gpu.js. It covers mapping the 4D filter tensor onto GPU execution threads, restructuring high-dimensional coordinates to fit gpu.js kernel limits, and implementing an accumulation loop over batch and spatial dimensions directly in WebGL-accelerated JavaScript.

Understanding the Filter Gradient Operation

In a convolutional layer backward pass, the gradient of the loss with respect to the filter weights (\(dW\)) is computed by convolving the input activations (\(X\)) with the incoming upstream gradients (\(dY\)).

For a weight tensor of shape \((K_h, K_w, C_{in}, C_{out})\), the gradient for a specific weight is:

\[dW(k_y, k_x, c_{in}, c_{out}) = \sum_{b=0}^{B-1} \sum_{y=0}^{H_{out}-1} \sum_{x=0}^{W_{out}-1} X(b, y \cdot s + k_y, x \cdot s + k_x, c_{in}) \cdot dY(b, y, x, c_{out})\]

Where:

  • \(B\) is the batch size.
  • \(H_{out}, W_{out}\) are the spatial dimensions of the upstream gradient.
  • \(s\) is the stride.
  • \(k_y, k_x\) are filter spatial coordinates.
  • \(c_{in}, c_{out}\) are input and output channel indices.

Parallelization Strategy in gpu.js

To parallelize this effectively on the GPU:

  1. Thread Assignment: Assign exactly one GPU thread to each unique filter parameter. Each thread computes a single scalar value of \(dW\).
  2. Dimension Mapping: Because gpu.js natively supports up to 3D output topologies ([x, y, z]), the 4D weight tensor \((K_h, K_w, C_{in}, C_{out})\) must be reshaped. A standard approach flattens the spatial filter dimensions \((K_w \cdot K_h)\) into the X-axis, maps \(C_{in}\) to the Y-axis, and maps \(C_{out}\) to the Z-axis.
  3. Inner Reduction: Inside each thread, iterate through the batch size and the output feature map coordinates (\(H_{out}, W_{out}\)), accumulating products of input features and output gradients.

Implementation in gpu.js

The following example shows how to configure and execute the kernel. The inputs \(X\) and \(dY\) are passed as flattened 1D arrays or appropriately mapped 3D/2D arrays. Here, inputs are treated as flattened arrays with explicit stride-based indexing for maximum compatibility.

const { GPU } = require('gpu.js');
const gpu = new GPU();

function createFilterGradientKernel(params) {
  const {
    batchSize,
    inHeight,
    inWidth,
    inChannels,
    outHeight,
    outWidth,
    outChannels,
    kernelHeight,
    kernelWidth,
    stride,
    padding
  } = params;

  return gpu.createKernel(function(input, gradOutput) {
    // Thread indices
    // x represents flattened spatial weight position: [0, kernelWidth * kernelHeight - 1]
    // y represents input channel: [0, inChannels - 1]
    // z represents output channel: [0, outChannels - 1]
    const kIndex = this.thread.x;
    const cIn = this.thread.y;
    const cOut = this.thread.z;

    const kx = kIndex % this.constants.kernelWidth;
    const ky = Math.floor(kIndex / this.constants.kernelWidth);

    let sum = 0.0;

    // Loop over batch and spatial positions of the upstream gradient
    for (let b = 0; b < this.constants.batchSize; b++) {
      for (let oy = 0; oy < this.constants.outHeight; oy++) {
        for (let ox = 0; ox < this.constants.outWidth; ox++) {
          
          const iy = oy * this.constants.stride - this.constants.padding + ky;
          const ix = ox * this.constants.stride - this.constants.padding + kx;

          // Boundary check for padding
          if (iy >= 0 && iy < this.constants.inHeight && ix >= 0 && ix < this.constants.inWidth) {
            
            // Calculate 1D indices for flattened inputs
            const inIdx = b * (this.constants.inHeight * this.constants.inWidth * this.constants.inChannels)
                        + iy * (this.constants.inWidth * this.constants.inChannels)
                        + ix * this.constants.inChannels
                        + cIn;

            const gradIdx = b * (this.constants.outHeight * this.constants.outWidth * this.constants.outChannels)
                          + oy * (this.constants.outWidth * this.constants.outChannels)
                          + ox * this.constants.outChannels
                          + cOut;

            sum += input[inIdx] * gradOutput[gradIdx];
          }
        }
      }
    }

    return sum;
  })
  .setConstants({
    batchSize,
    inHeight,
    inWidth,
    inChannels,
    outHeight,
    outWidth,
    outChannels,
    kernelHeight,
    kernelWidth,
    stride,
    padding
  })
  .setOutput([kernelWidth * kernelHeight, inChannels, outChannels]);
}

Execution and Reshaping

To execute the kernel:

const convParams = {
  batchSize: 16,
  inHeight: 28,
  inWidth: 28,
  inChannels: 3,
  outHeight: 26,
  outWidth: 26,
  outChannels: 8,
  kernelHeight: 3,
  kernelWidth: 3,
  stride: 1,
  padding: 0
};

const computeFilterGradients = createFilterGradientKernel(convParams);

// inputData: Float32Array of size [16 * 28 * 28 * 3]
// gradOutputData: Float32Array of size [16 * 26 * 26 * 8]
const filterGradients = computeFilterGradients(inputData, gradOutputData);

The output filterGradients returns a 3D nested array of dimensions [outChannels][inChannels][kernelWidth * kernelHeight]. You can directly reshape or upload this result to update weights using gradient descent.

Optimizations

  • Pipelining and Textures: Set pipeline: true and immutable: true on the kernel if you intend to feed the resulting gradients directly into an optimizer kernel (e.g., Adam or SGD). This avoids transferring weights back to the CPU.
  • Index Math Hoisting: Flattened coordinates use repetitive multiplications. While WebGL compilers optimize certain index calculations, splitting operations into separate 2D texture accesses or passing pre-formatted textures matching [W, H, C * B] can reduce multiplication overhead inside deep loops.
