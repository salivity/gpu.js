Update GPU.js Kernel Constants Without Recompiling

This guide explains how to modify values that act as constants in a GPU.js pipeline without incurring the performance penalty of shader recompilation. You will learn why the standard constants configuration enforces a full pipeline rebuild and how to re-architect your kernel parameters using WebGL uniforms and texture inputs to update values instantly between execution cycles.

The Problem With GPU.js Kernel Constants

When you define values using the constants property in a GPU.js kernel configuration, GPU.js hardcodes those values directly into the underlying WebGL shader source code (typically as preprocessor definitions or static literals).

const kernel = gpu.createKernel(function() {
  return this.constants.multiplier * 10;
}, {
  constants: { multiplier: 5 },
  output: [100]
});

Because these values become immutable components of the compiled GLSL shader, altering them requires tearing down the WebGL program and compiling a new shader pipeline from scratch. In real-time rendering, physics simulations, or iterative data processing, this recompilation causes severe frame drops and latency.

The Solution: Pass Values as Kernel Arguments (Uniforms)

To update values dynamically between runs without recompiling, pass them directly as arguments to the kernel function instead of declaring them in the constants configuration object.

In GPU.js, primitive arguments (numbers, booleans, and floats) passed to the execution call are automatically treated as WebGL uniforms. Uniforms are variables pushed to the GPU memory space per draw call, bypassing the shader compilation step entirely.

Implementation Example

Instead of referencing this.constants:

// 1. Define the kernel to accept your variable as a standard parameter
const computeKernel = gpu.createKernel(function(multiplier, data) {
  return data[this.thread.x] * multiplier;
})
.setOutput([1024]);

// 2. Initial execution with multiplier = 2.5
computeKernel(2.5, inputData);

// 3. Update the value instantly on the next frame without recompilation
computeKernel(4.0, inputData);

When changing the multiplier from 2.5 to 4.0, GPU.js merely invokes gl.uniform1f() under the hood. The shader pipeline remains cached, and the execution is practically instantaneous.

Handling Array-Based Constants

If your "constants" consist of large arrays, lookup tables, or weight matrices that you periodically need to swap out:

  1. Do not use static arrays in shader code: Large arrays compiled into GLSL expand code size and worsen compile times.
  2. Pass arrays as kernel parameters: Array parameters are transferred as WebGL textures. Updating an array parameter uploads new texture data via gl.texSubImage2D without rebuilding the shader.
const transformKernel = gpu.createKernel(function(lut, data) {
  const index = Math.floor(data[this.thread.x]);
  return lut[index];
})
.setOutput([1024]);

// Pass the lookup table as an argument
transformKernel(lookupTableA, data);

// Update the lookup table dynamically
transformKernel(lookupTableB, data);

When to Keep Using constants

Only reserve the official { constants: { ... } } object for parameters that:

  • Dictate loop boundaries (GLSL requires unrolled loops to have fixed, compile-time bounds).
  • Define structural dimensions that alter the fundamental logic of your algorithm.
  • Will never change over the entire lifecycle of the application.

For all other values that change at runtime, use kernel arguments to maintain continuous GPU execution without pipeline interrupts.
