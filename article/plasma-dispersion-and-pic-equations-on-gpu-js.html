Plasma Dispersion and PIC Equations on gpu.js

Plasma dispersion relations and Particle-in-Cell (PIC) electromagnetic simulations can run on gpu.js, but their performance and feasibility depend heavily on the underlying computational architecture. While plasma dispersion equations and field updates map naturally to gpu.js, standard PIC algorithms face substantial bottlenecks due to the limitations of WebGL-based computing. Understanding how each component behaves under gpu.js clarifies what is achievable in browser-based or lightweight Node.js plasma simulations.

Plasma Dispersion Equations on gpu.js

Plasma dispersion relations describe how waves propagate through a plasma by relating frequency (\(\omega\)) to the wavenumber (\(k\)). Solving these equations typically requires:

  • Evaluating transcendental equations (such as those involving the Plasma Dispersion Function, \(Z(\zeta)\)).
  • Root-finding algorithms (e.g., Newton-Raphson or contour integration in the complex plane).
  • Eigenvalue calculations for magnetized, multi-species dielectric tensors.

Because these calculations represent "embarrassingly parallel" workloads where each grid point in \((k, \omega)\) space is independent, gpu.js handles them efficiently. By compiling JavaScript functions into WebGL fragment shaders, gpu.js can evaluate thousands of wave modes simultaneously across a discretized grid, enabling real-time visualization of kinetic and fluid dispersion curves.

Particle-in-Cell (PIC) Electromagnetic Equations

A standard electromagnetic PIC cycle consists of four distinct stages:

  1. Field Solver (Maxwell's Equations): Solves Faraday’s Law and Ampère’s Law using Finite-Difference Time-Domain (FDTD) or spectral methods.
  2. Field Interpolation (Gather): Interpolates grid-based electric and magnetic fields to particle positions.
  3. Particle Pusher (Newton-Lorentz Force): Updates particle velocities and positions using integration schemes like the Boris algorithm.
  4. Current and Charge Deposition (Scatter): Interpolates moving charges onto the spatial grid to generate charge density (\(\rho\)) and current density (\(\mathbf{J}\)).

What Works Well in gpu.js

  • Field Solvers: FDTD stencils read from neighboring grid cells and write to a fixed target. This gather-based pattern matches the native WebGL fragment shader model used by gpu.js.
  • Particle Pusher: The Boris pusher computes forces and updates coordinates independently for every particle. It maps directly to a 1D or 2D gpu.js kernel, yielding high execution speeds.
  • Field Interpolation: Particles read field data from a texture or grid array via texture lookups, which is a standard operation in WebGL shaders.

The Major Bottleneck: Charge and Current Deposition

The primary obstacle to running a full electromagnetic PIC code on gpu.js is the deposition step. PIC deposition is an irregular scatter operation: multiple particles write their fractional charges into the same grid cell simultaneously.

Because gpu.js relies on WebGL fragment shaders, it lacks native support for atomic memory additions (atomicAdd) available in compute-oriented frameworks like CUDA, OpenCL, or WebGPU. Attempting to write multiple particle contributions to a single grid cell causes race conditions and data overwrites.

Workarounds for Deposition in gpu.js

To run a functional PIC code on gpu.js, developers must use architectural workarounds:

  • Scatter-to-Gather Inversion: Instead of particles writing to the grid, grid cells query all particles within their interaction radius. While correct, this increases computational complexity from \(\mathcal{O}(N)\) to \(\mathcal{O}(M \times N_{local})\), where \(M\) is grid size and \(N_{local}\) is the local particle density.
  • CPU-GPU Hybrid Approach: The computationally heavy particle push and field solves remain on the GPU via gpu.js, while position data is read back to the CPU to perform deposition. Memory transfer overhead between CPU and GPU limits this approach to small particle counts.
  • Sorting and Reduction Passes: Sorting particles by cell index and using parallel reduction passes avoids race conditions, but implementing multi-pass reductions in gpu.js introduces considerable overhead.

Practical Assessment

Running plasma calculations on gpu.js is practical for:

  • 1D and 2D kinetic dispersion solvers.
  • Educational, small-scale electrostatic or electromagnetic 1D-3V PIC simulations.
  • Real-time browser demonstrations with fewer than \(10^5\) particles.

For production-scale, 2D/3D electromagnetic PIC codes requiring millions to billions of particles, gpu.js is constrained by WebGL's execution model and lack of atomics. For modern, in-browser simulations requiring high performance, WebGPU compute shaders provide the atomic operations and memory control needed for efficient charge deposition.
