GPU.js Parallel De-Essing and Notch Filtering

This article demonstrates how to implement parallel notch filtering and dynamic de-essing on raw 32-bit floating-point PCM audio buffers using GPU.js. By compiling JavaScript functions into WebGL compute shaders, you can bypass the sequential processing limitations of the CPU and run sample-level digital signal processing across thousands of GPU cores simultaneously.

Architecture and State Challenges in GPGPU Audio

Digital filters like traditional IIR (Infinite Impulse Response) biquads are inherently recursive: the current output sample depends on previously calculated output samples (\(y[n] = f(y[n-1], y[n-2])\)). This dependency chain prevents naive parallelization across individual audio samples.

To execute notch filtering and de-essing in parallel on a GPU without inter-thread dependencies, you must use Finite Impulse Response (FIR) convolution or local windowed processing. Each GPU thread calculates the output for a single sample index this.thread.x by reading a static window of neighboring input samples from the input PCM buffer.

1. Preparing the FIR Notch Filter Coefficients

A notch filter attenuates a narrow frequency band (such as 60 Hz hum or a specific resonant tone). You can generate symmetric FIR coefficients on the CPU using the windowed-sinc method before passing them to the GPU.

function createNotchFIR(sampleRate, centerFreq, bandwidth, numTaps) {
  const h = new Float32Array(numTaps);
  const mid = (numTaps - 1) / 2;
  const omegaC = (2 * Math.PI * centerFreq) / sampleRate;
  const deltaOmega = (2 * Math.PI * bandwidth) / sampleRate;

  for (let i = 0; i < numTaps; i++) {
    if (i === mid) {
      h[i] = 1 - (deltaOmega / Math.PI);
    } else {
      const n = i - mid;
      // Band-stop filter sinc calculation with Blackman window
      const sinc = (Math.sin(Math.PI * n) - Math.sin(omegaC * n) * 2 * Math.sin((deltaOmega * n) / 2)) / (Math.PI * n);
      const window = 0.42 - 0.5 * Math.cos((2 * Math.PI * i) / (numTaps - 1)) + 0.08 * Math.cos((4 * Math.PI * i) / (numTaps - 1));
      h[i] = sinc * window;
    }
  }
  return h;
}

2. Formulating Parallel Dynamic De-Essing

De-essing suppresses harsh high frequencies (sibilance, usually between 4 kHz and 10 kHz). A GPU-based parallel de-esser processes each sample using three stages:

  1. Sidechain Band-pass: Convolve a local window of samples with a band-pass FIR filter centered on the sibilance range.
  2. Envelope Estimation: Measure the Root Mean Square (RMS) energy within a local window around the current sample.
  3. Dynamic Attenuation: If the measured RMS exceeds a defined threshold, calculate a gain reduction factor and apply it directly to the center sample.

3. GPU.js Combined Processing Kernel

The following complete implementation builds a GPU.js kernel that sequentially applies the FIR notch filter and the dynamic de-essing algorithm on raw PCM data in a single shader pass.

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Kernel accepting audio buffer and filter parameters
function createAudioProcessorKernel(bufferLength, notchTapsCount, deessTapsCount) {
  return gpu.createKernel(function (
    inputSignal,
    notchCoeffs,
    deessCoeffs,
    rmsWindowSize,
    threshold,
    ratio
  ) {
    const idx = this.thread.x;
    const notchMid = Math.floor(this.constants.notchTaps / 2);
    const deessMid = Math.floor(this.constants.deessTaps / 2);

    // 1. Apply FIR Notch Filter
    let notchedSample = 0.0;
    for (let i = 0; i < this.constants.notchTaps; i++) {
      const sampleIdx = idx - notchMid + i;
      if (sampleIdx >= 0 && sampleIdx < this.constants.totalSamples) {
        notchedSample += inputSignal[sampleIdx] * notchCoeffs[i];
      }
    }

    // 2. Sibilance Detection (Band-pass Convolution)
    let sibilantEnergy = 0.0;
    const halfWindow = Math.floor(rmsWindowSize / 2);
    
    for (let w = -halfWindow; w <= halfWindow; w++) {
      const windowIdx = idx + w;
      if (windowIdx >= 0 && windowIdx < this.constants.totalSamples) {
        let bandpassed = 0.0;
        for (let j = 0; j < this.constants.deessTaps; j++) {
          const bpSampleIdx = windowIdx - deessMid + j;
          if (bpSampleIdx >= 0 && bpSampleIdx < this.constants.totalSamples) {
            bandpassed += inputSignal[bpSampleIdx] * deessCoeffs[j];
          }
        }
        sibilantEnergy += bandpassed * bandpassed;
      }
    }

    const rms = Math.sqrt(sibilantEnergy / rmsWindowSize);

    // 3. Dynamic Gain Reduction
    let gain = 1.0;
    if (rms > threshold) {
      const overDb = 20.0 * (Math.log(rms / threshold) / Math.LN10);
      const reductionDb = overDb * (1.0 - 1.0 / ratio);
      gain = Math.pow(10.0, -reductionDb / 20.0);
    }

    // Return the final processed sample
    return notchedSample * gain;
  })
  .setConstants({
    totalSamples: bufferLength,
    notchTaps: notchTapsCount,
    deessTaps: deessTapsCount
  })
  .setOutput([bufferLength]);
}

4. Executing the Pipeline on PCM Buffers

To run the pipeline, convert your audio stream or file to a single-channel Float32Array, initialize the filter taps, and pass the data directly to the compiled kernel.

const sampleRate = 44100;
const rawPcm = new Float32Array(/* Extracted PCM buffer */);

const notchTaps = 65;
const deessTaps = 33;
const rmsWindowSize = 128; // Window length for envelope detection
const threshold = 0.05;    // Linear amplitude threshold for sibilance
const compressionRatio = 4.0;

// Generate CPU-side FIR coefficients
const notchCoefficients = createNotchFIR(sampleRate, 60, 10, notchTaps);
const deessBandpassCoefficients = createBandpassFIR(sampleRate, 6000, 2000, deessTaps);

// Create and execute kernel

// Cast Float32Array output back to standard audio pipeline

Performance Considerations

  • Tap Count Boundaries: The inner loops run per thread. Keeping tap sizes odd and compact (e.g., 33 to 129 taps) prevents shader execution timeouts on lower-end WebGL implementations.
  • Buffer Partitioning: When dealing with multi-minute files, partition the Float32Array into chunk sizes between \(2^{18}\) and \(2^{20}\) samples. This limits memory transfer overhead to the GPU texture memory and ensures continuous frame rates inside browser environments.
