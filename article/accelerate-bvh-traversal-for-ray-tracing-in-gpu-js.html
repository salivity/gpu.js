Accelerate BVH Traversal for Ray Tracing in GPU.js

Bounding Volume Hierarchy (BVH) traversal represents the primary computational bottleneck in browser-based ray tracing pipelines. This article explains how to accelerate BVH ray intersection inside GPU.js by structuring memory for the WebGL pipeline, eliminating recursion, optimizing Ray-AABB (Axis-Aligned Bounding Box) intersection tests, and minimizing execution divergence across GPU threads.

Linearize the BVH into Texture-Friendly Arrays

GPU.js executes kernels by compiling JavaScript functions into WebGL fragment shaders. WebGL shaders cannot navigate pointer-based tree structures or dynamically allocated nodes. To traverse a BVH, you must flatten the hierarchical tree into linear, typed arrays before passing them to the GPU.js kernel.

Organize your node data into a continuous Float32Array. Each node can be represented using 32-byte or 64-byte alignments matching 4-component vectors (vec4). For example, two vec4 structures per node:

  • Vector A: [min_x, min_y, min_z, left_child_or_primitive_offset]
  • Vector B: [max_x, max_y, max_z, primitive_count_or_miss_link]

Flattening the structure into tightly packed textures maximizes texture cache hits during traversal.

Implement Stackless or Fixed-Stack Traversal

WebGL lacks native call-stack recursion. Because GPU.js kernels cannot recurse, traversal must be converted into an iterative loop using one of two approaches:

1. The Skip-Pointer (Rope) Method

The most performant approach for GPU.js is stackless traversal using skip-pointers (also called "escape indices"). Each BVH node stores an index to the next node to visit when the current bounding box test yields a miss.

  • On Hit: Move directly to the left child (offset index + 1).
  • On Miss: Jump directly to the precomputed skip target.

This removes the need for any local array stack, reducing private register allocation per invocation and preventing memory spills.

2. Fixed-Size Emulated Stacks

If your acceleration structure requires depth-first traversal with back-to-front sorting:

  • Allocate a fixed-size integer array inside the kernel (e.g., const stack = new Int32Array(32)).
  • Avoid dynamic lengths; manage a simple pointer index variable (let stackPtr = 0).
  • Keep the maximum depth strictly bounded during the offline BVH build phase to avoid exceeding the fixed array boundary.

Optimize the Ray-AABB Slab Test

Repeated box intersection tests dominate traversal runtime. Standard ray-box intersection equations involve divisions that degrade shader performance.

  • Precompute Reciprocals: Compute ray direction inverses (1.0 / rayDirX, 1.0 / rayDirY, 1.0 / rayDirZ) on the CPU or once at the start of the ray generation kernel.
  • Eliminate Branching in Slab Tests: Use Math.min() and Math.max() (which map directly to native GPU instructions min and max) rather than if-else blocks to determine the near and far intersection distances:
// Precomputed invDirX, invDirY, invDirZ passed to traversal
const t1 = (nodeMinX - rayOrigX) * invDirX;
const t2 = (nodeMaxX - rayOrigX) * invDirX;
const tNearX = Math.min(t1, t2);
const tFarX = Math.max(t1, t2);

const tMin = Math.max(tNearX, Math.max(tNearY, tNearZ));
const tMax = Math.min(tFarX, Math.min(tFarY, tFarZ));

const hit = tMax >= Math.max(tMin, 0.0) && tMin < hitDistance;

Reduce Warp and Workgroup Divergence

GPU execution efficiency drops dramatically when adjacent threads follow different execution branches. Rays traversing different branches of the BVH cause execution serialization within a warp or wavefront.

  • Ray Sorting: Sort rays by spatial direction (e.g., using Morton codes or simple screen-space tiling) before execution. Rays covering adjacent pixels should evaluate similar regions of the BVH simultaneously.
  • Early Out Traversal: Maintain the current closest intersection distance (hitDistance) globally within the thread. Test tMin < hitDistance before evaluating the node's children to prune dead branches immediately.
  • SAH Construction: Build the BVH using a Surface Area Heuristic (SAH) on the CPU prior to sending data to GPU.js. A well-balanced SAH tree minimizes empty space within bounding boxes and drastically cuts traversal steps across all rays.
