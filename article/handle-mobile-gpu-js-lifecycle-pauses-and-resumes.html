Handle Mobile GPU.js Lifecycle Pauses and Resumes

Running GPU-accelerated computations on mobile devices using gpu.js presents unique challenges when users switch apps or lock their screens. Mobile operating systems aggressively manage resources by throttling execution, suspending WebViews, or discarding WebGL contexts entirely to preserve battery life and memory. This guide outlines how to handle background and foreground transitions, prevent dropped contexts, pause compute loops gracefully, and rebuild gpu.js kernels when returning to the foreground.

The Challenge with Mobile WebGL and Backgrounding

When a mobile browser or hybrid wrapper (such as Capacitor or Cordova) transitions to the background, two primary issues occur:

  1. Thread Throttling: Timers (setInterval, setTimeout) and requestAnimationFrame callbacks are either throttled heavily or stopped completely.
  2. WebGL Context Loss: The OS may reclaim the GPU memory allocated to the underlying WebGL canvas, triggering a webglcontextlost event. If a gpu.js kernel executes while the context is lost, the application throws unrecoverable runtime errors.

Managing these transitions requires intercepting lifecycle events, safely halting execution loops, and verifying or recreating the gpu.js context upon return.

Detecting Lifecycle Transitions

For standard mobile browsers and PWAs, the Page Visibility API is the standard mechanism to track lifecycle shifts. For hybrid frameworks, use the native application lifecycle events.

Web and PWA Implementation

document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    pauseGPUProcessing();
  } else if (document.visibilityState === 'visible') {
    resumeGPUProcessing();
  }
});

Hybrid Apps (Capacitor Example)

import { App } from '@capacitor/app';

App.addListener('appStateChange', ({ isActive }) => {
  if (!isActive) {
    pauseGPUProcessing();
  } else {
    resumeGPUProcessing();
  }
});

Implementing a Safe Pause Mechanism

Avoid running single, uninterrupted computations that take seconds to complete on mobile devices. Instead, break intensive tasks into discrete chunks or frames. Track a processing state flag to exit execution cleanly when a pause event fires.

let isPaused = false;
let isProcessing = false;

function pauseGPUProcessing() {
  isPaused = true;
}

async function runComputePipeline(dataChunks) {
  isProcessing = true;

  for (let i = 0; i < dataChunks.length; i++) {
    if (isPaused) {
      saveProgress(i);
      isProcessing = false;
      return;
    }

    // Execute gpu.js kernel
    results[i] = computeKernel(dataChunks[i]);

    // Yield back to the event loop between iterations
    await new Promise((resolve) => setTimeout(resolve, 0));
  }

  isProcessing = false;
}

Handling WebGL Context Loss in gpu.js

gpu.js abstracts the underlying WebGL context, but you must still monitor the canvas element associated with it. If the context is dropped by the mobile OS, the compiled kernels become invalid.

1. Intercept Context Events

Obtain the canvas from your GPU instance and bind listeners for context destruction and restoration:

let gpu = new GPU();
let computeKernel;

function initKernels() {
  computeKernel = gpu.createKernel(function (data) {
    return data[this.thread.x] * 2;
  }).setOutput([1024]);
}

const canvas = gpu.canvas;

canvas.addEventListener('webglcontextlost', (event) => {
  // Prevent default behavior to allow recovery
  event.preventDefault();
  pauseGPUProcessing();
  console.warn('WebGL context lost. Execution halted.');
}, false);

canvas.addEventListener('webglcontextrestored', () => {
  console.info('WebGL context restored. Re-initializing kernels.');
  reinitializeGPU();
}, false);

2. Rebuilding the Kernel State

When the context is restored, the compiled shaders and textures are gone. The cleanest recovery method is to destroy the old gpu.js instance, instantiate a new one, and recompile the kernels:

function reinitializeGPU() {
  try {
    gpu.destroy();
  } catch (e) {
    // Suppress errors if context cleanup fails
  }

  gpu = new GPU();
  initKernels();

  if (document.visibilityState === 'visible') {
    resumeGPUProcessing();
  }
}

Resuming Execution in the Foreground

When the app returns to the foreground, verify that the WebGL context is functional before resuming computations.

function resumeGPUProcessing() {
  if (!isPaused) return;

  // Check if context is active
  const gl = gpu.context;
  if (!gl || gl.isContextLost()) {
    console.warn('Cannot resume: context is not ready yet.');
    return;
  }

  isPaused = false;

  // Only restart if not already active
  if (!isProcessing) {
    runComputePipeline(remainingChunks);
  }
}

Best Practices for Mobile Stability

  • Keep Outputs in TypedArrays: Avoid keeping large amounts of intermediate data as GPU textures (pipeline: true) while backgrounded. If the context drops, that texture data is lost permanently. Pull critical state down to CPU memory (Float32Array) after significant milestones.
  • Keep Kernels Small: Mobile GPUs compile kernels slower than desktops. If you must recompile upon foregrounding, modular kernels compile faster and reduce UI freeze times on resume.
  • Release Memory Proactively: If the app enters the background for extended periods, call .destroy() on intermediate textures to minimize the chance of the OS terminating the application process due to high memory usage.
