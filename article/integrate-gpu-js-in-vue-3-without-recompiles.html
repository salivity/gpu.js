Integrate GPU.js in Vue 3 Without Recompiles

Integrating GPU.js into Vue 3's Composition API requires separating expensive WebGL shader compilation from Vue’s reactive cycle. Compiling a GPU.js kernel is a resource-intensive operation that translates JavaScript functions into WebGL shaders. If a kernel is unintentionally wrapped in Vue’s deep reactivity system or instantiated within a recurring reactive trigger, the application faces severe performance degradation. This guide explains how to properly isolate GPU instances and compiled kernels using shallowRef or markRaw, instantiate them once, and safely execute them using reactive inputs.

The Problem: Reactive Proxies and Kernel Re-creation

When you place an object inside Vue 3's ref() or reactive(), Vue creates a deep Proxy wrapper around the object and its internal methods. GPU.js relies on native WebGL contexts, typed arrays, and hardware references that can break or encounter unexpected overhead when intercepted by JavaScript Proxies.

Furthermore, if the kernel declaration gpu.createKernel() is placed inside a computed property, a watchEffect, or regular component render logic, Vue will recompile the WebGL shader on every reactive state change. Shader compilation takes hundreds of milliseconds, nullifying any computational performance gains provided by the GPU.

Architectural Rules for GPU.js in Vue 3

  1. Compile Once, Run Many Times: The GPU instance and its compiled kernels must be initialized only once during the component's setup or mounting phase.
  2. Bypass Deep Reactivity: Use shallowRef() to store kernel functions or wrap the new GPU() instance with markRaw(). This tells Vue not to traverse or proxy the WebGL context.
  3. Pass Reactive Data as Kernel Arguments: Supply changing state into the kernel via dynamic parameters rather than rebuilding kernels with hardcoded values.
  4. Clean Up Resources: WebGL contexts must be manually destroyed when the component unmounts using gpu.destroy() to prevent memory leaks in the browser.

Implementation Pattern

The following pattern uses the Vue 3 <script setup> syntax to maintain optimal performance.

import { ref, shallowRef, onMounted, onBeforeUnmount } from 'vue';
import { GPU } from 'gpu.js';

// 1. Reactive state for UI and inputs
const matrixSize = 512;
const isProcessing = ref(false);
const executionTime = ref(0);

// 2. Non-reactive or shallow-reactive holders for GPU resources
const gpuInstance = shallowRef(null);
const computeKernel = shallowRef(null);

onMounted(() => {
  // Initialize the GPU instance without deep proxying
  const gpu = new GPU();
  gpuInstance.value = gpu;

  // Compile the kernel once
  computeKernel.value = gpu.createKernel(function (a, b) {
    let sum = 0;
    for (let i = 0; i < 512; i++) {
      sum += a[this.thread.y][i] * b[i][this.thread.x];
    }
    return sum;
  })
  .setOutput([matrixSize, matrixSize]);
});

// 3. Execution function reading reactive data without recompiling
function runComputation(matrixA, matrixB) {
  if (!computeKernel.value) return;

  isProcessing.value = true;
  const start = performance.now();

  // Execute the pre-compiled shader
  const result = computeKernel.value(matrixA, matrixB);

  executionTime.value = performance.now() - start;
  isProcessing.value = false;

  return result;
}

// 4. Free WebGL context on teardown
onBeforeUnmount(() => {
  if (gpuInstance.value) {
    gpuInstance.value.destroy();
  }
});

Dynamic Dimensions Without Full Recompilation

If output dimensions must change dynamically, do not recreate the entire GPU instance. While changing .setOutput([x, y]) fundamentally requires a new kernel compilation, you can mitigate the performance penalty by caching kernels inside a standard JavaScript Map using dimension keys:

const kernelCache = new Map();

function getOrCreateKernel(width, height) {
  const key = `${width}x${height}`;
  if (kernelCache.has(key)) {
    return kernelCache.get(key);
  }

  const newKernel = gpuInstance.value.createKernel(function (data) {
    return data[this.thread.x] * 2;
  }).setOutput([width, height]);

  kernelCache.set(key, newKernel);
  return newKernel;
}

By storing the kernel cache in a standard JavaScript Map outside Vue's reactivity chain, the application avoids proxy overhead, reuses existing WebGL shaders, and only compiles when a completely new dimension profile is requested.
