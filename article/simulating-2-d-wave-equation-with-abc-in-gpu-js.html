Simulating 2D Wave Equation with ABC in GPU.js

Yes, the two-dimensional wave equation with absorbing boundary conditions (ABCs) can be efficiently simulated using gpu.js. By compiling JavaScript-like code into WebGL shaders, gpu.js enables parallelized finite-difference time-domain (FDTD) calculations directly on the GPU within a web browser. This article explains how the 2D wave equation is mapped to GPU kernels, how absorbing boundary conditions prevent boundary reflections, and how to structure the pipeline for real-time performance.

Discretizing the 2D Wave Equation

The standard 2D acoustic wave equation is defined as:

\[\frac{\partial^2 u}{\partial t^2} = c^2 \left( \frac{\partial^2 u}{\partial x^2} + \frac{\partial^2 u}{\partial y^2} \right)\]

where \(u(x, y, t)\) represents wave amplitude, and \(c\) is the wave propagation speed. Using standard second-order central finite differences on an evenly spaced grid (\(\Delta x = \Delta y\)), the displacement at the next time step (\(u^{n+1}\)) is computed using values from the current time step (\(u^n\)) and the previous time step (\(u^{n-1}\)):

\[u^{n+1}_{i,j} = 2u^n_{i,j} - u^{n-1}_{i,j} + r^2 \left( u^n_{i+1,j} + u^n_{i-1,j} + u^n_{i,j+1} + u^n_{i,j-1} - 4u^n_{i,j} \right)\]

where \(r = c \frac{\Delta t}{\Delta x}\) is the Courant number, which must satisfy the Courant-Friedrichs-Lewy (CFL) stability condition (\(r \le 1/\sqrt{2} \approx 0.707\)).

Implementing Absorbing Boundary Conditions (ABCs)

Standard boundaries act as hard reflectors (Dirichlet boundaries: \(u = 0\)) or open-ended reflectors (Neumann boundaries: \(\frac{\partial u}{\partial n} = 0\)). To simulate infinite open domains, absorbing boundary conditions must be applied to suppress unphysical reflections:

  1. Mur's First-Order ABC: Mur's formulation simulates one-way wave propagation normal to the boundary. For example, at the left boundary (\(i = 0\)): \[u^{n+1}_{0,j} = u^n_{1,j} + \frac{c\Delta t - \Delta x}{c\Delta t + \Delta x} (u^{n+1}_{1,j} - u^n_{0,j})\] Because this condition requires values from neighboring interior cells, it can be evaluated directly in the GPU kernel based on thread coordinates.
  2. Sponge Layers (Damping Boundaries): An alternative, GPU-friendly approach is an absorbing layer (such as a simplified Perfectly Matched Layer or continuous damping zone) along the outer perimeter. A damping coefficient \(\gamma(x, y)\) is introduced, scaling to zero reflection over several grid cells by adding a dissipation term: \[u^{n+1}_{i,j} = \frac{1}{1 + \gamma} \left[ 2u^n_{i,j} - (1 - \gamma)u^{n-1}_{i,j} + r^2 \nabla^2 u^n_{i,j} \right]\] This approach avoids conditional logic branches at the edges and maps smoothly to SIMD GPU architectures.

Setting Up the Simulation in GPU.js

A high-performance simulation in gpu.js requires three core steps:

  • Kernel Definition: Create a 2D kernel that outputs the next state \(u^{n+1}\). Each thread corresponds to a grid point accessed via this.thread.x and this.thread.y.
  • Branching or Masking: Use coordinate checks (if (this.thread.x === 0) ...) for analytical ABCs like Mur's, or supply a static damping texture for sponge layers to maintain uniform code paths.
  • Pipeline Mode: Set pipeline: true on the kernel. This keeps computation results in WebGL texture memory, avoiding the major performance penalty of copying data back to the CPU between time steps. Two texture buffers are swapped each frame to provide \(u^n\) and \(u^{n-1}\) inputs.

Practical Considerations and Limitations

  • Precision: Standard WebGL 1.0 environments in gpu.js may fall back to 16-bit float textures if float extensions are not supported, which can introduce numerical drift over long simulations. Ensuring WebGL 2.0 or 32-bit floating-point support is recommended.
  • Conditional Branching: Extensive conditional branching inside the kernel can cause warp divergence on the GPU. Using continuous damping masks rather than multiple distinct boundary checks generally yields higher frame rates.
  • Step Swapping: Three state arrays (\(u^{n-1}\), \(u^n\), and \(u^{n+1}\)) must cycle continuously, requiring precise reference rotation in JavaScript to prevent memory reallocation.
