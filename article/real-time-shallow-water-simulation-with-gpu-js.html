Real-Time Shallow Water Simulation with GPU.js

Simulating 2D shallow water wave equations with reflective obstacle boundaries in real time is entirely feasible in modern web browsers using GPU.js. By translating explicit finite-difference numerical solvers into WebGL fragment shaders, GPU.js leverages the parallel architecture of the graphics card to update fluid grids at interactive frame rates. This article breaks down the mathematical formulation, boundary condition implementations, and performance considerations necessary to achieve stable, real-time wave dynamics with solid obstacles.

The Shallow Water Equations

The shallow water equations, also known as the Saint-Venant equations, describe fluid flow below a pressure surface where horizontal scale is significantly larger than fluid depth. In a simplified, linearized 2D form suitable for high-performance wave rendering, the system governs fluid height (\(h\)) and horizontal velocities (\(u, v\)):

\[\frac{\partial h}{\partial t} + H \left( \frac{\partial u}{\partial x} + \frac{\partial v}{\partial y} \right) = 0\]

\[\frac{\partial u}{\partial t} + g \frac{\partial h}{\partial x} = 0\]

\[\frac{\partial v}{\partial t} + g \frac{\partial h}{\partial y} = 0\]

Where \(H\) is the mean fluid depth and \(g\) is gravitational acceleration. For full non-linear behavior, advection terms are included, but the core wave propagation mechanics remain numerically similar.

Executing via GPU.js

GPU.js abstracts the complexities of writing raw GLSL shaders by compiling JavaScript functions into WebGL compute shaders. In a numerical simulation, the computational domain is discretized into a 2D grid where each cell corresponds to a pixel.

To execute the solver:

  1. Pipelining: Enable pipeline: true on GPU.js kernels. This keeps calculation outputs in GPU memory as textures, preventing expensive round-trip transfers between the CPU and GPU.
  2. Ping-Pong Buffering: Numerical PDE solvers require the state at the previous time step to compute the next. Two alternating textures (read-state and write-state) are maintained to allow safe read-write operations per time step.
  3. Explicit Integration: Numerical schemes like the Leapfrog method or Lax-Wendroff can be expressed directly in GPU.js kernels, where each thread updates a single cell by sampling its immediate orthogonal neighbors (\(i \pm 1, j \pm 1\)).

Implementing Reflective Obstacle Boundaries

Reflective boundaries require enforcing zero normal flux across solid surfaces. In physical terms, fluid cannot penetrate a solid wall, causing incident waves to reflect back into the domain with equal phase.

  1. Obstacle Masking: An auxiliary 2D array or texture acts as a collision mask, where values designate whether a cell is fluid or an obstacle.
  2. Velocity Inversion (Dirichlet Condition): For any cell adjacent to an obstacle, the velocity normal to the obstacle boundary is set to zero (\(u \cdot \hat{n} = 0\)), or mirrored negatively to eliminate mass transfer through the boundary interface.
  3. Height Extrapolation (Neumann Condition): Fluid height at the boundary cell is set equal to the adjacent fluid cell (\(\frac{\partial h}{\partial n} = 0\)). This ensures zero pressure gradient across the boundary wall.

In GPU.js, this logic is handled within the kernel via conditional checks against the obstacle mask texture. If a neighbor is marked as solid, the kernel replaces that neighbor's state with the reflective counterpart before applying the finite-difference stencil.

Performance and Stability Constraints

Real-time performance of 60 FPS or higher is easily achievable on consumer hardware for grid sizes ranging from \(256 \times 256\) up to \(1024 \times 1024\). However, two key constraints must be managed:

  • The Courant-Friedrichs-Lewy (CFL) Condition: The numerical time step (\(\Delta t\)) must satisfy \(\Delta t \le \frac{\Delta x}{\sqrt{gH}}\) to prevent numerical instability and exponential explosion of wave amplitudes. Multiple sub-steps per animation frame may be required if spatial resolution (\(\Delta x\)) is high.
  • Precision Limits: GPU.js relies on WebGL texture precision. Ensuring that WebGL floating-point textures (OES_texture_float) are supported is critical for preventing quantization artifacts in fluid height calculations.
