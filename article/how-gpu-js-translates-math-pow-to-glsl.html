How GPU.js Translates Math.pow to GLSL

When executing kernels on the GPU, gpu.js accelerates JavaScript by transpiling its syntax into WebGL-compatible GLSL (OpenGL Shading Language). This article explains the internal pipeline gpu.js uses to convert JavaScript's standard Math.pow(base, exponent) call into GLSL's native pow(x, y) function, covering abstract syntax tree parsing, strict float type enforcement, and execution implications on the GPU hardware.

AST Parsing and Function Mapping

To convert JavaScript code into shader code, gpu.js first uses an Abstract Syntax Tree (AST) parser (such as Acorn). When you write a kernel containing Math.pow(base, exponent), the parser identifies this operation as a CallExpression whose callee is a MemberExpression corresponding to the Math object and the pow property.

The internal transpiler in gpu.js traverses this AST. When it encounters the Math.pow signature, it redirects the call to its internal GLSL translation dictionary. Instead of emitting a JavaScript function call, it replaces the identifier with GLSL's native pow() function.

Type Coercion and Float Casting

The primary technical hurdle during this translation is GLSL's strict type system. In standard JavaScript, numbers are dynamic 64-bit floating-point values, and Math.pow(2, 3) works seamlessly with integer primitives. Conversely, GLSL requires explicit types, and its built-in pow() function is overloaded strictly for floating-point values (float, vec2, vec3, vec4), defined as:

genType pow(genType x, genType y);

During transpilation, gpu.js enforces the following rules on Math.pow arguments:

  1. Literal Conversion: Integer literals are converted to floating-point representation (e.g., 2 becomes 2.0).
  2. Variable Casting: If an argument is determined to be an integer variable, gpu.js automatically injects explicit float() casts around the arguments to satisfy the GLSL compiler.
  3. Matching Dimensions: Both arguments must match in type and vector dimensions, meaning scalar floats must be paired with scalar floats.

Consequently, JavaScript written as:

let result = Math.pow(x, 2);

is translated into the following GLSL output:

float result = pow(x, 2.0);

Hardware Execution and Behavioral Divergence

Once translated to GLSL pow(), the calculation is executed directly by the GPU’s hardware vector units. This direct translation introduces an important behavioral difference compared to CPU-based JavaScript:

  • In JavaScript, Math.pow(-2, 3) cleanly returns -8.
  • In GLSL, pow(x, y) is calculated using exponential and logarithmic hardware instructions equivalent to exp2(y * log2(x)). Because the logarithm of a negative number is undefined, passing a negative base to pow() in GLSL results in undefined behavior (often returning NaN or 0.0), regardless of whether the exponent is an integer.

To maintain maximum compute throughput, gpu.js does not insert conditional branches or wrapper logic to simulate JavaScript's negative base handling. It delegates the computation directly to the graphics driver's native GLSL pow() implementation.
