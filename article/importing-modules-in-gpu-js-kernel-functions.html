Importing Modules in GPU.js Kernel Functions

You cannot directly import ES modules or CommonJS packages inside a GPU.js kernel function. This article explains why the GPU.js architecture prevents direct module imports within kernels and outlines the standard alternatives, such as CPU-side pre-processing and using the native addFunction feature to run custom logic on the GPU.

Why Module Imports Do Not Work in GPU.js Kernels

GPU.js works by parsing standard JavaScript functions, analyzing their Abstract Syntax Tree (AST), and transpiling the operations into WebGL shader code (GLSL). Because the compiled code runs directly on the graphics card rather than within a standard JavaScript runtime like Node.js or the browser's V8 engine, the kernel does not have access to typical JavaScript runtime features.

Statements such as import, export, or require() cannot be transpiled into GLSL. Attempting to use them inside a kernel function will result in compilation errors. Furthermore, any external library code that relies on standard JavaScript objects, DOM APIs, heap allocations, or dynamic memory management is incompatible with the GPU execution model.

Workarounds and Alternatives

To integrate external package logic with GPU.js, you must separate CPU-bound logic from GPU-accelerated numeric operations.

1. Pre-process Data on the CPU

The most common solution is to run the module's logic on the CPU prior to kernel execution. Once the data is transformed into simple flat arrays or matrices, pass the resulting numeric values directly into the GPU.js kernel as arguments:

// Step 1: Use CommonJS or ES modules on the CPU
const externalPackage = require('external-package');
const processedInput = externalPackage.compute(rawData);

// Step 2: Pass the processed arrays into the kernel
const kernel = gpu.createKernel(function(data) {
  return data[this.thread.x] * 2;
}).setOutput([processedInput.length]);

const result = kernel(processedInput);

2. Use gpu.addFunction() for Modular Code

If you need reusable helper functions inside your kernel, you cannot import them from standard external packages, but you can define custom functions using gpu.addFunction(). Any function added this way must contain purely mathematical, GLSL-transpilable JavaScript:

function customFormula(a, b) {
  return a * b + 1.0;
}

gpu.addFunction(customFormula);

const kernel = gpu.createKernel(function(values) {
  return customFormula(values[this.thread.x], 2.0);
}).setOutput([100]);

3. Re-implement Algorithms in Pure GLSL-Compatible JavaScript

If an external package contains a mathematical algorithm you must run on the GPU, you must extract and rewrite the core algorithm to avoid dynamic objects, closures, strings, or native JS array methods like .map() or .reduce(). Once reduced to basic arithmetic and typed array indexing, the logic can be included directly inside the kernel body or registered as a helper function.
