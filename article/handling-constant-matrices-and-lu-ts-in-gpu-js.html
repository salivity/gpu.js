Handling Constant Matrices and LUTs in GPU.js

GPU.js accelerates JavaScript calculations by transpiling code into WebGL shaders, utilizing GPU memory to store and sample static data structures such as constant matrices and lookup tables (LUTs). Because WebGL shaders lack the native unified constant memory found in dedicated compute frameworks like CUDA, GPU.js primarily abstracts constant matrices and LUTs by converting them into immutable WebGL textures or GLSL uniform declarations. This architecture ensures high-throughput, low-latency parallel access while respecting the memory limitations of browser-based graphic pipelines.

The constants Configuration

GPU.js allows developers to supply fixed data using the constants property when creating a kernel via gpu.createKernel(). When a matrix or lookup table is defined in the constants object, GPU.js evaluates its dimensionality, data type, and size to determine the most efficient method for binding that data into the kernel’s execution context.

Once bound, these constants remain read-only throughout the kernel's execution, allowing thousands of concurrent GPU threads to read from identical offsets without race conditions or memory locking overhead.

WebGL Texture-Based Storage

For large constant matrices or lookup tables, GPU.js avoids native shader array limits by encoding the data into 2D floating-point WebGL textures:

  1. Texture Packing: The multi-dimensional array or lookup table is flattened and written to an internal WebGL texture buffer on the GPU.
  2. Sampler Binding: The generated GLSL shader binds the texture to a 2D sampler uniform (sampler2D).
  3. Sampling Logic: Whenever your kernel code accesses this.constants.myLUT[y][x], the GPU.js compiler replaces the array subscript syntax with an internal texture lookup function (such as texture2D in WebGL 1 or texelFetch in WebGL 2).

This approach delegates memory caching to the GPU's hardware texture cache. Because texture caches are heavily optimized for spatial locality, kernels performing nearby lookups benefit from fast cache hits and high memory bandwidth.

Inline GLSL Constant Arrays

When a lookup table or matrix is very small and statically declared directly inside the kernel function body, GPU.js transpiles the array into a native GLSL constant array (e.g., const float lut[4] = float[4](...);).

In WebGL 2 contexts, these arrays reside directly in the shader’s register or uniform memory space, providing direct indexing with minimal overhead. However, WebGL 1 imposes strict limitations on dynamic indexing into native GLSL arrays; if dynamic index access is required under WebGL 1, GPU.js defaults back to texture emulation to preserve cross-platform compatibility.

Performance and Memory Optimization

To maximize throughput when using constant matrices and LUTs in GPU.js, consider the following behaviors:

  • Zero Per-Run Overhead: Defining lookup tables within the constants mapping uploads the data to GPU memory during kernel compilation. Subsequent calls to the kernel execute without re-uploading the table, eliminating CPU-to-GPU data transfer bottlenecks during repeated computations.
  • Dimension Alignment: Textures perform best when dimensions match hardware texture size limits (often 2048x2048, 4096x4096, or higher depending on the hardware). GPU.js automatically maps 1D LUTs into 2D texture dimensions if the 1D length exceeds the maximum allowed 1D texture width.
  • Precision Modes: Setting the kernel mode to precision: 'single' ensures that constant floating-point matrices retain high precision without unexpected rounding issues during texture sampling.
