Spatial Lotka-Volterra Dynamics in gpu.js

This article explains how to model continuous spatial Lotka-Volterra predator-prey dynamics using gpu.js, a JavaScript library that compiles code to run on WebGL-enabled GPUs. It breaks down the mathematical representation of reaction-diffusion equations, the mechanics of mapping grid cells to GPU threads, implementation details such as discrete Laplacians and ping-pong buffering, and practical constraints regarding numerical stability in browser-based parallel computing.

The Mathematical Foundation

Standard Lotka-Volterra models define temporal interactions between predators and prey using ordinary differential equations (ODEs). To expand this model across continuous space, it must be converted into a reaction-diffusion partial differential equation (PDE) system:

\[\frac{\partial u}{\partial t} = D_u \nabla^2 u + \alpha u - \beta u v\] \[\frac{\partial v}{\partial t} = D_v \nabla^2 v + \delta u v - \gamma v\]

Where:

  • \(u(x, y, t)\) is prey density, and \(v(x, y, t)\) is predator density.
  • \(D_u\) and \(D_v\) are the spatial diffusion coefficients.
  • \(\nabla^2\) is the Laplace operator representing spatial diffusion.
  • \(\alpha, \beta, \delta,\) and \(\gamma\) denote natural prey growth, predation rate, predator reproduction efficiency, and predator mortality, respectively.

When modeled on a continuous grid, the spatial domain is discretized into a 2D mesh, and spatial derivatives are computed using finite difference methods.

How gpu.js Executes Grid-Based Simulations

gpu.js translates standard JavaScript functions into WebGL fragment shaders, executing operations simultaneously across thousands of GPU cores.

Because ecological reaction-diffusion models require localized, independent calculations for every point in space, they map directly to the Single Instruction, Multiple Threads (SIMT) architecture of graphics hardware. Each thread represents a discrete grid coordinate \((x, y)\), computing local interactions and exchanging density data with immediate neighbors.

Implementation Architecture

1. Grid Discretization and State Representation

To track two populations (\(u\) and \(v\)), the spatial domain is maintained as 2D textures or arrays. Because gpu.js handles multidimensional outputs, the state can be stored as distinct floating-point arrays or mapped across color channels (e.g., prey in the Red channel, predators in the Green channel).

2. Spatial Diffusion via Discrete Laplacian

Diffusion requires calculating the flow of organisms into and out of adjacent cells. In gpu.js, this is achieved through a 2D discrete convolution stencil (such as a 5-point stencil):

\[\nabla^2 u \approx \frac{u_{x+1,y} + u_{x-1,y} + u_{x,y+1} + u_{x,y-1} - 4u_{x,y}}{\Delta x^2}\]

Within the gpu.js kernel, threads sample these adjacent coordinates using thread-indexed lookups: this.thread.x and this.thread.y.

3. Numerical Integration Step

Each iteration represents a time increment (\(\Delta t\)). The kernel calculates:

  1. The discrete Laplacian for both species.
  2. The reaction kinetics (predation and growth rates).
  3. The integrated state update using a method such as Forward Euler:

\[u^{t+\Delta t} = u^t + \Delta t \left( D_u \nabla^2 u^t + \alpha u^t - \beta u^t v^t \right)\] \[v^{t+\Delta t} = v^t + \Delta t \left( D_v \nabla^2 v^t + \delta u^t v^t - \gamma v^t \right)\]

4. Ping-Pong Buffering

Simulations cannot read from and write to the same texture simultaneously. A ping-pong buffer pattern resolves this: Texture A serves as input while Texture B receives the calculated frame. On the next time step, the roles are swapped. In gpu.js, this is handled by setting the kernel output to a texture and feeding that output texture back into the kernel as the primary argument for the subsequent step.

Performance and Stability Considerations

  • Courant-Friedrichs-Lewy (CFL) Condition: For explicit integration schemes, stability requires that the time step satisfies \(\Delta t \le \frac{\Delta x^2}{4 \max(D_u, D_v)}\). Exceeding this threshold causes unbounded numerical oscillations and system collapse.
  • Boundary Conditions: The kernel must explicitly enforce boundaries, typically implementing periodic boundaries (toroidal space) using modulo arithmetic on indices, or reflective (Neumann) boundaries by clamping indices at grid edges.
  • Precision: High-precision ecological patterns require 32-bit floating-point textures (pipeline: true and float textures enabled in WebGL) to avoid truncation errors during low-density diffusion phases.

Spatial Lotka-Volterra dynamics can be modeled effectively in gpu.js, transforming a computationally heavy PDE simulation into an interactive, real-time visual system inside a browser.
