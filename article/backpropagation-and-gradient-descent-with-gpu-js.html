Backpropagation and Gradient Descent with GPU.js

Implementing backpropagation and gradient descent directly with gpu.js allows you to accelerate neural network training routines inside the browser or Node.js without relying on high-level machine learning frameworks. By compiling JavaScript functions into WebGL shader code, gpu.js executes massive parallel matrix operations directly on the graphics card. This guide explains how to structure the forward pass, calculate error gradients via backpropagation, and update network weights using gradient descent kernels in gpu.js.

The Architecture of Training in GPU.js

Neural network training consists of linear algebra routines and element-wise matrix math. Because gpu.js maps calculations over an \(n\)-dimensional grid (where each output element corresponds to a parallel GPU thread), it is well-suited for the primary computations of training:

  1. Forward Pass: Compute linear combinations (\(Z = W \cdot X + B\)) and apply non-linear activations.
  2. Backward Pass (Backpropagation): Compute output errors, derive activation gradients, and propagate errors backward through transposed weight matrices.
  3. Weight Update (Gradient Descent): Adjust weights and biases using calculated gradients and a defined learning rate (\(\theta = \theta - \alpha \cdot \nabla \theta\)).

1. Defining the Forward Pass Kernels

The forward pass requires a matrix multiplication kernel to compute layer outputs and an activation kernel (such as Sigmoid or ReLU).

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Matrix multiplication: C = A * B
const matMul = gpu.createKernel(function(a, b, aCols) {
    let sum = 0;
    for (let i = 0; i < aCols; i++) {
        sum += a[this.thread.y][i] * b[i][this.thread.x];
    }
    return sum;
}).setOutput([/* outputCols */ 1, /* outputRows */ 2]);

// Sigmoid activation
const sigmoid = gpu.createKernel(function(z) {
    return 1 / (1 + Math.exp(-z[this.thread.y][this.thread.x]));
}).setOutput([1, 2]);

2. Implementing Backpropagation Kernels

Backpropagation relies on the chain rule to determine how much each parameter contributed to the total loss. This requires two main operations on the GPU:

Calculating Output Layer Gradients

For Mean Squared Error (MSE) loss paired with a sigmoid activation, the output gradient (\(\delta_o\)) is: \[\delta_o = (Y_{pred} - Y_{true}) \odot \sigma'(Z_o)\] Where \(\sigma'(z) = \sigma(z) \cdot (1 - \sigma(z))\).

const calculateOutputDelta = gpu.createKernel(function(predicted, actual) {
    let y_hat = predicted[this.thread.y][this.thread.x];
    let y = actual[this.thread.y][this.thread.x];
    let sigmoidDeriv = y_hat * (1 - y_hat);
    return (y_hat - y) * sigmoidDeriv;
}).setOutput([1, 2]);

Propagating Error to Hidden Layers

To send the error backwards, multiply the output delta by the transposed weight matrix (\(W^T\)), then multiply element-wise by the hidden layer's activation derivative:

// Hidden delta: delta_h = (W_output^T * delta_o) * sigma'(A_h)
const calculateHiddenDelta = gpu.createKernel(function(weightsNext, deltaNext, activation, nextRows) {
    let errorSum = 0;
    for (let i = 0; i < nextRows; i++) {
        // Access weights transposed: thread.y becomes column
        errorSum += weightsNext[i][this.thread.y] * deltaNext[i][this.thread.x];
    }
    let a = activation[this.thread.y][this.thread.x];
    return errorSum * (a * (1 - a));
}).setOutput([1, 4]); // 4 hidden nodes, 1 sample

3. Implementing the Gradient Descent Kernel

Once the deltas are calculated, the gradients for the weights are obtained by multiplying the delta with the transposed input/activation of that layer (\(\nabla W = \delta \cdot A_{prev}^T\)).

You can perform the gradient step directly in an update kernel:

// Updates weights: W = W - (learningRate * delta * input^T)
const updateWeights = gpu.createKernel(function(weights, delta, prevActivation, learningRate) {
    let currentWeight = weights[this.thread.y][this.thread.x];
    let grad = delta[this.thread.y][0] * prevActivation[this.thread.x][0];
    return currentWeight - (learningRate * grad);
}).setOutput([/* prevLayerSize */ 3, /* currentLayerSize */ 4]);

// Updates biases: B = B - (learningRate * delta)
const updateBiases = gpu.createKernel(function(biases, delta, learningRate) {
    return biases[this.thread.y][this.thread.x] - (learningRate * delta[this.thread.y][this.thread.x]);
}).setOutput([1, 4]);

Performance Considerations

  • Keep Data on the GPU: Transferring floating-point arrays between the CPU and GPU introduces bus latency. Use gpu.createKernel(...).setPipeline(true) to ensure that intermediate outputs remain on the GPU as WebGL textures throughout the forward and backward loops.
  • Batch Processing: Running one sample at a time leads to GPU underutilization. Expand kernel dimensions to support minibatches, setting output dimensions to [batchSize, layerSize].
  • Precision Constraints: WebGL handles 32-bit floating-point precision. Ensure that accumulated values do not underflow or overflow, particularly within exponentiation routines like Math.exp().
