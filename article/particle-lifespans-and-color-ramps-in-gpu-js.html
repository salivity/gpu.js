Particle Lifespans and Color Ramps in GPU.js

Managing a high-performance particle system entirely on the GPU requires treating textures as memory buffers to avoid CPU-GPU transfer bottlenecks. By utilizing GPU.js with pipeline mode enabled, you can store particle attributes—such as position, velocity, remaining life, and maximum life—in floating-point textures. Lifespan degradation, conditional respawning, and color ramp evaluations are executed directly inside WebGL compute shaders via GPU.js kernels, cycling textures frame-by-frame through ping-pong buffering to produce fully GPU-driven particle simulations.

Texture State Architecture

In a GPU-bound particle system, each particle is represented by a specific texel across one or more data textures. To manage lifespan and visuals effectively, state is split into structured 4-channel (RGBA) floating-point textures:

  1. Position and Life Texture:
    • R: Position X
    • G: Position Y
    • B: Position Z
    • A: Current Life (countdown in seconds)
  2. Velocity and Max Life Texture:
    • R: Velocity X
    • G: Velocity Y
    • B: Velocity Z
    • A: Maximum Life (constant duration for normalization)
  3. Color Ramp Texture: A 1D or 2D reference texture containing the RGBA color gradient mapped from birth to death.

GPU.js kernels must be configured with pipeline: true to return native WebGL textures rather than serializing data back to JavaScript typed arrays.

Managing Lifespan and Conditional Respawning

The simulation step updates particle positions and subtracts elapsed time (deltaTime) from the remaining lifespan. When a particle's life drops below zero, the kernel immediately resets its position to the emitter origin, generates a new pseudo-random velocity, and resets its life attribute to its maximum value.

Because GPU.js kernels do not have access to standard Math.random(), pseudo-randomness must be generated deterministically using the particle's thread index and a continuous time seed.

const updateParticles = gpu.createKernel(function(posLife, velMaxLife, timeSeed, dt, emitterPos) {
    const x = this.thread.x;
    const y = this.thread.y;

    const p = posLife[y][x];
    const v = velMaxLife[y][x];

    let posX = p[0];
    let posY = p[1];
    let posZ = p[2];
    let life = p[3] - dt;
    const maxLife = v[3];

    // Check if particle is dead
    if (life <= 0.0) {
        // Respawn at emitter position
        posX = emitterPos[0];
        posY = emitterPos[1];
        posZ = emitterPos[2];

        // Reset to initial lifespan
        life = maxLife;
    } else {
        // Normal integration step
        posX += v[0] * dt;
        posY += v[1] * dt;
        posZ += v[2] * dt;
    }

    return [posX, posY, posZ, life];
})
.setOutput([textureWidth, textureHeight])
.setPipeline(true);

For respawning velocities deterministically, a high-frequency sine hash based on coordinate space produces fast pseudo-random vectors directly in the compute shader:

function hash(seed) {
    return fract(sin(seed) * 43758.5453123);
}

Implementing the Color Ramp

The visual stage calculates a normalized lifespan factor (\(t\)) between 0.0 (death) and 1.0 (birth):

\[t = \text{clamp}\left(\frac{\text{Current Life}}{\text{Maximum Life}}, 0.0, 1.0\right)\]

This normalized scalar is used to sample a precomputed color ramp texture. The ramp is represented as an array or texture where index 0 is the final death color and index N is the initial birth color.

const renderColorKernel = gpu.createKernel(function(posLife, velMaxLife, rampTexture, rampLength) {
    const x = this.thread.x;
    const y = this.thread.y;

    const currentLife = posLife[y][x][3];
    const maxLife = velMaxLife[y][x][3];

    // Normalize life to a 0.0 - 1.0 scale
    let t = currentLife / maxLife;
    if (t < 0.0) t = 0.0;
    if (t > 1.0) t = 1.0;

    // Lookup index on the color ramp
    const rampIndex = Math.floor(t * (rampLength - 1));
    const color = rampTexture[rampIndex];

    return [color[0], color[1], color[2], color[3]];
})
.setOutput([textureWidth, textureHeight])
.setPipeline(true);

If dynamic sampling from a separate texture creates overhead, mathematical interpolation between control points (such as linear blending from blue to yellow to red) can be hardcoded directly into the kernel function to calculate RGB values procedurally.

The Ping-Pong Loop

WebGL textures cannot be read from and written to simultaneously. Maintaining states entirely within GPU textures requires a ping-pong buffer technique:

  1. Provide Texture A (current state) as input to the update kernel.
  2. Direct output to Texture B (new state).
  3. Pass Texture B into the color ramp kernel to generate the display state.
  4. Swap references: Texture B becomes the input for the subsequent frame, and Texture A becomes the target.

By keeping textures permanently inside the pipeline loop, lifespan counters decrement, respawns trigger conditionally, and colors map dynamically without moving a single byte of simulation data across the PCI bus.
