Parallelizing High-Dimensional KNN in GPU.js

Parallelizing K-Nearest Neighbors (KNN) classification in high-dimensional feature spaces requires offloading compute-intensive distance metrics from the CPU to the GPU. This article demonstrates how to leverage GPU.js to execute multi-dimensional vector comparisons concurrently, structure input data for fast GPU memory access, and efficiently extract the top-k labels to achieve high-throughput classification directly in JavaScript.

Understanding the Computational Bottleneck

The standard KNN algorithm computes the distance between an unclassified query point \(Q\) and every reference point \(R_i\) in a dataset of size \(N\), where each point contains \(D\) dimensions. In high-dimensional spaces (e.g., \(D > 128\)), the distance computation cost scales as \(O(N \cdot D)\) per query. On a single CPU thread, computing Euclidean distances across thousands of high-dimensional vectors causes latency spikes.

GPU.js accelerates this process by mapping each reference point calculation to an independent GPU thread, computing the element-wise differences across all \(D\) dimensions concurrently.

1. Formatting Data for GPU Memory

JavaScript arrays of objects are inefficient for GPU processing. To minimize data transfer bottlenecks, convert your training points and query vectors into flattened or two-dimensional Float32Array buffers.

// Example: N reference samples, each with D dimensions

2. Implementing the Parallel Distance Kernel

Create a GPU.js compute kernel that calculates the squared Euclidean distance between the target query vector and all reference points simultaneously.

import { GPU } from 'gpu.js';

const gpu = new GPU();

const computeDistances = gpu.createKernel(function(references, query, dimensions) {
    let sum = 0;
    for (let d = 0; d < dimensions; d++) {
        let diff = references[this.thread.x][d] - query[d];
        sum += diff * diff;
    }
    return Math.sqrt(sum);
})
.setOutput([N]); // One thread per reference point

In this kernel:

  • this.thread.x corresponds to the index of a reference point in the dataset.
  • The inner loop iterates through the high-dimensional feature space (\(D\)), running sequentially within the thread while thousands of threads run in parallel.
  • Returning squared Euclidean distance (omitting Math.sqrt) is mathematically equivalent for neighbor ranking and saves additional clock cycles.

3. Multi-Query Batching

To classify multiple query points simultaneously, extend the kernel to a 2D output grid where the X-axis represents reference samples and the Y-axis represents query samples.

const batchComputeDistances = gpu.createKernel(function(references, queries, dimensions) {
    let sum = 0;
    const refIdx = this.thread.x;
    const queryIdx = this.thread.y;

    for (let d = 0; d < dimensions; d++) {
        let diff = references[refIdx][d] - queries[queryIdx][d];
        sum += diff * diff;
    }
    return sum;
})
.setOutput([N, M]); // N reference points by M query points

4. Extracting the Nearest Neighbors

While GPUs excel at calculating millions of distances, finding the top \(K\) smallest values is often faster on the CPU when \(K \ll N\).

  1. Read Distances: Execute the kernel and retrieve the output distance array.
  2. Index Mapping: Pair each computed distance with its corresponding class label or index.
  3. Partial Sort: Instead of performing a full \(O(N \log N)\) sort, use a min-heap or a quickselect algorithm to identify the smallest \(K\) elements in \(O(N + K \log K)\) time.
function getKNearest(distances, labels, k) {
    const indexed = Array.from(distances).map((dist, idx) => ({
        dist,
        label: labels[idx]
    }));

    indexed.sort((a, b) => a.dist - b.dist);
    return indexed.slice(0, k);
}

5. Optimizations for High-Dimensional Spaces

  • Texture Pipelining: If using computed distances in subsequent GPU operations, set { pipeline: true } in the kernel options to keep data inside GPU VRAM, bypassing CPU-GPU transfer overhead.
  • Dimensionality Truncation: For extremely high dimensions (\(D > 1000\)), apply dimensionality reduction such as Principal Component Analysis (PCA) or random projections before feeding arrays into GPU.js to avoid thread timeout limits imposed by WebGL contexts.
  • Memory Coalescing: Pack multi-dimensional vectors into 2D textures to ensure that threads access continuous memory blocks, which maximizes memory bandwidth utilization during feature iteration.
