Dense Lucas-Kanade Optical Flow in GPU.js

This article explains how to implement the Lucas-Kanade optical flow algorithm for dense motion estimation directly in the browser using gpu.js. Dense motion estimation computes displacement vectors for every pixel between two consecutive image frames. By mapping the mathematical steps of spatial-temporal differentiation and local linear system solving to WebGL fragment shaders via gpu.js, you can achieve real-time dense optical flow estimation on consumer-grade hardware.

Mathematical Formulation

The Lucas-Kanade method relies on the brightness constancy assumption:

\[I(x, y, t) = I(x + u, y + v, t + 1)\]

Applying a first-order Taylor expansion yields the optical flow constraint equation:

\[I_x u + I_y v + I_t = 0\]

where \(I_x\) and \(I_y\) are the spatial image gradients, \(I_t\) is the temporal gradient, and \((u, v)\) represents the horizontal and vertical velocity vector.

For dense optical flow, the algorithm assumes that motion is constant within a small window \(\Omega\) of size \(W \times W\) centered at every pixel \((x, y)\). This creates an overdetermined linear system \(A \mathbf{v} = \mathbf{b}\), solved using the standard least-squares solution:

\[\begin{bmatrix} u \\ v \end{bmatrix} = (A^T A)^{-1} A^T \mathbf{b}\]

Explicitly:

\[\begin{bmatrix} \sum I_x^2 & \sum I_x I_y \\ \sum I_x I_y & \sum I_y^2 \end{bmatrix} \begin{bmatrix} u \\ v \end{bmatrix} = - \begin{bmatrix} \sum I_x I_t \\ \sum I_y I_t \end{bmatrix}\]

Using Cramer's rule, the motion components are calculated as:

\[\det(A^T A) = \left(\sum I_x^2\right)\left(\sum I_y^2\right) - \left(\sum I_x I_y\right)^2\]

\[u = \frac{-\left(\sum I_y^2\right)\left(\sum I_x I_t\right) + \left(\sum I_x I_y\right)\left(\sum I_y I_t\right)}{\det(A^T A)}\]

\[v = \frac{-\left(\sum I_x^2\right)\left(\sum I_y I_t\right) + \left(\sum I_x I_y\right)\left(\sum I_x I_t\right)}{\det(A^T A)}\]

If \(\det(A^T A)\) is below a regularizing threshold \(\epsilon\), the aperture problem occurs or the region lacks texture, meaning motion cannot be reliably determined and \((u, v)\) is set to \((0, 0)\).

GPU.js Implementation Pipeline

Executing this calculation across every pixel in JavaScript using CPU threads causes significant frame drops. With gpu.js, each output pixel's motion vector is evaluated in parallel inside a GPU kernel.

Step 1: Kernel Initialization

Install and import the library, then instantiate the GPU context:

const { GPU } = require('gpu.js'); // Or via <script src="gpu-browser.min.js">
const gpu = new GPU();

Step 2: Grayscale and Gradient Extraction

While you can compute optical flow directly on luminance buffers, combining gradient calculation and the window integration inside a single kernel minimizes texture transfer overhead.

The inputs are two 2D arrays (or HTML Video/Canvas elements) containing pixel intensities for frame \(t\) (frame1) and frame \(t+1\) (frame2) normalized between 0.0 and 1.0.

Step 3: Complete Optical Flow Kernel

The following kernel integrates gradient calculation, neighborhood summation over a \(5 \times 5\) window, and matrix inversion per pixel:

const width = 640;
const height = 480;
const windowRadius = 2; // Results in a 5x5 window (2*radius + 1)
const threshold = 0.0001; // Eigenvalue/determinant threshold to handle aperture problem

const denseLucasKanadeKernel = gpu.createKernel(function(frame1, frame2, width, height, radius, eps) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Reject boundary pixels where the window exceeds frame limits
    if (x < radius || x >= width - radius || y < radius || y >= height - radius) {
        return [0, 0];
    }

    let Sxx = 0.0;
    let Syy = 0.0;
    let Sxy = 0.0;
    let Sxt = 0.0;
    let Syt = 0.0;

    // Accumulate structural tensors over the local window
    for (let dy = -radius; dy <= radius; dy++) {
        for (let dx = -radius; dx <= radius; dx++) {
            const px = x + dx;
            const py = y + dy;

            // Central differences for spatial gradients on frame1
            const Ix = (frame1[py][px + 1] - frame1[py][px - 1]) * 0.5;
            const Iy = (frame1[py + 1][px] - frame1[py - 1][px]) * 0.5;

            // Temporal gradient between frame1 and frame2
            const It = frame2[py][px] - frame1[py][px];

            Sxx += Ix * Ix;
            Syy += Iy * Iy;
            Sxy += Ix * Iy;
            Sxt += Ix * It;
            Syt += Iy * It;
        }
    }

    // Calculate determinant of structure tensor (A^T * A)
    const det = (Sxx * Syy) - (Sxy * Sxy);

    // Solve for u (horizontal) and v (vertical) using Cramer's rule
    if (det > eps) {
        const u = (-Syy * Sxt + Sxy * Syt) / det;
        const v = (-Sxx * Syt + Sxy * Sxt) / det;
        return [u, v];
    } else {
        return [0, 0];
    }
})
.setOutput([width, height])
.setPrecision('single')
.setPipeline(true); // Retains output as a texture for chaining

Running Motion Estimation on Video Frames

To process incoming frames in a loop, extract the grayscale channel into 2D arrays, dispatch them to the kernel, and obtain the resulting velocity field:

let previousFrame = getGrayscaleArray(videoElement, width, height);

function processFrame() {
    const currentFrame = getGrayscaleArray(videoElement, width, height);

    // Output is a 2D array of [u, v] motion vectors per pixel
    const flowTexture = denseLucasKanadeKernel(
        previousFrame,
        currentFrame,
        width,
        height,
        windowRadius,
        threshold
    );

    // If needed on CPU: const motionField = flowTexture.toArray();
    previousFrame = currentFrame;
    requestAnimationFrame(processFrame);
}

function getGrayscaleArray(video, w, h) {
    const ctx = offscreenCanvas.getContext('2d');
    ctx.drawImage(video, 0, 0, w, h);
    const imgData = ctx.getImageData(0, 0, w, h).data;
    
    // Construct 2D luminance array (h x w)
    const gray = [];
    for (let y = 0; y < h; y++) {
        const row = [];
        for (let x = 0; x < w; x++) {
            const idx = (y * w + x) * 4;
            // Standard luminance weights
            row.push((0.299 * imgData[idx] + 0.587 * imgData[idx + 1] + 0.114 * imgData[idx + 2]) / 255.0);
        }
        gray.push(row);
    }
    return gray;
}

Tuning and Practical Considerations

  1. Window Size: A larger radius (such as \(W = 7\) or \(9\)) handles larger displacements and provides smoother results, but increases texture lookups per thread (\(W^2\)) and blurs motion boundaries.
  2. Pre-smoothing: Lucas-Kanade relies on continuous gradients. Applying a Gaussian blur kernel prior to the optical flow kernel eliminates high-frequency noise that causes incorrect gradient spikes.
  3. Multi-Scale (Pyramid) Approach: Standard Lucas-Kanade fails when displacement exceeds 1 to 2 pixels. To capture large motion paths, downsample frames into a Gaussian pyramid, compute flow at coarse scales, and propagate the flow vectors as an offset to finer layers.
