Parallel Pitch Detection Using gpu.js Autocorrelation

This article demonstrates how to leverage WebGL-accelerated parallel computing in JavaScript using gpu.js to perform real-time autocorrelation for pitch detection. By offloading the computationally intensive calculation of signal correlations across multiple time lags to the GPU, applications can detect the fundamental frequency (\(f_0\)) of audio signals with high throughput and low CPU overhead. Below, you will find the mathematical background, the gpu.js kernel design, and the full implementation pipeline.

Autocorrelation and Pitch Detection

Autocorrelation measures the similarity between a signal and a time-shifted version of itself. For a discrete audio signal \(x[n]\) of length \(N\), the autocorrelation function \(R(\tau)\) at lag \(\tau\) is defined as:

\[R(\tau) = \sum_{n=0}^{N - 1 - \tau} x[n] \cdot x[n + \tau]\]

When an audio signal contains a periodic waveform, \(R(\tau)\) reaches high values at lags corresponding to multiples of the fundamental period \(T\). The fundamental frequency \(f_0\) is calculated using the sampling rate \(f_s\) and the optimal lag \(\tau_{\text{peak}}\):

\[f_0 = \frac{f_s}{\tau_{\text{peak}}}\]

Because calculating \(R(\tau)\) for every lag independently requires \(O(N \cdot \text{maxLag})\) operations, running it iteratively on a single CPU thread can introduce latency. Because each lag \(\tau\) can be calculated independently, it is an ideal candidate for parallel execution on the GPU.

Setting Up the gpu.js Kernel

gpu.js compiles a subset of JavaScript into WebGL shaders, allowing you to run calculations concurrently across GPU threads. In our implementation, each thread computes the autocorrelation value for a single lag \(\tau\).

Installation

Install gpu.js via npm or include it via a CDN:

npm install gpu.js

Kernel Definition

import { GPU } from 'gpu.js';

const gpu = new GPU();

// Create the autocorrelation kernel
const createAutocorrelationKernel = (bufferSize, maxLag) => {
  return gpu.createKernel(function (signal, length) {
    const tau = this.thread.x;
    let sum = 0;

    // Calculate sum of products for lag tau
    for (let i = 0; i < length - tau; i++) {
      sum += signal[i] * signal[i + tau];
    }

    return sum;
  })
  .setOutput([maxLag])
  .setDynamicOutput(false);
};

Peak Detection and Frequency Extraction

The output array from the kernel contains \(R(\tau)\) values ranging from \(\tau = 0\) to \(\tau = \text{maxLag} - 1\).

  1. Ignore \(\tau = 0\): The maximum autocorrelation always occurs at zero lag (\(R(0)\)), representing total signal energy.
  2. Find the Zero Crossing: Walk forward from \(\tau = 0\) until the correlation drops below a certain threshold or crosses zero to move past the initial main lobe.
  3. Locate the First Major Peak: Find the local maximum after the zero crossing.
  4. Parabolic Interpolation (Optional): Refine \(\tau_{\text{peak}}\) to fractional precision to improve frequency resolution.

Complete Implementation

Below is a complete module that initializes the GPU context, captures an audio frame, calculates autocorrelation in parallel, and returns the detected pitch.

import { GPU } from 'gpu.js';

export class GPUPitchDetector {
  constructor(sampleRate = 44100, bufferSize = 2048, minFreq = 50, maxFreq = 1000) {
    this.sampleRate = sampleRate;
    this.bufferSize = bufferSize;

    // Calculate lag boundaries based on target frequency range
    this.minLag = Math.floor(sampleRate / maxFreq);
    this.maxLag = Math.ceil(sampleRate / minFreq);

    this.gpu = new GPU();
    this.kernel = this.gpu.createKernel(function (signal, length) {
      const tau = this.thread.x;
      let sum = 0.0;

      for (let i = 0; i < length - tau; i++) {
        sum += signal[i] * signal[i + tau];
      }

      return sum;
    })
    .setOutput([this.maxLag]);
  }

  detectPitch(audioFrame) {
    if (audioFrame.length !== this.bufferSize) {
      throw new Error(`Audio frame length must be ${this.bufferSize}`);
    }

    // Run parallel autocorrelation on GPU
    const correlation = this.kernel(audioFrame, this.bufferSize);

    // Peak picking on the correlation result
    let peakLag = -1;
    let maxCorrelation = -Infinity;

    // Search strictly within lag bounds corresponding to target frequencies
    for (let tau = this.minLag; tau < this.maxLag - 1; tau++) {
      const current = correlation[tau];

      // Detect local peak
      if (current > correlation[tau - 1] && current > correlation[tau + 1]) {
        if (current > maxCorrelation) {
          maxCorrelation = current;
          peakLag = tau;
        }
      }
    }

    if (peakLag === -1) {
      return null; // No defined periodic pitch found
    }

    // Parabolic interpolation for sub-sample accuracy
    const alpha = correlation[peakLag - 1];
    const beta = correlation[peakLag];
    const gamma = correlation[peakLag + 1];
    const delta = (alpha - gamma) / (2 * (alpha - 2 * beta + gamma));

    const refinedLag = peakLag + delta;

    return this.sampleRate / refinedLag;
  }

  destroy() {
    this.kernel.destroy();
    this.gpu.destroy();
  }
}

Performance Considerations

  • Memory Transfers: Transferring data from the CPU to GPU via textures introduces a slight overhead. To maximize efficiency, keep the buffer size power-of-two (e.g., 1024, 2048) and avoid running the kernel on unnecessarily small chunks.
  • Normalization: If working with audio containing varying gain, divide the correlation by \(R(0)\) to normalize values between -1.0 and 1.0, simplifying peak thresholding.
  • Dynamic Frequency Limits: Restricting maxLag to the lowest frequency you realistically need to detect reduces the thread count and iteration length of the GPU loops, improving frame rates.
