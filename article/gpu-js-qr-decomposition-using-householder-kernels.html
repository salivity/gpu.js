GPU.js QR Decomposition Using Householder Kernels

This article explains how to implement QR decomposition using Householder reflections within gpu.js by breaking the sequential mathematical process into modular, chained GPU kernels. Because Householder reflections require global reductions and step-dependent transformations that cannot run inside a single GPU thread dispatch, chaining kernels via texture pipelining allows intermediate matrix states to remain entirely in GPU memory. Below is a structured guide to organizing the algorithm, defining the kernel stages, and orchestrating the execution loop.

Algorithmic Breakdown and GPU Parallelism Challenges

QR decomposition factors an \(m \times n\) matrix \(A\) into an orthogonal matrix \(Q\) and an upper triangular matrix \(R\). Householder reflections achieve this by zeroing out the subdiagonal entries of each column \(k\) iteratively from \(k = 0\) to \(\min(m-1, n)\):

  1. Extract vector: Isolate the \(k\)-th column below the diagonal: \(x = A[k:m, k]\).
  2. Compute reflection parameters: Find the Euclidean norm \(\|x\|_2\), compute the scalar \(\alpha = -\text{sgn}(x_0)\|x\|_2\), construct Householder vector \(v = x - \alpha e_1\), and normalize or compute \(\tau = \frac{2}{v^T v}\).
  3. Update \(R\) (submatrix of \(A\)): Transform trailing columns \(j \ge k\) via \(A_{k:m, j} \leftarrow A_{k:m, j} - \tau v (v^T A_{k:m, j})\).
  4. Accumulate \(Q\): Update \(Q \leftarrow Q (I - \tau v v^T)\).

Because each iteration depends entirely on the completion of the previous reflection, the outer loop over columns must run sequentially on the CPU. Within each step \(k\), calculating the norm requires a parallel reduction, and updating the matrix requires parallel element-wise arithmetic. These distinct operations cannot synchronize globally within a single kernel dispatch in WebGL, necessitating multiple chained kernels.

Designing the Chained Kernel Pipeline

To avoid costly readbacks from GPU memory to CPU memory (Texture.toArray()), you must enable pipeline: true on all kernels in gpu.js. This ensures output textures are passed directly as input textures to the next kernel.

The computation for each column \(k\) is structured into three chained kernels:

1. Column Norm and Vector Kernel

This kernel takes the current matrix state \(A^{(k)}\) and computes the Householder vector \(v\) for column \(k\). Because computing \(\|x\|_2\) requires summing squares along column \(k\), it can be split into a two-pass reduction if \(m\) is large, or computed across the 1D slice in a single pass if \(m\) is moderately sized.

const computeHouseholderVector = gpu.createKernel(function(A, k, m) {
    let sumSq = 0;
    for (let i = k; i < m; i++) {
        sumSq += A[i][k] * A[i][k];
    }
    let norm = Math.sqrt(sumSq);
    let x0 = A[k][k];
    let alpha = (x0 >= 0 ? -1 : 1) * norm;
    
    // Thread index represents row i
    let i = this.thread.x;
    if (i < k) {
        return 0;
    } else if (i === k) {
        return x0 - alpha;
    } else if (i < m) {
        return A[i][k];
    }
    return 0;
}, {
    pipeline: true,
    immutable: true
});

2. Vector Norm / Scaling Factor Kernel

Computing \(\tau = \frac{2}{v^T v}\) can be outputted as a \(1 \times 1\) texture or pre-scaled within the vector representation:

const computeTau = gpu.createKernel(function(v, k, m) {
    let dot = 0;
    for (let i = k; i < m; i++) {
        dot += v[i] * v[i];
    }
    if (dot === 0) return 0;
    return 2.0 / dot;
}, {
    pipeline: true,
    immutable: true
});

3. Matrix Reflection Kernel (Update \(R\))

This kernel applies the Householder transformation \(A \leftarrow (I - \tau v v^T)A\) to the active matrix block in parallel. Every output cell \((i, j)\) is computed simultaneously:

const applyHouseholderToR = gpu.createKernel(function(A, v, tau, k, m, n) {
    let row = this.thread.y;
    let col = this.thread.x;

    if (row < k || col < k) {
        return A[row][col];
    }

    // Compute dot product: v^T * A[:, col]
    let vDotA = 0;
    for (let i = k; i < m; i++) {
        vDotA += v[i] * A[i][col];
    }

    // Apply: A[row, col] - tau * v[row] * (v^T * A[:, col])
    return A[row][col] - tau[0][0] * v[row] * vDotA;
}, {
    pipeline: true,
    immutable: true
});

4. Accumulate Matrix \(Q\) Kernel

If the orthogonal matrix \(Q\) is explicitly required, it is initialized to the identity matrix \(I_m\) and updated at each step: \(Q \leftarrow Q (I - \tau v v^T)\).

const applyHouseholderToQ = gpu.createKernel(function(Q, v, tau, k, m) {
    let row = this.thread.y;
    let col = this.thread.x;

    let qDotV = 0;
    for (let j = k; j < m; j++) {
        qDotV += Q[row][j] * v[j];
    }

    return Q[row][col] - tau[0][0] * qDotV * v[col];
}, {
    pipeline: true,
    immutable: true
});

The Iterative Orchestration Loop

With the kernels compiled and texture output enabled, the CPU loop controls the dispatch sequence while the actual matrix data never leaves VRAM during decomposition:

function qrDecomposition(matrixA, m, n) {
    computeHouseholderVector.setOutput([m]);
    computeTau.setOutput([1, 1]);
    applyHouseholderToR.setOutput([n, m]);
    applyHouseholderToQ.setOutput([m, m]);

    let R = matrixA;
    let Q = initializeIdentityMatrix(m); // Uploaded as GPU texture

    const steps = Math.min(m - 1, n);

    for (let k = 0; k < steps; k++) {
        // Step 1: Calculate Householder vector
        const v = computeHouseholderVector(R, k, m);

        // Step 2: Calculate scalar tau
        const tau = computeTau(v, k, m);

        // Step 3: Update R and Q textures
        R = applyHouseholderToR(R, v, tau, k, m, n);
        Q = applyHouseholderToQ(Q, v, tau, k, m);
    }

    // Final readback to JavaScript arrays
    return {
        Q: Q.toArray(),
        R: R.toArray()
    };
}

Critical Considerations for gpu.js

  1. Texture Ping-Ponging: WebGL does not support reading and writing to the same texture simultaneously. Setting immutable: true ensures that gpu.js allocates alternating framebuffers, avoiding race conditions and pipeline invalidations.
  2. Loop Bounds Inside Kernels: Dynamic loops in WebGL can face compiler limitations. Keep upper bounds fixed to kernel dimensions and use variables to selectively skip computation indices inside loops.
  3. Floating Point Precision: By default, WebGL targets precision mediump or highp single-precision (32-bit float). Small errors accumulate faster during Householder transformations than in standard CPU 64-bit float math, so normalize sub-vectors carefully to prevent catastrophic cancellation.
