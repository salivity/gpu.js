Triplet Margin Loss in GPU.js for Metric Learning

This guide explains how to accelerate Triplet Margin Loss calculations for metric learning algorithms directly in the browser or Node.js using gpu.js. You will learn how the mathematical loss function translates into parallel shader code, how to configure the GPU kernel to process vector embeddings, and how to execute batch distance computations efficiently on hardware threads.

Understanding Triplet Margin Loss

Metric learning aims to map inputs into an embedding space where similar items are close together and dissimilar items are far apart. Triplet Margin Loss achieves this by comparing three samples simultaneously: an Anchor (\(A\)), a Positive (\(P\)) belonging to the same class as the anchor, and a Negative (\(N\)) belonging to a different class.

The loss function is defined as:

\[\mathcal{L}(A, P, N) = \max(0, d(A, P) - d(A, N) + \alpha)\]

Where:

  • \(d(x, y)\) represents the distance metric (commonly squared Euclidean distance: \(\sum (x_i - y_i)^2\)).
  • \(\alpha\) is the margin, a hyperparameter defining how much further away the negative should be compared to the positive.

Setting Up GPU.js

gpu.js compiles JavaScript functions into WebGL or OpenCL shaders, allowing massive parallelization of linear algebra operations across GPU cores without writing raw GLSL.

First, install the package:

npm install gpu.js

Implementing the Kernel

To implement the loss in gpu.js, design a 1D kernel where each thread calculates the loss for one triplet in a batch. Each thread iterates through the vector dimensions, calculates the squared Euclidean distance between \((A, P)\) and \((A, N)\), adds the margin, and applies the hinge function (\(\max(0, x)\)).

const { GPU } = require('gpu.js');
const gpu = new GPU();

/**
 * Creates a GPU kernel for computing Triplet Margin Loss across a batch.
 * @param {number} batchSize - Total triplets in the batch.
 * @param {number} embeddingDim - Dimension size of each embedding vector.
 */
function createTripletLossKernel(batchSize, embeddingDim) {
  return gpu.createKernel(function(anchors, positives, negatives, margin) {
    let distAP = 0;
    let distAN = 0;

    // Calculate squared Euclidean distance for this.thread.x
    for (let i = 0; i < this.constants.embeddingDim; i++) {
      const diffAP = anchors[this.thread.x][i] - positives[this.thread.x][i];
      const diffAN = anchors[this.thread.x][i] - negatives[this.thread.x][i];
      
      distAP += diffAP * diffAP;
      distAN += diffAN * diffAN;
    }

    // Apply the margin and hinge function
    const loss = distAP - distAN + margin;
    return loss > 0 ? loss : 0;
  })
  .setConstants({ embeddingDim: embeddingDim })
  .setOutput([batchSize]);
}

Running the Computation

Pass 2D arrays containing normalized embedding vectors of shape [batchSize, embeddingDim] to the generated kernel function:

const batchSize = 4;
const embeddingDim = 3;
const margin = 1.0;

// Example batch data: [batchSize][embeddingDim]
const anchors = [
  [0.1, 0.2, 0.3],
  [0.5, 0.1, 0.9],
  [0.2, 0.8, 0.4],
  [0.9, 0.3, 0.1]
];

const positives = [
  [0.12, 0.19, 0.31], // Close to anchor
  [0.52, 0.08, 0.88],
  [0.18, 0.82, 0.41],
  [0.88, 0.31, 0.12]
];

const negatives = [
  [0.8, 0.9, 0.1],    // Far from anchor
  [0.1, 0.7, 0.2],
  [0.9, 0.1, 0.3],
  [0.2, 0.7, 0.8]
];

const tripletKernel = createTripletLossKernel(batchSize, embeddingDim);
const losses = tripletKernel(anchors, positives, negatives, margin);

// Calculate the mean loss of the batch on CPU
let totalLoss = 0;
for (let i = 0; i < losses.length; i++) {
  totalLoss += losses[i];
}
const meanLoss = totalLoss / batchSize;

console.log('Individual Losses:', Array.from(losses));
console.log('Batch Mean Loss:', meanLoss);

Performance Considerations

  1. Memory Transfers: Minimize data transfers between the CPU and GPU. If your model generates embeddings on the GPU, keep them stored as textures by using .setPipeline(true) and passing them directly into the loss kernel.
  2. Batch Sizing: GPU parallelism benefits from large batch sizes (e.g., 256, 512, or higher). Small batches may exhibit overhead due to GPU invocation latency.
  3. Distance Metrics: For standard Euclidean distance instead of squared Euclidean distance, wrap the accumulated differences with Math.sqrt(distAP) and Math.sqrt(distAN), ensuring an epsilon value (e.g., 1e-8) is added to avoid zero-division during backpropagation pipelines.
