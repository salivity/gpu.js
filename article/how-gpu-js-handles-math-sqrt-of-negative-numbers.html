How gpu.js Handles Math.sqrt of Negative Numbers

When computing the square root of a negative number in gpu.js, the framework does not implement custom boundary checks; instead, it transpiles JavaScript's Math.sqrt() directly into the native WebGL shading language (GLSL) sqrt() function. Consequently, passing a negative radicand relies directly on the underlying GPU architecture and driver behavior, which follows the GLSL specification for undefined results and typically evaluates to NaN or zero rather than throwing a runtime error.

GLSL Transpilation and Undefined Behavior

gpu.js accelerates JavaScript code by compiling kernel functions into WebGL shaders. In this pipeline, Math.sqrt(x) is converted to the GLSL equivalent sqrt(x). According to the OpenGL ES Shading Language specification, the result of sqrt(x) is undefined if x < 0.0.

Because it is classified as undefined behavior at the hardware and driver level:

  • Standard Modern GPUs: Most desktop and modern mobile GPUs adhere closely to IEEE-754 floating-point standards, returning NaN (Not-a-Number).
  • Older or Specialized GPUs: Some hardware architectures handle invalid roots by clamping the value to 0.0 or returning a fallback float to prevent calculation crashes inside the graphics pipeline.

GPU Mode vs. CPU Fallback

The exact output can differ depending on whether the kernel executes on the GPU or falls back to the CPU:

  1. WebGL/GPU Mode: The value returned from the kernel texture readback is governed by the GPU's handling of the GLSL sqrt() call. If the GPU produces NaN, it will be passed back into the final JavaScript typed array as NaN. If the hardware evaluates it to 0.0, the output will reflect 0.0.
  2. CPU Fallback Mode: If WebGL is unavailable or if CPU mode is forced, gpu.js runs standard JavaScript in a loop. In this execution path, native JavaScript semantics apply strictly, and Math.sqrt() with a negative radicand always returns NaN.

Preventing Undefined Behavior in Kernels

To avoid inconsistent outputs across different client hardware, negative values must be guarded against inside the kernel function before computing the root.

You can clamp the input using Math.max():

const kernel = gpu.createKernel(function(values) {
  const val = values[this.thread.x];
  // Clamp negative numbers to zero
  return Math.sqrt(Math.max(0, val));
}).setOutput([100]);

Alternatively, use a conditional operator to return a specific sentinel value:

const kernel = gpu.createKernel(function(values) {
  const val = values[this.thread.x];
  return val < 0 ? 0 : Math.sqrt(val);
}).setOutput([100]);

Adding explicit validation inside the kernel prevents hardware-specific anomalies and ensures cross-platform consistency across all devices executing the code.
