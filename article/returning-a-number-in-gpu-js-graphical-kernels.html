Returning a Number in GPU.js Graphical Kernels

In GPU.js, configuring a kernel with the graphical mode enabled allows developers to render visual output directly to an HTML5 canvas via WebGL. This article explains the technical consequences of returning a standard numerical value rather than invoking the built-in this.color() method inside a graphical kernel, detailing WebGL shader behavior, compilation failures, and canvas rendering issues.

The Role of this.color in Graphical Kernels

When you initialize a GPU.js kernel with { graphical: true }, the library converts your JavaScript function into a WebGL fragment shader. In WebGL, every fragment (or pixel) requires a four-component vector representing red, green, blue, and alpha channels (vec4(r, g, b, a)).

The this.color(r, g, b, a) function is an internal API binding provided by GPU.js. It directly translates your JavaScript arguments into an assignment to WebGL's native gl_FragColor. Each color channel expects a normalized floating-point value between 0 and 1.

What Happens When Returning a Number

If you replace this.color() with a numerical return statement (such as return 1; or return 0.5;), the following issues occur:

1. WebGL Type Mismatch and Transpilation Errors

GPU.js relies on an Abstract Syntax Tree (AST) parser to transpile JavaScript into GLSL (OpenGL Shading Language). In graphical mode, the compiler expects the kernel execution path to terminate with pixel operations. If the parser attempts to map a scalar float return type directly to a fragment shader that expects a void return type or a vec4 color assignment, the internal shader compilation will fail. This results in a runtime JavaScript error indicating that the shader could not be compiled or linked.

2. Blank or Transparent Canvas Output

If the compiler does not throw an explicit parsing error, it wraps the return value into dead code because it does not know which color channel the number belongs to. Because gl_FragColor is never assigned a value, the underlying WebGL context defaults to an unwritten state. The resulting canvas will appear entirely black, fully transparent (0, 0, 0, 0), or retain whatever clear color the WebGL context was initialized with.

3. Loss of Canvas Output Mapping

A standard kernel (non-graphical) uses the return statement to output multi-dimensional arrays of numbers back to the CPU. In graphical mode, GPU.js overrides the return pathway to optimize memory transfer straight to the screen buffer. Returning a raw number breaks the contract of the graphical pipeline, failing both to populate the canvas and to return an accessible numerical array.

Correct Usage

To display a grayscale or numerical representation on the canvas, map the numerical value across the RGB channels using this.color():

const kernel = gpu.createKernel(function() {
    const value = 0.75; // Calculated numerical value
    this.color(value, value, value, 1);
}, {
    output: [512, 512],
    graphical: true
});

If the objective is to perform parallel mathematical calculations and retrieve the raw numbers, disable graphical mode (graphical: false or omit the flag) and use return value; to receive standard typed arrays.
