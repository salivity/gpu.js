GPU.js Polynomial Root Finding via Companion Matrix

This article explains how to parallelize polynomial root finding in JavaScript by formulating the problem as an eigenvalue computation of a companion matrix and offloading the workload to the GPU using GPU.js. It details the construction of the Frobenius companion matrix, outlines the iterative QR algorithm used for eigenvalue extraction, and demonstrates how to implement compute kernels for both single high-degree polynomials and large-scale batch polynomial evaluation.

The Companion Matrix Formulation

Given a monic polynomial of degree \(n\):

\[P(x) = x^n + a_{n-1}x^{n-1} + \dots + a_1x + a_0\]

Its roots are identical to the eigenvalues of its companion matrix \(C \in \mathbb{R}^{n \times n}\). A standard Frobenius companion matrix has the form:

\[C = \begin{bmatrix} 0 & 0 & \dots & 0 & -a_0 \\ 1 & 0 & \dots & 0 & -a_{n-1} \\ 0 & 1 & \dots & 0 & -a_{n-2} \\ \vdots & \vdots & \ddots & \vdots & \vdots \\ 0 & 0 & \dots & 1 & -a_{n-1} \end{bmatrix}\]

Computing the eigenvalues of \(C\) reveals all real and complex roots of \(P(x)\) without requiring initial root estimates.

Parallelization Strategies in GPU.js

Eigenvalue computation typically relies on the iterative QR algorithm (\(A_{k+1} = R_k Q_k\)). Because the QR algorithm is inherently iterative, parallelization must be targeted appropriately depending on the workload:

  1. Batch Parallelism (Many Polynomials): Ideal for low-to-medium degree polynomials evaluated across thousands of inputs. Each GPU thread runs the QR algorithm on a distinct companion matrix independently.
  2. Matrix-Level Parallelism (Single High-Degree Polynomial): Ideal for very large matrices (\(n > 100\)). Each step of the QR decomposition—specifically matrix-matrix multiplications and orthogonal transformations—is mapped across a 2D grid of GPU threads.

Implementing Batch Companion Matrix Solvers

When evaluating thousands of polynomials simultaneously, map each polynomial to a thread index. GPU.js executes each thread over WebGL compute shaders.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel to construct companion matrices in parallel for M polynomials of degree N
const buildCompanionMatrices = gpu.createKernel(function(coefficients, n) {
    const polyIdx = this.thread.z;
    const row = this.thread.y;
    const col = this.thread.x;
    
    // Last column contains negated coefficients
    if (col === n - 1) {
        return -coefficients[polyIdx][row];
    }
    // Subdiagonal contains ones
    if (row === col + 1) {
        return 1.0;
    }
    // All other entries are zero
    return 0.0;
}).setOutput([N, N, M]);

Parallelizing the QR Step for Large Companion Matrices

For a single large companion matrix, parallelize the underlying linear algebra operations. The standard shifted QR step involves:

  1. Orthogonalization (\(Q\) and \(R\) extraction): Parallelized using block Householder reflectors or parallel Givens rotations.
  2. Similarity Update (\(A_{k+1} = R Q\)): Parallel matrix multiplication, which maps directly to 2D GPU.js kernels.

Parallel Matrix Multiplication Kernel

The similarity transformation step requires repeated matrix multiplications:

const multiplyMatrices = gpu.createKernel(function(A, B, n) {
    let sum = 0;
    for (let i = 0; i < n; i++) {
        sum += A[this.thread.y][i] * B[i][this.thread.x];
    }
    return sum;
})
.setOutput([N, N])
.setPipeline(true); // Retain output in GPU VRAM to avoid transfer overhead

By setting pipeline: true, intermediate matrices remain in GPU memory between iterations, eliminating CPU-GPU memory bus bottlenecks during convergence loops.

Handling Complex Roots

Companion matrices of real polynomials often produce complex conjugate pairs. Because standard single-thread scalar registers in GPU.js operate on real numbers, complex eigenvalues must be extracted from the quasi-triangular real Schur form produced by the Francis double-shift QR algorithm.

In this form:

  • Real roots appear directly as \(1 \times 1\) blocks on the diagonal.
  • Complex conjugate roots \((\lambda = \alpha \pm \beta i)\) appear as \(2 \times 2\) blocks along the diagonal:

\[\begin{bmatrix} a & b \\ c & d \end{bmatrix} \implies \lambda = \frac{a + d}{2} \pm \frac{\sqrt{4bc + (a - d)^2}}{2}\]

A final extraction kernel scans the diagonal in parallel, flags \(2 \times 2\) non-zero subdiagonal blocks, and computes the real and imaginary components directly on the GPU.
