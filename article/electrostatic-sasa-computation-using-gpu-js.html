Electrostatic SASA Computation Using GPU.js

Computing the electrostatic solvent-accessible surface area (SASA) of macromolecules is entirely achievable in GPU.js by offloading intensive geometric sampling and electrostatic potential evaluations to the GPU via WebGL or WebGPU. This article outlines how to implement this computational pipeline in JavaScript, detailing the algorithm design, GPU kernel decomposition, performance advantages, and technical limitations of performing macromolecular electrostatic analysis within a browser or Node.js environment.

The Computational Problem

Solvent-Accessible Surface Area (SASA) measures the surface area of a macromolecule that is reachable by a solvent sphere (typically with a radius of 1.4 Å for water). When coupled with electrostatics, each accessible surface point is assigned an electrostatic potential derived from the partial charges of neighboring atoms.

This workflow involves two computationally demanding, highly parallelizable components:

  1. Geometric Surface Generation: Calculating accessibility using algorithms such as Shrake-Rupley (sphere dot-distribution) or Lee-Richards (sliced circles).
  2. Electrostatic Evaluation: Calculating the electrostatic potential at each solvent-exposed surface point, typically via Coulomb's Law, Debye-Hückel approximations, or boundary-element Poisson-Boltzmann methods.

How GPU.js Handles the Workload

GPU.js compiles standard JavaScript functions into GLSL shaders running on the GPU. Because both surface generation and electrostatic evaluations operate as "embarrassingly parallel" point-wise computations, they map efficiently to GPU compute kernels.

1. Data Structuring and Memory Mapping

Macromolecular data (such as PDB structures) must be flattened into numeric arrays before passing to GPU kernels:

  • Coordinates: Flattened 1D or 2D arrays containing \((x, y, z)\) positions of all atoms.
  • Radii: Van der Waals radii adjusted by the solvent probe radius (\(r_{vdw} + r_{probe}\)).
  • Charges: Partial atomic charges assigned from standard force fields (e.g., AMBER or CHARMM).

2. Surface Accessibility Kernel

Using the Shrake-Rupley numerical method, each atom is enclosed by a test sphere populated by \(N\) evenly distributed test points (typically \(N = 92\) to \(960\) points based on the Golden Spiral method).

The GPU.js kernel can be structured as follows:

  • Kernel Dimension: \([N_{points}, N_{atoms}]\).
  • Computation: For each test point on a target atom, the kernel computes the Euclidean distance to every other neighboring atom.
  • Result: If the distance to any other atom \(j\) is strictly less than \((r_j + r_{probe})\), the point is buried (\(0\)); otherwise, it is accessible (\(1\)).

3. Electrostatic Potential Kernel

Once accessible points are identified, a second GPU.js kernel evaluates the electrostatic potential at each exposed point:

  • Input: Coordinates of accessible surface points and atom coordinates with partial charges.
  • Computation: The kernel evaluates a Coulombic summation or screened Coulomb potential (Debye-Hückel): \[\Phi(\mathbf{r}) = \sum_{i=1}^{M} \frac{q_i}{4 \pi \varepsilon_0 \varepsilon_r \|\mathbf{r} - \mathbf{r}_i\|} \exp(-\kappa \|\mathbf{r} - \mathbf{r}_i\|)\] where \(q_i\) represents partial atomic charges, \(\varepsilon_r\) is the dielectric constant, and \(\kappa\) represents the inverse Debye screening length.
  • Result: A scalar potential value assigned to each exposed surface patch.

Limitations and Practical Considerations

While GPU.js enables electrostatic SASA calculations directly within JavaScript environments, several constraints must be managed:

  • Precision Limits: WebGL often restricts calculations to 32-bit floating-point precision (float32). While adequate for geometric accessibility and Coulombic approximations, it can introduce rounding artifacts in delicate Poisson-Boltzmann solvers.
  • Memory Limits and Uniform Buffers: Passing thousands of atom coordinates into a kernel can exceed uniform limits on older WebGL configurations. The standard solution is encoding atom data into floating-point textures (DataTexture).
  • Neighbor Lists: A brute-force pairwise calculation on the GPU runs in \(O(N_{atoms} \times N_{points} \times N_{atoms})\) time. To scale to large complexes, a spatial grid (cell list or voxel grid) should be precomputed on the CPU to restrict search radii on the GPU.

Summary

Electrostatic SASA calculations can be effectively implemented in GPU.js by parallelizing the Shrake-Rupley test-point verification and electrostatic potential summations across GPU shader pipelines. This approach provides real-time, in-browser analysis suitable for web-based molecular viewers, structural bioinformatics workflows, and interactive drug-discovery platforms without relying on native C/CUDA backends.
