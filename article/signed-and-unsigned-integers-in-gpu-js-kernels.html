Signed and Unsigned Integers in GPU.js Kernels

This article explores whether developers can explicitly declare signed and unsigned integers inside a gpu.js kernel function. It explains how gpu.js translates JavaScript code into WebGL shaders, how data types are inferred, and the limitations surrounding integer type declarations within GPU-accelerated JavaScript kernels.

In gpu.js, you cannot explicitly declare signed or unsigned integers inside a kernel function. Because gpu.js kernels are written using valid JavaScript syntax, type declarations like C-style int, uint, signed, or unsigned do not exist. Attempting to use static type keywords inside the kernel function will result in a JavaScript syntax error before the kernel can be compiled.

Kernel variables must be declared using standard JavaScript keywords: let, const, or var. When compiling the JavaScript function into WebGL Shading Language (GLSL), gpu.js uses static analysis to infer the underlying data types.

By default, gpu.js treats most numeric values and mathematical operations as 32-bit floating-point numbers (float). This design ensures broad compatibility across both WebGL 1.0 and WebGL 2.0 implementations, as WebGL 1.0 has limited native integer support.

The gpu.js compiler infers signed integers (int in GLSL) primarily for specific control-flow structures, such as loop counters in standard for loops, and for the built-in thread coordinate properties like this.thread.x. However, you cannot force the compiler to treat a local variable specifically as an unsigned integer (uint), as the parser does not provide a mechanism or syntax for unsigned integer inference within the kernel body.

To work with specific integer representations, you must manage them outside the kernel function. You can pass integer data into a kernel using JavaScript typed arrays, such as Int32Array or Uint32Array, or configure the kernel's output texture mode. Once those values enter the kernel body, however, gpu.js handles them through its internal type inference and casting rules rather than explicit, in-kernel integer declarations.
