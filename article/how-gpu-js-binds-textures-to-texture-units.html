How gpu.js Binds Textures to Texture Units

This article explains how gpu.js binds textures to specific WebGL texture units prior to kernel execution. By translating JavaScript arrays and texture objects into GPU-compatible memory, the library manages texture slots, activates target texture units, binds WebGL texture handles, and sets corresponding sampler uniforms so that the generated GLSL fragment shader can access input data during shader dispatch.

Argument Parsing and Texture Allocation

When a kernel function is invoked in gpu.js, the runtime evaluates each passed argument. If an argument is an array or typed array, gpu.js either packs it into a newly created WebGLTexture or reuses an existing texture buffer. If the argument is already a gpu.js Texture instance, it retains its existing GPU texture handle.

The kernel maintains an internal registry of texture arguments. Each texture is assigned a sequential index corresponding to an available hardware texture unit, starting from index 0 up to the hardware limit determined by gl.MAX_COMBINED_TEXTURE_IMAGE_UNITS.

Activating the Texture Unit

WebGL requires a texture unit to be designated as "active" before a texture can be bound to it. Internally, gpu.js iterates through the list of texture arguments prior to running the draw call. For each texture argument at index i, it calls the standard WebGL API:

gl.activeTexture(gl.TEXTURE0 + i);

This sets the hardware context's active texture slot to TEXTURE0, TEXTURE1, and so forth, preparing it to receive binding instructions.

Binding the WebGLTexture Object

Once the specific texture unit is marked active, gpu.js binds the actual underlying WebGLTexture reference to the gl.TEXTURE_2D target:

gl.bindTexture(gl.TEXTURE_2D, texture.texture);

Because gl.activeTexture precedes this call, the texture object is linked specifically to gl.TEXTURE0 + i. gpu.js also ensures the appropriate texture parameters (such as gl.CLAMP_TO_EDGE and gl.NEAREST filtering) are set to avoid unwanted interpolation when reading raw numerical data.

Linking Samplers via Uniforms

To enable the compiled GLSL shader to read from the bound unit, gpu.js updates the uniform sampler declared inside the shader source. During kernel compilation, gpu.js generates variable declarations such as uniform sampler2D user_variableName;.

Before the draw command, gpu.js passes the integer index i (not the enum gl.TEXTURE0 + i) to the sampler's uniform location:

const location = gl.getUniformLocation(program, 'user_' + argumentName);
gl.uniform1i(location, i);

This tells the shader sampler to fetch data from the texture unit configured at index i.

Shader Dispatch

With all input textures bound to their respective units and all sampler uniforms updated, gpu.js sets the WebGL viewport to match the output kernel dimensions and invokes gl.drawArrays or gl.drawElements. As the GPU processes fragments, the shader uses texture2D lookups referencing the bound units to read input elements in parallel.
