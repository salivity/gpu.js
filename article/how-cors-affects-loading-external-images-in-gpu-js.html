How CORS Affects Loading External Images in GPU.js

When loading external images into gpu.js for parallel processing, the browser's Cross-Origin Resource Sharing (CORS) policy strictly dictates whether the graphics hardware can access the underlying pixel data. Because gpu.js relies on WebGL under the hood, any cross-origin image loaded without explicit CORS permissions is flagged as a security risk, preventing texture creation and halting kernel execution. Resolving this requires proper HTTP response headers on the host server and an explicit cross-origin attribute on the client image object.

The Mechanism: WebGL and Tainted Textures

gpu.js accelerates image processing by passing HTML image elements directly into WebGL textures via the texImage2D method. Under standard web security rules, the Same-Origin Policy allows the browser to display external images in an <img> tag, but it blocks scripts from reading the raw pixel values unless the serving domain explicitly authorizes it.

If a script attempts to read pixel data from an untrusted source, the canvas or WebGL context becomes "tainted." Because gpu.js must read and transform these pixels on the GPU, WebGL immediately throws a SecurityError and refuses to bind the image to a texture. As a result, your gpu.js kernel cannot run.

The Required Server-Side Headers

For an external image to be usable in gpu.js, the server hosting that image must include appropriate CORS headers in its HTTP response. At minimum, the server must supply:

Access-Control-Allow-Origin: *

Alternatively, the header can specify your exact domain instead of the wildcard *. Without this header, the client browser will block gpu.js from using the image data in WebGL computations, even if the image successfully loads in the DOM.

Client-Side Configuration

Configuring the server alone is not enough; the client must also request the asset with CORS enabled. When loading an external image in JavaScript to pass into a gpu.js kernel, you must set the crossOrigin property before defining the image source:

const img = new Image();
img.crossOrigin = "anonymous";
img.src = "https://example.com/data-image.png";

img.onload = () => {
  const gpu = new GPU();
  const kernel = gpu.createKernel(function(image) {
    const pixel = image[this.thread.y][this.thread.x];
    this.color(pixel.r, pixel.g, pixel.b, pixel.a);
  }).setOutput([img.width, img.height]).setGraphical(true);

  kernel(img);
};

Setting img.crossOrigin = "anonymous" instructs the browser to make a CORS request without transmitting user credentials like cookies or HTTP authentication headers.

Workarounds When Server Headers Cannot Be Modified

If you do not control the external image server and it does not serve CORS headers, the browser will categorically reject the image inside WebGL. In this scenario, you must route the image through an intermediary solution:

  1. CORS Proxy: Direct image requests through a reverse proxy server that fetches the asset and attaches the required Access-Control-Allow-Origin header to the response.
  2. Backend Fetching: Have your own server fetch the image, process or forward it, and serve it to your frontend from the same origin or with the appropriate CORS headers configured.
