GPU.js Viewport Scaling and Canvas Output Dimensions

GPU.js manages the relationship between kernel output dimensions and HTML canvas sizes by decoupling computational resolution from DOM display rendering. When a graphical kernel runs, GPU.js configures the underlying WebGL context to render precisely at the resolution specified by the kernel's output property, while any visual size discrepancy with the <canvas> element is handled at the WebGL drawing buffer or browser layout level.

Kernel Output and the WebGL Viewport

In GPU.js, the output array defines the execution grid of the compute shader. When graphical mode is enabled (kernel.setGraphical(true)), this execution grid directly corresponds to pixel coordinates. GPU.js translates the output dimensions into the WebGL viewport using the native WebGL API:

gl.viewport(0, 0, outputWidth, outputHeight);

This ensures that the WebGL normalized device coordinates (NDC) map directly to the defined output dimensions of your kernel function, allowing this.thread.x and this.thread.y to align with the rendered pixels.

Internal Drawing Buffer vs. Display Size

HTML5 canvases have two distinct size properties: the drawing buffer resolution (canvas.width and canvas.height) and the visual display size managed by CSS (canvas.style.width and canvas.style.height).

GPU.js automatically synchronizes the canvas's internal drawing buffer with the kernel's output dimensions:

  1. Automatic Canvas Resizing: If you use the default canvas generated by GPU.js, the library sets the canvas element’s internal drawing buffer dimensions to match the kernel's output: [width, height].
  2. Custom Canvas Elements: If you pass an existing canvas instance into the GPU context, GPU.js overrides the canvas drawing buffer resolution to match the kernel output during rendering cycles.

Because the internal buffer matches the kernel output, there is no sub-sampling or pixel mismatch at the execution level; one compute thread generates exactly one pixel in the WebGL frame.

Browser-Level Viewport Scaling

When the visual display size of the canvas (defined via CSS or HTML attributes) differs from the kernel’s output dimensions, the scaling is managed by the browser's graphics compositor rather than the GPU.js kernel.

  • Upscaling and Downscaling: If the output resolution is smaller than the display area, the browser stretches the rendered buffer across the canvas area. By default, WebGL canvases use linear filtering (bilinear interpolation), resulting in a smoothed or blurred image.
  • Preserving Sharp Pixels: To prevent smoothing when upscaling low-resolution kernel outputs to a larger canvas, the CSS image-rendering property must be set to pixelated or crisp-edges.
  • Aspect Ratio Discrepancies: If the aspect ratio of the kernel output dimensions does not match the aspect ratio of the canvas display size, the browser stretches the image non-uniformly. GPU.js does not automatically add letterboxing or pillarboxing; developers must maintain aspect ratio parity manually through CSS rules or by matching output and canvas proportions.
