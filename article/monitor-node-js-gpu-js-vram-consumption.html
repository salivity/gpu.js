Monitor Node.js gpu.js VRAM Consumption

Running a long-running Node.js microservice powered by gpu.js requires strict monitoring of Video RAM (VRAM) to prevent silent out-of-memory crashes and resource starvation. Because Node.js's native V8 garbage collector does not automatically govern GPU memory allocations managed by WebGL or OpenCL backends, orphaned textures and compute kernels can easily accumulate. This guide details practical methods to inspect, extract, and monitor per-process VRAM metrics in production environments using native GPU tools, in-process polling, and modern observability pipelines.

Understanding the GPU Memory Footprint

gpu.js accelerates JavaScript operations by compiling functions into WebGL shaders or OpenCL kernels. When executing kernels:

  • Textures are allocated directly on the GPU.
  • If pipeline mode (pipeline: true) is enabled, output textures remain in VRAM to feed subsequent computations without CPU-roundtrips.
  • Failure to call texture.delete() or manage kernel lifecycles keeps VRAM allocated indefinitely, bypassing Node.js heap limits.

Method 1: Programmatic Process Monitoring via NVIDIA Tools

On host machines equipped with NVIDIA GPUs, the nvidia-smi CLI provides direct access to VRAM consumption filtered by process ID (PID). You can programmatically sample this data directly inside your Node.js application to expose it to an APM or logging pipeline.

import { exec } from 'node:child_process';
import { promisify } from 'node:util';

const execAsync = promisify(exec);

async function getProcessVramUsage() {
  const pid = process.pid;
  const command = `nvidia-smi --query-compute-apps=pid,used_gpu_memory --format=csv,noheader,nounits`;

  try {
    const { stdout } = await execAsync(command);
    const lines = stdout.trim().split('\n');
    
    for (const line of lines) {
      const [appPid, memoryMb] = line.split(',').map(item => item.trim());
      if (parseInt(appPid, 10) === pid) {
        return parseInt(memoryMb, 10); // VRAM in MB
      }
    }
    return 0; // Not actively using VRAM or not found
  } catch (error) {
    console.error('Failed to query GPU memory:', error.message);
    return null;
  }
}

// Poll periodically
setInterval(async () => {
  const vram = await getProcessVramUsage();
  console.log(`Current PID (${process.pid}) VRAM Consumption: ${vram} MB`);
}, 10000);

Method 2: System Information Libraries

For multi-vendor environments (NVIDIA, AMD, Intel) where custom shell parsing is suboptimal, use the systeminformation npm package to poll device-level GPU stats:

import si from 'systeminformation';

async function checkGpuMetrics() {
  const gpuData = await si.graphics();
  gpuData.controllers.forEach((controller, index) => {
    console.log(`GPU ${index} (${controller.model}):`);
    console.log(`  Total VRAM: ${controller.vram} MB`);
    console.log(`  Dynamic Usage: ${controller.memoryUsed || 'N/A'} MB`);
  });
}

Note: OS-level access control may limit non-NVIDIA process-level tracking, returning overall device utilization rather than individual Node.js thread usage.

Method 3: Production Observability with Prometheus

For containerized microservices running in Kubernetes or Docker:

  1. NVIDIA DCGM Exporter: Deploy the NVIDIA Data Center GPU Manager (DCGM) exporter alongside your service container. It continuously reads hardware counters and exposes Prometheus metrics.
  2. Prometheus Metrics Endpoint: Use the prom-client package in your Node.js app to combine process-level V8 metrics with the VRAM consumption queries established in Method 1.
import client from 'prom-client';

const vramGauge = new client.Gauge({
  name: 'nodejs_gpu_vram_used_bytes',
  help: 'VRAM used by this specific Node.js process in bytes',
});

setInterval(async () => {
  const vramMb = await getProcessVramUsage();
  if (vramMb !== null) {
    vramGauge.set(vramMb * 1024 * 1024);
  }
}, 5000);

Best Practices to Prevent VRAM Leaks

  • Explicit Cleanup: Always destroy textures manually when using pipelining: 
    const resultTexture = kernel();
// ... process results ...
resultTexture.delete();
  • Re-use Kernels: Compiling kernels repeatedly creates new contexts. Initialize gpu.createKernel() instances once at startup and reuse them across requests.
  • VRAM Threshold Alerts: Set alerts when your process reaches 80% of total available device VRAM to allow safe process draining and worker recycling before an unrecoverable out-of-memory error terminates the microservice.
