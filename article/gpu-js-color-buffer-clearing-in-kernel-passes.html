gpu.js Color Buffer Clearing in Kernel Passes

This article explores how gpu.js handles color buffer clearing and memory state resets between consecutive kernel runs. When executing chained or pipelined calculations, the library relies on the underlying WebGL context, alternating Framebuffer Objects (FBOs), explicit API clearing calls, and full-viewport draw passes to isolate data and prevent residual fragment artifacts between compute iterations.

Framebuffer Objects and Ping-Pong Buffering

In pipelined workflows where the output of one kernel serves as the input to the next, gpu.js utilizes a technique known as ping-pong buffering. The library binds alternating Framebuffer Objects (FBOs) backed by WebGL textures. Instead of repeatedly allocating and deallocating GPU memory, gpu.js toggles the roles of two or more textures: one acts as the active render target (color attachment) while the other acts as an input texture sampler. Isolating consecutive passes to separate textures inherently prevents the destination buffer from polluting the source data before computation finishes.

Explicit Clearing via WebGL API

When preparing an FBO for a new execution pass, gpu.js interacts directly with the WebGL rendering context state machine. Before rendering into a target texture, the framework can invoke:

  • gl.clearColor(0.0, 0.0, 0.0, 0.0) to define the reset values for each color channel (RGBA).
  • gl.clear(gl.COLOR_BUFFER_BIT) to explicitly instruct the GPU rasterizer to flush the currently bound color attachment and reset all fragment values to the defined clear color.

This explicit clear guarantees that unmapped or out-of-bounds fragments do not preserve residual numerical values from previous computational cycles.

Implicit Full-Viewport Fragment Overwriting

In standard GPGPU operations through WebGL, computations are executed by rendering a screen-aligned quad—composed of two triangles covering the entire viewport—via orthographic projection. Because the output texture matches the exact dimensions of the thread grid, the fragment shader executes and evaluates every single pixel location corresponding to the output dimensions.

Because every pixel in the target color buffer is systematically overwritten during the draw call (gl.drawArrays or gl.drawElements), the fragment shader writes fresh values across the entire buffer surface. In scenarios where a full overwrite is mathematically guaranteed, explicit clearing can be bypassed to reduce overhead, as the shader execution natively replaces prior buffer contents.

Viewport and Scissor State Adjustments

Before clearing or drawing, gpu.js synchronizes the execution dimensions using gl.viewport(0, 0, width, height). If scissor testing is active (gl.SCISSOR_TEST), WebGL restricts buffer clears to a sub-rectangle of the render target. gpu.js disables or reconfigures the scissor box to encompass the entire dimension of the compute grid, ensuring that gl.clear(gl.COLOR_BUFFER_BIT) uniformly resets the entire designated color buffer rather than leaving uncleared borders.
