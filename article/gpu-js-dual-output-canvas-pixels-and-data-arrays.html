GPU.js Dual Output: Canvas Pixels and Data Arrays

A single GPU.js kernel cannot directly output both raw numerical array data and visual canvas pixels at the same time. In GPU.js, a kernel must be explicitly designated for computation (returning typed arrays or textures) or rendering (outputting color values to a WebGL canvas). While a single execution pass cannot simultaneously produce both targets, you can achieve identical results with minimal overhead by utilizing kernel pipelines, reading canvas pixels directly, or encoding numerical data into color channels.

The Underlying WebGL Limitation

GPU.js compiles JavaScript functions into WebGL fragment shaders. In WebGL, a fragment shader renders output to an active framebuffer. GPU.js abstracts this by offering two mutually exclusive modes:

  1. Computational Mode (Default): The kernel returns floats or vectors, which GPU.js compiles into an array or a WebGL texture for mathematical operations.
  2. Graphical Mode (graphical: true): The kernel requires using this.color(r, g, b, a) to write directly to an HTML5 <canvas> element. When this mode is active, the function cannot return a standard numerical array to JavaScript.

Because these configurations use different execution paths and shader output instructions, you cannot return a standard number array while simultaneously calling this.color() to draw to the screen in the same kernel.

Workaround 1: Kernel Pipelining (Recommended)

The most performant way to retain numerical data while rendering visually is to split the logic across two chained kernels using GPU.js pipelining (pipeline: true). Pipelining keeps the data on the GPU memory as a texture, avoiding costly CPU-GPU memory transfers.

  • Step 1 (Compute Kernel): Set pipeline: true. Compute the mathematical calculations and return the raw output. This keeps the result in GPU VRAM as a texture.
  • Step 2 (Render Kernel): Create a second kernel with graphical: true. Pass the output texture from the first kernel into this render kernel, read the values, and paint them using this.color().
  • Step 3 (Data Retrieval): If the CPU needs the numerical values, call .toArray() on the result of the compute kernel.

This technique provides maximum performance because visual output occurs at native GPU speeds, and CPU data conversion only takes place when explicitly requested.

Workaround 2: Extracting Data from a Graphical Kernel

If you primarily need to display output to a canvas and only occasionally need the numerical values, configure the kernel with graphical: true:

  1. Render your visual output using this.color(r, g, b, a).
  2. Access the generated canvas element via kernel.canvas.
  3. Use the standard 2D canvas or WebGL context API (getImageData() or readPixels()) to extract the pixel array back to JavaScript.

Keep in mind that color channels normalize data between 0.0 and 1.0 (8 bits per channel when reading standard image data), which will lead to precision loss if your calculations rely on floating-point data beyond the 0–255 integer range.

Summary

While GPU.js enforces a separation between array computation and canvas rendering within a single kernel call, you can achieve both goals seamlessly by pipelining a computational kernel into a graphical kernel. This approach ensures high visual performance on the canvas while preserving full-precision numerical data for application logic.
