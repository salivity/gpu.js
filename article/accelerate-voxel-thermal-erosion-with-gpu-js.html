Accelerate Voxel Thermal Erosion with GPU.js

Thermal erosion and talus deposition simulate the natural weathering of slopes, where material exceeding a critical angle of repose shears away and deposits downhill. While executing these calculations on three-dimensional voxel grids is computationally expensive in standard JavaScript, GPU.js can significantly accelerate the process by running cellular automata kernels in parallel on the GPU via WebGL. However, maximizing this performance requires accounting for race conditions, 3D memory representations, and CPU-GPU data transfer bottlenecks.

Understanding Thermal Erosion and Talus Formation

Thermal erosion models the breakdown of terrain due to temperature fluctuations and gravity. In a discrete grid, each cell evaluates the elevation difference between itself and its immediate neighbors:

  1. Talus Angle Threshold: If the slope to an adjacent lower neighbor exceeds a defined threshold (the talus angle), material becomes unstable.
  2. Mass Movement: A proportional volume of matter detaches from the unstable voxel and shifts to the lower cell.
  3. Deposition: The transported material settles at the base of slopes, forming characteristic scree or talus ramps until all slopes settle beneath the resting angle.

In a fully volumetric voxel environment, this process is significantly more demanding than in a 2D heightmap because voxels can feature overhangs, caves, and multi-layered soil types, exponentially increasing the cell evaluation count.

Why GPU.js Is Suited for Voxel Erosion

GPU.js allows developers to write computational kernels in standard JavaScript syntax, which the library compiles into WebGL fragment shaders. Thermal erosion is inherently a local stencil operation—each voxel’s next state depends primarily on its immediate Moore or von Neumann neighborhood.

Because every cell can evaluate its slope rules simultaneously, the algorithm is an ideal candidate for Single Instruction, Multiple Data (SIMD) parallelization. Offloading millions of neighbor comparisons to hundreds or thousands of GPU cores yields speedups of an order of magnitude or more compared to single-threaded CPU loops in JavaScript.

Technical Challenges and Solutions in GPU.js

While GPU.js provides parallel computing primitives, several architectural constraints must be addressed when simulating voxel physics:

1. Data Structure and 3D Mapping

GPU.js outputs data using 2D WebGL textures. True 3D arrays must either be mapped to flattened 1D arrays or encoded across 2D atlas textures (e.g., slicing a \(128 \times 128 \times 128\) voxel cube into a grid of 2D cross-sections). Inside the GPU.js kernel, developers must convert 3D coordinates \((x, y, z)\) into the corresponding flattened index to sample neighboring voxels correctly.

2. Race Conditions and Mass Conservation

A common issue in parallel erosion is multiple high cells simultaneously dumping material into the same lower neighbor, creating artificial pillars and violating mass conservation. To resolve this in GPU.js:

  • Gather Over Scatter: The GPU kernel should be written to "pull" data rather than "push" it. Each cell computes how much material it receives from higher neighbors and how much it loses to lower neighbors.
  • Ping-Pong Buffering: Run simulations across alternating buffers. The state at time step \(t\) reads strictly from Buffer A and writes to Buffer B. Time step \(t+1\) reads from Buffer B and writes back to Buffer A.

3. Minimizing Bus Transfers

Transferring large voxel arrays between system RAM and the GPU introduces severe latency. If the simulation requires data to round-trip back to the CPU after every iteration, memory bus bottlenecks will eliminate any GPU performance gains.

To achieve real-time rates, keep the voxel data on the GPU by chaining iterations directly using GPU.js textures (kernel.setOutputOrder('array') or texture modes). Data should only be read back to the CPU when the erosion simulation reaches equilibrium or when updating the visible mesh.

Conclusion

Thermal erosion and talus deposition on voxel terrains can be accelerated effectively with GPU.js. By structuring the physics as a gather-based cellular automaton, packing 3D grids efficiently into GPU textures, and chaining simulation passes on the graphics hardware, developers can achieve interactive, real-time terrain weathering inside the browser.
