How gpu.js Maps Math.sin and Math.cos to Native GPU

This article explains the underlying translation pipeline used by gpu.js to execute JavaScript trigonometric functions on graphics hardware. By parsing JavaScript code into an Abstract Syntax Tree (AST), transpiling high-level mathematical calls into OpenGL Shading Language (GLSL), and leveraging the graphics driver’s shader compiler, gpu.js bridges the gap between the JavaScript runtime and native GPU Special Function Units (SFUs) that execute sine and cosine calculations at the silicon level.

JavaScript AST Parsing

When you define a kernel in gpu.js, the library does not execute the function directly within the JavaScript engine. Instead, it extracts the function's source string and parses it into an Abstract Syntax Tree (AST) using a JavaScript parser (such as Acorn).

During this traversal, the compiler watches for CallExpression nodes where the callee matches a member expression on the global Math object, specifically Math.sin and Math.cos. Once identified, the compiler flags these nodes for mathematical translation rather than standard JavaScript method dispatch.

Transpilation to GLSL

After extracting the mathematical calls, gpu.js runs an internal GLSL code generator that converts the JavaScript AST into a WebGL fragment shader or compute shader.

In OpenGL Shading Language (GLSL), trigonometry is supported out of the box through standard built-in functions. The gpu.js transpiler performs a direct name and signature substitution:

  • Math.sin(x) is rewritten as sin(x)
  • Math.cos(x) is rewritten as cos(x)

The transpiler also ensures that arguments passed into these functions are cast to or maintained as standard floating-point types (float), matching GLSL's strict typing requirements.

WebGL Shader Compilation and Driver Optimization

Once the GLSL string is generated, gpu.js passes the shader code to the browser’s WebGL context via gl.shaderSource() and triggers compilation with gl.compileShader().

At this point, the host machine's graphics driver takes over. The driver contains an architecture-specific compiler that translates the high-level GLSL into the GPU's intermediate representation or native Machine Instruction Set Architecture (ISA). The driver recognizes GLSL's intrinsic sin and cos functions and maps them directly to the GPU's hardware instruction set rather than generating complex software-based polynomial expansion loops.

Hardware Execution via Special Function Units (SFUs)

Modern GPU architectures (such as NVIDIA, AMD, Intel, and Apple Silicon) contain dedicated hardware blocks known as Special Function Units (SFUs) or Special Execution Units.

When the compiled shader runs on the streaming multiprocessors:

  1. The GPU scheduler routes the trigonometry instructions directly to the SFUs.
  2. The SFU executes hardware-level algorithms (often based on hardware-implemented Taylor series, minimax polynomial approximations, or CORDIC algorithms) to evaluate the trigonometric result in very few clock cycles.
  3. The result is returned directly to the general-purpose register file for subsequent kernel operations.

Precision Differences

Because Math.sin and Math.cos in standard JavaScript engines follow double-precision (64-bit) IEEE 754 floating-point standards, results calculated via gpu.js may show slight precision variations. Most WebGL contexts target single-precision (32-bit) floats or lower, and hardware SFU implementations prioritize throughput over extreme precision, resulting in native, high-speed execution tailored for parallel computational workloads.
