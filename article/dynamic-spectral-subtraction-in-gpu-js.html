Dynamic Spectral Subtraction in GPU.js

Dynamic spectral subtraction is a frequency-domain digital signal processing technique designed to eliminate stationary and quasi-stationary background noise from audio signals by continuously updating an estimate of the noise floor. Implementing this algorithm using gpu.js is entirely feasible and offers significant parallel performance advantages inside web browsers and Node.js environments. By offloading time-frequency transformations and array-wide magnitude subtractions to the GPU via WebGL shaders, developers can achieve low-latency audio cleanup without relying entirely on native desktop binaries.

Feasibility and Core Architecture

GPU.js compiles a subset of JavaScript into GLSL shaders, running parallel operations over multi-dimensional arrays. Because spectral subtraction operates on discrete frequency bins across short-time audio frames, it fits the single instruction, multiple data (SIMD) execution model of graphics processors.

To execute dynamic spectral subtraction in gpu.js, the audio pipeline is divided into distinct computational kernels:

  1. Short-Time Fourier Transform (STFT): The time-domain audio stream is segmented into overlapping windowed frames (such as Hann or Hamming windows). A Fast Fourier Transform (FFT) kernel calculates the complex frequency components (real and imaginary) for each frame.
  2. Magnitude and Phase Extraction: A kernel extracts the magnitude spectrum to manipulate energy levels while preserving the original phase angles for accurate signal reconstruction.
  3. Dynamic Noise Profile Tracking: Unlike static subtraction, dynamic spectral subtraction updates the noise floor over time. A Voice Activity Detector (VAD) or minimum statistics algorithm runs across recent frames to differentiate active audio from steady background noise.
  4. Spectral Subtraction Kernel: The estimated noise magnitude is scaled by an over-subtraction factor and subtracted from the total signal magnitude. Spectral floor thresholds prevent negative values and minimize artifacts known as "musical noise."
  5. Inverse Short-Time Fourier Transform (ISTFT): The modified magnitudes are recombined with the original phase components, converted back into time-domain frames via an Inverse FFT kernel, and stitched together using overlap-add synthesis.

Implementation Challenges in GPU.js

While the mathematical operations map well to GPU parallelization, several architectural limitations require deliberate design choices:

  • Complex Number Handling: GPU.js does not have native support for complex numbers. The real and imaginary parts of the Fourier transforms must be handled as distinct elements, typically using 2D arrays or interleaved channels.
  • Data Transfer Bottlenecks: Passing large audio buffers between the CPU (RAM) and GPU (VRAM) introduces latency. To achieve near-real-time throughput, operations—from windowing through inverse transformation—must remain inside GPU memory as textures, minimizing round-trip memory readbacks.
  • FFT Optimization: Cooley-Tukey FFT implementations in gpu.js require multiple kernel passes (butterfly operations). Ensuring these passes execute efficiently without intermediate CPU reads is essential for maintaining high frame rates.

Practical Viability

Implementing dynamic spectral subtraction in gpu.js is practical for offline processing of large audio files and can support real-time audio streams if frame sizes are appropriately balanced (typically 512 to 2048 samples). For browser-based applications that require custom, hardware-accelerated DSP pipelines without writing low-level WebGL or WebGPU shader code manually, gpu.js provides a viable and accessible framework.
