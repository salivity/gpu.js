Bicubic Interpolation for Irregular Data in GPU.js

This article evaluates whether bicubic surface interpolation can be performed directly on irregularly distributed geospatial coordinates using the gpu.js WebGL acceleration library. While bicubic interpolation strictly requires a structured rectilinear grid, gpu.js can still be leveraged to process irregular geospatial datasets by pairing an initial rasterization or gridding phase with a GPU-accelerated bicubic kernel. Below, we examine the mathematical constraints, the capabilities of gpu.js, and the architectural pattern required to achieve this workflow.

The Mathematical Limitation of Bicubic Interpolation

Bicubic interpolation constructs a smooth surface by evaluating a \(4 \times 4\) grid of sixteen evenly spaced control points surrounding a target location. The algorithm relies on standard finite-difference formulas or precalculated spatial derivatives along orthogonal axes (\(x\) and \(y\)) to determine the sixteen polynomial coefficients of the cubic surface patch.

Because irregular geospatial points (scatter data) lack uniform spacing and orthogonal alignment, bicubic interpolation cannot be computed directly on the raw coordinates. Standard bicubic formulas cannot handle arbitrary Delaunay triangulations or non-uniform neighborhoods without an intermediate transformation.

How gpu.js Handles the Problem

The library gpu.js compiles JavaScript functions into GLSL shaders executed via WebGL. Shaders excel at parallel pixel-by-pixel calculations across 2D matrices and textures.

Directly querying an arbitrary point cloud in a fragment shader requires sending large arrays of unstructured coordinates to the GPU and performing brute-force distance searches, which defeats the performance advantages of GPU execution. To compute a bicubic surface across irregular geospatial points using gpu.js, you must implement a two-step pipeline.

Step 1: Initial Gridding (Scattered Data to Regular Grid)

Before applying bicubic interpolation, the irregular geospatial points must be converted into a regularly sampled uniform grid. This can be achieved through:

  1. GPU-Accelerated Inverse Distance Weighting (IDW): Pass the raw point array \((x, y, z)\) into a gpu.js kernel. Each output thread corresponds to a cell on a regular grid, computing an IDW value based on nearby points within a search radius.
  2. CPU-Side Triangulation: Perform Delaunay triangulation or Natural Neighbor interpolation on the CPU, rasterizing the primary surface elevation into a float array or canvas texture.

Step 2: Bicubic Interpolation Kernel in gpu.js

Once the dataset is mapped to a uniform 2D matrix, gpu.js can execute standard bicubic interpolation at scale:

  1. Matrix Mapping: Pass the regular grid as a 2D array or WebGL texture to a gpu.js kernel sized to the desired output resolution.
  2. Neighbor Sampling: For any continuous coordinate \((u, v)\) on the surface, the kernel identifies the surrounding \(4 \times 4\) grid cells.
  3. Cubic Weighting: Apply cubic convolution (such as the Catmull-Rom or Keys spline kernel) independently along the rows and columns: \[W(t) = \begin{cases} (a+2)|t|^3 - (a+3)|t|^2 + 1 & \text{for } |t| \le 1 \\ a|t|^3 - 5a|t|^2 + 8a|t| - 4a & \text{for } 1 < |t| < 2 \\ 0 & \text{otherwise} \end{cases}\]
  4. Surface Evaluation: The GPU computes the weighted sum across all 16 values in parallel, yielding continuous, smooth elevation, slope, and curvature data.

Conclusion

Bicubic surface interpolation cannot be applied directly to raw, irregularly sampled geospatial data due to the mathematical formulation of the bicubic algorithm. However, using gpu.js, you can build a high-performance pipeline by first re-gridding the scattered data through an algorithm like Inverse Distance Weighting, and then executing a parallel bicubic interpolation kernel across the resulting regular matrix.
