Computing LDA Scatter Matrices with GPU.js

Computing the between-class scatter matrix for Linear Discriminant Analysis (LDA) can be efficiently executed using gpu.js to leverage parallel hardware acceleration. This article explores how to translate the mathematical definition of the between-class scatter matrix into GPU-accelerated operations, the structural setup required in gpu.js, and the computational trade-offs involved in browser- or Node-based environments.

Mathematical Formulation of the Scatter Matrix

In Linear Discriminant Analysis, the between-class scatter matrix, denoted as \(S_B\), measures the variance between different class centroids relative to the overall dataset centroid. The formula is:

\[S_B = \sum_{c=1}^{C} N_c (\mathbf{\mu}_c - \mathbf{\mu})(\mathbf{\mu}_c - \mathbf{\mu})^T\]

Where:

  • \(C\) is the total number of classes.
  • \(N_c\) is the number of samples in class \(c\).
  • \(\mathbf{\mu}_c\) is the mean vector of class \(c\) (a \(d \times 1\) vector, where \(d\) is the number of features).
  • \(\mathbf{\mu}\) is the global mean vector of the entire dataset (\(d \times 1\)).
  • \((\mathbf{\mu}_c - \mathbf{\mu})(\mathbf{\mu}_c - \mathbf{\mu})^T\) represents the outer product, resulting in a \(d \times d\) matrix.

Why Use GPU.js?

The computation of \(S_B\) scales quadratically with the number of features (\(O(d^2)\) per class) due to the outer product operations. When datasets have high dimensionality (large \(d\)), generating and accumulating these \(d \times d\) matrices becomes computationally intensive on a single CPU thread.

gpu.js compiles JavaScript functions into WebGL (or WebGPU) shaders, running calculations across hundreds of GPU cores in parallel. Since each cell \((i, j)\) in the resulting \(d \times d\) matrix can be computed independently, the operation maps directly to GPU kernel paradigms.

Implementation Architecture in GPU.js

To compute \(S_B\) using gpu.js, the workflow consists of three primary stages:

  1. Mean Calculation: Calculate class centroids (\(\mathbf{\mu}_c\)) and the global centroid (\(\mathbf{\mu}\)). This can be performed on the CPU or via parallel reduction kernels if the sample size is exceptionally large.
  2. Mean Difference Matrix: Compute difference vectors \(\mathbf{\Delta}_c = \mathbf{\mu}_c - \mathbf{\mu}\) for each class \(c\).
  3. Scatter Accumulation Kernel: A 2D GPU kernel calculates the weighted outer products directly into the final \(d \times d\) output matrix.

GPU.js Kernel Design

The kernel outputs a 2D matrix of size \([d, d]\). For any cell \((i, j)\), the kernel iterates over all classes \(C\), multiplying the \(i\)-th and \(j\)-th components of the difference vector, scaling by \(N_c\), and summing the results:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// d is the number of features, C is the number of classes
function createScatterKernel(d, C) {
  return gpu.createKernel(function(differences, classCounts) {
    let sum = 0;
    for (let c = 0; c < this.constants.numClasses; c++) {
      let diff_i = differences[c][this.thread.y];
      let diff_j = differences[c][this.thread.x];
      sum += classCounts[c] * (diff_i * diff_j);
    }
    return sum;
  })
  .setConstants({ numClasses: C })
  .setOutput([d, d]);
}

In this kernel:

  • this.thread.x and this.thread.y correspond to coordinates \(j\) and \(i\) in the \(d \times d\) matrix.
  • differences is a 2D array of size \([C, d]\) containing \((\mathbf{\mu}_c - \mathbf{\mu})\).
  • classCounts is an array of size \(C\) containing \(N_c\).

Performance Considerations

  • Dimensionality Threshold: For datasets with a small number of features (\(d < 50\)), CPU calculation in native JavaScript is generally faster due to the overhead of compiling shaders and transferring data between CPU and GPU memory.
  • High Dimensions: For high-dimensional domains such as genomics, spectral data, or image representations (\(d > 500\)), the parallel kernel achieves substantial speedups over standard nested JavaScript loops.
  • Precision: WebGL operates primarily in 32-bit floating-point precision. If the classification task demands 64-bit double-precision floating-point arithmetic, standard gpu.js WebGL kernels may introduce slight numerical drift compared to native 64-bit CPU math.
