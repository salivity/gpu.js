Template Literal String Interpolation in gpu.js

This article explains how gpu.js handles template literal string interpolation when encountered inside user-defined functions. Because gpu.js relies on an Abstract Syntax Tree (AST) parser to convert JavaScript into WebGL-compatible GLSL (OpenGL Shading Language), syntax that cannot be mapped to graphics hardware receives special handling. The sections below break down how gpu.js processes template literals, why runtime string operations fail, and how to handle dynamic data properly.

Transpilation and the AST

When you define a kernel function in gpu.js, the library does not execute your JavaScript code line-by-line in a standard JavaScript engine. Instead, it extracts the function's source code using .toString() and parses it into an AST via an internal parser (Acorn). This AST is then translated node-by-node into corresponding GLSL shader code.

The GLSL Type Limitation

GLSL is a strictly typed shading language optimized for mathematical computations on the GPU. It contains primitives such as float, int, vec2, vec3, vec4, and bool. GLSL has no native string data type, no string concatenation operators, and no dynamic memory allocation to support text processing.

Because strings do not exist in the GPU execution environment, user-defined functions running inside a GPU kernel cannot create, manipulate, or return string values.

Behavior of Template Literals Inside the Kernel

When gpu.js encounters a TemplateLiteral AST node inside a kernel function, it cannot map the node to any valid GLSL construct:

  1. Compilation-Time Failure: If a template literal ( text ${value} ) is used within the body of the user-defined kernel, the AST-to-GLSL compiler fails during the kernel construction phase. gpu.js throws an unhandled node or unsupported feature error before the code ever reaches the GPU.
  2. No Dynamic String Evaluation: Unlike the host JavaScript environment, the GPU cannot evaluate ${expression} inside text dynamically per thread.

Correct Alternatives and Workarounds

To use dynamic values or logic without triggering compilation errors, you must keep string operations in the CPU domain:

  • Pre-Compilation Interpolation: If you need dynamic kernel generation, interpolate strings into your function source before passing the function to gpu.createKernel(). Creating the function using new Function(...) or dynamically constructing the kernel via code generation allows the JavaScript engine to evaluate the template literal first.
  • Numeric Flags Instead of Strings: Replace string-based conditionals with integers, floats, or booleans. Rather than checking string values inside the kernel, pass numbers or uniforms to conditionally branch execution.
  • Constants and Uniforms: Use the constants map or uniform variables provided by gpu.js to inject read-only values into the kernel without relying on string manipulation inside the GPU function.
