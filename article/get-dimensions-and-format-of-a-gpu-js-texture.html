Get Dimensions and Format of a gpu.js Texture

When working with chained kernels in gpu.js using pipeline mode, kernels return GPU-resident Texture objects instead of standard JavaScript arrays to maximize performance. This guide explains how to read the logical and physical dimensions of a returned Texture object and determine its underlying data format and precision.

Reading Texture Dimensions

A Texture returned by a gpu.js kernel contains two primary properties that describe its dimensions: logical dimensions and physical GPU dimensions.

  1. Logical Dimensions (texture.output)
    The texture.output property returns the output dimensions originally defined by the kernel via .setOutput([x, y, z]). This matches the multidimensional shape of your computed data array:

    const logicalDimensions = texture.output; // e.g., [512, 512] or [100, 100, 4]

  2. Physical Dimensions (texture.size)
    WebGL requires data textures to be stored as 2D surfaces in GPU memory. The texture.size property returns the actual width and height [width, height] of the underlying WebGL texture. If your kernel outputs 3D data, gpu.js packs the data into a 2D grid, making texture.size differ from texture.output:

    const physicalSize = texture.size; // [width, height] of the 2D WebGL texture

Determining Texture Format and Type

The data structure and internal channel layout of a gpu.js Texture are determined by the kernel configuration and can be inspected via internal metadata:

  1. Output Data Type (texture.type)
    The type property defines the data representation returned by the kernel. Common values include:

    • 'Number': Single float or integer values.
    • 'Array(2)', 'Array(3)', 'Array(4)': Vector outputs mapped to texture color channels (RG, RGB, RGBA).

  2. Internal WebGL Precision and Format
    gpu.js configures the WebGL texture format based on the kernel's precision setting (single or unsigned):

    • Single Precision: Uses floating-point textures (gl.FLOAT), typically configured under the gl.RGBA format to maximize hardware compatibility.
    • Unsigned Precision: Uses 8-bit unsigned byte textures (gl.UNSIGNED_BYTE).

To inspect the runtime context and active texture settings directly from the texture instance:

// Access the WebGL rendering context
const gl = texture.context;

// Check kernel precision configuration
const precision = kernel.precision; // 'single' or 'unsigned'

Complete Inspection Example

const gpu = new GPU();

const kernel = gpu.createKernel(function() {
  return [1.0, 0.5, 0.2, 1.0];
})
.setOutput([256, 256])
.setPipeline(true); // Forces return of a Texture object

const texture = kernel();

// Dimensions
console.log('Logical Dimensions:', texture.output); // [256, 256]
console.log('Physical WebGL Size:', texture.size);   // [256, 256]

// Format / Data Type
console.log('Output Type:', texture.type);           // e.g., 'Array(4)'
console.log('Kernel Precision:', kernel.precision);  // 'single'
