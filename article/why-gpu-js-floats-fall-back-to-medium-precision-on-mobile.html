Why GPU.js Floats Fall Back to Medium Precision on Mobile

When executing compute kernels on mobile devices using GPU.js, developers frequently observe high-precision 32-bit floats (highp) degrading to 16-bit medium precision (mediump). This article explains the technical reasons behind this fallback, focusing on the underlying WebGL specifications, mobile System-on-Chip (SoC) architecture, driver implementations, and how GPU.js handles these constraints to prevent kernel crashes.

WebGL and OpenGL ES Specification Relaxations

GPU.js relies on WebGL to translate JavaScript functions into GLSL shaders. Because WebGL is based on OpenGL ES (the embedded systems specification), it is subject to the hardware-oriented trade-offs of mobile devices:

  • Optional highp in Fragment Shaders: In the WebGL 1.0 (OpenGL ES 2.0) specification, support for highp precision in the fragment shader is optional. While modern mobile devices generally implement WebGL 2.0 (OpenGL ES 3.0), the legacy behavior persists across certain low-end or older chipsets.
  • Format Querying: WebGL allows runtimes to query shader precision ranges using gl.getShaderPrecisionFormat(). If a chipset reports that highp has the same range and precision as mediump, the browser environment treats them identically.

Mobile GPU Architectural Limitations

Mobile chipsets—such as certain ARM Mali, Imagination PowerVR, and entry-level Qualcomm Adreno GPUs—are designed under strict thermal and power envelopes. Precision choices reflect these hardware realities:

Native 16-Bit ALUs

Unlike desktop GPUs that process 32-bit floating-point data (FP32) natively with minimal overhead, many mobile GPU architectures rely heavily on 16-bit floating-point units (FP16). FP16 operations require roughly half the register space, significantly less memory bandwidth, and substantially lower power consumption.

Thermal Throttling and Register Pressure

When a shader strictly demands FP32, it increases register pressure inside the mobile execution units. To avoid register spilling to off-chip memory—which drains battery life and induces severe thermal throttling—mobile architectures either limit high-precision registers or internally downcast precision.

Driver Aliasing and Emulation

Even when GLSL source code specifies precision highp float;, the underlying mobile graphics driver has the authority to alias precision qualifiers:

  1. Driver-Level Precision Lowering: Some mobile drivers silently map highp tokens directly to mediump internally to guarantee stable framerates and meet manufacturer power targets.
  2. Lack of Float Texture Render Targets: High-precision computation in GPU.js requires writing FP32 values into floating-point textures (OES_texture_float or WebGL 2 equivalents). If the mobile driver lacks native hardware support for rendering to FP32 textures, WebGL fails to attach these buffers.

How GPU.js Handles Mobile Fallbacks

GPU.js detects device capabilities during initialization before compiling kernels. When executed on an affected mobile chipset, the library takes specific mitigation steps:

  • Precision Probing: GPU.js queries the browser's WebGL context for supported extensions and shader precision capabilities.
  • Graceful Degradation: If native FP32 texturing or fragment precision is missing or unreliable, GPU.js automatically switches precision to mediump or invokes float-packing routines (encoding 32-bit floats across four 8-bit RGBA channels).
  • Crash Prevention: Without this fallback mechanism, compiling a GLSL kernel that explicitly mandates unsupported 32-bit operations would result in shader compilation errors, context loss, or completely black/empty output buffers.

Impact on Computations

The transition from FP32 to FP16 reduces the mantissa from 23 bits to 10 bits. In GPU.js applications, this manifests as:

  • Rapid accumulation of rounding errors in iterative algorithms (e.g., neural network training or matrix multiplication).
  • Severe dynamic range constraints, where values greater than 65,504 overflow to infinity, and values smaller than \(2^{-14}\) underflow to zero.
