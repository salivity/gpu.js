Cellular Automata Cave Generation with GPU.js

Cellular automata algorithms commonly used for procedural cave generation can be implemented and significantly accelerated using GPU.js. By translating JavaScript functions into WebGL shaders, GPU.js executes cellular updates across thousands of grid cells simultaneously on the graphics card. This article explains how the cellular automata method creates organic cave structures, why GPU.js is well-suited for this task, and the core implementation steps required to build performant, web-based procedural terrain.

The Cellular Automata Cave Model

Procedural cave generation typically relies on a modified version of Conway’s Game of Life, often using the "4-5 rule." The process begins by initializing a two-dimensional grid with a randomized noise pattern, where each cell has a fixed probability (usually between 40% and 45%) of being a wall.

Over several iterative steps, each cell updates its state based on the number of neighboring wall cells:

  • If a cell has 5 or more wall neighbors within a 1-tile radius, it becomes a wall.
  • If it has fewer than 4 wall neighbors, it becomes empty space.
  • If it has exactly 4, it retains its previous state.

Repeating this process over 4 to 6 iterations smooths out the random noise into coherent, organic-looking caverns, tunnels, and chambers.

Why Use GPU.js?

On a traditional CPU, cellular automata requires nested loops that iterate through every cell in the grid and check surrounding neighbors. While fast enough for small grids (such as 128x128), performance drops quickly on larger maps (such as 2048x2048 or continuous infinite generation) because execution is typically single-threaded.

Because each cell's next state depends entirely on the static state of its neighbors from the previous generation, the problem is embarrassingly parallel. GPU.js compiles written JavaScript into WebGL compute shaders, allowing thousands of cell calculations to occur concurrently across GPU cores. This yields a massive performance increase, enabling real-time generation of large-scale maps directly inside a browser environment.

Implementation Workflow

To generate caves with GPU.js, follow this computational pipeline:

  1. Grid Initialization: Create a random 2D array of integers (0 for empty space, 1 for wall) on the CPU, or write a custom GPU.js kernel to initialize random noise directly on the GPU.
  2. Kernel Definition: Write a GPU.js kernel that accepts the current grid state. Using this.thread.x and this.thread.y, the kernel inspects the eight surrounding values, calculates the neighbor sum, and outputs the next cell state using the 4-5 rule.
  3. Double Buffering (Ping-Ponging): Pass the output of the first kernel execution directly back into the kernel as the input for the next iteration. Enabling texture output mode (setPipeline(true)) ensures that data stays entirely within GPU VRAM across iterations, avoiding the costly memory transfer between the GPU and CPU.
  4. Data Retrieval: Once the iterations (usually 4–6 steps) finish, extract the final result array back to the CPU for collision handling, pathfinding, or mesh generation via algorithms like Marching Squares.

Performance Considerations

While GPU.js dramatically speeds up the simulation, developers must account for data transfer bottlenecks. Reading memory back from the GPU (kernel.getArray()) takes time. For optimal performance in games, keep the map data on the GPU as a texture for direct rendering whenever possible, and only read back localized chunks for gameplay physics and player collision logic.
