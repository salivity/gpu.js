GPU.js Dynamic Output Dimensions and Thread Indexing

This article explains how GPU.js handles thread indexing when kernel output dimensions are changed dynamically at runtime. When updating output dimensions using the setOutput() method, GPU.js recalculates the execution grid and reconfigures the underlying WebGL viewport. As a result, the internal this.thread coordinates immediately reflect the new boundaries, which alters how computational workloads, multi-dimensional coordinate mapping, and input-output memory alignments behave.

How GPU.js Handles Thread Coordinates

In GPU.js, computation is distributed across parallel threads mapped to the pixels of a WebGL output texture. The execution coordinates are accessible inside the kernel function via the this.thread object:

  • 1D Kernels: this.thread.x spans from 0 to width - 1.
  • 2D Kernels: this.thread.x spans from 0 to width - 1, and this.thread.y spans from 0 to height - 1.
  • 3D Kernels: Adds this.thread.z, spanning from 0 to depth - 1.

Under the hood, GPU.js generates fragment shaders where these integer thread coordinates are derived from the normalized texture coordinates (gl_FragCoord) and the defined output bounds.

Updating Dimensions with setOutput()

Output dimensions are not permanently locked to the values provided during kernel creation. You can modify them dynamically using the .setOutput() method on an existing kernel instance:

const kernel = gpu.createKernel(function() {
    return this.thread.x;
}).setOutput([512]);

// Dynamically updating to a new dimension
kernel.setOutput([1024]);

Calling setOutput() triggers internal state adjustments without forcing you to re-declare the kernel logic via gpu.createKernel().

Thread Indexing Behavior During Dynamic Updates

When dimensions change dynamically, thread indexing exhibits the following behaviors:

1. Instantaneous Coordinate Rescaling

The bounds of this.thread.x, this.thread.y, and this.thread.z immediately adapt to the newly assigned array. If an output is resized from [512, 512] to [1024, 256], the maximum value for this.thread.x doubles, while the maximum value for this.thread.y is halved on the very next dispatch. Threads are executed across the newly sized grid, and no threads are spawned outside the new limits.

2. Normalized Coordinate Recalculation

Because GPU.js maps output dimensions to WebGL texture coordinates (which range from 0.0 to 1.0), changing dimensions alters the scaling factor used inside the generated GLSL shader. GPU.js automatically updates the uniform values representing output dimensions, ensuring that integer conversion from gl_FragCoord accurately maps to the new integer coordinates of this.thread.

3. Independence from Input Array Dimensions

this.thread indexes strictly according to the output dimensions, not the sizes of any input arrays passed into the kernel. If output dimensions are enlarged beyond the dimensions of input buffers, accessing an input using input[this.thread.y][this.thread.x] can lead to out-of-bounds reads. In WebGL mode, reading beyond input bounds typically returns 0 or wraps around depending on texture clamp configurations, rather than throwing a runtime error.

Technical Considerations and Performance

  • Framebuffer Reallocation: When increasing or decreasing output dimensions, GPU.js must resize or recreate the underlying WebGL framebuffer and target textures. While faster than recompiling the shader, calling setOutput() repeatedly in a tight loop introduces allocation overhead and potential garbage collection pressure.
  • Pipeline Mode Impacts: If the kernel has .setPipeline(true) enabled, the returned texture adopts the new dimensions. Downstream kernels consuming this texture must account for the updated geometry, or their internal indexing logic may read distorted matrices.
  • Preservation of Dimensional Rank: When updating dimensions dynamically, maintain the same dimensional rank (e.g., keeping a 2D array [w, h] rather than switching from a 2D array to a 1D array [w]). Changing the rank dynamically can cause coordinate mapping mismatches in the compiled shader uniform logic.
