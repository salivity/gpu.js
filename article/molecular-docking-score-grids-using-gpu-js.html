Molecular Docking Score Grids Using GPU.js

This article explains how to accelerate the evaluation of molecular docking score grids for virtual ligand screening using GPU.js. Virtual screening requires scoring millions of ligand conformations against pre-calculated target protein potential grids. By offloading trilinear interpolation and per-atom energy summation to the GPU via WebGL through GPU.js, developers can achieve high-throughput docking evaluation directly within Node.js or modern web browsers without native CUDA dependencies.

Pre-Calculated Potential Grids

In grid-based docking engines like AutoDock, a target binding site is mapped inside a discrete 3D bounding box. Pre-calculated affinity grids are generated for specific probe atom types (e.g., aliphatic carbon, hydrogen-bond donors, electrostatics). Evaluating a ligand pose involves:

  1. Mapping each ligand atom's coordinates \((x, y, z)\) into the grid index space.
  2. Performing trilinear interpolation across the eight surrounding voxels on the corresponding atom-type grid to obtain the potential value.
  3. Summing the interpolated potentials across all atoms to produce the final binding score for that pose.

Structuring Grid and Ligand Data for GPU.js

GPU.js executes JavaScript-like code on the GPU by compiling it into WebGL fragment shaders. Because WebGL manages memory via textures, grid data and ligand coordinates must be flattened into structured arrays or multi-dimensional matrices.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Grid parameters
const gridDimX = 60;
const gridDimY = 60;
const gridDimZ = 60;
const gridSpacing = 0.375; // Angstroms per voxel
const gridOrigin = [10.5, -12.3, 4.2]; // (x, y, z) minimum corner

Implementing Trilinear Interpolation in GPU.js

The kernel maps floating-point coordinates inside the grid and interpolates the score. GPU.js handles 3D arrays natively, mapping the 3D potential grid directly to WebGL textures.

const evaluateLigandPose = gpu.createKernel(function(
  atomCoords, 
  atomTypes, 
  gridData, 
  gridOrigin, 
  spacing, 
  dimX, 
  dimY, 
  dimZ, 
  numAtoms
) {
  let totalScore = 0.0;

  for (let i = 0; i < numAtoms; i++) {
    // Transform world coordinates to grid coordinates
    const gx = (atomCoords[i][0] - gridOrigin[0]) / spacing;
    const gy = (atomCoords[i][1] - gridOrigin[1]) / spacing;
    const gz = (atomCoords[i][2] - gridOrigin[2]) / spacing;

    // Determine corner voxel indices
    const x0 = Math.floor(gx);
    const y0 = Math.floor(gy);
    const z0 = Math.floor(gz);
    const x1 = x0 + 1;
    const y1 = y0 + 1;
    const z1 = z0 + 1;

    // Boundary check
    if (x0 >= 0 && x1 < dimX && y0 >= 0 && y1 < dimY && z0 >= 0 && z1 < dimZ) {
      // Interpolation weights
      const xd = gx - x0;
      const yd = gy - y0;
      const zd = gz - z0;

      const type = atomTypes[i];

      // Read values at the 8 corners for the atom's grid type
      const c000 = gridData[type][z0][y0][x0];
      const c100 = gridData[type][z0][y0][x1];
      const c010 = gridData[type][z0][y1][x0];
      const c110 = gridData[type][z0][y1][x1];
      const c001 = gridData[type][z1][y0][x0];
      const c101 = gridData[type][z1][y0][x1];
      const c011 = gridData[type][z1][y1][x0];
      const c111 = gridData[type][z1][y1][x1];

      // Interpolate along x
      const c00 = c000 * (1.0 - xd) + c100 * xd;
      const c01 = c001 * (1.0 - xd) + c101 * xd;
      const c10 = c010 * (1.0 - xd) + c110 * xd;
      const c11 = c011 * (1.0 - xd) + c111 * xd;

      // Interpolate along y
      const c0 = c00 * (1.0 - yd) + c10 * yd;
      const c1 = c01 * (1.0 - yd) + c11 * yd;

      // Interpolate along z
      const atomEnergy = c0 * (1.0 - zd) + c1 * zd;
      totalScore += atomEnergy;
    } else {
      // Penalty for atoms leaving the grid bounds
      totalScore += 1000.0;
    }
  }

  return totalScore;
}).setOutput([1]); // Returns a single combined score for the pose

High-Throughput Screening across Multiple Conformations

To evaluate thousands of candidate poses concurrently, configure the kernel output dimension to match the number of poses in the screening batch:

const batchEvaluateKernel = gpu.createKernel(function(
  batchCoords, 
  atomTypes, 
  gridData, 
  gridOrigin, 
  spacing, 
  dimX, 
  dimY, 
  dimZ, 
  numAtoms
) {
  const poseIndex = this.thread.x;
  let totalScore = 0.0;

  for (let i = 0; i < numAtoms; i++) {
    const gx = (batchCoords[poseIndex][i][0] - gridOrigin[0]) / spacing;
    const gy = (batchCoords[poseIndex][i][1] - gridOrigin[1]) / spacing;
    const gz = (batchCoords[poseIndex][i][2] - gridOrigin[2]) / spacing;

    const x0 = Math.floor(gx);
    const y0 = Math.floor(gy);
    const z0 = Math.floor(gz);
    const xd = gx - x0;
    const yd = gy - y0;
    const zd = gz - z0;

    const type = atomTypes[i];

    const c000 = gridData[type][z0][y0][x0];
    const c100 = gridData[type][z0][y0][x0 + 1];
    const c010 = gridData[type][z0][y0 + 1][x0];
    const c110 = gridData[type][z0][y0 + 1][x0 + 1];
    const c001 = gridData[type][z0 + 1][y0][x0];
    const c101 = gridData[type][z0 + 1][y0][x0 + 1];
    const c011 = gridData[type][z0 + 1][y0 + 1][x0];
    const c111 = gridData[type][z0 + 1][y0 + 1][x0 + 1];

    const c00 = c000 * (1.0 - xd) + c100 * xd;
    const c01 = c001 * (1.0 - xd) + c101 * xd;
    const c10 = c010 * (1.0 - xd) + c110 * xd;
    const c11 = c011 * (1.0 - xd) + c111 * xd;

    const c0 = c00 * (1.0 - yd) + c10 * yd;
    const c1 = c01 * (1.0 - yd) + c11 * yd;

    totalScore += c0 * (1.0 - zd) + c1 * zd;
  }

  return totalScore;
}).setOutput([10000]); // Evaluates 10,000 poses in parallel

Performance Considerations

  • Pipeline Pipeline Buffers: Keep grid data bound to GPU memory across iterations. Recreating textures per evaluation severely degrades throughput.
  • Precision Limits: Standard WebGL targets 32-bit floating-point textures. Ensure GPU.js uses precision: 'single' rather than default integer clamping.
  • Memory Limits: Extremely large grids across many atom types can exceed GPU texture limits. Consolidate atom types to standard chemical subsets (e.g., generic Carbon, Aromatic Carbon, Nitrogen Donor, Nitrogen Acceptor, Oxygen, Sulfur, Electrostatics) to keep memory within hardware bounds.
