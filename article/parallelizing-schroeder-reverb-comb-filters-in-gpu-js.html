Parallelizing Schroeder Reverb Comb Filters in gpu.js

Parallelizing the comb filter feedback loops of a Schroeder reverberator across audio channels in gpu.js is entirely possible and computationally efficient. While individual Infinite Impulse Response (IIR) feedback loops are inherently sequential over time, the separate delay networks and independent audio channels in a Schroeder topology do not depend on one another. By assigning distinct audio channels and filter banks to independent GPU threads, developers can execute multiple comb filter loops concurrently using gpu.js kernels.

Understanding the Dependency Model

A classic Schroeder reverberator uses a bank of parallel feedback comb filters followed by a series of allpass filters. The discrete-time equation for a feedback comb filter is:

\[y[n] = x[n] + g \cdot y[n - D]\]

Because sample \(y[n]\) depends directly on the delayed output sample \(y[n - D]\), parallelizing a single comb filter across the time axis (\(n\)) is inefficient and requires complex parallel-scan algorithms.

However, cross-channel and cross-filter parallelism does not have this limitation:

  • Filter Independence: Each of the four or more comb filters in the bank processes the input independently.
  • Channel Independence: Channel streams (such as Left, Right, Surround, or Ambisonic channels) process their own signals without cross-talk inside the comb filter bank.

Parallelizing Across Channels in gpu.js

In gpu.js, you execute operations across multi-dimensional thread grids using WebGL compute shaders. You can map the kernel output dimensions to handle channel and filter parallelization simultaneously.

Performance and Architecture Considerations

Memory Transfers and Latency

While gpu.js accelerates parallel processing, moving sample buffers between the CPU (RAM) and GPU (VRAM) creates measurable overhead. For standard real-time low-latency stereo audio (e.g., 128-sample buffer sizes in standard Web Audio contexts), the bus transfer latency often outweighs GPU compute gains.

Scaling Thresholds

GPU parallelization becomes advantageous under specific conditions:

  • High Channel Counts: Multichannel setups such as 7.1.4 Dolby Atmos, higher-order ambisonics, or spatial audio installations with dozens of concurrent sources.
  • Offline Rendering: Batch processing large audio files or pre-rendering impulse responses.
  • Massive Filter Banks: Extended reverberator designs containing dozens or hundreds of parallel feedback loops rather than the classic 4-comb configuration.

Using gpu.js for Schroeder comb filter banks is architecturally sound across channels and filter indices. The key to maintaining high throughput is ensuring each thread computes the time-series feedback loop internally, avoiding fine-grained synchronization across time steps.
