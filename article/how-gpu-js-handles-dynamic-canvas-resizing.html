How GPU.js Handles Dynamic Canvas Resizing

GPU.js does not automatically adapt its rendering canvas or internal WebGL viewport when the browser window geometry changes. Because GPU.js kernels rely on fixed dimensional arrays defined during initialization, handling dynamic canvas resizing requires developers to manually listen for window resize events, synchronize the HTML canvas element's buffer resolution, and update the kernel's execution dimensions using the setOutput API.

Static Dimension Architecture in GPU.js

When creating a kernel in GPU.js, you define an output configuration via the setOutput([width, height]) method or options object. GPU.js compiles this configuration into WebGL shaders and maps the output directly to a WebGL texture or a <canvas> element.

By default, this bound dimension is static. If the browser window changes size or the layout shifts, the underlying canvas may stretch via CSS scaling, leading to blurred or distorted graphics, or it may clip the output entirely if CSS dimensions do not match the canvas drawing buffer.

Synchronizing Canvas Dimensions with Window Changes

To handle window geometry changes properly without distortion, you must establish an event listener that captures dynamic resizing and propagates the changes back to GPU.js.

  1. Detect the Change: Use window.addEventListener('resize', callback) or a ResizeObserver attached to the canvas wrapper to capture changes in the viewport or layout.
  2. Update the Drawing Buffer: Update the actual width and height attributes of the canvas element rather than altering only its CSS styling. Setting canvas.width = window.innerWidth adjusts the WebGL drawing buffer resolution.
  3. Reconfigure the Kernel Output: GPU.js provides the .setOutput([width, height]) method directly on the compiled kernel instance. Call this method with the new dimensions so the internal WebGL viewport aligns with the updated canvas bounds.
  4. Re-execute the Kernel: Run the kernel with the updated dimensions to redraw the scene across the expanded or contracted pixel grid.
const gpu = new GPU();

// Create a kernel rendering directly to a canvas
const renderKernel = gpu.createKernel(function() {
  const x = this.thread.x / this.output.x;
  const y = this.thread.y / this.output.y;
  this.color(x, y, 0.5, 1);
})
.setOutput([window.innerWidth, window.innerHeight])
.setGraphical(true);

const canvas = renderKernel.canvas;
document.body.appendChild(canvas);

// Dynamic resize handler
function handleResize() {
  const width = window.innerWidth;
  const height = window.innerHeight;

  // Update canvas buffer dimensions
  canvas.width = width;
  canvas.height = height;

  // Update kernel output dimensions and re-render
  renderKernel.setOutput([width, height]);
  renderKernel();
}

window.addEventListener('resize', handleResize);
renderKernel();

Performance and Lifecycle Considerations

Repeatedly resizing a WebGL context can trigger expensive texture reallocations and buffer rebinding inside GPU.js. When implementing dynamic resizing, wrap the resize callback inside a debounce or throttle mechanism using requestAnimationFrame. This prevents the kernel from reallocating buffers on every individual pixel shift during continuous window dragging, ensuring smooth frame rates and preventing memory spikes.
