GPU.js SubKernels: Returning Multiple Outputs

This article explains how the subKernels feature in GPU.js enables a single kernel execution to return multiple distinct outputs simultaneously. It covers the technical mechanics behind this feature, how to implement it using createKernelMap, and why it significantly improves performance over executing multiple individual kernels.

The Single-Output Limitation

Standard GPU.js kernels return only one value per thread, mapping directly to a single output matrix or array. In complex simulations, physics engines, or image processing pipelines, a single coordinate or thread often needs to compute multiple related values—such as position, velocity, and force. Executing multiple separate kernels to calculate each property introduces redundant memory transfers and repeated intermediate calculations.

How subKernels Work

The subKernels feature circumvents this limitation by leveraging Multiple Render Targets (MRT) under the hood in WebGL. Instead of outputting to a single color attachment in a framebuffer, the underlying GLSL fragment shader is configured to write to multiple output textures concurrently within the same execution pass.

To utilize this, GPU.js provides the createKernelMap method. You define sub-functions (sub-kernels) that handle each specific calculation, and then invoke them from the primary kernel function.

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Define subKernels inside createKernelMap
const multiOutputKernel = gpu.createKernelMap({
  addResult: function add(a, b) {
    return a[this.thread.x] + b[this.thread.x];
  },
  multiplyResult: function multiply(a, b) {
    return a[this.thread.x] * b[this.thread.x];
  }
}, function(a, b) {
  add(a, b);
  return multiply(a, b);
}).setOutput([5]);

const a = [1, 2, 3, 4, 5];
const b = [10, 20, 30, 40, 50];

const results = multiOutputKernel(a, b);
console.log(results.addResult);      // [11, 22, 33, 44, 55]
console.log(results.result);         // [10, 40, 90, 160, 250] (primary return)

Execution and Return Structure

When createKernelMap executes:

  1. Mapping to Render Buffers: GPU.js registers each declared sub-kernel as a distinct output target mapped to a dedicated GPU texture.
  2. Synchronized Computation: As each thread executes, any call to a sub-kernel writes that sub-kernel's return value directly to its assigned texture at the thread's active index (this.thread.x, this.thread.y, etc.).
  3. Structured Object Return: Instead of returning a flat array or 2D matrix, the kernel returns an object. The properties of this object match the keys defined in the kernel map, while the primary function return is stored in the result property.

Performance Advantages

Using subKernels provides two major optimizations:

  • Elimination of Redundant Dispatches: Launching a kernel incurs CPU-to-GPU dispatch overhead. Consolidating outputs into one pass reduces draw calls.
  • Shared Intermediate Values: Expensive shared calculations can be performed once per thread and used across multiple sub-kernel outputs, bypassing the need to store and reread intermediate data across distinct passes.
