Hydraulic Erosion on Heightmaps with GPU.js

This article details how to implement real-time hydraulic erosion on 2D heightmap terrains using GPU.js. It covers setting up grid-based simulation data, executing hydrodynamic kernels across GPU threads to calculate water flow and sediment transport, and optimizing read-write cycles using textures to achieve fast terrain generation in a browser or Node.js environment.

1. Heightmap Representation and Pipeline Architecture

Hydraulic erosion over heightmaps on a GPU is most efficiently implemented using a grid-based shallow water model rather than independent droplet particles. This avoids race conditions inherent to parallel droplet writes.

The simulation maintains four primary floating-point 2D grids of identical dimensions (\(W \times H\)):

  • Terrain Height (\(T\)): The base elevation of the bedrock.
  • Water Depth (\(W\)): The layer of water resting on top of the terrain.
  • Sediment (\(S\)): The suspended sediment carried by the water.
  • Outflow Flux (\(F\)): A 4-channel grid (Left, Right, Top, Bottom) tracking directional water movement.
const { GPU } = require('gpu.js');
const gpu = new GPU();

const width = 512;
const height = 512;

2. The Four Simulation Kernels

The simulation loop executes four sequential stages per iteration: water arrival, flow simulation, erosion/deposition, and sediment advection followed by evaporation.

Step A: Water Addition

Water is added uniformly across the map to simulate rainfall:

const addRainKernel = gpu.createKernel(function(waterMap, rainRate) {
    return waterMap[this.thread.y][this.thread.x] + rainRate;
})
.setOutput([width, height])
.setPipeline(true);

Step B: Outflow Flux Calculation

Water flows toward lower adjacent cells based on hydrostatic pressure. The kernel calculates the difference between the total height (terrain + water) of the current cell and its four neighbors, updating outflow fluxes:

const calculateFluxKernel = gpu.createKernel(function(terrain, water, flux, dt) {
    const x = this.thread.x;
    const y = this.thread.y;
    const h = terrain[y][x] + water[y][x];

    // Read neighbor total heights with boundary clamping
    const hL = terrain[y][Math.max(0, x - 1)] + water[y][Math.max(0, x - 1)];
    const hR = terrain[y][Math.min(511, x + 1)] + water[y][Math.min(511, x + 1)];
    const hT = terrain[Math.min(511, y + 1)][x] + water[Math.min(511, y + 1)][x];
    const hB = terrain[Math.max(0, y - 1)][x] + water[Math.max(0, y - 1)][x];

    const dL = Math.max(0, h - hL);
    const dR = Math.max(0, h - hR);
    const dT = Math.max(0, h - hT);
    const dB = Math.max(0, h - hB);

    let fL = Math.max(0, flux[y][x][0] + dt * dL);
    let fR = Math.max(0, flux[y][x][1] + dt * dR);
    let fT = Math.max(0, flux[y][x][2] + dt * dT);
    let fB = Math.max(0, flux[y][x][3] + dt * dB);

    const sumFlux = fL + fR + fT + fB;
    const currentWater = water[y][x];

    if (sumFlux > 0) {
        const scale = Math.min(1.0, currentWater / (sumFlux * dt));
        fL *= scale;
        fR *= scale;
        fT *= scale;
        fB *= scale;
    }

    this.color(fL, fR, fT, fB);
})
.setOutput([width, height])
.setPipeline(true);

Step C: Water and Velocity Updates

Update water levels according to inflow and outflow, deriving the local velocity vector \((\vec{u}_x, \vec{u}_y)\):

const updateWaterKernel = gpu.createKernel(function(water, flux, dt) {
    const x = this.thread.x;
    const y = this.thread.y;

    const fSelf = flux[y][x];
    const fL = flux[y][Math.max(0, x - 1)][1]; // Inflow from left neighbor's right flux
    const fR = flux[y][Math.min(511, x + 1)][0]; // Inflow from right neighbor's left flux
    const fB = flux[Math.max(0, y - 1)][x][2]; // Inflow from bottom neighbor's top flux
    const fT = flux[Math.min(511, y + 1)][x][3]; // Inflow from top neighbor's bottom flux

    const inFlux = fL + fR + fB + fT;
    const outFlux = fSelf[0] + fSelf[1] + fSelf[2] + fSelf[3];
    
    return Math.max(0, water[y][x] + (inFlux - outFlux) * dt);
})
.setOutput([width, height])
.setPipeline(true);

Step D: Erosion, Deposition, and Transport

Compute terrain modification based on sediment capacity \(C\). The capacity is proportional to local tilt angle and flow velocity. If the carried sediment \(S\) is lower than \(C\), a portion of the bedrock dissolves into the water; if \(S > C\), the excess sediment deposits onto the terrain:

const erodeAndDepositKernel = gpu.createKernel(function(terrain, sediment, water, dt, K_erode, K_deposit, capacityFactor) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Height differential for slope estimation
    const slope = Math.abs(terrain[y][Math.min(511, x + 1)] - terrain[y][Math.max(0, x - 1)]) +
                  Math.abs(terrain[Math.min(511, y + 1)][x] - terrain[Math.max(0, y - 1)][x]);

    const c = Math.max(0.01, slope) * water[y][x] * capacityFactor;
    const currentSediment = sediment[y][x];

    let newTerrain = terrain[y][x];
    let newSediment = currentSediment;

    if (currentSediment < c) {
        const eroded = K_erode * (c - currentSediment) * dt;
        newTerrain -= eroded;
        newSediment += eroded;
    } else {
        const deposited = K_deposit * (currentSediment - c) * dt;
        newTerrain += deposited;
        newSediment -= deposited;
    }

    this.color(newTerrain, newSediment, 0, 1);
})
.setOutput([width, height])
.setPipeline(true);

3. Execution Loop and Performance Best Practices

To avoid CPU-GPU transfer bottlenecks:

  1. Enable .setPipeline(true): This keeps computation results in WebGL texture memory between iterations rather than copying data back to JavaScript typed arrays.
  2. Ping-Pong Textures: Alternate between read and write textures in successive frames to ensure thread safety without creating new allocations.
  3. Download Selectively: Only call .toArray() or output directly to a WebGL canvas once the full simulation cycle (typically 50 to 500 iterations) completes.
