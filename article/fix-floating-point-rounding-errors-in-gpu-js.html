Fix Floating-Point Rounding Errors in gpu.js

Accumulating large sets of numbers using gpu.js frequently leads to floating-point precision loss and rounding errors due to hardware-level limitations. Because WebGL and gpu.js primarily operate using 32-bit single-precision floating-point numbers (IEEE 754 standard), adding small numbers to an increasingly large sum drops the least significant bits. This article explains why floating-point rounding errors happen in gpu.js and outlines the most effective techniques to prevent them, including Kahan summation, parallel tree reduction, and fixed-point arithmetic.

The Cause of Summation Drift in GPU Kernels

Single-precision floats dedicate 1 bit to the sign, 8 bits to the exponent, and 23 bits to the mantissa (significand), which offers roughly 7 decimal digits of precision. When a loop in a GPU kernel iteratively adds small numbers to an accumulator, the magnitude of the accumulator grows. Eventually, the smaller values are shifted out of the 23-bit significand before addition, causing catastrophic cancellation or complete omission of small numbers.

Because standard WebGL pipelines often lack native 64-bit double-precision support, you must handle precision issues through software-level algorithms.

Method 1: Kahan Compensated Summation

The Kahan summation algorithm significantly reduces numerical error when accumulating sequential arrays inside a single kernel thread. It uses a secondary running variable to store the low-order bits lost during the addition, reintroducing them into the next iteration.

Below is an implementation of Kahan summation inside a gpu.js kernel:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const kahanSumKernel = gpu.createKernel(function(data, length) {
  let sum = 0.0;
  let c = 0.0; // Compensation variable for lost precision

  for (let i = 0; i < length; i++) {
    let y = data[i] - c;
    let t = sum + y;
    c = (t - sum) - y;
    sum = t;
  }

  return sum;
}).setOutput([1]);

const numbers = new Float32Array([100000.0, 0.00001, 0.00002, 0.00003]);
const result = kahanSumKernel(numbers, numbers.length);

While Kahan summation minimizes error inside a single thread's sequential loop, it does not take full advantage of GPU parallelization.

Method 2: Parallel Reduction (Tree Summation)

Instead of summing elements sequentially on a single thread, parallel reduction divides the dataset into pairs and sums them concurrently across multiple passes.

Tree reduction limits rounding errors by ensuring numbers of comparable magnitudes are added together. It also maximizes throughput by distributing the workload across thousands of GPU cores.

  1. Kernel Pass: Each thread sums two adjacent elements or chunks.
  2. Intermediate Output: The output size is halved on each pass.
  3. Loop: Re-run the kernel iteratively until only a single scalar value remains.
const gpu = new GPU();

// Kernel to halve the array size per pass
const reduceKernel = gpu.createKernel(function(array, step) {
  const i = this.thread.x;
  return array[i * 2] + array[i * 2 + 1];
});

function parallelSum(data) {
  let currentArray = data;
  let length = currentArray.length;

  while (length > 1) {
    reduceKernel.setOutput([length / 2]);
    currentArray = reduceKernel(currentArray, length);
    length = length / 2;
  }

  return currentArray[0];
}

By balancing the tree of additions, the maximum error grows logarithmically (\(O(\log N)\)) rather than linearly (\(O(N)\)).

Method 3: Fixed-Point Arithmetic

If the values have a known, bounded number of decimal places (such as currency or sensor measurements), convert the inputs to integers before loading them into the GPU.

Integer addition is exact within its range and avoids fractional rounding drift:

  1. Multiply floating-point inputs by a scaling factor (e.g., 1000 for three decimal places) on the CPU.
  2. Accumulate the integers using 32-bit signed or unsigned integers inside the gpu.js kernel.
  3. Divide the final accumulated result by the scaling factor when reading the data back to the CPU.

Ensure the final accumulated sum does not exceed \(2^{31} - 1\) (\(2,147,483,647\)) to prevent integer overflow.

Choosing the Right Approach

  • Use Parallel Reduction when processing large arrays (thousands to millions of elements) where performance and stability are equally critical.
  • Use Kahan Summation when you must process data sequentially within individual worker threads or cannot afford multi-pass kernel calls.
  • Use Fixed-Point Scaling when dealing with low-decimal, high-accuracy requirements where fractional errors cannot be tolerated.
