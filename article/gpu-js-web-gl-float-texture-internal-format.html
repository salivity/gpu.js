GPU.js WebGL Float Texture Internal Format

This article examines the internal WebGL pixel formats selected by gpu.js when rendering and outputting 2D floating-point textures. It details the underlying texture allocation mechanisms across both WebGL 1 and WebGL 2 environments, explaining how precision settings dictate the exact OpenGL texture targets, formats, and channel layouts used during GPU execution.

WebGL 2 Context: Sized Internal Formats

In a modern WebGL 2 context, gpu.js utilizes sized internal formats to allocate high-precision floating-point textures. When running a kernel configured with precision: 'single' that outputs 2D float data, gpu.js selects:

  • Internal Format: gl.RGBA32F
  • Format: gl.RGBA
  • Type: gl.FLOAT

WebGL 2 natively supports sized internal formats, and gpu.js relies on four-channel allocations (RGBA32F) for its primary compute pipeline rather than single-channel formats like R32F. This design decision maintains unified texture memory management across multi-value returns, matrices, and internal pipelines where 32-bit floats are stored in each color component.

WebGL 1 Context: Unsized Internal Formats

In environments limited to WebGL 1, sized formats such as gl.RGBA32F are unavailable in the core specification. To achieve floating-point output, gpu.js requires the OES_texture_float (and often WEBGL_color_buffer_float) extension. Under this backend, gpu.js specifies:

  • Internal Format: gl.RGBA
  • Format: gl.RGBA
  • Type: gl.FLOAT

In WebGL 1, the internalFormat argument in gl.texImage2D must match the format parameter. As a result, the internal format remains unsized (gl.RGBA), but the GPU assigns 32-bit floating-point precision per channel because the data type parameter is explicitly set to gl.FLOAT.

Fallback Behavior: Unsigned Byte Encoding

If a hardware device or browser environment does not support floating-point render targets, or if precision: 'unsigned' is configured, gpu.js alters its texture output strategy. Instead of relying on raw floating-point textures, it uses:

  • Internal Format: gl.RGBA
  • Format: gl.RGBA
  • Type: gl.UNSIGNED_BYTE

Under this fallback mechanism, 32-bit floating-point numbers are mathematically encoded (packed) across the four 8-bit channels (\(R, G, B, A\)) inside the fragment shader and decoded upon CPU retrieval or subsequent kernel reads.
