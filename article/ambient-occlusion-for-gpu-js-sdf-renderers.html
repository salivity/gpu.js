Ambient Occlusion for GPU.js SDF Renderers

This article provides an implementation guide for integrating ambient occlusion (AO) approximations into a Signed Distance Field (SDF) raymarcher using GPU.js. By utilizing the geometric properties inherent to distance fields, realistic contact shadows and soft ambient lighting can be calculated in real time without the computational cost of secondary ray casts. Below, you will find the mathematical foundation of SDF-based ambient occlusion, the implementation details adapted for GPU.js's JavaScript-to-WebGL compiler, and the complete kernel logic required to render the effect in the browser.

The SDF Ambient Occlusion Principle

In standard raymarching, finding the distance to the closest surface at any point in space is done via a Signed Distance Function (SDF). To compute ambient occlusion at a hit point, you do not need to cast stochastic rays across the hemisphere. Instead, you sample the SDF at fixed intervals along the surface normal vector.

If a point is in open space, the measured distance to the scene will match the distance traveled along the normal. If geometry curves inward or another surface is nearby, the scene's distance field will return a value smaller than the distance traveled. The discrepancy between the sampling distance and the actual distance returned by the SDF indicates the level of occlusion:

\[AO = 1.0 - \sum_{i=1}^{k} w_i \cdot (d_i - \text{SDF}(p + n \cdot d_i))\]

Where:

  • \(p\) is the surface point.
  • \(n\) is the surface normal.
  • \(d_i\) is the sampling distance for step \(i\).
  • \(w_i\) is a weight factor that decreases with distance, ensuring nearby occluders cast darker shadows.

GPU.js Constraints and Considerations

GPU.js compiles a subset of JavaScript into WebGL GLSL shaders. Because it does not support native GLSL vector types (vec3, vec4) natively in arbitrary user-defined structures without array allocations, vector operations are best handled either as flat arrays or broken down into explicit scalar variables (x, y, z) to maintain peak performance and avoid allocation overhead inside loops.

Implementing the Kernel Functions

1. The Distance Estimator

Define the scene using an SDF. For example, a sphere on top of a ground plane:

function sceneSDF(x, y, z) {
  // Sphere: center at (0, 1, 0), radius 1.0
  const sphereDist = Math.sqrt(x * x + (y - 1.0) * (y - 1.0) + z * z) - 1.0;
  // Plane: at y = 0
  const planeDist = y;
  return Math.min(sphereDist, planeDist);
}

2. Estimating Surface Normals

The surface normal is the gradient of the SDF at the hit point, calculated via finite differences:

function getNormalX(x, y, z) {
  const eps = 0.001;
  return (sceneSDF(x + eps, y, z) - sceneSDF(x - eps, y, z));
}
function getNormalY(x, y, z) {
  const eps = 0.001;
  return (sceneSDF(x, y + eps, z) - sceneSDF(x, y - eps, z));
}
function getNormalZ(x, y, z) {
  const eps = 0.001;
  return (sceneSDF(x, y, z + eps) - sceneSDF(x, y, z - eps));
}

3. The Ambient Occlusion Approximation Function

Sample along the normal using a fixed number of steps (typically 4 to 5). Accumulate the difference between the expected distance and the SDF sample:

function calculateAO(pX, pY, pZ, nX, nY, nZ) {
  let occ = 0.0;
  let weight = 1.0;
  const stepSize = 0.15;
  
  // Normalize the normal vector
  const len = Math.sqrt(nX * nX + nY * nY + nZ * nZ);
  const normX = nX / len;
  const normY = nY / len;
  const normZ = nZ / len;

  for (let i = 1; i <= 5; i++) {
    const dist = i * stepSize;
    // Step out along the normal
    const sampleX = pX + normX * dist;
    const sampleY = pY + normY * dist;
    const sampleZ = pZ + normZ * dist;

    const sceneDist = sceneSDF(sampleX, sampleY, sampleZ);
    occ += (dist - sceneDist) * weight;
    weight *= 0.5; // Diminish influence of farther samples
  }

  // Clamp occlusion factor to [0.0, 1.0] and invert
  const ao = 1.0 - (1.5 * occ);
  if (ao < 0.0) return 0.0;
  if (ao > 1.0) return 1.0;
  return ao;
}

Integrating AO into the Main Render Kernel

Combine the primary raymarching loop, normal evaluation, and AO function inside the GPU.js kernel initialization:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Register helper functions
gpu.addFunction(sceneSDF);
gpu.addFunction(getNormalX);
gpu.addFunction(getNormalY);
gpu.addFunction(getNormalZ);
gpu.addFunction(calculateAO);

const renderKernel = gpu.createKernel(function(cameraX, cameraY, cameraZ) {
  // Screen space coordinates normalized from -1.0 to 1.0
  const u = (this.thread.x / this.output.x) * 2.0 - 1.0;
  const v = (this.thread.y / this.output.y) * 2.0 - 1.0;

  // Simple ray generation
  let rayDirX = u;
  let rayDirY = v;
  let rayDirZ = 1.0;
  const rayLen = Math.sqrt(rayDirX * rayDirX + rayDirY * rayDirY + rayDirZ * rayDirZ);
  rayDirX /= rayLen;
  rayDirY /= rayLen;
  rayDirZ /= rayLen;

  let totalDist = 0.0;
  const maxDist = 50.0;
  let hit = 0;

  let currentX = cameraX;
  let currentY = cameraY;
  let currentZ = cameraZ;

  // Primary raymarch
  for (let step = 0; step < 64; step++) {
    const d = sceneSDF(currentX, currentY, currentZ);
    if (d < 0.001) {
      hit = 1;
      break;
    }
    totalDist += d;
    if (totalDist > maxDist) break;

    currentX = cameraX + rayDirX * totalDist;
    currentY = cameraY + rayDirY * totalDist;
    currentZ = cameraZ + rayDirZ * totalDist;
  }

  if (hit === 1) {
    const normX = getNormalX(currentX, currentY, currentZ);
    const normY = getNormalY(currentX, currentY, currentZ);
    const normZ = getNormalZ(currentX, currentY, currentZ);

    const ao = calculateAO(currentX, currentY, currentZ, normX, normY, normZ);

    // Apply basic directional lighting modulated by AO
    const lightDirX = 0.577;
    const lightDirY = 0.577;
    const lightDirZ = -0.577;
    
    const diff = Math.max(0.0, normX * lightDirX + normY * lightDirY + normZ * lightDirZ);
    const ambient = 0.2;
    const lighting = (ambient + diff * 0.8) * ao;

    this.color(lighting, lighting, lighting, 1.0);
  } else {
    // Background color
    this.color(0.05, 0.05, 0.08, 1.0);
  }
})
.setOutput([800, 600])
.setGraphical(true);

Tuning and Performance Tips

  • Step Size (stepSize): Defines the spatial scale of the contact shadows. Smaller values (e.g., 0.05) create tight crevices and creases, while larger values (e.g., 0.3) create broader, softer environmental shadowing.
  • Intensity Multiplier: Adjusting the multiplier on occ (set to 1.5 in calculateAO) increases or decreases shadow contrast.
  • Step Count: 4 to 5 iterations provide a balance between visual fidelity and frame rate. Since this loop runs per-pixel on geometry hits, keeping the step count low is necessary for consistent 60 FPS performance in WebGL.
