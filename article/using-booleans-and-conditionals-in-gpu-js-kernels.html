Using Booleans and Conditionals in GPU.js Kernels

GPU.js allows developers to pass boolean flags and execute conditional logic within kernels, translating standard JavaScript syntax directly into WebGL shader code. While booleans can be passed cleanly as kernel arguments or evaluated through standard if/else statements, developers must understand how GPU architecture handles branching to maintain optimal performance.

Passing Booleans into Kernels

GPU.js natively supports passing standard JavaScript boolean values (true and false) directly as arguments to a compiled kernel function. When compiled to WebGL shaders, these values are mapped to GLSL boolean uniforms. Alternatively, numeric representations (1 and 0) are commonly used for stricter type alignment with graphical pipelines.

const gpu = new GPU();

const kernel = gpu.createKernel(function(data, useMultiplier) {
    let val = data[this.thread.x];
    if (useMultiplier) {
        return val * 2;
    } else {
        return val + 10;
    }
}).setOutput([512]);

// Execution
const result = kernel([1, 2, 3, 4], true);

Supported Conditional Syntax

Inside a GPU.js kernel, standard JavaScript branching syntax is fully functional:

  • if / else if / else statements: Transpiles cleanly into GLSL conditional blocks.
  • Ternary operators: condition ? valueIfTrue : valueIfFalse works efficiently for inline evaluations.
  • Logical operators: Standard operators (&&, ||, !) can be used to construct complex conditions.

The Performance Impact of Branch Divergence

While the syntax is clean and familiar, execution behavior on the GPU differs fundamentally from the CPU due to the Single Instruction, Multiple Threads (SIMT) architecture:

  1. Uniform Branching (Fast): When a boolean flag is passed as a global kernel argument, every thread in the execution grid takes the exact same execution path. Modern GPU hardware handles this type of uniform branching with virtually zero performance overhead.
  2. Divergent Branching (Slow): When conditional logic depends on thread-specific data (such as this.thread.x % 2 === 0), adjacent threads may take different paths. In this scenario, the GPU must serialize the execution of both paths across the warp or workgroup, masking out inactive threads and effectively halving computation throughput.

Best Practices

  • Use Global Flags for Features: Use boolean arguments to toggle modes, calculation styles, or debug logging across the entire dataset.
  • Avoid Nested, Thread-Dependent Branches: Keep per-thread conditional checks shallow to minimize thread serialization.
  • Compile Specialized Kernels: If a boolean flag is known ahead of time and changes infrequently, consider compiling two distinct kernels rather than using a runtime conditional check, entirely eliminating runtime evaluation.
