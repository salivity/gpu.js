How GPU.js Handles Nullish Coalescing Operators

This article explains how GPU.js processes the JavaScript nullish coalescing operator (??) when encountered within kernel functions. GPU.js translates JavaScript functions into WebGL GLSL shaders via Abstract Syntax Tree (AST) parsing. Because GLSL operates on statically typed primitives that lack concepts of null or undefined, GPU.js cannot translate the nullish coalescing operator, resulting in compile-time errors unless managed beforehand.

The AST Translation Pipeline

GPU.js relies on an internal AST parser (such as Acorn) to convert JavaScript kernel code into equivalent GLSL (OpenGL Shading Language) code executed on the GPU. During this compilation step, the parser traverses expressions and maps JavaScript operators directly to their GLSL counterparts.

Binary and logical expressions such as +, -, *, /, &&, and || map directly to standard GLSL arithmetic and boolean logic. However, the parser must recognize each specific operator node to generate valid shader strings.

Why ?? Fails in Kernel Code

The nullish coalescing operator (??) specifically tests whether the left-hand operand evaluates to null or undefined. In GPU execution contexts:

  1. Lack of null and undefined in GLSL: WebGL GLSL is a strictly typed language where variables represent floats, integers, booleans, or vectors. There is no concept of dynamic reference types, null, or uninitialized undefined states.
  2. Missing AST Visitor Rule: The GPU.js AST compiler does not implement a translation rule for the ?? operator. When the parser encounters a LogicalExpression with operator: "??", it fails to map the token to a valid GLSL construct, throwing a compilation error such as Unhandled operator ?? or an unsupported syntax exception.

The Effect of Transpilation

If code is processed through build tools like Babel or TypeScript before being passed into GPU.js, a ?? b is often converted to:

a !== null && a !== void 0 ? a : b

While this replaces the operator, GPU.js will still fail to compile the resulting expression into GLSL because void 0 and strict comparison to null are also invalid in the GLSL shader generation pipeline.

Proper Workarounds

To use fallback logic inside a GPU.js kernel, code must be adapted to conform to GLSL-compatible types:

  • Resolve Defaults on the CPU: Handle nullish checks in JavaScript prior to passing data arrays, textures, or constants into the kernel.
  • Use Numeric Sentinels: Designate specific numerical values (such as -1.0, 0.0, or NaN) to represent missing data, and branch using standard ternary operators or if statements:
const kernel = gpu.createKernel(function(values) {
    const val = values[this.thread.x];
    // Use -1.0 as a sentinel value instead of null/undefined
    const resolved = (val === -1.0) ? 0.0 : val;
    return resolved;
}).setOutput([100]);
