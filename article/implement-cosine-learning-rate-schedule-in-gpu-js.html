Implement Cosine Learning Rate Schedule in GPU.js

This article demonstrates how to implement a cosine annealing learning rate schedule within a machine learning orchestration loop using GPU.js. You will explore the mathematical formulation of cosine decay, learn how to integrate dynamic scalar hyperparameter updates into parallelized GPU execution, and implement a clean, high-performance training loop in JavaScript.

Understanding the Cosine Learning Rate Schedule

The cosine annealing schedule adjusts the learning rate \(\eta_t\) at any given step \(t\) between a maximum learning rate (\(\eta_{max}\)) and a minimum target (\(\eta_{min}\)) across total steps \(T\):

\[\eta_t = \eta_{min} + \frac{1}{2} (\eta_{max} - \eta_{min}) \left(1 + \cos\left(\frac{t}{T} \pi\right)\right)\]

This approach provides smooth, gradual warm-down transitions without requiring abrupt step drops.

Architectural Approach with GPU.js

When orchestrating a training pipeline with GPU.js, learning rate calculations are scalar operations. Computing a single scalar per iteration directly inside a massively parallel GPU kernel introduces unnecessary dispatch overhead.

The most efficient architecture uses a hybrid approach:

  1. CPU Execution: Compute the dynamic learning rate scalar inside the JavaScript orchestration loop per batch or epoch.
  2. GPU Execution: Pass the calculated learning rate as a dynamic argument to the GPU.js weight-update kernel, which executes the element-wise weight and gradient calculations in parallel on the GPU.

Step-by-Step Implementation

1. Define the Weight Update Kernel

Create a GPU.js kernel that accepts the current weights, calculated gradients, and the updated learning rate scalar to perform gradient descent updates in parallel.

import { GPU } from 'gpu.js';

const gpu = new GPU();

const updateWeightsKernel = gpu.createKernel(function(weights, gradients, learningRate) {
    return weights[this.thread.x] - (learningRate * gradients[this.thread.x]);
}).setOutput([1000]); // Matches parameter vector length

2. Define the Cosine Calculation Function

Implement a helper function to determine the learning rate for any step in the schedule.

function getCosineLearningRate(currentStep, totalSteps, baseLr, minLr = 0.0) {
    if (currentStep >= totalSteps) {
        return minLr;
    }
    const decayRatio = currentStep / totalSteps;
    const cosineDecay = 0.5 * (1 + Math.cos(Math.PI * decayRatio));
    return minLr + (baseLr - minLr) * cosineDecay;
}

3. Build the Orchestration Loop

Integrate the scheduler calculation into the main training iteration. The loop updates the learning rate at each step and dispatches the execution to the GPU kernel.

// Hyperparameters
const totalSteps = 1000;
const baseLr = 0.01;
const minLr = 0.0001;
const parameterCount = 1000;

// Initialize mock weights and gradients
let weights = new Float32Array(parameterCount).fill(0.5);
let gradients = new Float32Array(parameterCount).fill(0.01);

// Orchestration Loop
for (let step = 0; step < totalSteps; step++) {
    // 1. Calculate dynamic learning rate on the CPU
    const currentLr = getCosineLearningRate(step, totalSteps, baseLr, minLr);

    // 2. Dispatch the update kernel to the GPU
    weights = updateWeightsKernel(weights, gradients, currentLr);

    // 3. Periodic logging
    if (step % 100 === 0 || step === totalSteps - 1) {
        console.log(`Step ${step} | Learning Rate: ${currentLr.toFixed(6)} | Sample Weight: ${weights[0].toFixed(5)}`);
    }
}

Performance Considerations

  • Memory Transfers: Re-allocating typed arrays on each iteration causes GPU-to-CPU transfer bottlenecks. To maximize throughput, use updateWeightsKernel.setPipeline(true) when chaining multiple operations, keeping the updated weights inside GPU memory between iterations.
  • Warm Restarts: To implement Cosine Annealing with Warm Restarts (SGDR), reset the currentStep counter back to zero periodically according to your restart interval \(T_i\).
