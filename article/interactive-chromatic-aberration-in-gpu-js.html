Interactive Chromatic Aberration in gpu.js

Dynamic chromatic aberration can be implemented as an interactive post-processing effect in gpu.js. By translating JavaScript logic into WebGL shaders, gpu.js allows developers to execute per-pixel image manipulation directly on the graphics card. This article explains how chromatic aberration works digitally, how to structure a gpu.js kernel to achieve the effect, and how to drive the visual distortion interactively using dynamic input parameters such as mouse coordinates, time, or custom uniforms.

How Digital Chromatic Aberration Works

Chromatic aberration simulates a real-world lens defect where different wavelengths of light fail to focus on the exact same focal point. In computer graphics and 2D post-processing, this effect is recreated by decoupling the red, green, and blue color channels of an image and sampling them at slightly different spatial coordinates.

When a channel is offset horizontally, vertically, or radially away from the center of the image, visible color fringing occurs at high-contrast edges.

Implementing the Effect in gpu.js

To run chromatic aberration in gpu.js, you configure a kernel that takes an existing canvas or image as an input texture, reads the pixel data, applies a coordinate offset to individual channels, and writes the composite result to an output canvas.

1. Setting Up the Kernel

The kernel must be created with graphical: true so it can output directly to a WebGL canvas. The dimensions of the kernel should match the resolution of your source image or screen buffer.

const gpu = new GPU();

const chromaticAberrationKernel = gpu.createKernel(function(image, shiftX, shiftY) {
    const x = this.thread.x;
    const y = this.thread.y;

    // Sample Red channel with a negative offset
    const pixelR = image[y - shiftY][x - shiftX];
    
    // Sample Green channel at original coordinates
    const pixelG = image[y][x];
    
    // Sample Blue channel with a positive offset
    const pixelB = image[y + shiftY][x + shiftX];

    this.color(pixelR[0], pixelG[1], pixelB[2], 1.0);
})
.setOutput([width, height])
.setGraphical(true);

2. Making the Effect Interactive

To make the effect dynamic, the offset values (shiftX and shiftY) can be tied to user input inside an animation or event loop:

  • Mouse Position: Calculate the distance of the cursor from the center of the screen to scale the offset intensity.
  • Scroll Speed or Velocity: Increase color separation during rapid scrolling or fast camera movements to mimic motion blur.
  • Audio or Animation: Modulate the shift parameters using sine waves, timers (performance.now()), or audio frequency data.
let mouseXOffset = 0;
let mouseYOffset = 0;

window.addEventListener('mousemove', (e) => {
    // Normalize and scale the offset based on cursor position
    mouseXOffset = Math.floor((e.clientX / window.innerWidth - 0.5) * 15);
    mouseYOffset = Math.floor((e.clientY / window.innerHeight - 0.5) * 15);
});

function render() {
    chromaticAberrationKernel(sourceCanvas, mouseXOffset, mouseYOffset);
    requestAnimationFrame(render);
}
render();

Radial Aberration

For a more physically accurate effect, the shift should scale radially from the center of the screen rather than moving uniformly in one direction. In gpu.js, this is achieved by calculating the vector from the screen center to the current thread:

const centerX = this.constants.width / 2;
const centerY = this.constants.height / 2;

const dirX = (this.thread.x - centerX) / centerX;
const dirY = (this.thread.y - centerY) / centerY;

const pixelR = image[this.thread.y - dirY * intensity][this.thread.x - dirX * intensity];
const pixelG = image[this.thread.y][this.thread.x];
const pixelB = image[this.thread.y + dirY * intensity][this.thread.x + dirX * intensity];

Performance Considerations

Because gpu.js runs directly on the GPU, calculating offset samples for every pixel takes negligible time—even at 60 frames per second on high-resolution displays. Ensure bounds checking is handled when sampling offsets near the canvas edges to avoid out-of-bounds artifacting, and ensure the source texture updates efficiently if processing continuous video or dynamic WebGL frames.
