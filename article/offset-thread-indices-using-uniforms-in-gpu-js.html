Offset Thread Indices Using Uniforms in GPU.js

This article explains how to implement offset thread indices using global uniform displacement vectors in GPU.js. While native thread coordinates (this.thread.x, this.thread.y, and this.thread.z) are read-only hardware identifiers that cannot be directly reassigned, developers can easily apply uniform displacement vectors within kernel functions to access shifted memory locations, perform coordinate transformations, and calculate spatial offsets.

Understanding Thread Coordinates in GPU.js

In GPU.js, kernels execute code across hundreds or thousands of parallel threads. Each thread receives a fixed, unique coordinate mapped to the output grid:

  • this.thread.x
  • this.thread.y
  • this.thread.z

Because these values reflect the physical position of the current execution unit relative to the output buffer, attempting to mutate them directly (such as this.thread.x += dx) will cause compilation errors or undefined behavior in the underlying WebGL shader translation.

Applying Displacement Vectors via Uniforms

To achieve thread displacement, you pass your offset values—such as a 2D or 3D displacement vector—into the kernel as arguments. GPU.js treats kernel function arguments as GLSL uniforms. Uniforms are global values that remain constant across all threads for a single dispatch.

Inside the kernel logic, compute virtual or displaced coordinates by combining the native thread position with the uniform vector:

const { GPU } = require('gpu.js');
const gpu = new GPU();

const computeShiftedKernel = gpu.createKernel(function(sourceMatrix, displacement) {
    // Read displaced coordinates
    const shiftedX = this.thread.x + displacement[0];
    const shiftedY = this.thread.y + displacement[1];

    // Read from the source matrix at the displaced coordinate
    return sourceMatrix[shiftedY][shiftedX];
}).setOutput([512, 512]);

// Usage: displace by 10 units on X and -5 units on Y
const displacementVector = [10, -5];
const result = computeShiftedKernel(sourceData, displacementVector);

Boundary Handling Considerations

When thread coordinates are offset by uniform vectors, displaced indices frequently exceed the boundaries of input matrices or textures. Standard arrays will return 0 or cause sampling artifacts if accessed out of bounds. To prevent invalid reads, implement boundary checks such as clamping or wrapping directly inside the kernel:

  • Clamping: Restrict the offset coordinate so it does not drop below zero or exceed matrix dimensions.
  • Wrapping (Toroidal): Use the modulo operator to wrap coordinates around the edges of the simulation domain.
  • Conditional Fallbacks: Return a predefined default value (like zero or transparent alpha) when the displaced index falls outside the valid range.
const safeShiftKernel = gpu.createKernel(function(source, dx, dy, width, height) {
    let targetX = this.thread.x + dx;
    let targetY = this.thread.y + dy;

    // Boundary check
    if (targetX < 0 || targetX >= width || targetY < 0 || targetY >= height) {
        return 0;
    }

    return source[targetY][targetX];
}).setOutput([512, 512]);

Practical Use Cases

Using uniform displacement vectors to offset index reads is fundamental in high-performance GPU tasks, including:

  1. Convolution and Image Filters: Accessing neighboring pixels using fixed kernel offsets (e.g., Sobel, Gaussian blur).
  2. Cellular Automata: Evaluating neighbor states in simulations like Conway's Game of Life.
  3. Fluid and Particle Simulations: Sampling velocity fields at displaced coordinates to calculate advection.
  4. Scrolling Backgrounds: Translating coordinate systems for camera movement across game maps.
