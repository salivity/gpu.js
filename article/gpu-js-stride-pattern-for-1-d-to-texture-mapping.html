GPU.js Stride Pattern for 1D to Texture Mapping

This article provides an overview of how GPU.js handles memory layout when converting flat 1D memory buffers into multi-dimensional WebGL textures. It details the underlying mathematical stride formulas, row-major memory ordering, and the hardware-constrained 2D texture wrapping techniques used to maintain high throughput during parallel GPU computations.

Logical Stride: Row-Major Order

GPU.js relies on standard row-major (C-contiguous) ordering to translate multi-dimensional array coordinates into a contiguous 1D linear sequence. When mapping logical 2D or 3D matrices, the innermost dimension (typically the X-axis) has a stride of 1, meaning consecutive elements along this axis are adjacent in memory.

For a 3D volume with dimensions \((D_x, D_y, D_z)\), the linear index \(I\) of any logical element at \((x, y, z)\) is calculated using the following stride formula:

\[I = x + (y \times D_x) + (z \times D_x \times D_y)\]

Here, the stride for the Y-dimension is \(D_x\), and the stride for the Z-dimension is the area of a 2D slice, \(D_x \times D_y\).

Physical Stride: Mapping 1D Memory to 2D Textures

WebGL cannot handle arbitrarily long 1D textures because hardware drivers enforce a strict MAX_TEXTURE_SIZE limit on any single dimension. To circumvent this, GPU.js folds 1D memory buffers across a 2D texture grid.

The system determines a texture width (\(W_{tex}\)) and height (\(H_{tex}\)) that can fit the total element count \(N\). The 1D index \(I\) is then mapped to 2D texture coordinates \((U, V)\) using standard division and modulo strides:

  • Horizontal Texel Coordinate (\(X_{tex}\)): \(I \pmod{W_{tex}}\)
  • Vertical Texel Coordinate (\(Y_{tex}\)): \(\lfloor I / W_{tex} \rfloor\)

In normalized WebGL texture space, an offset of \(0.5\) is added to sample the center of each texel:

\[U = \frac{(I \pmod{W_{tex}}) + 0.5}{W_{tex}}\] \[V = \frac{\lfloor I / W_{tex} \rfloor + 0.5}{H_{tex}}\]

Channel-Level Packing Stride

When floating-point texture support (OES_texture_float) is unavailable or when packing data into standard 8-bit or 32-bit RGBA channels, GPU.js introduces a 4-element sub-stride. Four sequential logical values are packed into the Red, Green, Blue, and Alpha channels of a single pixel:

  • Pixel Index: \(I_{pixel} = \lfloor I / 4 \rfloor\)
  • Channel Offset: \(I \pmod 4\) (where 0 maps to R, 1 to G, 2 to B, and 3 to A)

The resulting physical texture coordinates are calculated relative to \(I_{pixel}\), reducing the required texture surface area by a factor of four while preserving the overall row-major layout across the texture grid.
