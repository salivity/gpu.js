Ambiguous Variable Types in GPU.js Functions

When using GPU.js to run JavaScript on the GPU, declaring a variable with an ambiguous type inside a custom function causes the kernel transpilation process to fail. Because GPU.js translates JavaScript code into statically typed OpenGL Shading Language (GLSL), it relies on static analysis to infer the exact type of every variable. If the library cannot determine whether a variable is an integer, float, vector, or array, it throws a compile-time error, generates an invalid shader, or falls back to CPU execution.

The JavaScript to GLSL Type Barrier

JavaScript is dynamically typed, but GPUs operate strictly on statically typed languages like GLSL. In GLSL, every variable must have a declared data type such as float, int, or vec4.

When a kernel or custom function is defined in GPU.js, an internal abstract syntax tree (AST) parser evaluates your JavaScript code ahead of runtime. This parser inspects variable declarations and their assignments to deduce the appropriate GLSL data type automatically.

What Causes Type Ambiguity?

A variable's type becomes ambiguous to the GPU.js compiler under several common conditions:

  • Declaration without initialization: Declaring a variable without a starting value (e.g., let x;) gives the AST analyzer no initial clue regarding its underlying type.
  • Mixed-type assignments: Assigning one type to a variable and subsequently assigning a different type (e.g., starting with an integer x = 1 and later assigning a float or an array x = 2.5).
  • Ambiguous arithmetic or logical expressions: Assigning the result of an operation whose operands have unresolved or conflicting types.
  • Conditional type assignment: Initializing a variable within an if/else block where one branch assigns a scalar and another branch assigns an array or vector.

The Consequence: Transpilation Errors and WebGL Failures

If the type inference engine cannot establish a clear type for a variable inside a custom function, the execution halts through one of two failure modes:

  1. GPU.js Parser Exception: In most instances, the GPU.js analyzer detects the ambiguity before generating the shader string. It throws an explicit JavaScript error during kernel creation, typically stating that it is unable to infer the variable type or that an unsupported AST node was encountered.
  2. GLSL Shader Compilation Failure: If GPU.js defaults the ambiguous variable to a generic type (often a float) and later encounters an operation incompatible with that type, the generated GLSL string will contain invalid syntax. The WebGL context will fail to compile the shader, throwing a native WebGL error.

CPU Fallback and Performance Penalties

If the kernel is configured with mode: 'gpu' and encounters an unresolvable type error, execution will stop completely. However, if the kernel is configured to auto-detect or allow fallbacks, GPU.js may bypass the GPU entirely and run the function using standard JavaScript on the CPU. While the code might run without crashing in this fallback state, it defeats the purpose of GPU acceleration and causes severe performance degradation.

How to Ensure Proper Type Inference

To prevent ambiguous types in custom functions, always declare and initialize variables in a single step using literal values that clearly define the intended data type. Use explicit floating-point notation (e.g., let total = 0.0; instead of let total = 0; if floats are required), avoid reassigning different types to the same identifier, and ensure all conditional branches maintain uniform variable typing.
