Importing External WebGL Textures into GPU.js

This article examines whether external WebGL textures created by third-party libraries can be imported into GPU.js for general-purpose GPU computing. It covers the architectural prerequisites for texture sharing, how to configure a shared WebGL context, the process of wrapping raw textures into GPU.js-compatible structures, and the technical limitations to consider when integrating external graphics pipelines.

The Direct Answer

Yes, external WebGL textures generated by other libraries (such as Three.js, Babylon.js, or raw WebGL) can be used within GPU.js, but they cannot be passed directly as raw WebGLTexture objects into a kernel. GPU.js requires two conditions to make this work: a shared WebGL context and an internal GPU.js wrapper around the external texture.

1. Sharing the WebGL Context

WebGL objects, including textures, cannot be shared across different WebGL contexts without extensions like shared contexts, which are not universally supported across browsers. Therefore, GPU.js must be explicitly initialized using the existing WebGL context created by the external library:

// Retrieve the context from your rendering engine (e.g., Three.js)
const gl = renderer.getContext();

// Initialize GPU.js using the existing context
const gpu = new GPU({
  context: gl
});

By binding GPU.js to the external library's context, any texture allocated on that context resides in the same GPU memory space.

2. Wrapping the External Texture

GPU.js kernels expect arguments to be standard primitives, typed arrays, HTML media elements, or instances of GPU.js’s internal texture class. A bare WebGLTexture lacks the metadata (such as dimensions and channel configurations) that GPU.js needs to inject appropriate sampler uniforms into its generated shader code.

To use an external texture, you must instantiate a GPU.js Texture wrapper around the native texture:

const externalTexture = /* raw WebGLTexture from another library */;
const width = 512;
const height = 512;

// Wrap the external texture into a GPU.js texture representation
const wrappedTexture = new gpu.Texture({
  texture: externalTexture,
  size: [width, height],
  dimensions: [width, height],
  output: [width, height],
  context: gl,
  type: 'NumberTexture' // or appropriate type matching texture format
});

// Pass the wrapped texture into the kernel
myKernel(wrappedTexture);

Potential Caveats and Limitations

  • State Conflicts: External libraries frequently modify WebGL state flags (such as active texture units, depth tests, and blending modes). Running a GPU.js kernel in the middle of another library's render loop can cause state corruption unless the state is explicitly saved and restored.
  • Texture Formats: GPU.js relies heavily on specific internal pixel formats (such as floating-point textures via OES_texture_float or WebGL 2 float formats). If the external texture uses an unsupported format or packing scheme, sampling errors will occur inside the kernel.
  • Pipeline Mode: When sending data back and forth, ensure that GPU.js kernel execution produces a texture (kernel.setPipeline(true)) if you intend to feed the result back to the host rendering engine without incurring the performance penalty of reading pixels back to the CPU via readPixels.
