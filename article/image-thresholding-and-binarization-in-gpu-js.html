Image Thresholding and Binarization in GPU.js

Processing high-resolution imagery can severely bottleneck CPU threads, making hardware acceleration essential for real-time web applications. This article outlines how to implement high-performance image thresholding and binarization using GPU.js, enabling you to offload per-pixel calculations to the GPU via WebGL shaders without writing complex GLSL code directly.

Understanding the Process

Image binarization converts an image into two colors: pure black and pure white. This process begins by evaluating the luminance of each pixel (converting RGB to grayscale) and comparing that value against a defined cutoff known as the threshold:

  • If the pixel luminance is greater than or equal to the threshold, it is assigned a value of white (255).
  • If the pixel luminance is lower than the threshold, it is assigned a value of black (0).

Because this operation processes each pixel independently, it is an embarrassingly parallel task ideally suited for graphics processing units.

Prerequisites and Setup

Install GPU.js using npm or import it via a CDN:

npm install gpu.js

Or include it in your HTML:

<script src="https://cdn.jsdelivr.net/npm/gpu.js@latest/dist/gpu-browser.min.js"></script>

Extracting High-Resolution Image Data

Before feeding image data into GPU.js, load the high-resolution image into an HTML5 <canvas> element to extract its pixel data.

async function loadImageData(url) {
  const img = new Image();
  img.crossOrigin = "Anonymous";
  img.src = url;
  await img.decode();

  const canvas = document.createElement("canvas");
  canvas.width = img.naturalWidth;
  canvas.height = img.naturalHeight;

  const ctx = canvas.getContext("2d");
  ctx.drawImage(img, 0, 0);

  return {
    imageData: ctx.getImageData(0, 0, canvas.width, canvas.height),
    width: canvas.width,
    height: canvas.height
  };
}

Creating the GPU Kernel

GPU.js allows you to write standard JavaScript functions that it compiles into WebGL fragment shaders. To maximize throughput on high-resolution images, use setGraphical(true) to render directly to a WebGL canvas rather than transferring massive numeric arrays back to the CPU.

const gpu = new GPU();

function createBinarizationKernel(width, height) {
  return gpu.createKernel(function(imageArray, threshold) {
    // Calculate pixel coordinates
    const x = this.thread.x;
    const y = this.thread.y;
    
    // Invert the y-axis to match standard image coordinate space
    const invertedY = this.constants.height - 1 - y;
    const index = (invertedY * this.constants.width + x) * 4;

    // Read normalized RGB values (0 to 1)
    const r = imageArray[index] / 255;
    const g = imageArray[index + 1] / 255;
    const b = imageArray[index + 2] / 255;

    // Calculate standard Rec. 601 grayscale luminance
    const luminance = 0.299 * r + 0.587 * g + 0.114 * b;

    // Apply the binary threshold
    if (luminance >= threshold) {
      this.color(1, 1, 1, 1); // White
    } else {
      this.color(0, 0, 0, 1); // Black
    }
  })
  .setConstants({ width, height })
  .setOutput([width, height])
  .setGraphical(true);
}

Executing the Binarization

Pass the raw Uint8ClampedArray and the normalized threshold value (between 0.0 and 1.0) into the kernel:

async function run() {
  const { imageData, width, height } = await loadImageData("path/to/high-res-image.jpg");

  // Create the kernel configured to the dimensions of the image
  const binarize = createBinarizationKernel(width, height);

  // Set the threshold (e.g., 0.5 equates to mid-level luminance)
  const threshold = 0.5;
  binarize(imageData.data, threshold);

  // Access the output canvas and attach it to the DOM
  const outputCanvas = binarize.canvas;
  document.body.appendChild(outputCanvas);
}

run();

Optimizing for High-Resolution Imagery

When working with very high-resolution images (such as 4K, 8K, or gigapixel panoramas), consider the following limitations:

  • Hardware Texture Limits: WebGL has a maximum texture dimension limit (gl.MAX_TEXTURE_SIZE), often 4096, 8192, or 16384 pixels depending on the client GPU. Verify this property before execution.
  • Tiling/Chunking: If the image exceeds the hardware's maximum texture size, split the image into smaller rectangular tiles, process each tile sequentially through the kernel, and assemble them back onto an offscreen canvas.
  • Eliminate Readback Overhead: Calling kernel.getPixels() pulls data from GPU memory back to CPU RAM, which creates an expensive execution block. Using setGraphical(true) keeps execution entirely on the GPU, yielding the highest possible frame rates.
