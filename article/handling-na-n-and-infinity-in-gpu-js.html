Handling NaN and Infinity in gpu.js

When an arithmetic operation in a gpu.js kernel results in NaN (Not-a-Number) or Infinity, the resulting behavior depends heavily on whether the kernel executes on the GPU via WebGL or falls back to the CPU. Unlike native JavaScript, which strictly adheres to the IEEE 754 standard for floating-point exceptions, GPU execution maps directly to underlying graphics drivers and WebGL specifications. Consequently, producing NaN or Infinity inside gpu.js can lead to undefined values, clamped numbers, corrupted output arrays, or divergence between CPU and GPU execution modes.

WebGL and GLSL Execution Behavior

gpu.js compiles your JavaScript kernel functions into WebGL Shading Language (GLSL). The handling of operations like dividing by zero (1.0 / 0.0) or computing the square root of a negative number depends on the targeted WebGL version and the underlying GPU hardware:

  • WebGL 1 (GLSL ES 1.00): IEEE 754 compliance is not strictly mandated. Dividing by zero or generating indeterminate values results in undefined behavior at the hardware level. Depending on the GPU vendor (NVIDIA, AMD, Intel, or mobile chipsets), the hardware may substitute 0.0, clamp to the maximum representable float value, or generate garbage data.
  • WebGL 2 (GLSL ES 3.00): IEEE 754 support is more rigorously defined. Operations generating infinity or undefined numbers will typically produce true 32-bit floating-point representations of Infinity, -Infinity, or NaN.

Data Readback and Output Corruption

gpu.js computes values within shader passes and extracts the output by reading pixels from a WebGL framebuffer. How NaN and Infinity transition from the GPU back into JavaScript arrays depends on your kernel configuration:

  • Float Textures Enabled: If your environment supports floating-point textures (via WebGL 2 or the OES_texture_float extension) and gpu.js reads directly from float buffers, bitwise representations of Infinity and NaN may correctly deserialize into JavaScript's Infinity and NaN values in the returned Float32Array.
  • Packed Mode (8-bit Integer Fallback): When float textures are unsupported or disabled, gpu.js encodes floating-point numbers across the 8-bit Red, Green, Blue, and Alpha channels of a standard texture. Bitwise encoding algorithms generally fail when processing NaN or Infinity. These values typically collapse to 0, 255, or trigger arithmetic overflow that corrupts surrounding channel data, returning nonsensical numbers to your application.

Discrepancies with CPU Fallback

If WebGL is unavailable, or if you explicitly set mode: 'cpu', gpu.js runs the kernel as standard JavaScript loops. In this mode:

  • Dividing a positive number by zero yields Infinity.
  • Dividing zero by zero or taking the square root of a negative number yields NaN.

This creates behavioral divergence. A kernel that reliably returns Infinity or NaN during local development on a CPU fallback may output 0.0 or unexpected numeric noise when deployed to a client machine executing on a WebGL 1 GPU context.

Avoiding Non-Finite Results in gpu.js

Because hardware-level handling of NaN and Infinity is inconsistent across different client devices, you should prevent non-finite numbers from occurring within the kernel logic:

  • Add an Epsilon to Denominators: Prevent division-by-zero errors by introducing a small constant: x / (y + 0.000001).
  • Clamp Input Ranges: Use functions like Math.max() or Math.min() to ensure values passed to sensitive functions (like Math.sqrt() or Math.log()) remain strictly within valid domains.
  • Conditional Checks: Implement inline ternary checks inside the kernel to intercept hazardous operations before they are processed by the shader.
