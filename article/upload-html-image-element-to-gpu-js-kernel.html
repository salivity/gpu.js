Upload HTMLImageElement to GPU.js Kernel

This article explains how to efficiently upload and process an HTMLImageElement inside a gpu.js kernel. Passing image elements directly to GPU.js allows WebGL to handle texture creation automatically, bypassing the CPU overhead of manual pixel extraction via a 2D canvas context. Below is a concise guide covering the direct implementation, output dimension mapping, and best practices for maximum performance.

Direct Passing of Image Elements

GPU.js includes built-in support for HTML DOM media elements, including HTMLImageElement, HTMLVideoElement, and HTMLCanvasElement. When passed as an argument to a kernel, the library binds the image directly as a WebGL texture on the GPU.

Inside the kernel function, the image is accessed as a 2D array representing pixel coordinates, returning an array of four normalized float values [r, g, b, a] ranging from 0 to 1.

Basic Implementation

const { GPU } = require('gpu.js'); // or window.GPU in the browser
const gpu = new GPU();

// 1. Create a kernel expecting an image
const processImage = gpu.createKernel(function(image) {
    const pixel = image[this.thread.y][this.thread.x];
    
    // Invert the colors (pixel.r, pixel.g, pixel.b, pixel.a)
    const r = 1 - pixel.r;
    const g = 1 - pixel.g;
    const b = 1 - pixel.b;

    this.color(r, g, b, pixel.a);
})
.setGraphical(true); // Enables direct rendering to a canvas

// 2. Load the image element
const img = new Image();
img.src = 'path/to/image.png';

img.onload = () => {
    // 3. Match kernel output dimensions to the image
    processImage.setOutput([img.width, img.height]);

    // 4. Pass the HTMLImageElement directly into the kernel
    processImage(img);

    // 5. Append or draw the generated canvas to the document
    document.body.appendChild(processImage.canvas);
};

Performance Best Practices

To achieve optimal performance when working with image textures in GPU.js, apply the following practices:

  • Ensure Image Loading Completes: Always verify that image.complete is true or run the kernel inside the image's onload callback. Passing an unrendered or partially loaded image will result in WebGL texture binding errors.
  • Match Kernel Dimensions Dynamically: Use .setOutput([img.width, img.height]) so the thread distribution precisely matches the pixel grid. Coordinate [x, y] in the thread space corresponds directly to image[this.thread.y][this.thread.x].
  • Enable Graphical Mode for Rendering: If the goal is to display the output, use .setGraphical(true) and use this.color(r, g, b, a) within the kernel. This draws the output straight to the WebGL canvas, eliminating CPU-side memory allocation.
  • Use Pipeline Mode for Multi-Pass Processing: When chaining multiple kernels together (e.g., blurring, then color-grading), enable .setPipeline(true) on the intermediate kernels. This keeps the image data on the GPU as a texture instead of reading float arrays back to JavaScript memory.
