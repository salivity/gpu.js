Compute Pairwise Hamming Distance in GPU.js

Computing pairwise Hamming distances across large libraries of genetic sequences involves an \(O(N^2 \cdot L)\) computational complexity, where \(N\) is the number of sequences and \(L\) is sequence length. This article explains how to parallelize this process on consumer GPUs using gpu.js. By translating sequence characters into numeric representations and executing parallel comparison kernels via WebGL or Node.js compute pipelines, you can process millions of sequence comparisons simultaneously with minimal computational overhead.

1. Data Preprocessing and Encoding

GPUs natively process numerical data rather than strings. To compute Hamming distances, convert genetic sequence strings (e.g., "ACGT") into numeric matrices. Assign each nucleotide an integer:

  • A = 0
  • C = 1
  • G = 2
  • T = 3

Represent a library of \(N\) sequences of uniform length \(L\) as a 2D array of dimensions [N][L].

function encodeSequences(sequences) {
  const map = { 'A': 0, 'C': 1, 'G': 2, 'T': 3 };
  return sequences.map(seq => 
    seq.split('').map(char => map[char.toUpperCase()] ?? 4)
  );
}

2. Defining the GPU.js Kernel

In gpu.js, the execution dimensions determine the output matrix size. For pairwise distances across \(N\) sequences, create an \(N \times N\) output grid. Each thread at coordinate (this.thread.x, this.thread.y) compares sequence x against sequence y.

import { GPU } from 'gpu.js';

const gpu = new GPU();

function createHammingKernel(librarySize, sequenceLength) {
  return gpu.createKernel(function(sequences, length) {
    let distance = 0;
    const seqA = this.thread.y;
    const seqB = this.thread.x;

    for (let i = 0; i < length; i++) {
      if (sequences[seqA][i] !== sequences[seqB][i]) {
        distance++;
      }
    }

    return distance;
  })
  .setOutput([librarySize, librarySize])
  .setPipeline(false); // Returns raw typed arrays or standard JS arrays
}

3. Execution Example

Combine sequence encoding with kernel execution to compute the complete distance matrix.

// Example: 4 sequences of length 6
const rawSequences = [
  "ACTGAC",
  "ACTTAC",
  "GCTGAC",
  "ACTGAA"
];

const encoded = encodeSequences(rawSequences);
const N = rawSequences.length;
const L = rawSequences[0].length;

const kernel = createHammingKernel(N, L);
const distanceMatrix = kernel(encoded, L);

console.log(distanceMatrix);
// Output will be an N x N matrix containing Hamming distances

4. Handling Scale and Memory Limits

When working with libraries exceeding thousands of sequences, typical GPU texture size limits and memory constraints must be addressed:

  • Texture Size Limits: WebGL often limits individual texture dimensions to 4096, 8192, or 16384 pixels. If \(N\) exceeds these bounds, tile the computation into smaller blocks (e.g., \(2048 \times 2048\)) and run the kernel iteratively over offset indices.
  • 1D Flattening: Passing flat 1D arrays instead of nested arrays reduces JavaScript garbage collection overhead and optimizes GPU buffer allocation.
  • Symmetry Optimization: The pairwise Hamming matrix is symmetric (\(D_{ij} = D_{ji}\)) with a diagonal of zero. While running a full \(N \times N\) kernel is simpler and avoids thread branching, calculating only the upper triangle in partitioned chunks reduces hardware compute usage by half on extremely large datasets.
