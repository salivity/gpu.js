Can GPU.js Run SHA-256 Compression Functions?

Computing the SHA-256 compression function and message schedule expansion inside gpu.js is technically feasible, provided the environment supports WebGL 2.0. Because SHA-256 relies heavily on 32-bit unsigned integer arithmetic and bitwise logic—such as XOR, right shifts, and bitwise rotations—the underlying execution context must support native integer types. While WebGL 1.0 lacks these primitives, WebGL 2.0 enables them, allowing both the 64-word message schedule expansion and the 64-round compression loop to be compiled into GPU shader code via gpu.js.

Core Mathematical Requirements of SHA-256

SHA-256 operates on 32-bit words (\(W\)) using specific mathematical operations:

  • Bitwise logic: AND, OR, XOR, and NOT.
  • Bitwise shifts and rotations: Logical right shifts (SHR) and circular right rotations (ROTR).
  • Modular addition: Addition modulo \(2^{32}\).

To implement SHA-256 in gpu.js, these operations must be translated into equivalent operations within the kernel functions without losing precision.

Message Schedule Expansion in GPU.js

The message schedule expansion takes an initial 512-bit message block (divided into 16 32-bit words, \(W_0\) through \(W_{15}\)) and expands it into an array of 64 words (\(W_0\) through \(W_{63}\)).

The formula for words 16 to 63 is: \[W_t = \sigma_1(W_{t-2}) + W_{t-7} + \sigma_0(W_{t-15}) + W_{t-16} \pmod{2^{32}}\]

Where:

  • \(\sigma_0(x) = \text{ROTR}^7(x) \oplus \text{ROTR}^{18}(x) \oplus \text{SHR}^3(x)\)
  • \(\sigma_1(x) = \text{ROTR}^{17}(x) \oplus \text{ROTR}^{19}(x) \oplus \text{SHR}^{10}(x)\)

Inside a gpu.js kernel, this expansion can be processed sequentially within a single thread for a specific block. Because gpu.js allows fixed-size local arrays, a thread can allocate an array of 64 integers, populate the first 16 from the input data, and loop from index 16 to 63 to calculate the remaining elements.

Implementing the Compression Function

Once the message schedule \(W\) is prepared, the compression function updates eight 32-bit state registers (\(a, b, c, d, e, f, g, h\)) initialized from the previous hash state.

The compression loop runs 64 rounds. Each round computes two temporary words: \[T_1 = h + \Sigma_1(e) + Ch(e, f, g) + K_t + W_t \pmod{2^{32}}\] \[T_2 = \Sigma_0(a) + Maj(a, b, c) \pmod{2^{32}}\]

The registers are then shifted:

  • \(h = g\)
  • \(g = f\)
  • \(f = e\)
  • \(e = d + T_1 \pmod{2^{32}}\)
  • \(d = c\)
  • \(c = b\)
  • \(b = a\)
  • \(a = T_1 + T_2 \pmod{2^{32}}\)

In gpu.js, this is written as a standard JavaScript for loop inside the kernel. The round constants (\(K_0\) to \(K_{63}\)) can be embedded directly as a constant array within the kernel code or passed as an input texture/array.

The WebGL 2.0 Dependency

The primary barrier to running SHA-256 inside gpu.js is the graphical backend:

  • WebGL 1.0 Limitation: Standard WebGL 1.0 shaders do not support native integers or bitwise operators (^, &, |, >>, <<). Emulating 32-bit bitwise logic using floating-point math is computationally expensive, prone to rounding inaccuracies, and inefficient for hashing.
  • WebGL 2.0 Requirement: WebGL 2.0 introduces GLSL ES 3.00, which includes native signed and unsigned 32-bit integers and standard bitwise operators. When initializing gpu.js, you must explicitly enforce WebGL 2 mode:
const gpu = new GPU({ mode: 'webgl2' });

Transpiler Considerations in GPU.js

While WebGL 2 supports integer operations, gpu.js parses JavaScript Abstract Syntax Trees (AST) and converts them to GLSL. Developers must account for several syntax constraints:

  1. Bitwise Rotations: JavaScript lacks a native bitwise rotate operator. Rotation must be expressed using shifts: (x >>> n) | (x << (32 - n)). In gpu.js, ensure that variables are explicitly treated as unsigned integers so that the logical shift (>>>) transpiles correctly.
  2. Integer Overflow: JavaScript numbers are 64-bit floats by default, but bitwise operations force them into 32-bit integers. In GLSL, integer addition overflows automatically to match standard modular arithmetic, but you must ensure gpu.js outputs integer addition (+) rather than converting operands to floats.
  3. Thread Architecture: SHA-256 is inherently sequential within a single block due to data dependencies between rounds. GPU acceleration achieves high throughput only by parallelizing across multiple message blocks (hashing thousands of separate inputs simultaneously), rather than accelerating a single hash computation.
