GPU.js Cholesky Factorization for SPD Matrices

This article provides a practical guide to implementing Cholesky factorization for symmetric positive-definite (SPD) matrices in JavaScript using gpu.js. It covers the mathematical formulation of the decomposition, addresses the challenge of sequential dependencies in parallel environments, and provides an end-to-end code implementation that utilizes GPU kernels to accelerate matrix computations.

Understanding the Cholesky Algorithm

Cholesky factorization decomposes an \(n \times n\) symmetric positive-definite matrix \(\mathbf{A}\) into the product of a lower triangular matrix \(\mathbf{L}\) and its transpose:

\[\mathbf{A} = \mathbf{L}\mathbf{L}^T\]

The components of \(\mathbf{L}\) are computed using the following equations:

  • Diagonal elements: \[L_{j,j} = \sqrt{A_{j,j} - \sum_{k=0}^{j-1} L_{j,k}^2}\]

  • Off-diagonal elements (\(i > j\)): \[L_{i,j} = \frac{1}{L_{j,j}} \left( A_{i,j} - \sum_{k=0}^{j-1} L_{i,k} L_{j,k} \right)\]

For all \(i < j\), \(L_{i,j} = 0\).

Parallelization Strategy in GPU.js

Cholesky factorization has strict data dependencies: computing column \(j\) requires values from columns \(0\) to \(j-1\). Because of this sequential dependency across columns, the entire decomposition cannot be computed in a single GPU kernel dispatch.

The standard parallel approach is a right-looking Cholesky algorithm:

  1. Compute the diagonal element \(L_{k,k}\) and scale the current column \(k\) on the CPU or via a light kernel.
  2. Dispatch a 2D GPU kernel to update the trailing submatrix (rows and columns from \(k+1\) to \(n-1\)) simultaneously.
  3. Repeat for \(k = 0, 1, \dots, n-1\).

Implementing Cholesky Factorization with GPU.js

First, install or include gpu.js:

npm install gpu.js

Kernel Definition and Orchestration

The implementation uses an outer JavaScript loop to handle step dependencies, while parallelizing the submatrix elimination step across WebGL compute shaders via gpu.js.

const { GPU } = require('gpu.js');
const gpu = new GPU();

/**
 * GPU Kernel: Updates the trailing submatrix.
 * Computes: A[i][j] = A[i][j] - L[i][k] * L[j][k]
 */
function createSubmatrixKernel(size) {
  return gpu.createKernel(
    function (A, colK, k) {
      const j = this.thread.x;
      const i = this.thread.y;

      // Only update the lower triangular trailing submatrix where i >= j > k
      if (i > k && j > k && i >= j) {
        return A[i][j] - colK[i] * colK[j];
      }
      return A[i][j];
    },
    {
      output: [size, size],
      pipeline: true, // Keep data on GPU memory between iterations
    }
  );
}

/**
 * Computes Cholesky Factorization L of an SPD matrix A.
 * @param {number[][]} matrix - An n x n symmetric positive-definite matrix.
 * @returns {number[][]} L - The lower triangular matrix.
 */
function choleskyGPU(matrix) {
  const n = matrix.length;
  
  // Clone matrix to store L locally
  let L = Array.from({ length: n }, () => new Float32Array(n));
  let currentA = matrix.map(row => Float32Array.from(row));

  const updateSubmatrix = createSubmatrixKernel(n);

  for (let k = 0; k < n; k++) {
    // Step 1: Compute diagonal element on CPU
    const diagVal = currentA[k][k];
    if (diagVal <= 0) {
      throw new Error("Matrix is not symmetric positive-definite.");
    }
    L[k][k] = Math.sqrt(diagVal);

    // Step 2: Scale column k below the diagonal
    const colK = new Float32Array(n);
    colK[k] = L[k][k];

    for (let i = k + 1; i < n; i++) {
      L[i][k] = currentA[i][k] / L[k][k];
      colK[i] = L[i][k];
    }

    // If at the last element, factorization is complete
    if (k === n - 1) break;

    // Step 3: Parallel update of trailing submatrix on the GPU
    const kernelResult = updateSubmatrix(currentA, colK, k);
    
    // Transfer updated matrix for the next iteration
    // When pipeline is true, kernelResult.toArray() brings data back to JS
    currentA = kernelResult.toArray();
  }

  return L.map(row => Array.from(row));
}

// Example Usage:
const A = [
  [4, 12, -16],
  [12, 37, -43],
  [-16, -43, 98]
];

try {
  const L = choleskyGPU(A);
  console.log("Lower Triangular Matrix L:");
  console.table(L);
} catch (err) {
  console.error(err.message);
}

Performance Considerations

  • Pipeline Mode: Enabling { pipeline: true } in gpu.js minimizes texture-to-array transfer latency by keeping data stored in WebGL framebuffer textures between steps.
  • Matrix Size: Because transferring buffers between the CPU and GPU introduces overhead, the GPU-accelerated implementation is best suited for large matrices (\(n > 256\)). For smaller matrices, CPU-based algorithms (such as standard loop vectorization) often outperform GPU implementations due to initialization latency.
  • Precision: Standard WebGL configurations in gpu.js operate on 32-bit single-precision floats (Float32Array). Ensure your matrix condition number is well-behaved to avoid numerical instability associated with reduced precision.
