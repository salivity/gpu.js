Double-Buffering with Multiple Kernels in gpu.js

Yes, multiple pipeline kernels can write to alternating textures in a double-buffering scheme using gpu.js. By setting pipeline: true, gpu.js outputs WebGL textures directly to GPU memory rather than reading them back to the CPU as typed arrays. Because WebGL prevents a single texture from being sampled and rendered to simultaneously, an alternating ping-pong or double-buffering pattern is the standard, high-performance approach for multi-stage and iterative computations.

How Double-Buffering Works in gpu.js

When you configure a kernel with .setPipeline(true), calling that kernel returns a Texture object instead of an array. You can immediately feed this output texture as an argument into another pipeline kernel (or back into the same kernel across sequential iterations).

To execute alternating textures with multiple kernels:

  1. Define Kernels with Pipeline Enabled: Set .setPipeline(true) on every kernel in your processing chain.
  2. Initialize Textures: Provide initial data to the first kernel to produce the starting texture.
  3. Alternate References: Pass the output of Kernel A as the input to Kernel B, then route the output of Kernel B back to Kernel A or the next stage.

Implementation Example

Below is a demonstration of chaining two distinct kernels that alternate textures in an iterative loop:

const { GPU } = require('gpu.js');
const gpu = new GPU();

// Kernel 1: Performs the first stage of computation
const stepOneKernel = gpu.createKernel(function(prevTexture) {
    return prevTexture[this.thread.y][this.thread.x] + 1.0;
})
.setOutput([512, 512])
.setPipeline(true);

// Kernel 2: Performs the second stage of computation
const stepTwoKernel = gpu.createKernel(function(intermediateTexture) {
    return intermediateTexture[this.thread.y][this.thread.x] * 2.0;
})
.setOutput([512, 512])
.setPipeline(true);

// Initial input data
let currentTexture = [/* 512x512 array initialized with starting values */];

// Iterative double-buffered execution loop
const iterations = 10;
for (let i = 0; i < iterations; i++) {
    // Stage 1 writes to an intermediate texture
    const tempTexture = stepOneKernel(currentTexture);
    
    // Delete the previous texture from GPU memory if it is a gpu.js Texture instance
    if (currentTexture.delete) {
        currentTexture.delete();
    }

    // Stage 2 reads the intermediate texture and writes to the next state
    currentTexture = stepTwoKernel(tempTexture);

    // Delete intermediate texture to prevent VRAM memory leaks
    tempTexture.delete();
}

// Read the final result back to the CPU
const finalResult = currentTexture.toArray();
currentTexture.delete();

Memory Management and Texture Cleanup

In gpu.js, intermediate textures persist on the GPU until manually destroyed or garbage-collected. In tight iterative loops, continuously generating textures without cleanup will quickly exhaust available WebGL texture units and VRAM.

Always call .delete() on intermediate and prior-frame textures once they have been consumed by downstream kernels. This keeps the execution footprint limited to strictly the active ping-pong buffers.
