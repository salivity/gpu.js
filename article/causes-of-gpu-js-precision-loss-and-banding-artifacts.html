Causes of gpu.js Precision Loss and Banding Artifacts

Precision loss and visual banding artifacts in gpu.js calculations primarily stem from the underlying constraints of WebGL, including default 8-bit texture channel quantization, float packing algorithms, shader precision qualifiers, and hardware-specific floating-point arithmetic. When performing high-dynamic-range mathematical calculations or generating continuous gradients, these constraints restrict the numerical resolution of the output, resulting in visible stepping (banding) or truncated decimal values.

Default 8-Bit Framebuffer Quantization

By default, WebGL renders shader outputs to a standard 8-bit-per-channel RGBA framebuffer. This limits each color channel (Red, Green, Blue, Alpha) to 256 discrete levels (values from 0 to 255, normalized between 0.0 and 1.0).

When a gpu.js kernel computes continuous mathematical functions—such as smooth gradients, physics simulations, or matrix multiplications—without explicitly returning floating-point textures, continuous floating-point values are clamped and rounded to the nearest \(1/255\) increment (~0.00392). This step-like rounding manifests visually as distinct contour lines or color banding instead of smooth transitions.

Float-to-RGBA Packing Inaccuracies

To bypass 8-bit channel limits without requiring WebGL floating-point texture extensions, gpu.js can encode 32-bit floating-point numbers across the four 8-bit RGBA channels using bit-shifting arithmetic.

While this packing mechanism increases range, it introduces precision loss through:

  • Division and Modulo Rounding: Packing involves repeated division and fractional extraction, which can introduce microscopic rounding errors in the least significant bits.
  • Denormalized Numbers: WebGL implementations on certain hardware flush subnormal (denormalized) floating-point numbers directly to zero, causing sudden drops in output near zero.

Shader Floating-Point Precision Qualifiers

gpu.js compiles JavaScript code into GLSL fragment shaders. In GLSL, floating-point variables rely on precision qualifiers: lowp, mediump, or highp.

  • mediump Fallback: On many mobile devices and integrated GPUs, fragment shaders default to or enforce mediump instead of highp. A mediump float provides only 16-bit half-precision (a 10-bit mantissa), giving roughly 3.3 decimal places of precision. High-frequency or wide-range calculations quickly exhaust this precision, causing severe truncation.
  • Lack of Full IEEE 754 Compliance: GPU arithmetic does not strictly follow the IEEE 754 standard used by CPU JavaScript engines. Hardware operations may round toward zero instead of round-to-nearest-even, leading to cumulative drift in iterative loops.

Non-Linear Transformations and Gamma Space

When mathematical outputs represent visual color scales, applying non-linear functions (like gamma correction or exponential scaling) to low-precision linear values stretches quantization gaps. In dark regions, the distance between adjacent 8-bit values is amplified when converted to non-linear brightness, making discrete steps much more noticeable to the human eye.

How to Mitigate Precision Loss in gpu.js

To eliminate visual banding and preserve mathematical accuracy:

  1. Enable Float Outputs: Configure the kernel to output 32-bit floating-point textures directly using the pipeline: true mode or by ensuring WebGL float extensions (OES_texture_float and WEBGL_color_buffer_float) are utilized.
  2. Force High Precision: Ensure the execution context defaults to precision: 'single' rather than precision: 'unsigned' to force 32-bit IEEE floats whenever supported by the client hardware.
  3. Implement Dithering: For visual outputs destined for standard 8-bit displays, apply a small amount of high-frequency pseudo-random noise (ordered dithering) to break up spatial banding contours.
