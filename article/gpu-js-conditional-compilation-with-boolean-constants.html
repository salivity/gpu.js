gpu.js Conditional Compilation with Boolean Constants

Boolean constants can be used to achieve conditional compilation behavior within gpu.js kernels, though the mechanism depends on how the code is structured. While gpu.js does not feature a dedicated C-style preprocessor for #ifdef directives in JavaScript, developers can pass boolean values into the kernel's constants configuration. When these constants are evaluated in conditional statements, modern GPU shader compilers eliminate dead branches during kernel compilation. Alternatively, developers can use JavaScript-level dynamic function generation prior to kernel creation for true source-level conditional compilation.

How gpu.js Handles Constants

When creating a kernel in gpu.js, you can define immutable values using the constants property inside the kernel settings.

const kernel = gpu.createKernel(function() {
    if (this.constants.enableFeature) {
        // Code path A
        return 1.0;
    } else {
        // Code path B
        return 0.0;
    }
}, {
    constants: { enableFeature: true },
    output: [100]
});

When gpu.js compiles the JavaScript function to WebGL/GLSL shader code, it injects the constants as fixed values rather than dynamic uniform variables.

GLSL Dead-Code Elimination

True conditional compilation removes unused code paths entirely to save memory and execution cycles. Because gpu.js converts this.constants.booleanName into static GLSL values at compile time, the underlying graphics driver's shader compiler executes constant folding and dead-code elimination.

If this.constants.enableFeature is hardcoded to true upon compilation:

  • The shader compiler evaluates if (true) as guaranteed.
  • The instructions within the else block are stripped completely from the compiled binary.
  • The branch penalty is removed, preventing divergent branching issues across GPU warps/wavefronts.

Source-Level Conditional Compilation via Closures

If you require complete omission of code before gpu.js parses the JavaScript Abstract Syntax Tree (AST), boolean flags can be evaluated in standard JavaScript to generate the kernel function dynamically.

function createDynamicKernel(enableFeature) {
    const kernelFunction = enableFeature 
        ? function() { return 1.0; }
        : function() { return 0.0; };

    return gpu.createKernel(kernelFunction, { output: [100] });
}

This method ensures that unsupported operations or references are never parsed by the gpu.js transpiler, which is useful when branching between different complex mathematical operations that the gpu.js AST parser might struggle to optimize.

Practical Considerations

  • Recompilation Cost: Changing the value of a constant requires instantiating a new kernel or calling kernel.setConstants(), which triggers a full GLSL recompile. If a boolean value must change frequently per frame, pass it as a dynamic kernel argument instead, accepting the minimal cost of runtime branching.
  • Type Strictness: Ensure constants defined as booleans in JavaScript are handled as strict booleans within the kernel body to prevent unexpected implicit conversions during GLSL generation.
