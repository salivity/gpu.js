How GPU.js Handles Compound Assignment Operators

This article explains how GPU.js translates compound assignment operators—such as +=, -=, *=, and /=—from JavaScript kernel functions into executable GLSL shader code. It covers the abstract syntax tree (AST) parsing process, GLSL compatibility, automatic type coercion, and specific limitations encountered when running accelerated calculations across different WebGL contexts.

Abstract Syntax Tree Parsing

GPU.js converts JavaScript functions into WebGL shader code at runtime. It starts by taking the kernel function's string representation and parsing it into an Abstract Syntax Tree (AST) using an internal JavaScript parser.

Within the AST, an expression like total += value is categorized as an AssignmentExpression. This node contains three primary components:

  • operator: The operator string (e.g., "+=", "-=", "*=", "/=").
  • left: The target being assigned (an Identifier representing a variable, or a MemberExpression representing an array index).
  • right: The evaluated expression or value added, subtracted, or multiplied.

The GPU.js code generator traverses these nodes to reconstruct equivalent GLSL (OpenGL Shading Language) statements.

Native GLSL Mapping

GLSL natively supports the standard arithmetic compound assignment operators: +=, -=, *=, and /=. Because of this native support, GPU.js does not need to expand an expression like x += y into x = x + y for standard scalar operations.

During transpilation, the generator identifies the operator and outputs it directly into the shader string. For example:

// JavaScript Kernel Code
let sum = 0;
sum += values[this.thread.x];

Translates directly in the resulting fragment shader to:

// Generated GLSL
float user_sum = 0.0;
user_sum += user_values[index];

Type Coercion and Strict Typing

JavaScript allows dynamic typing and implicit coercion, whereas GLSL requires strict static typing. GPU.js tracks the inferred types of kernel variables (such as Integer, Float, or Array) to ensure type matching across compound assignments.

If an integer literal is used with a floating-point variable in a compound assignment, GPU.js automatically casts the operand to prevent GLSL compilation errors:

  • JavaScript input: val += 1; (where val is a float)
  • GLSL output: user_val += 1.0;

If an unsupported type mixture occurs (such as attempting compound assignments with unsupported object types or arrays that cannot be resolved to vector math), the transpiler throws a compilation error during the kernel build phase before the shader is dispatched to the GPU.

Scope and Reassignment Rules

Compound operators can only be used on mutable local variables or writable temporary structures inside the kernel body.

  • Local Variables: Any local variable declared with let or var within the kernel function can freely use +=, -=, and *= throughout loops or branching logic.
  • Output Restrictions: In GPU.js, kernel results are traditionally returned at the end of the function using a return statement rather than assigned directly to an output buffer via +=. The output buffer is populated by the return value of each thread coordinate (this.thread.x, this.thread.y, etc.).

Bitwise Compound Operators

For bitwise compound operators such as &=, |=, ^=, <<=, and >>=, support depends entirely on the WebGL backend being targeted:

  • WebGL 2.0: Supports integer types and bitwise operations natively. GPU.js can transpile these operations directly when the kernel is initialized with WebGL 2 mode.
  • WebGL 1.0: Lacks native bitwise operator support. Attempting to use bitwise compound operators on WebGL 1.0 contexts will result in a transpile-time error, as the operations cannot be mapped directly to WebGL 1.0 GLSL specifications.
