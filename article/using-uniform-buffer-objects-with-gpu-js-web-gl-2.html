Using Uniform Buffer Objects with GPU.js WebGL 2

This article explores whether Uniform Buffer Objects (UBOs) can be bound directly to shaders generated by gpu.js when running in WebGL 2 mode. While WebGL 2 natively introduces UBOs to efficiently share data across programs, gpu.js does not provide native API support for declaring or binding uniform blocks. Direct binding cannot be performed out of the box because the library's built-in transpiler does not emit the necessary GLSL uniform block declarations, though low-level workarounds exist if you are willing to interact directly with the underlying WebGL 2 context.

How gpu.js Manages Data in WebGL 2

By default, gpu.js compiles JavaScript functions into GLSL fragment shaders to perform parallel calculations. To supply input data to these shaders, gpu.js primarily uses two mechanisms:

  1. Textures: Large datasets, arrays, and matrices are encoded into floating-point or integer textures. The shader reads from these via sampler uniforms.
  2. Standard Uniforms: Scalar values (numbers, booleans) and small fixed-size vectors are passed as individual, standard uniform variables (such as uniform float or uniform vec4).

Because gpu.js was architected around compatibility with both WebGL 1 and WebGL 2, its high-level pipeline does not incorporate WebGL 2–specific uniform blocks.

The Problem with Direct UBO Binding

To bind a Uniform Buffer Object in WebGL 2, two conditions must be met:

  1. The compiled GLSL shader source must explicitly define an interface block using the uniform BlockName { ... }; syntax.
  2. The WebGL application must query the block index using gl.getUniformBlockIndex and bind a buffer to that block index via gl.uniformBlockBinding and gl.bindBufferBase.

The gpu.js JavaScript-to-GLSL compiler automatically generates the shader source code based on your kernel function arguments. Because the compiler does not generate interface blocks, the resulting WebGL program lacks any uniform block targets. Calling gl.getUniformBlockIndex on a standard gpu.js kernel program will return gl.INVALID_INDEX, making standard UBO binding impossible without modifying the shader generation step.

Low-Level Workarounds

If your application strictly requires UBOs, you can bypass the abstraction layer by interacting with the internal WebGL 2 context and kernel state:

  1. Accessing Context and Program: gpu.js exposes the underlying context through gpu.context (or kernel.context) and the compiled program via internal kernel properties (typically kernel.program).
  2. Source Interception: Before the program links, you must intercept or override the generated fragment shader source code to inject your custom uniform block declarations.
  3. Manual Binding: Once the shader is recompiled and linked, use the native WebGL 2 API methods (gl.bindBuffer, gl.bufferData, and gl.bindBufferBase) to bind your UBO to the designated binding point.

This approach requires monkey-patching internal methods of gpu.js, which creates maintenance issues and negates the convenience of using the library.

Recommended Alternatives

For standard use cases, working within the intended architecture of gpu.js is the most practical path:

  • Use Built-in Textures: Pass large arrays and structured data directly as kernel arguments. gpu.js automatically packs these into textures and manages binding seamlessly.
  • Standard Arguments: Pass configuration parameters and scalar variables directly into the kernel function as standard uniforms.
  • Pure WebGL 2 or WebGPU: If uniform buffer performance, explicit memory layout management (std140), or compute shaders are critical requirements for your application, consider writing native WebGL 2 code or migrating to the modern WebGPU API instead of using gpu.js.
